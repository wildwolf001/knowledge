# 5.3 渐进式信息披露 L0-L3

> Task → Evidence Index → Evidence Fragments → Full Evidence，按需加载

## 从"倾泻"到"渐进"的范式转变

传统的 RAG 系统（8.1 经典 RAG 四阶段）采用"先检索、后生成"的模式：一次性检索大量文档、一次性注入上下文。这种方式的问题在于——**你无法预知哪些信息是真正需要的，直到模型开始思考**。

渐进式信息披露（Progressive Information Disclosure）借鉴了人类侦探的思维方式：不一次性阅读全部卷宗，而是先了解案件摘要（Task），再看证据目录（Evidence Index），然后调取关键证据片段（Evidence Fragments），最后在必要时查看完整证据（Full Evidence）。

### L0: Task Definition（任务定义）

**内容**: 用户的原始问题或任务描述。这是唯一必须全部注入的层。

**目标**: 让模型理解"需要做什么"，但不提供任何背景资料。这迫使模型激活其内化知识来确定"需要什么信息"。

**Token 预算**: 50-200 tokens

**关键设计**: 在此阶段，模型可能提出一个"信息需求列表"。这是一个关键的设计决策点——后续所有层的加载策略都基于这个列表。

**实现**:

```python
class ProgressiveDisclosure:
    """渐进式信息披露控制器"""
    
    def __init__(self, retriever, llm_call):
        self.retriever = retriever      # 检索器（8.3 混合检索）
        self.llm = llm_call              # LLM 调用函数
        self.disclosure_level = 0        # 当前披露级别
        self.information_requests = []   # L0 分析出的信息需求
        self.evidence_loaded = {}        # 已加载的证据
    
    def process_task(self, task: str) -> str:
        """L0: 处理任务"""
        self.disclosure_level = 0
        result = self.llm(
            system="分析以下任务，列出你需要哪些信息来完成它。"
                   "返回格式: 信息需求列表（每行一个需求）。",
            user=task
        )
        # 解析信息需求
        self.information_requests = self._parse_requests(result)
        return result
```

### L1: Evidence Index（证据索引）

**内容**: 所有可能相关文档/数据源的轻量级索引（文件名、摘要、元数据）。不包含具体内容，只包含"存在什么"。

**目标**: 让模型从"需要什么"过渡到"什么可用"。模型在此阶段**不做出最终决策**，而是筛选出值得深入查看的候选项。

**Token 预算**: 300-500 tokens

**关键设计**: 
- 索引必须是**人类可读的**——模型需要根据简短描述判断相关性
- 索引的元数据设计直接影响 L1→L2 的准确率
- 使用混合检索（8.3）从知识库中召回候选文档的摘要信息

**实现**:

```python
    def request_index(self) -> dict:
        """L1: 请求证据索引"""
        self.disclosure_level = 1
        
        # 为每个信息需求检索索引
        index_entries = []
        for req in self.information_requests:
            results = self.retriever.search_index(
                query=req,
                top_k=5,
                include_summary=True  # 仅获取摘要，非全文
            )
            index_entries.extend(results)
        
        # 去重
        seen = set()
        unique_entries = []
        for entry in index_entries:
            if entry["id"] not in seen:
                seen.add(entry["id"])
                unique_entries.append(entry)
        
        return {"entries": unique_entries[:10]}  # 最多返回 10 条
    
    def select_evidence(self, index: dict) -> list:
        """模型基于索引选择需要加载的证据"""
        selection = self.llm(
            system="基于以下证据索引，选择你需要进一步查看的条目。"
                   "返回条目 ID 列表，按重要性排序。",
            user=str(index)
        )
        return self._parse_selection(selection)
```

### L2: Evidence Fragments（证据片段）

**内容**: 从 L1 选中的文档中提取的关键片段。这是**最重要的设计层**——片段需要在信息量和 token 消耗之间取得平衡。

**目标**: 提供足够的上下文让模型完成初步分析或决策，但省略无关细节。

**Token 预算**: 1,000-3,000 tokens

**关键设计**:
- **分块策略**（8.2）直接影响片段质量：语义边界分块优于固定大小分块
- 片段应该包含**结论性信息**而非过程性细节
- 对于数据表格，使用聚合数据而非原始行

**实现**:

```python
    def load_fragments(self, selected_ids: list) -> dict:
        """L2: 加载证据片段"""
        self.disclosure_level = 2
        
        fragments = {}
        for doc_id in selected_ids[:5]:  # 最多加载 5 个
            full_doc = self.retriever.get_document(doc_id)
            
            # 智能提取片段：对长文档做关键内容提取
            if len(full_doc) > 2000:
                fragment = self._extract_fragment(full_doc, max_tokens=500)
            else:
                fragment = full_doc
            
            fragments[doc_id] = {
                "fragment": fragment,
                "source": doc_id,
                "token_count": len(fragment.split())
            }
        
        self.evidence_loaded = fragments
        return fragments
    
    def _extract_fragment(self, doc: str, max_tokens: int = 500) -> str:
        """智能提取文档片段"""
        # 方法1: 如果文档有结构化分段，取包含关键数据的段落
        # 方法2: 使用 Cross-Encoder 评分找最相关段落
        # 方法3: 用 LLM 摘要
        return doc[:max_tokens * 4]  # 简化: 按字符数截断
```

### L3: Full Evidence（完整证据）

**内容**: 在 L2 分析完成但模型认为信息不足时，按需加载的完整文档。

**目标**: 提供"最后细节"，只有在前三层都不足时才触发。

**触发条件**:
- 模型在 L2 分析中明确表示"信息不足"
- 模型输出中的置信度评分低于阈值
- 用户要求更详细的分析

**Token 预算**: 2,000-10,000+ tokens（但仅在必要时使用）

**实现**:

```python
    def load_full_evidence(self, doc_id: str) -> str:
        """L3: 加载完整证据"""
        self.disclosure_level = 3
        return self.retriever.get_document(doc_id)
    
    def analyze_with_l3_if_needed(self, l2_result: str) -> str:
        """如果 L2 分析不足，自动升级到 L3"""
        confidence = self._extract_confidence(l2_result)
        
        if confidence < 0.7:
            # 自动升级到 L3: 请求完整文档
            missing_ids = self._detect_missing_evidence(l2_result)
            for doc_id in missing_ids:
                full = self.load_full_evidence(doc_id)
                # 重新分析
                l2_result = self.llm(
                    system=f"额外证据已提供:\n{full[:2000]}\n更新你的分析。",
                    user=l2_result
                )
        
        return l2_result
```

## 决策流程：何时推进到下一层

```
L0: 收到任务
  │
  ├── 模型是否明确知道答案？──→ 直接输出（跳过 L1-L3）
  │
  ├── 模型需要更多信息？
  │     │
  │     ▼
  │  L1: 加载证据索引
  │     │
  │     ├── 模型能找到所需文档？──→ L2: 加载片段
  │     │                              │
  │     │                              ├── 片段足够？──→ 输出
  │     │                              │
  │     │                              └── 不够？──→ L3: 加载全文
  │     │                                            │
  │     │                                            └── 输出
  │     │
  │     └── 索引中没有？──→ 返回"无可用数据" + 建议
  │
  └── 模型拒绝回答（安全/伦理）
```

## Token 消耗对比

| 场景 | 传统一次性加载 | 渐进式 L0-L3 | 节省比例 |
|------|-------------|-------------|---------|
| 简单问答（L0 即够） | 12,000 tokens | 200 tokens | 98.3% |
| 中等查询（需要 L2） | 15,000 tokens | 1,500 tokens | 90% |
| 复杂分析（需要 L3） | 20,000 tokens | 5,000 tokens | 75% |
| 平均（混合场景） | 15,000 tokens | 2,000 tokens | 86.7% |

## 与 RAG 的关系

渐进式信息披露是对 RAG（8.1-8.7）的补充而非替代：

| 维度 | 经典 RAG | 渐进式信息披露 |
|------|---------|--------------|
| 信息注入时机 | 一次性，在生成前 | 多轮，按需加载 |
| 模型参与度 | 被动接收检索结果 | 主动决定需要什么 |
| Token 效率 | 低（常注入冗余内容） | 高（精确按需加载） |
| 实现复杂度 | 低 | 中-高 |
| 适用场景 | 单轮问答、事实核查 | 多步分析、复杂推理 |

**最佳实践**: 简单事实查询用经典 RAG（快速直接）；复杂分析任务用渐进式信息披露（精准深度）。8.4 节 Agentic RAG 进一步讨论了多步推理检索的集成方式。

## 代码示例：完整渐进式信息披露管道

```python
import json
from typing import List, Dict, Optional

class EvidenceController:
    """
    渐进式信息披露控制器 - 完整实现
    """
    
    def __init__(self, retriever: object, llm_func: callable):
        self.retriever = retriever
        self.llm = llm_func
        self.state = {
            "level": 0,
            "task": "",
            "info_requests": [],
            "index": None,
            "fragments": {},
            "full_evidence": {}
        }
    
    def run(self, task: str) -> str:
        """运行完整多阶段流程"""
        # L0
        self.state["task"] = task
        self.state["level"] = 0
        needs_info = self._analyze_task(task)
        
        if not needs_info:
            return self.llm(task)  # 模型已知答案
        
        # L1
        self.state["info_requests"] = needs_info
        self.state["level"] = 1
        index = self._build_index(needs_info)
        self.state["index"] = index
        
        selections = self._select_evidence(index)
        if not selections:
            return "无法找到相关信息。"
        
        # L2
        self.state["level"] = 2
        fragments = self._load_fragments(selections)
        self.state["fragments"] = fragments
        
        preliminary = self._preliminary_analysis(fragments, task)
        
        # 检查是否需要 L3
        if self._needs_deeper(preliminary):
            self.state["level"] = 3
            missing = self._identify_gaps(preliminary)
            full = self._load_full(missing)
            self.state["full_evidence"] = full
            return self._final_analysis(fragments, full, task)
        
        return preliminary
    
    def _analyze_task(self, task: str) -> List[str]:
        """L0: 分析任务的信息需求"""
        prompt = f"""分析以下任务，判断是否需要额外信息。
如果不需要，返回 EMPTY。
如果需要，列出你需要的信息类型（每行一个）。

任务: {task}"""
        result = self.llm(prompt)
        if result.strip() == "EMPTY":
            return []
        return [line.strip() for line in result.split("\n") if line.strip()]
    
    def _build_index(self, requests: List[str]) -> dict:
        """L1: 构建证据索引"""
        all_entries = []
        for req in requests:
            results = self.retriever.search(req, top_k=3)
            all_entries.extend(results)
        # 去重 + 限制数量
        return {"entries": list({e["id"]: e for e in all_entries}.values())[:10]}
    
    def _select_evidence(self, index: dict) -> List[str]:
        """模型从索引中选择需要的条目"""
        prompt = f"""基于以下索引，选择你需要的条目 ID:

{json.dumps(index, ensure_ascii=False, indent=2)}

返回格式: id1, id2, id3"""
        result = self.llm(prompt)
        return [r.strip() for r in result.split(",")]
    
    def _load_fragments(self, selections: List[str]) -> Dict[str, str]:
        """L2: 加载证据片段"""
        fragments = {}
        for doc_id in selections[:5]:
            doc = self.retriever.get_document(doc_id)
            fragments[doc_id] = doc[:2000]  # 片段
        return fragments
    
    def _preliminary_analysis(self, fragments: dict, task: str) -> str:
        """基于片段做初步分析"""
        context = "\n\n".join(fragments.values())
        return self.llm(f"背景信息:\n{context}\n\n任务: {task}")
    
    def _needs_deeper(self, analysis: str) -> bool:
        """判断是否需要更深的证据"""
        indicators = ["信息不足", "需要更多数据", "无法确定", 
                      "置信度低", "可能", "建议补充"]
        return any(ind in analysis for ind in indicators)
    
    def _identify_gaps(self, analysis: str) -> List[str]:
        """识别缺失的证据"""
        return self._analyze_task(analysis)  # 复用 L0 分析
    
    def _load_full(self, doc_ids: List[str]) -> Dict[str, str]:
        """L3: 加载完整证据"""
        return {did: self.retriever.get_document(did) 
                for did in doc_ids}
    
    def _final_analysis(self, fragments: dict, full: dict, task: str) -> str:
        """基于完整证据做最终分析"""
        all_evidence = {**fragments, **full}
        context = "\n\n".join(all_evidence.values())
        return self.llm(f"完整背景信息:\n{context}\n\n任务: {task}")
```

## 生产考量

### 延迟增加

渐进式信息披露增加了最多 3 次 LLM 调用（L0 分析、L1 选择、L2/3 分析），延迟相应增加。**缓解方案**:

```python
# 可使用小型模型做 L0 和 L1 决策
L0_MODEL = "claude-3-haiku"  # 快速、廉价
L2_MODEL = "claude-4-opus"   # 分析使用最强模型
```

### 缓存策略

L0 的分析结果（信息需求列表）可以缓存。对于相似问题，可直接复用而不需重新分析：

```python
cache_key = hashlib.md5(task.encode()).hexdigest()
if cache_key in task_analysis_cache:
    info_requests = task_analysis_cache[cache_key]
else:
    info_requests = analyze_task(task)
    task_analysis_cache[cache_key] = info_requests
```

## 关键概念速查表

| 概念 | 英文 | 定义 | 要点 |
|------|------|------|------|
| 渐进式信息披露 | Progressive Information Disclosure | 按需、分层地加载上下文信息 | 从 L0 到 L3 递进 |
| L0 任务定义 | Task Definition | 纯任务描述，无背景 | 模型先行理解需求 |
| L1 证据索引 | Evidence Index | 文档摘要/元数据清单 | 轻量级，300-500 tokens |
| L2 证据片段 | Evidence Fragments | 文档的关键段落 | 信息量与 token 的平衡 |
| L3 完整证据 | Full Evidence | 全文按需加载 | 仅当 L2 不足时触发 |
| 信息需求列表 | Information Request List | L0 阶段模型确定的信息需求 | 驱动后续所有加载决策 |
| 置信度触发 | Confidence Trigger | 低置信度自动升级到下一层 | <0.7 升级到 L3 |
