### 1.2 架构设计原则

本框架遵循四条核心设计原则：

**原则一：单向依赖** —— 运行时层依赖基础设施层，基础设施层的各模块之间无循环依赖。主循环不直接操作数据库，而是通过记忆层接口访问。

**原则二：依赖倒置** —— 每一层都通过抽象接口（Abstract Base Class / Protocol）定义合约，具体实现通过依赖注入注入。例如主循环不直接引用 OpenAI SDK，而是引用 `LLMProvider` 抽象。

**原则三：环绕式安全** —— 安全层是横切关注点，通过装饰器或中间件方式挂载到各层，不侵入主循环的业务逻辑。

**原则四：可观测性优先** —— 所有模块在关键路径打点，通过结构化日志暴露内部状态。可观测不是事后追加的，而是从第一天就内建在框架中。

## 二、各模块职责详解

### 2.1 主循环层 (Main Loop)

**核心职责**：管理 Agent 的 Think → Act → Observe 迭代循环，决定"什么时候停止"。

| 子模块 | 职责 |
|--------|------|
| Turn Manager | 管理每一轮的上下文组装、轮次计数、最大轮次限制 |
| Stop Hooks | 循环检测（是否原地打转）、最大轮次检测、目标达成检测 |
| Tool Executor | 调用注册的工具函数，处理同步/异步工具，超时控制 |
| Result Parser | 解析 LLM 输出中的 Tool Call 指令、JSON、结构化数据 |

**关键接口**：
```python
# 主循环核心接口
class AgentLoop(ABC):
    @abstractmethod
    async def run(self, task: str, context: Context) -> AsyncIterator[Turn]:
        ...

    @abstractmethod
    def register_stop_hook(self, hook: StopHook) -> None:
        ...
```

### 2.2 工具编排层 (Tool Orchestration Layer)

**核心职责**：管理工具注册、发现、调用、结果处理。

| 子模块 | 职责 |
|--------|------|
| Tool Registry | 工具注册中心，维护工具名称→工具的映射，支持按标签检索 |
| Schema Generator | 从 Python 函数签名自动生成 JSON Schema（用于 LLM Function Calling） |
| Executor | 工具执行引擎，处理参数校验、超时、重试、错误转换 |
| Result Processor | 将工具原始返回值转换为标准化的 Observation 格式 |

**关键接口**：
```python
class ToolRegistry:
    """工具注册中心"""
    
    def __init__(self):
        self._tools: dict[str, Tool] = {}
    
    def register(self, tool: Tool) -> None:
        """注册一个工具"""
        self._tools[tool.name] = tool
    
    def register_from_fn(self, fn: Callable, name: str = None, description: str = None) -> None:
        """从函数自动注册工具"""
        ...
    
    def get_schemas(self) -> list[dict]:
        """返回所有工具的 JSON Schema，用于 LLM Function Calling"""
        return [tool.openai_schema for tool in self._tools.values()]
    
    async def execute(self, name: str, args: dict[str, Any]) -> ToolResult:
        """执行指定工具"""
        if name not in self._tools:
            raise ToolNotFoundError(f"Tool '{name}' not found")
        return await self._tools[name].execute(args)
```

### 2.3 记忆层 (Memory Layer)

**核心职责**：持久化和管理 Agent 的对话历史、状态、知识。

| 子模块 | 职责 |
|--------|------|
| ShortTerm Memory | 当前会话的上下文窗口管理，滑动窗口 + 摘要 |
| LongTerm Memory | 跨会话的记忆持久化（向量数据库、SQLite、PostgreSQL） |
| Working Memory | 当前正在处理的任务状态、中间变量、临时数据 |
| Retrieval | 从长期记忆中检索相关记忆片段 |

详细设计见第 21.4 节「会话管理」，底层原理见第 7 章「记忆系统设计」。

**关键接口**：
```python
class Memory(ABC):
    @abstractmethod
    async def add(self, role: str, content: str, metadata: dict = None) -> None:
        ...
    
    @abstractmethod
    async def get_context(self, max_tokens: int = 4096) -> list[Message]:
        ...
    
    @abstractmethod
    async def clear(self) -> None:
        ...

class PersistentMemory(Memory):
    """持久化记忆 —— 支持会话恢复"""
    @abstractmethod
    async def snapshot(self, session_id: str) -> None:
        """保存当前会话快照"""
        ...
    
    @abstractmethod
    async def restore(self, session_id: str) -> None:
        """恢复指定会话"""
        ...
```

### 2.4 安全层 (Security Layer)

**核心职责**：防止恶意输入、保证输出安全、检测异常行为。

| 子模块 | 职责 |
|--------|------|
| Input Filter | Prompt Injection 检测、越狱检测、PII 脱敏、输入长度限制 |
| Output Guard | 内容合规检测、禁止输出模式过滤、敏感信息泄露检测 |
| Rate Limiter | 请求频率限制、Token 消耗限制、并发控制 |
| Audit Trail | 记录所有安全相关事件，供事后审计 |

详细设计与 Prompt Injection 攻防见第 17 章「安全防护」。

**关键接口**：
```python
class SecurityLayer:
    """安全层 —— 通过装饰器模式挂载到 Agent 运行时"""
    
    async def check_input(self, message: str) -> SecurityVerdict:
        """检查用户输入"""
        checks = [
            self._detect_prompt_injection(message),
            self._check_rate_limit(),
            self._validate_length(message),
        ]
        results = await asyncio.gather(*checks)
        return self._aggregate(results)
    
    async def check_output(self, response: str) -> SecurityVerdict:
        """检查模型输出"""
        ...
```

### 2.5 可观测层 (Observability Layer)

**核心职责**：提供链路追踪、指标监控、日志聚合。

| 子模块 | 职责 |
|--------|------|
| Tracer | 分布式链路追踪，记录每个 Turn 的完整调用链 |
| Metrics | Prometheus 指标：延迟分布、Token 消耗、工具调用成功率 |
| Logger | 结构化日志（JSON 格式），支持日志分级和动态采样 |
| Span Exporter | 将追踪数据导出到 Jaeger、OpenTelemetry Collector 等后端 |

详细设计见第 19 章「可观测性」。

**关键接口**：
```python
class Tracer:
    """链路追踪器 —— 使用 OpenTelemetry 规范"""
    
    @contextmanager
    def span(self, name: str, attributes: dict = None):
        """创建一个追踪 span"""
        span_id = str(uuid.uuid4())
        self._spans.append(Span(name=name, span_id=span_id, parent_id=self._current_span_id))
        self._current_span_id = span_id
        try:
            yield SpanContext(span_id=span_id)
        finally:
            self._current_span_id = self._spans[-1].parent_id
            self._export(span_id)
    
    def record_metric(self, name: str, value: float, tags: dict = None):
        """记录一个指标"""
        ...
```

### 3.2 模块间依赖关系（Dependency Graph）

```
                    Application
                        │
                    AgentLoop
                   /    |    \
          Provider  ToolRegistry  Memory
               \      |      /
           Infrastructure Layer
          /     |      |      \
     Security  Tracer  Logger  DB
```

关键约束：
- AgentLoop 通过抽象接口依赖 Provider/ToolRegistry/Memory，不依赖具体实现
- Infrastructure 层各模块之间平级，不互相调用
- Security 和 Tracer 通过依赖注入挂载到 AgentLoop，不影响主循环的核心逻辑

## 四、框架入口：最小可用实现

下面是一个将上述架构落地的框架入口代码。它展示了如何将各层组装成一个可运行的 Agent 系统：

```python
# framework/core.py
"""Agent 框架核心 —— 五层架构的组装入口"""

import asyncio
import logging
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from typing import Any, AsyncIterator, Callable, Optional

logger = logging.getLogger(__name__)


# ─── 1. 核心数据结构 ───

@dataclass
class Message:
    role: str        # "system" | "user" | "assistant" | "tool"
    content: str
    tool_call_id: Optional[str] = None
    tool_name: Optional[str] = None
    metadata: dict = field(default_factory=dict)

@dataclass
class Turn:
    """Agent 的一轮迭代"""
    turn_id: int
    thought: Optional[str] = None
    action: Optional[dict] = None
    observation: Optional[str] = None
    finish_reason: Optional[str] = None  # "goal_achieved" | "max_turns" | "loop_detected" | "error"

@dataclass
class Context:
    """上下文对象，在 Agent 各层之间传递"""
    messages: list[Message] = field(default_factory=list)
    metadata: dict = field(default_factory=dict)


# ─── 2. Provider 抽象（21.3 详述） ───

class LLMProvider(ABC):
    """LLM Provider 统一接口"""
    
    @abstractmethod
    async def chat(self, messages: list[Message], tools: list[dict] = None) -> Message:
        ...
    
    @abstractmethod
    async def chat_stream(self, messages: list[Message], tools: list[dict] = None) -> AsyncIterator[str]:
        ...


# ─── 3. 工具系统 ───

@dataclass
class ToolResult:
    success: bool
    data: Any
    error: Optional[str] = None

class Tool(ABC):
    name: str
    description: str
    
    @abstractmethod
    async def execute(self, args: dict[str, Any]) -> ToolResult:
        ...
    
    @property
    @abstractmethod
    def openai_schema(self) -> dict:
        ...


# ─── 4. 记忆层（21.4 详述） ───

class Memory(ABC):
    @abstractmethod
    async def add(self, role: str, content: str, metadata: dict = None) -> None:
        ...
    
    @abstractmethod
    async def get_context(self, max_tokens: int = 4096) -> list[Message]:
        ...
    
    @abstractmethod
    async def clear(self) -> None:
        ...


# ─── 5. 安全层（跨切面） ───

@dataclass
class SecurityVerdict:
    passed: bool
    reason: str = ""
    score: float = 1.0

class SecurityLayer:
    async def check_input(self, message: str) -> SecurityVerdict:
        # 基础实现：返回通过
        return SecurityVerdict(passed=True)
    
    async def check_output(self, response: str) -> SecurityVerdict:
        return SecurityVerdict(passed=True)


# ─── 6. 可观测层（跨切面） ───

@dataclass
class SpanContext:
    span_id: str

class Tracer:
    @contextmanager
    def span(self, name: str, attributes: dict = None):
        """创建一个追踪 span"""
        span_id = str(uuid.uuid4())
        logger.debug(f"[Trace] start span={name} id={span_id}")
        try:
            yield SpanContext(span_id=span_id)
        finally:
            logger.debug(f"[Trace] end span={name} id={span_id}")
    
    def record_metric(self, name: str, value: float, tags: dict = None):
        logger.debug(f"[Metric] {name}={value} tags={tags}")


# ─── 7. 框架组装 ───

class AgentFramework:
    """Agent 框架 —— 将所有层组装为完整的运行时"""
    
    def __init__(
        self,
        provider: LLMProvider,
        tool_registry: dict[str, Tool],
        memory: Memory,
        security: Optional[SecurityLayer] = None,
        tracer: Optional[Tracer] = None,
        max_turns: int = 20,
        loop_sensitivity: float = 0.85,
    ):
        self.provider = provider
        self.tools = tool_registry
        self.memory = memory
        self.security = security or SecurityLayer()
        self.tracer = tracer or Tracer()
        self.max_turns = max_turns
        self.loop_sensitivity = loop_sensitivity
    
    async def run(self, task: str, session_id: str = None) -> AsyncIterator[Turn]:
        """运行 Agent，返回 Turn 流"""
        with self.tracer.span("agent_run", {"task": task, "session_id": session_id}):
            # 安全检查
            verdict = await self.security.check_input(task)
            if not verdict.passed:
                yield Turn(turn_id=0, finish_reason="security_rejection")
                return
            
            # 添加用户消息到记忆
            await self.memory.add("user", task, {"session_id": session_id})
            
            # 恢复历史上下文
            context = await self.memory.get_context()
            
            # 执行主循环
            history = []
            async for turn in self._main_loop(context):
                yield turn
                if turn.finish_reason:
                    break
                history.append(turn)
            
            # 输出安全检查
            if history:
                last_turn = history[-1]
                if last_turn.observation:
                    out_verdict = await self.security.check_output(last_turn.observation)
                    if not out_verdict.passed:
                        yield Turn(turn_id=last_turn.turn_id, finish_reason="output_rejected")
    
    async def _main_loop(self, context: Context):
        """主循环 —— 详细实现见 21.2 节"""
        # 21.2 节将替换此处的占位实现
        yield Turn(turn_id=1, thought="Processing...", finish_reason="goal_achieved")
```

## 五、架构决策记录（ADR）

以下是在框架设计过程中需要做的重要决策及其理由：

### ADR-1：为何不采用 Plugin 架构？

- **方案**：Agent 框架是否可以做成 VS Code 那样的 Plugin 体系，让所有功能都是插件
- **否决理由**：Plugin 架构增加了启动复杂度（插件发现、版本冲突、依赖管理），而 Agent 框架的核心路径（主循环）不应被插件的加载机制干扰。本框架选择"模块化但非插件化"：模块是代码内组织方式，不引入动态加载。

### ADR-2：为何安全层和可观测层是横切关注点而非独立进程？

- **方案**：安全检查和链路追踪是否可以作为一个 Sidecar 进程运行？
- **决策**：在中小规模场景中，Sidecar 增加了部署复杂度（Kubernetes Sidecar、进程间通信延迟）。本框架将二者实现为框架内的横切关注点，通过依赖注入挂载。需要隔离时，可以部署为一个独立的 Agent 服务。

### ADR-3：为何主循环是 Async Generator？

- **方案**：Agent 的输出是一次性返回还是逐步流式？
- **决策**：选择 Async Generator 模式（`async def run() -> AsyncIterator[Turn]`），原因：
  1. 调用方可以实时获取每一步的进展（前端 SSE 推送）
  2. 支持在运行过程中注入中断（Stop Hooks）
  3. 方便做流式日志和调试
  详细实现见 21.2 节。

## 六、五层架构的演进路线

设计好的架构不是一步到位的，而是随着需求逐步演进：

### Phase 1：单体最小可用版
- 主循环 + 单 Provider + 内存记忆 + 基础工具系统
- 足够运行一个简单的 ReAct Agent
- 约 300 行代码

### Phase 2：多 Provider + 持久化
- 增加 Provider 适配层（21.3）
- 增加 SQLite 持久化记忆（21.4）
- 增加连接池复用（21.6）

### Phase 3：生产级加固
- 增加安全层（17 章）
- 增加可观测层（19 章）
- 增加流式通信支持（21.5）

### Phase 4：高可用部署
- 多 Provider 热切换（降级）
- 分布式会话管理
- 集群模式

本框架的设计目标是在 Phase 2 阶段做到可用的框架骨架，Phase 3/4 的能力通过"选配"方式接入。

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Agent Runtime | Agent 框架核心运行时，包含主循环和工具编排 |
| Memory Layer | 记忆层，负责对话历史持久化和上下文管理 |
| Security Layer | 安全层，负责 Prompt Injection 检测、输入输出过滤 |
| Observability Layer | 可观测层，负责链路追踪、指标监控、日志聚合 |
| Provider Adapter | Provider 适配层，屏蔽不同 LLM API 的差异 |
| Async Generator | 异步生成器，`async yield` 逐步产出结果 |
| Tool Registry | 工具注册中心，管理工具发现和调用 |
| Span | 链路追踪中的基本单位，记录一次操作的生命周期 |
| 关键路径 | Agent 推理过程中对延迟和正确性最关键的执行路径 |
