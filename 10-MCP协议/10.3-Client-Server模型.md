# 10.3 Client/Server 模型

> MCP 采用经典的 Client/Server 架构：客户端（Client）是 AI 应用（如 Claude Code、Cursor），服务器端（Server）是工具或数据源的提供方。两者通过 JSON-RPC 2.0 协议进行通信。本章详细拆解通信流程、核心方法、安全模型和完整实现代码。

---

## 一、Client/Server 架构总览

### 1.1 角色定义

MCP 协议中有三个核心角色：

| 角色 | 职责 | 例子 |
|------|------|------|
| **MCP Host** | 用户直接交互的宿主程序，负责管理多个 Client 连接 | Claude Code、Cursor、VS Code AI 插件 |
| **MCP Client** | 与 Server 建立一对一连接的协议客户端，维护会话状态 | Host 内部的连接管理器 |
| **MCP Server** | 提供工具、资源和提示模板的轻量级服务器进程 | 文件系统服务器、数据库服务器、浏览器服务器 |

Host 与 Client 的关系：一个 Host 可以管理多个 Client，每个 Client 连接一个 Server。

```
┌──────────────────────────────────────────────────┐
│                  MCP Host（宿主）                   │
│  ┌────────────────────────────────────────────┐  │
│  │         MCP Client Manager                  │  │
│  │                                              │  │
│  │  ┌──────────┐   ┌──────────┐   ┌──────────┐ │  │
│  │  │ Client A  │   │ Client B │   │ Client C │ │  │
│  │  │ (Stdio)   │   │ (SSE)    │   │ (HTTP)   │ │  │
│  │  └─────┬────┘   └────┬─────┘   └─────┬────┘ │  │
│  └────────┼──────────────┼───────────────┼──────┘  │
└───────────┼──────────────┼───────────────┼─────────┘
            │              │               │
     ┌──────▼──┐    ┌──────▼──┐     ┌─────▼─────┐
     │ Server  │    │ Server  │     │  Server   │
     │ 本地文件 │    │ Web搜索  │     │  数据库   │
     └─────────┘    └─────────┘     └───────────┘
```

### 1.2 生命周期

一次完整的 MCP 连接包含以下阶段：

```
阶段 1：初始化（Initialization）
  Client → Server: initialize（协议版本 + 能力协商）
  Server → Client: 返回支持的协议版本和自身能力
  Client → Server: initialized（确认初始化完成）
  ─── 连接建立完成 ───

阶段 2：工具发现（Tool Discovery）
  Client → Server: list_tools
  Server → Client: 返回可用工具列表（名称 + 描述 + JSON Schema）

阶段 3：正常运行（Operation）
  Client → Server: call_tool / read_resource / list_resources / list_prompts / get_prompt
  Server → Client: 返回对应的结果

阶段 4：关闭（Shutdown）
  Client → Server: close（或传输层断开）
  ─── 连接结束 ───
```

## 二、核心方法详解

### 2.1 方法总表

MCP 协议定义了 6 个核心方法（Methods），分为三个原语类别：

```
Tools（工具）原语：
  list_tools     → 列出所有可用工具及 Schema
  call_tool      → 调用指定工具，传入参数，获取结果

Resources（资源）原语：
  list_resources → 列出所有可用资源
  read_resource  → 读取指定 URI 的资源内容

Prompts（提示模板）原语：
  list_prompts   → 列出所有可用提示模板
  get_prompt     → 获取指定提示模板的具体内容
```

### 2.2 call_tool 完整通信流程

以下展示一次完整的工具调用通信流程，包含所有细节：

```
                                                                       时间流
┌─────────┐                  ┌──────────┐                  ┌───────────┐  │
│  LLM     │                  │ MCP      │                  │ MCP       │  │
│  (模型)   │                  │ Client   │                  │ Server    │  │
└────┬────┘                  └────┬─────┘                  └─────┬─────┘  │
     │                            │                              │         │
     │  1. 模型决定调用工具        │                              │         │
     │  "我需要 search_web"       │                              │         │
     │                            │                              │         │
     │  2. 工具调用请求           │                              │         │
     │─────────────────────────→  │  3. JSON-RPC call_tool       │         │
     │                            │────────────────────────────→ │         │
     │                            │                              │         │
     │                            │  4. Server 执行工具逻辑      │         │
     │                            │     - 验证参数 Schema        │         │
     │                            │     - 执行具体操作           │         │
     │                            │     - 处理错误/超时          │         │
     │                            │                              │         │
     │                            │  5. 返回执行结果             │         │
     │                            │←──────────────────────────── │         │
     │                            │                              │         │
     │  6. Client 格式化结果      │                              │         │
     │  注入模型上下文            │                              │         │
     │←─────────────────────────  │                              │         │
     │                            │                              │         │
     │  7. 模型基于结果生成回答    │                              │         ▼
     │  "北京明天有雨，气温..."    │                              │
```

对应的 JSON-RPC 消息：

```json
// 步骤 3: Client 发送 call_tool 请求
// → Client → Server
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "method": "call_tool",
  "params": {
    "name": "search_web",
    "arguments": {
      "query": "北京 明天 天气预报 2026-06-02",
      "max_results": 3
    }
  }
}

// 步骤 5: Server 返回执行结果
// ← Server → Client
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "北京2026年6月2日天气预报：\n"
               + "白天：小雨，23-28°C，东风3-4级\n"
               + "夜间：多云，18-22°C，微风\n"
               + "降水概率：65%\n"
               + "来源：中国天气网"
      },
      {
        "type": "resource",
        "resource": {
          "uri": "file:///weather/result.html",
          "mimeType": "text/html"
        }
      }
    ],
    "isError": false
  }
}
```

### 2.3 read_resource 完整通信流程

资源读取流程与工具调用类似，但针对的是**数据读取**而非**动作执行**：

```json
// Client 请求读取资源
{
  "jsonrpc": "2.0",
  "id": "req-002",
  "method": "read_resource",
  "params": {
    "uri": "file:///data/project_config.json"
  }
}

// Server 响应
{
  "jsonrpc": "2.0",
  "id": "req-002",
  "result": {
    "contents": [
      {
        "uri": "file:///data/project_config.json",
        "mimeType": "application/json",
        "text": "{\n  \"project\": \"ai-agent\",\n  \"version\": \"2.1.0\",\n  \"env\": \"production\"\n}"
      }
    ]
  }
}
```

资源 URI 的设计要点：
- **URI Scheme** 表示资源类型（file, db, api, notion, clipboard 等）
- **URI Path** 表示资源的具体路径
- **MIME Type** 告诉 Client 返回内容的格式
- 资源内容可以是文本（text）或二进制（blob）

## 三、传输层（Transport Layer）

MCP 支持两种主要的传输方式：

### 3.1 Stdio 传输（标准输入/输出）

适用于**本地进程间通信**。Client 启动 Server 作为子进程，通过 stdin/stdout 传输 JSON-RPC 消息。

```
MCP Host (Claude Code)
    │
    ├── fork/exec──→ MCP Server 进程（子进程）
    │                    │
    │  ┌── stdin ──────→ 读取 JSON-RPC 请求
    │  │                 处理请求
    │  └──←── stdout ──  写入 JSON-RPC 响应
    │
    ├── fork/exec──→ MCP Server 数据库（子进程）
    └── fork/exec──→ MCP Server 文件系统（子进程）
```

**Stdio 的优点**：
- 不需要网络端口绑定，安全性高
- 子进程的权限由 Host 管理，天然隔离
- 延迟低（管道通信，约 0.1-1ms）

**Stdio 的缺点**：
- 只能本地通信，不能远程
- 需要 Host 管理子进程生命周期

### 3.2 SSE 传输（Server-Sent Events）

适用于**远程通信**。Client 通过 HTTP 连接到远程的 MCP Server，Server 通过 SSE 向 Client 推送消息。

```
MCP Host (云的AI应用)                 远程 MCP Server
    │                                      │
    │  HTTP POST /message ────────────────→ │
    │  (发送 JSON-RPC 请求)                  │
    │                                       │
    │  ←── SSE stream ─────────────────── │
    │  (持续接收 JSON-RPC 响应)              │
```

**SSE 的优点**：
- 支持远程部署，Server 可以在云端
- 多个 Client 可以共享同一个 Server

**SSE 的缺点**：
- 需要网络连接，延迟较高
- 需要额外的认证和加密（HTTPS）

### 3.3 Streamable HTTP（最新传输标准）

MCP 规范的最新版本引入了 Streamable HTTP 传输，结合了 HTTP 的简单性和 SSE 的流式能力：

- 使用标准 HTTP POST 发送请求
- 服务端可响应完整的 JSON-RPC 响应，也可通过 SSE 流式返回
- 兼容标准 HTTP 基础设施（负载均衡、反向代理、CDN）

### 3.4 MCP Tunnels（2026 年 5 月新增）

MCP Tunnels 是 2026 年 5 月引入的企业级传输方式，解决 Agent 安全访问内网资源的问题：

```
远程 AI Agent                         企业内网
    │                                      │
    │  1. Agent 发起 MCP Tunnel 连接        │
    │─────────────────────────────────────→ │
    │                                       │
    │  2. 双向加密隧道建立                   │
    │  ←─────────── TLS ──────────────────→ │
    │                                       │
    │  3. Agent ↔ MCP Tunnel ↔ 内网服务     │
    │  ┌────────┐    ┌──────────┐    ┌────┐ │
    │  │ Agent  │───→│ MCP      │───→│ DB │ │
    │  │        │←───│ Tunnel   │←───│ API│ │
    │  └────────┘    └──────────┘    │ KB │ │
    │                                └────┘ │
```

**MCP Tunnels 的核心特性**：
- **单向发起**：仅 Agent 发起出站连接，内网无需开放入站端口
- **加密通信**：全程 TLS 加密，防止中间人攻击
- **零信任架构**：每次请求都需要认证和授权，不依赖网络边界
- **审计日志**：所有通过 Tunnel 的数据流被记录，满足合规要求

## 四、完整 MCP Server 实现

以下是一个完整的 MCP Server 实现，使用 Python 的官方 SDK：

```python
"""
mcp_server.py — 一个完整的 MCP Server 示例
提供：文件搜索、天气查询、系统信息三个工具
"""

import json
import os
import subprocess
import datetime
from typing import Any
from mcp.server import Server, NotificationOptions
from mcp.server.models import InitializationOptions
from mcp.types import (
    GetPromptResult,
    Prompt,
    PromptMessage,
    ReadResourceResult,
    Resource,
    TextContent,
    Tool,
    ListToolsResult,
    CallToolResult,
)

# ============================================
# 1. 创建 Server 实例
# ============================================
app = Server("ai-agent-server")


# ============================================
# 2. 工具发现：list_tools
# ============================================
@app.list_tools()
async def list_tools() -> list[Tool]:
    """
    返回所有可用工具及其 Schema。
    这是 MCP 的"动态发现"核心方法。
    """
    return [
        Tool(
            name="search_files",
            description="在指定目录中搜索文件，支持通配符模式",
            inputSchema={
                "type": "object",
                "properties": {
                    "pattern": {
                        "type": "string",
                        "description": "文件搜索模式（如 *.py, **/*.md）"
                    },
                    "root_dir": {
                        "type": "string",
                        "description": "搜索根目录",
                        "default": "."
                    },
                    "max_results": {
                        "type": "integer",
                        "description": "返回结果数上限",
                        "default": 20
                    }
                },
                "required": ["pattern"]
            }
        ),
        Tool(
            name="get_weather",
            description="查询指定城市的当前天气",
            inputSchema={
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "城市名称（中文）"
                    },
                    "date": {
                        "type": "string",
                        "description": "日期，格式 YYYY-MM-DD，默认今天"
                    }
                },
                "required": ["city"]
            }
        ),
        Tool(
            name="get_system_info",
            description="获取系统信息（CPU、内存、磁盘）",
            inputSchema={
                "type": "object",
                "properties": {},
                "required": []
            }
        ),
    ]


# ============================================
# 3. 工具执行：call_tool
# ============================================
@app.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    """
    执行工具调用。
    根据工具名称路由到对应的处理函数。
    """
    if name == "search_files":
        return await _search_files(arguments)
    elif name == "get_weather":
        return await _get_weather(arguments)
    elif name == "get_system_info":
        return await _get_system_info(arguments)
    else:
        raise ValueError(f"未知工具: {name}")


async def _search_files(args: dict) -> list[TextContent]:
    """执行文件搜索"""
    pattern = args["pattern"]
    root_dir = args.get("root_dir", ".")
    max_results = args.get("max_results", 20)
    
    try:
        # 使用 find 命令搜索文件
        result = subprocess.run(
            ["find", root_dir, "-name", pattern],
            capture_output=True,
            text=True,
            timeout=10
        )
        
        files = result.stdout.strip().split("\n")
        files = [f for f in files if f]  # 过滤空行
        files = files[:max_results]  # 限制数量
        
        if not files:
            return [TextContent(
                type="text",
                text=f"在 {root_dir} 中未找到匹配 '{pattern}' 的文件"
            )]
        
        response = f"找到 {len(files)} 个匹配文件（显示前 {max_results} 个）:\n"
        response += "\n".join(files)
        
        return [TextContent(type="text", text=response)]
    
    except subprocess.TimeoutExpired:
        return [TextContent(
            type="text",
            text="文件搜索超时（10秒），请缩小搜索范围"
        )]
    except Exception as e:
        return [TextContent(
            type="text",
            text=f"搜索出错: {str(e)}"
        )]


async def _get_weather(args: dict) -> list[TextContent]:
    """模拟天气查询（实际项目应调用真实天气 API）"""
    city = args["city"]
    date = args.get("date", datetime.date.today().isoformat())
    
    # 示例：返回模拟数据
    # 实际项目中在此处调用 weather API
    response = (
        f"🌤 {city} {date} 天气预报\n"
        f"温度：22-28°C\n"
        f"天气：多云转晴\n"
        f"湿度：45-60%\n"
        f"风力：微风 2-3级\n"
        f"降水概率：20%\n"
        f"更新时间：{datetime.datetime.now().strftime('%H:%M')}"
    )
    
    return [TextContent(type="text", text=response)]


async def _get_system_info(args: dict) -> list[TextContent]:
    """获取系统信息"""
    import psutil
    
    cpu_percent = psutil.cpu_percent(interval=1)
    memory = psutil.virtual_memory()
    disk = psutil.disk_usage("/")
    
    response = (
        f"系统信息\n"
        f"{'='*30}\n"
        f"CPU 使用率：{cpu_percent}%\n"
        f"内存使用：{memory.percent}% ({memory.used // (1024**3)}GB/{memory.total // (1024**3)}GB)\n"
        f"磁盘使用：{disk.percent}% ({disk.used // (1024**3)}GB/{disk.total // (1024**3)}GB)\n"
        f"进程数：{len(psutil.pids())}\n"
        f"系统时间：{datetime.datetime.now().isoformat()}"
    )
    
    return [TextContent(type="text", text=response)]


# ============================================
# 4. 资源提供（可选）
# ============================================
@app.list_resources()
async def list_resources() -> list[Resource]:
    """列出可读取的资源"""
    return [
        Resource(
            uri="file:///etc/hostname",
            name="hostname",
            description="当前主机名",
            mimeType="text/plain"
        )
    ]


@app.read_resource()
async def read_resource(uri: str) -> str:
    """读取指定资源"""
    if uri == "file:///etc/hostname":
        with open("/etc/hostname", "r") as f:
            return f.read()
    raise ValueError(f"未知资源: {uri}")


# ============================================
# 5. 启动 Server
# ============================================
async def main():
    """主入口"""
    async with app.run_stdio() as server:
        await server.wait_for_shutdown()

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

## 五、完整 MCP Client 实现

以下是一个完整的 MCP Client 实现，可与上面的 Server 配合使用：

```python
"""
mcp_client.py — 一个完整的 MCP Client 示例
通过 Stdio 传输连接到 MCP Server
"""

import asyncio
import json
import sys
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


class MCPClient:
    """MCP 客户端，管理连接和工具调用"""
    
    def __init__(self, server_command: str, server_args: list[str]):
        self.server_params = StdioServerParameters(
            command=server_command,
            args=server_args
        )
        self.session: ClientSession | None = None
        self.tools_cache: list[dict] | None = None
    
    async def connect(self) -> None:
        """
        建立连接并完成初始化握手。
        
        连接流程：
        1. 启动 Server 子进程
        2. 创建 ClientSession
        3. 发送 initialize 请求（协议版本协商）
        4. 接收 Server 的能力声明
        5. 连接就绪
        """
        # 创建 stdio 客户端连接
        self.stdio, self.write = await stdio_client(self.server_params)
        
        # 创建会话并初始化
        self.session = await ClientSession.create(
            self.stdio, self.write
        )
        
        print(f"[MCP Client] 已连接到 Server: {self.server_params.command}")
    
    async def list_tools(self) -> list[dict]:
        """
        获取所有可用工具（使用缓存加速）。
        
        首次调用时请求 Server，后续使用缓存。
        调用 refresh_tools() 可强制刷新。
        """
        if self.tools_cache is None:
            response = await self.session.list_tools()
            self.tools_cache = [
                {
                    "name": tool.name,
                    "description": tool.description,
                    "inputSchema": tool.inputSchema
                }
                for tool in response.tools
            ]
            print(f"[MCP Client] 发现 {len(self.tools_cache)} 个工具")
        
        return self.tools_cache
    
    async def refresh_tools(self) -> list[dict]:
        """强制刷新工具缓存"""
        self.tools_cache = None
        return await self.list_tools()
    
    async def call_tool(self, name: str, arguments: dict) -> str:
        """
        调用指定工具。
        
        Args:
            name: 工具名称
            arguments: 参数字典
            
        Returns:
            工具执行结果的文本内容
        """
        print(f"[MCP Client] 调用工具: {name}({json.dumps(arguments, ensure_ascii=False)})")
        
        result = await self.session.call_tool(name, arguments)
        
        # 提取文本内容
        text_parts = [
            content.text 
            for content in result.content 
            if content.type == "text"
        ]
        response = "\n".join(text_parts)
        
        print(f"[MCP Client] 工具返回: {response[:100]}...")
        return response
    
    async def close(self):
        """关闭连接"""
        if self.session:
            await self.session.close()
        print("[MCP Client] 连接已关闭")


async def main():
    """演示 MCP Client 的使用"""
    
    # 1. 创建 Client 并连接
    client = MCPClient("python", ["mcp_server.py"])
    await client.connect()
    
    try:
        # 2. 发现工具
        tools = await client.list_tools()
        print("\n可用工具列表:")
        for t in tools:
            print(f"  - {t['name']}: {t['description']}")
        
        # 3. 调用工具
        print("\n" + "="*50)
        
        # 3.1 查询系统信息
        result = await client.call_tool("get_system_info", {})
        print(result)
        
        print("\n" + "="*50)
        
        # 3.2 查询天气
        result = await client.call_tool("get_weather", {
            "city": "北京",
            "date": "2026-06-02"
        })
        print(result)
        
        print("\n" + "="*50)
        
        # 3.3 搜索文件
        result = await client.call_tool("search_files", {
            "pattern": "*.py",
            "root_dir": ".",
            "max_results": 5
        })
        print(result)
        
    finally:
        # 4. 关闭连接
        await client.close()


if __name__ == "__main__":
    asyncio.run(main())
```

## 六、安全沙箱模型

### 6.1 安全架构分层

MCP 的安全模型分为四个层级：

```
层级 1: 进程隔离
  ┌────────────────────────────┐
  │  MCP Host                  │
  │  工具调用请求 → Stdio管道   │
  └────────┬───────────────────┘
           │ 独立的操作系统进程
  ┌────────▼───────────────────┐
  │  MCP Server（子进程）       │
  │  只能访问被授权的资源       │
  └────────────────────────────┘

层级 2: 权限声明
  每个 MCP Server 在初始化时声明自己需要的权限：
  - filesystem: read, write
  - network: api.example.com
  - env: DATABASE_URL

层级 3: 用户授权
  Host 在每次高风险操作前向用户确认：
  "MCP Server 'FileSystem' 想要写入文件 /data/config.json，是否允许？"

层级 4: 沙箱执行
  - Linux: 可使用 bubblewrap / nsjail / Docker 容器
  - Windows: 可使用 AppContainer / 受限 Token
  - macOS: 可使用 sandbox-exec / Seatbelt
```

**2026 年新增：Self-Hosted Sandboxes（自托管沙箱）**

2026 年 5 月，MCP 引入了 Self-Hosted Sandboxes 能力，允许企业客户将代码执行环境迁移到自有基础设施：

- 支持平台：Cloudflare、Daytona、Modal、Vercel
- Agent 推理循环保留在 Anthropic 云
- 代码执行在企业自有沙箱中完成
- 解决了企业数据主权和合规问题

```
Self-Hosted Sandbox 架构（2026）：
┌─────────────────┐         ┌──────────────────────────┐
│  Anthropic Cloud│         │   企业基础设施              │
│                 │         │                          │
│  Agent Loop     │←── TLS──→  Self-Hosted Sandbox     │
│  (推理/决策)     │         │  (代码执行)               │
│                 │         │  Cloudflare/Daytona/Modal │
└─────────────────┘         └──────────────────────────┘
```

### 6.2 STDIO RCE 安全漏洞（2026 年 4 月）

2026 年 4 月，OX Security 披露了一个影响所有 MCP SDK 语言的严重安全漏洞：

> **漏洞描述**：STDIO 传输在执行 MCP Server 前无条件执行进程命令。攻击者可以构造恶意的 MCP Server 配置，在宿主系统上执行任意代码。

**影响评估**：
- 影响范围：约 1.5 亿次 SDK 下载、7000+ 公共 Server、最多 20 万个易受攻击实例
- CVE 编号：待分配
- 攻击向量：通过 `command` 参数注入恶意进程

**Anthropic 的官方回应**：
Anthropic 确认这是"有意设计"（by design），并拒绝在协议架构层面修补。理由：STDIO 的设计前提是"运行一个受信任的进程"，安全性应由宿主环境（进程隔离、容器、沙箱）保障，而非协议本身。

**社区影响**：
- 推动了沙箱执行和 MCP Tunnels 的广泛采用
- 促进了 Server 签名验证机制的讨论
- 强化了"最小权限原则"的工程实践

### 6.3 安全最佳实践（2026 更新版）

```python
# MCP Server 的安全配置清单

SERVER_SECURITY_CONFIG = {
    # 文件系统访问限制
    "allowed_paths": ["/data", "/home/user/projects"],  # 白名单路径
    "denied_paths": ["/etc", "/sys", "/proc"],          # 黑名单路径
    "read_only": False,                                  # 是否只读
    
    # 网络访问限制
    "allowed_domains": ["api.weather.com", "api.github.com"],
    "denied_domains": ["internal.company.com", "localhost:3306"],
    "allow_localhost": False,
    
    # 系统资源限制
    "max_memory_mb": 512,        # 最大内存
    "max_cpu_percent": 50,       # 最大 CPU 使用率
    "max_processes": 10,         # 最大子进程数
    "timeout_seconds": 30,       # 工具调用超时
    "max_output_size": 10*1024*1024,  # 最大输出 10MB
    
    # 审计日志
    "log_all_calls": True,       # 记录所有工具调用
    "log_sensitive_params": False # 是否记录敏感参数
}
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| MCP Host | 用户直接交互的宿主程序（如 AI 应用） |
| MCP Client | 与 Server 一对一连接的协议客户端 |
| MCP Server | 提供工具/资源的独立进程 |
| JSON-RPC 2.0 | MCP 使用的远程过程调用协议 |
| Stdio Transport | 通过 stdin/stdout 的本地进程间通信 |
| SSE Transport | 基于 Server-Sent Events 的远程通信 |
| list_tools | 工具发现方法，返回可用工具列表及 Schema |
| call_tool | 工具调用方法，执行指定工具并返回结果 |
| read_resource | 资源读取方法，通过 URI 读取数据 |
| 进程隔离 | 每个 MCP Server 运行在独立的操作系统进程中 |
| 初始化握手 | Client 和 Server 在连接建立时进行协议协商 |
| 安全沙箱 | 限制 MCP Server 对系统资源的访问范围 |
| MCP Tunnels | 单向加密网关，Agent 安全访问内网服务（2026.05） |
| Self-Hosted Sandboxes | 企业自有基础设施上的代码执行沙箱（2026.05） |
| STDIO RCE | 2026 年 4 月被披露的 STDIO 远程代码执行漏洞 |
