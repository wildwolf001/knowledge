# 18.4 静默失败的检测

> Agent 最危险的失败不是报错，而是"看起来一切正常，但实际上在做无用功"。静默失败（Silent Failure）指 Agent 没有抛出异常、没有返回错误码，但输出是错的、行为是无意义的，或者正在偏离目标轨道而不自知。

---

## 一、什么是静默失败？

### 1.1 显式失败 vs 静默失败

```python
# 显式失败——容易发现、容易处理
try:
    result = call_llm_api()
except APIError as e:
    # 错误明确，可以重试或 Fallback
    handle_error(e)

# 静默失败——难以发现、难以处理
result = agent.run("帮我计算第一季度营收")
# result 是一个看起来完整但实际上用了错误数据的报告
# 没有异常、没有警告，一切看起来都正常
```

**静默失败**（Silent Failure）是指系统在没有任何显式的错误信号（异常、错误码、超时）的情况下，产生了不正确或不可用的结果。

### 1.2 为什么 Agent 系统特别容易发生静默失败

Agent 系统的三层结构决定了静默失败的高风险：

```
LLM 层：   模型总是"自信地"输出某种结果，几乎不会说"我不知道"
   ↓
Agent 层： 将 LLM 输出解析为"有效"的动作，格式正确就认为成功
   ↓
任务层：   结果看似完整但可能基于错误的中间推理
```

每一层都对下一层隐藏了不确定性。LLM 从不报告"我不确定这个参数"，Agent 框架通常只检查格式正确性而不检查语义正确性。

### 1.3 静默失败的严重后果

| 后果 | 说明 | 案例 |
|------|------|------|
| **错误累积** | 静默失败不触发重试机制，错误会持续传播 | 错误的 SQL 查询 → 后续所有分析基于错误数据 |
| **信任侵蚀** | 用户发现 Agent 产出明显错误时，信任被破坏 | "上次那个报告完全错了，以后不能信它了" |
| **调试困难** | 没有错误日志，难以定位失败发生在哪一步 | 需要在每一步都打关键指标日志才能追溯 |
| **资源浪费** | Agent 在错误路径上持续运行，消耗时间和费用 | 工具调用循环暴增，API 费用成倍增加 |

---

## 二、静默失败的四类检测信号

根据实际生产环境的数据，静默失败可以通过四类行为信号来检测。以下是每类信号的具体指标、阈值和检测方法。

### 2.1 信号 A：重复重规划（Repeated Replanning）

**现象**：Agent 反复重新规划同一个子任务，无法推进到下一步。

```
Agent 日志（异常模式）：
Step 3: 规划 → "我需要查询用户信息"
Step 4: 规划 → "让我先查询用户信息"  
Step 5: 规划 → "首先，查询用户信息"
Step 6: 规划 → "要完成这个任务，第一步是查询用户信息"
         ↑ 每次产出不同的表述，但都是同一个步骤
```

**检测指标**：

| 指标 | 公式 | 阈值 | 说明 |
|------|------|------|------|
| 语义重复率 | 连续 N 步的步骤描述的语义相似度 | > 0.85 | N 建议 ≥ 3 |
| 进度停滞步数 | 最后推进的步骤索引未更新的步数 | > 5 步 | 步骤索引不变就是卡住了 |
| 重规划频率 | 同一步骤被重新规划的绝对次数 | > 3 次 | 重规划本身不是问题，反复重规划是 |

**检测实现**：

```python
import numpy as np
from collections import deque

class ReplanningDetector:
    """
    重复重规划检测器
    
    监控 Agent 的步骤描述序列，检测语义上重复但
    未被推进的重规划行为。
    """
    
    def __init__(
        self, 
        window_size: int = 5,
        similarity_threshold: float = 0.85,
        max_replan_count: int = 3,
    ):
        self.step_descriptions = deque(maxlen=window_size)
        self.step_indices = deque(maxlen=window_size)
        self.replan_count = 0
        self.last_advanced_step = -1
        self.advance_stall_count = 0
        self.similarity_threshold = similarity_threshold
        self.max_replan_count = max_replan_count
    
    def observe(self, step_description: str, step_index: int) -> Dict:
        """
        观察 Agent 的一步执行
        
        Returns:
            dict: 包含检测结果的字典
                  {"is_replanning_loop": bool, "detail": str}
        """
        self.step_descriptions.append(step_description)
        self.step_indices.append(step_index)
        
        # 信号 1: 进度停滞检测
        if step_index == self.last_advanced_step:
            self.advance_stall_count += 1
        else:
            self.last_advanced_step = step_index
            self.advance_stall_count = 0
        
        # 信号 2: 语义重复检测
        avg_similarity = self._compute_avg_similarity()
        if avg_similarity > self.similarity_threshold:
            self.replan_count += 1
        else:
            # 一旦出现新的不同步骤，重置重规划计数
            self.replan_count = max(0, self.replan_count - 1)
        
        is_stuck = (
            self.advance_stall_count >= 5 or
            self.replan_count >= self.max_replan_count
        )
        
        return {
            "is_replanning_loop": is_stuck,
            "advance_stall_count": self.advance_stall_count,
            "replan_count": self.replan_count,
            "avg_similarity": avg_similarity,
            "detail": self._build_detail(),
        }
    
    def _compute_avg_similarity(self) -> float:
        """计算窗口内步骤描述的语义平均相似度"""
        if len(self.step_descriptions) < 2:
            return 0.0
        
        # 计算相邻步骤的语义相似度（使用 text embedding）
        similarities = []
        for i in range(1, len(self.step_descriptions)):
            sim = self._cosine_similarity(
                self.step_descriptions[i-1],
                self.step_descriptions[i]
            )
            similarities.append(sim)
        
        return np.mean(similarities) if similarities else 0.0
    
    def _cosine_similarity(self, text_a: str, text_b: str) -> float:
        """计算两个文本的余弦相似度"""
        # 生产环境中用 embedding 模型计算
        # 这里简化用基于 token 的 Jaccard 相似度作为近似
        tokens_a = set(text_a.lower().split())
        tokens_b = set(text_b.lower().split())
        if not tokens_a or not tokens_b:
            return 0.0
        intersection = tokens_a & tokens_b
        union = tokens_a | tokens_b
        return len(intersection) / len(union)
    
    def _build_detail(self) -> str:
        """构建检测详情"""
        parts = []
        if self.advance_stall_count >= 5:
            parts.append(f"进度停滞 {self.advance_stall_count} 步")
        if self.replan_count >= self.max_replan_count:
            parts.append(f"重规划 {self.replan_count} 次")
        return "; ".join(parts) if parts else "正常"
```

### 2.2 信号 B：工具调用暴增（Tool Call Explosion）

**现象**：Agent 在同一任务中调用工具的次数远超正常水平，典型模式是调用同一个工具多次但都不推进任务。

```
正常模式：
search("Q1 营收数据") → extract_numbers(...) → calculate_sum(...) → done
工具调用次数：3

异常模式：  
search("Q1 营收数据") → search("Q1 营收 2024") → search("Q1 收入")
→ search("第一季度营收") → search("Q1 revenue") → search("财报 Q1")
工具调用次数：6+（且持续增长）
```

**检测指标**：

| 指标 | 公式 | 阈值 | 说明 |
|------|------|------|------|
| 调用频率 | 工具调用次数 / 任务运行时间 | > 正常值 3x | 基于该任务类型的基线 |
| 空转比例 | 返回空结果或错误结果的调用占比 | > 50% | 结果对任务没有推进作用 |
| 单一工具重复率 | 同一工具的连续调用次数 | > 3 次 | 反复调用同一个工具却无进展 |
| 总调用数 | 任务的工具调用总数 | > 任务类型 P95 | 超过同类型任务 95% 分位数 |

**检测实现**：

```python
from collections import defaultdict

class ToolCallExplosionDetector:
    """工具调用暴增检测器"""
    
    def __init__(self):
        self.task_tool_counts: Dict[str, List[int]] = defaultdict(list)
        # 预配置各任务类型的正常调用基线
        self.baselines = {
            "qa": {"mean": 2, "p95": 5},
            "data_analysis": {"mean": 5, "p95": 12},
            "code_generation": {"mean": 3, "p95": 8},
            "web_research": {"mean": 8, "p95": 20},
        }
    
    def observe(
        self,
        task_type: str,
        tool_calls: List[Dict],
    ) -> Dict:
        """
        观察工具调用序列
        
        Args:
            task_type: 任务类型
            tool_calls: 本轮所有工具调用列表，每项包含 name, result_status
        
        Returns:
            检测结果
        """
        baseline = self.baselines.get(task_type, {"mean": 3, "p95": 8})
        
        total_calls = len(tool_calls)
        empty_calls = sum(
            1 for c in tool_calls 
            if c.get("result_status") == "empty"
        )
        error_calls = sum(
            1 for c in tool_calls 
            if c.get("result_status") == "error"
        )
        empty_ratio = empty_calls / max(total_calls, 1)
        
        # 检测单一工具重复
        tool_sequence = [c["name"] for c in tool_calls]
        max_consecutive = self._max_consecutive_repeat(tool_sequence)
        
        is_exploding = (
            total_calls > baseline["p95"] or
            empty_ratio > 0.5 or
            max_consecutive > 3
        )
        
        return {
            "is_tool_call_explosion": is_exploding,
            "total_calls": total_calls,
            "baseline_p95": baseline["p95"],
            "empty_ratio": empty_ratio,
            "max_consecutive_same_tool": max_consecutive,
            "detail": (
                f"调用 {total_calls} 次 (基线 P95: {baseline['p95']}), "
                f"空结果率 {empty_ratio:.0%}, "
                f"连续重复 {max_consecutive} 次"
            ),
        }
    
    def _max_consecutive_repeat(self, seq: List[str]) -> int:
        """计算序列中同一工具连续重复的最大次数"""
        if not seq:
            return 0
        max_count = 1
        current = 1
        for i in range(1, len(seq)):
            if seq[i] == seq[i-1]:
                current += 1
                max_count = max(max_count, current)
            else:
                current = 1
        return max_count
```

### 2.3 信号 C：状态漂移（State Drift）

**现象**：Agent 内部维护的"任务状态"与实际情况不一致。Agent 认为自己在做步骤 X，但实际上已经偏离了任务目标。

**常见模式**：

```
状态漂移类型 1：目标遗忘
初始目标："计算 Q1 到 Q3 的营收增长率"
5 步之后 Agent 在做："整理公司的组织架构"
└── Agent 完全忘记了原始目标

状态漂移类型 2：上下文污染
Agent 之前输出了一个错误的计算结果，后续所有推理
基于这个错误结果展开，但 Agent 不认为自己错了

状态漂移类型 3：工具滥用
Agent 开始用计算器工具做"推理"，用搜索工具做"验证"，
工具的使用方式严重偏离设计意图
```

**检测指标**：

| 指标 | 公式 | 阈值 | 说明 |
|------|------|------|------|
| 目标相似度 | 当前步骤描述与初始目标的语义相似度 | < 0.3 | 完全偏离原始目标 |
| 内部一致性 | 中间结论之间的逻辑一致性分数 | < 0.5 | 结论前后矛盾 |
| 事实偏差 | Agent 声称的状态 vs 实际系统状态的不一致数 | > 2 | 如 Agent 说数据已导入但数据库无记录 |

**检测实现**：

```python
class StateDriftDetector:
    """
    状态漂移检测器
    
    通过持续对比 Agent 的"内部状态"和"外部事实"来
    检测 Agent 是否偏离了正确轨道。
    """
    
    def __init__(self):
        self.initial_goal: str = ""
        self.state_snapshots: List[Dict] = []
    
    def set_goal(self, goal: str):
        """设置任务的初始目标"""
        self.initial_goal = goal
    
    def observe(self, agent_state: Dict) -> Dict:
        """
        观察 Agent 的当前状态
        
        Args:
            agent_state: Agent 的报告状态，包含：
                - current_step_description: str
                - claimed_intermediate_result: str
                - current_step_index: int
                - relevant_tools: List[str]
        
        Returns:
            检测结果
        """
        self.state_snapshots.append(agent_state)
        
        # 信号 1: 目标偏离
        goal_alignment = self._compute_goal_alignment(
            agent_state.get("current_step_description", "")
        )
        
        # 信号 2: 内部一致性（检查中间结论是否矛盾）
        consistency = self._check_internal_consistency()
        
        # 信号 3: 工具使用偏离
        tool_deviation = self._check_tool_deviation(
            agent_state.get("relevant_tools", [])
        )
        
        has_drift = (
            goal_alignment < 0.3 or
            consistency < 0.5 or
            tool_deviation > 0.7
        )
        
        return {
            "has_state_drift": has_drift,
            "goal_alignment": goal_alignment,
            "internal_consistency": consistency,
            "tool_deviation": tool_deviation,
            "detail": self._build_drift_detail(
                goal_alignment, consistency, tool_deviation
            ),
        }
    
    def _compute_goal_alignment(self, current_description: str) -> float:
        """计算当前步骤与初始目标的语义对齐度"""
        if not self.initial_goal or not current_description:
            return 1.0
        # 使用 embedding 语义相似度
        # 简化实现用关键词重叠率
        goal_keywords = set(self.initial_goal.lower().split())
        step_keywords = set(current_description.lower().split())
        if not goal_keywords:
            return 1.0
        overlap = goal_keywords & step_keywords
        return len(overlap) / len(goal_keywords)
    
    def _check_internal_consistency(self) -> float:
        """检查状态快照之间的一致性"""
        if len(self.state_snapshots) < 2:
            return 1.0
        
        # 检查相邻状态之间是否有矛盾
        # 例如：前一步说"数据已就绪"，后一步说"需要获取数据"
        contradictions = 0
        for i in range(1, len(self.state_snapshots)):
            if self._is_contradictory(
                self.state_snapshots[i-1],
                self.state_snapshots[i]
            ):
                contradictions += 1
        
        if len(self.state_snapshots) <= 1:
            return 1.0
        return 1.0 - (contradictions / (len(self.state_snapshots) - 1))
    
    def _is_contradictory(self, state_a: Dict, state_b: Dict) -> bool:
        """判断两个状态是否矛盾"""
        # 检查步骤索引是否倒退
        idx_a = state_a.get("current_step_index", 0)
        idx_b = state_b.get("current_step_index", 0)
        if idx_b < idx_a - 1:  # 允许小幅度回溯（如重试）
            return True
        return False
    
    def _check_tool_deviation(self, current_tools: List[str]) -> float:
        """
        检查工具使用是否偏离预期
        
        如果 Agent 开始把工具用于非预期用途，返回高偏离值
        """
        # 检查工具名称中是否包含滥用模式
        abuse_patterns = {
            "calculator": ["reason", "think", "decide"],
            "search": ["calculate", "compute", "transform"],
            "database": ["summarize", "explain"],
        }
        
        deviations = 0
        total_checks = 0
        for tool, expected_verbs in abuse_patterns.items():
            if tool in current_tools:
                total_checks += 1
                # 检查 tool 的输入参数是否包含非预期的动词
                # （简化实现，实际需要对 tool 的输入做语义分析）
        
        return deviations / max(total_checks, 1)
    
    def _build_drift_detail(self, alignment, consistency, deviation) -> str:
        parts = []
        if alignment < 0.3:
            parts.append(f"目标严重偏离 (对齐度: {alignment:.2f})")
        if consistency < 0.5:
            parts.append(f"内部状态矛盾 (一致性: {consistency:.2f})")
        if deviation > 0.7:
            parts.append(f"工具使用偏离设计意图")
        return "; ".join(parts) if parts else "状态正常"
```

### 2.4 信号 D：无显性 Error 但产出异常

**现象**：Agent 正常完成了所有步骤，没有报任何错误，但最终产出质量明显不合格。

```
示例 1：Agent 生成了 SQL，SQL 语法正确、运行成功，
       但返回了空结果集——因为 WHERE 条件写错了。
       → 没有错误，但结果完全无用。

示例 2：Agent 写了一份邮件，格式完美、语气恰当，
       但邮件内容的日期全部写错了（用了去年的日期）。
       → 没有错误，但邮件发出去会造成问题。
```

**检测指标**：

| 指标 | 公式 | 阈值 | 说明 |
|------|------|------|------|
| 输出置信度 | Agent 对自身输出的置信度评分（见 14.5 节） | < 0.6 | 低置信度是静默失败的强信号 |
| 空结果率 | 工具调用返回空结果的占比 | > 30% | 大量空结果意味 Agent 在无效搜索 |
| 输出质量分 | 规则/验证器对输出的质量评分 | < 0.5 | 简单的规则检查就能发现异常 |
| 前一步骤失败率 | Agent 自述的已完成步骤中标记为"不确定"的比例 | > 20% | Agent 自己在过程中感到了不确定性 |

**综合检测器**：

```python
class SilentFailureDetector:
    """
    静默失败综合检测器
    
    集成四个维度的检测信号，给出综合的静默失败评分。
    """
    
    def __init__(self):
        self.replan_detector = ReplanningDetector()
        self.tool_explosion_detector = ToolCallExplosionDetector()
        self.state_drift_detector = StateDriftDetector()
        
        # 各信号的权重
        self.signal_weights = {
            "replanning": 0.25,
            "tool_explosion": 0.25,
            "state_drift": 0.30,
            "output_anomaly": 0.20,
        }
    
    def observe_step(
        self,
        step_context: Dict,
    ) -> Dict:
        """
        对 Agent 的一步执行做静默失败检测
        
        Args:
            step_context: 包含该步骤的所有上下文信息
                - task_type: str
                - step_description: str
                - step_index: int
                - tool_calls: List[Dict]
                - agent_state: Dict
                - output: str (可选)
                - confidence: float (可选, 参见 14.5 节)
        
        Returns:
            检测结果
                - is_silent_failure: bool
                - failure_score: float (0-1)
                - triggered_signals: List[str]
                - detail: str
        """
        signals = {}
        
        # 检测信号 A: 重复重规划
        replan_result = self.replan_detector.observe(
            step_description=step_context.get("step_description", ""),
            step_index=step_context.get("step_index", 0),
        )
        signals["replanning"] = 1.0 if replan_result["is_replanning_loop"] else 0.0
        
        # 检测信号 B: 工具调用暴增
        tool_result = self.tool_explosion_detector.observe(
            task_type=step_context.get("task_type", "unknown"),
            tool_calls=step_context.get("tool_calls", []),
        )
        signals["tool_explosion"] = 1.0 if tool_result["is_tool_call_explosion"] else 0.0
        
        # 检测信号 C: 状态漂移
        drift_result = self.state_drift_detector.observe(
            agent_state=step_context.get("agent_state", {}),
        )
        signals["state_drift"] = 1.0 if drift_result["has_state_drift"] else 0.0
        
        # 检测信号 D: 产出异常
        output_confidence = step_context.get("confidence", 1.0)
        signals["output_anomaly"] = 1.0 if output_confidence < 0.6 else 0.0
        
        # 综合评分
        failure_score = sum(
            signals[s] * self.signal_weights[s]
            for s in signals
        )
        
        triggered = [s for s, v in signals.items() if v > 0]
        
        return {
            "is_silent_failure": failure_score >= 0.4,  # 阈值可调
            "failure_score": failure_score,
            "triggered_signals": triggered,
            "signal_scores": signals,
            "detail": (
                f"静默失败评分: {failure_score:.2f} "
                f"(触发信号: {', '.join(triggered) if triggered else '无'})"
            ),
        }
    
    def set_goal(self, goal: str):
        """设置初始目标（用于状态漂移检测）"""
        self.state_drift_detector.set_goal(goal)
```

## 三、检测后的处理流程

### 3.1 三级响应机制

```
静默失败评分
    │
    ├── < 0.3: 正常，无需操作
    │
    ├── 0.3 - 0.6: 黄色告警
    │       → 记录日志到静默失败事件表
    │       → 降低该步骤输出的置信度
    │       → 加强后续步骤的验证强度
    │
    ├── 0.6 - 0.8: 橙色干预
    │       → 中断当前步骤执行
    │       → 重置 Agent 状态到上一个检查点
    │       → 尝试不同的规划路径
    │
    └── ≥ 0.8: 红色终止
            → 终止整个任务
            → 降级到规则引擎或转人工
            → 记录详细上下文供事后分析
```

### 3.2 静默失败事件记录

```python
@dataclass
class SilentFailureEvent:
    """静默失败事件"""
    task_id: str

        return {
            "event_type": "silent_failure",
            "task_id": self.task_id,
            "failure_score": self.failure_score,
            "triggered_signals": self.triggered_signals,
            "timestamp": self.timestamp,
        }
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 静默失败（Silent Failure） | Agent 无报错但产出错误或偏离目标的失败模式 |
| 重复重规划 | Agent 反复规划同一任务步骤，无法推进 |
| 工具调用暴增 | Agent 在同一任务中无意义地重复调用工具 |
| 状态漂移 | Agent 内部任务状态与实际情况不一致 |
| 目标偏离 | Agent 的当前行为与初始任务目标无关 |
| 输出置信度 | Agent 对自身生成结果的确信程度（参见 14.5 节） |
| 空结果率 | 工具调用返回无意义或空结果的占比 |
| 语义相似度 | 通过文本 embedding 衡量两段文本的内容相似程度 |
