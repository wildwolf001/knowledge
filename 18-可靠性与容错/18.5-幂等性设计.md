# 18.5 幂等性设计

> "如果某件事失败了，重新做一次会怎样？"——在 Agent 系统中，答案应该是"不会更糟"。幂等性设计确保重试是安全的，从崩溃点恢复是可行的，整个系统是可以被"回放"的。

---

## 一、什么是幂等性？

### 1.1 定义

**幂等性**（Idempotency）是一个数学和工程概念：一个操作无论执行多少次，其产生的效果都与执行一次相同。

\[
f(f(x)) = f(x)
\]

在 Agent 系统的语境下：

- **幂等操作**：重复执行同一 Agent 步骤，不会产生额外副作用或不同的最终结果
- **非幂等操作**：重复执行可能导致重复扣费、重复发送消息、重复创建资源

### 1.2 Agent 系统中的幂等性为什么重要

Agent 系统天然需要幂等性，因为：

1. **Agent 是概率系统**：每一步都可能失败，需要重试（参见 18.1 节）
2. **重试是核心容错手段**（参见 18.2 节）：没有幂等性的重试是危险的
3. **网络不确定性**：请求可能已到达服务器但响应丢失，Agent 不确定是否需要重试
4. **崩溃恢复**：Agent 进程可能崩溃，恢复后需要从上次位置继续而非从头开始

### 1.3 非幂等操作的代价

```
非幂等的重试：
Agent: 执行 "创建订单" → API 返回超时（但订单已创建）
Agent: 重试 "创建订单" → 又创建一个订单（重复扣费）
Agent: 重试 "创建订单" → 再创建一个订单
→ 用户收到 3 个相同的订单，被扣了 3 次钱

幂等的重试：
Agent: 执行 "创建订单（幂等键: abc123）" → API 返回超时（订单已创建）
Agent: 重试 "创建订单（幂等键: abc123）" → API 检测到重复，返回已有订单
Agent: 重试 "创建订单（幂等键: abc123）" → 返回相同订单
→ 用户只收到 1 个订单，只扣 1 次钱
```

## 二、幂等性设计的关键技术

### 2.1 幂等键（Idempotency Key）

**幂等键**是标识一个操作唯一性的 token。服务端用幂等键来识别重复请求。

```python
import uuid
import hashlib
import json

class IdempotencyKeyGenerator:
    """幂等键生成器"""
    
    @staticmethod
    def generate_uuid() -> str:
        """基于 UUID 的幂等键"""
        return str(uuid.uuid4())
    
    @staticmethod
    def generate_from_request(request: Dict) -> str:
        """基于请求内容的哈希生成幂等键"""
        content = json.dumps(request, sort_keys=True)
        return hashlib.sha256(content.encode()).hexdigest()
    
    @staticmethod
    def generate_composite(step_id: str, attempt: int, params_hash: str) -> str:
        """
        复合幂等键：结合步骤 ID、尝试次数和参数哈希
        
        适用于 Agent 的多步场景——每一步都有唯一标识，
        即使参数相同，不同步骤的幂等键也不同
        """
        raw = f"{step_id}:{attempt}:{params_hash}"
        return hashlib.sha256(raw.encode()).hexdigest()
```

### 2.2 幂等性存储

服务端需要存储已处理过的幂等键及其结果：

```python
import time
from typing import Optional, Dict, Any

class IdempotencyStore:
    """
    幂等性存储
    
    记录已处理的幂等键及其对应的操作结果。
    需要定期清理过期的幂等键以防止存储无限增长。
    """
    
    def __init__(self, ttl: float = 86400):  # 默认保留 24 小时
        self._store: Dict[str, Dict] = {}
        self.ttl = ttl
    
    def get(self, key: str) -> Optional[Dict]:
        """获取幂等键对应的已处理结果"""
        entry = self._store.get(key)
        if not entry:
            return None
        
        # 检查是否过期
        if time.time() - entry["timestamp"] > self.ttl:
            del self._store[key]
            return None
        
        return entry["result"]
    
    def set(self, key: str, result: Dict):
        """记录幂等键的处理结果"""
        self._store[key] = {
            "result": result,
            "timestamp": time.time(),
        }
    
    def exists(self, key: str) -> bool:
        """检查幂等键是否已存在"""
        return key in self._store
    
    def cleanup(self):
        """清理过期条目"""
        now = time.time()
        expired = [
            k for k, v in self._store.items()
            if now - v["timestamp"] > self.ttl
        ]
        for k in expired:
            del self._store[k]


# Agent 步骤的幂等执行器
class IdempotentStepExecutor:
    """
    Agent 步骤的幂等执行
    
    确保每个 Agent 步骤最多执行一次"副作用"，
    重试时只返回之前的结果。
    """
    
    def __init__(self, store: IdempotencyStore):
        self.store = store
    
    def execute(self, step_id: str, params: Dict, action_fn) -> Dict:
        """
        幂等地执行一个 Agent 步骤
        
        Args:
            step_id: 步骤的唯一标识
            params: 步骤参数
            action_fn: 实际的执行函数
        
        Returns:
            执行结果（可能是之前缓存的结果）
        """
        # 生成幂等键
        key = IdempotencyKeyGenerator.generate_composite(
            step_id=step_id,
            attempt=1,
            params_hash=hashlib.sha256(
                json.dumps(params, sort_keys=True).encode()
            ).hexdigest(),
        )
        
        # 检查是否已执行过
        existing = self.store.get(key)
        if existing is not None:
            print(f"幂等命中: 步骤 {step_id} 已执行过，返回缓存结果")
            return existing
        
        # 首次执行
        try:
            result = action_fn(params)
            self.store.set(key, result)
            return result
        except Exception as e:
            # 执行失败→不缓存结果（允许重试）
            raise
```

### 2.3 可重放的步骤（Replayable Steps）

**可重放**是指 Agent 的某一步骤可以被多次执行而不改变状态。这与幂等性相关但有区别：

- **幂等**：重复执行产生相同结果
- **可重放**：执行过程可以被安全地重复

可重放步骤的设计原则：

```python
class ReplayableStep:
    """
    可重放的 Agent 步骤
    
    设计原则：
    1. 不产生外部副作用（或在重放时跳过副作用）
    2. 所有输入来自确定的上下文（而非上次运行的遗留状态）
    3. 输出可以被缓存和验证
    """
    
    def __init__(
        self,
        step_id: str,
        fn: Callable,
        is_deterministic: bool = False,
    ):
        self.step_id = step_id
        self.fn = fn
        self.is_deterministic = is_deterministic
        self.execution_cache: Dict[str, Any] = {}
    
    def execute(self, context: Dict) -> Any:
        """执行步骤"""
        if self.is_deterministic:
            # 确定性步骤：相同输入 → 相同输出，可以安全缓存
            cache_key = json.dumps(context, sort_keys=True)
            if cache_key in self.execution_cache:
                return self.execution_cache[cache_key]
            result = self.fn(context)
            self.execution_cache[cache_key] = result
            return result
        else:
            # 非确定性步骤（如 LLM 调用）：每次重放重新执行
            return self.fn(context)


class ReplayablePipeline:
    """
    可重放的 Agent 流水线
    
    支持从任意检查点恢复，而非从头开始。
    """
    
    def __init__(self, steps: List[ReplayableStep]):
        self.steps = steps
        self.checkpoints: Dict[int, Any] = {}  # step_index → output
    
    def run(self, initial_context: Dict, resume_from: int = 0) -> Any:
        """
        运行流水线
        
        Args:
            initial_context: 初始上下文
            resume_from: 从哪个步骤开始（0=从头开始）
        """
        context = deepcopy(initial_context)
        
        for i in range(resume_from, len(self.steps)):
            step = self.steps[i]
            
            # 尝试恢复之前的检查点
            if i in self.checkpoints and i >= resume_from:
                context["step_result"] = self.checkpoints[i]
                continue
            
            # 执行步骤
            try:
                result = step.execute(context)
                context["step_result"] = result
                self.checkpoints[i] = result
            except Exception as e:
                print(f"步骤 {i} ({step.step_id}) 失败: {e}")
                raise ReplayablePipelineError(
                    f"流水线中断于步骤 {i}", 
                    last_checkpoint=max(self.checkpoints.keys()) 
                        if self.checkpoints else -1
                )
        
        return context.get("step_result")
```

## 三、从崩溃点恢复（Checkpoint Recovery）

### 3.1 检查点的设计

**检查点**（Checkpoint）是 Agent 在某一步执行完后保存的完整状态快照。它包括：

```
检查点 = {
    "step_index": 5,           # 已完成到第几步
    "context": {...},          # 完整的上下文状态
    "intermediate_results": [...],  # 已产出的中间结果
    "tool_call_history": [...],     # 已执行的工具调用
    "timestamp": "...",        # 检查点时间
    "version": "...",          # Agent 版本（兼容性检查）
}
```

### 3.2 检查点实现

```python
import pickle
import os
from datetime import datetime

@dataclass
class Checkpoint:
    """Agent 检查点"""
    step_index: int
    context: Dict
    intermediate_results: List[Any]
    tool_call_history: List[Dict]
    timestamp: datetime
    agent_version: str
    
    def save(self, path: str):
        """保存检查点到磁盘"""
        os.makedirs(os.path.dirname(path), exist_ok=True)
        with open(path, 'wb') as f:
            pickle.dump(self, f)
    
    @classmethod
    def load(cls, path: str) -> 'Checkpoint':
        """从磁盘加载检查点"""
        with open(path, 'rb') as f:
            return pickle.load(f)


class CheckpointManager:
    """
    检查点管理器
    
    管理 Agent 的检查点：自动保存、定期清理、从检查点恢复。
    """
    
    def __init__(self, checkpoint_dir: str, save_interval: int = 1):
        """
        Args:
            checkpoint_dir: 检查点存储目录
            save_interval: 每 N 步保存一次检查点
        """
        self.checkpoint_dir = checkpoint_dir
        self.save_interval = save_interval
        self.current_checkpoint: Optional[Checkpoint] = None
    
    def save_checkpoint(
        self,
        step_index: int,
        context: Dict,
        intermediate_results: List[Any],
        tool_call_history: List[Dict],
        agent_version: str,
    ):
        """保存检查点"""
        if step_index % self.save_interval != 0:
            return  # 没到保存间隔
        
        self.current_checkpoint = Checkpoint(
            step_index=step_index,
            context=deepcopy(context),
            intermediate_results=deepcopy(intermediate_results),
            tool_call_history=deepcopy(tool_call_history),
            timestamp=datetime.now(),
            agent_version=agent_version,
        )
        
        path = os.path.join(
            self.checkpoint_dir, 
            f"checkpoint_step_{step_index}.pkl"
        )
        self.current_checkpoint.save(path)
        
        # 清理旧检查点（只保留最近的 3 个）
        self._cleanup_old_checkpoints(keep=3)
    
    def get_latest_checkpoint(self) -> Optional[Checkpoint]:
        """获取最新的检查点"""
        if self.current_checkpoint:
            return self.current_checkpoint
        
        # 从磁盘加载最新的
        files = sorted(
            [f for f in os.listdir(self.checkpoint_dir) 
             if f.startswith("checkpoint_step_")],
            key=lambda x: int(x.split("_")[2].split(".")[0]),
        )
        if files:
            path = os.path.join(self.checkpoint_dir, files[-1])
            return Checkpoint.load(path)
        return None
    
    def restore_from_checkpoint(
        self, 
        checkpoint_path: Optional[str] = None
    ) -> Optional[Checkpoint]:
        """从检查点恢复"""
        if checkpoint_path:
            return Checkpoint.load(checkpoint_path)
        return self.get_latest_checkpoint()
    
    def _cleanup_old_checkpoints(self, keep: int = 3):
        """清理旧检查点，只保留最新的 keep 个"""
        files = sorted(
            [f for f in os.listdir(self.checkpoint_dir) 
             if f.startswith("checkpoint_step_")],
            key=lambda x: int(x.split("_")[2].split(".")[0]),
        )
        for f in files[:-keep]:
            os.remove(os.path.join(self.checkpoint_dir, f))
```

### 3.3 "从零重跑" vs "从检查点恢复" 的成本对比

这是幂等性设计的核心论据——定量对比两种方案的差异。

**场景设定**：
- Agent 任务总共 30 步
- 在第 22 步发生崩溃
- 每步平均耗时 5 秒（含 LLM 调用）
- 每步平均消耗 1000 tokens
- tokens 价格 $0.01/K tokens

| 维度 | 从零重跑 | 从检查点恢复 | 节省 |
|------|---------|-------------|------|
| **重跑步数** | 30 步 | 8 步（23-30） | 73% |
| **耗时** | 150 秒 | 40 秒 | 73% |
| **Token 消耗** | 30K | 8K | 73% |
| **成本** | $0.30 | $0.08 | 73% |
| **二次失败风险** | 30 步的新概率爆炸 | 仅 8 步的低风险 | — |

**不同崩溃时刻的成本对比**：

```
崩溃时刻   | 从零重跑成本 | 从检查点恢复成本 | 节省比例
第 5 步    | 150s, $0.30  | 125s, $0.25      | 17%
第 10 步   | 150s, $0.30  | 100s, $0.20      | 33%
第 15 步   | 150s, $0.30  | 75s, $0.15       | 50%
第 22 步   | 150s, $0.30  | 40s, $0.08       | 73%
第 28 步   | 150s, $0.30  | 10s, $0.02       | 93%
```

**关键结论**：
1. 崩溃发生得越晚，检查点恢复的收益越大（节省比例从 17% 到 93%）
2. 除了成本节省，更重要的是**二次失败概率的降低**——重新跑 30 步的失败概率远高于重新跑 8 步
3. 检查点还提供了"多级回退"能力：如果第 22 步是"开始写文件"这样的不可逆操作，检查点可以回退到第 15 步并选择不同的路径

### 3.4 Agent 级别检查点恢复的完整流程

```python
class AgentWithRecovery:
    """
    支持从崩溃点恢复的 Agent
    
    当 Agent 崩溃：
    1. 检测上次运行的检查点
    2. 从断点继续执行而非从头开始
    3. 跳过的步骤从检查点恢复上下文
    """
    
    def __init__(self, agent_id: str, checkpoint_dir: str):
        self.agent_id = agent_id
        self.checkpoint_manager = CheckpointManager(
            checkpoint_dir=checkpoint_dir,
            save_interval=1,
        )
    
    def run_with_recovery(
        self,
        task: str,
        force_restart: bool = False,
    ) -> Any:
        """
        运行 Agent 任务，支持从崩溃点恢复
        
        Args:
            task: 任务描述
            force_restart: 是否强制从头开始（忽略已有检查点）
        
        Returns:
            任务执行结果
        """
        checkpoint = None
        
        if not force_restart:
            checkpoint = self.checkpoint_manager.get_latest_checkpoint()
        
        if checkpoint:
            print(f"检测到检查点: 已执行到第 {checkpoint.step_index} 步")
            print(f"从第 {checkpoint.step_index + 1} 步恢复执行")
            
            # 用检查点的上下文恢复 Agent 状态
            context = checkpoint.context
            start_step = checkpoint.step_index + 1
            intermediate_results = checkpoint.intermediate_results
        else:
            print("未找到检查点，从头开始执行")
            context = {"task": task, "start_time": time.time()}
            start_step = 0
            intermediate_results = []
        
        # 执行剩余的步骤
        for step_index in range(start_step, self.total_steps):
            try:
                # 执行步骤
                result = self._execute_step(step_index, context)
                
                # 保存中间结果
                intermediate_results.append(result)
                
                # 保存检查点
                self.checkpoint_manager.save_checkpoint(
                    step_index=step_index,
                    context=context,
                    intermediate_results=intermediate_results,
                    tool_call_history=self.tool_history,
                    agent_version=self.version,
                )
                
            except RecoverableError as e:
                print(f"步骤 {step_index} 失败（可恢复）: {e}")
                
                if checkpoint:
                    # 回退到上一个检查点
                    print(f"回退到检查点 {checkpoint.step_index}")
                    return self._restart_from_checkpoint(
                        checkpoint, task
                    )
                else:
                    # 没有检查点→从当前步骤重试
                    self._retry_step(step_index, context)
            
            except NonRecoverableError as e:
                print(f"步骤 {step_index} 失败（不可恢复）: {e}")
                raise
            
            except Exception as e:
                # 系统级崩溃（进程退出、断电等）
                # 下次运行时通过检查点恢复
                print(f"系统异常: {e}")
                self.checkpoint_manager.save_checkpoint(
                    step_index=step_index - 1,  # 保存到上一步
                    context=context,
                    intermediate_results=intermediate_results,
                    tool_call_history=self.tool_history,
                    agent_version=self.version,
                )
                raise SystemFailure(
                    f"系统异常退出，已保存检查点到步骤 {step_index - 1}"
                )
        
        # 任务完成，清理检查点
        self.checkpoint_manager._cleanup_old_checkpoints(keep=0)
        
        return intermediate_results[-1] if intermediate_results else None
```

## 四、进度追踪（Progress Tracking）

### 4.1 为什么进度追踪是幂等性的基础

进度追踪让 Agent 知道"我做到了哪里"。没有进度追踪，重试只能"全有或全无"。

```python
class ProgressTracker:
    """
    进度追踪器
    
    以日志形式记录 Agent 的执行进度，支持：
    - 当前进度查询
    - 已完成步骤列表
    - 回退到指定步骤
    - 进度持久化（崩溃恢复用）
    """
    
    def __init__(self, task_id: str, total_steps: int):
        self.task_id = task_id
        self.total_steps = total_steps
        self.completed_steps: List[int] = []
        self.failed_steps: List[int] = []
        self.step_results: Dict[int, Any] = {}
    
    def mark_completed(self, step_index: int, result: Any):
        """标记步骤为已完成"""
        self.completed_steps.append(step_index)
        self.step_results[step_index] = result
    
    def mark_failed(self, step_index: int, error: Exception):
        """标记步骤为失败"""
        self.failed_steps.append(step_index)
        if step_index in self.completed_steps:
            self.completed_steps.remove(step_index)
    
    def get_current_step(self) -> int:
        """获取当前应该执行的步骤"""
        if not self.completed_steps:
            return 0
        return max(self.completed_steps) + 1
    
    def get_progress(self) -> Dict:
        """获取进度信息"""
        return {
            "task_id": self.task_id,
            "total_steps": self.total_steps,
            "completed": len(self.completed_steps),
            "failed": len(self.failed_steps),
            "progress_pct": len(self.completed_steps) / max(self.total_steps, 1) * 100,
            "current_step": self.get_current_step(),
        }
    
    def rollback_to(self, step_index: int):
        """回退到指定步骤（移除该步骤之后的所有进度）"""
        self.completed_steps = [
            s for s in self.completed_steps if s < step_index
        ]
        self.step_results = {
            k: v for k, v in self.step_results.items() if k < step_index
        }
```

### 4.2 进度持久化

```python
class PersistentProgressTracker(ProgressTracker):
    """支持持久化的进度追踪器"""
    
    def __init__(self, task_id: str, total_steps: int, storage_path: str):
        super().__init__(task_id, total_steps)
        self.storage_path = storage_path
        self._load_from_disk()
    
    def save(self):
        """保存进度到磁盘"""
        data = {
            "task_id": self.task_id,
            "total_steps": self.total_steps,
            "completed_steps": self.completed_steps,
            "failed_steps": self.failed_steps,
        }
        path = os.path.join(self.storage_path, f"{self.task_id}_progress.json")
        with open(path, 'w') as f:
            json.dump(data, f)
    
    def _load_from_disk(self):
        """从磁盘加载进度"""
        path = os.path.join(self.storage_path, f"{self.task_id}_progress.json")
        if os.path.exists(path):
            with open(path, 'r') as f:
                data = json.load(f)
            self.completed_steps = data.get("completed_steps", [])
            self.failed_steps = data.get("failed_steps", [])
    
    def mark_completed(self, step_index: int, result: Any):
        super().mark_completed(step_index, result)
        self.save()
    
    def mark_failed(self, step_index: int, error: Exception):
        super().mark_failed(step_index, error)
        self.save()
```

## 五、幂等性设计的工程原则

### 原则 1：每个外部动作都要有幂等键

任何对外部系统产生副作用的操作（API 调用、数据库写入、消息发送），都必须携带幂等键。

### 原则 2：检查点是上下文快照而非操作记录

检查点保存的是"完成到哪一步时的完整状态"，而不是"已经执行了哪些操作"。前者可以安全恢复，后者不足以重建上下文。

### 原则 3：先写日志再执行操作（WAL 模式）

借鉴数据库的 Write-Ahead Logging（预写日志）模式：在执行任何外部操作之前，先把"即将执行操作"记录到日志中。崩溃后可以通过日志判断操作是否已执行。

### 原则 4：明确可重放边界

不是所有操作都需要幂等。分类处理：

```
操作类型                    | 幂等要求 | 实现方式
数据库 INSERT                | 必须    | 唯一约束 + 幂等键
数据库 UPDATE                | 必须    | 条件更新 (WHERE version = N)
发送 Email                   | 必须    | 幂等键去重
发送 HTTP 请求               | 必须    | 幂等头 (Idempotency-Key)
LLM 文本生成（非确定）       | 不必须  | 缓存输入 → 输出映射
LLM 工具调用（格式化输出）  | 推荐    | 基于哈希的幂等检查
读取操作（纯查询）          | 天然    | 无副作用，不需要额外处理
```

### 原则 5：恢复后验证

从检查点恢复后，不要完全相信检查点的上下文——对关键状态做轻量级验证：

```python
def verify_checkpoint(checkpoint: Checkpoint) -> bool:
    """验证检查点的一致性"""
    # 验证关键上下文字段是否存在
    required_fields = ["task", "session_id"]
    for field in required_fields:
        if field not in checkpoint.context:
            return False
    
    # 验证中间结果的数量是否与步骤索引一致
    expected_count = checkpoint.step_index + 1
    if len(checkpoint.intermediate_results) != expected_count:
        return False
    
    return True
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 幂等性（Idempotency） | 同一操作重复执行多次与执行一次的效果相同 |
| 幂等键（Idempotency Key） | 标识操作唯一性的 token，用于检测和去重重复请求 |
| 可重放（Replayable） | Agent 步骤可以被安全地重复执行而不产生副作用 |
| 检查点（Checkpoint） | 在某一步完成后保存的 Agent 完整状态快照 |
| 崩溃恢复 | 从检查点恢复 Agent 执行而非从头开始 |
| Write-Ahead Logging | 先写日志后执行，崩溃后通过日志判断操作状态 |
| 进度追踪 | 记录 Agent 已完成的步骤，支持查询和回退 |
| 从零重跑 vs 从检查点恢复 | 前者的成本随崩溃时刻线性增长，后者的成本固定为剩余步骤 |
| 唯一约束 | 数据库层面保证幂等性的机制（如 UNIQUE INDEX） |
