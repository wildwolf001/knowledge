# 14.1 幻觉根因

> 幻觉（Hallucination）是指 LLM 生成的内容在表面上流畅、自信，但包含事实错误、无据虚构或与输入上下文矛盾。理解幻觉的根因是构建防御体系的前提。

---

## 一、什么是幻觉？

在 Agent 工程的语境下，幻觉不仅仅是"编造事实"——它涵盖三个维度：

| 类别 | 定义 | 示例 |
|------|------|------|
| **事实性幻觉（Factual Hallucination）** | 生成的内容与客观事实不一致 | "李白是唐朝第二位皇帝" |
| **忠实性幻觉（Faithfulness Hallucination）** | 生成的内容偏离了用户指令或给定上下文 | 检索到的文档说 X，模型输出却说 Y |
| **逻辑性幻觉（Logical Hallucination）** | 推理过程中的逻辑跳跃或矛盾 | 步骤1推出A，步骤2却说"因为A不成立，所以B" |

从概率角度看，幻觉并非模型"故意撒谎"，而是 **语言模型在概率分布上的采样结果偏离了事实分布**。LLM 本质上是一个条件概率模型 P(token | context)，它学到的是"什么样的文本是合理的"，而不是"什么样的文本是真实的"。

---

## 二、幻觉的四大根因

### 2.1 训练数据噪声

**问题本质**：LLM 的训练数据来自互联网，包含大量错误信息、过时内容、偏见和矛盾叙述。模型在训练过程中无法区分"高频出现的错误信息"和"低频但正确的事实"。

具体表现：
- **共现偏差（Co-occurrence Bias）**：某些实体在训练数据中频繁共现，模型倾向于将它们关联，但这种关联可能只是统计上的巧合而非事实关系。例如，"爱因斯坦"和"E=mc²"高度共现，模型可能把其他物理公式也归因于爱因斯坦。
- **流行度偏差（Popularity Bias）**：出现频率高的事件被模型过度信任，而正确但罕见的事实被低估。比如在训练数据中某个错误的"常识"如果被大量网页重复，模型就会更倾向于输出它。
- **时效性问题**：训练数据有截止日期，模型对截止日期后发生的事件没有真实知识，但可能在生成时"合理推测"出看似可信但实际错误的内容。
- **长尾知识缺失**：对于训练数据中出现频率低的事实（罕见疾病、小众历史事件、冷门技术细节），模型缺乏足够的学习信号，在生成时容易产生幻觉。

**工程影响**：这解释了为什么 RAG（检索增强生成）是降低幻觉的核心手段——通过注入准确的外部知识来弥补训练数据的不足。

### 2.2 概率采样机制

**问题本质**：LLM 生成每个 token 时，是从 softmax 输出的概率分布中采样。即使模型"知道"正确事实（正确 token 的概率最高），采样过程仍可能选中低概率的错误 token。

具体机制：

```
采样温度（Temperature）的影响：
- Temperature → 0：分布变尖锐，倾向于选最高概率 token（更"确定"但缺少多样性）
- Temperature = 1：保持原始分布
- Temperature → ∞：分布趋于均匀（更"随机"但幻觉率飙升）
```

**Top-K / Top-P 采样**：
- **Top-K**：只从概率最高的 K 个 token 中采样。K 太小会丢失正确答案，K 太大会引入噪声。
- **Top-P（Nucleus Sampling）**：从累计概率达到 P 的最小 token 集合中采样。P=0.9 意味着只考虑概率最高的前 N 个 token，使其累计概率 >= 90%。但 P 值设置不当可能把正确但低概率的 token 排除在外。

**概率幻觉的数学解释**：
假设模型对某个事实有 95% 的"信心"（即正确 token 的概率为 0.95），每一步都选正确 token 的概率是 0.95。但生成一个 100 个 token 的段落：

```
P(全部正确) = 0.95^100 ≈ 0.59%
```

这意味着即使每一步的"正确率"都高达 95%，生成较长内容时的**累积错误率**也会急剧上升。这就是为什么 Agent 在多步推理中幻觉问题尤为严重——如同第 18.1 节讨论的概率爆炸。

### 2.3 上下文误导

**问题本质**：模型对输入上下文高度敏感，上下文中存在矛盾信息、误导性线索或格式陷阱时，模型可能优先遵循上下文模式而非其参数知识。

具体表现：

**① 上下文污染（Context Contamination）**
当检索结果或对话历史中包含错误信息时，模型可能采信错误内容。这是 RAG 系统常见的失败模式（详见 8.7 节）：
```
User: 2024年诺贝尔物理学奖得主是谁？
Retrieved: [一篇2025年的错误文章："2024年诺贝尔物理学奖授予John Doe..."]
Model: 2024年诺贝尔物理学奖得主是John Doe。（实际是John Hopfield和Geoffrey Hinton）
```

**② Sycophancy（谄媚效应）**
模型倾向于迎合用户提供的观点或假设，即使这些观点在客观上错误：
```
User: 我觉得Python的GIL在多线程中完全没有影响，对吧？
Model: 是的，你说得完全正确！Python的GIL对多线程性能几乎没有影响...
```
实际上 GIL 对 CPU 密集型多线程任务有显著影响。

**③ 格式诱导**
当上下文的格式模式暗示某种回答风格时，模型可能优先遵循格式而非事实。例如，历史对话中所有回答都以"根据我的经验"开头，模型可能延续这一模式，甚至在无经验可谈的事实问题上也"假装有经验"。

**④ Prompt Injection 的变体**
攻击者可能通过注入恶意上下文来诱导模型产生特定幻觉（详见第 17 章 Prompt Injection）。

### 2.4 知识截止与参数知识局限

**问题本质**：LLM 的参数知识在训练完成后就冻结了，无法获取训练截止日期后的新信息，也无法访问训练数据中不存在的私有知识。

具体表现：

**① 时间性幻觉**
模型不知道训练截止日期后发生的事件，但会被迫生成回答：
```
User: 2026年世界杯冠军是谁？
Model: 2026年世界杯的冠军是...（截止2024年的训练数据，模型只能猜测或编造）
```

**② 领域知识盲区**
- **低频知识**：训练数据中出现次数少的长尾知识，模型记忆不牢固
- **私有知识**：企业内部文档、专有数据，完全不在模型的训练数据中
- **动态知识**：实时变化的信息（股票价格、天气、新闻），参数知识天然滞后

**③ 知识冲突（Knowledge Conflict）**
当上下文提供的信息与模型参数知识不一致时，模型面临"信谁"的决策：
- **参数知识优先**：模型忽略上下文提供的正确信息，坚持其过时或错误的参数记忆
- **上下文优先**：模型过分信任上下文，甚至采信上下文中明显的错误信息

研究表明，较大的模型更倾向于**参数知识优先**，这被称为"顽固知识"（Stubborn Knowledge）问题。

## 三、幻觉的工程危害

对于 Agent 系统，幻觉的破坏性远大于单次问答场景：

1. **级联失败（Cascading Failure）**：Agent 的后续步骤基于前一步的输出。第 3 步的幻觉会导致第 4 步到第 20 步全部基于错误前提，最终输出完全偏离目标。

2. **工具调用幻觉**：Agent "自信地"调用一个不存在的函数或传入了错误的参数格式，导致工具执行失败。小模型（1B-3B）在这方面尤其脆弱（见第 24.8 节）。

3. **不可察觉性**：幻觉通常被流畅的表述掩盖，用户和下游逻辑都难以察觉，直到产生严重后果。

4. **信任侵蚀**：多次幻觉后用户彻底丧失对 Agent 的信任，这是 Agent 产品最致命的失败模式。

---

## 四、幻觉不是 Bug，是 Feature？

有一个值得讨论的视角：**幻觉能力其实是 LLM 创造性生成能力的代价**。

- 如果模型 100% 忠实于训练数据，它将失去推理能力、创意写作能力、代码生成能力——这些本质上都是"生成不存在于训练数据中的文本"
- 真正的问题不是"模型会产生幻觉"，而是"模型不知道什么时候该不确定"
- 因此，降低幻觉的核心策略不是消除生成多样性，而是让模型具备**元认知能力**——知道自己知道什么、不知道什么

这正是 14.5 节「置信度评分」要解决的核心问题。

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Hallucination | LLM 生成流畅但事实错误的内容 |
| 共现偏差 | 训练数据中频繁共现导致错误关联 |
| Sycophancy | 模型迎合用户错误观点 |
| 知识冲突 | 上下文信息与参数知识不一致 |
| 级联失败 | 前一步错误导致后续步骤全部偏离 |
| 元认知 | 模型对自己知识边界的认知能力 |
