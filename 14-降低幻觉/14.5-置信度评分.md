# 14.5 置信度评分

> 置信度评分（Confidence Scoring）是让模型具备"知道自己不知道什么"的能力。在 Agent 系统中，一个准确反映不确定性的置信度分数，比一个高度自信但可能错误的回答有价值得多。**"我不知道"比信口开河好 100 倍。**

---

## 一、为什么置信度评分是 Agent 的关键能力？

### 1.1 幻觉和过度自信的同源性

LLM 的核心问题不是产生幻觉本身，而是**用与正确内容相同的自信语调产生幻觉**：

```
正确回答："巴黎是法国的首都。"
幻觉回答："里昂是法国的首都。"  ← 措辞同样流畅、自信、不容置疑
```

从语言流畅度来判断，两者几乎无法区分。这就是为什么需要显式的置信度机制——仅凭文本表面的流畅程度无法区分真假。

### 1.2 Agent 场景的特殊需求

在 Agent 系统中，置信度评分有独特价值：

| 场景 | 置信度的用途 |
|------|------------|
| **工具调用决策** | 低置信度时选择更安全的工具（Read 而非 Write） |
| **多步推理** | 低置信度的中间结果标记为"待验证"，不让其污染下游步骤 |
| **自动降级** | 置信度 < 阈值时自动转人工或回退到规则引擎 |
| **多 Agent 投票** | 用置信度加权投票——高置信度的 Agent 观点获得更高权重 |
| **用户展示** | 向用户展示不确定性，让用户可以做判断 |

## 二、获取置信度的三种途径

### 2.1 基于 Token 概率（Logit-Based）

直接从模型的输出概率分布中提取置信度：

**Token 级概率**：
```python
def get_token_confidence(logits, generated_token_ids):
    """计算生成序列的置信度"""
    confidences = []
    for i, token_id in enumerate(generated_token_ids):
        probs = softmax(logits[i])  # 该位置的完整概率分布
        token_prob = probs[token_id]  # 被选中 token 的概率
        confidences.append(token_prob)
    
    # 序列级置信度 = 各 token 概率的几何平均
    sequence_confidence = np.exp(
        np.mean([np.log(p) for p in confidences])
    )
    return sequence_confidence
```

**优缺点**：
- 优点：无需额外 API 调用，零额外成本
- 缺点：
  - 模型被选中的 token 概率高，不代表事实正确（模型可能对错误事实也很"自信"）
  - 仅当 API 返回 logprobs 时可用（需要 `logprobs=True` 参数）
  - 不适用于 black-box API（如某些闭源模型不返回概率）

**实践观察**：Token 概率反映的是"模型认为自己生成正确文本的概率"，而非"该陈述真实的概率"——这两者之间存在差距，被称为**校准误差（Calibration Error）**。

### 2.2 基于语言表达（Verbalized Confidence）

**方法一：直接询问置信度**

```
Prompt: 请回答以下问题，并在回答末尾以0-100的数值评估你的置信度。
问题：2024年诺贝尔物理学奖得主是谁？

期望输出：
    2024年诺贝尔物理学奖得主是John Hopfield和Geoffrey Hinton。
    置信度：85/100
```

**方法二：要求模型表达不确定性**

```
Prompt: 如果你不确定某个信息，请在回答中使用以下语言标记：
- [确定]：有充分依据的信息
- [存疑]：有依据但不完全确定  
- [推测]：基于推理的推断，缺乏直接证据
- [未知]：没有相关信息
```

**方法三：一致性检查**

```
Prompt: 请多次评估你对以下回答的置信度，并解释为什么给出这个分数。
回答：{answer}

评估：
1. 我的置信度是X分（满分100分）
2. 原因：
   - 确定部分：[列出有充分依据的部分]
   - 不确定部分：[列出依据不足的部分]
```

**优缺点**：
- 优点：适用于任何模型（包括 black-box API），可以直接展示给用户
- 缺点：
  - 模型在"说出自己有多不确定"这件事上同样可能不准确
  - 语言表达的置信度往往被**过度自信偏差**影响（模型倾向于高估自己的准确性）
  - 研究者发现，让模型给出"置信度分数"时，它经常给出 85-95 分的狭窄高分范围，而很少给出 30-50 分

### 2.3 基于多采样（Sampling-Based）

通过多次独立采样来估计置信度（与 14.3 节的 Self-Consistency 一致）：

```python
def estimate_confidence_by_sampling(prompt, n=10, temperature=0.7):
    """通过多次采样估算置信度"""
    responses = []
    for _ in range(n):
        response = llm.generate(prompt, temperature=temperature)
        responses.append(response)
    
    # 计算答案的语义聚类
    clusters = semantic_cluster(responses)
    
    if len(clusters) == 1 and clusters[0].size == n:
        # 所有采样高度一致 → 高置信度
        confidence = 0.9 + 0.1 * (1 - 1/n)  # 在 0.9-1.0 范围内
    else:
        # 分布分散 → 置信度取决于最大聚类的比例
        largest_cluster_ratio = max(c.size for c in clusters) / n
        confidence = largest_cluster_ratio
    
    return {
        "consensus_answer": clusters[0].representative,
        "confidence": confidence,
        "num_clusters": len(clusters),
        "cluster_distribution": [c.size for c in clusters]
    }
```

**语义聚类的工程方法**：
- 对于**有明确对错**的问题：比较答案的字面文本（或对数值型比较数值是否一致）
- 对于**开放性**问题：用 Embedding 计算语义相似度后聚类

**优缺点**：
- 优点：不依赖模型对自己的评估能力，客观反映模型的不确定性
- 缺点：成本高（n 倍 token 消耗），延迟大（n 次串行或并行调用），不适合低延迟场景

## 三、置信度校准

### 3.1 什么是校准？

一个良好校准的模型应该满足：当模型声称"90% 置信度"时，其实际正确的比例应该是 90%。

**校准曲线（Reliability Diagram）**：
```
声称置信度 | 实际正确率（良好校准）| 实际正确率（过度自信）
   90%             90%                     72%
   80%             80%                     58%
   70%             70%                     51%
   60%             60%                     47%
   50%             50%                     45%
```

大多数 LLM 未经校准时表现为**过度自信**——声称 90% 置信度的回答实际正确率可能只有 70%。

### 3.2 校准方法

**方法一：Temperature Scaling（温度缩放）**

学习一个最优的 temperature 参数来平滑概率分布：

```python
def calibrate_with_temperature(logits, temperature):
    """使用 Temperature Scaling 校准置信度"""
    calibrated_logits = logits / temperature
    probs = softmax(calibrated_logits)
    return probs

# 在验证集上搜索最优 temperature
best_t = find_optimal_temperature(validation_set)
# best_t > 1 说明模型过度自信，需要"降温"（使分布更均匀）
```

**方法二：Platt Scaling**

将原始置信度作为特征，训练一个简单的逻辑回归模型来映射到校准后的置信度：
```python
from sklearn.linear_model import LogisticRegression

# 在验证集上训练校准器
calibrator = LogisticRegression()
# X = 模型的原始置信度分数
# y = 是否正确 (0/1)
calibrator.fit(X_raw_confidences, y_correctness)

# 预测时
calibrated_confidence = calibrator.predict_proba([[raw_confidence]])[0][1]
```

**方法三：Prompt 校准**

直接在 Prompt 中引导模型进行更诚实的置信度评估：
```
在评估置信度时，请严格遵循以下指南：
- 90-100分：你100%确定，信息来自训练数据中反复出现的基本常识
- 70-89分：你比较确定，信息来自可靠的常见来源
- 50-69分：你部分确定，信息可能在不同来源中有不同表述
- 30-49分：你不确定，信息基于推理或模糊记忆
- 0-29分：你基本在猜测，缺乏任何直接相关记忆
```

### 3.3 校准的局限性

- 校准依赖于**验证集的代表性**，如果部署场景的分布与验证集不同，校准效果会衰减
- 校准无法解决**系统性幻觉**（模型从未学到正确事实的情况），只能让概率更诚实地反映不确定性
- **分布偏移（Distribution Shift）**：模型的校准曲线会随着使用场景的变化而缓慢漂移，需要定期重新校准

## 四、置信度驱动的决策

### 4.1 三级置信度决策框架

```
模型生成回答 + 置信度分数
    │
    ├── 置信度 ≥ HIGH_THRESHOLD（如 ≥ 0.85）
    │       → 直接输出，可选标注"高置信度"
    │
    ├── MID_THRESHOLD ≤ 置信度 < HIGH_THRESHOLD（如 0.5-0.85）
    │       → 输出但标注不确定性
    │       → "根据现有信息，...（置信度：中等）"
    │       → 提供来源链接供用户自行判断
    │
    └── 置信度 < MID_THRESHOLD（如 < 0.5）
            → 不直接输出猜测性内容
            → 选项A："我无法提供可靠回答，以下是相关参考信息..."
            → 选项B：转人工处理
            → 选项C：回退到规则引擎/确定性系统
```

### 4.2 不可逆操作的阈值设计

对于不可逆操作（发送邮件、删除数据、执行数据库写入），Agent 应当：

1. **内部置信度检查**：置信度必须达到 VERY_HIGH（如 ≥ 0.95）
2. **影响范围确认**：展示即将执行的操作及其影响范围
3. **用户确认**：对于影响外部系统的操作，始终需要用户显式确认
4. **可撤销性设计**：尽可能使操作可撤销（软删除、延迟发送、Dry Run 预览）

### 4.3 多模型置信度融合

当系统使用多个模型时（如第 13.5 节的多模型路由），每个模型的置信度需要统一校准后才能比较：

```python
def fused_confidence(model_outputs):
    """融合多个模型的置信度"""
    # 每个模型的置信度先通过各自的校准器
    calibrated = []
    for output in model_outputs:
        calibrator = get_calibrator(output.model_name)
        cal_conf = calibrator.calibrate(output.raw_confidence)
        calibrated.append(cal_conf)
    
    # 加权平均（权重可以为模型在该类任务上的历史准确率）
    weights = [get_model_accuracy(m.model_name) for m in model_outputs]
    fused = np.average(calibrated, weights=weights)
    
    return fused
```

## 五、"我不知道"的工程实现

### 5.1 触发不确定回应的时机

```
Agent 应该回复"我不确定/我不知道"的情况：
1. 置信度 < 系统设定阈值
2. 检索结果为空或不相关（无法从外部知识获取依据）
3. 多个来源信息矛盾且无法判断哪个更可靠
4. 任务需要实时数据但当前数据过期
5. 问题是基于错误的假设（"你什么时候停止打你妻子"类问题）
6. 需要的工具不可用（如需要查询数据库但数据库连接失败）
```

### 5.2 好的"我不知道" vs 差的"我不知道"

```
差的"我不知道"：
"对不起，我无法回答这个问题。"
→ 用户不知道原因，也不知道下一步该做什么

好的"我不知道"：
"关于X的具体数据，我目前无法提供准确答案，原因如下：
1. 检索到的资料中缺乏2025年之后的数据（最新资料为2024年3月）
2. 不同来源对此数据的报告存在差异（来源A说42%，来源B说38%）
建议：您可以查看[来源A链接]和[来源B链接]获取更多信息，
或告诉我是否需要我基于2024年的数据做相关分析。"
→ 用户了解原因，有后续行动选项
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 置信度校准 | 使模型的预测概率与实际正确率匹配的过程 |
| Logit-Based Confidence | 从输出 token 的概率分布直接提取置信度 |
| Verbalized Confidence | 让模型用自然语言表达自己的置信度 |
| Temperature Scaling | 通过调整 softmax 温度参数来校准概率 |
| 过度自信偏差 | 模型系统性地高估自己回答正确的概率 |
| 三级决策框架 | 基于置信度分级：高→直接输出，中→标注不确定，低→拒绝回答 |
