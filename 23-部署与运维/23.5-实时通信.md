# 23.5 实时通信 —— WebSocket 长连接管理 + SSE 单向流 + 断线重连

> Agent 与用户之间的交互早已超越了"发送请求—等待—接收完整响应"的陈旧模式。现代 Agent 需要在推理过程中实时推送 Token、即时更新工具调用状态、支持用户中断正在进行的推理——这一切都依赖于实时通信协议。本节深入分析 WebSocket 和 SSE 两种方案在 Agent 场景中的适用边界、实现细节和工程挑战。

---

## 一、Agent 实时通信的场景分析

### 1.1 三种交互模式

Agent 与前端之间存在三种不同的实时通信需求，它们各自有最适合的协议：

```
模式一：推送流式推理结果
─────────────────────────────────────────
Agent → 用户（单向）

场景：
- LLM 逐 Token 生成回复时，将 Token 流式推送给用户
- Agent 执行工具调用时，实时推送状态更新
- Agent 内部思考过程的可视化

推荐协议：SSE (Server-Sent Events)
原因：单向数据流，HTTP 标准，实现简单，自动重连


模式二：双向实时对话
─────────────────────────────────────────
Agent ↔ 用户（双向）

场景：
- 用户可以在 Agent 推理过程中发送"停止"、"重试"等指令
- Agent 在推理过程中需要向用户请求确认或补充信息
- Agent 状态变化实时同步到前端界面

推荐协议：WebSocket
原因：双向通信，低延迟，全双工


模式三：事件驱动的状态同步
─────────────────────────────────────────
Agent → 前端（单向，批量）

场景：
- Agent 从暂停状态恢复后，批量同步当前状态
- 多个用户共享同一个 Agent 会话时，广播状态变更

推荐协议：WebSocket + 消息队列
原因：支持广播，可扩展至多用户
```

### 1.2 SSE vs WebSocket：选型对比

| 维度 | SSE | WebSocket |
|------|-----|-----------|
| **通信方向** | 服务端 → 客户端（单向） | 双向全双工 |
| **协议基础** | HTTP (标准 HTTP/1.1+) | 独立的 WS/WSS 协议 |
| **浏览器支持** | 原生 EventSource API | 原生 WebSocket API |
| **自动重连** | 内置（EventSource 自动重连） | 需自行实现 |
| **消息格式** | 纯文本（可携带 JSON） | 文本或二进制 |
| **连接数限制** | HTTP/1.1 每个域名 6 个并发 | 无浏览器限制（但有服务器限制） |
| **反向代理配置** | 需关闭缓冲（与普通 HTTP 相同） | 需要 Upgrade 握手 |
| **实现复杂度** | 极低 | 中等 |
| **Head-of-Line Blocking** | HTTP/2 下不存在 | 无（独立协议） |
| **Agent 适用场景** | Token 流式输出、单方向状态推送 | 用户中断、实时配置、双向交互 |

**选型决策原则**：

```
Agent 端点的通信方式选择：

如果只需要"服务端 → 客户端"的数据推送
    └── 使用 SSE（实现简单、自动重连、HTTP 标准）

如果需要"客户端 → 服务端"的控制指令
    └── 客户端也需要在 Agent 推理过程中发送消息？
        ├── 是 → 使用 WebSocket（双向实时）
        │        可以同时承载 Token 推送和用户指令
        └── 否 → 使用 SSE + HTTP POST 组合
                   SSE 推送 Token，用户中断通过 POST /cancel 实现

如果需要二进制传输（音频、图像流）
    └── 使用 WebSocket（原生支持二进制帧）
```

## 二、SSE 实现：单向 Token 流推送

### 2.1 SSE 协议格式

SSE 的协议格式极其简单——基于纯文本的事件流：

```
event: token
data: {"text": "人工"}

event: token
data: {"text": "智能"}

event: token
data: {"text": "助"}

event: token
data: {"text": "手"}

event: done
data: {"content": "人工智能助手", "latency_ms": 1523}
```

每个事件由一行或多行组成：
- `event:` — 事件类型（可选，默认 message）
- `data:` — 数据内容（可多行，以换行符拼接）
- `id:` — 事件 ID（用于断线重连时的 Last-Event-ID）
- `retry:` — 重连间隔（毫秒）
- 事件之间用空行分隔

### 2.2 SSE Agent 端点完整实现（FastAPI）

```python
# app/routes/streaming.py
import json
import asyncio
import time
from typing import AsyncGenerator

from fastapi import APIRouter, Request, Depends
from sse_starlette.sse import EventSourceResponse

from app.agent.core import AgentEngine
from app.cache.session_cache import SessionCache
from app.middleware.auth import verify_api_key
from app.config import config


router = APIRouter(prefix="/api/v1")


class SSEEventManager:
    """SSE 事件管理器——管理 Agent 推理过程中的事件推送"""

    def __init__(self, agent_engine: AgentEngine, cache: SessionCache):
        self.agent = agent_engine
        self.cache = cache
        # 存储进行中的推理任务，用于支持取消操作
        self.active_streams: dict[str, asyncio.Task] = {}

    async def generate_events(
        self,
        session_id: str,
        messages: list[dict],
    ) -> AsyncGenerator[dict, None]:
        """生成 SSE 事件流"""
        start_time = time.time()
        all_tokens = []
        task = asyncio.current_task()

        # 注册当前流（用于取消）
        self.active_streams[session_id] = task

        try:
            # 发送会话初始化事件
            yield {"event": "session_start", "data": json.dumps({
                "session_id": session_id,
                "timestamp": time.time(),
            })}

            # Agent 推理循环
            async for event in self.agent.run(messages=messages, stream=True):
                if asyncio.current_task().cancelled():
                    yield {"event": "cancelled", "data": json.dumps({
                        "reason": "user_cancelled",
                    })}
                    return

                if event["type"] == "token":
                    all_tokens.append(event["content"])
                    yield {"event": "token", "data": json.dumps({
                        "text": event["content"],
                        "session_id": session_id,
                    })}

                elif event["type"] == "tool_calls":
                    yield {"event": "tool_calls", "data": json.dumps({
                        "tool_calls": [
                            {
                                "id": tc["id"],
                                "name": tc["function"]["name"],
                                "arguments": tc["function"]["arguments"],
                            }
                            for tc in event["tool_calls"]
                        ],
                        "session_id": session_id,
                    })}

                elif event["type"] == "tool_result":
                    yield {"event": "tool_result", "data": json.dumps({
                        "tool_call_id": event["tool_call_id"],
                        "result_preview": event["result"][:200],  # 截断长结果
                        "session_id": session_id,
                    })}

                elif event["type"] == "usage":
                    yield {"event": "usage", "data": json.dumps({
                        "prompt_tokens": event["prompt_tokens"],
                        "completion_tokens": event["completion_tokens"],
                        "total_tokens": event["total_tokens"],
                    })}

            # 推理完成
            elapsed = int((time.time() - start_time) * 1000)
            yield {"event": "done", "data": json.dumps({
                "content": "".join(all_tokens),
                "latency_ms": elapsed,
                "session_id": session_id,
                "token_count": len(all_tokens),
            })}

        except asyncio.CancelledError:
            yield {"event": "cancelled", "data": json.dumps({
                "reason": "server_cancelled",
                "session_id": session_id,
            })}
        except Exception as e:
            yield {"event": "error", "data": json.dumps({
                "error": str(e),
                "error_code": "INTERNAL_ERROR",
                "session_id": session_id,
            })}
        finally:
            # 清理
            self.active_streams.pop(session_id, None)

    async def cancel_stream(self, session_id: str) -> bool:
        """取消正在进行的 SSE 流"""
        task = self.active_streams.get(session_id)
        if task and not task.done():
            task.cancel()
            return True
        return False


# 全局事件管理器
event_manager = SSEEventManager(
    agent_engine=AgentEngine(config),
    cache=SessionCache(None),  # 实际注入 Redis 客户端
)


@router.post("/chat/stream")
async def chat_stream(
    request: Request,
    api_key: str = Depends(verify_api_key),
):
    """
    SSE 流式对话端点。

    使用方式（前端 JavaScript）：
    ```javascript
    const eventSource = new EventSource('/api/v1/chat/stream', {
        method: 'POST',
        body: JSON.stringify({...}),
    });

    eventSource.addEventListener('token', (e) => {
        const data = JSON.parse(e.data);
        // 追加 Token 到界面
    });

    eventSource.addEventListener('done', (e) => {
        eventSource.close();
    });
    ```
    """
    body = await request.json()
    session_id = body.get("session_id")
    messages = body.get("messages", [])

    # 恢复会话历史（从 Redis 缓存加载，详见 Ch23.4）
    cached_messages = await event_manager.cache.get_messages(session_id)
    full_messages = cached_messages + messages

    return EventSourceResponse(
        event_manager.generate_events(session_id, full_messages)
    )


@router.post("/chat/cancel")
async def cancel_stream(
    request: Request,
    api_key: str = Depends(verify_api_key),
):
    """取消正在进行的 SSE 流"""
    body = await request.json()
    session_id = body.get("session_id")
    cancelled = await event_manager.cancel_stream(session_id)
    return {"cancelled": cancelled}
```

### 2.3 SSE 前端集成

```javascript
// frontend/sse-client.js
class SSEClient {
    constructor() {
        this.eventSource = null;
        this.listeners = {};
        this.reconnectAttempts = 0;
        this.maxReconnectAttempts = 10;
        this.baseDelay = 1000;  // 初始重连延迟 1 秒
    }

    async connect(sessionId, messages) {
        // SSE 不支持 POST 请求体，所以使用 URL 参数
        // 替代方案：先用 POST 创建会话，再用 SSE GET 连接
        const url = `/api/v1/chat/stream?session_id=${sessionId}`;
        this.eventSource = new EventSource(url);

        // 注册标准事件处理
        this.eventSource.addEventListener('token', (e) => {
            const data = JSON.parse(e.data);
            if (this.listeners['token']) {
                this.listeners['token'](data.text);
            }
        });

        this.eventSource.addEventListener('tool_calls', (e) => {
            const data = JSON.parse(e.data);
            if (this.listeners['tool_calls']) {
                this.listeners['tool_calls'](data.tool_calls);
            }
        });

        this.eventSource.addEventListener('done', (e) => {
            const data = JSON.parse(e.data);
            if (this.listeners['done']) {
                this.listeners['done'](data);
            }
            this.eventSource.close();
            this.reconnectAttempts = 0;
        });

        this.eventSource.addEventListener('error', (e) => {
            if (this.eventSource.readyState === EventSource.CLOSED) {
                // 连接关闭——尝试重连
                this._reconnect(sessionId, messages);
            }
        });

        // 通过 POST 发送消息体
        await fetch(`/api/v1/chat/stream/start`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ session_id: sessionId, messages }),
        });
    }

    _reconnect(sessionId, messages) {
        if (this.reconnectAttempts >= this.maxReconnectAttempts) {
            console.error('SSE 最大重连次数已达上限');
            if (this.listeners['max_retry']) {
                this.listeners['max_retry']();
            }
            return;
        }

        const delay = this.baseDelay * Math.pow(2, this.reconnectAttempts);
        console.log(`SSE 断线重连 (第 ${this.reconnectAttempts + 1} 次)，延迟 ${delay}ms`);

        setTimeout(() => {
            this.reconnectAttempts++;
            this.connect(sessionId, messages);
        }, delay);
    }

    on(event, callback) {
        this.listeners[event] = callback;
    }

    disconnect() {
        if (this.eventSource) {
            this.eventSource.close();
            this.eventSource = null;
        }
    }
}


// 使用示例
const client = new SSEClient();

client.on('token', (text) => {
    displayToken(text);  // 前台追加 Token
});

client.on('tool_calls', (calls) => {
    showToolCalls(calls);  // 显示工具调用卡片
});

client.on('done', (data) => {
    console.log(`推理完成，耗时 ${data.latency_ms}ms`);
});

// 开始 SSE 流
client.connect('session-123', [
    { role: 'user', content: '帮我分析这份报告' }
]);
```

## 三、WebSocket 实现：双向实时通信

### 3.1 Agent WebSocket 协议设计

```
客户端 → 服务端（指令）           服务端 → 客户端（事件）
─────────────────────────       ─────────────────────────
{                              {
  "type": "chat",                 "type": "token",
  "messages": [...],              "text": "..."
  "stream": true                }
}                              {
                                 "type": "tool_calls",
{                                "tool_calls": [...]
  "type": "cancel"             }
}                              {
                                 "type": "tool_result",
{                                "tool_call_id": "...",
  "type": "interrupt",           "result": "..."
  "instruction": "改用另一种    }
  方法"                        {
}                                "type": "done",
                                 "content": "..."
{                              }
  "type": "ping"               {
}                                "type": "pong"
                              }
                              {
                                "type": "error",
                                "code": "...",
                                "message": "..."
                              }
```

### 3.2 WebSocket Agent 端点完整实现

```python
# app/routes/websocket.py
import json
import asyncio
import time
import uuid
from typing import Optional

from fastapi import APIRouter, WebSocket, WebSocketDisconnect
from app.agent.core import AgentEngine
from app.cache.session_cache import SessionCache
from app.config import config


router = APIRouter()


class WebSocketConnectionManager:
    """
    WebSocket 连接管理器——管理所有活跃的 Agent WS 连接。

    职责：
    - 连接生命周期管理（accept / disconnect）
    - 消息路由（接收客户端消息 → Agent 推理 → 发送事件）
    - 心跳检测（Ping / Pong）
    - 断线重连支持（Session ID 关联）
    - 并发推理控制（一个连接同时只能有一个推理任务）
    """

    def __init__(self, agent_engine: AgentEngine, cache: SessionCache):
        self.agent = agent_engine
        self.cache = cache
        # 活跃连接: {connection_id: WebSocket}
        self.connections: dict[str, WebSocket] = {}
        # Session 到 Connection 的映射: {session_id: connection_id}
        self.session_map: dict[str, str] = {}
        # 进行中的推理任务: {connection_id: asyncio.Task}
        self.active_tasks: dict[str, asyncio.Task] = {}
        # 心跳检测任务
        self._heartbeat_task: Optional[asyncio.Task] = None

    async def connect(self, websocket: WebSocket, session_id: str) -> str:
        """接受新连接并注册"""
        await websocket.accept()
        connection_id = str(uuid.uuid4())

        self.connections[connection_id] = websocket
        self.session_map[session_id] = connection_id

        # 发送连接确认
        await self._send(connection_id, {
            "type": "connected",
            "connection_id": connection_id,
            "session_id": session_id,
            "timestamp": time.time(),
        })

        # 恢复会话上下文
        meta = await self.cache.get_session_meta(session_id)
        if meta:
            await self._send(connection_id, {
                "type": "session_restored",
                "meta": meta,
            })

        # 启动心跳检测（仅在第一个连接时启动）
        if self._heartbeat_task is None:
            self._heartbeat_task = asyncio.create_task(self._heartbeat_loop())

        return connection_id

    async def disconnect(self, connection_id: str):
        """断开连接并清理资源"""
        # 取消进行中的推理任务
        task = self.active_tasks.pop(connection_id, None)
        if task and not task.done():
            task.cancel()

        # 清理映射关系
        websocket = self.connections.pop(connection_id, None)
        # 从 session_map 中移除
        for sid, cid in list(self.session_map.items()):
            if cid == connection_id:
                del self.session_map[sid]
                break

        # 关闭 WebSocket
        if websocket:
            try:
                await websocket.close()
            except Exception:
                pass

        # 如果没有活跃连接，停止心跳
        if not self.connections and self._heartbeat_task:
            self._heartbeat_task.cancel()
            self._heartbeat_task = None

    async def handle_message(self, connection_id: str, data: dict):
        """处理客户端发送的消息"""
        msg_type = data.get("type")

        if msg_type == "chat":
            # 开始 Agent 推理
            await self._start_agent_inference(connection_id, data)

        elif msg_type == "cancel":
            # 取消正在进行的推理
            await self._cancel_inference(connection_id)

        elif msg_type == "interrupt":
            # 用户打断并给出新指令（高级特性）
            await self._interrupt_inference(connection_id, data.get("instruction", ""))

        elif msg_type == "ping":
            await self._send(connection_id, {"type": "pong"})

        elif msg_type == "config":
            # 动态更新 Agent 配置
            await self._update_config(connection_id, data.get("config", {}))

    async def _start_agent_inference(self, connection_id: str, data: dict):
        """启动 Agent 推理任务"""
        # 如果已有推理在进行，先取消旧的
        old_task = self.active_tasks.get(connection_id)
        if old_task and not old_task.done():
            old_task.cancel()

        # 创建新推理任务
        task = asyncio.create_task(
            self._run_agent_inference(connection_id, data)
        )
        self.active_tasks[connection_id] = task

    async def _run_agent_inference(self, connection_id: str, data: dict):
        """执行 Agent 推理并推送事件"""
        messages = data.get("messages", [])
        stream = data.get("stream", True)

        try:
            async for event in self.agent.run(messages=messages, stream=stream):
                if event["type"] == "token":
                    await self._send(connection_id, {
                        "type": "token",
                        "text": event["content"],
                    })
                elif event["type"] == "tool_calls":
                    await self._send(connection_id, {
                        "type": "tool_calls",
                        "tool_calls": event["tool_calls"],
                    })
                elif event["type"] == "tool_result":
                    await self._send(connection_id, {
                        "type": "tool_result",
                        "tool_call_id": event["tool_call_id"],
                        "result": event["result"][:500],  # 截断
                    })
                elif event["type"] == "done":
                    await self._send(connection_id, {
                        "type": "done",
                        "content": event["content"],
                        "usage": event.get("usage", {}),
                    })

        except asyncio.CancelledError:
            await self._send(connection_id, {
                "type": "cancelled",
                "reason": "user_cancelled",
            })
        except Exception as e:
            await self._send(connection_id, {
                "type": "error",
                "code": "INFERENCE_ERROR",
                "message": str(e),
            })

    async def _cancel_inference(self, connection_id: str):
        """取消推理"""
        task = self.active_tasks.get(connection_id)
        if task and not task.done():
            task.cancel()
            await self._send(connection_id, {
                "type": "cancelled",
                "reason": "user_cancelled",
            })

    async def _interrupt_inference(self, connection_id: str, instruction: str):
        """中断当前推理并注入新指令"""
        task = self.active_tasks.get(connection_id)
        if task and not task.done():
            task.cancel()
            # 在更复杂的实现中，这里会将 instruction 注入到 Agent 的上下文中
            # 然后重新启动推理
            await self._send(connection_id, {
                "type": "interrupted",
                "instruction_received": instruction,
            })

    async def _update_config(self, connection_id: str, config_data: dict):
        """更新连接级别的 Agent 配置"""
        await self._send(connection_id, {
            "type": "config_updated",
            "config": config_data,
        })

    async def _send(self, connection_id: str, data: dict):
        """安全地发送消息"""
        websocket = self.connections.get(connection_id)
        if websocket is None:
            return
        try:
            await websocket.send_json(data)
        except Exception:
            # 发送失败，可能是连接已断开
            await self.disconnect(connection_id)

    async def _heartbeat_loop(self):
        """心跳检测循环"""
        while True:
            try:
                await asyncio.sleep(30)  # 每 30 秒检测一次
                for connection_id in list(self.connections.keys()):
                    if connection_id in self.active_tasks:
                        continue  # 推理中的连接不检测
                    websocket = self.connections.get(connection_id)
                    if websocket:
                        try:
                            await websocket.send_json({"type": "ping"})
                        except Exception:
                            await self.disconnect(connection_id)
            except asyncio.CancelledError:
                break
            except Exception:
                continue

    async def broadcast(self, message: dict, exclude: Optional[str] = None):
        """广播消息给所有连接（或排除某个连接）"""
        for connection_id in list(self.connections.keys()):
            if connection_id == exclude:
                continue
            await self._send(connection_id, message)

@router.websocket("/ws/{session_id}")
async def agent_websocket_endpoint(

    session_id: str,
):
    """
    Agent WebSocket 端点。

    使用方式（前端 JavaScript）：
    ```javascript
    const ws = new WebSocket('wss://api.example.com/ws/session-123');

    ws.onopen = () => {
        ws.send(JSON.stringify({
            type: 'chat',
            messages: [{ role: 'user', content: '你好' }],

        }));

    ws.onmessage = (event) => {
        const data = JSON.parse(event.data);
        switch (data.type) {
            case 'token':
                // 显示 Token
                break;
            case 'tool_calls':
                // 显示工具调用
                break;
            case 'done':
                // 推理完成
                break;
        }
    };
    ```
    """
    connection_id = await ws_manager.connect(websocket, session_id)

    try:
        while True:
            # 接收客户端消息（可能同时有多个消息排队）
            raw = await websocket.receive_text()
            data = json.loads(raw)
            await ws_manager.handle_message(connection_id, data)

    except WebSocketDisconnect:
        pass
    except Exception as e:
        print(f"WebSocket 错误 ({session_id}): {e}")
    finally:
        await ws_manager.disconnect(connection_id)
```

### 3.3 WebSocket 前端集成

```javascript
// frontend/ws-client.js
class WSClient {
    constructor(url, sessionId) {
        this.url = url;
        this.sessionId = sessionId;
        this.ws = null;
        this.listeners = {};
        this.reconnectAttempts = 0;
        this.maxReconnectAttempts = 10;
        this.baseDelay = 1000;
        this.messageQueue = [];  // 断线期间的消息队列
        this.isConnected = false;
    }

    connect() {
        const wsUrl = `${this.url}/${this.sessionId}`;
        this.ws = new WebSocket(wsUrl);

        this.ws.onopen = () => {
            this.isConnected = true;
            this.reconnectAttempts = 0;
            console.log(`WebSocket 已连接: ${wsUrl}`);

            // 发送队列中的消息
            while (this.messageQueue.length > 0) {
                const msg = this.messageQueue.shift();
                this.send(msg);
            }

            if (this.listeners['connect']) {
                this.listeners['connect']();
            }
        };

        this.ws.onmessage = (event) => {
            const data = JSON.parse(event.data);

            // 自动处理 ping（无需业务方介入）
            if (data.type === 'ping') {
                this.send({ type: 'pong' });
                return;
            }

            // 派发到注册的监听器
            if (this.listeners[data.type]) {
                this.listeners[data.type](data);
            }
        };

        this.ws.onclose = (event) => {
            this.isConnected = false;
            console.log(`WebSocket 已关闭 (code: ${event.code})`);

            // 非正常关闭时尝试重连
            if (event.code !== 1000) {  // 1000 = 正常关闭
                this._reconnect();
            }

            if (this.listeners['disconnect']) {
                this.listeners['disconnect'](event.code);
            }
        };

        this.ws.onerror = (error) => {
            console.error('WebSocket 错误:', error);
            if (this.listeners['error']) {
                this.listeners['error'](error);
            }
        };
    }

    _reconnect() {
        if (this.reconnectAttempts >= this.maxReconnectAttempts) {
            console.error('WebSocket 最大重连次数已达上限');
            if (this.listeners['max_retry']) {
                this.listeners['max_retry']();
            }
            return;
        }

        const delay = this.baseDelay * Math.pow(2, this.reconnectAttempts);
        // 增加随机抖动（jitter），避免多个客户端同时重连
        const jitter = Math.random() * 1000;
        const totalDelay = delay + jitter;

        console.log(
            `WebSocket 重连 (第 ${this.reconnectAttempts + 1} 次)，` +
            `延迟 ${Math.round(totalDelay)}ms`
        );

        this.reconnectAttempts++;

        setTimeout(() => {
            this.connect();
        }, totalDelay);
    }

    send(data) {
        if (!this.isConnected) {
            // 未连接时入队，连接后自动发送
            this.messageQueue.push(data);
            return;
        }
        this.ws.send(JSON.stringify(data));
    }

    /**
     * 发送聊天消息（Agent 推理请求）
     */
    sendMessage(messages, options = {}) {
        this.send({
            type: 'chat',
            messages,
            stream: options.stream ?? true,
            temperature: options.temperature,
        });
    }

    /**
     * 取消正在进行的推理
     */
    cancel() {
        this.send({ type: 'cancel' });
    }

    on(event, callback) {
        this.listeners[event] = callback;
    }

    disconnect() {
        if (this.ws) {
            this.ws.close(1000, 'user_disconnect');
            this.ws = null;
        }
        this.isConnected = false;
    }
}


// 使用示例
const client = new WSClient('wss://api.example.com/ws', 'session-123');

client.on('connect', () => {
    console.log('已连接，开始对话');
    client.sendMessage([
        { role: 'user', content: '帮我分析一下这份数据' }
    ]);
});

client.on('token', (data) => {
    displayToken(data.text);
});

client.on('tool_calls', (data) => {
    showToolCalls(data.tool_calls);
});

client.on('cancelled', (data) => {
    console.log('推理已取消:', data.reason);
});

client.on('disconnect', (code) => {
    showReconnectNotice();
});

client.connect();
```

## 四、断线重连机制

### 4.1 会话状态恢复的核心逻辑

断线重连最关键的工程问题是：**如何让重连后的会话无缝接续断点**。

```
时间线: 连接断开 ─────────── 重连成功 ─────────── 继续推理
                            │
                            ├── 1. 前端恢复 WebSocket 连接
                            │
                            ├── 2. 发送 session_id（服务端识别旧会话）
                            │
                            ├── 3. 服务端从 Redis 恢复会话上下文
                            │     ├── 消息历史
                            │     ├── 进行中的推理状态（如果有）
                            │     └── Agent 配置
                            │
                            ├── 4. 如果推理在进行中
                            │     ├── 前端收到 "in_progress" 事件
                            │     ├── 接收断线期间积压的 Token
                            │     └── 继续接收后续事件
                            │
                            └── 5. 如果推理已完成
                                  ├── 前端收到完整结果
                                  └── 前端恢复正常对话状态
```

### 4.2 服务端断线恢复实现

```python
# app/reconnection.py
import json
import asyncio
import time
from collections import deque


class ReconnectionManager:
    """
    断线重连管理器——断线期间缓存事件，重连后批量推送。

    设计原理：
    - 使用环形缓冲区保存最近 N 个事件
    - 断线后继续缓存事件（最多保留 M 秒）
    - 重连时根据 Last-Event-ID 回放丢失的事件
    - 超过缓存窗口的事件无法恢复，需要重新推理
    """

    def __init__(self, max_events: int = 1000, max_age: float = 60.0):
        self.max_events = max_events
        self.max_age = max_age
        # {session_id: deque of (event_id, timestamp, event_data)}
        self.buffers: dict[str, deque] = {}

    def get_buffer(self, session_id: str) -> deque:
        """获取或创建会话的事件缓冲区"""
        if session_id not in self.buffers:
            self.buffers[session_id] = deque(maxlen=self.max_events)
        return self.buffers[session_id]

    def push_event(self, session_id: str, event_type: str, data: dict):
        """向缓冲区添加事件"""
        buffer = self.get_buffer(session_id)
        event = {
            "id": f"{int(time.time() * 1000)}-{len(buffer)}",
            "type": event_type,
            "data": data,
            "timestamp": time.time(),
        }
        buffer.append(event)
        # 清理过期事件
        self._cleanup(buffer)

    def _cleanup(self, buffer: deque):
        """移除超出时间窗口的旧事件"""
        cutoff = time.time() - self.max_age
        while buffer and buffer[0]["timestamp"] < cutoff:
            buffer.popleft()

    def get_missed_events(
        self, session_id: str, last_event_id: str
    ) -> list[dict]:
        """获取从 last_event_id 之后的所有事件（用于重连恢复）"""
        buffer = self.get_buffer(session_id)
        missed = []
        found = False

        for event in buffer:
            if found:
                missed.append(event)
            elif event["id"] == last_event_id:
                found = True

        if not found and len(buffer) > 0:
            # last_event_id 不在缓冲区中（可能已过期）
            # 返回全部缓冲区内容，让前端自己判断是否需要重建会话
            return list(buffer)

        return missed

    def release_buffer(self, session_id: str):
        """会话结束后释放缓冲区"""
        self.buffers.pop(session_id, None)


# 全局重连管理器（可在 FastAPI lifespan 中初始化）
reconnect_manager = ReconnectionManager()
```

### 4.3 前端重连策略

```javascript
// frontend/reconnection.js
class ReconnectionStrategy {
    /**
     * 断线重连策略
     *
     * 策略层次：
     * 1. 瞬时重连：断线后立即尝试重连（应对网络抖动）
     * 2. 指数退避：多次失败后延迟逐渐增加
     * 3. 会话重建：如果断线时间过长，重建新会话
     */
    constructor(sessionId, onReconnect) {
        this.sessionId = sessionId;
        this.onReconnect = onReconnect;
        this.lastEventId = null;
        this.disconnectTime = null;
        this.maxSessionAge = 300000;  // 会话最长保留 5 分钟
    }

    /**
     * 记录接收到的事件 ID
     */
    recordEvent(eventId) {
        this.lastEventId = eventId;
    }

    /**
     * 断线发生时记录时间
     */
    onDisconnect() {
        this.disconnectTime = Date.now();
    }

    /**
     * 重连时调用——决定使用哪种恢复策略
     */
    async onReconnectAttempt() {
        const offlineDuration = Date.now() - this.disconnectTime;

        // 策略 1: 断线时间短 (< 30s) → 直接恢复
        if (offlineDuration < 30000) {
            console.log('快速重连，直接恢复会话');
            await this.onReconnect({
                strategy: 'resume',
                lastEventId: this.lastEventId,
            });
            return;
        }

        // 策略 2: 断线时间中等 (30s - 5min) → 从已知状态恢复
        if (offlineDuration < this.maxSessionAge) {
            console.log('断线时间较长，从已知状态恢复');
            // 发送断线前最后已知的状态快照
            await this.onReconnect({
                strategy: 'restore',
                lastEventId: this.lastEventId,
                // 最后已知的消息历史和 Agent 状态从本地缓存获取
                localState: this.getLocalState(),
            });
            return;
        }

        // 策略 3: 断线时间过长 (> 5min) → 重建会话
        console.log('断线时间过长，重建新会话');
        await this.onReconnect({
            strategy: 'new_session',
        });
    }

    getLocalState() {
        try {
            const saved = localStorage.getItem(`agent_state_${this.sessionId}`);
            return saved ? JSON.parse(saved) : null;
        } catch {
            return null;
        }
    }
}

### 5.1 WebSocket 连接池管理

```python
# app/routes/ws_pool.py
class WebSocketPool:
    """
    WebSocket 连接池——限制最大连接数，管理资源。

    生产环境考虑：
    - 单个 Agent 服务器通常能支撑 1000-5000 个并发 WS 连接
    - 每个空闲连接约消耗 10-20KB 内存（TCP 缓冲区）
    - 每个活跃推理连接约消耗 50-200MB 内存（会话历史 + 推理状态）
    """

    def __init__(self, max_connections: int = 5000, max_inference_per_node: int = 50):
        self.max_connections = max_connections
        self.max_inference = max_inference_per_node
        self.connection_count = 0
        self.inference_count = 0

    async def try_acquire(self) -> bool:
        """尝试获取连接槽位"""
        if self.connection_count >= self.max_connections:
            return False
        self.connection_count += 1
        return True

    async def release(self):
        """释放连接槽位"""
        self.connection_count = max(0, self.connection_count - 1)
        self.inference_count = max(0, self.inference_count - 1)

    async def try_start_inference(self) -> bool:
        """尝试启动推理（限制并发推理数）"""
        if self.inference_count >= self.max_inference:
            return False
        self.inference_count += 1
        return True
```

### 5.2 水平扩展方案

当单机无法支撑更多 WebSocket 连接时，需要通过水平扩展来解决：

```
方案 A：Sticky Session（会话亲和性）
─────────────────────────────────
负载均衡器根据 session_id 将同一用户的 WS 连接固定到同一台后端。
优点：实现简单，不需要共享状态
缺点：后端宕机时所有连接断开

方案 B：Redis Pub/Sub 广播
─────────────────────────────────
后端实例之间通过 Redis Pub/Sub 同步消息。
所有实例订阅同一个频道，用户连接到任意实例都能接收消息。
优点：实例之间无状态，扩缩容简单
缺点：需要额外的 Redis 带宽

方案 C：专用 WebSocket 网关
─────────────────────────────────
使用独立的 WS 网关层（如 WebSocket King、Soketi、Centrifugo），
Agent 服务只通过 Redis Pub/Sub 推送消息到网关。
优点：WS 连接管理和业务逻辑分离，各自独立扩缩容
缺点：引入了额外的基础设施组件
```

## 六、SSE vs WebSocket 对比总结

```
            SSE                                WebSocket
    ┌──────────────────┐              ┌──────────────────┐
    │  Agent → 用户     │              │ Agent ↔ 用户     │
    │  单向 Token 流    │              │ 双向实时交互      │
    │                   │              │                  │
    │  ✅ 自动重连      │              │ ✅ 全双工        │
    │  ✅ HTTP 标准     │              │ ✅ 低延迟        │
    │  ✅ 实现简单      │              │ ✅ 支持二进制     │
    │  ❌ 单向          │              │ ❌ 需自建重连     │
    │  ❌ 无二进制       │              │ ❌ 更复杂         │
    └──────────────────┘              └──────────────────┘

什么时候用 SSE？
- 只推送 Token 流（最常见的 Agent 场景）
- 用户控制通过独立的 REST 端点（POST /cancel）
- 希望在前端简化实现（EventSource 自动重连）

什么时候用 WebSocket？
- 用户需要实时中断/干预 Agent 推理
- 需要推送二进制数据（音频流、实时图像）
- Agent 需要向用户请求即时确认
- 需要低延迟的双向通信
```

**最佳实践建议**：对于大多数 Agent 产品，推荐以 SSE 为主要通信协议（简单可靠），仅在需要用户实时干预的场景下使用 WebSocket 作为补充通道。可以混合使用两个协议：

```
Agent 服务体系中的实时通信：
┌───────────────────────────────────────────────┐
│   前端应用                                        │
│  ┌─────────────┐     ┌─────────────┐          │
│  │ SSE Client  │     │ WS Client   │          │
│  │ (Token 流)   │     │ (控制指令)   │          │
│  └──────┬──────┘     └──────┬──────┘          │
│         │                   │                  │
└─────────┼───────────────────┼──────────────────┘
          │ SSE               │ WebSocket
          ▼                   ▼
┌───────────────────────────────────────────────┐
│   Agent 服务后端                                │
│  ┌─────────────┐     ┌─────────────┐          │
│  │ SSE Router  │     │ WS Router   │          │
│  │ /chat/stream │     │ /ws/{session}│         │
│  └──────┬──────┘     └──────┬──────┘          │
│         │                   │                  │
│         └──────┬────────────┘                  │
│                ▼                               │
│         ┌──────────────┐                       │
│         │ Agent Engine  │                       │
│         │ (共享实例)     │                       │
│         └──────────────┘                       │
└───────────────────────────────────────────────┘
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| SSE (Server-Sent Events) | 基于 HTTP 的单向服务端推送协议，浏览器原生 EventSource API 支持自动重连 |
| WebSocket | 独立于 HTTP 的全双工通信协议，通过 Upgrade 握手建立持久连接 |
| 断线重连 (Reconnection) | 网络中断后自动恢复连接并续传断点消息的机制 |
| 指数退避 (Exponential Backoff) | 重连延迟逐次加倍，配合随机抖动避免重连风暴 |
| 心跳检测 (Heartbeat) | 定期发送 Ping/Pong 帧检测连接活性 |
| 事件缓冲 (Event Buffer) | 断线期间缓存事件，重连后批量回放 |
| Last-Event-ID | SSE 标准字段，用于断线重连时的消息续传 |
| Sticky Session | 负载均衡策略，将同一用户的连接固定到同一台后端服务器 |
