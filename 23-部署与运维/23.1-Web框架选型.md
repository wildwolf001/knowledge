# 23.1 Web 框架选型 —— FastAPI + Uvicorn 的异步部署模式

> 将 Agent 从开发笔记本推向生产环境，第一道门槛是选择一个匹配 Agent 运行模式的 Web 框架。Agent 不是传统的 CRUD 应用——它需要处理长连接、流式输出、异步工具调用和不确定性延迟。本章从 Agent 工程的特有需求出发，分析 FastAPI + Uvicorn 为何成为当前 Agent 部署的主流选择，并给出完整的实现代码。

---

## 一、Agent 对 Web 框架的独特需求

### 1.1 传统 Web 框架的局限

传统的 WSGI 框架（Flask、Django）是为"请求-响应"模式设计的：客户端发送 HTTP 请求，服务器在短时间内（通常 < 1s）返回一个完整的 HTTP 响应。这一模型在 Agent 场景下面临三个根本性挑战：

**① 长延迟适配问题**
Agent 的推理过程可能需要几秒到几十秒，内部涉及多轮 Think-Act-Observe 循环、外部 API 调用、文档检索等。WSGI 同步模型下，一个长时间占用的 worker 会阻塞整个线程池，导致服务器吞吐量断崖式下降。

**② 流式输出需求**
现代 Agent 需要逐 token 流式输出推理过程和最终回答（详见 Ch21.5 流式通信）。WSGI 标准不支持 HTTP 流式响应（Server-Sent Events 或 Chunked Transfer Encoding）。

**③ WebSocket 双工通信**
Agent 经常需要与前端建立持久化的双向通信通道，用于实时推送状态更新、接收用户的即时干预。WSGI 框架无法原生支持 WebSocket。

### 1.2 ASGI 标准的诞生

ASGI（Asynchronous Server Gateway Interface）是 WSGI 的异步继任者，由 Django Channels 团队提出，目前已被 Python Web 生态广泛接受。ASGI 的核心能力：

```
WSGI 模式: 请求 → 处理 → 响应 (同步阻塞)
             单次调用，一对一

ASGI 模式: 请求 → 处理 → 流式推送 (异步非阻塞)
             同时支持 HTTP / WebSocket / SSE / Lifespan
```

ASGI 标准定义了三种消息协议在同一连接上的共存方式：
- **HTTP**: 标准的请求-响应模式，但支持流式 body
- **WebSocket**: 全双工持久连接
- **Lifespan**: 应用启动/关闭的事件通知

### 1.3 为什么选择 FastAPI + Uvicorn

| 特性 | FastAPI | Flask | Django | Starlette |
|------|---------|-------|--------|-----------|
| 异步原生 | 是 | 需插件 | 3.1+ 有限支持 | 是（底层） |
| OpenAPI 自动生成 | 内置 | 需 flasgger | 需 drf-spectacular | 无 |
| WebSocket 支持 | 内置 | 需插件 | Channels | 内置 |
| 类型校验 (Pydantic) | 内置 | 无 | 需 drf | 无 |
| 性能 (请求/秒) | ~24,000 | ~4,500 | ~7,200 | ~28,000 |
| Agent 生态活跃度 | 高 | 低 | 中 | 低 |

FastAPI 基于 Starlette 构建，但增加了对 Agent 开发至关重要的 Pydantic 模型校验和自动 API 文档生成。对于 Agent 服务，FastAPI 的轻量异步模型意味着可以在保持高吞吐的同时处理复杂的长延迟推理。

### 2.4 Agent 核心端点（流式 + 非流式）

这是 Agent 服务的核心——一个同时支持流式和非流式响应的 `POST /api/v1/chat` 端点：

```python
# app/agent/core.py
import asyncio
import time
import uuid
from typing import AsyncGenerator

from openai import AsyncOpenAI


class AgentEngine:
    """Agent 推理引擎 — 处理多轮工具调用循环"""

    def __init__(self, config):
        self.config = config
        self.client = AsyncOpenAI()

    async def run(
        self,
        messages: list[dict],
        stream: bool = False,
        temperature: float | None = None,
        max_tokens: int | None = None,
    ) -> AsyncGenerator[dict, None]:
        """
        执行 Agent 推理循环。
        支持流式和非流式两种模式。
        """
        temp = temperature or self.config.temperature
        max_tok = max_tokens or self.config.max_tokens
        tool_round = 0

        # 如果消息列表的第一个不是 system prompt，自动插入
        if not messages or messages[0].get("role") != "system":
            messages.insert(0, {
                "role": "system",
                "content": "你是一个智能助手，可以调用工具来帮助用户。"
            })

        while tool_round < self.config.max_tool_rounds:
            tool_round += 1

            if stream:
                # ========== 流式模式 ==========
                full_content = ""
                tool_calls_buffer = []

                response = await self.client.chat.completions.create(
                    model=self.config.model_name,
                    messages=messages,
                    temperature=temp,
                    max_tokens=max_tok,
                    stream=True,
                    stream_options={"include_usage": True},
                )

                async for chunk in response:
                    delta = chunk.choices[0].delta if chunk.choices else None
                    if delta is None:
                        continue

                    # 文本增量
                    if delta.content:
                        full_content += delta.content
                        yield {"type": "token", "content": delta.content}

                    # 工具调用增量（流式工具调用）
                    if delta.tool_calls:
                        for tc in delta.tool_calls:
                            # 收集工具调用的各字段
                            while len(tool_calls_buffer) <= tc.index:
                                tool_calls_buffer.append({
                                    "id": "",
                                    "type": "function",
                                    "function": {"name": "", "arguments": ""}
                                })
                            if tc.id:
                                tool_calls_buffer[tc.index]["id"] = tc.id
                            if tc.function and tc.function.name:
                                tool_calls_buffer[tc.index]["function"]["name"] += tc.function.name
                            if tc.function and tc.function.arguments:
                                tool_calls_buffer[tc.index]["function"]["arguments"] += tc.function.arguments

                    # 用法统计（流式模式下在最后一个 chunk 中）
                    if chunk.usage:
                        yield {
                            "type": "usage",
                            "prompt_tokens": chunk.usage.prompt_tokens,
                            "completion_tokens": chunk.usage.completion_tokens,
                            "total_tokens": chunk.usage.total_tokens,
                        }

                # 流式推理结束，检查是否有工具调用
                if tool_calls_buffer:
                    yield {"type": "tool_calls", "tool_calls": tool_calls_buffer}

                    # 执行工具
                    for tc in tool_calls_buffer:
                        tool_result = await self.execute_tool(
                            tc["function"]["name"],
                            tc["function"]["arguments"]
                        )
                        yield {"type": "tool_result", "tool_call_id": tc["id"], "result": tool_result}

                        # 将工具调用和结果追加到消息历史
                        messages.append({
                            "role": "assistant",
                            "tool_calls": [{
                                "id": tc["id"],
                                "type": "function",
                                "function": {
                                    "name": tc["function"]["name"],
                                    "arguments": tc["function"]["arguments"]
                                }
                            }],
                            "content": None
                        })
                        messages.append({
                            "role": "tool",
                            "tool_call_id": tc["id"],
                            "content": str(tool_result)
                        })

                    # 继续下一轮推理
                    continue

                # 没有工具调用，流式结束
                yield {"type": "done", "content": full_content}
                return

            else:
                # ========== 非流式模式 ==========
                response = await self.client.chat.completions.create(
                    model=self.config.model_name,
                    messages=messages,
                    temperature=temp,
                    max_tokens=max_tok,
                    stream=False,
                )

                choice = response.choices[0]
                message = choice.message

                if message.tool_calls:
                    # 有工具调用 → 执行工具后继续
                    yield {"type": "tool_calls", "tool_calls": [
                        {
                            "id": tc.id,
                            "function": {
                                "name": tc.function.name,
                                "arguments": tc.function.arguments
                            }
                        }
                        for tc in message.tool_calls
                    ]}

                    for tc in message.tool_calls:
                        tool_result = await self.execute_tool(
                            tc.function.name,
                            tc.function.arguments
                        )
                        yield {"type": "tool_result", "tool_call_id": tc.id, "result": tool_result}

                        messages.append({
                            "role": "assistant",
                            "tool_calls": [{
                                "id": tc.id,
                                "type": "function",
                                "function": {
                                    "name": tc.function.name,
                                    "arguments": tc.function.arguments
                                }
                            }],
                            "content": None
                        })
                        messages.append({
                            "role": "tool",
                            "tool_call_id": tc.id,
                            "content": str(tool_result)
                        })

                    continue

                # 最终回复
                yield {
                    "type": "done",
                    "content": message.content or "",
                    "usage": {
                        "prompt_tokens": response.usage.prompt_tokens if response.usage else 0,
                        "completion_tokens": response.usage.completion_tokens if response.usage else 0,
                        "total_tokens": response.usage.total_tokens if response.usage else 0,
                    }
                }
                return

    async def execute_tool(self, name: str, arguments_json: str) -> str:
        """执行工具调用（简化实现）"""
        import json
        try:
            args = json.loads(arguments_json)
        except json.JSONDecodeError:
            return f"Error: 无效的 JSON 参数: {arguments_json}"

        tool_map = self._get_tools()
        if name not in tool_map:
            return f"Error: 未知工具: {name}"

        try:
            result = await asyncio.wait_for(
                tool_map[name](**args),
                timeout=self.config.tool_timeout
            )
            return result
        except asyncio.TimeoutError:
            return f"Error: 工具 {name} 执行超时（{self.config.tool_timeout}s）"
        except Exception as e:
            return f"Error: 工具 {name} 执行失败: {str(e)}"

    def _get_tools(self) -> dict:
        """返回工具注册表"""
        # 实际项目中通过工具注册系统动态加载
        from app.agent.tools import tool_registry
        return tool_registry.get_all()
```

```python
import uuid
import json
import asyncio
from contextlib import asynccontextmanager

from fastapi import FastAPI, HTTPException, Depends, Request
from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import StreamingResponse, JSONResponse

from app.config import config

from app.agent.core import AgentEngine
from app.middleware.auth import verify_api_key

# 全局实例

rate_limiter: RateLimiter = None
start_time: float = time.time()
active_sessions: dict = {}  # 简单内存会话跟踪，生产环境使用 Redis


@asynccontextmanager
async def lifespan(app: FastAPI):
    """应用生命周期管理"""
    global agent_engine, rate_limiter

    # 启动事件
    agent_engine = AgentEngine(config)
    rate_limiter = RateLimiter(config.redis_url)

    print(f"[{config.app_name}] Agent engine initialized, model={config.model_name}")
    yield

    # 关闭事件
    print(f"[{config.app_name}] Shutting down...")
    # 清理资源
    active_sessions.clear()


app = FastAPI(
    title=config.app_name,
    version="1.0.0",
    lifespan=lifespan,
)

# CORS 配置
app.add_middleware(
    CORSMiddleware,
    allow_origins=config.allowed_origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


# ===========================
# Agent 核心端点：非流式对话
# ===========================
@app.post(f"{config.api_prefix}/chat", response_model=AgentResponse)
async def chat(
    request: AgentRequest,
    req: Request,
    api_key: str = Depends(verify_api_key),
):
    """非流式 Agent 对话端点"""
    # 限流检查
    client_ip = req.client.host if req.client else "unknown"
    await rate_limiter.check(client_ip)

    # 会话初始化/恢复
    session_id = request.session_id
    session = await _get_or_create_session(session_id)
    active_sessions[session_id] = time.time()

    # 构造消息列表
    messages = session.get("system_prompt", [])
    messages.extend([
        {"role": m.role, "content": m.content}
        for m in request.messages
    ])

    start = time.time()
    final_content = ""
    total_tool_calls = 0
    usage = {}

    try:
        async with asyncio.timeout(config.agent_timeout):
            async for event in agent_engine.run(
                messages=messages,
                stream=False,
                temperature=request.temperature,
                max_tokens=request.max_tokens,
            ):
                if event["type"] == "tool_calls":
                    total_tool_calls += len(event["tool_calls"])
                elif event["type"] == "done":
                    final_content = event.get("content", "")
                    usage = event.get("usage", {})
    except asyncio.TimeoutError:
        raise HTTPException(status_code=504, detail="Agent 推理超时")

    elapsed = int((time.time() - start) * 1000)

    return AgentResponse(
        session_id=session_id,
        reply=final_content,
        metadata=AgentMetadata(
            model=config.model_name,
            total_tokens=usage.get("total_tokens", 0),
            prompt_tokens=usage.get("prompt_tokens", 0),
            completion_tokens=usage.get("completion_tokens", 0),
            latency_ms=elapsed,
            tool_calls_count=total_tool_calls,
        ),
    )

@app.post(f"{config.api_prefix}/chat/stream")
async def chat_stream(
    request: AgentRequest,
    req: Request,
    api_key: str = Depends(verify_api_key),
):
    """流式 Agent 对话端点，使用 Server-Sent Events"""
    client_ip = req.client.host if req.client else "unknown"
    await rate_limiter.check(client_ip)

    session_id = request.session_id
    session = await _get_or_create_session(session_id)
    active_sessions[session_id] = time.time()

    messages = session.get("system_prompt", [])
    messages.extend([
        {"role": m.role, "content": m.content}
        for m in request.messages
    ])

    async def event_generator():
        """SSE 事件生成器"""
        start = time.time()
        try:
            async with asyncio.timeout(config.agent_timeout):
                async for event in agent_engine.run(
                    messages=messages,
                    stream=True,
                    temperature=request.temperature,
                    max_tokens=request.max_tokens,
                ):
                    if event["type"] == "token":
                        yield {"event": "token", "data": json.dumps({"text": event["content"]})}

                    elif event["type"] == "tool_calls":
                        yield {"event": "tool_calls", "data": json.dumps({
                            "tool_calls": event["tool_calls"]
                        })}

                    elif event["type"] == "tool_result":
                        yield {"event": "tool_result", "data": json.dumps({
                            "tool_call_id": event["tool_call_id"],
                            "result": event["result"]
                        })}

                    elif event["type"] == "usage":
                        yield {"event": "usage", "data": json.dumps({
                            "prompt_tokens": event["prompt_tokens"],
                            "completion_tokens": event["completion_tokens"],
                            "total_tokens": event["total_tokens"],
                        })}

                    elif event["type"] == "done":
                        elapsed = int((time.time() - start) * 1000)
                        yield {"event": "done", "data": json.dumps({
                            "content": event.get("content", ""),
                            "latency_ms": elapsed,
                        })}

        except asyncio.TimeoutError:
            yield {"event": "error", "data": json.dumps({"error": "推理超时"})}
        except Exception as e:
            yield {"event": "error", "data": json.dumps({"error": str(e)})}

    return EventSourceResponse(event_generator())

    active_sessions[session_id] = time.time()

    try:
        while True:
            # 接收前端消息

            if data.get("type") == "chat":
                messages = data.get("messages", [])
                stream = data.get("stream", True)

                async for event in agent_engine.run(
                    messages=[{"role": m["role"], "content": m["content"]} for m in messages],
                    stream=stream,

                    await websocket.send_json(event)

            elif data.get("type") == "cancel":
                # 取消当前正在进行的推理
                # 实际项目中通过 Task 取消机制实现
                await websocket.send_json({"type": "cancelled"})
                break

            elif data.get("type") == "ping":
                await websocket.send_json({"type": "pong"})

    except Exception as e:
        print(f"WebSocket error ({session_id}): {e}")
    finally:
        # 清理
        if session_id in active_sessions:
            del active_sessions[session_id]
```

```python
# 方式二：代码启动（推荐开发和测试）
# run.py
import uvicorn
from app.config import config

if __name__ == "__main__":
    uvicorn.run(
        "app.main:app",
        host=config.host,
        port=config.port,
        workers=config.workers,
        loop="uvloop",
        http="httptools",
        timeout_keep_alive=config.keep_alive_timeout,
        limit_concurrency=1000,
        limit_max_requests=1000,
        log_level="info",
        access_log=True,
        proxy_headers=True,
        forwarded_allow_ips="*",
    )
```

**Uvicorn 关键参数说明**：

| 参数 | 推荐值 | 作用 |
|------|--------|------|
| `workers` | 4-8 | Worker 进程数，推荐 2 * CPU 核心数 + 1 |
| `loop` | uvloop | 使用 C 扩展事件循环（比 asyncio 默认快 2x） |
| `http` | httptools | 使用 C 扩展 HTTP 解析器（比 h11 快 3x） |
| `timeout-keep-alive` | 75 | 长连接保持时间，需略高于反向代理的 keepalive 超时 |
| `limit-concurrency` | 1000 | 最大并发连接数，防止连接过多导致 OOM |
| `proxy-headers` | true | 信任反向代理传递的客户端真实 IP（需配合 nginx） |

## 三、反向代理配置

### 3.1 Nginx 反向代理

```nginx
# nginx.conf
upstream agent_backend {
    least_conn;  # 最少连接数负载均衡
    server 127.0.0.1:8000;
    server 127.0.0.1:8001;
    server 127.0.0.1:8002;
    server 127.0.0.1:8003;
}

server {
    listen 80;
    server_name api.example.com;

    client_max_body_size 10m;
    proxy_read_timeout 120s;  # Agent 推理可能很长
    proxy_send_timeout 120s;

    location / {
        proxy_pass http://agent_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 缓冲必须关闭
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding on;
    }

    # WebSocket 专用配置
    location /api/v1/ws/ {
        proxy_pass http://agent_backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;  # WebSocket 长连接超时
        proxy_send_timeout 3600s;
    }
}
```

### 3.2 关键配置说明

**必须关闭的 Nginx 特性**：
- `proxy_buffering off` — 关闭缓冲，否则 SSE 流式输出会被缓冲到 buffer 满才发送，导致前端感知到延迟
- `proxy_cache off` — 关闭缓存，Agent 的每次请求都是唯一的
- `chunked_transfer_encoding on` — 启用分块传输编码，配合流式输出

**WebSocket 特殊配置**：
- `proxy_read_timeout 3600s` — WebSocket 连接可以持续数小时，超时设置为 1 小时以上
- `proxy_set_header Upgrade $http_upgrade` — 传递 WebSocket 升级请求

## 四、部署模式对比

### 4.1 单进程单 Worker（开发环境）

```bash
uvicorn app.main:app --reload --port 8000
```

- 适用：开发调试
- 特点：热重载，但单进程性能有限
- Agent 场景问题：一个长时间推理会阻塞所有其他请求

### 4.2 多 Worker 多进程（生产环境）

```bash
uvicorn app.main:app --workers 4 --port 8000
```

- 适用：无状态 Agent 服务
- 特点：每个 Worker 独立进程，利用多核 CPU
- Agent 场景注意：Worker 之间不共享状态（会话存储需依赖 Redis，详见 Ch23.4）

### 4.3 Gunicorn + Uvicorn Worker（高并发生产环境）

```bash
gunicorn app.main:app \
    --worker-class uvicorn.workers.UvicornWorker \
    --workers 8 \
    --bind 0.0.0.0:8000 \
    --max-requests 1000 \
    --max-requests-jitter 50 \
    --timeout 120 \
    --graceful-timeout 30
```

- 适用：需要进程管理（自动重启、预加载、平滑升级）的场景
- 特点：Gunicorn 负责进程管理，Uvicorn 负责 ASGI 协议
- Agent 场景注意：`--timeout 120` 需大于 Agent 最大推理时间

### 4.4 扩展阅读：多 Worker 下的会话亲和性

对于需要保持状态在本地内存的场景（不推荐生产用），可以通过 nginx `ip_hash` 实现会话亲和性（Session Affinity），确保同一用户的请求始终路由到同一 Worker：

```nginx
upstream agent_backend {
    ip_hash;
    server 127.0.0.1:8000;
    server 127.0.0.1:8001;
}
```

**生产环境建议**：不要依赖会话亲和性，而是将会话存储到 Redis（详见 Ch23.4）。这样 Worker 可以随意扩缩容，且容错性更好。

## 五、性能优化实践

### 5.1 连接池复用

Agent 服务对外部 API（LLM、检索数据库）有大量调用，连接池是第一个优化点：

```python
# app/agent/core.py
import aiohttp
from app.config import config

class AgentEngine:
    def __init__(self, config):
        self.config = config
        
        # 为工具调用创建共享连接池
        self.http_session = aiohttp.ClientSession(
            connector=aiohttp.TCPConnector(
                limit=100,        # 最大并发连接数
                limit_per_host=30, # 每台主机的最大并发
                ttl_dns_cache=300, # DNS 缓存时间
                force_close=False, # 使用连接复用
            ),
            timeout=aiohttp.ClientTimeout(total=30),
        )
```

### 5.2 请求体流式处理

对于大型请求（如上传文档进行 Agent 分析），使用流式请求体避免内存溢出：

```python
@app.post(f"{config.api_prefix}/analyze")
async def analyze_document(request: Request):
    """流式接收大型文档"""
    # 使用 request.stream() 逐块读取
    chunks = []
    async for chunk in request.stream():
        chunks.append(chunk)
    
    content = b"".join(chunks).decode("utf-8")
    # 处理文档...
```

### 5.3 后台任务与 TaskGroup

多工具并行执行时使用 Python 3.11+ 的 TaskGroup 管理并发：

```python
async def execute_tools_parallel(tool_calls: list) -> list:
    """并行执行多个独立工具调用"""
    async with asyncio.TaskGroup() as tg:
        tasks = [
            tg.create_task(agent_engine.execute_tool(tc["name"], tc["arguments"]))
            for tc in tool_calls
        ]
    
    return [task.result() for task in tasks]
```

## 六、常见问题与排查

### 6.1 连接重置（Connection Reset）

**症状**：长推理过程中 Nginx 返回 502，客户端收到 Connection Reset。

**原因**：反向代理的 `proxy_read_timeout` 小于 Agent 最大推理时间。Agent 在长达几十秒内没有产生任何输出（如在收集多个工具调用的结果），代理误判为连接闲置而关闭。

**解决**：
```
# 方案 A：增加 Nginx 超时
proxy_read_timeout 180s;

# 方案 B：在 Agent 推理过程中发送 keepalive 心跳
# （每 10s 发送一个空行保持连接）
```

### 6.2 Worker 内存泄漏

**症状**：Worker 进程 RSS 持续增长，最终被 OOM Killer 杀死。

**原因**：Agent 推理历史存储在内存中，会话过多且未清理。

**解决**：
- 设置 `--limit-max-requests 1000` 让 Worker 每处理 1000 个请求后自动重启
- 使用外部存储（Redis/PostgreSQL）保存会话历史（详见 Ch23.3 / Ch23.4）
- 实现 `max_session_history` 截断策略（保留最近 N 轮对话）

### 6.3 流式输出延迟

**症状**：Agent 已经开始生成 Token，但前端要等很久才收到第一个 Token。

**原因**：未关闭 Nginx 缓冲，或 SSE 数据未及时 flush。

**解决**：
```python
# 在 FastAPI 端显式 flush
async for event in agent_engine.run(...):
    yield event
    await asyncio.sleep(0)  # 让出事件循环，触发 flush
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| ASGI | 异步服务器网关接口，WSGI 的异步继任者，原生支持 WebSocket 和 SSE |
| Uvicorn | 基于 uvloop 和 httptools 的 ASGI 服务器，FastAPI 的推荐运行环境 |
| UVLoop | libuv 的 Python 封装，比 asyncio 默认事件循环快 2-4 倍 |
| Server-Sent Events | 基于 HTTP 的单向流式推送协议，适合 Agent Token 流式输出 |
| Lifespan | ASGI 定义的应用启动/关闭事件机制，替代 FastAPI 旧版 startup/shutdown |
| 会话亲和性 | 负载均衡中将同一用户的请求路由到同一后端的策略 |
| proxy_buffering off | 关闭反向代理缓冲，对 SSE 和 WebSocket 至关重要 |
