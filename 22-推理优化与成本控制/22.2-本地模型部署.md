# 22.2 本地模型部署

> 本地模型部署（Local Model Deployment）是指将大语言模型运行在自有基础设施（个人工作站、企业服务器、边缘设备）上，而非依赖第三方 API 服务。对于 Agent 系统，本地部署意味着低延迟、数据隐私、无 API 调用成本和可定制性，但也带来了硬件管理和运维的挑战。

---

## 一、为什么选择本地部署？

### 1.1 本地部署 vs API 调用的权衡

| 维度 | 本地部署 | API 调用（如 OpenAI） |
|------|---------|---------------------|
| **延迟** | 10-100ms（同机） | 200-2000ms（含网络） |
| **数据隐私** | 数据不出域 | 数据发送至第三方 |
| **成本** | 前期硬件投资，边际成本低 | 按 token 付费，量大成本高 |
| **模型选择** | 完全自由（开源模型） | 仅限提供商支持的模型 |
| **可靠性** | 取决于自有机房 | 依赖提供商 SLA |
| **运维复杂度** | 高（硬件、框架、监控） | 无 |
| **弹性扩缩** | 需提前规划容量 | 自动弹性 |

**Agent 场景的特殊考量**：Agent 通常需要大量多轮交互和工具调用，这意味着每完成一个任务可能需要数千甚至数万 tokens。对于日均百万 tokens 的生产系统，API 调用成本可能每月高达数千美元，此时本地部署的边际成本优势开始显现。

### 1.2 适用场景决策树

```
你的 Agent 系统需要推理吗？
    │
    ├── 日均 tokens < 10 万 → API 调用更经济
    │
    ├── 日均 tokens 10 万 - 100 万
    │   ├── 对延迟敏感 → 本地部署
    │   └── 对延迟不敏感 → API 调用
    │
    ├── 日均 tokens > 100 万
    │   ├── 有 GPU 资源 → 本地部署
    │   └── 无 GPU 资源 → API 调用 + 缓存优化
    │
    └── 数据隐私要求
        ├── 数据不能出域 → 本地部署（强制）
        └── 数据可出域 → 按成本权衡
```

## 二、主流部署框架对比

### 2.1 框架概览

| 特性 | vLLM | Ollama | llama.cpp | SGLang |
|------|------|--------|-----------|--------|
| **后端** | CUDA/Triton | llama.cpp | 自研 C++ | CUDA/Triton |
| **量化支持** | GPTQ/AWQ/FP8 | GGUF | GGUF | INT8/FP8 |
| **Continuous Batching** | 原生支持 | 有限 | 有限 | 原生支持 |
| **多 GPU 支持** | 原生（Tensor Parallel） | 有限 | 部分 | 原生 |
| **API 兼容** | OpenAI 兼容 | OpenAI 兼容 | 自建 Server | OpenAI 兼容 |
| **硬件** | NVIDIA GPU | CPU + GPU | CPU 优先 | NVIDIA GPU |
| **安装难度** | 中（需 CUDA） | 极低（一键） | 低（C++编译） | 中（需 CUDA） |
| **最佳场景** | 高吞吐生产服务 | 个人试用/开发 | CPU 部署/嵌入式 | 复杂推理/结构化输出 |

### 2.2 性能基准测试

以下为 LLaMA-3-8B 在不同框架和硬件配置下的性能（使用 ShareGPT 数据集测试）：

| 框架 | 硬件 | 精度 | 吞吐量（tokens/s） | 显存占用 | TTFT（首 Token 延迟） |
|------|------|------|------------------|---------|---------------------|
| vLLM | A100-80GB | FP16 | 2,450 | 16GB | 45ms |
| vLLM | A100-80GB | FP8 | 3,820 | 8GB | 38ms |
| vLLM | RTX 4090 | AWQ | 1,860 | 6GB | 52ms |
| Ollama | RTX 4090 | Q4_K_M | 1,520 | 5.5GB | 68ms |
| Ollama | M2 Ultra | Q4_K_M | 890 | 8GB | 95ms |
| llama.cpp | RTX 4090 | Q4_K_M | 1,680 | 5.5GB | 58ms |
| llama.cpp | MacBook M2 | Q4_K_M | 420 | 6GB | 180ms |
| llama.cpp | CPU (AMD 7950X) | Q4_K_M | 85 | 32GB | 1,200ms |
| SGLang | A100-80GB | FP16 | 2,680 | 16GB | 40ms |
| SGLang | A100-80GB | FP8 | 3,950 | 8GB | 35ms |

**关键观察**：
- vLLM 和 SGLang 在高吞吐生产场景下大幅领先，得益于成熟的 Continuous Batching
- Ollama 的优势在于易用性和多平台支持，性能虽略低但对开发测试已经足够
- llama.cpp 在 CPU 推理上独一无二（框架中唯一能高效利用纯 CPU 的）
- SGLang 在结构化输出场景（如 JSON Mode、约束解码）有独特优势

## 三、vLLM 部署配置

### 3.1 基本安装与启动

```bash
# 安装 vLLM（推荐使用 CUDA 12.1+）
pip install vllm

# 启动 OpenAI 兼容的 API 服务
python -m vllm.entrypoints.openai.api_server \
    --model meta-llama/Meta-Llama-3-8B-Instruct \
    --tensor-parallel-size 2 \           # 使用 2 张 GPU 的张量并行
    --gpu-memory-utilization 0.90 \      # GPU 显存利用率
    --max-model-len 8192 \               # 最大上下文长度
    --dtype auto \                       # 自动选择数据类型
    --api-key "your-api-key" \
    --port 8000
```

### 3.2 生产环境的精细配置

```python
# 生产级 vLLM 配置示例
from vllm import LLM, SamplingParams

# 初始化
llm = LLM(
    model="mistralai/Mixtral-8x7B-Instruct-v0.1",
    tensor_parallel_size=4,          # 4 卡张量并行
    dtype="bfloat16",                # BF16 精度
    max_model_len=16384,             # 16K 上下文
    gpu_memory_utilization=0.88,     # 保留部分显存给 KV Cache
    enforce_eager=False,             # 使用 CUDA Graph 优化
    max_num_seqs=256,                # 最大并发序列数
    trust_remote_code=True,          # 信任远程代码
)

# 采样参数配置
sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.9,
    max_tokens=2048,
    stop=["</s>", "\n\n"],           # 自定义停止词
    use_beam_search=False,           # 不使用 beam search（太慢）
    best_of=1,                       # 只生成 1 个候选
)

# 批量推理
def batch_inference(prompts: list[str]) -> list[str]:
    # 格式化输入（按 Instruct 模板）
    formatted = [
        f"<s>[INST] {p} [/INST]" for p in prompts
    ]
    
    outputs = llm.generate(formatted, sampling_params)
    return [o.outputs[0].text for o in outputs]
```

## 四、Ollama 部署配置

### 4.1 安装与基础使用

```bash
# macOS / Linux 一键安装
curl -fsSL https://ollama.com/install.sh | sh

# 或 Windows 下载安装包后启动
# 下载模型
ollama pull llama3:8b          # LLaMA-3 8B 指令版
ollama pull qwen2.5:7b         # Qwen 2.5 7B
ollama pull mistral:7b         # Mistral 7B
ollama pull llama3.1:70b       # LLaMA-3.1 70B（需要足够内存/显存）

# 查看已下载的模型
ollama list

# 删除模型
ollama rm llama3:8b
```

### 4.2 自定义 Modelfile

Ollama 的 Modelfile 类似于 Dockerfile，允许自定义模型的系统提示词、参数模板等：

```dockerfile
# Modelfile
FROM llama3:8b

# 设置系统提示词（Agent 角色）
SYSTEM """你是一个专业的 RAG（检索增强生成）Agent。你的职责包括：
1. 根据用户问题检索相关知识库
2. 用检索结果回答用户问题
3. 如果检索结果不足以回答问题，明确说明"没有足够的信息"
4. 不确定时标注置信度
请按照上述规则执行。"""

# 设置参数
PARAMETER temperature 0.7
PARAMETER top_p 0.9
PARAMETER num_ctx 8192          # 上下文窗口大小
PARAMETER stop "</s>"
PARAMETER seed 42

# 设置模板
TEMPLATE """{{ .System }}

用户: {{ .Prompt }}

助手: """
```

构建和运行自定义模型：

```bash
ollama create my-rag-agent -f ./Modelfile
ollama run my-rag-agent
```

### 4.4 Ollama 的 Python 集成

```python
import requests
import json

class OllamaAgent:
    def __init__(self, model: str = "llama3:8b", base_url: str = "http://localhost:11434"):
        self.model = model
        self.base_url = base_url
    
    def generate(self, prompt: str, system: str = "", stream: bool = False) -> str:
        payload = {
            "model": self.model,
            "prompt": prompt,
            "system": system,
            "stream": stream,
            "options": {
                "temperature": 0.7,
                "num_ctx": 8192,
                "num_predict": 2048,
            }
        }
        
        response = requests.post(
            f"{self.base_url}/api/generate",
            json=payload,
            stream=stream,
        )
        
        if stream:
            # 流式响应
            full_response = ""
            for line in response.iter_lines():
                if line:
                    chunk = json.loads(line)
                    if chunk.get("response"):
                        full_response += chunk["response"]
                    if chunk.get("done"):
                        break
            return full_response
        else:
            return response.json()["response"]
    
    def chat(self, messages: list[dict]) -> str:
        """聊天接口"""
        payload = {
            "model": self.model,
            "messages": messages,
            "stream": False,
        }
        response = requests.post(
            f"{self.base_url}/api/chat",
            json=payload,
        )
        return response.json()["message"]["content"]


# 使用示例
agent = OllamaAgent("llama3:8b")
response = agent.chat([
    {"role": "system", "content": "你是一个代码助手。"},
    {"role": "user", "content": "用 Python 写一个快速排序。"},
])
print(response)
```

## 五、llama.cpp 部署

### 5.1 特点和优势

llama.cpp 是一个纯 C/C++ 实现的 LLM 推理框架，其核心理念是：
- **CPU 优先**：即使没有 GPU 也能高效推理
- **极致优化**：对 ARM（Apple Silicon）和 x86 都有深度优化
- **GGUF 格式**：统一量化格式，模型跨平台兼容
- **极低内存占用**：Q4 量化下 7B 模型仅需约 4GB 内存

### 5.2 安装和启动

```bash
# 克隆仓库
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp

# 编译（macOS/Linux）
make -j

# 或使用 CMake（支持 GPU 加速）
cmake -B build -DLLAMA_CUBLAS=ON  # NVIDIA GPU
cmake --build build --config Release

# 下载 GGUF 格式模型
# 可以从 HuggingFace 下载预量化模型
# 或将 PyTorch 模型转换为 GGUF

# 启动 HTTP 服务器
./build/bin/llama-server \
    -m models/llama-3-8b-instruct.Q4_K_M.gguf \
    --host 0.0.0.0 \
    --port 8080 \
    --n-gpu-layers 32 \      # GPU 卸载层数（0 = 全部 CPU）
    --ctx-size 8192 \
    --batch-size 512 \
    --threads 8
```

### 5.3 在 Agent 系统中使用 llama.cpp

```python
# 使用 llama-cpp-python 作为 Agent 的后端
from llama_cpp import Llama

# 加载 GGUF 模型
llm = Llama(
    model_path="models/llama-3-8b-instruct.Q4_K_M.gguf",
    n_ctx=8192,              # 上下文窗口
    n_threads=8,             # CPU 线程数
    n_gpu_layers=32,         # GPU 加速层数
    verbose=False,
)

def agent_generate(system_prompt: str, user_input: str) -> str:
    """Agent 生成函数"""
    prompt = f"<|system|>{system_prompt}</s><|user|>{user_input}</s><|assistant|>"
    
    output = llm(
        prompt,
        max_tokens=2048,
        temperature=0.7,
        top_p=0.9,
        stop=["</s>", "<|user|>"],
        echo=False,
    )
    return output["choices"][0]["text"]
```

## 六、SGLang 部署

### 6.1 核心优势

SGLang 由斯坦福大学开发，专门针对**复杂推理和结构化输出**场景优化：

- **RadixAttention**：自动 KV Cache 复用，特别是针对共享前缀的场景
- **结构化生成**：支持 JSON Schema 约束、正则约束
- **约束解码**：保证输出格式，减少下游解析错误
- **多模态支持**：支持图片、视频等输入

### 6.2 安装与配置

```bash
# 安装 SGLang
pip install sglang[all]

# 启动服务
python -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3-8B-Instruct \
    --port 30000 \
    --tp-size 1 \
    --host 0.0.0.0

# 使用结构化输出
python -m sglang.launch_server \
    --model-path meta-llama/Meta-Llama-3-8B-Instruct \
    --constrained-json-mode \     # 启用 JSON 约束
    --port 30000
```

### 6.3 SGLang 结构化生成示例

```python
# SGLang 的结构化生成——Agent 工具调用的理想选择
import sglang as sgl
from pydantic import BaseModel

# 定义输出结构
class ToolCall(BaseModel):
    tool_name: str
    arguments: dict
    confidence: float

class Thought(BaseModel):
    reasoning: str
    next_action: str

@sgl.function
def agent_pipeline(system, user_input):
    # 定义输出模板
    thought = sgl.gen(
        "thought",
        max_tokens=256,
        temperature=0.1,
    )
    
    tool_call = sgl.gen(
        "tool_call",
        max_tokens=128,
        temperature=0.1,
        # 约束为有效的 JSON 格式
        regex='{"tool_name": "\\w+", "arguments": \\{.*\\}, "confidence": 0\\.[0-9]+}',
    )
    
    return thought, tool_call

# 调用
state = agent_pipeline.run(
    system="你是一个工具调用 Agent。",
    user_input="查询北京的天气",
)
print(state["thought"])
print(state["tool_call"])
```

## 七、框架选型决策树

```
选择部署框架
    │
    ├── 是否需要 Continuous Batching？
    │   ├── 是 → 需要 GPU？
    │   │   ├── 是 → vLLM（通用）或 SGLang（结构化输出）
    │   │   └── 否 → Ollama（有限支持）
    │   └── 否 → 需要 GPU？
    │       ├── 是 → vLLM / Ollama
    │       └── 否 → llama.cpp（CPU）
    │
    ├── 是否需要结构化输出？
    │   └── 是 → SGLang（最佳选择）
    │
    ├── 硬件条件
    │   ├── 多 GPU → vLLM（Tensor Parallel 最成熟）
    │   ├── 单 GPU → vLLM / Ollama
    │   ├── Apple Silicon → Ollama / llama.cpp
    │   └── 纯 CPU → llama.cpp（唯一选择）
    │
    └── 团队能力
        ├── 有 DevOps → vLLM（彻底掌控）
        ├── 快速原型 → Ollama（5 分钟上线）
        └── 边缘部署 → llama.cpp（最小依赖）
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| vLLM | 高性能推理框架，原生支持 Continuous Batching、PagedAttention 和 Tensor Parallel |
| Ollama | 极简的本地模型管理工具，一键安装和运行开源模型 |
| llama.cpp | 纯 C/C++ LLM 推理框架，支持 CPU 推理和 GGUF 量化格式 |
| SGLang | 结构化生成框架，支持 JSON Schema 约束和高效的 RadixAttention |
| GGUF | llama.cpp 使用的模型量化格式，统一了量化模型的存储和加载 |
| Tensor Parallel | 张量并行，将模型层切分到多张 GPU 上并行计算 |
| PagedAttention | vLLM 提出的类虚拟内存的 KV Cache 管理技术，减少显存碎片 |
| RadixAttention | SGLang 的前缀树 KV Cache 复用技术，自动检测和复用共享前缀 |
| CUDA Graph | 将 GPU 内核调用图固化，减少内核启动开销的优化技术 |
| OpenAI 兼容 API | 以 OpenAI API 格式为标准，本地服务实现相同接口实现无缝替换 |
