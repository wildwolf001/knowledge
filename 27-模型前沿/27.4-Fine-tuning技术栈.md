# 27.4 Fine-tuning 技术栈 —— LoRA / QLoRA / DPO / RLHF / GRPO，各自的适用场景和资源需求

> Fine-tuning（微调）是在预训练模型基础上，通过额外训练使模型适应特定任务或行为偏好的过程。随着模型规模从 7B 增长到 671B，微调技术栈已经从"全参数微调"发展为包含 LoRA、QLoRA、DPO、RLHF、GRPO 等多种方法的工具箱。选择合适的微调方法取决于任务目标、可用资源和数据规模。

---

## 一、微调方法全景图

```
微调方法分类
│
├── 参数效率微调 (PEFT)
│   ├── LoRA (Low-Rank Adaptation) —— 低秩适配
│   ├── QLoRA —— 量化版 LoRA
│   ├── Adapter —— 插入式适配层
│   └── Prefix Tuning —— 前缀调优
│
├── 偏好对齐 (Alignment)
│   ├── RLHF (Reinforcement Learning from Human Feedback)
│   │   ├── PPO —— 近端策略优化
│   │   └── Reward Model —— 奖励模型训练
│   └── DPO (Direct Preference Optimization) —— 直接偏好优化
│       └── GRPO (Group Relative Policy Optimization) —— 组相对策略优化
│
└── 全参数微调 (Full Fine-tuning)
    └── 更新所有模型参数（昂贵但效果最强）
```

## 二、核心方法详解

### 2.1 LoRA（Low-Rank Adaptation）

**原理**：LoRA 基于一个关键观察——预训练模型的权重矩阵在微调过程中，权重的变化量 ΔW 是**低秩（Low-rank）**的。因此，ΔW 可以被分解为两个小矩阵的乘积：

```
原始前向传播：h = W₀ · x
LoRA 前向传播：h = (W₀ + ΔW) · x = (W₀ + B·A) · x

其中：
- W₀ ∈ ℝ^{d×k}：原始权重矩阵（冻结，不更新）
- B ∈ ℝ^{d×r}：低秩矩阵（可训练）
- A ∈ ℝ^{r×k}：低秩矩阵（可训练）
- r << min(d, k)：秩（rank），通常取 4、8、16、32
```

LoRA 只训练 B·A 两个小矩阵，参数量减少至原来的 r / d（例如 d=4096, r=8 时仅为 0.2%）。

**资源需求**：
- 7B 模型：峰值显存 ~16GB（单卡 RTX 3090 可运行）
- 70B 模型：峰值显存 ~80GB（需 A100/H100）

### 2.2 QLoRA（Quantized LoRA）

**原理**：在 LoRA 的基础上，将原始模型权重进行 **4-bit NormalFloat (NF4) 量化**，进一步降低显存占用。仅 LoRA 适配器权重保持 BF16/FP16 精度。

```
QLoRA 的显存构成：
- 原始权重（4-bit 量化）：模型总参数量 × 0.5 bytes
- LoRA 适配器（BF16）：训练参数量 × 2 bytes
- 优化器状态（Adam）：训练参数量 × 8 bytes
- 激活值缓存：取决于 batch size 和序列长度
```

**资源需求**：
- 7B 模型：峰值显存 ~6GB（单卡 RTX 3060 可运行）
- 70B 模型：峰值显存 ~48GB（单卡 A100 可运行）

### 2.3 RLHF（Reinforcement Learning from Human Feedback）

**原理**：RLHF 是一个三阶段流程，将人类偏好注入模型：

```
阶段 1: SFT（监督微调）
  输入：高质量指令-回答对
  输出：可以回答问题的基础模型

阶段 2: 训练奖励模型（Reward Model, RM）
  输入：同一个问题对应的多个回答，人工标注偏好排序
  训练：学习一个打分函数 R(x, y)，对人类偏好进行建模
  输出：可以评估回答质量的奖励模型

阶段 3: PPO 强化学习
  使用奖励模型提供的分数作为奖励信号，通过 PPO 算法优化 SFT 模型
  目标：max E[R(x, y_θ)] - β·KL(π_θ || π_sft)
  其中 KL 项防止模型偏离 SFT 模型太远（防止"奖励黑客"现象）
```

**资源需求**：
- 阶段 1（SFT）：与全参数微调相当
- 阶段 2（RM）：需要训练一个与基础模型规模相近的奖励模型
- 阶段 3（PPO）：需要同时加载 SFT 模型、Reward Model、参考模型 ← **总计 3 个模型**
- 7B 模型 RLHF：至少需要 4 × A100 80GB

### 2.4 DPO（Direct Preference Optimization）

**原理**：DPO 绕过了 RLHF 的奖励模型训练和 PPO 阶段，直接在偏好数据上优化模型：

```
DPO 损失函数：
L(π_θ) = -E[log σ(β · (log(π_θ(y_w | x) / π_ref(y_w | x))
                     - log(π_θ(y_l | x) / π_ref(y_l | x))))]

其中：
- y_w：人类偏好的回答（win）
- y_l：人类不偏好的回答（lose）
- π_ref：参考模型（SFT 后的模型，冻结）
- β：控制模型偏离参考模型的程度
```

**优势**：比 RLHF 简单得多——不需要训练奖励模型，不需要 PPO 的 4 模型加载。
**局限**：在复杂对齐任务上效果可能不如 RLHF。

### 2.5 GRPO（Group Relative Policy Optimization）

**原理**：GRPO 是 DeepSeek-R1 引入的一种强化学习对齐方法，对 DPO 的改进方案。它与 DPO 的核心区别在于：

```
DPO: 偏好来自人类标注的固定数据对 (y_w, y_l)
GRPO: 偏好来自模型自身采样的多个回答的组内比较

GRPO 的流程：
1. 对每个 prompt，模型采样生成一组回答 {y₁, y₂, ..., y_G}
2. 使用规则/奖励函数对这组回答自动评分
3. 组内归一化：将每个回答的分数基于组均值进行归一化
4. 优化策略：让模型更倾向于生成组内分数高于均值的回答
```

GRPO 的优势在于：
- **完全去除了奖励模型**：RLHF 需要训练一个独立的奖励模型
- **组内归一化消除评分偏差**：不同 prompt 的分数尺度不一致问题被解决
- **数据效率更高**：每次采样生成 G 个回答一次使用

## 三、技术选型决策矩阵

选择合适的微调方法需要综合考虑六个维度的约束。以下矩阵列出了各方法在关键维度上的表现：

| 维度 | Full Fine-tune | LoRA | QLoRA | RLHF | DPO | GRPO |
|------|---------------|------|-------|------|-----|------|
| **适用场景** | 最大效果（领域适应） | 适配特定任务 | 资源严重受限时 | 细粒度的行为对齐 | 简单偏好对齐 | 自动偏好对齐 |
| **训练参数量** | 全部（100%） | ~0.1%-1% | ~0.1%-1% | SFT+RM+PPO | 全部但训练稳定 | 全部但训练稳定 |
| **显存需求（7B）** | ~60GB | ~16GB | ~6GB | ~160GB（4卡） | ~60GB | ~60GB |
| **显存需求（70B）** | ~480GB | ~80GB | ~48GB | ~1280GB | ~480GB | ~480GB |
| **训练速度** | 最慢 | 快 | 最快 | 最慢 | 较慢 | 较慢 |
| **数据需求** | 1000-10000条 | 100-1000条 | 100-1000条 | 10000+偏好对 | 1000+偏好对 | 500+ prompt |
| **实现复杂度** | 低 | 低 | 低 | 高（4个组件） | 中 | 中 |
| **效果上限** | 最高 | 接近全参数 | 接近全参数 | 最高（行为层面） | 较高 | 接近 RLHF |
| **覆盖类型** | 知识注入 | 任务适应 | 任务适应 | 价值观对齐 | 价值观对齐 | 推理偏好 |

### 场景化推荐

```
场景 1: 我有 1 张 RTX 3090，想让模型学会回答公司内部知识
→ 推荐：QLoRA (r=8, target_modules=q_proj,v_proj)
  理由：显存最低，适配私有知识足够

场景 2: 我要让模型在数学推理上达到 o1 水平
→ 推荐：SFT (高质量 CoT 数据) + GRPO (组内推理路径优化)
  理由：DeepSeek-R1 的验证路径

场景 3: 我需要模型安全性极高，拒绝有害提问
→ 推荐：RLHF (全流程) 或 DPO (资源受限时)
  理由：行为对齐RLHF效果最佳

场景 4: 我正在做 671B MoE 模型的部署（如 DeepSeek-V3）
→ 推荐：LoRA (仅微调部分 Expert 或注意力层)
  理由：全参数微调成本过高，LoRA 冻结 Router 微调 Expert

场景 5: 我只有 100 条样本，想要提升特定格式输出的能力
→ 推荐：LoRA (r=4)
  理由：小秩+小数据，防止过拟合
```

## 四、微调实践示例

### LoRA 微调完整流程（使用 HuggingFace PEFT）

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model
from datasets import load_dataset
from trl import SFTTrainer

# 1. 加载基础模型（4-bit 量化）
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-7B",
    load_in_4bit=True,  # 使用 QLoRA 量化
    device_map="auto",
)

# 2. 配置 LoRA
lora_config = LoraConfig(
    r=8,                    # 低秩矩阵的秩
    lora_alpha=16,          # 缩放系数
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

model = get_peft_model(model, lora_config)

# 3. 配置训练器
trainer = SFTTrainer(
    model=model,
    train_dataset=load_dataset("json", data_files="train.jsonl")["train"],
    max_seq_length=2048,
    args=TrainingArguments(
        output_dir="./lora_output",
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,
        learning_rate=2e-4,
        num_train_epochs=3,
        fp16=True,
    ),
)

# 4. 训练
trainer.train()

# 5. 保存适配器
model.save_pretrained("./lora_adapter")
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| LoRA (Low-Rank Adaptation) | 低秩适配，将权重更新量分解为两个小矩阵，大幅降低训练参数量 |
| QLoRA | 量化版 LoRA，将基础模型量化为 4-bit 以进一步降低显存 |
| RLHF (Reinforcement Learning from Human Feedback) | 基于人类反馈的强化学习，三阶段流程（SFT + RM + PPO） |
| DPO (Direct Preference Optimization) | 直接偏好优化，无需训练奖励模型的轻量级对齐方法 |
| GRPO (Group Relative Policy Optimization) | 组相对策略优化，DeepSeek-R1 使用的组内比较对齐方法 |
| Reward Model (RM) | 奖励模型，对模型输出进行打分以反映人类偏好 |
| PPO (Proximal Policy Optimization) | 近端策略优化，RLHF 中使用的强化学习算法 |
| SFT (Supervised Fine-tuning) | 监督微调，使用标注数据微调模型的第一步 |
| 低秩 (Low-rank) | 矩阵的秩远小于其维度，表示信息可以用更少的参数表示 |
| 偏好对齐 (Alignment) | 使模型行为符合人类价值观和偏好的过程 |
