# 27.3 多模态 Agent —— 视觉 + 代码 + 文档 + 语音的统一理解与行动

> 多模态 Agent（Multimodal Agent）是指能够同时理解并操作文本、图像、代码、文档、语音等多种信息形式的 AI Agent。它不再是"读文字的模型"，而是"能看、能听、能读、能写的行动者"。这是从 LLM（大语言模型）向 LMM（大多模态模型）演进的必然方向。

---

## 一、为什么需要多模态 Agent？

传统 LLM 的能力边界在文本领域，但现实世界的问题天然是多模态的：

- 用户可能拍一张截图问"这行代码有 bug 吗？"
- 用户可能上传 PDF 文档说"提取其中所有表格数据并做分析"
- Agent 需要"看懂"UI 界面才能操作 Web 应用（如 Playwright 自动化）
- Agent 需要"听懂"语音指令才能融入移动端和 IoT 场景

多模态 Agent 的核心挑战是 **跨模态对齐（Cross-modal Alignment）**——让模型在不同模态之间建立语义关联，使得"看到一只猫"和"读到'一只猫'"在模型的表征空间中是相近的。

## 二、多模态 Agent 的架构

### 2.1 典型架构示意

```
                    ┌──────────────────────────────────────┐
                    │          多模态编码器                  │
                    │  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐    │
视觉输入 ──────────►│  │ViT  │ │CLIP │ │SigLIP│ │ ... │    │
                    │  └─────┘ └─────┘ └─────┘ └─────┘    │
                    └────────────────┬─────────────────────┘
                                     │ 视觉特征向量
                                     ▼
                    ┌──────────────────────────────────────┐
                    │       模态投影层 (Projection Layer)   │
                    │   把视觉特征对齐到 LLM 的嵌入空间     │
                    └────────────────┬─────────────────────┘
                                     │ 对齐后的特征
                                     ▼
                    ┌──────────────────────────────────────┐
                    │           LLM Backbone                │
                    │   (处理文本 + 视觉 token 的联合序列)  │
                    └────────────────┬─────────────────────┘
                                     │
                    ┌────────────────┼────────────────────┐
                    ▼                ▼                    ▼
              ┌──────────┐    ┌──────────┐        ┌──────────┐
              │文本输出   │    │工具调用   │        │视觉输出   │
              │(回答/解释)│    │(API/代码) │        │(图像生成) │
              └──────────┘    └──────────┘        └──────────┘
```

### 2.2 主要组件详解

**① 视觉编码器（Vision Encoder）**
- **ViT（Vision Transformer）**：将图像切分为 patches，每个 patch 通过 Transformer 编码为特征向量
- **CLIP / SigLIP**：对比学习训练的视觉-语言联合编码器，输出与文本语义对齐的视觉表示
- **Resolution 挑战**：高分辨率图像产生大量 patches（如 1024×1024 图像约产生 4096 个 patch），对 Transformer 的序列长度构成巨大压力（参见 27.6 节 Attention 精度衰减）

**② 模态投影层（Projection Layer）**
将视觉编码器的输出映射到 LLM 的嵌入空间。常见设计：
- **Q-Former（BLIP-2）**：使用一个轻量级 Transformer 查询视觉特征，压缩为少量"查询 token"
- **MLP Projector**：简单高效的线性/多层投射，如 LLaVA 系列
- **Resampler**：对可变数量视觉特征进行重采样为固定长度，如 Flamingo

**③ LLM Backbone**
接收文本 token 和视觉 token 的混合序列，自回归生成文本/工具调用。视觉 token 通常位于文本 token 之前（如 LLaVA 的格式）：

```
[IMG] [IMG] ... [IMG] [TEXT] User: 这张图里有什么？ [TEXT] Assistant: ...
  ↑ 视觉 token           ↑ 文本 token
```

### 2.3 主流多模态模型架构对比

| 模型 | 视觉编码器 | 连接方式 | LLM Backbone | 特点 |
|------|-----------|---------|-------------|------|
| GPT-4V / GPT-4o | - | - | GPT-4 | 闭源，多模态能力最强 |
| LLaVA | CLIP ViT-L | MLP Projector | Llama/Vicuna | 开源主流方案，训练简单 |
| Qwen-VL | ViT + 位置编码 | Q-Former | Qwen-7B/14B | 中文优化，文档理解强 |
| CogVLM | ViT + Deep Fusion | 深度交叉注意力 | Llama | 视觉理解精度高，推理稍慢 |
| Gemini Pro Vision | - | - | Gemini | Google 出品，多模态原生 |
| Flamingo | NFNet-F6 | Perceiver Resampler | Chinchilla | DeepMind 先驱，高效跨模态 |

## 三、多模态 Agent 的感知与行动

### 3.1 感知能力分类

| 模态 | 输入类型 | 技术挑战 | 当前 SOTA |
|------|---------|---------|----------|
| 图像 | 照片、截图、图表 | 高分辨率处理、OCR | GPT-4o / Gemini 2.0 |
| 视频 | 短片、直播流 | 时序建模、关键帧提取 | Gemini 1.5 Pro |
| 音频 | 语音、音乐、环境音 | 端到端语音理解 | GPT-4o Audio |
| 文档 | PDF、表格、PPT | 复杂布局、嵌套表格 | Qwen2.5-VL / DocLLM |
| 代码 | 多文件、仓库级 | 跨文件引用、调用图 | Claude 3.5 Sonnet |
| GUI | 网页/应用界面 | 元素定位、动作规划 | CogAgent / SeeClick |

### 3.2 行动能力

多模态 Agent 不仅"理解"，还要"行动"。典型行动空间包括：

```
文本层面：
  - 撰写回复、编辑文档、重写代码
工具层面：
  - 调用 API、执行 Shell 命令、操作数据库
图形层面：
  - 绘制图表、编辑图像、操作 GUI 界面
交互层面：
  - 点击按钮、填写表单、导航页面（Web Agent）
```

### 3.3 GUI Agent 示例

GUI Agent 是多模态 Agent 最具代表性的应用之一。模型"看懂"屏幕截图后决定点击哪里：

```python
class GUIAgent:
    """基于视觉理解的 GUI 操作 Agent"""
    def __init__(self, model, ocr_engine=None):
        self.model = model  # 多模态模型
        self.ocr = ocr_engine
    
    def act(self, screenshot_path, instruction):
        """根据截图和指令决定下一步操作"""
        # 1. 加载并预处理截图
        image = load_image(screenshot_path)
        
        # 2. 用多模态模型理解屏幕
        response = self.model.generate([
            {"role": "user", "content": [
                {"type": "image", "data": image},
                {"type": "text", "text": f"当前屏幕截图如上。指令：{instruction}\n"
                 "你的任务：输出下一步操作，格式为：\n"
                 "ACTION: click(x=100, y=200)\n"
                 "或 ACTION: type('查询内容')\n"
                 "或 ACTION: scroll(direction='down')"}
            ]}
        ])
        
        # 3. 解析动作并执行
        action = parse_action(response)
        return execute_on_screen(action)
```

## 四、核心工程挑战

### 4.1 视觉 token 的效率问题

一张 1024×1024 的图像被 ViT 切分为 16×16 patches，产生 4096 个视觉 token。加上文本 token 后，序列长度可达 5000+，这带来了两个问题：
- **Attention 计算量平方级增长**：O(L²) 的复杂度意味着 4096² 次注意力计算
- **位置编码压力**：长序列需要更强的位置编码（参见 27.6 节 RoPE 的局限性）

解决方案：
- **高分辨率时使用动态分辨率**：对输入图像进行智能缩放和切分
- **视觉 token 压缩**：通过 Pooling 或 Perceiver Resampler 压缩视觉 token 数量

### 4.2 多模态对齐的失败模式

```
场景：用户上传一张股票走势图并提问"这只股票最近表现如何？"
多模态 Agent 可能：
- 成功：识别图表 → 提取趋势 → 结合日期 → 给出分析 ✅
- 失败（视觉幻觉）：把下降趋势看成上升趋势 ❌
- 失败（OCR 错误）：把"3.45"读成"3.75" ❌
- 失败（跨模态断裂）：正确读取图表但生成分析时忽略了图表数据 ❌
```

多模态幻觉（见 14.1 节）在多模态场景中更加危险——模型可能"看到"图中并不存在的元素。

### 4.3 流式多模态

实时场景（如语音对话、视频分析）要求：
- **流式（Streaming）处理**：边接收边处理，不等完整输入
- **低延迟**：语音交互要求端到端延迟 < 300ms
- **模态切换**：从语音到图像的模态跳转需要无缝衔接

GPT-4o 的可中断语音交互是流式多模态的一个里程碑——用户可以在模型说话时打断它，模型能实时理解并调整响应。

## 五、多模态 Agent 的评估

传统 NLP 评估指标（BLEU, ROUGE）不足以衡量多模态 Agent 能力。现代评估框架包括：

| 评估维度 | 典型基准 | 测试内容 |
|----------|---------|---------|
| 视觉问答 | VQA-v2, VizWiz | 对图像内容的问答准确性 |
| 文档理解 | DocVQA, InfoVQA | 文档布局、表格、图表理解 |
| GUI 操作 | ScreenSpot, Mind2Web | 屏幕元素定位与操作规划 |
| 视觉数学 | MathVista, GeometryQA | 图表/图形的数学推理 |
| 多模态幻觉 | POPE, MMHal-Bench | 模型是否描述图像中不存在的对象 |
| 实时交互 | StreamingBench | 多轮流式交互的连贯性 |

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 多模态 (Multimodal) | 同时处理文本、图像、语音等多种信息形式 |
| 跨模态对齐 (Cross-modal Alignment) | 不同模态在模型表征空间中的语义对齐 |
| ViT (Vision Transformer) | 将图像切分为 patches，用 Transformer 编码 |
| CLIP / SigLIP | 对比学习训练的视觉-语言联合编码器 |
| Q-Former | 轻量级 Transformer，将视觉特征压缩为查询 token |
| 模态投影层 (Projection Layer) | 将非文本模态特征映射到 LLM 的嵌入空间 |
| GUI Agent | 通过视觉理解屏幕内容并执行 GUI 操作的 Agent |
| 多模态幻觉 | 模型在图像中"看到"不存在的元素（见 14.1 节） |
| 视觉 token | ViT 将图像 patch 编码后形成的 token 序列 |
