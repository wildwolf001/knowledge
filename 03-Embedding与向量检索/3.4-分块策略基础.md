# 3.4 分块策略基础

## 概述

分块（Chunking）是将长文档切分成更小片段的过程。在 RAG 系统中，分块策略直接影响 Embedding 质量和最终检索效果——因为 Embedding 模型的输入长度限制（通常为 512-8192 tokens）决定了不能简单地将整篇文档编码为一个向量。

分块策略需要平衡三个核心矛盾：

```
                    ┌─── 语义完整性 ───┐
                    │                    │
                    │  每个块应有完整的    │
                    │  语义单元，不截断    │
                    │  关键信息           │
                    └───────┬────────────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
    ┌──────────┐     ┌──────────┐     ┌──────────┐
    │ Embedding │     │ 检索粒度  │     │  上下文   │
    │  质量     │     │          │     │  长度     │
    │ 块不可太短│     │ 块越细 → │     │ 块不可太短│
    │ 否则语义 │     │ 检索越准 │     │ 否则LLM   │
    │ 信息不足  │     │ 但召回难  │     │ 缺少上下文│
    └──────────┘     └──────────┘     └──────────┘
```

> **注意**：本节聚焦于分块策略如何影响 Embedding 质量这一核心命题。关于分块的实现细节、动态分块、基于 LLM 的分块等高级内容，详见 **8.2 分块策略深度**。

## 3.4.1 分块策略对 Embedding 质量的影响机制

分块策略通过以下三个维度影响 Embedding 质量：

### 1. 语义截断效应

当分块切断了文档的自然语义边界时，该块的 Embedding 会变成"噪声向量"——既不能准确代表原段落的内容，又可能与其他语义无关的块产生虚假的相似度。说白了，好的 Embedding 质量建立在一个前提上：**被编码的文本本身得是一个有意义的语义单元**。

```
                    语义截断的影响
    
        正确分块 (按段落)           错误分块 (按固定长度)
    ┌──────────────────┐      ┌──────────────────┐
    │ 注意力机制是深度  │      │ 注意力机制是深度  │ ← 语义完整
    │ 学习中的核心概念... │      │ 学习中的核心概念... │
    └──────────────────┘      ├──────────────────┤
    ┌──────────────────┐      │基于注意力机制，   │ ← 被截断的句子
    │它的计算复杂度为   │      │它的计算复杂度为   │   缺少主语
    │O(n²)......        │      └──────────────────┘
    └──────────────────┘
         Embedding ✓             Embedding ✗ (语义模糊)
    "这是一个关于注意力的片段"   "这是一个语法不完整的片段"
```

### 2. 信息稀释效应

当块过大时，块中包含多个不相关的主题，Embedding 向量会成为这些主题的"平均表示"，对任何一个具体主题的区分能力都下降。

```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-base-zh-v1.5")

# 对比不同分块大小的 Embedding 质量
topics = {
    "气候变化": "全球变暖导致北极冰盖融化...",
    "机器学习": "Transformer 架构是深度学习的重要突破...",
    "量子计算": "量子比特利用叠加态实现并行计算..."
}

# 模拟：过大的块包含多个主题 → Embedding 模糊
mixed_text = topics["气候变化"] + topics["机器学习"] + topics["量子计算"]

# 模拟：合理大小的块只包含单一主题
pure_text = topics["量子计算"]

# 对比两种 Embedding 对查询的响应能力
query = "量子比特的叠加态原理"
q_emb = model.encode(query, normalize_embeddings=True)
mixed_emb = model.encode(mixed_text, normalize_embeddings=True)
pure_emb = model.encode(pure_text, normalize_embeddings=True)

cos = lambda a, b: np.dot(a, b)

print(f"混合块的相似度: {cos(q_emb, mixed_emb):.4f}")  # 通常 0.3-0.5
print(f"纯净块的相似度: {cos(q_emb, pure_emb):.4f}")   # 通常 0.6-0.8
```

### 3. 粒度失配效应

检索系统的"块粒度"需要与查询的"信息粒度"匹配：

- **细粒度查询**（如"注意力机制的数学公式是什么"）：需要较小的块（段落级）
- **粗粒度查询**（如"总结第三章内容"）：需要较大的块（章节级）

如果粒度过粗，细粒度的查询会检索到包含大量无关信息的块，稀释了相关信号的强度，导致后生成质量下降。

## 3.4.2 常见分块方法及其 Embedding 影响

### 方法一：固定长度分块

将文本按固定 token 数切分，通常带有重叠（overlap）。

```
    ┌───── 输入文本 ────────────────────────────────┐
    │ 这是第一句。这是第二句。这是第三句。这是第... │
    └────────────────────────────────────────────────┘
                        ↓
    ┌────────────────────────┐ ┌─────────────────────┐
    │ 这是第一句。这是第二句  │ │ 第三句。这是第四句  │
    │ 句。这是第三句。      │ │ 句。这是第五句。    │
    └────────────────────────┘ └─────────────────────┘
    └── 256 tokens ──┘◄── overlap 32 tokens ──►└── 256 tokens ─┘
```

**对 Embedding 的影响**：
- **优点**：实现简单，Embedding 模型输入长度可控
- **缺点**：极易切断语义边界，产生大量"语义不完整"的 Embedding
- **适用场景**：对话日志、结构化日志等语义边界不明确的文本
- **典型 overlap**：10-20% 的块大小

### 方法二：递归字符分割

按优先级依次尝试不同的分隔符进行切分：段落("\n\n") → 行("\n") → 句号/问号 → 字符。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", "！", "？", "．", "，", " ", ""]
)

chunks = splitter.split_text("长文档内容...")
```

**对 Embedding 的影响**：
- **优点**：尽可能保持语义边界完整，Embedding 质量最高
- **缺点**：块大小不固定，极端情况下单块可能超出模型最大长度
- **适用场景**：论文、书籍、报告等格式规整的文档
- **效果**：Embedding 质量优于固定长度分块，召回率通常高 3-8%

### 方法三：语义分块

利用 Embedding 模型本身检测文本中的"语义断点"——当相邻句子之间的语义相似度低于某个阈值时，在此处分块。

```
    语义分块示意图
    
    句子序列: [s1]——[s2]——[s3]——[s4]——[s5]——[s6]
                 │      │      │      │      │
    语义相似度:  0.92   0.88   0.45   0.91   0.85
                            ║
                         阈值 0.6
                         在此处分块!
    
    分块结果:
    Chunk 1: [s1, s2, s3]  ← 语义一致
    Chunk 2: [s4, s5, s6]  ← 语义一致（新主题）
```

```python
from sentence_transformers import SentenceTransformer
import numpy as np

def semantic_chunking(text, threshold=0.6):
    """
    基于语义相似度的分块
    """
    model = SentenceTransformer("BAAI/bge-base-zh-v1.5")
    
    # 按句子分割
    sentences = text.replace("。", "。\n").replace("！", "！\n").split("\n")
    sentences = [s.strip() for s in sentences if s.strip()]
    
    # 编码所有句子
    embeddings = model.encode(sentences, normalize_embeddings=True)
    
    # 计算相邻句子的相似度
    chunks = []
    current_chunk = [sentences[0]]
    
    for i in range(1, len(sentences)):
        sim = np.dot(embeddings[i-1], embeddings[i])
        
        if sim < threshold:  # 语义变化，切分
            chunks.append("".join(current_chunk))
            current_chunk = [sentences[i]]
        else:
            current_chunk.append(sentences[i])
    
    if current_chunk:
        chunks.append("".join(current_chunk))
    
    return chunks
```

**对 Embedding 的影响**：
- **优点**：每个块的 Embedding 语义内聚性最强，检索精度最高
- **缺点**：需要额外 Embedding 计算，延迟增加；阈值需要针对不同领域调优
- **适用场景**：主题频繁切换的长文档（如会议记录、多主题报告）
- **效果**：在 MTEB Retrieval 任务上，语义分块比固定长度分块的 NDCG@10 高 5-12%

### 方法四：文档结构分块

利用文档本身的结构信息（Markdown 标题、HTML 标签、PDF 大纲）进行层次化分块。

```
    ┌─ # 第一章                     ← 父块
    │  ┌─ ## 1.1 背景              ← 子块 1
    │  │   (段落内容...)
    │  ├─ ## 1.2 相关工作           ← 子块 2
    │  │   (段落内容...)
    │  └─ ## 1.3 方法              ← 子块 3
    │      (段落内容...)
    └─ # 第二章（属于不同父块）...     ← 独立父块
```

**对 Embedding 的影响**：
- **优点**：完全保持自然语义边界，Embedding 质量最高；同时支持层级检索（先查父块再查子块）
- **缺点**：依赖文档格式规范，不含结构信息的文档无法使用
- **适用场景**：技术文档、Wiki、Notion 页面等结构化文档
- **效果**：按章节分块的 Embedding 在领域检索中 Recall@20 可达 0.92+

## 3.4.3 分块策略对检索质量的影响对比

以下是基于 MS MARCO 数据集、使用 BGE-base 模型、不同分块策略的效果对比：

| 分块策略 | Chunk 大小 | Recall@5 | Recall@10 | 平均检索延迟 | Embedding 一致性 |
|---------|-----------|---------|----------|------------|----------------|
| 固定 128 tokens | 128 | 0.623 | 0.741 | 8ms | 低 |
| 固定 256 tokens | 256 | 0.671 | 0.783 | 6ms | 中 |
| 固定 512 tokens | 512 | 0.694 | 0.801 | 4ms | 中高 |
| 递归字符分割 | 200-600 | 0.726 | 0.832 | 5ms | 高 |
| 语义分块 | 100-800 | 0.745 | 0.851 | 12ms* | 最高 |
| 文档结构分块 | 50-2000 | 0.738 | 0.845 | 4ms | 最高 |

> *语义分块的额外延迟来自计算句子间相似度的过程。

**关键发现**：
1. **固定长度分块是最差的选择**——虽然简单，但 Embedding 质量损失最大
2. **256-512 tokens 是黄金区间**——无论使用哪种分块方案，单块在这个范围内效果最优
3. **递归字符分割在通用场景下综合表现最好**——平衡了 Embedding 质量和实现复杂度
4. **语义边界完整性 > 均匀性**——宁可块大小不均，也不要切断语义

## 3.4.4 Chunk Size 对 Embedding 的隐性影响

除了分块方法，**块长度**本身也对 Embedding 质量有重要影响：

### 位置偏差（Position Bias）

大多数 Transformer 编码器存在"位置衰减"现象——靠近文本开头的 token 对 Embedding 的影响更大。过长的块会加剧这个问题，导致块尾部的信息被"淹没"。

```
                  位置偏差对 Embedding 的影响
    ┌──────────────────────────────────────────┐
    │ 注意力权重分布                            │
    │  ████████████████░░░░░░░░░░░░░░░░░░░░░░  │
    │  ↑ 开头 token      ↑ 中部      ↑ 结尾    │
    │  权重高  ████      权重中 ██   权重低 ░░  │
    └──────────────────────────────────────────┘
    
    过大的块 (1500 tokens)：
    ┌──────────────────────────────────────┐
    │ 核心信息在结尾 → Embedding 中信息被稀释 │
    └──────────────────────────────────────┘
    
    合理分块 (300 tokens)：
    ┌──────────────┐
    │ 每个块的信息都 │
    │ 在 Embedding 中│
    │ 得到充分表达   │
    └──────────────┘
```

### 池化策略

Embedding 模型在将 token 序列压缩为单个向量时，使用的池化（Pooling）策略也影响分块决策：

| 池化策略 | 说明 | 对分块的建议 |
|---------|------|------------|
| CLS Token | 取 `[CLS]` 特殊 token 的隐藏状态 | 对开头信息敏感，关键信息尽量前置 |
| Mean Pooling | 所有 token 隐藏状态的平均值 | 受尾部信息衰减影响较小 |
| Max Pooling | 取各维度上的最大值 | 对稀疏信息敏感，长块中可能丢失细节 |
| Weighted Mean | 加权平均，通常使用 attention 权重 | 综合表现最好 |

## 3.4.5 分块策略选择的经验法则

```
                    分块策略选择决策树
    
    文档是否有明确的结构（标题、段落）？
    ┌──────┴──────┐
    是              否
    ▼               ▼
    文档结构分块    文档长度？
    (最佳效果)      ┌──┴──┐
                  <512t  ≥512t
                  ▼      ▼
              不分块   主题是否频繁切换？
                 ┌──────┴──────┐
                 频繁            不频繁
                 ▼               ▼
              语义分块         递归字符分割
              (精度优先)        (通用平衡)
```

**核心建议**：
- **优先保证语义边界完整**——这是对 Embedding 质量影响最大的因素
- **块大小控制在 256-512 tokens**——Embedding 模型在此范围内表现最优
- **overlap 设置为 10-20%**——有效缓解边界截断的损失
- **先测试 3 种通用策略**：递归字符分割 → 语义分块 → 固定长度（按优先级排序）

## 关键概念速查表

| 概念 | 定义 | 说明 |
|------|------|------|
| 分块 (Chunking) | 将长文本切分成适合 Embedding 输入的片段 | 检索系统的预处理步骤 |
| 语义截断效应 | 分块切断自然语义边界导致 Embedding 质量下降 | 最需要避免的问题 |
| 信息稀释效应 | 块中混合多个不相关主题导致 Embedding 区分度下降 | 控制块大小和主题纯度 |
| 粒度失配 | 查询粒度与分块粒度不匹配导致检索效果差 | 需要根据查询类型调整块大小 |
| 固定长度分块 | 按固定 token 数均匀切分 | 简单但效果最差 |
| 递归字符分割 | 按优先级尝试多种分隔符 | 通用场景的最佳折中 |
| 语义分块 | 利用语义相似度检测边界 | 精度最高但速度较慢 |
| 文档结构分块 | 利用文档的标题/结构信息分块 | 结构化文档的最佳选择 |
| 位置偏差 | 模型对文本不同位置的注意力不均 | 过长块会加剧此问题 |
| overlap (重叠) | 相邻块之间的共享 token 数 | 缓解边界截断 |
