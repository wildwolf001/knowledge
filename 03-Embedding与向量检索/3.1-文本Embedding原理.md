# 3.1 文本 Embedding 原理

## 概述

文本 Embedding（嵌入）是将自然语言文本转换为固定长度的稠密向量表示的过程。这个向量空间的设计目标是：语义相似的文本在向量空间中距离相近，语义不同的文本则距离较远。Embedding 是整个 RAG（检索增强生成）系统、记忆检索和语义搜索的基石——没有高质量的 Embedding，后续的所有检索步骤都是空中楼阁。

```
                    文本空间                         向量空间
                  ┌────────────┐                 ┌──────────────────┐
    "猫坐在垫子上" ──→  │            │     ┌──→    │ [0.23, 0.87, ...] │
                  │  Embedding │     │      │                    │
    "A cat sits" ──→  │    Model   │─────┤      │ [0.25, 0.85, ...] │
                  │            │     │      │                    │
    "量子计算"   ──→  │            │     └──→    │ [0.91, 0.12, ...] │
                  └────────────┘            └──────────────────┘
                   语义相似 → 向量距离近        ↑语义不相关→距离远
```

## 3.1.1 对比学习：Embedding 的训练范式

### 核心思想

对比学习（Contrastive Learning）是现代高质量 Embedding 模型的主流训练方法。其核心直觉非常简单：

> **让模型学会区分"相似"和"不相似"——拉近正样本对，推远负样本对。**

形式化地，给定一个 query（查询）$q$，一个正例 $p^+$（与 $q$ 语义相关）和一组负例 $\{p^-_1, p^-_2, ..., p^-_n\}$（与 $q$ 语义不相关），对比学习的目标是优化以下损失函数：

$$L = -\log \frac{e^{\text{sim}(q, p^+)/\tau}}{e^{\text{sim}(q, p^+)/\tau} + \sum_{i=1}^{n} e^{\text{sim}(q, p^-_i)/\tau}}$$

这就是经典的 **InfoNCE Loss**（Noise Contrastive Estimation 损失），其中：
- $\text{sim}(\cdot, \cdot)$ 是余弦相似度（Cosine Similarity）
- $\tau$ 是温度系数（Temperature），控制分布的平滑程度

### 数据构建策略

对比学习的关键在于如何构造有效的正负样本对。常见策略包括：

| 策略 | 方法 | 优点 | 缺点 |
|------|------|------|------|
| **In-Batch Negatives** | 同批次内的其他样本互为负例 | 计算效率高，无需额外构造 | 负例质量不可控 |
| **Hard Negatives** | 用检索器找出语义相近但不匹配的文本作为负例 | 训练出的模型区分能力更强 | 需要额外检索步骤 |
| **Self-Negatives** | 对同一文本做不同的数据增强作为负例 | 简单易行 | 可能引入噪声 |
| **Cross-Batch Negatives** | 跨批次队列中复用历史样本 | 负例池更大 | 内存消耗高 |

实际工业应用中，**In-Batch Negatives + Hard Negatives** 的组合是最常见且效果最好的方案。例如 BGE（BAAI General Embedding）系列模型在训练时就使用了这种混合策略。

### 温度系数的作用

温度系数 $\tau$ 控制着相似度分布的"锐利程度"：
- **低温度**（如 $\tau=0.05$）：放大相似度差异，让模型更关注最难区分的负例（hard negatives），但也容易导致训练不稳定
- **高温度**（如 $\tau=0.2$）：平滑相似度分布，让模型关注所有负例的全局结构，训练更稳定但可能区分能力不足

```python
import torch
import torch.nn.functional as F

def info_nce_loss(query_emb, positive_emb, negative_embs, temperature=0.07):
    """
    计算 InfoNCE Loss
    
    Args:
        query_emb:     [batch_size, dim] 查询向量
        positive_emb:  [batch_size, dim] 正例向量
        negative_embs: [batch_size, num_neg, dim] 负例向量
        temperature:   温度系数
    """
    # 计算 query 与正例的相似度
    pos_sim = F.cosine_similarity(query_emb, positive_emb, dim=-1)  # [batch_size]
    
    # 计算 query 与所有负例的相似度
    neg_sim = F.cosine_similarity(
        query_emb.unsqueeze(1), negative_embs, dim=-1
    )  # [batch_size, num_neg]
    
    # 拼接正负例相似度
    logits = torch.cat([pos_sim.unsqueeze(1), neg_sim], dim=1) / temperature
    
    # 正例在位置 0
    labels = torch.zeros(logits.size(0), dtype=torch.long, device=logits.device)
    
    loss = F.cross_entropy(logits, labels)
    return loss
```

## 3.1.2 Matryoshka Embedding：嵌套式表示

### 问题背景

传统 Embedding 模型输出的向量维度是固定的（如 768 维或 1024 维）。在高维向量检索时，维度越高：
- 存储成本越大（每个向量占用更多内存）
- 检索速度越慢（计算距离需要更多浮点运算）
- 但通常语义信息更丰富

**Matryoshka Embedding**（嵌套式嵌入，又称俄罗斯套娃嵌入）是由 Google Research 在 2022 年提出的一种创新表示方法。它得名于俄罗斯套娃（Matryoshka doll）——外层娃娃打开后里面还有更小的娃娃。

### 核心原理

Matryoshka Embedding 的思想是：**训练一个模型，使其输出的高维向量的前缀子向量本身就携带有意义的语义信息**。也就是说，一个 1024 维的 Matryoshka Embedding，其前 128 维、前 256 维、前 512 维各自都是一个可用的 Embedding 表示。

```
         完整向量 (1024维)
    ┌──────────────────────────────────────────────────────┐
    │  ████████████████████████████████████████████████████  │
    └──────────────────────────────────────────────────────┘
                              ↓ 截取前缀
    ┌──────────────┐
    │  ████████████  │ ← 前 128 维（保留足够的语义信息）
    └──────────────┘
    ┌──────────────────────────┐
    │  ████████████████████████  │ ← 前 512 维（更好的区分度）
    └──────────────────────────┘
```

### 数学形式

训练时，模型同时优化多个维度的损失：

$$L = \sum_{d \in D} \alpha_d \cdot L_{\text{contrast}}(f_d(x))$$

其中：
- $D$ 是一组预定义的目标维度，如 $\{64, 128, 256, 512, 768\}$
- $f_d(x)$ 是取前 $d$ 维后的子向量
- $\alpha_d$ 是各维度的权重系数，通常低维度权重略高以补偿其信息量不足
- $L_{\text{contrast}}$ 是对比损失函数

### Matryoshka 的优势

| 维度 | 存储大小（100万向量） | 检索速度（相对） | 精度（Recall@10） |
|------|---------------------|-----------------|-------------------|
| 1024 | ~4 GB (float32) | 1.0x (基准) | 0.972 |
| 512 | ~2 GB | 1.9x | 0.965 |
| 256 | ~1 GB | 3.5x | 0.941 |
| 128 | ~512 MB | 6.2x | 0.892 |

典型应用流程：
1. 先用低维向量（128 维）做粗略检索，快速筛选出候选池
2. 再用高维向量（1024 维）在候选池中做精确重排序

这种**级联检索**策略可以在精度基本不损失的前提下将检索速度提升 3-6 倍。

```python
from sentence_transformers import SentenceTransformer

# 加载支持 Matryoshka 的模型
model = SentenceTransformer("intfloat/multilingual-e5-large")

def matryoshka_search(query, corpus, dims=[128, 256, 512, 1024], top_k=100):
    """
    使用 Matryoshka Embedding 进行级联检索
    """
    # 编码查询
    q_emb = model.encode(query, normalize_embeddings=True)
    
    # 第一级：低维粗筛 (128维)
    # 从完整的1024维向量中截取前128维
    q_low = q_emb[:128]
    corpus_low = [doc[:128] for doc in corpus]
    
    # 计算相似度，取 top-1000
    scores = np.dot(corpus_low, q_low)
    candidate_indices = np.argsort(scores)[-1000:][::-1]
    
    # 第二级：高维精排 (使用完整1024维)
    q_full = q_emb[:1024]
    candidates = [corpus[i][:1024] for i in candidate_indices]
    final_scores = np.dot(candidates, q_full)
    top_k_indices = candidate_indices[np.argsort(final_scores)[-top_k:][::-1]]
    
    return top_k_indices
```

## 3.1.3 多语言 Embedding 模型

### 面临的挑战

多语言 Embedding 需要将不同语言的文本映射到同一个语义空间中。主要挑战包括：

1. **语言偏移**（Language Shift）：不同语言的 Embedding 在向量空间中形成各自的聚类，导致跨语言检索时同一语义在不同语言中的表示不一致
2. **数据不平衡**：英文训练数据远多于其他语言，导致非英语语言效果显著下降
3. **词序与语法差异**：日语的 SOV 语序与英语的 SVO 语序导致编码器需要学习不同的句法模式

### BGE (BAAI General Embedding)

BGE 系列是当前开源社区最流行的 Embedding 模型之一，由北京智源人工智能研究院（BAAI）发布。

| 模型 | 参数量 | 向量维度 | 最大长度 | 语言支持 | MTEB 平均分 |
|------|--------|---------|---------|---------|------------|
| BGE-small | 24M | 384 | 512 | 多语言 | 57.8 |
| BGE-base | 102M | 768 | 512 | 多语言 | 60.1 |
| BGE-large | 326M | 1024 | 512 | 多语言 | 63.7 |
| BGE-M3 | 567M | 1024 | 8192 | 100+语言 | 67.2 |

**BGE-M3** 是 BGE 系列的重大升级，支持三种粒度：
- **Dense Embedding**（稠密向量）：传统语义匹配
- **Sparse Encoding**（稀疏编码）：词汇级精确匹配（类似 BM25）
- **Multi-Vector**（多向量）：ColBERT 风格的细粒度匹配

```python
from sentence_transformers import SentenceTransformer

# BGE-M3 的使用示例
model = SentenceTransformer("BAAI/bge-m3")

# 多语言语义相似度
sentences = [
    "The cat sits on the mat",           # 英语
    "猫坐在垫子上",                       # 中文
    "猫がマットの上に座っている",           # 日语
    "고양이가 매트 위에 앉아 있다"          # 韩语
]

embeddings = model.encode(sentences, normalize_embeddings=True)

# 计算跨语言相似度
similarities = embeddings @ embeddings.T
# 中文与英语的相似度 ≈ 0.91
# 中文与日语的相似度 ≈ 0.87
```

### text-embedding-3 (OpenAI)

OpenAI 的 text-embedding-3 系列是目前商业场景中最广泛使用的 Embedding 模型：

| 模型 | 维度（默认） | 最大输入 | 定价 | 特点 |
|------|------------|---------|------|------|
| text-embedding-3-small | 1536 | 8191 tokens | $0.02/1M tokens | 性价比最高 |
| text-embedding-3-large | 3072 | 8191 tokens | $0.13/1M tokens | 精度最高 |

关键特性：
- **维度可截断**：支持从 3072 维向下任意截断（类似 Matryoshka），在 API 调用时通过 `dimensions` 参数指定
- **多语言能力强**：在 100+ 语言上训练，中英文交叉检索效果优秀
- **支持短文本和长文本**：最大 8191 tokens 的上下文窗口

```python
from openai import OpenAI

client = OpenAI()

response = client.embeddings.create(
    model="text-embedding-3-large",
    input="需要检索的文本内容",
    dimensions=512  # 截断到 512 维，节省存储空间
)

embedding = response.data[0].embedding
print(f"维度: {len(embedding)}")  # 输出: 512
```

### 多语言模型的选型建议

| 场景 | 推荐模型 | 理由 |
|------|---------|------|
| 仅英文、预算有限 | text-embedding-3-small | 极致性价比 |
| 多语言、高精度要求 | text-embedding-3-large | 业界顶尖效果 |
| 需要本地部署 | BGE-M3 | 开源、多语言、支持三种粒度 |
| 中文为主、需要微调 | BGE-large-zh | 中文优化，可针对特定领域微调 |
| 超长文档检索 | BGE-M3 | 支持8192 tokens |

## 3.1.4 Embedding 模型的评估指标

### MTEB (Massive Text Embedding Benchmark)

MTEB 是目前业界最权威的 Embedding 评估基准，涵盖 8 类任务、58 个数据集：

| 任务类别 | 示例数据集 | 评估指标 | 说明 |
|---------|-----------|---------|------|
| 语义相似度 (STS) | STS-B, SICK-R | Spearman 相关系数 | 预测句子对的相似度与人工标注的一致性 |
| 分类 (Classification) | Amazon, DBpedia | Accuracy | 用 Embedding 作为特征训练分类器 |
| 聚类 (Clustering) | Reddit, Arxiv | V-Measure | Embedding 空间的聚类质量 |
| 检索 (Retrieval) | MIRACL, MS MARCO | NDCG@10, Recall@100 | 信息检索场景的召回率 |
| 重排序 (Reranking) | MIRACL Rerank | MAP (Mean Average Precision) | 对检索结果重新排序的能力 |
| 配对分类 (Pair Classification) | Twitter, Sprint | Average Precision | 判断句子对是否语义相同 |
| 文本排序 (Reranking) | AskUbuntu, SciDocs | MAP | 细粒度语义排序 |

## 3.1.5 实践指南

### 向量归一化

在使用余弦相似度时，始终对 Embedding 向量进行 L2 归一化：

$$v_{\text{normalized}} = \frac{v}{\|v\|_2}$$

这样可以将余弦相似度 $ \text{cos}(a, b) = \frac{a \cdot b}{\|a\|\|b\|} $ 简化为向量点积 $a \cdot b$，大幅提高检索速度。

### 批量编码性能

```python
import time
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-base-zh-v1.5")

data = ["这是第{}个句子".format(i) for i in range(10000)]

# ❌ 逐个编码（慢）
start = time.time()
single_results = [model.encode(s) for s in data[:100]]
print(f"逐个编码耗时: {time.time() - start:.2f}s")

# ✅ 批量编码（快 5-10 倍）
start = time.time()
batch_results = model.encode(data[:100], batch_size=64)
print(f"批量编码耗时: {time.time() - start:.2f}s")
```

### 输入前缀

许多 Embedding 模型对输入有特定的前缀要求，这会影响检索效果：

| 模型 | Query 前缀 | Document 前缀 |
|------|-----------|--------------|
| BGE | `"为这个句子生成表示以用于检索相关问题："`（中文） | 无特殊前缀 |
| E5 | `"query: "` | `"passage: "` |
| Instructor | `"Represent the query for retrieval: "` | `"Represent the document: "` |

## 关键概念速查表

| 概念 | 定义 | 重要性 |
|------|------|--------|
| Embedding | 将文本转换为固定长度的稠密向量表示 | 检索系统的基石 |
| 对比学习 (Contrastive Learning) | 通过拉近正样本、推远负样本来训练 Embedding 模型 | 主流训练范式 |

| 温度系数 (Temperature) | 控制对比损失中相似度分布的平滑程度 | 影响训练稳定性和区分能力 |
| In-Batch Negatives | 同批次内其他样本作为负例 | 高效的负例构造策略 |
| Hard Negatives | 与查询语义接近但不匹配的样本作为负例 | 提升模型区分能力的关键 |
| BGE | 智源研究院开发的开源多语言 Embedding 模型系列 | 开源社区最流行方案之一 |
| text-embedding-3 | OpenAI 的商业 Embedding 模型（small/large） | 商业场景的标杆 |
