# Agno（原 Phidata）—— 轻量高性能、内置 Session Memory、关注点分离

## 概述

Agno（原名 **Phidata**，2025 年更名）是一个专注于 **轻量高性能** 和 **关注点分离**（Separation of Concerns）的 Agent 构建框架。它在社区中以其极端的性能优势著称——官方基准测试显示，Agno 的 Agent 实例化速度比 LangGraph 快 **529 倍**，比 CrewAI 快 **118 倍**。截至 2026 年，Agno 在 GitHub 拥有约 **18k+ stars**，保持活跃开发状态。

Agno 的设计哲学可以用三个关键词概括：
- **轻量**：核心库极简，没有厚重的抽象层，无冗余依赖
- **高性能**：最小化运行时开销，优化 Agent 实例化和执行路径
- **关注点分离**（Separation of Concerns）：将 Agent 的知识、工具、记忆、执行逻辑清晰地分离为独立组件

Agno 不试图成为一个"全栈 Agent 框架"，而是专注于提供一个极简的 Agent 构建核心，让开发者可以根据需求自由组合其他组件。

## 核心架构

### 三组件模型

Agno 的核心架构由三个独立组件构成，每个组件负责一个关注点：

```python
from agno import Agent, KnowledgeBase, Tool, SessionMemory

agent = Agent(
    name="research_agent",
    knowledge=KnowledgeBase(...),  # 知识库（关注领域知识）
    tools=[Tool(...), Tool(...)],  # 工具集（关注执行能力）
    memory=SessionMemory(...),     # 记忆（关注状态持久化）
    model="gpt-4o"                # LLM 模型
)
```

#### 1. Knowledge（知识层）

Knowledge 组件负责管理 Agent 的领域知识和上下文信息：
- **向量知识库**（Vector Knowledge Base）：基于嵌入（embedding）的语义检索
- **结构化知识**：JSON / CSV / 数据库查询结果
- **实时知识**：Web 搜索、API 调用结果
- **知识自动注入**：在每次 Agent 执行时，自动将相关知识注入到 Prompt 上下文中

```python
from agno.knowledge import PDFKnowledgeBase, WebKnowledgeBase

# PDF 知识库
pdf_kb = PDFKnowledgeBase(
    path="./documents/",
    vector_db="chroma",
    embedding_model="text-embedding-3-small"
)

# Web 知识库
web_kb = WebKnowledgeBase(
    urls=["https://docs.example.com/api"],
    crawler_depth=2
)
```

#### 2. Tool（工具层）

Tool 组件封装 Agent 的执行能力：
- **函数工具**（Function Tool）：将任意 Python 函数包装为 Agent 可调用的工具
- **API 工具**：封装 REST/gRPC API 调用
- **代码执行工具**：安全沙箱中的代码运行器
- **框架集成工具**：与 LangChain、LlamaIndex 等生态的互操作适配器

```python
from agno.tools import FunctionTool
from agno.tools.code_interpreter import CodeInterpreterTool

# 自定义函数工具
def search_database(query: str) -> list[dict]:
    """在数据库中搜索相关记录"""
    return db.execute(f"SELECT * FROM records WHERE content LIKE '%{query}%'")

search_tool = FunctionTool(
    name="database_search",
    func=search_database,
    description="在内部数据库中搜索信息"
)

# 代码执行工具
code_tool = CodeInterpreterTool(
    sandbox="docker",  # Docker 沙箱
    timeout=30
)
```

#### 3. Memory（记忆层）

Memory 组件管理 Agent 的状态和历史，这是 Agno 区别于许多轻量框架的核心能力：

- **Session Memory（会话记忆）**：按 session_id 隔离的对话历史，支持持久化到多种存储后端
- **短期记忆**：当前会话内的上下文窗口管理
- **长期记忆**：跨会话的用户偏好和行为模式学习
- **结构化记忆**：提取并存储关键信息（如用户偏好、事实提取）

```python
from agno.memory import SessionMemory
from agno.storage import PostgresStorage

# 持久化会话记忆
memory = SessionMemory(
    storage=PostgresStorage(
        table_name="agent_sessions",
        db_url="postgresql://user:pass@localhost:5432/agents"
    ),
    session_id="user_123_session_456",
    max_messages=100  # 每个会话最多保留 100 条消息
)
```

### 性能数据深度分析

Agno 官方公布的基准测试数据（基于 v0.8+）：

| 操作 | LangGraph | CrewAI | Agno |
|---|---|---|---|
| Agent 实例化（单 Agent） | 5,290 ms | 1,180 ms | **10 ms** |
| Agent 实例化（多 Agent，10 个） | 52,300 ms | 11,200 ms | **95 ms** |
| 单次工具调用延迟（含 LLM） | 1,450 ms | 1,520 ms | **1,380 ms** |
| 内存占用（空闲 Agent） | 245 MB | 189 MB | **32 MB** |
| Docker 镜像大小（基础） | 1.2 GB | 890 MB | **180 MB** |

性能差异的关键原因：

1. **无冗余依赖**：Agno 的核心依赖仅包括 `aiohttp`、`pydantic` 等必要的库，不捆绑任何 Agent 框架依赖
2. **懒加载设计**（Lazy Loading）：组件在需要时才初始化，而非在 Agent 实例化时全部预加载
3. **优化的类型系统**：基于 Pydantic v2 的类型系统相比 LangChain/LangGraph 复杂的 Runnable 继承体系开销低得多
4. **无全局状态**：Agno 不维护任何全局注册表或工厂，减少了初始化开销

```python
# 性能对比的简单基准代码
import time
from agno import Agent as AgnoAgent
from langgraph.graph import StateGraph  # 仅用于对比

# Agno 实例化
start = time.perf_counter()
agno_agent = AgnoAgent(model="gpt-4o")
print(f"Agno: {(time.perf_counter() - start) * 1000:.1f} ms")
# 输出: Agno: 8.5 ms

# LangGraph 实例化（StateGraph + Node 设置）
start = time.perf_counter()
from langgraph.graph import StateGraph, MessagesState
graph = StateGraph(MessagesState)
graph.add_node("agent", lambda state: state)
print(f"LangGraph: {(time.perf_counter() - start) * 1000:.1f} ms")
# 输出: LangGraph: ~5000 ms
```

### 关注点分离的实践价值

Agno 的设计哲学不仅仅是技术选择，而是对 Agent 工程实践的深刻理解：

**传统单体 Agent 的问题**：
```
# 单体设计：知识、工具、记忆全部耦合
class MonolithicAgent:
    def __init__(self):
        self.vector_db = ChromaDB(...)
        self.search_tool = SearchTool(...)
        self.memory = []
```

**Agno 的关注点分离**：
```python
# 分离设计：每个组件独立定义、独立测试、独立替换
from agno.components import KnowledgeComponent, ToolComponent, MemoryComponent

agent = Agent(
    knowledge=KnowledgeComponent(vector_db=ChromaDB(...)),
    tools=[SearchTool()],
    memory=SessionMemory(storage=PostgresStorage(...))
)

# 每个组件可独立替换
# 切换知识库只改一个参数
agent.knowledge = KnowledgeComponent(vector_db=PineconeDB(...))
```

这种设计的实际好处：

1. **可测试性**：知识、工具、记忆可以独立测试，无需启动完整的 Agent
2. **可替换性**：切换向量数据库或存储后端不需要修改 Agent 核心代码
3. **性能优化**：每个组件可以独立进行性能调优
4. **团队协作**：不同团队成员可以并行开发不同组件

## 内置 Session Memory 详解

Session Memory 是 Agno 最具特色的功能之一。与 LangGraph 的全局检查点不同，Agno 的 Session Memory 提供了更简洁的会话级状态管理。

### Session 生命周期

```
Session 创建
    │
    ▼
  ┌─────────────┐     ┌──────────────┐
  │   Session   │────▶│   Message    │────▶ ...
  │   Active    │     │   History    │
  └─────────────┘     └──────────────┘
        │
        ▼
  ┌─────────────┐
  │   Session   │
  │Persisted to │
  │  Storage    │
  └─────────────┘
        │
        ▼
  ┌─────────────┐
  │   Session   │
  │  Restored   │
  │ for Updates │
  └─────────────┘
```

### 存储后端支持

| 存储后端 | 适用场景 | 性能 |
|---|---|---|
| `InMemoryStorage` | 开发/测试 | 最快 |
| `JSONFileStorage` | 单机小规模 | 中等 |
| `SQLiteStorage` | 单机中小规模 | 中高 |
| `PostgresStorage` | 生产环境 | 高 |
| `RedisStorage` | 高并发缓存 | 极高 |
| `MongoDBStorage` | 文档存储 | 高 |

## 部署与生态

### 部署方式

Agno 的轻量设计使其特别适合资源受限的部署环境：

- **Serverless 函数**（AWS Lambda / Cloudflare Workers）：32MB 基础镜像大小使其非常适合 Serverless 部署
- **边缘计算**：可在资源有限的边缘设备上运行
- **Docker / K8s**：标准容器化部署
- **嵌入式服务**：作为微服务的一部分嵌入到更大的应用中

```python
# AWS Lambda 部署示例
from agno import Agent

def lambda_handler(event, context):
    agent = Agent(model="gpt-4o-mini", tools=[...])
    result = agent.run(event["query"])
    return {"statusCode": 200, "body": result}
```

### 生态集成

Agno 保持极小的核心库，通过插件机制与其他生态集成：

- **LLM 提供商**：OpenAI、Anthropic、Google Gemini、Mistral、Groq、Ollama（本地模型）
- **向量数据库**：ChromaDB、Pinecone、Weaviate、Qdrant、Milvus
- **存储后端**：PostgreSQL、SQLite、Redis、MongoDB、AWS S3
- **框架集成**：LangChain（工具适配）、LlamaIndex（知识库适配）
- **监控和可观测性**：Langfuse、Weights & Biases

## 优劣势分析

### 优势

- **极致的性能**：Agent 实例化速度比竞争对手快 2-3 个数量级，内存占用极低
- **关注点分离设计**：组件独立性强，可测试性和可维护性优秀
- **内置 Session Memory**：开箱即用的会话持久化能力
- **Serverless 友好**：极小的体积使其适合边缘计算和无服务器部署
- **低依赖度**：几乎不捆绑第三方 Agent 框架依赖，减少版本冲突

### 劣势

- **架构灵活性有限**：相比 LangGraph 的自定义图拓扑和 AutoGen 的 Actor 模型，Agno 的工作流模式较为简单
- **多 Agent 协作原生支持弱**：缺乏类似 CrewAI 的角色扮演或 AutoGen 的 GroupChat 内置抽象
- **社区规模较小**：相比 LangChain/LangGraph 和 CrewAI，社区贡献和第三方模板较少
- **企业功能缺失**：无原生内置的企业级监控、A/B 测试、版本管理
- **文档和生产案例不足**：与 Microsoft 支持的 AutoGen 或获 1800 万美元融资的 CrewAI 相比，企业背书较少

## 与 LangGraph 和 AutoGen 的性能对比

| 维度 | Agno | LangGraph | AutoGen |
|---|---|---|---|
| 实例化耗时（单 Agent） | ~10 ms | ~5,290 ms | ~120 ms |

## 何时选择 Agno

### 适用场景

- **对延迟敏感的应用**：客服、实时推荐等需要亚秒级响应的场景
- **Serverless 架构**：AWS Lambda、Cloudflare Workers 等资源受限环境
- **嵌入式 Agent**：将 Agent 嵌入到现有微服务架构中
- **快速原型开发**：需要在几分钟内搭建一个可工作的 Agent 原型
- **成本敏感项目**：较低的资源占用意味着更低的云服务费用

### 不适用场景

- **复杂多 Agent 协作**：需要高级多 Agent 编排能力时，AutoGen 或 LangGraph 更合适
- **企业级全栈方案**：需要内置监控、日志、A/B 测试等企业功能时
- **需要复杂图拓扑**：工作流涉及复杂的条件分支、循环、并行节点时
- **团队熟悉 CrewAI 范式**：如果团队更适应角色扮演模式，不建议引入新框架

## 关键概念速查

| 概念 | 解释 |
|---|---|
| **关注点分离** | 将知识、工具、记忆和执行逻辑分离为独立组件的设计原则 |
| **Session Memory** | 按 session_id 隔离的会话级记忆系统，支持多存储后端持久化 |
| **KnowledgeBase** | 知识库组件，管理 Agent 的领域知识和检索逻辑 |
| **FunctionTool** | 将 Python 函数包装为 LLM 可调用工具的组件 |
| **CodeInterpreterTool** | 在安全沙箱中运行 Python 代码的工具 |
| **InMemoryStorage** | 运行时的内存存储，非持久化 |
| **Serverless 友好** | 框架的轻量设计使其适合无服务器部署 |
| **懒加载** | 组件在使用时才初始化，减少启动时间 |
| **Pydantic v2** | Agno 使用的类型系统，提供高性能的数据验证和序列化 |
