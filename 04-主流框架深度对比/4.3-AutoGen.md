# AutoGen的退场与MAF/AG2的新生 —— Actor Model 遗产与生态分裂

## 概述

> **重要通知**：Microsoft AutoGen 仓库于 **2025 年 9 月** 正式进入维护模式（maintenance mode），Microsoft 不再推荐新项目选用 AutoGen。官方推荐迁移至 **Microsoft Agent Framework (MAF)**。社区分支 **AG2**（由 ag2ai/ag2 维护，Apache 2.0 许可证）延续了原 AutoGen 的 API 风格，为存量用户提供了替代迁移路径。

AutoGen 曾是由 **Microsoft Research** 开发并开源的多 Agent 对话框架，采用 **Actor Model（参与者模型）** 作为核心架构：每个 Agent 是一个独立的消息驱动 Actor，通过异步消息传递进行通信。它在 **GAIA 基准测试**（General AI Assistants benchmark）中曾取得 **#1 排名**，是 2024-2025 年间最具影响力的多 Agent 框架之一。

AutoGen 的三个核心理念：
- **异步消息驱动**：Agent 之间通过事件/消息通信，而非共享状态
- **模块化三层架构**：Core（基础运行时） → AgentChat（对话抽象） → Extensions（生态扩展）
- **开发者可控**：框架提供细粒度的控制能力，不隐藏底层复杂性

AutoGen 的退场标志着第一代 Agent 框架的转折点。其技术遗产通过两个分支继续演进：

| 方向 | 项目 | 维护方 | 定位 | GitHub Stars |
|---|---|---|---|---|
| **官方继任** | Microsoft Agent Framework (MAF) | Microsoft | Python + C# 双语言，企业级 Agent 框架 | 10.2k+ |
| **社区继承** | AG2 (ag2ai/ag2) | 社区维护 | Apache 2.0，延续 AutoGen API 风格 | 快速增长中 |

## Microsoft Agent Framework (MAF) —— 官方继任者

### 概述

Microsoft Agent Framework (MAF) 是 Microsoft 推出的新一代 Agent 开发框架，也是 AutoGen 的官方继任者。MAF 采用 **Python + C# 双语言** 支持，与 Microsoft 365 Copilot 生态深度集成，提供企业级的 Agent 开发、部署和管理能力。

MAF 的核心特性：

- **双语言支持**：Python 和 C# 提供对等的 API 体验，.NET 生态可直接使用
- **Microsoft 365 集成**：与 SharePoint、Teams、Outlook 等 Microsoft 365 服务原生集成
- **企业级安全**：基于 Microsoft Entra ID 的认证和权限管理
- **Azure AI 深度集成**：与 Azure AI Foundry、Azure OpenAI Service 无缝对接
- **Copilot 扩展性**：可直接扩展 Microsoft Copilot 的能力

### 核心架构

MAF 的架构围绕 **"Agent as a Service"** 的理念设计，放弃了 AutoGen 中复杂的 Actor Model，采用更简洁的 Kernel-Agent 架构：

```python
# MAF Python SDK 示例（概念）
from maf import Agent, Kernel

# 创建 Kernel（运行时容器）
kernel = Kernel()

# 定义 Agent
research_agent = Agent(
    name="research_assistant",
    instructions="你是一个研究助手，帮助用户分析市场趋势",
    model="gpt-4o"
)

# 注册 Agent 并运行
kernel.add_agent(research_agent)
response = await kernel.run(
    agent="research_assistant",
    input="分析2026年AI Agent框架市场格局"
)
```

### 适用场景

- **微软技术栈企业**：已使用 Azure、Microsoft 365 的组织
- **.NET / C# 团队**：希望在 .NET 生态中构建 Agent 应用
- **需要 Copilot 扩展**：需要将自定义 Agent 集成到 Microsoft Copilot
- **企业级合规要求**：需要 Microsoft 生态的安全和合规管理能力

### 与 AutoGen 的关系

MAF 并非 AutoGen 的简单升级，而是一个全新的框架设计。它保留了 AutoGen 的异步消息驱动理念，但放弃了 Actor Model 的复杂度，采用更简洁的 Kernel-Agent 架构。Microsoft 提供了从 AutoGen 到 MAF 的迁移指南，但需要一定的代码重构。

## AG2 —— 社区分支的延续

### 概述

AG2（原名 AutoGen 社区分支，托管于 **ag2ai/ag2**）是在 AutoGen 进入维护模式后，由原社区核心贡献者创建的分支项目。它在 **Apache 2.0 许可证** 下延续 AutoGen 的 API 风格和架构理念，为不希望迁移到 MAF 的团队提供了替代方案。

AG2 的核心定位：

- **API 兼容性**：尽可能保持与 AutoGen v0.4+ (AGnext) API 的兼容
- **社区驱动**：由原 AutoGen 社区的核心贡献者维护，不受 Microsoft 产品路线图限制
- **Apache 2.0 许可证**：宽松许可证，适合商业使用
- **独立演进**：可自主决定功能迭代方向，不受厂商策略影响

### 核心特性

AG2 继承了 AutoGen 的核心架构，并在此基础上进行改进：

- 保留了 **Actor Model** 和异步消息传递的核心设计
- 持续更新 LLM 模型支持（包括最新模型如 GPT-4.1、Claude 4 Sonnet 等）
- 简化了部分过度复杂的三层架构
- 增加了社区贡献的新工具和集成

### 适用场景

- **AutoGen 存量项目**：已有 AutoGen 代码库，希望最小化迁移成本
- **偏好 Apache 2.0 许可证**：对许可证要求敏感的商业项目
- **需要 Actor Model 架构**：特定场景仍需要此并发模型
- **不想绑定 Microsoft 生态**：希望框架独立于特定厂商的团队

## 核心架构

### Actor Model 与消息传递

AutoGen 的底层模型是 **Actor Model**，这是一种起源于 1973 年的并发计算模型，在 Erlang 语言中得到了充分验证。每个 Actor 拥有：

- **私有的状态**：Actor 维护自己的内部状态，不与其他 Actor 共享
- **消息队列**（Mailbox）：接收异步消息的队列
- **行为定义**：定义如何响应不同类型的消息

```python
# AutoGen Core 的 Actor 示例（简化概念）
from autogen_core import AgentRuntime, SingleThreadedAgentRuntime
from autogen_core import TopicId, MessageContext

class MyAgent(BaseAgent):
    async def on_message(self, message, ctx: MessageContext):
        # 处理收到的消息
        result = await self.process(message)
        # 发送消息给其他 Agent
        await self.publish_message(result, topic_id=TopicId("default", "agent_b"))
        return result
```

这种设计与传统的函数调用模式有本质区别：

| 维度 | Actor Model（AutoGen） | 图模型（LangGraph） |
|---|---|---|
| 通信方式 | 异步消息传递 | 状态共享 + 边路由 |
| 状态管理 | 每个 Actor 私有状态 | 全局共享 State 对象 |
| 并发模型 | 天然支持并发 Actor | 串行图执行 |
| 容错性 | Actor 隔离，失败不影响其他 Actor | 检查点恢复 |
| 调试复杂度 | 消息追踪 | 状态回溯 |

### 三层架构详解

AutoGen v0.4+ 采用清晰的三层架构，自底向上依次是：

**1. Core 层（基础运行时）**

Core 层是 AutoGen 的运行时基础，提供：

- **AgentRuntime**：Agent 的运行时容器，负责消息路由、Agent 生命周期管理
- **消息传递基础设施**：基于 Topic（主题）的发布/订阅机制
- **Agent 代理**（AgentProxy）：允许非 Agent 组件（如 Web 服务）与 Agent 通信
- **分布式支持**：底层支持跨进程、跨机器的 Agent 通信（通过 gRPC）

Core 层提供两种运行时实现：
- `SingleThreadedAgentRuntime`：单线程轻量运行时，适合开发和测试
- `DistributedAgentRuntime`：分布式运行时，适合生产部署

```python
# Core 层使用示例
from autogen_core import SingleThreadedAgentRuntime

runtime = SingleThreadedAgentRuntime()
runtime.start()  # 启动运行时

# 注册 Agent
await MyAgent.register(runtime, "my_agent", lambda: MyAgent())

# 发送消息
await runtime.send_message(
    source="user",
    destination="my_agent",
    message=MyMessage(content="hello")
)
```

**2. AgentChat 层（对话抽象）**

AgentChat 层在 Core 层之上构建了更高层的对话抽象，包括：

- **ChatAgent**：高级 Agent 接口，内置对话历史管理
- **GroupChat**：多 Agent 群组对话，支持多种对话模式（轮转、广播、选择性响应）
- **Tool**：工具调用的标准接口，与 OpenAI Function Calling 兼容
- **AgentTeam**：团队协作的更高层抽象

AgentChat 层是大多数开发者直接使用的 API 层：

```python
# AgentChat 层使用示例
from autogen_agentchat.agents import AssistantAgent
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.ui import Console

# 定义 Agent
agent1 = AssistantAgent(
    name="assistant_1",
    model_client="gpt-4o",
    tools=[search_tool, calculator_tool],
    system_message="你是一个研究助手"
)

agent2 = AssistantAgent(
    name="assistant_2",
    model_client="gpt-4o",
    system_message="你是一个审稿人，负责检查回答的准确性"
)

# 创建团队
team = RoundRobinGroupChat(
    participants=[agent1, agent2],
    max_turns=10
)

# 执行对话
async for message in team.run(task="分析2025年AI行业趋势"):
    Console(message)
```

**3. Extensions 层（生态扩展）**

Extensions 层提供了与外部生态的集成能力：

- **Magentic-One**：Microsoft 的通用多 Agent 系统，基于 AutoGen 构建，支持跨应用操作
- **AutoGen Bench**：框架的基准测试工具集
- **社区扩展**：与 LangChain、LlamaIndex、ChromaDB 等生态的集成
- **Web 集成**：基于 AutoGen 的 Web 应用模板和中间件

### 消息与 Topic 机制

AutoGen 的消息系统基于 **发布/订阅（Pub/Sub）** 模式：

- **Topic**：消息的分类通道，Agent 订阅特定 Topic 来接收相关消息
- **TopicId**：由 `source`（来源）和 `topic_type`（类型）组成
- **消息路由**：Agent 通过 `publish_message` 发送消息到 Topic，运行时负责路由

```python
# 消息发布/订阅示例
from autogen_core import TopicId

# Agent A 发布消息到 Topic
await agent_a.publish_message(
    message=AnalysisResult(data=...),
    topic_id=TopicId(topic_type="analysis", source="agent_a")
)

# Agent B 订阅"analysis"类型的 Topic
class AgentB(BaseAgent):
    def __init__(self):
        super().__init__()
        self.subscribe("analysis")  # 订阅分析结果
    
    async def on_message(self, message, ctx):
        # 当有 analysis 类型的消息发布时自动触发
        ...
```

### 对话模式

AutoGen 支持多种多 Agent 对话模式：

1. **轮转对话**（RoundRobin）：Agent 按固定顺序轮流发言
2. **选择式对话**（Selective）：Agent 选择性地响应特定消息
3. **广播式对话**（Broadcast）：消息发送给所有订阅者
4. **管理者模式**（Manager）：一个 Agent 负责调度和协调其他 Agent

## 与 LangGraph 和 CrewAI 的架构对比

| 维度 | AutoGen (历史) / AG2 | MAF | LangGraph | CrewAI |
|---|---|---|---|---|
| **架构模型** | Actor 模型 | Kernel-Agent | 有向图 | 角色扮演 |
| **通信方式** | 异步消息 | 同步/异步 | 状态传递 | Task 输出传递 |
| **状态管理** | Actor 私有状态 | Kernel 托管 | 全局共享 State | 隐式 Task 上下文 |
| **并发支持** | 原生并发 | 中等 | 串行（可并行节点） | 顺序/层次 |
| **流式支持** | 消息级流式 | 支持 | Token 级细粒度流式 | 有限 |
| **分布式** | 原生支持 | Azure 原生 | 通过 LangGraph Cloud | 通过 Enterprise |
| **学习曲线** | 中高 | 中 | 中 | 低 |
| **当前状态** | 维护模式 / 社区分支 | 积极开发 | 积极开发 | 积极开发 |

## 优劣势分析

### 优势

- **异步架构的高扩展性**：Actor 模型天然支持高并发和大规模 Agent 部署，适合需要大量 Agent 协同的场景
- **GAIA #1 证明的推理能力**：在复杂多步骤推理任务上经过验证的性能
- **分布式原生支持**：与其他框架不同，AutoGen 在底层就设计了分布式通信能力
- **Microsoft 生态整合**：与 Azure AI、Semantic Kernel 等 Microsoft 技术栈无缝集成
- **低框架锁定性**：Core 层的抽象较少，开发者对底层逻辑有更大的控制权

### 劣势

- **学习曲线陡峭**：Actor 模型、消息系统、三层架构的概念深度高于 CrewAI 和多数框架
- **高并发场景下的调试困难**：异步消息流的追踪比同步调用链复杂得多
- **版本兼容性问题**：v0.2 → v0.4（AGnext）的重构导致 API 不兼容，社区有许多过时的教程
- **文档滞后**：截至 2025 年底，许多官方文档仍反映旧版本 API，新版本的最佳实践文档不完善
- **框架门槛较高**：对于简单的单 Agent 应用，Actor 模型是过度设计

## 2026年选型建议：MAF vs AG2 vs 替代框架

### AutoGen 存量用户迁移路径

| 当前状态 | 推荐方案 |
|---|---|
| 新项目，考虑 AutoGen | **不要选择 AutoGen**。选用 MAF（微软栈）、AG2（社区版）、或 LangGraph/CrewAI（非微软栈） |
| 已有 AutoGen 代码，希望最小化改动 | 迁移至 **AG2**（API 兼容性最高，学习成本最低） |
| 已有 AutoGen 代码，深度绑定 Microsoft 生态 | 迁移至 **MAF**（官方推荐路径，需一定代码重构） |
| 已有 AutoGen 代码，对框架中立性有要求 | 考虑 **LangGraph** 或 **CrewAI**（架构差异大，需较大重构） |

### MAF 适用场景

- **微软技术栈企业**：已使用 Azure、Microsoft 365 的组织
- **需要 Copilot 集成**：扩展 Microsoft Copilot 的能力
- **.NET/C# 团队**：希望在 .NET 生态中开发 Agent 应用
- **企业级合规要求**：需要 Microsoft 生态的完整安全和合规管理能力

### AG2 适用场景

- **AutoGen 存量项目延续**：已有代码库最小化迁移成本
- **偏好 Apache 2.0 许可证**：宽松许可证适合商业项目
- **需要 Actor Model 架构**：特定场景仍需要此并发模型

### 不再推荐使用 AutoGen 的场景

- **任何新项目**：AutoGen 已进入维护模式，不再有新功能开发
- **对长期维护有要求的项目**：官方不再提供长期支持
- **需要持续更新的 LLM 集成**：新模型的支持将由 MAF 和 AG2 分别处理
