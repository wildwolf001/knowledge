# CrewAI — 角色扮演式多 Agent 协作框架

## 概述

CrewAI 是一个独立的多 Agent 协作框架，专注于通过 **角色扮演（role-playing）** 范式组织多个 AI Agent 协同完成任务。该框架在 2024 年获得 **1800 万美元** 融资，与 LangChain 生态无强制性依赖关系。截至 2026 年 4 月，CrewAI 最新版本为 **v1.14.4**，GitHub 星标超过 **50.8k**，是 Agent 框架中社区最活跃的项目之一。CrewAI 的设计理念直观：每个 Agent 被赋予一个角色（role）、目标（goal）和背景故事（backstory），多个 Agent 组成"团队（crew）"来执行任务。

## 核心架构

### 三层抽象

CrewAI 的核心抽象由三个主要概念构成：

**1. Agent（代理）**
- 定义：`Agent(role="研究员", goal="收集市场数据", backstory="资深市场分析师")`
- 每个 Agent 拥有独立的角色描述、目标、背景故事，用于在 Prompt 层面塑造 LLM 行为
- 可配置：LLM 模型、温度参数、允许的工具集、是否允许委派任务（delegation）
- Agent 之间可以互相委派任务，形成动态协作

**2. Task（任务）**
- 定义：`Task(description="分析季度销售数据", expected_output="结构化报告", agent=analyst_agent)`
- 每个任务绑定一个 Agent，包含明确的任务描述和期望输出格式
- 支持上下文任务传递（context from other tasks）

**3. Crew（团队）**
- 定义：`Crew(agents=[...], tasks=[...], process=Process.sequential)`
- 组织 Agent 和 Task 的执行流程
- 管理共享资源（如工具集、知识库）

### 执行流程（Process 类型）

CrewAI 提供两种内置的执行流程：

**顺序执行（Sequential Process）**
- Task 按定义顺序依次执行，每个 Task 分配给指定的 Agent
- 前一个 Task 的输出可以作为下一个 Task 的上下文
- 简单、可预测、适合线性流水线

**层次执行（Hierarchical Process）**
- 一个 Agent 被指定为"经理（manager）"，负责将 Task 分解并委派给其他 Agent
- 经理 Agent 决定任务分配和优先级
- 适合需要动态任务拆分的复杂场景
- 经理 LLM 通常需要更强的推理能力（如 GPT-4、Claude 3 Opus）

### YAML 驱动配置

CrewAI 支持通过 YAML 文件定义 Agent、Task 和 Crew，实现低代码（low-code）配置：

```yaml
# agents.yaml
researcher:
  role: "市场研究员"
  goal: "发现市场趋势"
  backstory: "资深市场分析师，拥有10年经验"
```

这种方式适合与业务团队协作，减少代码变更需求。

## Flows —— 事件驱动控制流

CrewAI v1.12+ 引入了 **Flows** 机制，为工作流编排提供了事件驱动的控制能力，弥补了此前 CrewAI 在复杂流程控制上的短板：

```python
from crewai.flow.flow import Flow, start, listen
from crewai import Agent, Task, Crew

class ContentPipeline(Flow):
    
    @start()
    def research(self):
        """研究方向"""
        research_agent = Agent(role="研究员", goal="收集资料", ...)
        research_task = Task(description="调研AI趋势", agent=research_agent)
        crew = Crew(agents=[research_agent], tasks=[research_task])
        result = crew.kickoff()
        return {"research_data": result}
    
    @listen(research)
    def write_draft(self, previous_output):
        """在调研完成后自动触发写作"""
        writer = Agent(role="作者", goal="撰写文章", ...)
        write_task = Task(
            description=f"基于调研结果撰写文章: {previous_output['research_data']}",
            agent=writer
        )
        crew = Crew(agents=[writer], tasks=[write_task])
        return crew.kickoff()
    
    @listen(write_draft)
    def review(self, previous_output):
        """在草稿完成后自动触发审校"""
        ...

# 执行事件驱动流程
pipeline = ContentPipeline()
result = pipeline.run()
```

Flows 的核心特性：

- **事件驱动**：使用 `@start()`、`@listen()` 装饰器定义方法间的依赖关系，方法在依赖条件满足时自动触发
- **状态共享**：Flow 类内部共享状态，方法间通过返回值传递数据
- **条件路由**：支持基于条件判断选择不同的执行路径
- **并行执行**：多个 `@listen()` 方法可以并行执行

## AMP Cloud 与 AMP Factory —— 商业化方案

CrewAI 在 2025-2026 年推出了两条商业化产品线，从开源框架扩展为企业级 Agent 平台：

- **AMP Cloud**（托管平台）：全托管的 Agent 部署平台，提供自动扩缩容、监控告警、日志聚合等企业级功能。适合希望快速上线、减少运维投入的团队。
- **AMP Factory**（私有化部署）：面向大型企业的私有化部署方案，支持在客户自有基础设施上运行，满足数据安全和合规要求。提供定制化 Agent 模板和审批工作流引擎。

这两条商业化路径使 CrewAI 覆盖了从快速原型到大规模生产部署的完整链路。

## 优劣势分析

### 优势

- **快速上手**：角色扮演范式直观，新团队可以快速理解并产出原型
- **内容生成流水线**：非常适合多步骤内容创作场景，如：调研 → 写作 → 审核 → 发布
- **营销自动化**：典型用例包括 SEO 内容策略、社交媒体管理、邮件营销序列
- **企业级采用**：已有较多企业部署案例，融资充足，生态发展较活跃
- **低代码配置**：YAML 驱动使非技术团队也能参与 Agent 定义

### 劣势

- **流式支持有限**：相比 LangGraph 的细粒度流式，CrewAI 的实时输出能力较弱
- **控制粒度不足**：无法像 LangGraph 那样控制每个状态转换的细节
- **生态较年轻**：相比 LangChain 生态，工具集成、插件、社区模板和最佳实践积累较少
- **复杂工作流受限**：对于需要循环、条件分支、人工介入审核的场景，CrewAI 的原生支持不如 LangGraph 成熟
- **框架绑定风险**：CrewAI 的抽象层较厚，底层逻辑难以完全透明调试

## 典型应用场景

| 场景 | 配置建议 |
|---|---|
| 内容创作流水线 | 顺序执行，3-5 个 Agent 各司其职 |
| 客户服务团队 | 层次执行，经理 Agent 路由到垂直 Agent |
| 研究分析报告 | 顺序执行，研究员 → 分析师 → 编辑 |
| 多角度评估 | 并行 Agent + 汇总 Task |

## 与 LangGraph 的架构对比

| 维度 | CrewAI | LangGraph |
|---|---|---|
| 核心抽象 | 角色 + 团队 | 状态图 + 节点 |
| 控制流 | 预设流程类型 | 完全自定义的条件边 |
| 状态管理 | 隐式（Task 输出传递） | 显式类型化 State 对象 |
| 人工介入 | 有限 | 一等公民（interrupt） |
| 学习曲线 | 低 | 中高 |
| 灵活度 | 中 | 高 |
