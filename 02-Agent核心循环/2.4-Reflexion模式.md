# 2.4 Reflexion 模式

## 论文来源

- **Reflexion: An Autonomous Agent with Dynamic Memory and Self-Reflection** -- Noah Shinn, Federico Cassano, Ashwin Gopinath, Karthik Narasimhan, Shunyu Yao (2023)
  - arXiv: [2303.11366](https://arxiv.org/abs/2303.11366)
  - 发表于 NeurIPS 2023
- **Self-Refine: Iterative Refinement with Self-Feedback** -- Aman Madaan, Niket Tandon, Prakhar Gupta, Skyler Hallinan, Luyu Gao, Sarah Wiegreffe, Uri Alon, Nouha Dziri, Shrimai Prabhumoye, Yiming Yang, Sean Welleck, Bodhisattwa Prasad Majumder, Shashank Gupta, Amir Yazdanbakhsh, Peter Clark (2023)
  - arXiv: [2303.17651](https://arxiv.org/abs/2303.17651)

## 核心思想

ReAct 循环（[2.1 节](./2.1-ReAct模式.md)）的 Agent 每步都能看到 Observation，但不会系统地思考"我从刚才的错误中学到了什么？"。Reflexion 的核心洞察是：**引入一个显式的反思环节，将执行过程中的经验教训提炼为结构化记忆，在后续决策中加以利用。**

```
ReAct:         Thought → Action → Obs → Thought → Action → Obs ...

Reflexion:     Thought → Action → Obs → Reflection → 
               Memory Update → 
               Thought → Action → Obs → Reflection → ...
                                        ↑
               Agent 停下来反思：刚才哪里做错了？这个教训存入记忆，
               下次不再犯同样的错误。
```

### 人类类比

就像一个程序员 debug：先尝试修复（Action），观察结果（Observation），如果修复失败，反思为什么失败（Reflection），将原因记在笔记中（Memory），下次修复时参考笔记不再犯同样错误。

## 三组件架构

Reflexion Agent 由三个核心组件构成：

```
┌────────────────────────────────────────────────────────┐
│                   Reflexion Agent                        │
├────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────────┐              ┌──────────────────┐     │
│  │   Actor      │  ──执行──→   │    Environment    │     │
│  │  (LLM+Tools) │  ←──观察──   │  (任务环境+工具)  │     │
│  └──────┬───────┘              └──────────────────┘     │
│         │                                                       │
│         │ 失败/完成时触发                                         │
│         ▼                                                       │
│  ┌──────────────┐              ┌──────────────────┐     │
│  │   Evaluator  │  ──评估──→   │  Actor 的表现     │     │
│  │  (LLM/规则)  │  ←──结果──   │  (成功/失败/错误) │     │
│  └──────┬───────┘              └──────────────────┘     │
│         │                                                       │
│         │ 生成反思文本                                            │
│         ▼                                                       │
│  ┌──────────────┐                                             │
│  │   Memory     │  ←── 存储反思结果                              │
│  │  (经验池)    │  ──→ 注入 Actor 的上下文                       │
│  └──────────────┘                                             │
│                                                          │
└────────────────────────────────────────────────────────┘
```

### 组件详解

| 组件 | 角色 | 输入 | 输出 |
|------|------|------|------|
| **Actor** | 执行主体，与任务环境交互 | 任务描述 + 记忆 + 当前状态 | 动作序列、中间结果 |
| **Evaluator** | 评估 Actor 的输出质量 | Actor 的执行轨迹 + 任务目标 | 成功/失败判定 + 错误原因 |
| **Memory** | 存储和检索反思经验 | 反思文本（来自 Evaluator） | 与当前任务最相关的历史教训 |

### 三个组件的协作流程

```
1. Actor 在任务环境中运行，通常使用 ReAct 循环
2. 任务完成或 Actor 失败时，Evaluator 分析执行轨迹
3. Evaluator 输出反思文本（自然语言），描述：
   - 哪里出了问题
   - 根本原因是什么
   - 下次应该如何改进
4. 反思文本被存入 Memory（短期记忆 → 长期记忆）
5. 下一轮任务开始时，Memory 中的相关反思被注入 Actor 的上下文
6. Actor 带着历史经验再次尝试，避免重复犯错
```

## 具体示例：代码生成 Agent

用户要求：*"编写一个 Python 函数，读取 CSV 文件并按指定列排序。"*

### 第 1 轮尝试（无反思记忆）

```
Actor 第 1 轮：
  Thought: 我需要写一个读取 CSV 并排序的函数。用 pandas 应该很简单。
  Action: write_file("sort_csv.py", "...使用 pandas.read_csv 和 sort_values...")
  Evaluation: 函数运行报错 "FileNotFoundError"——没有检查文件是否存在。
  
Evaluator 反思：
  "我犯了一个错误：没有做输入验证就直接读取文件。CSV 文件可能不存在、
   路径可能错误、用户可能没有读取权限。下次任何涉及文件操作的函数，
   都需要先检查文件存在性和可读性。"

Memory 存储: [经验 #1] 文件操作必须先验证输入 → 存入长期记忆
```

### 第 2 轮尝试（带反思记忆）

```
Actor 第 2 轮（上下文包含记忆中的经验 #1）：
  Thought: 用户要求写 CSV 排序函数。根据之前的经验，我必须先验证
           文件存在性。
  Action: write_file("sort_csv.py", """
           import pandas as pd
           import os
           
           def sort_csv(filepath, column):
               # [经验] 先检查文件是否存在
               if not os.path.exists(filepath):
                   raise FileNotFoundError(f"文件不存在: {filepath}")
               if not os.access(filepath, os.R_OK):
                   raise PermissionError(f"无读取权限: {filepath}")
               
               df = pd.read_csv(filepath)
               if column not in df.columns:
                   raise ValueError(f"列 '{column}' 不存在")
               return df.sort_values(column)
           """)
  Evaluation: 函数运行成功，但排序没有指定 ascending 参数。
             默认是升序，用户可能想自定义排序方向。
  
Evaluator 反思：
  "虽然函数基本正确，但忽略了排序方向参数。函数签名应包含
   ascending 参数以提供灵活性。另外应该考虑对大型 CSV 文件的
   内存优化（分块读取）。"

Memory 存储: [经验 #2] 函数设计应预留常用参数，包括排序方向 → 存入长期记忆
            [经验 #1] 文件操作必须先验证输入（已存在，强化权重）
```

### 第 3 轮尝试（累积两条经验）

```
Actor 第 3 轮（上下文包含经验 #1 和 #2）：
  Thought: 这次要加入文件验证和 ascending 参数，还要考虑大文件。
  Action: write_file("sort_csv.py", """
           import pandas as pd
           import os
           
           def sort_csv(filepath, column, ascending=True, chunksize=None):
               # 输入验证
               if not os.path.exists(filepath):
                   raise FileNotFoundError(...)
               if not os.access(filepath, os.R_OK):
                   raise PermissionError(...)
               
               if chunksize:
                   # 大文件：分块排序后合并
                   chunks = []
                   for chunk in pd.read_csv(filepath, chunksize=chunksize):
                       chunk = chunk.sort_values(column, ascending=ascending)
                       chunks.append(chunk)
                   return pd.concat(chunks).sort_values(column, ascending=ascending)
               else:
                   df = pd.read_csv(filepath)
                   return df.sort_values(column, ascending=ascending)
           """)
  Evaluation: 函数运行完全正确，包含了所有需要的特性。
  
  任务完成！共经过 3 轮 Reflexion 循环。
```

这个例子展示了 Reflexion 的核心优势：**Agent 不是简单地重试，而是每次失败后都有结构性改进**。三轮后的代码质量远超第一轮。

## 记忆系统设计

Reflexion 的记忆系统决定了反思经验能否被有效复用。Shinn et al. 提出了两种记忆类型：

### 短期记忆（Episodic Buffer）

```
存储当前任务执行过程中的即时经验。
任务完成后，有价值的经验会被转移至长期记忆。

特点: 每个新任务开始时清空，只保留最近的执行轨迹。
```

### 长期记忆（Long-term Memory）

```
存储跨任务可复用的经验教训。

每条记录结构:
{
  "id": "exp_001",
  "timestamp": "2024-01-15T10:30:00",
  "task_type": "csv_processing",
  "error_pattern": "input_validation",
  "reflection": "文件操作必须先检查存在性和可读性",
  "success_rate": 0.85,         # 该经验的应用成功率
  "weight": 2.3,                 # 经验权重（成功应用会提升）
  "source_trace": "sort_csv() 第1轮"  # 来源轨迹（用于追溯）
}

检索策略: 根据当前任务的类型标签匹配，返回 top-K 条相关经验。
```

```python
class ReflexionMemory:
    def __init__(self, max_long_term=100):
        self.episodic_buffer = []    # 短期记忆：当前任务轨迹
        self.long_term_memory = []   # 长期记忆：跨任务经验
        self.max_long_term = max_long_term
    
    def add_reflection(self, reflection: str, task_type: str, trace: list):
        """将反思添加到长期记忆"""
        entry = {
            "reflection": reflection,
            "task_type": task_type,
            "source_trace": trace[-3:],  # 只保留最近 3 步轨迹
            "timestamp": time.now(),
            "weight": 1.0,
            "success_count": 0
        }
        self.long_term_memory.append(entry)
        # 如果超过容量，淘汰权重最低的经验
        if len(self.long_term_memory) > self.max_long_term:
            self.long_term_memory.sort(key=lambda x: x["weight"])
            self.long_term_memory.pop(0)
    
    def retrieve(self, task_type: str, top_k: int = 3) -> list[str]:
        """检索与当前任务最相关的反思经验"""
        candidates = [
            e for e in self.long_term_memory
            if self._similar_task_type(e["task_type"], task_type)
        ]
        # 按权重排序
        candidates.sort(key=lambda x: x["weight"], reverse=True)
        return [c["reflection"] for c in candidates[:top_k]]
    
    def update_weight(self, reflection_id: str, success: bool):
        """根据应用结果更新经验权重"""
        for entry in self.long_term_memory:
            if entry["id"] == reflection_id:
                if success:
                    entry["weight"] *= 1.1   # 成功提升权重
                    entry["success_count"] += 1
                else:
                    entry["weight"] *= 0.9   # 失败降低权重
                break
```

### 记忆检索的关键问题

1. **相关性匹配**：如何判断历史经验与当前任务相关？Shinn et al. 使用任务描述的 embedding 相似度。简单实现可用关键词重叠或 LLM 判断。
2. **注入时机**：经验应该在每个 ReAct 循环开始前注入，还是只在任务开始时注入？实践中，**在每轮新任务开始时批量注入**效果更稳定——中间注入可能打乱 Agent 当前的推理流。
3. **经验数量上限**：注入过多记忆会占据上下文窗口。典型做法是按权重取 top-3 到 top-5 条。

## Evaluator 的设计

Evaluator 是 Reflexion 的"老师"，它决定了 Agent 能从错误中学到什么。有三种常见实现策略：

### 策略对比

| 策略 | 实现方式 | 优点 | 缺点 |
|------|----------|------|------|
| **硬规则** | 代码检查：是否报错、是否超时、输出格式是否匹配 | 确定性强、零成本 | 只能检查表面正确性 |
| **LLM 评判** | 让 LLM 评估输出质量并给出改进建议 | 灵活、可评估语义正确性 | 成本高、可能产生幻觉 |
| **外部反馈** | 单元测试、用户反馈、真值标签 | 最可靠 | 需要预先准备评判标准 |

### LLM 评判器实现

```python
class LLMEvaluator:
    def __init__(self, llm):
        self.llm = llm
    
    def evaluate(self, task: str, trajectory: list[dict], 
                 final_output: str) -> EvaluationResult:
        """评估 Actor 的执行轨迹并生成反思"""
        prompt = f"""你是一个严格的导师。评估以下 Agent 的任务执行情况。

任务: {task}

执行轨迹:
{self._format_trajectory(trajectory)}

最终输出:
{final_output}

请分析：
1. 任务是否成功完成？(success/failure/partial)
2. 如果失败，根本原因是什么？
3. 从这次执行中可以总结出什么经验教训，以避免未来重蹈覆辙？
4. 给出具体的改进建议。

以 JSON 格式输出。
"""
        response = self.llm.generate(prompt)
        result = json.loads(response.content)
        
        return EvaluationResult(
            status=result["status"],
            root_cause=result.get("root_cause", ""),
            reflection=result.get("reflection", ""),
            suggestions=result.get("suggestions", [])
        )
```

## ReAct vs. Reflexion vs. Self-Refine 对比

| 维度 | ReAct | Self-Refine | Reflexion |
|------|-------|-------------|-----------|
| **核心循环** | Thought→Action→Obs | Generate→Feedback→Refine | Act→Evaluate→Reflect→Memory |
| **反馈粒度** | 每步 Observation（外部环境） | 每轮输出后自我反馈 | 任务完成/失败后系统总结 |
| **记忆持久性** | 无（上下文窗口内） | 无（仅当前轮次） | 有（长期记忆跨任务） |
| **经验复用** | 无 | 无 | 有（同类任务直接受益） |
| **适用场景** | 单次交互任务 | 单次内容生成 | 需反复执行的同类任务 |
| **额外开销** | 无 | 每次迭代 2× LLM 调用 | 反思阶段的 LLM 调用 + 记忆存储 |

## 工程实现伪代码

```python
class ReflexionAgent:
    def __init__(self, llm, tools, evaluator=None, max_attempts=3):
        self.actor = ReActAgent(llm, tools)  # 复用 2.1 节的 ReAct Agent
        self.evaluator = evaluator or LLMEvaluator(llm)
        self.memory = ReflexionMemory()
        self.max_attempts = max_attempts
    
    def run(self, task: str) -> str:
        # 1. 从长期记忆中检索相关经验
        past_reflections = self.memory.retrieve(
            task_type=self._classify_task(task),
            top_k=3
        )
        
        # 2. 构建带反思上下文的系统提示
        system_prompt = self._build_prompt_with_reflections(
            task, past_reflections
        )
        
        for attempt in range(self.max_attempts):
            print(f"\n{'='*50}")
            print(f"[Reflexion] 第 {attempt + 1} 轮尝试")
            print(f"{'='*50}")
            
            # 3. Actor 执行任务
            trajectory = []  # 记录执行轨迹用于后续评估
            result = self.actor.run(
                task, 
                system_prompt=system_prompt,
                trajectory_callback=trajectory.append
            )
            
            # 4. Evaluator 评估结果
            evaluation = self.evaluator.evaluate(
                task=task,
                trajectory=trajectory,
                final_output=result
            )
            
            if evaluation.status == "success":
                print(f"[Reflexion] 任务成功完成！")
                # 成功经验也应记录，强化好的做法
                self.memory.add_reflection(
                    reflection=f"成功经验: {evaluation.reflection}",
                    task_type=self._classify_task(task),
                    trace=trajectory
                )
                return result
            
            # 5. 失败：生成反思并存入记忆
            print(f"[Reflexion] 失败原因: {evaluation.root_cause}")
            self.memory.add_reflection(
                reflection=evaluation.reflection,
                task_type=self._classify_task(task),
                trace=trajectory
            )
            
            # 6. 更新上下文，加入本轮反思
            system_prompt += f"\n\n## 前一次尝试的教训\n{evaluation.reflection}"
        
        # 达到最大尝试次数
        return f"经过 {self.max_attempts} 轮尝试后仍未成功。最终结果: {result}"
    
    def _build_prompt_with_reflections(self, task, reflections):
        prompt = f"任务: {task}\n\n"
        if reflections:
            prompt += "## 历史经验（请务必参考）\n"
            for i, ref in enumerate(reflections, 1):
                prompt += f"{i}. {ref}\n"
        return prompt
    
    def _classify_task(self, task: str) -> str:
        """对任务分类，用于记忆中检索匹配的经验"""
        # 简单实现：关键词匹配
        keywords = {
            "code": ["编写", "代码", "函数", "实现", "编程"],
            "data": ["数据", "分析", "CSV", "数据库", "查询"],
            "search": ["搜索", "查找", "调研", "研究"],
        }
        for category, kws in keywords.items():
            if any(kw in task for kw in kws):
                return category
        return "general"
```

## Token 成本分析

Reflexion 相比纯 ReAct 增加了 Evaluator 的额外开销：

```
单项任务，假设 3 轮 Reflexion，每轮 4 个 ReAct 子步骤：

成本构成:
  ├── 第 1 轮（4 步 ReAct）:
  │    ReAct: 4 × (150+50+300) = 2,000 tokens
  │    Evaluation: 500 tokens
  │    小计: 2,500 tokens
  ├── 第 2 轮（4 步 ReAct + 记忆注入）:
  │    ReAct: 4 × (150+50+300) = 2,000 tokens
  │    Evaluation: 500 tokens
  │    记忆注入: ~100 tokens (经验文本)
  │    小计: 2,600 tokens
  ├── 第 3 轮（4 步 ReAct + 更多记忆）:
  │    同上: ~2,700 tokens
  └── 总计: ~7,800 tokens

对比:
  - 纯 ReAct（4 步，一次性成功）: 2,000 tokens
  - ReAct + 人工重试 3 次: 6,000 tokens（但不系统）
  - Reflexion 3 轮: 7,800 tokens（系统性改进）

Reflexion 的额外开销（约 30%）换来了结构性改进和跨任务经验复用。
在多任务（10+ 同类任务）场景下，后续任务的成本会显著降低，
因为记忆中的经验减少了试错次数。
```

## 关键概念速查表

| 概念 | 定义 | 要点 |
|------|------|------|
| **Actor** | 执行任务的主体 | 通常基于 ReAct 循环；与环境交互生成轨迹 |
| **Evaluator** | 评估 Actor 表现并生成反思 | 可用硬规则、LLM评判或外部反馈；输出根因分析和改进建议 |
| **短期记忆 (Episodic Buffer)** | 当前任务执行轨迹的临时存储 | 任务完成后清空；用于 Evaluator 分析 |
| **长期记忆 (Long-term Memory)** | 跨任务复用的经验教训库 | 每条记录含 reflection + task_type + weight；需管理容量和淘汰策略 |
| **反思 (Reflection)** | 对失败原因的自然语言总结 | Refine: "我忽略了什么" vs. Retrospect: "我应该怎么做" |
| **经验权重** | 每条长期记忆的重要性分数 | 成功应用时提升，失败时降低；影响检索排序 |
| **记忆检索** | 从长期记忆中召回相关经验 | 按任务类型匹配；Top-K 注入 Actor 上下文；K 通常为 3-5 |
