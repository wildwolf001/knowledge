# 15.4 Few-shot 的放大效应

> 在受控解码场景下，Few-shot 示例的效果被显著放大。1-2 个精心设计的示例，对受控解码的准确率提升幅度（通常 10-20%）远大于对非受控解码的提升（通常 2-5%）。这一发现被称为 **Few-shot 的放大效应（Amplification Effect）**。本章揭示其背后的机制、最佳实践和工程实现。

---

## 一、发现：示例在受控解码下效果更好

### 1.1 现象描述

RANLP 2025 论文以及后续的多项研究都观察到了同一个现象：在约束解码场景下，Few-shot 示例的效果显著优于非约束场景。

```
实验条件：信息提取任务，同一模型（Qwen2.5-7B-Instruct）

非约束解码（自由生成后解析）：
  Zero-shot：准确率 72.3%
  One-shot：  准确率 74.8%  (+2.5%)
  Two-shot：  准确率 76.1%  (+3.8%)

约束解码（Outlines JSON Schema 强制）：
  Zero-shot：准确率 65.1%  （比非约束还低！见 15.3 节）
  One-shot：  准确率 78.4%  (+13.3%！)
  Two-shot：  准确率 82.7%  (+17.6%！！)
```

**关键观察**：
1. 约束解码的 Zero-shot 效果低于非约束解码——与 15.3 节的退化发现一致
2. 加入 1-2 个示例后，约束解码的效果**反超**了非约束解码
3. 示例对约束解码的提升幅度（13-18%）是对非约束解码（2-4%）的 **4-5 倍**

### 1.2 为什么这叫"放大效应"？

放大效应的本质是：**相同数量的示例，在约束解码场景下产生了更大的边际效益**。

```
示例数量 vs 准确率提升（斜率 = 边际效益）：
非约束：72% → 75% → 76%  （斜率 ~2%/example）
约束：  65% → 78% → 83%  （斜率 ~9%/example）

约束解码的边际效益是非约束解码的 4.5 倍！
```

## 二、放大效应的三大机制

### 2.1 机制一：格式-内容联合学习

在非约束场景下，Free-shot 示例主要提供了**内容层面的信号**——告诉模型"什么样的回答是好回答"。

在约束场景下，示例同时提供了两个信号：
- **格式信号**：'{"name": "...", "age": ...}'  这种格式是合法的、期望的
- **内容信号**："张三"对应 name 字段，"28"对应 age 字段——字段-值的映射关系

```python
# 非约束场景：示例主要传递内容信号
example_non_constrained = """
输入：张三，28岁，北京
输出：姓名是张三，年龄28岁，居住在北京
"""

# 约束场景：示例同时传递格式信号和内容信号
example_constrained = """
输入：张三，28岁，北京
输出：{"name": "张三", "age": 28, "city": "北京"}
"""
```

在约束场景下，示例不仅告诉了模型"填什么"，还告诉了模型"怎么填"。这种双重信号产生了**协同效应**——模型同时学会了格式和内容的关联。

### 2.2 机制二：隐式约束内化

约束解码框架（Outlines、XGrammar）是在解码时"强制"模型遵守规则，是一种**外部约束**。模型本身并不理解为什么要输出 `{` 而不是直接开始说话。

Few-shot 示例起到了**内化**的作用：模型通过观察示例，将"外部强加的约束"转化为"自己理解的任务规则"。

```
外部约束（Outlines/XGrammar）：
  模型：为什么要输出 " ？我不理解，但框架强迫我这样选
  → 概率分布扭曲（见 15.3 节）

内化约束（通过 Few-shot 示例）：
  模型：哦，这个任务要求输出 JSON，" 是 JSON 字符串的开始
  → 模型主动按 JSON 格式生成，减少了概率扭曲

神经科学类比：
  外部约束 = 别人按住你的手写字（僵硬、不自然）
  内化约束 = 自己学会了写字（流畅、自然）
```

实证支持：论文分析了模型在约束解码下的 Attention 模式，发现：
- 无示例时，注意力集中在格式 token 上（'{"' 等）——**格式焦虑**
- 有示例时，注意力回归到语义 token 上——**任务理解优先**

### 2.3 机制三：分布对齐

第 15.3 节讨论了训练-推理分布不匹配：模型在自由文本下训练，在约束解码下推理。这导致了**分布偏移（Distribution Shift）**。

Few-shot 示例起到了**分布桥接**的作用：

```
训练分布（指令微调数据）：
  "好的，让我分析一下...最后结果是X。"

推理分布（约束解码初始状态）：
  {\n  "result": 

问题：模型处于未见过的状态空间中 → 行为不可预测

解决方案（Few-shot 示例）：
  在 prompt 中提供 {"result": "X"} 的示例
  → 模型看到"在这个任务中，输出应该是这种格式"
  → 将"未知状态"转化为"已知任务模式"
  → 分布偏移被"桥接"
```

直观理解：Few-shot 示例相当于告诉模型"我们现在玩一个 JSON 输出的游戏，规则是这样的"。没有这个"游戏说明"，模型只能猜规则，猜错的概率很高。

## 三、Few-shot 示例的最佳实践

### 3.1 示例数量：1-2 个足够

```
示例数 vs 准确率（约束解码，信息提取任务）：
0-shot:  65.1%
1-shot:  78.4%  (+13.3%)
2-shot:  82.7%  (+4.3%)
3-shot:  83.9%  (+1.2%)
4-shot:  84.2%  (+0.3%)
5-shot:  84.3%  (+0.1%)
```

**关键发现**：边际效益在 1-2 个示例时最高，之后急剧递减。2 个示例后，增加示例的收益微乎其微，但 token 成本线性增加。

**推荐**：约束解码场景下，1-2 个高质量示例即可获得大部分收益。

### 3.2 示例设计原则

并非任何示例都有效。高质量的约束解码示例需要满足以下条件：

```python
# 好的示例：展示格式 + 内容映射 + 边界情况
good_example = {
    "input": "张三，28岁，北京",
    "output": {
        "name": "张三",
        "age": 28,  # 数字类型
        "city": "北京"
    }
}

# 更好的示例：额外展示边界情况
better_example_1 = {
    "input": "张三，28岁，北京",
    "output": {
        "name": "张三",
        "age": 28,
        "city": "北京"
    }
}
better_example_2 = {
    "input": "信息不足，无法确定年龄",
    "output": {
        "name": None,   # 展示 null 处理
        "age": None,    # 展示缺失字段处理
        "city": None
    }
}
```

**示例设计原则**：

1. **展示格式**：让模型看到完整的 JSON 结构，包括引号、冒号、逗号、括号
2. **展示类型映射**：字符串、数字、布尔、null 各展示一次
3. **展示边界情况**：可选字段缺失时如何处理、空数组如何处理
4. **覆盖常见边缘场景**：长文本截断、特殊字符转义、嵌套结构

### 3.3 反模式：什么是不好的示例

```
不好的示例（只展示格式，不展示内容映射）：
示例输入：张三，28岁，北京
示例输出：{"name": "example", "age": 0, "city": "unknown"}

→ 模型学会了格式，但没学会"如何提取内容"
→ 实际输出：{"name": "example", "age": 0, "city": "unknown"}
→ 只是复制了示例中的内容，而不是从输入中提取
```

```
不好的示例（与 Schema 不一致）：
Schema: {"name": string, "age": integer, "city": string}
示例输出：{"name": "张三", "age": "二十八", "city": "北京"}

→ age 应该是 integer，但示例中用了字符串
→ 约束框架会强制 age 为数字，但模型倾向于学示例的字符串格式
→ 导致格式冲突，解码效率降低
```

## 四、放大效应的工程价值

### 4.1 成本效益分析

```
约束解码 + 2-shot 的额外成本：
- Prompt 增加约 200-500 token（一个示例）
- 解码延迟基本不变（约束框架的开销不变）
- 准确率从 65% 提升到 83%

不添加示例的隐性成本：
- 18% 的失败率需要重试
- 每次重试消耗 2-3 倍的推理成本
- 用户体验下降

结论：添加 2 个示例的成本远低于处理失败的隐形成本
```

### 4.2 动态示例选择

对于生产系统，推荐构建**动态示例库**：

```python
class DynamicExampleSelector:
    def __init__(self, example_pool, embedding_model):
        self.example_pool = example_pool  # 预构建的示例池
        self.embedder = embedding_model
    
    def select_examples(self, user_input, k=2):
        """根据用户输入选择最相关的示例"""
        # 将用户输入编码为向量
        input_embedding = self.embedder.encode(user_input)
        
        # 计算与每个示例输入的相关性
        scored_examples = []
        for example in self.example_pool:
            example_embedding = self.embedder.encode(example["input"])
            similarity = cosine_similarity(input_embedding, example_embedding)
            scored_examples.append((similarity, example))
        
        # 选择最相关的 k 个示例
        scored_examples.sort(reverse=True, key=lambda x: x[0])
        return [ex for _, ex in scored_examples[:k]]
    
    def add_success_case(self, user_input, output):
        """将成功的生成案例加入示例池"""
        self.example_pool.append({
            "input": user_input,
            "output": output
        })
```

这种方法的优势：
- 每次选择与当前输入最相关的示例，而不是固定示例
- 示例池可以从历史成功案例中持续扩展
- 相比固定示例，动态选择可额外提升 2-5% 的准确率

### 4.3 与 Schema 设计协同

Few-shot 示例的有效性还与 Schema 设计密切相关（详见 15.5 节）：

```python
def build_prompt_with_examples(user_input, schema, example_selector):
    """构建包含 Schema 和示例的 Prompt"""
    examples = example_selector.select_examples(user_input, k=2)
    
    prompt_parts = [
        "根据输入提取以下格式的信息：",
        f"Schema: {schema}",
        "",
        "示例：",
    ]
    
    for i, example in enumerate(examples, 1):
        prompt_parts.append(f"示例 {i}:")
        prompt_parts.append(f"输入：{example['input']}")
        prompt_parts.append(f"输出：{json.dumps(example['output'], ensure_ascii=False)}")
        prompt_parts.append("")
    
    prompt_parts.append(f"输入：{user_input}")
    prompt_parts.append("输出：")
    
    return "\n".join(prompt_parts)
```

## 五、与 14.6 节的联系

14.6 节提出的"约束生成的代价"中，一个核心观点是"训练-推理分布不匹配"。15.4 节的放大效应本质上解决了这个问题：

| 14.6 的问题 | 15.4 的解决方案 |
|------------|---------------|
| 训练在自由文本，推理在约束空间 → 分布不匹配 | Few-shot 示例将模型从"未见过的空间"拉到"已知任务模式" |
| 模型不理解为什么被约束 → 概率扭曲 | 示例让模型"内化"约束 → 减少概率扭曲 |
| 约束解码下 0-shot 效果差 | 1-2 个示例即可大幅提升效果 |

**核心结论**：如果你计划使用受控解码，**务必提供 1-2 个高质量的 Few-shot 示例**。这不只是"锦上添花"，而是"雪中送炭"——没有示例时，受控解码的效果可能比自由解码还差。
