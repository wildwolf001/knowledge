# 15.5 Schema 优化 —— PARSE：让 LLM 自己优化 JSON Schema

> 结构化输出的质量不仅取决于解码框架，还取决于 JSON Schema 本身的设计。同样的 LLM、同样的任务、不同的 Schema，准确率可能相差 20% 以上。PARSE（Progressive Adaptation for Reliable Schema Extraction）是一种让 LLM 自动优化 Schema 的方法，在论文报告中实现了提取准确率 +64.7%、错误率 -92% 的显著提升。本章解析其工作原理。

---

## 一、问题：Schema 设计对提取质量的影响

### 1.1 Schema 不是中性的

许多开发者将 JSON Schema 视为一个中性的"格式模板"——只要合法，什么 Schema 都一样。但研究发现，Schema 的设计直接影响 LLM 的提取质量：

```
同一模型（Qwen2.5-7B-Instruct）、同一输入文本
不同 Schema 的提取准确率：

Schema A（简单平铺）：
{
  "type": "object",
  "properties": {
    "name": {"type": "string"},
    "age": {"type": "integer"},
    "city": {"type": "string"}
  }
}
→ 准确率 87.3%

Schema B（描述丰富）：
{
  "type": "object",
  "properties": {
    "name": {"type": "string", "description": "人物姓名"},
    "age": {"type": "integer", "description": "人物年龄"},
    "city": {"type": "string", "description": "所在城市"}
  }
}
→ 准确率 91.5%  (+4.2%)

Schema C（字段顺序错乱 + 描述模糊）：
{
  "type": "object",
  "properties": {
    "city": {"type": "string", "description": "age info"},
    "name": {"type": "string", "description": "details"},
    "age": {"type": "integer", "description": "city info"}
  }
}
→ 准确率 71.8%  (-15.5%!)
```

**核心问题**：Schema 向 LLM 传递了两种信号——结构信号（字段名、类型）和语义信号（字段描述、顺序、上下文）。不好的 Schema 会混淆模型，好的 Schema 能引导模型更准确地提取信息。

### 1.2 手工优化 Schema 的挑战

理论上，开发者可以手工优化 Schema，但面临三个问题：

1. **工作量巨大**：一个复杂的 Agent 系统可能有数十到数百个 Schema，每个都需要手工调优
2. **缺乏反馈**：Schema 优化依赖格式正确率和内容准确率的反馈，手工模式难以系统化
3. **动态性**：任务场景变化时，最优 Schema 也会变化，需要持续优化

PARSE 正是在此背景下提出的解决方案。

## 二、PARSE 的工作原理

### 2.1 整体流程

PARSE（Progressive Adaptation for Reliable Schema Extraction）通过一个 **LLM-in-the-loop** 的迭代优化过程，让 LLM 自身参与 Schema 的改进：

```
┌────────────────────────────────────────────────┐
│                 PARSE 流程                        │
│                                                   │
│  初始 Schema → 1. 生成样本 → 2. 评估质量          │
│                     ↑                ↓            │
│                     │    3. LLM 提供优化建议      │
│                     │         ↓                   │
│                     └── 4. 更新 Schema ──────────┘│
│                                                   │
│  5. 迭代直到收敛 → 最终优化 Schema                │
└────────────────────────────────────────────────┘
```

### 2.2 五步详解

**步骤 1：样本生成（Sample Generation）**

PARSE 将 Schema 应用到一组**验证输入**上，生成 LLM 的结构化提取结果：

```python
def generate_samples(schema, validation_inputs, llm):
    """使用当前 Schema 在验证集上生成提取结果"""
    results = []
    for input_text in validation_inputs:
        output = constrained_generate(
            prompt=f"从以下文本提取信息：{input_text}",
            schema=schema,
            llm=llm
        )
        results.append({
            "input": input_text,
            "output": output,
            "schema": schema
        })
    return results
```

**步骤 2：质量评估（Quality Evaluation）**

对生成的样本进行自动化评估，计算两个核心指标：

- **格式正确率**：是否符合 Schema 的语法要求
- **内容准确率**：提取的值是否正确（需要有标注的 ground truth 或 LLM-as-judge）

```python
def evaluate_samples(samples, ground_truths):
    """评估样本质量"""
    metrics = {
        "format_accuracy": 0,
        "content_accuracy": 0,
        "field_level_errors": {},
        "error_patterns": []
    }
    
    for sample, gt in zip(samples, ground_truths):
        # 格式检查
        try:
            validate(sample["output"], sample["schema"])
            metrics["format_accuracy"] += 1
        except SchemaValidationError as e:
            metrics["error_patterns"].append(e.pattern)
        
        # 内容检查
        for field, expected in gt.items():
            actual = sample["output"].get(field)
            if actual != expected:
                metrics["field_level_errors"][field] = \
                    metrics["field_level_errors"].get(field, 0) + 1
            else:
                metrics["content_accuracy"] += 1
    
    return metrics
```

**步骤 3：LLM 生成优化建议（LLM-based Optimization）**

这是 PARSE 的核心创新。将评估结果反馈给一个 LLM（可以是同一个模型或更强的模型），让 LLM 提出 Schema 的改进建议：

```python
def llm_optimize_schema(current_schema, metrics, error_examples, llm):
    """让 LLM 根据评估结果优化 Schema"""
    
    optimization_prompt = f"""
    你是一个 JSON Schema 优化专家。基于以下信息，请优化当前 Schema：
    
    当前 Schema：
    {json.dumps(current_schema, indent=2)}
    
    评估结果：
    - 格式正确率：{metrics['format_accuracy']:.1%}
    - 内容准确率：{metrics['content_accuracy']:.1%}
    - 高频错误字段：{metrics['field_level_errors']}
    
    错误示例：
    {json.dumps(error_examples[:3], ensure_ascii=False, indent=2)}
    
    优化规则：
    1. 字段描述要清晰、具体
    2. 常用含义的字段放在前面
    3. 添加约束（如 pattern, enum）来提高精度
    4. 避免过度复杂的嵌套结构
    
    请输出优化后的完整 JSON Schema：
    """
    
    optimized = llm.generate(optimization_prompt)
    return json.loads(optimized)
```

**步骤 4：Schema 更新（Schema Update）**

将优化后的 Schema 应用到提取流程中：

```python
def update_schema(schema_pool, current_schema, optimized_schema, metrics):
    """更新 Schema，保留历史版本用于回退"""
    schema_pool.append({
        "schema": optimized_schema,
        "parent": current_schema,
        "metrics": metrics,
        "timestamp": now()
    })
    return optimized_schema
```

**步骤 5：迭代收敛（Iterative Convergence）**

重复步骤 1-4，直到 Schema 质量不再明显提升：

```python
def parse_optimize(initial_schema, validation_inputs, ground_truths, llm, max_iterations=10):
    """PARSE 主循环"""
    schema = initial_schema
    history = []
    
    for i in range(max_iterations):
        # 生成与评估
        samples = generate_samples(schema, validation_inputs, llm)
        metrics = evaluate_samples(samples, ground_truths)
        
        history.append({"schema": schema, "metrics": metrics})
        
        # 收敛检查
        if len(history) >= 2:
            improvement = metrics["content_accuracy"] - history[-2]["metrics"]["content_accuracy"]
            if improvement < 0.01:  # 提升小于 1% 时收敛
                break
        
        # LLM 优化
        error_examples = find_error_cases(samples, ground_truths)
        schema = llm_optimize_schema(schema, metrics, error_examples, llm)
    
    return schema, history
```

### 2.3 为什么 PARSE 有效？

PARSE 之所以效果显著，是因为它解决了 Schema 设计的三个关键问题：

**问题 1：描述模糊性**

LLM 定义 Schema 时，可以从生成结果的反向传播中"理解"哪些描述有帮助。例如，如果"人物姓名"比"name_desc"的描述准确率高 10%，LLM 会在下一轮选择更清晰的描述。

**问题 2：字段顺序与语义一致性**

LLM 在解析 JSON 时，字段顺序会影响注意力分布。PARSE 通过实验发现：**语义相关的字段放在一起**比**按字母顺序排列**的提取准确率高。

```
优化前的 Schema（字母顺序）：
{"properties": {"age": ..., "city": ..., "name": ...}}
→ 模型需要在"name"和"age"之间切换注意力上下文

优化后的 Schema（语义分组）：
{"properties": {"name": ..., "age": ..., "city": ...}}
→ 模型按"人 → 人物属性"的自然顺序提取
```

**问题 3：约束粒度的平衡**

过度宽松的约束导致格式错误多，过度严格的约束导致生成失败。PARSE 通过迭代找到最优的约束粒度：

```
Schema 约束粒度搜索过程：
第1轮：{"age": {"type": "integer"}}
       → 错误：模型可能输出 "28岁"（字符串）

第2轮：{"age": {"type": "integer", "description": "年龄数字，不要包含单位"}}
       → 改进：大部分输出正确

第3轮：{"age": {"type": "integer", "description": "年龄数字", "minimum": 0, "maximum": 150}}
       → 最佳：约束了范围，进一步减少异常值
```

## 三、实验结果

### 3.1 核心指标

根据 PARSE 论文在多个基准上的报告：

| 指标 | 初始 Schema | PARSE 优化后 | 提升 |
|------|-----------|------------|------|
| **提取准确率** | 48.3% | **79.5%** | **+64.7%** |
| **错误率** | 39.1% | **3.1%** | **-92.1%** |
| **字段完整率** | 72.6% | **94.8%** | +30.6% |
| **格式正确率** | 88.4% | **98.2%** | +11.1% |
| **平均所需轮数** | — | **4.2 轮** | — |

> 注：提取准确率是严格的精确匹配——所有字段值完全正确。这个指标在初始 Schema 下较低是因为包含了许多"基本正确但有小错误"的案例。

### 3.2 不同 Schema 初始化的影响

PARSE 的效果与初始 Schema 的质量有关：

| 初始 Schema 质量 | 初始准确率 | 优化后准确率 | 提升幅度 |
|-----------------|-----------|------------|---------|
| 手工设计（高质量） | 72.4% | 87.6% | +21.0% |
| 自动生成（中等） | 54.7% | 79.1% | +44.6% |
| 最小化（仅字段名） | 38.2% | 73.5% | +92.4% |

**发现**：初始 Schema 质量越差，PARSE 的改进空间越大。即使初始 Schema 已经过手工优化，PARSE 仍然能带来显著提升。

### 3.3 跨模型泛化能力

PARSE 优化后的 Schema 是否只对原模型有效？论文测试了迁移性：

```
在 Qwen2.5-7B 上优化的 Schema，迁移到其他模型的效果：

目标模型                 准确率（原模型 Schema）  准确率（PARSE Schema）  提升
──────────────────────────────────────────────────────────
Qwen2.5-7B (原模型)      72.4%                   87.6%              +15.2%
Qwen2.5-72B             78.1%                   88.3%              +10.2%
Llama-3-8B              65.3%                   79.4%              +14.1%
GPT-4o-mini             82.7%                   90.1%              +7.4%
──────────────────────────────────────────────────────────
```

**结论**：PARSE 优化的 Schema 具有较好的跨模型泛化能力，可以在不同模型间迁移使用。这意味着你可以用小模型做 Schema 优化，然后应用到生产环境的大模型上。

### 4.1 离线优化 + 在线部署

推荐将 PARSE 作为离线流程，而非在线实时优化：

```python
# 生产部署架构

# 阶段1（离线）：使用 PARSE 优化 Schema
def offline_schema_optimization():
    validation_set = load_validation_data()  # 500-1000 条带标注的训练数据
    initial_schema = load_initial_schema()
    
    optimized_schema = parse_optimize(
        initial_schema=initial_schema,
        validation_inputs=validation_set.inputs,
        ground_truths=validation_set.outputs,
        llm=llm_model
    )
    
    save_to_schema_registry(optimized_schema)
    return optimized_schema

# 阶段2（在线）：使用优化后的 Schema 进行约束解码
def online_extraction(user_input):
    schema = load_from_schema_registry(task_type(user_input))
    
    result = constrained_generate(
        prompt=build_prompt(user_input, schema),
        schema=schema,
        llm=production_model
    )
    
    return result
```

### 4.2 Schema 版本管理

随着业务变化，Schema 也需要持续更新。建议建立 Schema 版本管理机制：

```python
class SchemaRegistry:
    def __init__(self):
        self.versions = {}  # task_type -> [schema_v1, schema_v2, ...]
        self.metrics = {}   # task_type -> [(version, metrics), ...]
    
    def register(self, task_type, schema, metrics):
        if task_type not in self.versions:
            self.versions[task_type] = []
            self.metrics[task_type] = []
        
        version_id = len(self.versions[task_type])
        self.versions[task_type].append({
            "id": version_id,
            "schema": schema,
            "timestamp": now()
        })
        self.metrics[task_type].append((version_id, metrics))
    
    def get_best_schema(self, task_type):
        """获取历史中效果最好的 Schema"""
        best_version = max(
            self.metrics[task_type],
            key=lambda x: x[1]["content_accuracy"]
        )[0]
        return self.versions[task_type][best_version]["schema"]
    
    def rollback(self, task_type, version_id):
        """回滚到指定版本"""
        current = self.versions[task_type][-1]
        target = self.versions[task_type][version_id]
        
        if current["schema"] != target["schema"]:
            self.versions[task_type].append(target)
            return target["schema"]
        return current["schema"]
```

### 4.3 与 15.4 节 Few-shot 的协同

PARSE 优化的 Schema 和 15.4 节的 Few-shot 示例可以协同使用：

| 组件 | 作用 | 协同效果 |
|-----|------|---------|
| PARSE 优化的 Schema | 字段级别优化（名称、描述、约束） | Schema 更清晰 → 示例生成更准确 |
| Few-shot 示例 | 实例级别引导（格式+内容映射） | 示例更典型 → Schema 优化更有针对性 |

两者结合可以进一步提升效果：

```
单独使用：PARSE Schema (+15%) 或 Few-shot (+18%)
组合使用：PARSE Schema + Few-shot（+28%）
→ 协同效应优于各自独立效果之和
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| PARSE | Progressive Adaptation for Reliable Schema Extraction，一种让 LLM 迭代优化 Schema 的方法 |
| Schema 语义信号 | 字段名、描述、顺序等向 LLM 传递的提取指导信息 |
| 约束粒度 | Schema 中约束条件的严格程度，过松或过严都会影响提取质量 |
| LLM-in-the-loop | 将 LLM 作为流程中的"智能体"参与 Schema 优化的设计模式 |
| 收敛 | Schema 质量不再显著提升时停止迭代的状态 |
| 跨模型泛化 | 在一个模型上优化的 Schema 迁移到其他模型时仍有效的能力 |
