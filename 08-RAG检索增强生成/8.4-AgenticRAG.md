# 8.4 Agentic RAG

> Agentic RAG（智能体 RAG）是经典 RAG 的进化形态——不再是被动的"单轮检索→生成"，而是让 Agent 主动管理检索过程：多步推理、自我纠错、查询重写、工具调用。Agentic RAG 将 RAG 从"一个检索步骤"升级为"一个完整的检索推理循环"。

---

## 一、经典 RAG 的局限性

### 1.1 单轮检索的根本问题

经典 RAG 的范式是：**用户提问 → 检索一次 → 生成回答**。这种"一次性交互"存在四个结构性问题：

| 问题 | 描述 | 示例 |
|------|------|------|
| **查询表达能力不足** | 用户的原始查询可能过于宽泛或模糊，导致检索结果不相关 | 问"AI芯片"但实际想知道"NVIDIA和AMD的竞争格局" |
| **信息碎片化** | 答案可能需要多个来源的信息拼凑，一次检索无法覆盖 | "比较RAG和微调的优缺点"需要知道两者的技术细节 |
| **检索失败无反馈** | 如果第一次检索结果不相关，没有纠正机制 | 检索到"AI芯片的工作原理"而非"市场份额" |
| **缺乏上下文推理** | Agent 无法根据已检索到的内容决定下一步需要什么 | 检索到"2024年收入"后，自然应该检索"2023年收入"进行对比 |

### 1.2 从线性到循环

```
经典 RAG (线性)：
  用户 → 检索1次 → 生成 → 结束

Agentic RAG (循环)：
  用户 → 检索 → 推理 → 判断结果?
         ↑               │
         └─── 不满足 ────┘
         (重写查询 → 重新检索)
               │
               ▼ 满足条件
             生成 → 结束
```

---

## 二、Agentic RAG 的四种核心能力

### 2.1 多步推理检索（Multi-step Reasoning Retrieval）

让 Agent 将复杂问题分解为多个子问题，对每个子问题分别检索：

```python
from openai import OpenAI
import json

class MultiStepRetriever:
    """多步推理检索器"""
    
    def __init__(self, model: str = "gpt-4o"):
        self.client = OpenAI()
        self.model = model
    
    def decompose_question(self, question: str) -> list[dict]:
        """将复杂问题拆解为检索子问题"""
        prompt = f"""请将以下问题拆解为需要检索的子问题列表。
每个子问题应该是一个独立的、可以检索的信息单元。

要求：
1. 子问题必须具体、可检索
2. 子问题之间可以有依赖关系
3. 输出 JSON 格式

问题: {question}

输出 JSON:
{{
  "sub_questions": [
    {{
      "id": 1,
      "question": "子问题1",
      "rationale": "为什么需要这个信息",
      "dependencies": []  // 依赖的子问题 ID
    }},
    ...
  ]
}}"""
        
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": "你是一个问题分解专家，将复杂问题拆解为可检索的子问题。"},
                {"role": "user", "content": prompt}
            ],
            response_format={"type": "json_object"},
            temperature=0.1
        )
        
        return json.loads(response.choices[0].message.content)["sub_questions"]
    
    def retrieve_with_decomposition(self, question: str, retriever) -> list[str]:
        """分解问题并逐步检索"""
        sub_questions = self.decompose_question(question)
        
        # 确定执行顺序（拓扑排序）
        executed = set()
        all_chunks = []
        
        while len(executed) < len(sub_questions):
            for sq in sub_questions:
                if sq["id"] in executed:
                    continue
                deps = set(sq.get("dependencies", []))
                if deps.issubset(executed):
                    # 检索当前子问题
                    print(f"  [Retrieve] Sub-Q{sq['id']}: {sq['question']}")
                    chunks = retriever.search(sq["question"], top_k=3)
                    all_chunks.extend(chunks)
                    executed.add(sq["id"])
        
        # 去重并返回
        seen = set()
        unique_chunks = []
        for chunk in all_chunks:
            if chunk["text"] not in seen:
                seen.add(chunk["text"])
                unique_chunks.append(chunk)
        
        return unique_chunks


# 使用示例
question = "对比分析NVIDIA和AMD在2024年AI芯片市场的表现"

agent = MultiStepRetriever()
# 自动拆解为：
# 1. 2024年NVIDIA在AI芯片市场的表现（收入、份额、产品）
# 2. 2024年AMD在AI芯片市场的表现（收入、份额、产品）
# 3. 两者的对比分析框架

results = agent.retrieve_with_decomposition(question, pipeline)
```

### 2.2 查询重写（Query Rewriting）

用户的原始查询往往不适合直接用于向量检索。Agent 可以在检索前重写查询，使其更适合检索：

```python
class QueryRewriter:
    """查询重写引擎"""
    
    def rewrite(self, original_query: str, context: str = None) -> dict:
        """
        将用户查询重写为适合检索的形式
        
        返回多种重写策略的结果
        """
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": self._get_rewrite_prompt()},
                {"role": "user", "content": f"原始问题: {original_query}"}
            ],
            response_format={"type": "json_object"},
            temperature=0.3
        )
        
        return json.loads(response.choices[0].message.content)
    
    def _get_rewrite_prompt(self) -> str:
        return """你是一个查询重写专家。将用户的问题改写为更适合检索的形式。

## 重写策略
1. **去语境化**：移除代词/上下文依赖，使查询自包含
   - 原始: "它的收入是多少？" → "NVIDIA公司2024年Q4收入"
2. **查询扩展**：添加同义词和相关概念
   - 原始: "怎么治感冒" → "感冒 治疗 方法 药物 上呼吸道感染 临床处理"
3. **假设性文档**：假设有一篇理想文档的回答，直接陈述问题
   - 原始: "RAG怎么降低幻觉" → "RAG通过检索外部知识库提供事实依据来降低LLM幻觉的技术方法"
4. **子问题分解**：将复合问题拆解为多个简单查询
   - 原始: "比较Python和Java" → "Python语言特点 优势" + "Java语言特点 优势"

输出 JSON:
{
  "original": "原始问题",
  "rewrites": [
    {"strategy": "decontextualize", "query": "...", "rationale": "..."},
    {"strategy": "expansion", "query": "...", "rationale": "..."},
    {"strategy": "hypothetical", "query": "...", "rationale": "..."}
  ]
}"""
    
    def multi_strategy_search(self, original_query: str, retriever) -> list[dict]:
        """使用多种重写策略分别检索后合并结果"""
        rewrite_result = self.rewrite(original_query)
        
        all_results = []
        seen = set()
        
        # 用原始查询检索
        for r in retriever.search(original_query, top_k=5):
            if r["text"] not in seen:
                all_results.append(r)
                seen.add(r["text"])
        
        # 用每种重写策略检索
        for rewrite in rewrite_result["rewrites"]:
            for r in retriever.search(rewrite["query"], top_k=5):
                if r["text"] not in seen:
                    all_results.append(r)
                    seen.add(r["text"])
        
        return all_results
```

### 2.3 自我纠错（Self-Correction / Error Book）

检索结果可能不相关、不完整或相互矛盾。Agent 需要有自我纠错机制：

```python
class SelfCorrectiveRetriever:
    """自我纠错检索器"""
    
    def __init__(self, max_retries: int = 3):
        self.max_retries = max_retries
        self.error_book = []  # 错误记录簿
    
    def assess_retrieval_quality(self, query: str, retrieved_chunks: list[dict]) -> dict:
        """评估检索结果质量"""
        chunks_text = "\n\n".join([f"[{i+1}] {c['text'][:200]}" for i, c in enumerate(retrieved_chunks)])
        
        prompt = f"""评估以下检索结果是否充分回答了用户的查询。

查询: {query}

检索结果:
{chunks_text}

请分析：
1. 检索结果是否回答了查询的核心问题？(yes/no/partial)
2. 如果否，缺少什么关键信息？
3. 检索结果中存在矛盾吗？(yes/no)
4. 是否有检索结果是完全不相关的？

输出 JSON:
{{
  "sufficient": true/false,
  "missing_info": ["缺少的信息1", "缺少的信息2"],
  "irrelevant_chunks": [不相关块的索引],
  "contradictions": ["矛盾描述"],
  "suggestion": "如何改进检索的查询语句"
}}"""
        
        response = self.client.chat.completions.create(
            model="gpt-4o-mini",  # 质量评估用小模型即可
            messages=[
                {"role": "user", "content": prompt}
            ],
            response_format={"type": "json_object"},
            temperature=0.1
        )
        
        return json.loads(response.choices[0].message.content)
    
    def retrieve_with_self_correction(self, query: str, retriever, top_k: int = 10) -> list[dict]:
        """自我纠错检索循环"""
        
        for attempt in range(self.max_retries):
            print(f"  [Attempt {attempt + 1}/{self.max_retries}]")
            
            # 检索
            results = retriever.search(query, top_k=top_k)
            
            # 评估质量
            assessment = self.assess_retrieval_quality(query, results)
            
            if assessment["sufficient"]:
                print(f"  ✓ 检索质量满足要求")
                # 移除不相关的结果
                irrelevant_indices = assessment.get("irrelevant_chunks", [])
                results = [r for i, r in enumerate(results) if i not in irrelevant_indices]
                return results
            
            # 记录错误
            self.error_book.append({
                "attempt": attempt,
                "query": query,
                "assessment": assessment
            })
            
            # 根据评估改进查询
            query = self._improve_query(query, assessment)
            print(f"  → 改进查询: {query}")
        
        # 达到最大重试次数，返回当前最好结果
        return results
    
    def _improve_query(self, original_query: str, assessment: dict) -> str:
        """根据评估结果改进查询"""
        prompt = f"""根据检索结果评估，改进查询语句以获取更好的检索结果。

原始查询: {original_query}

评估结果:
- 缺少信息: {assessment.get('missing_info', [])}
- 改进建议: {assessment.get('suggestion', '')}

请生成一个改进后的检索查询:"""
        
        response = self.client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.3
        )
        
        return response.choices[0].message.content.strip()
```

## 三、完整的 Agentic RAG 循环

```python
class AgenticRAG:
    """完整的 Agentic RAG 循环"""
    
    def __init__(self, base_retriever, llm_model: str = "gpt-4o"):
        self.retriever = base_retriever
        self.llm_model = llm_model
        self.client = OpenAI()
        self.query_rewriter = QueryRewriter()
        self.self_corrector = SelfCorrectiveRetriever()
        self.multi_step = MultiStepRetriever()
        self.max_iterations = 5
    
    def run(self, question: str) -> dict:
        """
        主循环：Agentic RAG 的核心
        """
        print(f"\n{'='*60}")
        print(f"Agentic RAG 启动")
        print(f"问题: {question}")
        print(f"{'='*60}\n")
        
        # 状态跟踪
        context = {
            "question": question,
            "retrieved_chunks": [],
            "reasoning_history": [],
            "iteration": 0
        }
        
        while context["iteration"] < self.max_iterations:
            context["iteration"] += 1
            print(f"\n--- 第 {context['iteration']} 轮 ---")
            
            # Step 1: 推理 - 决定下一步做什么
            action = self._reason(context)
            print(f"  [Reason] 决定: {action['type']}")
            
            if action["type"] == "retrieve":
                # Step 2: 检索（含查询重写）
                query = action.get("query", question)
                results = self.retriever.search(query, top_k=5)
                context["retrieved_chunks"].extend(results)
                print(f"  [Retrieve] 查询: '{query}', 获取 {len(results)} 个结果")
                
            elif action["type"] == "self_correct":
                # Step 3: 自我纠错 - 改进查询
                query = action.get("improved_query")
                results = self.retriever.search(query, top_k=5)
                context["retrieved_chunks"].extend(results)
                context["reasoning_history"].append({
                    "type": "correction",
                    "reason": action.get("reason")
                })
                print(f"  [Correct] 改进查询: '{query}'")
                
            elif action["type"] == "decompose":
                # Step 4: 分解子问题
                sub_qs = self.multi_step.decompose_question(context["question"])
                for sq in sub_qs:
                    results = self.retriever.search(sq["question"], top_k=3)
                    context["retrieved_chunks"].extend(results)
                print(f"  [Decompose] 拆解为 {len(sub_qs)} 个子问题")
                
            elif action["type"] == "generate":
                # Step 5: 条件满足，生成回答
                return self._generate_answer(context)
            
            # 去重
            seen = set()
            deduped = []
            for chunk in context["retrieved_chunks"]:
                if chunk["text"] not in seen:
                    seen.add(chunk["text"])
                    deduped.append(chunk)
            context["retrieved_chunks"] = deduped
        
        # 达到最大轮次，强制生成
        return self._generate_answer(context)
    
    def _reason(self, context: dict) -> dict:
        """Agent 推理：根据当前状态决定下一步"""
        
        # 构建当前状态
        chunks_summary = ""
        for i, chunk in enumerate(context["retrieved_chunks"][-10:]):
            chunks_summary += f"[{i+1}] {chunk['text'][:150]}...\n"
        
        history_summary = ""
        for h in context["reasoning_history"][-3:]:
            history_summary += f"- {h.get('type', 'unknown')}: {h.get('reason', '')[:100]}\n"
        
        prompt = f"""你是 Agentic RAG 系统的推理引擎，需要根据当前状态决定下一步行动。

## 状态
问题: {context['question']}
当前轮次: {context['iteration']}/{self.max_iterations}
已检索文档数: {len(context['retrieved_chunks'])}
检索历史:
{history_summary}

最近检索的内容:
{chunks_summary}

## 可选行动
1. {{"type": "retrieve", "query": "改进后的查询", "reason": "..."}}
   - 用当前查询或改进后的查询检索更多信息
2. {{"type": "self_correct", "improved_query": "改进后的查询", "reason": "..."}}
   - 已检索到的内容不足以回答问题，需要改进查询
3. {{"type": "decompose", "reason": "..."}}
   - 问题复杂，需要分解为多个子问题分别检索
4. {{"type": "generate", "reason": "..."}}
   - 已有足够信息，可以生成最终回答

## 请决定下一步行动（JSON 格式）:"""
        
        response = self.client.chat.completions.create(
            model=self.llm_model,
            messages=[
                {"role": "system", "content": "你是 Agentic RAG 的推理引擎，冷静分析状态并做出最优决策。"},
                {"role": "user", "content": prompt}
            ],
            response_format={"type": "json_object"},
            temperature=0.2
        )
        
        return json.loads(response.choices[0].message.content)
    
    def _generate_answer(self, context: dict) -> dict:
        """生成最终回答"""
        
        chunks_text = "\n\n".join([
            f"[来源 {i+1}] {c['text']}" 
            for i, c in enumerate(context["retrieved_chunks"])
        ])
        
        prompt = f"""基于以下检索到的文档，回答用户的问题。

## 参考文档
{chunks_text}

## 问题
{context['question']}

## 要求
1. 严格基于检索文档回答
2. 标注引用来源 [来源编号]
3. 如果文档信息不足，明确指出
4. 如果存在矛盾信息，指出矛盾

## 回答:"""
        
        response = self.client.chat.completions.create(
            model=self.llm_model,
            messages=[
                {"role": "system", "content": "你是一个严谨的 AI 助手，严格依据参考文档回答问题。"},
                {"role": "user", "content": prompt}
            ],
            temperature=0.3
        )
        
        return {
            "question": context["question"],
            "answer": response.choices[0].message.content,
            "iterations": context["iteration"],
            "sources_used": len(context["retrieved_chunks"]),
            "retrieval_history": context["reasoning_history"]
        }


# ===== 使用示例 =====

agentic_rag = AgenticRAG(base_retriever=pipeline)

result = agentic_rag.run("NVIDIA的市值在2024年发生了什么变化？主要受哪些因素影响？")

print(f"\n{'='*60}")
print(f"最终答案:")
print(f"{'='*60}")
print(result["answer"])
print(f"\n[统计] 迭代 {result['iterations']} 轮, 使用 {result['sources_used']} 个来源")
```

## 四、Agentic RAG 的架构模式

### 4.1 三种主流架构

| 模式 | 描述 | 适用场景 | 复杂度 |
|------|------|----------|--------|
| **Corrective RAG** | 检索→评估→重检索的串行循环 | 需要高精度的事实性问答 | 低 |
| **Speculative RAG** | 先生成候选答案→用答案检索证据→验证 | 需要自洽性验证的生成任务 | 中 |
| **Adaptive RAG** | 根据问题类型自动选择策略（简单/复杂/多跳） | 混合问题类型 | 高 |

### 4.2 Corrective RAG（CRAG）详解

CRAG 是最成熟的 Agentic RAG 变体：

```
输入问题
    │
    ▼
┌──────────────┐
│  检索 Top-K   │
└──────┬───────┘
       │
       ▼
┌───────────────────┐
│  检索质量评估器     │
│  (一个小型分类器)   │
└───┬───────┬───────┘
    │       │
  正确/部分  │ 不正确
    │       │
    ▼       ▼
┌────────┐ ┌──────────────────┐
│ 直接生成 │ │ 查询重写/网络搜索  │
│        │ │ (纠正检索)         │
└────────┘ └────────┬─────────┘
                    │
                    ▼
           ┌────────────────┐
           │  重新检索+生成   │
           └────────────────┘
```

### 4.3 检索质量评估器的训练

CRAG 的关键组件是一个轻量级的检索质量评估器：

```python
def train_retrieval_quality_classifier():
    """
    训练一个轻量级分类器来评估检索结果质量
    
    输入：query + retrieved chunks
    输出：correct / partial / incorrect
```

## 六、2026 年前沿：Agentic Search vs GraphRAG 辩论

> 2026 年初，RAG 领域展开了一场关于架构选型的激烈辩论：Agentic Search 能否取代 GraphRAG？RAGSearch 基准测试（arXiv, Apr 2026）给出了关键数据。

### 6.1 RAGSearch 基准测试核心发现

| 对比维度 | Dense RAG | Agentic Search | GraphRAG |
|----------|-----------|----------------|----------|
| **简单事实查询 (Acc@1)** | 87.2% | 89.5% | 88.1% |
| **单跳关系查询** | 71.3% | 82.6% | 84.5% |
| **多跳推理（2跳）** | 48.5% | 68.2% | 76.8% |
| **多跳推理（3跳）** | 31.2% | 54.7% | 65.3% |
| **聚合/总结查询** | 43.8% | 61.5% | 70.2% |
| **平均延迟** | 0.8s | 2.1s | 3.8s |
| **构建成本** | 低 | 中 | 高 |

### 6.2 关键结论

1. **Agentic search 大幅缩小了差距**：通过多步推理、查询重写和自我纠错，Agentic search 在简单和单跳查询上已基本追平 GraphRAG，且延迟更低。

2. **GraphRAG 在多跳推理上仍具显著优势**：当查询需要 3 跳以上的关系推理时，GraphRAG 的图结构显式关系路径使得召回率领先 10-15 个百分点。

3. **成本-效果权衡清晰**：
   ```
   查询复杂度 → 推荐方案
   ├── 简单事实 → Dense RAG（最低成本，足够好）
   ├── 中等复杂度 → Dense RAG + Agentic Search（性价比最优）
   └── 复杂多跳 → GraphRAG（高成本但高精度）
   ```

### 6.3 实用选型指导

```
用户查询
    │
    ▼
┌─────────────────────┐
│  查询复杂度评估器     │
│  (轻量分类器)        │
└───┬───────┬─────────┘
    │       │
  简单    复杂（多跳/聚合）
    │       │
    ▼       ▼
┌────────┐ ┌──────────────────┐
│Dense   │ │  查询是否涉及     │
│RAG     │ │  显式关系路径？   │
│(快速)  │ └───┬───────┬─────┘
└────────┘     │       │
              是       否
               │       │
               ▼       ▼
        ┌──────────┐ ┌──────────────┐
        │GraphRAG  │ │Agentic Search│
        │(精确)    │ │(灵活)        │
        └──────────┘ └──────────────┘
```

**2026 年实践共识**：
- 对于大多数生产场景，**Dense RAG + Agentic Search** 是最佳性价比选择
- 仅在需要**显式多跳关系推理**（如"A 公司的竞争对手的供应商有哪些？"）或**全局聚合分析**时，才投入 GraphRAG 的构建成本
- 三者并非互斥——可以构建**自适应路由**：简单查询走 Dense RAG，中等走 Agentic Search，复杂走 GraphRAG

## 本章小结

Agentic RAG 将经典 RAG 从"单轮检索"升级为"多轮推理循环"，核心新增四种能力：

1. **多步推理检索**：将复杂问题分解为子问题，逐一检索
2. **查询重写**：用 Agent 优化查询表述，提高检索命中率
3. **自我纠错**：评估检索质量，自动纠正不充分的检索
4. **工具调用**：不限于文本检索，可调用外部工具获取数据

生产部署时建议采用**分级架构**：简单查询走经典 RAG（快速低成本），复杂查询走 Agentic RAG（多轮高精度）。这种分级策略可以在延迟增加约 2-4 倍的情况下，将准确率提升 10-15 个百分点。

下一节将介绍 GraphRAG——另一种增强 RAG 的方向，通过知识图谱的结构化关系提高信息检索的精确度。
