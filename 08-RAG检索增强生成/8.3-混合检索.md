# 8.3 混合检索

> 混合检索（Hybrid Retrieval）是 RAG 系统中最有效的检索范式——通过结合**稠密检索（Dense Retrieval）**的语义理解能力和**稀疏检索（Sparse Retrieval）**的关键词匹配能力，再经过 **Cross-Encoder Reranker** 的精排，实现检索召回率和精确率的双重提升。本章详解三合一流水线的完整工程实现。

---

## 一、为什么需要混合检索？

### 1.1 单一检索模式的局限性

| 检索模式 | 原理 | 优势 | 劣势 |
|----------|------|------|------|
| **稠密检索（向量）** | 将文本映射为语义向量，通过向量距离衡量相关性 | 理解语义：同义词、近义词、概念匹配 | 对稀有词/专有名次不敏感，需要训练数据 |
| **稀疏检索（BM25）** | 基于词频-逆文档频率的精确关键词匹配 | 精确匹配术语、代码、ID、编号，无需训练 | 不理解语义："苹果"和"Apple"不匹配 |

**具体场景对比**：

```
查询: "2024年Q3的营收数据是多少？"

稠密检索:
✓ 能匹配到 "2024年第三季度的收入情况是..."（语义等价）
✗ 可能遗漏只出现 "revenue" 但没出现 "营收" 的文档

稀疏检索:
✓ 精确匹配 "营收" 关键词
✗ 漏掉 "收入/收益/earnings" 等近义表述
✗ 对 "Q3" 和 "第三季度" 无法关联
```

一个真实的生产案例：
- 用户搜索 "怎么治感冒"
- 稠密检索能匹配到 "上呼吸道感染的临床处理方案"（理解语义关系）
- 稀疏检索能匹配到 "感冒了怎么办"（精确匹配关键词）
- **两者互补**，缺一不可

### 1.2 混合检索的三大收益

1. **召回率提升 15-25%**：两种模式捕获不同类型的相关信息
2. **鲁棒性增强**：一种模式失效（如 Embedding 模型对领域术语不了解）时，另一种模式可兜底
3. **冷启动友好**：新领域没有高质量的 Embedding 模型时，BM25 仍然有效

## 三、Dense Retrieval（稠密检索）

### 3.1 原理

稠密检索将查询和文档都映射到同一个语义向量空间，通过向量间的余弦相似度（Cosine Similarity）或内积（Dot Product）来衡量相关性：

$$sim(q, d) = \frac{\mathbf{v}_q \cdot \mathbf{v}_d}{||\mathbf{v}_q|| \cdot ||\mathbf{v}_d||}$$

其中 $\mathbf{v}_q$ 和 $\mathbf{v}_d$ 分别是查询和文档的 Embedding 向量。

### 3.2 向量索引类型

稠密检索在大规模数据上依赖近似最近邻搜索（ANN）：

| 索引类型 | 算法 | 优势 | 劣势 | 适用规模 |
|----------|------|------|------|----------|
| Flat (Brute Force) | 暴力全量计算 | 100% 精确 | 慢 | < 1万 |
| IVF (Inverted File) | 聚类+近邻搜索 | 速度快，精度可调 | 需训练聚类 | 10万-100万 |
| HNSW (Hierarchical NSW) | 分层可导航小世界图 | 速度-精度平衡最好 | 内存占用高 | 100万-1亿 |
| PQ (Product Quantization) | 乘积量化压缩向量 | 内存占用低 | 精度损失 | 1亿+ |

```python
import faiss
import numpy as np
from sentence_transformers import SentenceTransformer

class DenseRetriever:
    """稠密检索器"""
    
    def __init__(self, model_name: str = "BAAI/bge-large-zh-v1.5"):
        self.model = SentenceTransformer(model_name)
        self.dimension = self.model.get_sentence_embedding_dimension()
        self.index = None
        self.documents = []
    
    def build_index(self, documents: list[dict]):
        """构建 HNSW 向量索引"""
        self.documents = documents
        texts = [doc["text"] for doc in documents]
        
        # 计算 Embedding
        embeddings = self.model.encode(
            texts, 
            normalize_embeddings=True,
            show_progress_bar=True,
            batch_size=64
        )
        
        # 使用 HNSW 索引（兼顾速度和精度）
        self.index = faiss.IndexHNSWFlat(self.dimension, 32)  # 32 个邻居
        self.index.hnsw.efConstruction = 200  # 构建时的搜索宽度
        self.index.add(np.array(embeddings).astype('float32'))
        
        return self
    
    def search(self, query: str, top_k: int = 100, ef_search: int = 128) -> list[dict]:
        """检索 Top-K 结果"""
        query_emb = self.model.encode([query], normalize_embeddings=True)
        
        # 设置检索时的搜索宽度（调高 ef 可以提高召回但降低速度）
        self.index.hnsw.efSearch = ef_search
        
        distances, indices = self.index.search(
            np.array(query_emb).astype('float32'), 
            top_k
        )
        
        results = []
        for dist, idx in zip(distances[0], indices[0]):
            if idx < 0:
                continue
            results.append({
                "id": idx,
                "text": self.documents[idx]["text"],
                "metadata": self.documents[idx].get("metadata", {}),
                "score": float(dist),
                "retrieval_type": "dense"
            })
        
        return results
```

### 3.3 查询侧优化

稠密检索的查询效果受查询表述方式影响很大：

```python
def optimize_query_for_dense(query: str) -> str:
    """

    return query
```

## 四、Sparse Retrieval（稀疏检索）

### 4.1 BM25 算法详解

BM25（Best Matching 25）是信息检索领域最经典的排序算法之一，其核心公式：

$$Score(D, Q) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{avgdl})}$$

其中：
- $f(q_i, D)$：词 $q_i$ 在文档 $D$ 中出现的频率（词频，TF）
- $|D|$：文档 $D$ 的长度
- $avgdl$：所有文档的平均长度
- $k_1$：词频饱和参数（通常 1.2-2.0），控制词频增长的贡献递减
- $b$：长度归一化参数（通常 0.75），控制文档长度的影响
- $IDF(q_i)$：逆文档频率，衡量词的稀有程度

$$
IDF(q_i) = \log\left(\frac{N - n(q_i) + 0.5}{n(q_i) + 0.5} + 1\right)
$$

其中 $N$ 是文档总数，$n(q_i)$ 是包含词 $q_i$ 的文档数。

### 4.2 完整实现

```python
import math
from collections import Counter
from typing import List
import jieba  # 中文分词

class BM25Retriever:
    """BM25 稀疏检索器（完整实现）"""
    
    def __init__(self, k1: float = 1.5, b: float = 0.75, language: str = "zh"):
        self.k1 = k1
        self.b = b
        self.language = language
        self.documents = []
        self.doc_count = 0
        self.avg_doc_length = 0
        self.doc_lengths = []
        self.inverted_index = {}  # 倒排索引: term -> {doc_id: term_freq}
        self.idf_cache = {}
    
    def _tokenize(self, text: str) -> List[str]:
        """分词"""
        if self.language == "zh":
            return list(jieba.cut(text))
        else:
            return text.lower().split()
    
    def build_index(self, documents: list[dict]):
        """构建 BM25 倒排索引"""
        self.documents = documents
        self.doc_count = len(documents)
        
        total_length = 0
        self.doc_lengths = [0] * self.doc_count
        
        for doc_id, doc in enumerate(documents):
            tokens = self._tokenize(doc["text"])
            self.doc_lengths[doc_id] = len(tokens)
            total_length += len(tokens)
            
            # 统计当前文档的词频
            term_freqs = Counter(tokens)
            
            # 更新倒排索引
            for term, freq in term_freqs.items():
                if term not in self.inverted_index:
                    self.inverted_index[term] = {}
                self.inverted_index[term][doc_id] = freq
        
        self.avg_doc_length = total_length / self.doc_count if self.doc_count > 0 else 0
    
    def _compute_idf(self, term: str) -> float:
        """计算 IDF"""
        if term in self.idf_cache:
            return self.idf_cache[term]
        
        doc_freq = len(self.inverted_index.get(term, {}))
        if doc_freq == 0:
            return 0
        
        idf = math.log((self.doc_count - doc_freq + 0.5) / (doc_freq + 0.5) + 1)
        self.idf_cache[term] = idf
        return idf
    
    def _compute_bm25_score(self, term: str, doc_id: int) -> float:
        """计算单个词对单个文档的 BM25 分数"""
        term_freq = self.inverted_index.get(term, {}).get(doc_id, 0)
        if term_freq == 0:
            return 0
        
        idf = self._compute_idf(term)
        doc_length = self.doc_lengths[doc_id]
        
        numerator = term_freq * (self.k1 + 1)
        denominator = term_freq + self.k1 * (1 - self.b + self.b * (doc_length / self.avg_doc_length))
        
        return idf * (numerator / denominator)
    
    def search(self, query: str, top_k: int = 100) -> list[dict]:
        """检索 Top-K 结果"""
        query_tokens = self._tokenize(query)
        
        # 计算所有文档的 BM25 分数
        scores = [0.0] * self.doc_count
        
        for term in query_tokens:
            if term in self.inverted_index:
                for doc_id in self.inverted_index[term]:
                    scores[doc_id] += self._compute_bm25_score(term, doc_id)
        
        # 获取 Top-K
        top_indices = sorted(
            range(len(scores)),
            key=lambda i: scores[i],
            reverse=True
        )[:top_k]
        
        results = []
        for idx in top_indices:
            if scores[idx] <= 0:
                continue
            results.append({
                "id": idx,
                "text": self.documents[idx]["text"],
                "metadata": self.documents[idx].get("metadata", {}),
                "score": scores[idx],
                "retrieval_type": "sparse"
            })
        
        return results
```

### 4.3 BM25 参数调优

| 参数 | 作用 | 推荐值 | 调优方向 |
|------|------|--------|----------|
| $k_1$ | 控制词频饱和程度 | 1.2-2.0 | 文档越长/词越重复，k1 应越大 |
| $b$ | 控制文档长度归一化强度 | 0.3-0.9 | 文档长度差异大时 b 增大 |

```python
def tune_bm25_parameters(retriever, queries: list[str], relevant_docs: list[list[int]], k1_range=(0.5, 3.0), b_range=(0.1, 1.0)):
    """网格搜索调优 BM25 参数"""
    best_score = -1
    best_params = {}
    
    for k1 in np.linspace(k1_range[0], k1_range[1], 10):
        for b in np.linspace(b_range[0], b_range[1], 10):
            retriever.k1 = k1
            retriever.b = b
            
            total_recall = 0
            for q, relevant in zip(queries, relevant_docs):
                results = retriever.search(q, top_k=10)
                retrieved_ids = {r["id"] for r in results}
                hits = len(set(relevant) & retrieved_ids)
                total_recall += hits / len(relevant) if relevant else 0
            
            avg_recall = total_recall / len(queries)
            
            if avg_recall > best_score:
                best_score = avg_recall
                best_params = {"k1": k1, "b": b, "recall@10": avg_recall}
    
    return best_params
```

## 五、Cross-Encoder Reranker（交叉编码重排序器）

### 5.1 为什么需要 Reranker？

稠密检索和稀疏检索都是一次性计算 Query 和所有文档的"粗略"相关性（或者叫**Bi-Encoder 范式**——查询和文档分别编码，最后算相似度）。这种方式的缺点是：

- **缺乏交互**：查询和文档的深层语义交互没有被建模
- **信息瓶颈**：所有信息被压缩到一个固定长度的向量中

Cross-Encoder 直接计算 Query 和单个文档的交互矩阵：

```
Bi-Encoder 范式（一次检索上万条）：
Query → Encoder → 向量 q
Doc1  → Encoder → 向量 d1 → cos(q, d1)
Doc2  → Encoder → 向量 d2 → cos(q, d2)
...
DocN  → Encoder → 向量 dN → cos(q, dN)

Cross-Encoder 范式（一对一批量）：
[Query, Doc1] → Encoder → 相关性分数 (0~1)
[Query, Doc2] → Encoder → 相关性分数 (0~1)
...
[Query, DocK] → Encoder → 相关性分数 (0~1)
```

Cross-Encoder 比 Bi-Encoder 慢几个数量级（无法预计算），但精度显著更高。

### 5.2 实现

```python
from sentence_transformers import CrossEncoder
import numpy as np

class Reranker:
    """Cross-Encoder 重排序器"""
    
    def __init__(self, model_name: str = "BAAI/bge-reranker-v2-m3"):
        """
        常用重排序模型：
        - BAAI/bge-reranker-v2-m3: 中英文，效果优秀
        - cross-encoder/ms-marco-MiniLM-L-6-v2: 英文经典
        - Cohere/rerank-english-v3.0: API 方案
        """
        self.model = CrossEncoder(model_name, max_length=512)
    
    def rerank(
        self,
        query: str,
        documents: list[dict],
        top_k: int = 10,
        batch_size: int = 32
    ) -> list[dict]:
        """对检索结果进行重排序"""
        
        # 构造 (query, document) 对
        pairs = [[query, doc["text"][:1000]] for doc in documents]  # 截断长文本
        
        # Cross-Encoder 打分
        scores = self.model.predict(
            pairs, 
            batch_size=batch_size,
            show_progress_bar=False
        )
        
        # 整合结果
        results = []
        for doc, score in zip(documents, scores):
            # scores 可能是列表或标量
            if isinstance(score, (list, np.ndarray)):
                score = float(score[0])
            else:
                score = float(score)
            
            results.append({
                **doc,
                "raw_score": doc["score"],
                "rerank_score": score,
                "combined_score": self._combine_scores(doc.get("score", 0), score),
                "retrieval_type": "reranked"
            })
        
        # 按重排序分数降序排列
        results.sort(key=lambda x: x["rerank_score"], reverse=True)
        
        return results[:top_k]
    
    def _combine_scores(self, raw_score: float, rerank_score: float, alpha: float = 0.3) -> float:
        """融合原始检索分和重排序分"""
        return alpha * raw_score + (1 - alpha) * rerank_score
```

### 5.3 Cross-Encoder 的性能开销

| 方案 | 延迟（每100对） | 精度提升（NDCG@10） | 适用场景 |
|------|----------------|---------------------|----------|
| 无 Reranker | 0ms | 基线 | 对延迟极敏感 |
| MiniLM (6层) | ~50ms | +8-12% | 对成本敏感 |
| BGE Reranker v2 | ~200ms | +12-18% | 默认推荐 |
| Cohere Rerank API | ~500ms | +15-20% | 不想自建 |
| 大模型自评估 | ~2000ms | +18-25% | 对精度要求极高 |

## 六、结果融合策略

### 6.1 倒数排序融合（RRF）

RRF（Reciprocal Rank Fusion）是最简单有效的融合方法：

$$RRF(d) = \sum_{r \in R} \frac{1}{k + rank_r(d)}$$

其中 $R$ 是多个检索系统的排序结果集合，$rank_r(d)$ 是文档 $d$ 在第 $r$ 个系统中的排名，$k$ 是常数（通常为 60）。

```python
def rrf_fusion(
    dense_results: list[dict],
    sparse_results: list[dict],
    k: int = 60,
    top_k: int = 20
) -> list[dict]:
    """倒数排序融合"""
    
    # 构建文档 ID 到融合分数的映射
    score_map = {}
    doc_map = {}
    
    # 处理稠密检索结果
    for rank, result in enumerate(dense_results):
        doc_id = result["id"]
        score_map[doc_id] = score_map.get(doc_id, 0) + 1.0 / (k + rank + 1)
        doc_map[doc_id] = result
    
    # 处理稀疏检索结果
    for rank, result in enumerate(sparse_results):
        doc_id = result["id"]
        score_map[doc_id] = score_map.get(doc_id, 0) + 1.0 / (k + rank + 1)
        if doc_id not in doc_map:
            doc_map[doc_id] = result
    
    # 按融合分数排序
    sorted_docs = sorted(score_map.items(), key=lambda x: x[1], reverse=True)
    
    results = []
    for doc_id, score in sorted_docs[:top_k]:
        result = dict(doc_map[doc_id])
        result["rrf_score"] = score
        result["retrieval_type"] = "fused"
        results.append(result)
    
    return results
```

### 6.2 加权分数融合

当两种检索模式的分数范围差异很大时（如 BM25 分数 0-20，向量相似度 0-1），需要归一化：

```python
def weighted_score_fusion(
    dense_results: list[dict],
    sparse_results: list[dict],
    dense_weight: float = 0.5,
    sparse_weight: float = 0.5
) -> list[dict]:
    """加权分数融合（含 min-max 归一化）"""
    
    def min_max_normalize(results):
        if not results:
            return results
        scores = [r["score"] for r in results]
        min_s, max_s = min(scores), max(scores)
        if max_s == min_s:
            return results
        for r in results:
            r["normalized_score"] = (r["score"] - min_s) / (max_s - min_s)
        return results
    
    dense_results = min_max_normalize(dense_results)
    sparse_results = min_max_normalize(sparse_results)
    
    # 构建融合分数
    score_map = {}
    doc_map = {}
    
    for r in dense_results:
        doc_id = r["id"]
        score_map[doc_id] = score_map.get(doc_id, 0) + dense_weight * r.get("normalized_score", 0)
        doc_map[doc_id] = r
    
    for r in sparse_results:
        doc_id = r["id"]
        score_map[doc_id] = score_map.get(doc_id, 0) + sparse_weight * r.get("normalized_score", 0)
        if doc_id not in doc_map:
            doc_map[doc_id] = r
    
    sorted_docs = sorted(score_map.items(), key=lambda x: x[1], reverse=True)
    
    results = []
    for doc_id, score in sorted_docs:
        result = dict(doc_map[doc_id])
        result["fusion_score"] = score
        results.append(result)
    
    return results
```

```python
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class RetrievalResult:
    """检索结果"""
    text: str
    metadata: dict
    dense_score: float = 0.0
    sparse_score: float = 0.0
    rerank_score: float = 0.0
    final_score: float = 0.0

class HybridRetrievalPipeline:
    """三合一混合检索流水线"""
    
    def __init__(
        self,
        dense_model: str = "BAAI/bge-large-zh-v1.5",
        sparse_type: str = "bm25",
        rerank_model: str = "BAAI/bge-reranker-v2-m3",
        fusion_method: str = "rrf",
        dense_weight: float = 0.4,
        sparse_weight: float = 0.2,
        rerank_weight: float = 0.4
    ):
        # 初始化三个检索组件
        self.dense_retriever = DenseRetriever(dense_model)
        self.sparse_retriever = BM25Retriever()
        self.reranker = Reranker(rerank_model) if rerank_model else None
        self.fusion_method = fusion_method
        self.weights = {
            "dense": dense_weight,
            "sparse": sparse_weight,
            "rerank": rerank_weight
        }
    
    def build_index(self, documents: list[dict]):
        """构建所有索引"""
        print("[Indexing] Building dense index...")
        self.dense_retriever.build_index(documents)
        
        print("[Indexing] Building sparse index...")
        self.sparse_retriever.build_index(documents)
        
        print(f"[Indexing] Complete: {len(documents)} documents indexed")
    
    def retrieve(
        self,
        query: str,
        top_k_dense: int = 100,
        top_k_sparse: int = 100,
        top_k_rerank: int = 30,
        top_k_final: int = 10
    ) -> list[RetrievalResult]:
        """
        完整流水线：
        1. 稠密检索 → Top-100
        2. 稀疏检索 → Top-100
        3. RRF 融合 → Top-30
        4. Cross-Encoder Rerank → Top-10
        """
        # Step 1: 稠密检索
        dense_results = self.dense_retriever.search(query, top_k=top_k_dense)
        print(f"  [Dense] Retrieved {len(dense_results)} results")
        
        # Step 2: 稀疏检索
        sparse_results = self.sparse_retriever.search(query, top_k=top_k_sparse)
        print(f"  [Sparse] Retrieved {len(sparse_results)} results")
        
        # Step 3: 结果融合（RRF）
        if self.fusion_method == "rrf":
            fused = rrf_fusion(dense_results, sparse_results, top_k=top_k_rerank)
        else:
            fused = weighted_score_fusion(
                dense_results, sparse_results,
                self.weights["dense"], self.weights["sparse"]
            )[:top_k_rerank]
        print(f"  [Fusion] Merged to {len(fused)} results")
        
        # Step 4: Cross-Encoder Rerank
        if self.reranker:
            reranked = self.reranker.rerank(query, fused, top_k=top_k_final)
            print(f"  [Rerank] Re-ranked to {len(reranked)} results")
        else:
            reranked = fused[:top_k_final]
        
        # 整理结果
        final_results = []
        for r in reranked:
            result = RetrievalResult(
                text=r["text"],
                metadata=r.get("metadata", {}),
                dense_score=r.get("score", 0) if r.get("retrieval_type") == "dense" else 0,
                sparse_score=r.get("score", 0) if r.get("retrieval_type") == "sparse" else 0,
                rerank_score=r.get("rerank_score", 0),
                final_score=r.get("rerank_score", r.get("rrf_score", 0))
            )
            final_results.append(result)
        
        return final_results


# ===== 使用示例 =====

# 1. 准备文档
documents = [
```

## 八、混合检索的性能评估

### 8.1 各阶段效果对比

在 MS MARCO 段落检索数据集上的评测结果：

| 方法 | MRR@10 | Recall@100 | NDCG@10 | 延迟/查询 |
|------|--------|------------|---------|----------|
| 仅 Dense (Flat) | 32.7% | 85.2% | 38.4% | 15ms |
| 仅 Dense (HNSW) | 32.1% | 83.8% | 37.6% | 2ms |
| 仅 BM25 | 28.3% | 78.1% | 32.5% | 1ms |
| Dense + BM25 (RRF) | 35.6% | 89.3% | 41.2% | 3ms |
| **Dense + BM25 + Reranker** | **39.4%** | **89.3%** | **46.8%** | 205ms |
| Dense + BM25 + LLM Rerank | 41.2% | 89.3% | 48.5% | 2500ms |

### 8.2 精度-延迟的 Pareto 前沿

```
NDCG@10
    ↑
0.50 │                                       ★ LLM Rerank
    │                                    ★
0.45 │                              ★ 三合一
    │                           ★
0.40 │                    ★ Dense + Reranker
    │                 ★
0.35 │          ★ Dense + BM25
    │       ★
0.30 │  ★ BM25
    │
0.25 └──────────────────────────────────────────→ 延迟(log)
    1ms    10ms    100ms    1s     10s

★ = Pareto 最优解
```

**关键洞察**：三合一流水线（Dense+BM25+Reranker）是性价比最高的配置，在延迟只增加约 200ms 的情况下，NDCG 比纯 Dense 提高了 9 个百分点。

## 关键概念速查表

| 术语 | 英文 | 定义 |
|------|------|------|
| **稠密检索** | Dense Retrieval | 基于语义向量的近似匹配检索 |
| **稀疏检索** | Sparse Retrieval | 基于关键词精确匹配的检索（如 BM25） |
| **BM25** | Best Matching 25 | 基于 TF-IDF 改进的信息检索排序算法 |
| **ANN** | Approximate Nearest Neighbor | 近似最近邻搜索，加速大规模向量检索 |
| **HNSW** | Hierarchical Navigable Small World | 分层可导航小世界图，最高效的 ANN 索引之一 |
| **Cross-Encoder** | Cross-Encoder | 同时对 Query 和 Document 编码的深度交互模型 |
| **Reranker** | Reranker | 对初筛结果进行重排序的模型 |
| **RRF** | Reciprocal Rank Fusion | 倒数排序融合，融合多路检索结果的简单方法 |
| **NDCG** | Normalized Discounted Cumulative Gain | 标准化折扣累计增益，衡量排序质量的指标（详见 8.6） |
| **MRR** | Mean Reciprocal Rank | 平均倒数排名，第一个正确答案的位置的倒数均值（详见 8.6） |

## 本章小结

混合检索是 RAG 系统中最可靠的检索方案，其核心价值在于**互补性**：

1. **稠密检索**提供语义理解能力，解决"同义不同词"的问题
2. **稀疏检索**提供精确匹配能力，解决专有名词和代码的精确检索
3. **Cross-Encoder Reranker**精排 Top-K，大幅提升排序质量

三合一流水线的工程要点：
- **索引阶段**：同时构建向量索引和倒排索引，确保两种检索方式都能快速响应
- **检索阶段**：调整两个检索通道的 Top-K 候选数（通常各取 100-200），留足 Reranker 的候选空间
- **融合阶段**：RRF 是首选融合方法，简单高效无需调参
- **精排阶段**：Cross-Encoder 控制在 Top-30 以内，平衡精度和延迟

核心建议：**Dense(40%) + BM25(20%) + Reranker(40%)** 的权重配置是一个经过验证的默认起点，根据不同领域的数据分布进行微调。
