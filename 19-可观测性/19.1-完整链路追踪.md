# 19.1 完整链路追踪 —— Thought → Action → Observation 每一步的输入/输出/耗时/Token

> 当 Agent 在后台跑了 50 步后给出一个错误答案——你怎么知道是哪一步出的问题？链路追踪（Tracing）是回答这个问题的第一技术。它将 Agent 执行的每一"步"分解为可观测的单元，记录输入、输出、耗时和 Token 消耗，帮助开发者从全局时间线中定位异常节点。

---

## 一、Trace 与 Span：链路追踪的核心概念

### 1.1 什么是 Trace？

**Trace（追踪）** 代表一次完整的 Agent 执行请求从开始到结束的整个生命周期。在 Agent 场景中，一次用户请求可能触发多次 LLM 调用、多次工具执行和多次记忆检索——所有这些活动共同构成一个 Trace。

**Span（跨度）** 是 Trace 的组成单元，每个 Span 代表 Trace 中的一个具体操作。Span 之间通过父子关系构成树形结构。

```
                         Trace (用户请求: "帮我分析Q3财报")
                            │
              ┌─────────────┼─────────────┐
              │             │             │
         Span:         Span:          Span:
     "任务规划"    "工具调用"      "结果生成"
              │             │
              │    ┌────────┼────────┐
              │    │        │        │
              │ Span:   Span:    Span:
              │ "搜索   "读取   "计算
              │  财报"    PDF"    指标"
```

### 1.2 Agent Trace 的特殊性

不同于传统微服务追踪（一次 HTTP 请求经过多个服务），Agent Trace 有以下几个独特特征：

| 特征 | 微服务 Trace | Agent Trace |
|------|------------|-------------|
| **执行单元** | HTTP 请求/数据库查询 | Thought/Action/Observation 循环 |
| **数据形态** | 结构化 (JSON/Proto) | 半结构化 + 自然语言 |
| **长度** | 通常 < 10 个 Span | 可能 50-200+ 个 Span |
| **不确定性** | 确定性路径 | 分支、回退、重试 |
| **消耗追踪** | CPU/内存 | Token 消耗（关键指标） |
| **因果链路** | 请求-响应链 | 推理-行动-观察循环 |

## 二、完整的 Trace 数据结构定义

### 2.1 Span 数据模型

一个 Agent Trace 中的 Span 应该包含以下字段。这是参考 OpenTelemetry 语义规范并针对 Agent 场景扩展后的结构：

```python
from dataclasses import dataclass, field
from typing import Optional, Any
from datetime import datetime
import uuid

@dataclass
class AgentSpan:
    """Agent 执行链中的单一跨度"""
    # 标识
    span_id: str = field(default_factory=lambda: uuid.uuid4().hex[:16])
    trace_id: str = ""                    # 所属 Trace ID
    parent_span_id: Optional[str] = None  # 父 Span ID (None表示根Span)

    # 时间
    start_time: datetime = field(default_factory=datetime.now)
    end_time: Optional[datetime] = None
    duration_ms: Optional[float] = None   # 耗时（毫秒）

    # Agent 特定字段
    span_type: str = ""                   # "thought" | "action" | "observation" | "llm_call" | "tool_call"
    step_index: int = 0                   # 在 Agent 循环中的步数

    # 输入输出
    input: Any = None                     # Span 的输入
    output: Any = None                    # Span 的输出
    error: Optional[str] = None           # 错误信息

    # Token 消耗
    prompt_tokens: int = 0                # 输入 Token 数
    completion_tokens: int = 0            # 输出 Token 数
    total_tokens: int = 0                 # 总 Token 数

    # 模型信息
    model: str = ""                       # 使用的模型 (如 "gpt-4o")
    temperature: float = 0.0              # 采样温度

    # 元数据
    tags: dict = field(default_factory=dict)  # 自定义标签
    attributes: dict = field(default_factory=dict)  # OpenTelemetry 属性
```

### 2.3 Span 类型定义

Agent 场景中的 Span 分为五个核心类型，对应 ReAct 循环（详见第 2 章 [ReAct 模式](../02-Agent核心循环/2.1-ReAct模式.md)）的每一个环节：

| Span 类型 | 说明 | 记录重点 |
|-----------|------|---------|
| `thought` | Agent 的推理步骤 | 推理内容、使用的模型、推理耗时 |
| `action` | Agent 执行的操作 | 工具名称、输入参数、执行耗时 |
| `observation` | 动作的返回结果 | 原始返回、截断后的内容、大小 |
| `llm_call` | LLM API 调用 | 完整 Prompt、Completion、Token 消耗 |
| `tool_call` | 工具/函数调用 | 工具名、参数、返回码、错误信息 |

## 三、链路追踪实现方案

### 3.1 基于 Decorator 的自动埋点

最实用的做法是使用装饰器（Decorator）自动包装 Agent 的每一步执行函数，无需手动在每个步骤中插入追踪代码：

```python
import functools
import time
from datetime import datetime
from contextvars import ContextVar

# 线程安全的上下文变量，存储当前 Trace
current_trace: ContextVar[dict] = ContextVar("current_trace", default=None)

def trace_step(span_type: str):
    """自动追踪 Agent 步骤的装饰器"""
    def decorator(func):
        @functools.wraps(func)
        async def wrapper(*args, **kwargs):
            trace = current_trace.get()
            if trace is None:
                # 如果没有活跃的 Trace，创建一个新的
                trace = {
                    "trace_id": uuid.uuid4().hex,
                    "spans": [],
                    "start_time": datetime.now()
                }
                current_trace.set(trace)

            span = AgentSpan(
                span_id=uuid.uuid4().hex[:16],
                trace_id=trace["trace_id"],
                span_type=span_type,
                step_index=len(trace["spans"]),
                start_time=datetime.now(),
                input={"args": str(args), "kwargs": str(kwargs)}
            )

            try:
                result = await func(*args, **kwargs)
                span.output = result
                span.end_time = datetime.now()
                span.duration_ms = (span.end_time - span.start_time).total_seconds() * 1000
                return result
            except Exception as e:
                span.error = str(e)
                span.end_time = datetime.now()
                raise
            finally:
                trace["spans"].append(span)

        return wrapper
    return decorator


# ========== 使用示例 ==========

class FinancialAgent:
    @trace_step("thought")
    async def plan(self, query: str) -> str:
        """规划分析步骤"""
        response = await llm.call(
            model="gpt-4o",
            messages=[{"role": "user", "content": f"制定分析计划：{query}"}]
        )
        return response

    @trace_step("action")
    async def search(self, query: str) -> list:
        """执行搜索"""
        return await search_engine.search(query)

    @trace_step("observation")
    async def process_results(self, raw: list) -> str:
        """处理搜索结果"""
        return summarize(raw)
```

### 3.2 手动埋点（精细控制）

当需要精确控制 Span 边界和附加属性时，使用手动埋点：

```python
from opentelemetry import trace
from opentelemetry.trace import SpanKind

tracer = trace.get_tracer("agent-tracer")

async def agent_execute(user_query: str) -> str:
    with tracer.start_as_current_span(
        "agent_execute",
        kind=SpanKind.CLIENT,
        attributes={
            "user_query": user_query,
            "agent_type": "plan-and-execute"
        }
    ) as root_span:

        # Step 1: Thought - 规划
        with tracer.start_as_current_span(
            "thought.plan",
            attributes={"step": 1, "phase": "planning"}
        ) as thought_span:
            plan = await llm_call(PLANNING_PROMPT + user_query)
            thought_span.set_attribute("plan_content", plan)
            thought_span.set_attribute(
                "token_usage",
                {"prompt": 450, "completion": 180}
            )

        # Step 2: Action - 工具调用
        with tracer.start_as_current_span(
            "tool.search",
            attributes={
                "step": 2,
                "tool": "search_engine",
                "tool.input": user_query
            }
        ) as action_span:
            try:
                results = await search_engine.search(user_query)
                action_span.set_attribute("result_count", len(results))
            except Exception as e:
                action_span.record_exception(e)
                action_span.set_status(trace.Status(trace.StatusCode.ERROR, str(e)))
                raise

        # Step 3: Observation - 处理观察结果
        with tracer.start_as_current_span(
            "observation.process",
            attributes={"step": 3}
        ) as obs_span:
            summary = await summarize_results(results)
            obs_span.set_attribute("summary_length", len(summary))

        return summary
```

### 3.3 Span 的生命周期管理

```

│                                                           │

```

### 4.3 异常 Span 的自动检测

链路追踪的真正价值在于**自动识别异常 Span**。以下策略可集成到监控系统中：

```python
class TraceAnalyzer:
    def __init__(self):
        self.latency_baselines = {}  # span_type -> p50/p95/p99

    def detect_anomalous_spans(self, trace: dict) -> list:
        """检测 Trace 中的异常 Span"""
        anomalies = []

        for span in trace["spans"]:
            span_type = span["span_type"]

            # 1. 耗时异常检测
            if span_type in self.latency_baselines:
                baseline = self.latency_baselines[span_type]
                if span["duration_ms"] > baseline["p99"] * 2:
                    anomalies.append({
                        "span_id": span["span_id"],
                        "type": "latency_anomaly",
                        "actual": span["duration_ms"],
                        "threshold": baseline["p99"] * 2,
                        "severity": "high"
                    })

            # 2. Token 消耗异常检测
            if span.get("total_tokens", 0) > 10000:
                anomalies.append({
                    "span_id": span["span_id"],
                    "type": "token_spike",
                    "tokens": span["total_tokens"],
                    "severity": "medium"
                })

            # 3. 错误检测
            if span.get("error"):
                anomalies.append({
                    "span_id": span["span_id"],
                    "type": "execution_error",
                    "error": span["error"],
                    "severity": "critical"
                })

            # 4. 重试检测
            if span.get("retry_count", 0) > 3:
                anomalies.append({
                    "span_id": span["span_id"],
                    "type": "excessive_retries",
                    "retries": span["retry_count"],
                    "severity": "medium"
                })

        return anomalies
```

## 五、Trace 采样与存储策略

### 5.1 采样策略

高并发 Agent 系统会产生大量 Trace，全量存储不可行。常见采样策略：

| 策略 | 方法 | 适用场景 |
|------|------|---------|
| **头部采样** | 在 Trace 开始时决定是否采集 | 高吞吐量，低延迟 |
| **尾部采样** | Trace 结束后根据结果决定 | 需要按结果状态采样 |
| **概率采样** | 按固定比例（如 10%）随机采样 | 通用场景 |
| **动态采样** | 根据错误/延迟动态调整采样率 | 关注异常场景 |
| **重要 Trace 全采** | 特定用户/工作流 100% 采集 | 关键业务场景 |

```python
class TraceSampler:
    """动态 Trace 采样器"""

    def __init__(self, base_rate: float = 0.1):
        self.base_rate = base_rate
        self.error_count = 0
        self.total_count = 0

    def should_sample(self, trace_context: dict) -> bool:
        """决定是否采样当前 Trace"""
        # 1. 关键用户/工作流全采
        if trace_context.get("user_id") in self.critical_users:
            return True
        if trace_context.get("workflow") in self.critical_workflows:
            return True

        # 2. 错误率升高时提高采样率
        error_rate = self.error_count / max(self.total_count, 1)
        if error_rate > 0.05:  # 错误率 > 5%
            return random.random() < min(1.0, self.base_rate * 5)

        # 3. 基础概率采样
        return random.random() < self.base_rate
```

### 5.2 存储架构

Trace 数据的存储需要同时满足写入吞吐量（高并发写入）和查询性能（按 Trace ID 检索、按时间范围检索）：

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│ Agent 实例   │ ──→ │  Trace 收集器  │ ──→ │  实时分析     │
│ (Span 生成)  │     │  (缓冲/批处理) │     │  (告警/仪表盘)│
└─────────────┘     └──────┬───────┘     └──────────────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
         ┌────▼───┐  ┌────▼───┐  ┌────▼───┐
         │ 时序库  │  │ 对象存储 │  │ 搜索引擎 │
         │(InfluxDB│  │ (S3/OSS)│  │(Elastic)│
         │ /Victoria)│  │ 原始Span │  │ 索引查询 │
         │ 聚合指标 │  │ 全量存储 │  │ 全文检索 │
         └────────┘  └────────┘  └────────┘
```

## 六、Trace 导出与 OpenTelemetry 集成

Agent Trace 可以通过 OpenTelemetry 协议导出到任意兼容的后端：

```python
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor

# 配置 OTLP 导出器
exporter = OTLPSpanExporter(
    endpoint="http://otel-collector:4317",
    headers={"Authorization": "Bearer token123"}
)

# 配置 Tracer Provider
provider = TracerProvider(
    resource=Resource.create({
        "service.name": "agent-service",
        "service.version": "2.1.0",
        "deployment.environment": "production"
    })
)

# 配置 Span 处理器（批处理导出）
processor = BatchSpanProcessor(
    exporter,
    max_queue_size=2048,        # 队列最大长度
    max_export_batch_size=512,  # 每批导出数
    schedule_delay_millis=5000  # 导出间隔
)
provider.add_span_processor(processor)
trace.set_tracer_provider(provider)
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Trace | 一次完整 Agent 请求的全生命周期记录，由多个 Span 组成树形结构 |
| Span | Trace 中的单一操作单元，记录输入、输出、耗时、Token 消耗 |
| Span Context | 包含 Trace ID 和 Span ID 的上下文，用于跨进程/线程传递追踪信息 |
| Root Span | Trace 中的根 Span，代表整个 Agent 执行过程的开始 |
| 埋点（Instrumentation） | 在代码中插入追踪逻辑的过程，自动或手动方式 |
| 采样（Sampling） | 选择性地记录 Trace 以减少存储开销的策略 |
| OpenTelemetry | 开源的可观测性框架，提供统一的 Trace/Metric/Log API |
| 甘特图视图 | 以时间线方式展示 Span 的可视化方式，用于分析耗时分布 |
