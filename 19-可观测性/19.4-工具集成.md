# 19.4 工具集成 —— LangFuse / LangSmith / Phoenix / OpenTelemetry 的接入方式和差异

> 选择可观测性工具不是"用哪个最好"的问题，而是"哪个最适合你的场景"的问题。LangFuse、LangSmith、Phoenix（Arize）和 OpenTelemetry 代表着四种不同的理念：开源 vs 商业、全栈 vs 轻量、托管 vs 自建。理解它们的核心差异和接入方式，是搭建 Agent 可观测性基础设施的第一步。

---

## 一、四大工具概览

### 1.1 定位与核心理念

```
可观测性工具光谱

     开源/自建                         商业/SaaS
     ──────────────────────────────────────────────→

  OpenTelemetry      Phoenix         LangFuse       LangSmith
  (协议标准)        (开源平台)      (开源+云)       (商业SaaS)
     
  提供标准 API     AI 专用可       LLM 应用可       LLM 应用全
  和协议，不限    观测性平台      观测性平台       栈可观测性
  定 AI 场景      (Arize 开源)    (自建或云)       (LangChain 生态)
```

### 1.2 功能对比矩阵

| 特性 | LangFuse | LangSmith | Phoenix (Arize) | OpenTelemetry |
|------|----------|-----------|-----------------|---------------|
| **开源** | 是 (MIT) | 否 (商业) | 是 (BSL) | 是 (Apache 2.0) |
| **自建部署** | 支持 (Docker) | 不支持 | 支持 (Docker/Pip) | 需要搭建 Collector |
| **托管服务** | LangFuse Cloud | LangSmith | 无 (可通过 Arize 云) | 需要第三方后端 |
| **AI 专有** | 是 | 是 | 是 | 通用 (需扩展) |
| **Trace 视图** | 甘特图 + 树形 | 树形 + Debug 视图 | 树形 + 性能分析 | 需 GUI 工具 (Jaeger) |
| **Prompt 管理** | 内置 | 内置 | 无 | 无 |
| **Cost 追踪** | 内置 (按模型) | 内置 | 需自定义 | 无 (需扩展) |
| **数据集/评估** | 支持 | 支持 (LangSmith 数据集) | 支持 (Arize 平台) | 无 |
| **异常检测** | 规则 + LLM 评估 | 规则 + 人工审查 | 自动漂移检测 | 需自定义 |
| **Python SDK** | 完善 | 完善 | 完善 | 完善 |
| **TypeScript SDK** | 完善 | 完善 | 有限 | 完善 |
| **OpenTelemetry 兼容** | 支持 (OTLP 导入) | 支持 (LangChain 集成) | 原生 OTLP | 原生 |
| **社区活跃度** | 高 (GitHub 9k+ stars) | 高 (LangChain 生态) | 中 (GitHub 5k+ stars) | 极高 (CNCF 项目) |

## 二、LangFuse —— 开源 LLM 可观测性平台

### 2.1 核心概念

LangFuse 设计了三层数据结构：**Trace → Observation → Span**。Trace 代表一次完整的 Agent 执行，Observation 是其中的最小观测单元（LLM 调用、工具调用、生成事件）。

### 2.2 接入代码

```python
from langfuse import Langfuse
from langfuse.decorators import observe, langfuse_context
import os

# 初始化 LangFuse 客户端
langfuse = Langfuse(
    secret_key=os.environ["LANGFUSE_SECRET_KEY"],
    public_key=os.environ["LANGFUSE_PUBLIC_KEY"],
    host=os.environ.get("LANGFUSE_HOST", "https://cloud.langfuse.com")
)

# ========== 方式1: Decorator 方式（推荐） ==========

@observe()  # 自动捕获函数输入/输出/耗时
async def agent_think(prompt: str) -> str:
    """Agent 思考步骤"""
    response = await llm.call(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}]
    )

    # 记录 Token 消耗（自动从 LLM 响应中提取）
    langfuse_context.update_current_observation(
        input=prompt,
        output=response.text,
        usage={
            "input": response.usage.prompt_tokens,
            "output": response.usage.completion_tokens,
            "unit": "TOKENS"
        },
        model=response.model,
    )
    return response.text


@observe()
async def agent_search(query: str) -> list:
    """Agent 搜索步骤"""
    results = await search_engine.search(query)

    # 记录工具调用
    langfuse_context.update_current_observation(
        input=query,
        output=str(results[:3]),
        metadata={"tool": "search_engine", "result_count": len(results)}
    )
    return results


@observe()
async def agent_execute(user_query: str) -> str:
    """Agent 主执行流程（自动成为根 Trace）"""
    # 设置 Trace 级别属性
    langfuse_context.update_current_trace(
        name="agent-execute",
        user_id="user-123",
        session_id="session-456",
        tags=["production", "v2.1"],
        metadata={"workflow": "financial-analysis"}
    )

    plan = await agent_think(f"制定分析计划：{user_query}")
    results = await agent_search(plan)
    answer = await agent_think(f"基于结果生成回答：{results}")

    return answer


# ========== 方式2: 手动创建 Trace ==========

def manual_tracing_example():
    """需要精细控制时的手动埋点"""
    trace = langfuse.trace(
        name="manual-agent-trace",
        user_id="user-789",
        metadata={"version": "2.0"}
    )

    # 创建 LLM 调用 Span
    generation = trace.generation(
        name="thought-plan",
        model="gpt-4o",
        input="制定分析计划：...",
        output="计划内容...",
        usage={
            "input": 450,
            "output": 180,
            "unit": "TOKENS"
        }
    )

    # 创建工具调用 Span
    tool_call = trace.span(
        name="search-financial-data",
        input={"query": "Q3 财报 2026"},
        metadata={"tool": "search_engine"}
    )
    tool_call.end(
        output="搜索结果...",
        level="DEFAULT"
    )

    trace.update(
        output="最终回答...",
        completion_time=datetime.now().isoformat()
    )
```

### 2.3 LangFuse 的独特优势

- **Prompt 版本管理**：在 LangFuse UI 中管理 Prompt 模板，版本化发布，生产环境可即时回滚
- **成本追踪**：自动根据 Token 消耗和模型单价计算成本，支持自定义价格
- **人工标注**：支持在 UI 中对 Trace 进行打分和标注，构建评估数据集
- **自建部署**：一行命令 `docker compose up` 即可部署

## 三、LangSmith —— LangChain 生态的商业可观测性

### 3.1 核心概念

LangSmith 是 LangChain 官方提供的商业可观测性平台，与 LangChain SDK 深度集成。当你在使用 LangChain/LangGraph 构建 Agent 时，LangSmith 是最"零配置"的选择。

### 3.2 接入代码

```python
import os
from langsmith import Client
from langchain_openai import ChatOpenAI
from langchain.agents import create_react_agent, AgentExecutor
from langchain.tools import tool

# 设置 LangSmith 环境变量
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = "ls_..."
os.environ["LANGCHAIN_PROJECT"] = "my-agent-project"

# 创建 LangSmith 客户端
client = Client()

# ========== 自动追踪 LangChain Agent ==========
# 当设置了环境变量后，所有 LangChain/LangGraph 调用自动被追踪

@tool
def search_financial_data(query: str) -> str:
    """搜索金融数据"""
    return f"关于 {query} 的搜索结果..."

llm = ChatOpenAI(model="gpt-4o", temperature=0)
agent = create_react_agent(llm, [search_financial_data])
agent_executor = AgentExecutor(agent=agent, tools=[search_financial_data])

# 这个调用会自动被 LangSmith 追踪
result = agent_executor.invoke({
    "input": "分析 Q3 财报的主要风险"
})


# ========== 手动创建 Trace（非 LangChain 场景） ==========

from langsmith import traceable
from langsmith.run_trees import RunTree

@traceable(run_type="chain", name="agent-pipeline")
def custom_agent(query: str) -> str:
    """非 LangChain Agent 的手动追踪"""
    # 创建子 Span
    with traceable(run_type="llm", name="step-1-think") as think_step:
        thought = llm.invoke(f"思考: {query}")
        think_step.end(outputs={"thought": thought.content})

    with traceable(run_type="tool", name="step-2-search") as search_step:
        results = search_financial_data(query)
        search_step.end(outputs={"results": results})

    return f"最终回答: {thought.content} | {results}"


# ========== 为 Trace 添加评估 ==========

def evaluate_response(run_id: str, output: str, expected: str):
    """为 Trace 添加评估分数"""
    from langsmith.evaluation import StringEvaluator

    evaluator = StringEvaluator(
        evaluation_name="correctness",
        scoring_function=lambda x, y: 1.0 if x == y else 0.0
    )
    client.evaluate_run(
        run_id=run_id,
        evaluator=evaluator,
        reference=expected
    )
```

### 3.3 LangSmith 的独特优势

- **与 LangChain 深度集成**：如果你已经在用 LangChain/LangGraph，接入成本几乎为零
- **Prompt Hub**：Prompt 的版本管理和协作平台
- **数据集和测试**：可以创建测试数据集，批量运行 Agent 并对比结果
- **人工反馈**：支持收集用户的显式和隐式反馈
- **局限**：不提供自建部署选项，数据必须发送到 LangSmith 云

## 四、Phoenix —— Arize 的开源 AI 可观测性

### 4.1 核心概念

Phoenix 是 Arize AI 开源的 AI 可观测性平台，专注于 LLM 应用的 Tracing 和性能分析。与 LangFuse 和 LangSmith 不同，Phoenix 本身就是一个可运行的本地服务，不需要外部依赖。

### 4.2 接入代码

```python
# ========== 启动 Phoenix（本地模式） ==========
# 命令行启动:
#   $ phoenix serve
# 或 Python 内嵌启动:
import phoenix as px
from phoenix.trace import LangChainInstrumentor

# 启动 Phoenix 服务（内嵌模式）
session = px.launch_app()

# ========== OpenTelemetry 方式接入 ==========

from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import SimpleSpanProcessor

# 配置 OTLP 导出到 Phoenix
phoenix_endpoint = "http://localhost:6006/v1/traces"
tracer_provider = TracerProvider()
tracer_provider.add_span_processor(
    SimpleSpanProcessor(OTLPSpanExporter(endpoint=phoenix_endpoint))
)
trace.set_tracer_provider(tracer_provider)

tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("agent-execute") as root:
    with tracer.start_as_current_span("thought") as thought_span:
        thought_span.set_attribute("llm.model", "gpt-4o")
        thought_span.set_attribute("llm.token_count", 630)
        thought_span.set_attribute("llm.response", "plan content...")

    with tracer.start_as_current_span("tool-call") as tool_span:
        tool_span.set_attribute("tool.name", "search_engine")
        tool_span.set_attribute("tool.duration_ms", 2340)


# ========== LangChain 自动接入 ==========

# Phoenix 提供了 LangChain 的自动 Instrumentation
LangChainInstrumentor().instrument()

# 此后所有 LangChain 调用自动被 Phoenix 追踪
from langchain.chains import LLMChain
# ... 正常使用 LangChain


# ========== 手动记录 LLM 调用 ==========

from phoenix.trace import SpanEvaluations
from phoenix.trace.schemas import Span, SpanKind

span = Span(
    name="llm-call",
    span_kind=SpanKind.LLM,
    attributes={
        "llm.model": "gpt-4o",
        "llm.input_messages": [{"role": "user", "content": "你好"}],
        "llm.output_messages": [{"role": "assistant", "content": "你好！"}],
        "llm.token_count.prompt": 100,
        "llm.token_count.completion": 50,
    }
)
session.trace_processor.put(span.to_dict())
```

### 4.3 Phoenix 的独特优势

- **OpenTelemetry 原生**：完全基于 OTLP 协议，可以接入任意 OpenTelemetry 兼容的数据源
- **内嵌运行**：可以在 Jupyter Notebook 中直接启动，适合开发和调试
- **性能分析**：内置了 Embedding 降维可视化（UMAP）、LLM 响应时间分布分析
- **漂移检测**：Arize 平台的自动数据漂移和性能漂移检测
- **局限**：功能完整度不如 LangFuse/LangSmith，社区相对较小

## 五、OpenTelemetry —— 可观测性的"通用语言"

### 5.1 核心概念

**OpenTelemetry（OTel）** 是一个 CNCF 孵化项目，提供了一套统一的 API 和协议，用于生成、采集和导出遥测数据（Trace、Metrics、Logs）。它不是像 LangFuse 那样的"开箱即用"的可观测性平台，而是一个**集成标准**——你可以用它把数据发送到任何兼容的后端。

### 5.2 架构与组件

```
┌────────────────────────────────────────────────────────────┐
│                    OpenTelemetry 架构                        │
│                                                             │
│  Agent 应用                                                   │
│  ┌─────────────────┐                                        │
│  │ OTel SDK         │ ──→ OTLP Exporter                    │
│  │ (自动/手动埋点)   │       │                               │
│  └─────────────────┘       │                               │
│                             ▼                               │
│                      ┌─────────────┐                        │
│                      │ OTel         │                        │
│                      │ Collector     │                        │
│                      │ (可选中间件)   │                        │
│                      └──────┬──────┘                        │
│                             │                                │
│              ┌──────────────┼──────────────┐                │
│              ▼              ▼              ▼                │
│        ┌──────────┐  ┌──────────┐  ┌──────────┐            │
│        │ Jaeger    │  │ Zipkin    │  │ Prometheus│            │
│        │ (Tracing) │  │ (Tracing) │  │ (Metrics)│            │
│        └──────────┘  └──────────┘  └──────────┘            │
│              │              │              │                │
│        ┌─────┴──────┐  ┌───┴────┐  ┌─────┴──────┐         │
│        │ Grafana    │  │ 其他    │  │ Alertmanager│         │
│        │ (可视化)    │  │ 后端    │  │ (告警)      │         │
│        └────────────┘  └────────┘  └────────────┘         │
└────────────────────────────────────────────────────────────┘
```

### 5.3 完整接入配置

```python
# ========== Step 1: OTel SDK 初始化 ==========

from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.resources import Resource

# 创建资源（描述服务身份）
resource = Resource.create({
    "service.name": "agent-service",
    "service.namespace": "production",
    "service.version": "2.1.0",
    "deployment.environment": "prod",
})

# 配置 Tracer Provider
provider = TracerProvider(resource=resource)

# 配置 OTLP Exporter（发送到 Collector 或直接到后端）
otlp_exporter = OTLPSpanExporter(
    endpoint="http://otel-collector:4317",
    timeout=10,
    headers={"Authorization": "Bearer token123"}
)

# 批处理 Span 处理器
processor = BatchSpanProcessor(
    otlp_exporter,
    max_queue_size=2048,
    max_export_batch_size=512,
    schedule_delay_millis=5000,
)
provider.add_span_processor(processor)
trace.set_tracer_provider(provider)

tracer = trace.get_tracer(__name__, "2.1.0")


# ========== Step 2: 自定义 Agent Instrumentation ==========

class OpenTelemetryAgent:
    """基于 OpenTelemetry 的可观测 Agent"""

    def __init__(self):
        self.tracer = trace.get_tracer(__name__)

    async def execute(self, user_query: str) -> str:
        # 创建根 Span
        with self.tracer.start_as_current_span(
            "agent.execute",
            attributes={
                "user_query": user_query,
                "agent.type": "react"
            }
        ) as root_span:

            # Step: Thought
            with self.tracer.start_as_current_span(
                "agent.thought",
                attributes={
                    "step": 1,
                    "llm.model": "gpt-4o"
                }
            ) as thought_span:
                thought = await self._llm_call(user_query)
                thought_span.set_attribute("llm.response", thought)
                thought_span.set_attribute(
                    "llm.token_usage",
                    json.dumps({"prompt": 450, "completion": 180})
                )

            # Step: Action
            with self.tracer.start_as_current_span(
                "agent.action",
                attributes={
                    "step": 2,
                    "tool.name": "search_engine"
                }
            ) as action_span:
                try:
                    results = await self._tool_call(thought)
                    action_span.set_attribute(
                        "tool.result_count", len(results)
                    )
                except Exception as e:
                    action_span.record_exception(e)
                    action_span.set_status(
                        trace.Status(trace.StatusCode.ERROR, str(e))
                    )
                    raise

            root_span.set_attribute("result", str(results))
            return results


# ========== Step 3: OTel Collector 配置 ==========

# otel-collector-config.yml
"""
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 5s
    send_batch_size: 512
  memory_limiter:
    check_interval: 1s
    limit_mib: 500
  attributes:
    actions:
      - key: environment
        value: production
        action: upsert

exporters:
  jaeger:
    endpoint: http://jaeger:14250
    tls:
      insecure: true
  prometheus:
    endpoint: 0.0.0.0:8889
  logging:
    loglevel: debug

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [jaeger, logging]
    metrics:
      receivers: [otlp]
      processors: [batch]
      exporters: [prometheus, logging]
"""
```

### 5.4 OpenTelemetry 的独特优势

- **厂商中立**：数据可以发往 Jaeger、Zipkin、Datadog、Grafana 等任意后端
- **生态系统庞大**：CNCF 项目，几乎所有的可观测性后端都支持 OTLP
- **统一标准**：一个 SDK 同时处理 Trace、Metrics、Logs 三类数据
- **自动 Instrumentation**：对常见的库（HTTP、gRPC、DB）有自动埋点支持
- **局限**：对 LLM/Agent 没有原生语义支持（需要自定义属性），没有内置 UI

## 六、工具选型决策指南

### 6.1 按场景推荐

```
你的场景是什么？
│
├─ 使用 LangChain/LangGraph？
│   ├─ 需要自建部署？ → LangFuse
│   └─ 可以用 SaaS？ → LangSmith（零配置）
│
├─ 需要最大灵活性？
│   ├─ 有运维团队？ → OpenTelemetry + Jaeger + Grafana
│   └─ 需要快速起步？ → Phoenix（内嵌模式）
│
├─ 团队规模小，需要开箱即用？
│   └─ LangFuse（开源可自建，功能齐全）
│
└─ 企业级需求，需要商业支持？
    └─ LangSmith 或 Arize（Phoenix 的商业版）
```

### 6.2 成本对比

| 工具 | 基础设施成本 | 运维成本 | 学习成本 |
|------|------------|---------|---------|
| LangFuse (自建) | 1 台服务器 | 中 (Docker 运维) | 低 |
| LangFuse (Cloud) | 按量付费 (免费额度) | 无 | 低 |
| LangSmith | 按量付费 (~$25/月起步) | 无 | 低 (LangChain 用户) |
| Phoenix | 1 台服务器 / 内嵌 | 低 (单进程) | 中 |
| OTel + Jaeger + Grafana | 2-3 台服务器 | 高 (全栈运维) | 高 |

### 6.3 混合推荐方案

对于生产环境，推荐的**最佳实践是混合使用**：

```
┌────────────────────────────────────────────────────────────┐
│                   生产环境推荐方案                            │
│                                                             │
│  数据采集层: OpenTelemetry SDK（通用标准）                    │
│      ↓                                                      │
│  数据传输层: OTel Collector（缓冲、过滤、采样）              │
│      ↓                                                      │
│  数据存储与展示层:                                           │
│   ├─ Trace 展示: Jaeger 或 LangFuse                        │
│   ├─ 指标监控: Prometheus + Grafana                        │
│   ├─ LLM 专用分析: LangFuse（成本/Trace/Prompt管理）        │
│   └─ 告警: Alertmanager                                   │
│                                                             │
│  优势:                                                      │
│  1. 不绑定任何单一厂商                                       │
│  2. OTel 作为通用数据格式，可随时更换后端                     │
│  3. 分层设计：采集/传输/存储/展示 各层独立扩展                │
└────────────────────────────────────────────────────────────┘
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| OpenTelemetry (OTel) | CNCF 开源项目，提供统一的 Trace/Metric/Log 数据采集和导出标准 |
| OTLP | OpenTelemetry Protocol，OTel 定义的遥测数据传输协议 |
| LangFuse | 开源的 LLM 应用可观测性平台，支持自建和云服务 |
| LangSmith | LangChain 官方的商业可观测性平台，深度集成 LangChain 生态 |
| Phoenix | Arize AI 开源的可观测性平台，原生支持 OpenTelemetry |
| Jaeger | 开源的分布式追踪系统，CNCF 项目，常用于展示 Trace |
| OTel Collector | OpenTelemetry 的数据收集和处理中间件，支持路由、过滤、采样 |
| Instrumentation | 在应用中插入可观测性代码的过程（自动或手动） |
| Span Processor | OTel SDK 中处理 Span 的组件，支持批处理、采样等操作 |
| Self-hosting | 在自己的基础设施上部署和运行可观测性工具 |
