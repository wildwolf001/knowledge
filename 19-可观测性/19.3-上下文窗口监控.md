# 19.3 上下文窗口监控 —— 当前用量百分比、压缩触发预警、性能退化检测

> LLM 的上下文窗口（Context Window）是 Agent 最宝贵的资源——but 也是最有"限"的资源。当上下文使用量接近窗口上限时，模型会表现出注意力分散、早期信息遗忘、指令遵循能力下降等症状。上下文窗口监控的目标是：**在性能退化发生之前，主动管理上下文资源**。

---

## 一、为什么上下文窗口需要监控？

### 1.1 上下文窗口的"隐形污染"

Agent 在执行过程中，每一步的 Thought、Action、Observation 都会被追加到上下文中。随着步骤增加，上下文逐渐膨胀：

```
步骤 1: [系统指令] ~500 tokens  ← 始终保留
步骤 2: [用户查询] ~100 tokens
步骤 3: [Agent Thought 1]  ~200 tokens
步骤 4: [Agent Action 1]   ~50 tokens
步骤 5: [Observation 1]    ~3000 tokens  ← 工具返回大量数据
步骤 6: [Agent Thought 2]  ~250 tokens
步骤 7: [Agent Action 2]   ~80 tokens
步骤 8: [Observation 2]    ~500 tokens
...（持续累积）
步骤 50: [Agent Thought N] ~200 tokens → 上下文已达 80%
```

**问题**：当上下文使用量超过 70% 后，模型对早期内容的注意力开始下降。到 90% 时，Agent 可能已经"忘记"用户最初的问题或系统的关键指令——这就是性能退化。

### 1.2 上下文压力与 Agent 性能的关系

```
Agent 性能 vs 上下文使用率
  性能
  100% ┼
       │         ╱
   90% ┼       ╱
       │      ╱
   80% ┼    ╱                    ← 开始退化
       │   ╱
   70% ┼ ╱
       │╱
   50% ┼─────────────────────────→ 上下文使用率
       0%  25%  50%  75%  100%

三个阶段：
- 安全区 (0-50%)：性能稳定，注意力充足
- 退化区 (50-85%)：性能缓慢下降，需要监控
- 危险区 (85-100%)：性能急剧下降，必须压缩或截断
```

## 二、当前用量监控

### 2.1 Token 用量实时计算

上下文窗口监控的第一步是**实时、精确地计算当前 Token 用量**。不同模型的 Tokenizer 不同（GPT 系列用 cl100k_base，Claude 系列有自己的 BPE 实现），需要使用对应的 Tokenizer 进行计算。

```python
import tiktoken  # OpenAI Tokenizer
from anthropic import Anthropic  # Anthropic SDK 内置 Tokenizer
import json
from typing import List, Dict

class ContextWindowMonitor:
    """上下文窗口监控器"""

    def __init__(self, model: str = "gpt-4o"):
        self.model = model
        self.max_context_tokens = self._get_max_context(model)
        self.tokenizer = self._init_tokenizer(model)

        # Token 用量明细
        self.usage = {
            "system_prompt": 0,
            "conversation_history": 0,
            "tool_results": 0,
            "pending_output": 0
        }

    def _get_max_context(self, model: str) -> int:
        """获取模型的最大上下文窗口大小"""
        context_windows = {
            "gpt-4o": 128000,
            "gpt-4o-mini": 128000,
            "gpt-4-turbo": 128000,
            "gpt-3.5-turbo": 16385,
            "claude-3-opus": 200000,
            "claude-3-sonnet": 200000,
            "claude-3-haiku": 200000,
            "deepseek-chat": 65536,
        }
        return context_windows.get(model, 128000)

    def _init_tokenizer(self, model: str):
        """初始化对应模型的 Tokenizer"""
        if "gpt" in model or "deepseek" in model:
            return tiktoken.encoding_for_model(model)
        elif "claude" in model:
            # Claude 使用自己的 Tokenizer
            return None  # 使用 Anthropic SDK 计数
        else:
            return tiktoken.get_encoding("cl100k_base")

    def count_tokens(self, text: str) -> int:
        """计算文本的 Token 数"""
        if self.tokenizer:
            return len(self.tokenizer.encode(text))
        else:
            # Claude 模型使用 SDK 计数
            return Anthropic().count_tokens(text)

    def calculate_usage(self,
                        system_prompt: str,
                        messages: List[Dict],
                        tool_results: List[str]) -> dict:
        """计算当前上下文使用情况"""
        self.usage["system_prompt"] = self.count_tokens(system_prompt)

        for msg in messages:
            self.usage["conversation_history"] += self.count_tokens(
                json.dumps(msg, ensure_ascii=False)
            )

        for result in tool_results:
            self.usage["tool_results"] += self.count_tokens(result)

        total = sum(self.usage.values())
        usage_percent = (total / self.max_context_tokens) * 100

        return {
            "total_tokens": total,
            "max_tokens": self.max_context_tokens,
            "usage_percent": round(usage_percent, 2),
            "breakdown": {
                "system_prompt": self.usage["system_prompt"],
                "conversation_history": self.usage["conversation_history"],
                "tool_results": self.usage["tool_results"]
            },
            "remaining_tokens": self.max_context_tokens - total,
            "status": self._classify_status(usage_percent)
        }

    def _classify_status(self, percent: float) -> str:
        """根据使用百分比分类状态"""
        if percent < 50:
            return "safe"
        elif percent < 70:
            return "moderate"
        elif percent < 85:
            return "warning"
        else:
            return "critical"
```

## 三、压缩触发策略

### 3.1 分级压缩触发器

当上下文用量达到不同阈值时，触发不同级别的压缩操作：

```python
class ContextCompressionManager:
    """上下文压缩管理器"""

    def __init__(self, monitor: ContextWindowMonitor):
        self.monitor = monitor

        # 压缩阈值配置
        self.thresholds = {
            "light_compress": 70.0,   # 轻度压缩阈值 (%)
            "heavy_compress": 85.0,   # 重度压缩阈值 (%)
            "force_truncate": 95.0,   # 强制截断阈值 (%)
        }

        # 步数基线的压缩触发器
        self.max_steps_before_compress = 10  # 每 10 步检查一次
        self.step_counter = 0

    async def check_and_compress(self,
                                  system_prompt: str,
                                  messages: List,
                                  tool_results: List) -> tuple:
        """检查上下文状态并在需要时触发压缩"""
        usage = self.monitor.calculate_usage(
            system_prompt, messages, tool_results
        )

        self.step_counter += 1
        percent = usage["usage_percent"]

        # 判断是否需要压缩
        should_compress = False
        compress_level = "none"

        if percent >= self.thresholds["force_truncate"]:
            should_compress = True
            compress_level = "force_truncate"
        elif percent >= self.thresholds["heavy_compress"]:
            should_compress = True
            compress_level = "heavy_compress"
        elif percent >= self.thresholds["light_compress"]:
            should_compress = True
            compress_level = "light_compress"
        elif self.step_counter >= self.max_steps_before_compress:
            # 定时压缩（即使用量不高，每 N 步也做一次轻度压缩）
            should_compress = True
            compress_level = "periodic"
            self.step_counter = 0

        if should_compress:
            compressed = await self._apply_compression(
                messages, tool_results, compress_level
            )
            return compressed, compress_level

        return (messages, tool_results), "none"

    async def _apply_compression(self,
                                  messages: List,
                                  tool_results: List,
                                  level: str) -> tuple:
        """根据级别应用不同的压缩策略"""
        if level == "light_compress":
            # 轻度压缩：只压缩 Tool 结果
            compressed_tools = [
                self._summarize_tool_result(r) for r in tool_results
            ]
            return messages, compressed_tools

        elif level == "heavy_compress":
            # 重度压缩：压缩 Tool 结果 + 历史对话
            compressed_tools = [
                self._summarize_tool_result(r, max_tokens=200)
                for r in tool_results
            ]
            compressed_msgs = self._summarize_history(messages)
            return compressed_msgs, compressed_tools

        elif level == "force_truncate":
            # 强制截断：丢弃最早的对话历史
            truncated = self._truncate_oldest(messages)
            return truncated, []

        return messages, tool_results

    def _summarize_tool_result(self,
                                result: str,
                                max_tokens: int = 500) -> str:
        """用 LLM 压缩工具返回结果"""
        # 如果结果本身很小，直接返回
        token_count = self.monitor.count_tokens(result)
        if token_count <= max_tokens:
            return result

        # 通过 LLM 进行摘要压缩
        # 实际工程中可调用专用摘要模型
        summary_prompt = f"将以下内容压缩到 {max_tokens} tokens 以内，保留关键信息：\n{result}"
        # llm_call(summary_prompt)  # 伪代码
        return f"[压缩摘要: 原 {token_count} tokens]"

    def _truncate_oldest(self, messages: List, keep_latest: int = 20) -> List:
        """丢弃最早的消息，只保留最近的 K 条"""
        if len(messages) <= keep_latest:
            return messages
        # 保留系统指令 + 最近的 N 轮对话
        system_msgs = [m for m in messages if m.get("role") == "system"]
        recent_msgs = [m for m in messages if m.get("role") != "system"][-keep_latest:]
        return system_msgs + [{"role": "system", "content": "【已截断早期对话历史】"}] + recent_msgs
```

### 3.2 压缩策略对比

| 策略 | 压缩比 | 信息损失 | 延迟开销 | 适用场景 |
|------|--------|---------|---------|---------|
| **丢弃最早消息** | 高 (50-80%) | 高 | 无 | 紧急截断，快速恢复 |
| **Tool 结果摘要** | 中 (30-70%) | 中 | ~1s (摘要 LLM 调用) | Tool 结果长期占大头时 |
| **对话历史总结** | 高 (60-80%) | 中-高 | ~2s | 长对话场景 |
| **选择性丢弃** | 低 (10-30%) | 低 | 无 | 定期轻量维护 |
| **结构化压缩** | 高 (50-80%) | 低 | ~3s (需要 LLM) | 最佳压缩质量 |

## 四、性能退化检测

### 4.1 退化的早期信号

上下文压力导致的性能退化不是突发性的，而是渐进式的。以下信号可以提前检测到退化：

```
退化信号检测时间线：

上下文 50% ──────────────────────────────────────────────────
         │  基线性能稳定
         │
上下文 65% ──────────────────── 信号1: 指令遵循度下降 ────
         │                      模型偶尔忽略系统指令中的约束
         │
上下文 75% ──────────────────── 信号2: 早期内容遗忘 ────
         │                      模型无法引用对话早期的事实
         │
上下文 85% ──────────────────── 信号3: Token 重复率上升 ──
         │                      模型开始重复已生成的内容
         │
上下文 95% ──────────────────── 信号4: 输出质量急剧下降 ─
         │                      回答变得简短、空洞或矛盾
```

### 4.2 退化检测实现

```python
class DegradationDetector:
    """性能退化检测器"""

    def __init__(self):
        # 退化指标基线
        self.baselines = {
            "instruction_following": 0.95,  # 指令遵循率基线
            "content_repetition": 0.05,     # 内容重复率基线
            "response_length": 200,         # 平均响应长度基线（tokens）
        }
        self.samples = []

    def analyze_step(self, step: dict, context_usage: float) -> dict:
        """分析单步的退化信号"""
        signals = {}

        # 信号1: 指令遵循度下降
        signals["instruction_score"] = self._check_instruction_following(
            step["output"]
        )

        # 信号2: 内容重复率
        signals["repetition_rate"] = self._calc_repetition_rate(
            step["output"]
        )

        # 信号3: 响应长度变化
        signals["response_length"] = self.monitor.count_tokens(
            step["output"]
        )

        # 信号4: 引用准确性
        signals["citation_accuracy"] = self._check_citation_accuracy(
            step["output"], step["context"]
        )

        # 综合退化评分
        degradation_score = self._calc_degradation_score(signals)

        return {
            "signals": signals,
            "context_usage_pct": context_usage,
            "degradation_score": degradation_score,
            "is_degraded": degradation_score > 0.3  # 评分 > 0.3 表示退化
        }

    def _check_instruction_following(self, output: str) -> float:
        """检查输出是否遵循了系统指令（0.0-1.0）"""
        # 实际实现：使用另一个 LLM 或规则引擎验证
        # 返回 0.0 (完全不遵循) 到 1.0 (完全遵循)
        return 0.92

    def _calc_repetition_rate(self, text: str) -> float:
        """计算文本中的 N-gram 重复率"""
        import re
        # 将文本分割为句子
        sentences = re.split(r'[。！？\n]', text)
        if len(sentences) < 2:
            return 0.0

        # 检查是否有重复的句子或短语
        unique_sentences = set(s.strip() for s in sentences if s.strip())
        repetition = 1.0 - (len(unique_sentences) / len(sentences))
        return repetition

    def _calc_degradation_score(self, signals: dict) -> float:
        """计算综合退化评分"""
        score = 0.0

        # 指令遵循度下降
        if signals["instruction_score"] < self.baselines["instruction_following"]:
            score += 0.3

        # 重复率升高
        if signals["repetition_rate"] > self.baselines["content_repetition"]:
            score += 0.3

        # 响应长度异常
        length_ratio = signals["response_length"] / self.baselines["response_length"]
        if length_ratio < 0.5 or length_ratio > 2.0:
            score += 0.2

        return min(score, 1.0)

    def alert_if_degraded(self, result: dict) -> Optional[str]:
        """退化时发出告警"""
        if not result["is_degraded"]:
            return None

        score = result["degradation_score"]
        usage = result["context_usage_pct"]

        if score > 0.7:
            return f"[CRITICAL] 严重性能退化 (评分: {score:.2f}, 上下文: {usage:.1f}%)"
        elif score > 0.3:
            return f"[WARNING] 检测到性能退化 (评分: {score:.2f}, 上下文: {usage:.1f}%)"

        return None
```

## 五、Agent 中的上下文管理策略

### 5.1 预压缩策略

不要等到上下文接近满时才压缩——**在 Agent 设计阶段就嵌入压缩机制**：

```python
class ContextAwareAgent:
    """具备上下文感知能力的 Agent"""

    def __init__(self):
        self.monitor = ContextWindowMonitor()
        self.compressor = ContextCompressionManager(self.monitor)

    async def execute(self, user_query: str):
        """带上下文管理的主执行循环"""
        system_prompt = self._get_system_prompt()
        messages = [{"role": "user", "content": user_query}]
        tool_results = []
        steps = 0

        while not self._is_finished():
            # 1. 每次迭代前检查上下文
            (messages, tool_results), level = \
                await self.compressor.check_and_compress(
                    system_prompt, messages, tool_results
                )

            if level != "none":
                logger.info(f"上下文压缩: {level} (步骤 {steps})")

            # 2. 执行 Agent 步骤
            thought = await self._think(system_prompt, messages, tool_results)
            messages.append({"role": "assistant", "content": thought})

            action = await self._act(thought)
            observation = await self._execute_tool(action)

            tool_results.append(observation)
            steps += 1
```

### 5.2 上下文预算分配

在生产环境中，可以为不同工作流分配上下文预算：

| 工作流类型 | 建议预算 | 策略 |
|-----------|---------|------|
| **单轮问答** | 30% 以内 | 不需要压缩 |
| **多步推理** | 50% 以内 | 定期历史摘要 |
| **文档分析** | 80% 以内 | Tool 结果必须压缩 |
| **长时运行 Agent** | 动态调节 | 持续压缩 + 摘要 |

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 上下文窗口 | LLM 可以接收的最大 Token 数量，不同模型有不同限制 |
| Token 使用率 | 当前上下文已使用的 Token 占最大窗口的百分比 |
| 注意力衰减 | 上下文过长时模型对早期内容的注意力下降的现象 |
| 上下文压缩 | 通过摘要、丢弃、结构化等手段减小上下文体积的技术 |
| 性能退化 | 上下文压力导致的模型输出质量下降 |
| 指令遵循度 | Agent 生成的输出与系统指令中约束的匹配程度 |
| 内容重复率 | Agent 输出中出现重复内容的比例，退化的重要信号 |
| 预压缩 | 在 Agent 设计阶段嵌入的提前压缩机制，而非等到接近极限才触发 |
