### 1.2 架构差异详解

**MoE（Mixture of Experts）解读**：

MoE 的核心思想是用多个"专家"子网络代替单个 FFN 层，对每个输入 token 只激活部分专家，从而在**总参数量巨大**的情况下保持**激活参数可控**。

```
Dense 架构（Qwen4-72B）:
每个 token → FFN₁ → 激活全部 76B 参数

MoE 架构（DeepSeek-V4）:
每个 token → Router → 选择 8/256 个专家 → 激活 37B
                          ↑
                   专家选择器，只激活约 3% 的参数
```

**MLA（Multi-head Latent Attention）——DeepSeek 的核心创新**：

DeepSeek-V4 延续了 V3 的 MLA 架构。MLA 在保持表达能力的同时，将 KV Cache 压缩到一个低维潜空间中，大幅降低长上下文的显存占用（详见 [1.1 节](./1.1-Transformer自注意力与KV-Cache.md)）。这使 DeepSeek-V4 在处理 256K 上下文时的 KV Cache 仅为同等 MHA 模型的 5-10%。

## 七、2026 关键洞察与技术趋势

### 7.1 2026 关键洞察

1. **Sonnet 级模型达到去年 Opus 级能力（模型能力民主化）**

   Claude Sonnet 4.6 在 SWE-bench（79.6% vs 80.8%）和 OSWorld（72.5% vs 72.7%）上几乎与 Opus 4.6 持平，而成本仅为其 60%。这标志着高端模型能力的快速"民主化"——前一年的旗舰能力正在成为次年主流级别。Sonnet 4.6 以 1/5 的成本匹配 2025 年 Opus 4.5 的编码能力。

2. **Computer Use 成为新的差异化维度**

   Claude 系列在 OSWorld 基准上的显著领先（Opus 72.7%, Sonnet 72.5% vs GPT-5.3-Codex 64.7%）使 Computer Use 成为模型选择的关键维度。能够自主操作计算机界面的能力已从实验功能演变为核心差异化能力。这在 Agent 场景中是关键优势，尤其在需要 GUI 交互的自动化任务中。

3. **成本效率成为选型核心指标**

   随着多款模型在 SWE-bench 上趋近（前三名差距 <2%），成本效率成为工程选型的决定性因素。DeepSeek-V4 的每美元 SWE-bench 得分是 Opus 的 100 倍以上（292 vs 2.7），而 Sonnet 4.6 则以合理成本提供接近顶级的性能。模型选型已从"哪个最好"演变为"哪个在预算内最好"。

4. **1M 上下文窗口成为新标准**

   Claude Opus 4.6 和 Sonnet 4.6 均支持 1M 上下文，Gemini 3.1 Pro 支持 2M。2025 年的 128K-256K 标准已被全面超越，长上下文处理能力从"加分项"变为"必备项"。大量 Agent 场景（代码库分析、文档处理、长对话）因此受益。

### 7.2 技术趋势洞察

1. **MoE 继续主导顶级架构**：除 Qwen4-72B 外，顶级模型全部采用 MoE 架构。激活参数范围从 37B（DeepSeek-V4）到 ~350B（GPT-5.3-Codex），体现了架构效率的巨大差异。

2. **Agent 原生能力成为核心竞争点**：Computer Use、Tool Call、代码执行等 Agent 原生支持能力，已从附加功能演进为模型竞争力的核心维度。不支持 Computer Use 的模型在 2026 年的 Agent 选型中面临显著劣势。

3. **1M+ 上下文全面普及**：Claude 全系列（除 Haiku）和 Gemini 均已支持 1M 以上上下文，MiniMax 在 2025 年的创新已变为行业标配。

4. **中文模型的持续崛起**：DeepSeek-V4 和 Qwen4 在全球竞争力持续提升，在 SWE-bench 等关键基准上缩小了与国际顶级的差距。

5. **模型分层与专业化**：Opus → Sonnet → Haiku 的三层架构被证明是有效的市场覆盖策略。GPT 系列的 Codex 专业化分支（侧重编码与终端操作）和 Gemini 的 Pro 路线也走向差异化竞争。通用模型的时代正在向专业化模型演进。

## 关键概念速查

| 术语 | 解释 |
|------|------|
| MoE (Mixture of Experts) | 混合专家架构，总参数量大但每个 token 只激活部分专家 |
| 激活参数 | MoE 架构中每个 token 实际调用的参数量 |
| MLA (Multi-head Latent Attention) | DeepSeek 的低维潜空间注意力，大幅降低 KV Cache |
| Token 压缩比 | 同一文本在不同模型 tokenizer 下 token 数的比率 |
| SWE-bench | 软件工程任务基准，评测模型解决真实 GitHub Issue 的能力 |
| OSWorld | 计算机使用基准，评测模型在桌面环境中完成复杂任务的能力 |
| ARC-AGI-2 | 抽象与推理挑战基准，评测模型的泛化推理与模式识别能力 |
| HLE (Humanity's Last Exam) | 人类终极考试，包含跨学科高难度问题的综合基准 |
| BrowseComp | 网页浏览理解基准，评测模型在复杂网页中检索与整合信息的能力 |
| Terminal-Bench 2.0 | 终端操作基准，评测模型通过命令行与操作系统环境交互的能力 |
| FrontierMath | 前沿数学基准，包含研究生级及以上的高级数学问题 |
| MCP Atlas | 评测模型对 MCP（Model Context Protocol）协议支持度的综合基准 |
| Computer Use | 模型操控计算机图形界面（GUI）的能力，包括移动鼠标、点击、输入等操作 |
| Dense 架构 | 传统 Transformer，所有参数对每个 token 都激活 |
| Needle-in-a-Haystack | 长文档中检索特定信息的准确率测试 |
