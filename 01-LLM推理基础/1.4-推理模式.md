# 1.4 推理模式——从 Next-Token 到推理时扩展

> 大语言模型在最底层只是一个"下一个 token 预测器"，但通过不同的推理模式（Next-Token / CoT / ToT / Thinking Tokens / Test-time Compute），这个简单的机制涌现出了复杂的推理能力。理解不同模式的原理和取舍，是设计 Agent 推理策略的基础。

---

## 一、基础模式：Next-Token Prediction

### 1.1 核心原理

LLM 的训练目标是最简单的——给定前 t 个 token，预测第 t+1 个 token 的概率分布：

```
P(token_{t+1} | token_1, token_2, ..., token_t)
```

**推理时**，模型逐 token 生成：

```python
def generate_next_token(model, input_ids, temperature=0.7, top_p=0.9):
    logits = model(input_ids)  # 前向传播，输出所有位置的 logits
    last_logits = logits[:, -1, :]  # 只取最后一个位置的输出
    probs = softmax(last_logits / temperature)
    
    # Top-P 采样（Nucleus Sampling）
    sorted_probs, sorted_indices = sort(probs, descending=True)
    cumulative_probs = cumsum(sorted_probs)
    cutoff_idx = find_first(cumulative_probs >= top_p)
    valid_indices = sorted_indices[:cutoff_idx + 1]
    
    # 从 valid 集合中采样
    next_token = sample_from(valid_indices, probs[valid_indices])
    return next_token
```

### 1.2 朴素生成的局限

- **无回溯**：一旦生成了错误的 token，后续输出都会基于错误前提
- **无计划**：每一步只考虑局部最优，没有全局策略
- **无验证**：不会检查生成的内容是否合理
- **深度不足**：复杂推理需要在多个步骤间保持一致性

这些局限催生了更复杂的推理模式。

## 二、推理模式演进对比

| 模式 | 核心思想 | Token 开销 | 准确性 | 适用场景 |
|------|---------|-----------|--------|---------|
| Next-Token | 逐 token 贪心生成 | 低 | 低-中 | 简单问答、翻译、摘要 |
| CoT | "让我们一步步思考" | 中 | 中-高 | 数学、逻辑推理、决策 |
| CoT-SC | 多次 CoT + 投票 | 高 | 高 | 需要高可靠性的场景 |
| ToT | 树状探索 + 剪枝 | 很高 | 很高 | 规划、搜索、创作 |
| Thinking Tokens | 内部推理专用标记 | 中-高 | 高 | 复杂推理、代码、数学 |
| Test-time Compute | 推理阶段扩展计算量 | 极高 | 极高 | 竞赛数学、科学推理 |

## 三、Chain-of-Thought (CoT)

### 3.1 原理

Chain-of-Thought（Wei et al., 2022）通过在 Prompt 中加入"Let's think step by step"或展示中间推理步骤，诱导模型在生成最终答案前产出一系列中间推理步骤。

**数学推理示例**：

```
Prompt:
问：小明有 5 个苹果，小红有 3 个苹果，他们一共有几个苹果？
让我们一步步思考。

回答：
小明有 5 个苹果。
小红有 3 个苹果。
5 + 3 = 8
所以他们一共有 8 个苹果。
```

**Zero-shot CoT**（Kojima et al., 2022）发现，只需在问题后追加"Let's think step by step"即可显著提升推理准确性，无需示例。这对于 Agent 系统非常实用——可以将该短语注入系统 Prompt。

### 3.2 CoT 的工程效果

| 任务类型 | 无 CoT | 有 CoT | 提升幅度 |
|---------|--------|--------|---------|
| 数学推理（GSM8K） | ~18% | ~58% | +40% |
| 符号推理 | ~40% | ~80% | +40% |
| 常识推理 | ~75% | ~82% | +7% |
| 逻辑推理 | ~60% | ~85% | +25% |

**关键发现**：CoT 对数学和符号推理的提升最大，对常识推理的提升有限。因为常识推理依赖的是模型参数知识而非多步演绎。

### 3.3 CoT 消耗的 token

CoT 会消耗额外的输出 token，这对成本和延迟有直接影响：

```python
def cot_cost_estimate():
    """
    标准回答: "8 个苹果" → 4 个 token
    CoT 回答: "小明有 5 个苹果。小红有 3 个苹果。5+3=8。所以一共有 8 个苹果。"
            → 约 40 个 token（10x 增长）
    """
    pass
```

在构建 Agent 时，需要对非必要的简单任务**取消 CoT**，仅在复杂推理步骤启用——这被称为"自适应 CoT"策略（详见 [第 4 章 Agent 工作流设计](../04-Agent工作流设计/)）。

## 四、Chain-of-Thought-Self-Consistency (CoT-SC)

CoT-SC（Wang et al., 2022）是 CoT 的增强版本。基本流程：

```python
def cot_self_consistency(model, question, n_samples=5, temperature=0.7):
    """
    1. 多次采样：用不同的随机种子生成 n 条 CoT 链
    2. 投票选择：选取出现频率最高的最终答案
    """
    answers = []
    for _ in range(n_samples):
        response = model.generate(
            question + "\n让我们一步步思考。",
            temperature=temperature
        )
        final_answer = extract_answer(response)
        answers.append(final_answer)
    
    # 多数投票
    from collections import Counter
    voted_answer = Counter(answers).most_common(1)[0][0]
    return voted_answer
```

**效果**：在数学推理任务上，CoT-SC（n=5）将准确率从 CoT 的 ~58% 提升至 ~72%，但 Token 消耗增加了 5 倍。

**局限性**：如果大多数 CoT 链都犯了同样的错误，投票也无法纠正（系统性偏见问题）。

## 五、Tree-of-Thoughts (ToT)

### 5.1 原理

Tree-of-Thoughts（Yao et al., 2023）将推理过程从**线性链**扩展为**树状搜索**。模型在每一步生成多个可能的"思考分支"，然后评估每个分支的前景，选择最有希望的方向继续探索。

```
                   问题
                  /    \
             想法 A    想法 B
            /   |    \      \
         A1    A2    A3    B1
        /      |      \
    A1a  A1b  A2a    A3a A3b
```

### 5.2 搜索策略

ToT 使用 BFS（广度优先）或 DFS（深度优先）进行搜索，核心是**评估函数**（由 LLM 本身或一个独立的评估模型执行）：

```python
def tree_of_thoughts(model, problem, max_depth=3, branch_factor=3):
    """简化的 ToT 实现"""
    leaves = [problem]
    
    for depth in range(max_depth):
        new_leaves = []
        
        for leaf in leaves:
            # 生成多个候选下一步思考
            candidates = model.generate(
                leaf + "\n接下来可能的思路有：",
                n=branch_factor,  # 生成多条
                temperature=0.8
            )
            
            # 评估每个候选
            evaluations = model.generate(
                candidate + "\n这条思路正确吗？评分：",
                temperature=0.0  # 确定性评估
            )
            
            # 保留最有前途的（TOP-K 剪枝）
            sorted_candidates = sort_by_score(candidates, evaluations)
            new_leaves.extend(sorted_candidates[:branch_factor])
        
        leaves = new_leaves
    
    # 从最优路径生成最终答案
    best_path = select_best_path(leaves, model)
    return model.generate(best_path + "\n因此答案是：")
```

### 5.3 ToT 的成本分析

每条分支需要完整的推理链，token 消耗量随搜索深度和分支因子指数增长：

```
深度 3 × 宽度 3 → 最多 27 条完整路径
每条路径 100 token → 总计 2700 token
CoT 基线 → 300 token
→ ToT 约 9 倍于 CoT
```

ToT 的工程价值在于**高风险决策**（代码架构设计、安全策略规划、复杂 API 编排）——在这些场景中，计算成本远低于犯错成本。

## 六、Thinking Tokens

### 6.1 概念

Thinking Tokens 是一种专用的特殊 token，用来明确标记模型的"内部推理过程"。代表模型包括：
- **DeepSeek-R1**：使用 `<think>` 和 `</think>` 标记推理过程
- **Claude**：内部使用思考标记（在 API 的 `thinking` 参数中控制）
- **OpenAI o1/o3**：在不可见的内部推理链中使用专用 token

### 6.2 工作原理

```
用户输入: "如果 2x + 5 = 15，求 x 的值"

模型的解码过程（简化）:

[<BOS>][用户: "如果 2x + 5 = 15，求 x 的值"]
→ <think>
→ 这是一个简单的一元一次方程。
→ 2x + 5 = 15
→ 两边同时减去 5: 2x = 10
→ 两边同时除以 2: x = 5
→ </think>
→ 答案是 5。[<EOS>]
```

### 6.3 Thinking Tokens vs 普通人可见的 CoT

| 维度 | 普通人可见的 CoT | Thinking Tokens |
|------|-----------------|----------------|
| 可见性 | 用户可见 | 通常对用户隐藏（或可选择显示） |
| 控制粒度 | 模型自然产出 | 通过特殊 token 精确控制推理开始/结束 |
| 推理深度 | 模型自行决定 | 可通过参数显式控制（如"思考多少步"） |
| 安全风险 | 推理过程暴露，可能泄露提示词、PII 等 | 可控制推理过程是否暴露给用户 |
| 训练方式 | 可在推理数据上微调 | 需要专门的训练阶段（强化学习或蒸馏） |
| 代表模型 | GPT-4、Llama 系列 | DeepSeek-R1、OpenAI o1、Claude 4 部分能力 |

### 6.4 工程集成

在 Agent 系统中，Thinking Tokens 可以通过 API 参数控制：

```python
# DeepSeek-R1 API 调用示例
response = client.chat.completions.create(
    model="deepseek-r1",
    messages=[{"role": "user", "content": "分析这段代码的性能瓶颈..."}],
    # 通过 max_thinking_tokens 控制推理预算
    extra_body={
        "thinking_mode": True,
        "max_thinking_tokens": 2048,
    }
)

# 返回结果中包含 reasoning_content
print(response.choices[0].message.reasoning_content)
# → "让我逐步分析这段代码... 首先..."
print(response.choices[0].message.content)
# → "经过分析，代码的性能瓶颈主要在..."
```

## 七、推理时扩展（Test-time Compute）

### 7.1 核心思想

Test-time Compute（或称 Inference-time Scaling）是在推理阶段**动态分配更多计算量**来提升模型在复杂任务上的表现。这是 2024-2025 年最重要的推理范式变化。

**核心洞见**：对于复杂问题，与其增加模型参数量，不如在推理阶段让模型"思考更久"。

### 7.2 扩展策略对比

| 策略 | 原理 | Token 消耗 | 效果提升 |
|------|------|-----------|---------|
| 朴素 CoT | 鼓励逐步推理 | 3-10x | 中 |
| CoT-SC | 多次采样 + 投票 | 5-20x | 中-高 |
| ToT | 树状搜索 + 评估 | 10-100x | 高 |
| **Process Reward Model (PRM)** | 每一步给予奖励信号，选择最优路径 | 10-50x | 很高 |
| **Self-Play/Verification** | 生成多个答案 + 用验证器选择 | 10-50x | 很高 |
| **Search + Rerank** | 生成大量候选 + 重排序 | 10-100x | 很高 |

### 7.3 Test-time Scaling Laws

OpenAI o1 的技术报告和 DeepSeek-R1 论文揭示了一个关键关系：

```
推理准确率与推理时计算量呈对数线性关系（在合理范围内）：

Accuracy ∝ log(Test-time Compute)

具体表现：
- 简单问题（1 步推理）：增加计算量收益很小
- 中等问题（3-5 步推理）：计算量翻倍可提升 10-15%
- 复杂问题（>10 步推理）：计算量翻倍可提升 20-30%

→ 存在"饱和点"——超过某阈值后继续增加计算的边际收益递减
```

### 7.4 工程实现：自适应分配

```python
def adaptive_reasoning_allocator(model, question, max_budget=10000):
    """
    根据问题复杂度动态分配推理计算量
    
    简单问题 → 直接回答（低预算）
    复杂问题 → CoT（中等预算）
    极难问题 → CoT-SC 或 PRM（高预算）
    """
    # Step 1: 快速评估问题复杂度（仅需 ~50 token）
    complexity = model.generate(
        f"以下问题需要多少步推理？只输出数字：\n{question}",
        temperature=0.0,
        max_tokens=5
    )
    
    steps = parse_number(complexity)
    
    if steps <= 1:
        # 简单问题：直接回答
        return model.generate(question, max_tokens=100)
    elif steps <= 5:
        # 中等复杂度：CoT
        return model.generate(
            question + "\n让我们一步步思考。",
            max_tokens=min(steps * 200, max_budget)
        )
    else:
        # 复杂问题：CoT-SC + 投票
        return cot_self_consistency(
            model, question,
            n_samples=max(3, min(10, steps)),
            max_total_tokens=max_budget
        )
```

## 八、模式选择的工程指南

### 8.1 按任务选择

| 任务类型 | 推荐模式 | 理由 |
|---------|---------|------|
| 简单事实问答 | Next-Token | CoT 增加延迟无收益 |
| 数学计算 | CoT / CoT-SC | 逐步推理效果显著 |
| 代码生成 | CoT / Thinking Tokens | 结构化推理提升代码正确率 |
| 逻辑推理 | CoT / ToT | 多路径探索减少盲点 |
| 规划任务 | ToT / PRM | 需要评估多个方案的可行性 |
| 多步 Agent 任务 | CoT + Tool Calls | 工具调用与推理交织 |

### 8.2 成本预算指南

```
每任务 token 预算建议：
  简单任务:   ≤ 500 tokens 输出
  标准 Agent任务: 2K-5K tokens 输出
  复杂推理:  5K-20K tokens 输出
  竞赛级:    20K-200K+ tokens 输出
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Next-Token Prediction | LLM 最基本的生成方式，逐 token 自回归生成 |
| Chain-of-Thought (CoT) | 通过在回答中插入中间推理步骤来提升复杂推理能力 |
| CoT-Self-Consistency | 多次 CoT 采样 + 多数投票，提升结果可靠性 |
| Tree-of-Thoughts (ToT) | 树状搜索多个推理路径，评估并剪枝 |
| Thinking Tokens | 专用的特殊 token 标记推理过程，精度可控 |
| Test-time Compute | 推理阶段动态增加计算量以提升复杂任务表现 |
| Process Reward Model (PRM) | 对推理的每一步给予奖励信号，指导最优路径选择 |
| 自适应推理 | 根据问题复杂度动态分配推理计算预算 |
