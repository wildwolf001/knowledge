# 26.3 World Model 预测式执行

> World Model（世界模型）预测式执行是指 Agent 在执行关键操作之前，先在内部构建一个"模拟世界"来推演可能结果，评估各方案的代价与收益，再选择最优路径执行。这类似于人类在做出重要决策前的"脑内模拟"——在行动之前先思考。

---

## 一、什么是 World Model 预测式执行

### 1.1 动机：减少不可逆操作的代价

Agent 在真实环境中执行操作会带来实实在在的代价：

- **财务代价**：调用收费 API、下单购买、执行金融交易。
- **时间代价**：长时间运行的任务可能浪费计算资源。
- **声誉代价**：错误地回复客户、发送不合适的邮件。
- **安全代价**：执行文件删除、数据库写入等不可逆操作。

传统 Agent 的"先执行再看"模式（Execute-then-Correct）在面对这些场景时风险极高。World Model 提供了一种"先模拟再执行"（Simulate-then-Execute）的替代范式。

### 1.2 核心概念

```
传统 Agent 执行流程：
输入 → 思考 → 行动 → 观察结果 → 反思 → 继续

World Model Agent 执行流程：
输入 → 思考 → 
        ├→ (模拟分支1) 模拟结果 → 评估代价 → 
        ├→ (模拟分支2) 模拟结果 → 评估代价 → 
        ├→ (模拟分支3) 模拟结果 → 评估代价 → 
        └→ 选择最优路径 → 执行 → 验证结果
```

**World Model** 在 Agent 语境下指一个**轻量级的可执行预测模型**，它能在不调用真实环境的情况下，预测某个操作可能导致的结果。

## 二、World Model 的技术实现

### 2.1 三种实现层次

| 层次 | 方法 | 精度 | 成本 | 适用场景 |
|------|------|------|------|----------|
| **L0: Prompt-based** | 用 LLM 自身做模拟，"假设我执行了操作 X，结果会怎样？" | 中 | 极低 | 简单决策验证 |
| **L1: 专用预测模型** | 训练一个轻量级模型专门预测操作结果 | 高 | 中 | 高频操作场景 |
| **L2: 环境沙箱** | 在隔离的沙箱环境中真实执行 | 最高 | 高 | 高风险操作 |

### 2.2 L0 实现：Prompt-based World Model

这是最轻量级的实现方式，不需要额外模型或基础设施：

```python
class PromptBasedWorldModel:
    """
    基于 LLM Prompt 的轻量级 World Model。
    通过让 LLM "角色扮演"环境来预测操作结果。
    """
    
    def simulate(self, agent_plan: str, environment_context: dict) -> SimulationResult:
        simulation_prompt = f"""
        你是一个环境模拟器。给定以下上下文和 Agent 计划，
        请模拟执行这个计划，预测：
        1. 每一步的执行结果
        2. 可能出现的错误或异常
        3. 目标是否能够达成
        4. 潜在的风险和副作用

        环境上下文：
        {json.dumps(environment_context, indent=2, ensure_ascii=False)}

        Agent 计划：
        {agent_plan}

        请以 JSON 格式返回模拟结果：
        {{
            "success_probability": 0.0-1.0,
            "predicted_steps": [
                {{"step": 1, "action": "...", "predicted_result": "..."}}
            ],
            "risks": ["风险1", "风险2"],
            "recommended": true/false,
            "alternative_plan": "如果推荐为 false，给出替代方案"
        }}
        """
        
        response = llm_call(simulation_prompt)
        return SimulationResult.parse(response)
```

**应用示例**：Agent 收到用户请求"帮我取消今天下午 3 点的会议并重新预订明天同一时间"。

```python
# 实际执行前，World Model 进行模拟
simulation = world_model.simulate(
    agent_plan="1. 查询日历 → 2. 找到3点会议 → 3. 取消该会议 → 4. 创建明天3点新会议",
    environment_context={
        "user_calendar_today": ["14:00-15:00 团队周会", "15:00-16:00 客户沟通"],
        "user_calendar_tomorrow": ["09:00-10:00 晨会"]
    }
)

# 模拟结果可能揭示问题：
# - 今天15:00的会议是"客户沟通"，取消可能有商务风险
# - 明天15:00 似乎可用，但需要确认
# - World Model 建议：先确认"客户沟通"是否可以改期，再执行取消
```

### 2.3 L1 实现：专用预测模型

对于高频且模式固定的操作场景，可以训练一个轻量级专用预测模型。例如：

**金融交易 Agent 的 World Model**：

```
输入特征：
- 当前市场状态（价格、成交量、波动率）
- Agent 计划执行的操作（买入/卖出/持仓）
- 历史类似操作的 outcomes

输出预测：
- 成功概率
- 预期收益/损失分布（P50/P90/P10）
- 操作延迟
- 市场影响估计
```

### 2.4 L2 实现：环境沙箱

对于高风险操作（如数据库写入、文件删除），使用真实的隔离环境进行模拟：

```
┌─────────────────────────────────────────────┐
│              Agent 主流程                      │
│                                              │
│  输入 → 计划生成 → World Model 评估 → 执行    │
│                          │                   │
└──────────────────────────┼───────────────────┘
                           │ L2 沙箱
                           ▼
┌─────────────────────────────────────────────┐
│              环境沙箱 (Sandbox)               │
│                                              │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐  │
│  │ 数据库沙箱 │  │ 文件系统沙箱│  │ API 模拟器 │  │
│  │ (事务隔离) │  │ (临时目录) │  │ (Mock Server)│  │
│  └──────────┘  └──────────┘  └───────────┘  │
│                                              │
│  执行计划 → 捕获结果 → 清理沙箱 → 返回评估    │
└─────────────────────────────────────────────┘
```

## 三、预测式执行的工作流程

### 3.1 完整流水线

```
┌──────────────────────────────────────────────────────────────────┐
│                     World Model 预测式执行流程                       │
│                                                                  │
│  1. 计划生成阶段                                                   │
│  ┌─────────────────────────────────────────────┐                 │
│  │ Agent 分析用户请求，生成多个候选执行计划         │                 │
│  │ Plan A: 直接取消会议                          │                 │
│  │ Plan B: 先发消息确认再取消                     │                 │
│  │ Plan C: 委托助手处理                          │                 │
│  └─────────────────────────────────────────────┘                 │
│                            │                                     │
│  2. 模拟评估阶段                                                   │
│  ┌─────────────────────────────────────────────┐                 │
│  │ World Model 对每个计划进行模拟预测：            │                 │
│  │                                            │                 │
│  │  Plan A: 成功概率 60% | 风险: 客户不满意      │                 │
│  │  Plan B: 成功概率 95% | 风险: 多花2分钟       │                 │
│  │  Plan C: 成功概率 80% | 风险: 委托失败        │                 │
│  └─────────────────────────────────────────────┘                 │
│                            │                                     │
│  3. 方案选择阶段                                                   │
│  ┌─────────────────────────────────────────────┐                 │
│  │ 综合代价-收益分析，选择最优方案                │                 │
│  │ → 选择 Plan B (先确认再取消)                  │                 │
│  └─────────────────────────────────────────────┘                 │
│                            │                                     │
│  4. 执行与验证阶段                                                 │
│  ┌─────────────────────────────────────────────┐                 │
│  │ 执行选定方案，并持续验证结果是否与预测一致       │                 │
│  │ 如果偏离预测 → 触发重新规划                    │                 │
│  └─────────────────────────────────────────────┘                 │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 代价评估公式

```python
def evaluate_plan_cost(plan: Plan, world_model: WorldModel) -> float:
    """
    评估一个计划的综合代价。分数越低越好。
    """
    simulation = world_model.simulate(plan)
    
    # 直接成本
    direct_cost = plan.estimated_api_calls * API_UNIT_COST
    
    # 风险成本
    risk_cost = 0
    for risk in simulation.risks:
        risk_cost += risk.probability * risk.severity
    
    # 时间成本
    time_cost = plan.estimated_duration_seconds * TIME_UNIT_COST
    
    # 机会成本（选择此计划放弃其他机会的代价）
    opportunity_cost = plan.opportunity_cost
    
    # 综合代价
    total_cost = (
        WEIGHT_DIRECT * direct_cost +
        WEIGHT_RISK * risk_cost +
        WEIGHT_TIME * time_cost +
        WEIGHT_OPPORTUNITY * opportunity_cost
    )
    
    return total_cost
```

### 3.3 预测-执行差异检测

执行过程中，Agent 需要持续比较**预测结果**与**实际结果**：

```python
class ExecutionMonitor:
    def __init__(self, world_model: WorldModel):
        self.world_model = world_model
        self.threshold = 0.3  # 差异阈值
    
    def monitor_step(self, step: int, predicted: StepResult, actual: StepResult):
        deviation = self._compute_deviation(predicted, actual)
        
        if deviation > self.threshold:
            # 差异过大，触发重新规划
            logger.warning(f"Step {step} deviation {deviation:.2f} > threshold")
            return Action.REPLAN
        elif deviation > self.threshold * 0.5:
            # 中等差异，调整后续预测
            return Action.ADJUST
        else:
            # 正常执行
            return Action.CONTINUE
```

## 四、应用场景

### 4.1 数据库操作 Agent

**场景**：Agent 执行 Text-to-SQL 查询。

```
Without World Model:
  用户问："删除所有2023年以前的订单记录"
  Agent → 直接执行 DELETE FROM orders WHERE year < 2023
  → 删除了 100 万条记录，但其实用户只想删除"已归档"的订单

With World Model:
  用户问："删除所有2023年以前的订单记录"
  Agent → World Model 预测:
    "执行 DELETE 会删除约 100 万条记录，不可逆。
     建议：先 SELECT COUNT(*) 确认数量，再询问用户是否要备份"
  → Agent 先执行 SELECT，确认后要求用户二次确认
  → 安全执行
```

### 4.2 API 编排 Agent

**场景**：Agent 编排多个 API 调用来完成复杂工作流。

```python
# World Model 预测 API 编排的连锁效应
def orchestrate_with_simulation(agent, workflow: Workflow):
    # 阶段1：模拟
    simulation_results = []
    for step in workflow.steps:
        sim = world_model.simulate_api_call(
            endpoint=step.endpoint,
            method=step.method,
            payload=step.payload,
            depends_on=simulation_results[-1] if simulation_results else None
        )
        simulation_results.append(sim)
        
        if sim.predicted_status == "error":
            # 提前发现错误链，避免无效调用
            return AlternativePath(step_error=step)
    
    # 阶段2：执行（仅当模拟全部通过）
    return agent.execute_workflow(workflow)
```

### 4.3 邮件/消息发送 Agent

**场景**：Agent 代替用户发送重要邮件。

```
World Model 评估邮件内容：
- 检查语气是否合适
- 预测收件人的可能反应
- 检查是否包含敏感信息
- 检查附件是否正确

如果预测到"收件人可能误解"或"语气过于生硬"，Agent 会在发送前修改内容。
```

## 五、World Model 的局限与挑战

| 挑战 | 说明 | 应对 |
|------|------|------|
| **预测偏差** | World Model 的预测可能系统性偏离真实结果 | 定期校准，用真实结果修正预测模型 |
| **过度模拟** | 每个操作都模拟会导致延迟大幅增加 | 分层决策：低风险操作跳过模拟，高风险操作强制模拟 |
| **模拟粒度** | 太粗的模拟没有意义，太细的模拟成本高 | 自适应粒度：根据操作风险等级调整模拟深度 |
| **循环依赖** | 模拟自身的模拟（无限递归） | 设定模拟深度上限（Max Sim Depth） |
| **分布外泛化** | 遇到训练数据中未见过的情况时预测不准 | 结合 L0 + L2 兜底 |

## 六、关键概念速查表

| 概念 | 英文 | 解释 |
|------|------|------|
| 世界模型 | World Model | 用于预测操作结果的环境模拟器 |
| 预测式执行 | Predictive Execution | 先模拟再执行的操作范式 |
| L0 模拟 | L0 Simulation | 基于 LLM Prompt 的轻量级模拟 |
| 环境沙箱 | Environment Sandbox | 隔离的真实执行环境 |
| 代价评估 | Cost Evaluation | 综合计算操作的直接、风险、时间、机会成本 |
| 差异检测 | Deviation Detection | 比较预测结果与实际结果的差异 |
| 重新规划触发 | Replan Trigger | 当实际执行偏离预测时的修正机制 |
| 自适应粒度 | Adaptive Granularity | 根据风险等级调整模拟深度的策略 |
| 不可逆操作 | Irreversible Operation | 一旦执行无法撤销的操作 |
| 预测偏差 | Prediction Bias | 模拟结果与真实结果的系统性偏离 |
