# 26.4 Computer Use Agent

> Computer Use Agent（CUA，计算机使用 Agent）是一种能够像人类一样操作计算机界面的 AI Agent——它通过截图理解屏幕内容、用视觉模型定位交互元素、规划操作步骤、最终通过模拟鼠标键盘来执行操作。CUA 是实现"通用数字助手"愿景的关键技术路径。

---

## 一、什么是 Computer Use Agent

### 1.1 定义与场景

Computer Use Agent 与传统 API-based Agent 的核心区别在于交互方式：

| 维度 | API-based Agent | Computer Use Agent |
|------|----------------|-------------------|
| **交互接口** | RESTful API / SDK | GUI（图形用户界面） |
| **理解方式** | JSON Schema / 结构化数据 | 屏幕截图 / 视觉识别 |
| **操作方式** | API 调用 | 鼠标点击 / 键盘输入 |
| **适用范围** | 有 API 的系统 | 任意 GUI 应用（含无 API 的 legacy 系统） |
| **鲁棒性** | 依赖 API 稳定性 | 依赖 UI 视觉稳定性 |

典型应用场景：
- **自动化测试**：自动执行 UI 测试用例，无需编写 selector。
- **遗留系统操作**：操作只提供 Web 界面没有 API 的老系统。
- **跨平台任务**：同时操作 Web 应用、桌面软件和移动端应用。
- **RPA 升级**：替代传统基于坐标/模板匹配的 RPA，提升适应性。

### 2.2 阶段一：截图获取（Screen Capture）

CUA 的第一步是获取当前屏幕状态。根据目标平台不同，截图方式各异：

```python
class ScreenCapture:
    """多平台截图获取器"""
    
    def capture(self, platform: str, target: str) -> ScreenImage:
        if platform == "web":
            # 通过 CDP (Chrome DevTools Protocol) 截图
            return self._capture_cdp(target)
        elif platform == "windows":
            # Win32 API 截图
            return self._capture_win32(target)
        elif platform == "macos":
            # CoreGraphics / AVFoundation 截图
            return self._capture_macos(target)
        elif platform == "linux":
            # X11/Wayland 截图
            return self._capture_linux(target)
        elif platform == "mobile":
            # ADB (Android) / XCUITest (iOS) 截图
            return self._capture_mobile(target)
    
    def _capture_cdp(self, url: str) -> ScreenImage:
        """通过 CDP 获取浏览器截图"""
        # 使用 Playwright/Selenium CDP 协议
        screenshot = page.screenshot(full_page=True)
        return ScreenImage(
            data=screenshot,
            format="png",
            metadata={
                "viewport": page.viewport_size,
                "scroll_position": page.evaluate("window.scrollY"),
                "dom_ready": page.evaluate("document.readyState")
            }
        )
```

**关键考量**：
- **分辨率**：截图分辨率应与操作坐标一致（Retina 屏幕需做缩放处理）。
- **频率**：每次操作前截图还是定时截图？通常每次操作后重新截图。
- **区域**：全屏截图还是只截活动窗口？全屏提供更多上下文但增加处理延迟。

### 2.3 阶段二：视觉理解（Visual Understanding）

获取截图后，CUA 使用视觉语言模型（VLM，Visual Language Model）理解屏幕内容。

```python
class VisualUnderstanding:
    """
    使用视觉语言模型理解屏幕内容。
    输出截图中的元素语义描述。
    """
    
    def analyze(self, screenshot: ScreenImage, task: str) -> SceneGraph:
        prompt = f"""
        分析这张截图，识别所有可交互的元素。
        任务目标: {task}

        对每个可交互元素，提供：
        - type: 元素类型 (button/input/link/checkbox/...)
        - text: 元素上的文本（如果有）
        - bounding_box: [x1, y1, x2, y2] (相对于截图)
        - state: 元素状态 (enabled/disabled/selected)
        - role: 该元素在完成任务中的作用

        以 JSON 格式返回。
        """
        
        response = vlm.analyze(
            image=screenshot.data,
            prompt=prompt
        )
        
        return SceneGraph.parse(response)
```

**VLM 的理解能力要求**：
- 识别 UI 控件（按钮、输入框、下拉菜单、复选框等）。
- 读取屏幕文本（包括不同字体、大小、颜色的文字）。
- 理解 UI 布局（哪些元素相关、层次结构、分组关系）。
- 感知元素状态（激活态、禁用态、加载态、选中态）。

### 2.4 阶段三：元素定位（Element Localization）

视觉理解输出的是语义描述，但执行操作需要精确的像素坐标。

```python
class ElementLocalization:
    """
    将视觉识别结果映射到精确的操作坐标。
    支持多种定位策略以提升鲁棒性。
    """
    
    def localize(self, scene: SceneGraph, target_desc: str) -> ElementPosition:
        # 策略1：DOM-based 定位（仅适用于 Web）
        if self.has_dom_access:
            return self._locate_via_dom(target_desc)
        
        # 策略2：视觉 bounding box（适用于任何 GUI）
        if scene.has_element(target_desc):
            bbox = scene.get_element(target_desc).bounding_box
            # 计算点击点：元素中心
            center_x = (bbox[0] + bbox[2]) / 2
            center_y = (bbox[1] + bbox[3]) / 2
            return ElementPosition(x=center_x, y=center_y)
        
        # 策略3：OCR 坐标（当视觉模型无法定位时）
        ocr_result = self.ocr_engine.recognize(scene.screenshot)
        if ocr_result.has_text(target_desc):
            return ocr_result.get_text_position(target_desc)
        
        # 策略4：模糊匹配（支持部分匹配和近似位置）
        return self._fuzzy_match(scene, target_desc)
    
    def _locate_via_dom(self, target_desc: str) -> ElementPosition:
        """通过浏览器 DOM 获取精确坐标"""
        # 使用 XPath/CSS Selector 定位元素
        # 然后获取 getBoundingClientRect()
        element = page.query_selector(f"text={target_desc}")
        if element:
            bbox = element.bounding_box()
            return ElementPosition(
                x=bbox["x"] + bbox["width"] / 2,
                y=bbox["y"] + bbox["height"] / 2,
                confidence=1.0,
                method="dom"
            )
```

**定位策略优先级**：
```
高精度 ┌─────────────────────────────────────────────────────┐
       │  DOM-based (精确到像素, 仅 Web)                       │
       │  ↑  confidence ≈ 1.0                                 │
       │                                                     │
       │  Visual Bounding Box (依赖 VLM 准确性)                │
       │  ↑  confidence ≈ 0.8-0.95                            │
       │                                                     │
       │  OCR-based (文本坐标, 适用于文本按钮/输入框)             │
       │  ↑  confidence ≈ 0.6-0.9                             │
       │                                                     │
       │  Image Template Matching (传统 CV 方法, 兜底)          │
       │  ↑  confidence ≈ 0.3-0.7                             │
低精度 └─────────────────────────────────────────────────────┘
```

### 2.5 阶段四：操作规划（Action Planning）

定位到元素后，CUA 需要规划具体的操作序列：

```python
class ActionPlanner:
    """
    规划操作序列，将"人类意图"转化为"原子操作序列"。
    """
    
    def plan(self, task: str, screen_state: ScreenState, 
             element: ElementPosition) -> ActionSequence:
        
        planning_prompt = f"""
        任务: {task}
        当前屏幕状态: {screen_state.description}
        目标元素: {element.to_dict()}

        请生成具体的操作序列。每个操作必须是以下之一：
        - click(x, y): 左键点击
        - right_click(x, y): 右键点击
        - double_click(x, y): 双击
        - type(text): 键盘输入文本
        - key_press(key): 按键 (Enter, Tab, Esc, ...)
        - scroll(dx, dy): 滚动
        - drag(x1, y1, x2, y2): 拖拽
        - wait(ms): 等待

        考虑以下因素：
        1. 操作前是否需要等待动画完成
        2. 是否需要先聚焦某个元素再输入
        3. 是否需要组合操作 (Ctrl+C, Ctrl+V)
        4. 异常处理：如果某个操作失败怎么办
        """
        
        return ActionSequence.parse(llm_call(planning_prompt))
```

### 2.6 阶段五：鼠标键盘执行（Execution）

规划完成后，CUA 通过操作系统级的输入模拟执行操作：

```python
class InputExecutor:
    """跨平台输入模拟"""
    
    def __init__(self, platform: str):
        self.platform = platform
        if platform == "windows":
            self.backend = Win32Input()
        elif platform == "macos":
            self.backend = QuartzInput()
        elif platform == "linux":
            self.backend = XDoToolInput()
    
    def execute(self, actions: ActionSequence):
        for action in actions:
            self._ensure_focus()  # 确保目标窗口处于焦点
            
            if action.type == "click":
                self.backend.mouse_move(action.x, action.y)
                self.backend.mouse_click("left")
            elif action.type == "type":
                self.backend.keyboard_type(action.text)
            elif action.type == "key_press":
                self.backend.keyboard_press(action.key)
            elif action.type == "scroll":
                self.backend.mouse_scroll(action.dx, action.dy)
            elif action.type == "wait":
                time.sleep(action.ms / 1000)
            
            # 每次操作后等待 UI 响应
            self._wait_for_stable()
    
    def _wait_for_stable(self, timeout=2.0):
        """等待 UI 完成动画/渲染"""
        # 通过对比前后截图判断页面是否稳定
        start = time.time()
        prev_hash = self._screenshot_hash()
        while time.time() - start < timeout:
            time.sleep(0.1)
            curr_hash = self._screenshot_hash()
            if curr_hash == prev_hash:
                return  # 页面已稳定
            prev_hash = curr_hash
```

## 三、关键技术挑战

### 3.1 视觉鲁棒性

UI 会因以下因素发生变化，导致 CUA 失败：

| 变化类型 | 示例 | 应对策略 |
|----------|------|----------|
| **布局变化** | 响应式设计、窗口大小调整 | DOM-based 定位 + 相对坐标 |
| **主题变化** | 深色/浅色模式 | 规范化预处理 |
| **动态内容** | 加载动画、轮播图 | 等待稳定后操作 |
| **国际化** | 不同语言的 UI 文本 | 多语言 VLM 支持 |
| **A/B 测试** | 不同用户看到不同 UI | 多路径规划 |

### 3.2 执行可靠性

```python
class ReliabilityGuard:
    """
    执行可靠性保障：执行后验证，失败后重试。
    """
    
    def execute_with_verification(self, action: Action, 
                                   expected_state: str) -> bool:
        # 执行前截图
        before = self.screen.capture()
        
        # 执行操作
        self.executor.execute(action)
        
        # 执行后截图
        after = self.screen.capture()
        
        # 验证预期变化是否发生
        if not self._verify_change(before, after, expected_state):
            # 重试逻辑
            for attempt in range(MAX_RETRIES):
                self.executor.execute(action)
                after = self.screen.capture()
                if self._verify_change(before, after, expected_state):
                    return True
                time.sleep(0.5 * (attempt + 1))
            
            # 所有重试失败，回退
            self.fallback_handler.handle(action)
            return False
        
        return True
```

### 3.3 安全性

CUA 的能力使其成为双刃剑——能操作任何 GUI 也意味着能执行危险操作。安全措施包括：

- **操作白名单**：只允许访问指定域名或应用。
- **敏感操作确认**：涉及删除、修改、支付等操作需要用户确认。
- **操作限速**：防止恶意脚本通过 CUA 快速操作。
- **会话隔离**：每个 CUA 实例运行在独立的沙箱环境中。

#### 分层决策模型

Claude Code Computer Use 采用分层决策架构来平衡效率与可靠性：

```
执行优先级：
  1st —— API 集成（MCP/原生API）：最高效，优先使用
  2nd —— 截图 + DOM 分析：需视觉理解时使用
  3rd —— 截图 + 虚拟鼠标键盘：兜底方案，仅在前两者不可用时
```

- **第一层（API 集成）**：优先使用 MCP 工具或原生 API（如 VS Code Extension API、Git CLI），速度和可靠性最高
- **第二层（截图 + DOM）**：当 API 不可用时（如操作未集成 API 的 Web 应用），通过截图理解 + DOM 分析定位元素
- **第三层（虚拟鼠标键盘）**：作为最后的兜底方案，仅在 API 不可用且 DOM 也无法访问时使用（如操作原生桌面应用）

这种设计避免了纯视觉方案的"大炮打蚊子"问题，在 90% 以上的场景中使用前两层即可完成。

### 5.3 安全架构

CUA 的能力（能操作任意 GUI）使其安全设计至关重要。Claude Code Computer Use 的安全性设计代表了当前 CUA 的最佳实践：

| 安全机制 | 说明 |
|----------|------|
| **全局单会话锁** | 同一时间只有一个 CUA 会话可操作电脑，防止多 Agent 竞争操作 |
| **应用级授权** | 每个应用首次被操作时需用户明确授权，授权可撤回 |
| **权限分级** | 只读（截图/浏览） vs 读写（点击/输入） vs 高风险（终端命令/文件删除） |
| **Esc 键紧急停止** | 用户随时按 Esc 键可立即终止当前操作序列 |
| **操作日志审计** | 所有鼠标/键盘操作记录可回放，支持事后审查 |
| **沙箱隔离** | CUA 进程运行在独立沙箱中，与用户主环境隔离 |
