## 二、各项目深度解析

### 2.1 CrewAI —— 多 Agent 协作的"入门首选"

**基本信息**：
- 开发商：CrewAI Inc.（由 João Moura 创立）
- 融资情况：2024 年完成种子轮（未公开金额），2025 年完成 A 轮约 1800 万美元
- 商业模式：开源核心版 + CrewAI Enterprise（企业版，提供 RBAC、审计日志、SSO）
- 官网：https://crewai.com

**核心特性**：
- **基于角色的 Agent 设计**：每个 Agent 有 Role（角色）、Goal（目标）和 Backstory（背景故事），类似"剧本创作"的体验。
- **流程驱动**：支持顺序执行（Sequential）和层级执行（Hierarchical）两种流程。
- **内置工具**：提供文件读写、网页搜索、数据库查询等内置工具，也支持自定义 Tool。

**核心代码示例**：
```python
from crewai import Agent, Task, Crew, Process

# 定义研究员 Agent
researcher = Agent(
    role="高级研究员",
    goal="发现 AI Agent 领域的最新趋势",
    backstory="你是一个在 AI 领域有 10 年经验的研究员",
    tools=[search_tool, web_scraper_tool],
    verbose=True
)

# 定义写作者 Agent
writer = Agent(
    role="技术作者",
    goal="撰写清晰的趋势分析报告",
    backstory="你是一个擅长将复杂技术概念通俗化的技术作者",
    tools=[],
    verbose=True
)

# 定义任务
research_task = Task(
    description="研究 2025-2026 年 AI Agent 的三大趋势",
    agent=researcher,
    expected_output="列出三大趋势，每个趋势附带事实和引用"
)

write_task = Task(
    description="基于研究结果撰写 500 字分析报告",
    agent=writer,
    expected_output="一份可发布的专业报告，包含引言、主体和结论",
    context=[research_task]  # 依赖前一个任务的输出
)

# 组建 Crew 并执行
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.sequential  # 顺序执行
)

result = crew.kickoff()
print(result)
```

**优势与局限**：

| 优势 | 局限 |
|------|------|
| 学习曲线低，概念直观（Agent/Task/Crew） | 不适合超大规模部署（数百 Agent） |
| 文档完善，社区活跃 | 内置 Agent 间通信能力较弱 |
| 企业版提供生产级功能 | 复杂 Workflow 表达能力有限 |
| Python 优先，生态兼容好 | 状态管理和持久化依赖外部 |

### 2.2 AutoGen —— 维护模式与社区分裂

> **重要更新**：2025 年底，微软宣布 AutoGen 进入**维护模式**（Maintenance Mode），停止重大新功能开发。随后社区分裂为两个独立项目：**MAF（Microsoft Agent Framework）** 和 **AG2**。这是 2026 年 Agent 开源生态中最具影响的事件之一。

**原项目基本信息**：
- 开发商：Microsoft Research → 已进入维护模式
- 当前版本：AutoGen 0.4.x（最后一个主要版本）
- 官网：https://microsoft.github.io/autogen/（已标记维护状态）

**分裂背景**：
- 微软内部战略调整，将资源集中到 **Copilot Studio** 和 **MAF**
- AutoGen 0.4 的"全部重写"式重构导致社区不满，大量 PR 和 Issue 积压
- 社区核心贡献者 fork 出 **AG2** 项目，继续维护和演进 AutoGen 最初的愿景

**两个衍生项目对比**：

| 维度 | MAF（Microsoft 官方） | AG2（社区 Fork） |
|------|----------------------|-----------------|
| 定位 | 微软 Agent 生态的底层框架 | AutoGen 精神继承者 |
| 开发方 | Microsoft Research | 原 AutoGen 社区核心贡献者 |
| 协议兼容 | 偏向 Azure/AI Foundry | 保持框架无关 |
| 版本状态 | 0.1.x（早期） | 0.5.x（活跃开发） |
| 社区规模 | 较小（企业主导） | 活跃（原 AutoGen 社区迁移） |
| 推荐场景 | 微软生态内的 Agent 开发 | 通用的多 Agent 对话系统 |

**对生态的影响**：
1. **碎片化风险加重**：开发者需要评估 MAF 和 AG2 两条技术路径
2. **信任成本上升**：微软对 AutoGen 的"先投入后放弃"模式引发了业界对科技巨头开源项目可持续性的讨论
3. **AG2 接管社区**：截至 2026 年中，AG2 已吸引了原 AutoGen 约 60% 的活跃贡献者

### 2.3 LangGraph —— LangChain 的流程编排引擎

**基本信息**：
- 开发商：LangChain Inc.
- 融资情况：2024 年 B 轮 2500 万美元，累计融资 4000 万+
- 商业模式：开源（MIT）+ LangSmith（监控/调试 SaaS）+ LangGraph Cloud
- 官网：https://langchain-ai.github.io/langgraph/

**核心特性**：
- **有状态图（Stateful Graph）**：将 Agent 工作流建模为有向图，节点是计算步骤，边是状态流转。
- **人机交互（Human-in-the-Loop）**：内置 checkpoint 机制，支持在任意节点暂停等待人工干预。
- **流式优先**：支持节点级别的流式输出，适合 UI 交互场景。
- **LangChain 生态**：与 LangChain 的工具/模型/检索生态完全兼容。

**核心代码示例**：
```python
from langgraph.graph import StateGraph, END
from typing import TypedDict, List
from langchain_core.messages import HumanMessage, AIMessage

# 定义状态
class AgentState(TypedDict):
    messages: List
    next_step: str

# 定义节点函数
def analyze(state: AgentState) -> AgentState:
    """分析用户问题的意图"""
    # ... LLM 调用 ...
    return {"next_step": "search"}

def search(state: AgentState) -> AgentState:
    """搜索相关信息"""
    # ... 检索逻辑 ...
    return {"messages": [AIMessage(content="检索结果...")],
            "next_step": "generate"}

def generate(state: AgentState) -> AgentState:
    """生成最终回答"""
    # ... LLM 调用 ...
    return {"next_step": END, "messages": [...]}

def need_search(state: AgentState) -> str:
    """条件边：判断是否需要搜索"""
    return "search" if state["next_step"] == "search" else "generate"

# 构建图
builder = StateGraph(AgentState)
builder.add_node("analyze", analyze)
builder.add_node("search", search)
builder.add_node("generate", generate)

builder.set_entry_point("analyze")
builder.add_conditional_edges("analyze", need_search)
builder.add_edge("search", "generate")
builder.add_edge("generate", END)

graph = builder.compile()
```

**优势与局限**：

| 优势 | 局限 |
|------|------|
| 图结构表达能力强，适合复杂工作流 | 学习和调试成本高 |
| LangChain 生态无缝集成 | 图结构不当可能导致隐藏 bug |
| 生产级特性完善（checkpoint、流式、重试） | 对简单场景过度工程化 |
| 企业级支持和 SaaS 产品 | 依赖 LangChain 的庞大依赖树 |

### 2.4 Agno（原 Phidata）—— 轻量级 Agent 框架

**基本信息**：
- 开发商：Agno Inc.（前身 Phidata）
- 融资情况：2024 年种子轮 300 万美元
- 商业模式：开源（MIT）+ Agno Cloud（托管服务）
- 官网：https://agno.com

**核心特性**：
- **极简 API**：用最少的代码创建 Agent，适合快速原型开发。
- **多模态支持**：内置对图片、音频、视频的处理能力。
- **工具生态**：提供 100+ 预建工具连接器。
- **知识库集成**：内建 RAG 支持，Agent 可加载文档知识。

```python
from agno import Agent
from agno.tools.duckduckgo import DuckDuckGoTools

agent = Agent(
    name="Web Researcher",
    tools=[DuckDuckGoTools()],
    show_tool_calls=True,
    markdown=True
)

agent.print_response("告诉我 2026 年 AI Agent 的最新发展", stream=True)
```

### 2.5 Dify —— 低代码 LLMOps 平台

**基本信息**：
- 开发商：Dify Inc.（广州）
- 融资情况：2024 年种子轮，2025 年 A 轮（未公开金额）
- 商业模式：开源（Apache-2.0）+ Dify Cloud（云服务）+ 企业版
- 社区规模：55k+ Stars，600+ 贡献者
- 官网：https://dify.ai

**核心特性**：
- **可视化编排**：拖拽式 Workflow 编辑器，非技术人员可用。
- **RAG Pipeline**：内置完整的 RAG 管线（文档解析→分块→Embedding→检索）。
- **Agent 节点**：工作流中可嵌入 Agent 节点，支持 Tool-calling。
- **多模型支持**：兼容 OpenAI、Claude、Llama、通义千问等多个模型。
- **插件生态**：通过插件系统扩展工具和模型。

**适用场景**：
- 非技术团队快速构建 AI 应用。
- 需要可视化监控和调试的生产环境。
- 中小企业的 AI 客服、知识库问答。

### 2.6 Coze —— 字节跳动的 AI Bot 平台

**基本信息**：
- 开发商：字节跳动
- 商业模式：完全闭源，免费增值（Freemium）+ 付费 API 额度
- 官网：https://coze.com

**核心特性**：
- **对话式 Bot 构建**：通过自然语言配置 Agent 的行为。
- **插件市场**：丰富的预建插件（搜索、图片生成、数据分析等）。
- **知识库**：支持上传文档作为 Bot 的知识来源。
- **工作流**：可视化的流程编排（类似 Dify 但更注重 Bot 场景）。
- **发布渠道**：一键发布到微信、飞书、Discord、Telegram 等平台。

**优势**：
- 零代码，非技术人员 10 分钟可创建一个 Bot。
- 多渠道发布能力是差异化优势。
- 字节跳动的基础设施（豆包模型、云服务）支撑。

**局限**：
- 完全闭源，无法自托管，存在数据安全顾虑。
- 不可定制底层模型和推理参数。
- 依赖 Coze 平台生态，迁移成本高。

### 2.7 n8n —— 技术团队的自动化工作流引擎

**基本信息**：
- 开发商：n8n GmbH（德国柏林）
- 融资情况：2022 年 A 轮 1200 万美元，累计融资 2000 万+
- 商业模式：开源核心（Sustainable Use License）+ n8n Cloud + 企业版
- 社区规模：55k+ Stars，1,200+ 贡献者（社区贡献非常活跃）
- 官网：https://n8n.io

**核心特性**：
- **400+ 集成节点**：连接各种 SaaS、数据库、API。
- **AI Agent 节点**：2024 年起加入 AI Agent 支持（LangChain 集成）。
- **自托管优先**：设计上优先考虑自托管，适合对数据隐私有要求的团队。
- **可视化调试**：逐步执行的调试模式，每个节点的输入输出可见。

**与纯 Agent 框架区别**：n8n 本质上是**自动化工作流引擎**，Agent 只是其支持的众多节点类型之一。适合"需要 Agent 参与的自动化流程"而非"纯 Agent 应用"。

## 三、2026 年开源生态新格局

### 3.1 MCP SDK：月下载量 30 亿的基础设施级协议

截至 2026 年中，MCP SDK 的月下载量已突破 **30 亿次**（综合 npm、PyPI、Maven 等仓库），成为 AI Agent 生态中基础设施级的依赖。这一数据的意义：

```
MCP SDK 月下载量增长趋势：
2024.01: ~500万/月  (初始发布)
2024.06: ~8,000万/月 (Anthropic 采用)
2025.01: ~5亿/月    (主流框架集成)
2025.06: ~12亿/月   (企业大规模采用)
2026.01: ~22亿/月   (MCP 成为事实标准)
2026.05: ~30亿/月   (全面普及)
```

MCP 的普及深刻改变了 Agent 的开发模式：
- **从"为每个工具写胶水代码"到"MCP Server 一次开发到处使用"**，工具开发成本降低了约 70%
- 各大云厂商（AWS、GCP、Azure）均已提供 MCP Server 托管服务
- MCP Registry（社区工具注册中心）已收录 50,000+ 个公开 MCP Server

### 3.2 Skill 市场：OpenClaw 半年积累 13,700+ Skill

OpenClaw 的 Skill 市场代表了 Agent 能力的"App Store"化趋势：

- 2026 年初推出，半年内积累 **13,700+ 个 Skill**
- 覆盖场景：开发辅助（35%）、测试自动化（22%）、运维监控（18%）、数据处理（15%）、其他（10%）
- Skill 开发者生态：3,200+ 注册开发者，Top 100 Skill 平均月调用量 50 万+
- 商业模式：免费 + 高级 Skill 付费分成（平台抽成 20%）

这种"Agent Skill 经济"的兴起意味着 Agent 能力的供给从"框架开发者提供"转向"社区众包生产"，大幅扩展了 Agent 的能力边界。

### 3.3 选型环境的变化

2026 年的开源 Agent 选型环境相比 2024-2025 年发生了根本变化：

| 维度 | 2024-2025 | 2026 |
|------|-----------|------|
| **协议层** | 各自私有协议 | MCP（工具层）+ A2A（Agent 间）双协议标准 |
| **框架选择** | 单框架主导项目 | 多框架组合使用（LangGraph + CrewAI + Dify 混用） |
| **Agent 发现** | 人工配置 | Agent Card 自动发现（`/.well-known/agent.json`） |
| **工具供给** | 开发者自建 | 50,000+ MCP Server + 13,700+ Skill |
| **项目治理** | 单一厂商主导 | 维护/分裂事件频发（AutoGen 分裂为 MAF/AG2） |

## 五、选型建议

| 非技术人员构建 AI 应用 | Dify / Coze | 可视化编排，无需编码 |
| 企业级自动化流程 | n8n | 400+ 集成，自托管，成熟 |
| 研究和实验 | MetaGPT / AutoGen | 多 Agent 模拟场景丰富 |
| 生产级 Text-to-SQL | LangGraph + Dify | 稳定+可视化的组合 |

### 5.2 选型决策树

```
你的需求是什么？
│
├─ 需要快速验证想法？
│   └─ Agno 或 CrewAI（< 100 行代码）
│
├─ 需要构建复杂工作流？
│   ├─ 技术团队 → LangGraph
│   └─ 非技术团队 → Dify 或 n8n
│
├─ 需要多 Agent 深度协作？
│   ├─ 对话/讨论场景 → AutoGen
│   └─ 角色分工场景 → CrewAI
│
├─ 需要生产部署和监控？
│   ├─ 愿意付费 → LangGraph Cloud 或 Dify Cloud
│   └─ 需要自托管 → Dify 或 n8n
│
└─ 需要零代码解决方案？
    ├─ 可接受闭源 → Coze
    └─ 需要开源 → Dify
```
