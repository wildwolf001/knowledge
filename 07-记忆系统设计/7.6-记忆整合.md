# 7.6 记忆整合（Consolidation）—— Sleep Consolidation、语义聚类、短期到长期晋升流水线

> 人类记忆在清醒时形成，但在睡眠中巩固。**记忆整合（Memory Consolidation）** 是将碎片化的短期经验转化为稳定的长期知识的过程。对 Agent 而言，整合不仅是"搬数据"——它包括去噪、抽象、聚类和结构优化。

---

## 一、什么是记忆整合？

### 1.1 生物学的启发

在神经科学中，记忆整合分为两个阶段：

```
清醒 (Wake):
  经历事件 → 海马体快速编码（短期记忆）
       ↓   ◄── 临时存储，容量有限，易被覆盖

睡眠 (Sleep):
  海马体 → 新皮层回放（Replay）
       ↓   ◄── 慢波振荡（Slow Wave Oscillation）驱动
  新皮层 → 长期存储
       ↓   ◄── 突触巩固，形成结构化的知识
  知识抽象 → 提取共性，形成语义概念
```

对应到 Agent 系统：

| 生物学阶段 | Agent 对应操作 | 技术实现 |
|-----------|---------------|----------|
| **海马体编码** | 短期记忆写入 | Redis 会话存储 |
| **睡眠回放** | 离线整合（Offline Consolidation） | 定时 Job 扫描 STM |
| **皮层巩固** | LTM 存储 + 索引优化 | 向量 DB 写入 + 重新索引 |
| **语义抽象** | 聚类 + 摘要 | LLM 驱动的知识抽象 |

### 1.2 Agent 为什么要做整合？

如果没有整合，Agent 的记忆系统会面临：

| 问题 | 表现 | 后果 |
|------|------|------|
| **碎片化** | 同一主题的记忆分散在多个片段中 | 检索时只能看到部分上下文 |
| **冗余** | 同一事实被多次存入不同表述 | 浪费存储，提取出矛盾信息 |
| **噪声累积** | 错误/过时信息从未被清理 | 污染 Agent 的知识库 |
| **结构缺失** | 只有原始文本，没有知识关联 | 无法做推理和抽象 |

## 二、Sleep Consolidation（休眠整合）

### 2.1 概念

Sleep Consolidation 指 Agent 在**低负载时段**（而非实时对话中）执行的记忆后处理。它类比人类的睡眠——对话时系统只做"快速存储"，复杂度高的整合操作延后执行。

```
实时交互 (Online):
  Agent ←→ 用户
      │
      ├── 快速存储: STM 写入 (< 5ms)
      ├── 关键信息: 即时 LTM 写入（重要性 > 0.8）
      └── 非关键: 留在 STM 等整合
                ↑
                │ 等待 Sleep Cycle
                ▼

休眠整合 (Offline / Sleep):
  ┌─ 整合调度器 ──────────────────────────────┐
  │  1. STM 扫描 → 提取未处理记忆              │
  │  2. 去重 → 合并相似记忆                     │
  │  3. 语义聚类 → 发现主题群                  │
  │  4. 抽象提取 → 生成高层次摘要              │
  │  5. LTM 写入 → 更新向量索引                │
  │  6. 低分清理 → 标记/删除过时记忆           │
  └────────────────────────────────────────────┘
```

### 2.2 实现

```python
import time
import asyncio
from typing import List

class SleepConsolidation:
    """
    休眠整合：Agent 低负载时执行的记忆优化
    """
    def __init__(self, stm, ltm, llm, embedding_model):
        self.stm = stm            # Short-Term Memory (Redis)
        self.ltm = ltm            # Long-Term Memory (Vector DB)
        self.llm = llm
        self.embed = embedding_model
        self.sleep_interval = 3600  # 每小时执行一次
        self.min_memories_for_cluster = 10  # 最少 10 条才聚类

    async def run_consolidation_cycle(self):
        """执行一轮整合（应作为后台任务运行）"""
        print(f"[Consolidation] Starting cycle at {time.ctime()}")

        # Step 1: 收集 STM 中待整合的记忆
        pending = self.stm.get_pending_consolidation()
        if not pending:
            print("[Consolidation] No pending memories")
            return

        print(f"[Consolidation] Processing {len(pending)} memories")

        # Step 2: 去重
        deduped = self._deduplicate(pending)

        # Step 3: 语义聚类
        clusters = self._semantic_clustering(deduped)

        # Step 4: 为每个簇生成摘要（抽象）
        consolidated = []
        for cluster in clusters:
            if len(cluster) >= self.min_memories_for_cluster:
                summary = self._abstract_summary(cluster)
                consolidated.extend(summary)
            else:
                consolidated.extend(cluster)

        # Step 5: 写入 LTM
        for memory in consolidated:
            self.ltm.store(
                content=memory["content"],
                metadata={
                    "source": memory.get("source", "consolidation"),
                    "consolidated_at": time.time(),
                    "original_ids": memory.get("original_ids", []),
                    "importance": memory.get("importance", 0.5),
                }
            )

        # Step 6: 清理已整合的 STM
        self.stm.mark_consolidated([m["id"] for m in pending])

        print(f"[Consolidation] Completed. "
              f"{len(pending)} → {len(consolidated)} after consolidation")

    def _deduplicate(self, memories: List[dict]) -> List[dict]:
        """语义去重：合并相似度 > 0.9 的记忆"""
        unique = []
        for mem in memories:
            is_dup = False
            for existing in unique:
                sim = self._cosine_similarity(
                    self.embed.encode(mem["content"]),
                    self.embed.encode(existing["content"])
                )
                if sim > 0.9:
                    is_dup = True
                    # 合并元数据（保留更新时间更近的）
                    if mem.get("timestamp", 0) > existing.get("timestamp", 0):
                        existing["content"] = mem["content"]
                    existing["original_ids"] = existing.get("original_ids", []) + [mem["id"]]
                    break
            if not is_dup:
                unique.append(mem)
        return unique

    def _semantic_clustering(self, memories: List[dict]) -> List[List[dict]]:
        """
        基于 Embedding 的语义聚类
        使用 DBSCAN 算法（无需预设簇数量）
        """
        if len(memories) < 2:
            return [memories]

        embeddings = [self.embed.encode(m["content"]) for m in memories]

        # 简化版聚类（实际可使用 sklearn DBSCAN）
        clusters = []
        assigned = set()
        for i, mem_i in enumerate(memories):
            if i in assigned:
                continue
            cluster = [mem_i]
            assigned.add(i)
            for j, mem_j in enumerate(memories):
                if j in assigned:
                    continue
                sim = self._cosine_similarity(embeddings[i], embeddings[j])
                if sim > 0.75:  # 聚类阈值
                    cluster.append(mem_j)
                    assigned.add(j)
            clusters.append(cluster)

        return clusters

    def _abstract_summary(self, cluster: List[dict]) -> List[dict]:
        """
        用 LLM 为簇生成抽象知识（而非逐条保留）
        例: 多条关于"用户喜欢简约设计"的对话
        → 抽象为一条语义事实 "用户偏好 Material Design 风格"
        """
        # 提取簇内内容
        contents = [m["content"] for m in cluster]

        # LLM 生成抽象摘要
        abstraction = self.llm.generate(
            f"以下记忆片段描述了同一主题。"
            f"请提取核心事实并生成一条简洁的抽象知识：\n\n"
            f"{chr(10).join(f'- {c}' for c in contents)}"
        )

        return [{
            "content": abstraction,
            "source": "abstracted",
            "original_ids": [m["id"] for m in cluster],
            "importance": max(m.get("importance", 0) for m in cluster),
            "clustered_at": time.time(),
        }]
```

## 三、语义聚类（Semantic Clustering）

### 3.1 聚类策略

语义聚类是整合的核心步骤——将散落的记忆片段按主题归类：

```
原始记忆:
  [M1] "用户说他们公司用 Salesforce 管理客户"
  [M2] "用户问 Salesforce API 的文档在哪里"
  [M3] "用户提到正在评估 HubSpot 作为替代方案"
  [M4] "用户的项目预算大约 5 万美元"

聚类后:
  ┌── Cluster A: CRM 系统 ──────────────────────┐
  │  [M1] Salesforce 使用                        │
  │  [M2] Salesforce API                         │
  │  [M3] HubSpot 评估                            │
  ├── 抽象后:                                     │
  │  "用户公司的 CRM 需求: 正在使用 Salesforce,    │
  │   同时评估 HubSpot; 需要 API 集成支持"         │
  └──────────────────────────────────────────────┘

  ┌── Cluster B: 预算信息 ───────────────────────┐
  │  [M4] 预算约 5 万美元                         │
  └──────────────────────────────────────────────┘
```

### 3.2 聚类算法选择

| 算法 | 是否需要预设 K | 适合数据量 | 特点 |
|------|---------------|-----------|------|
| **K-Means** | 是 | 大 | 快，但 K 难确定 |
| **DBSCAN** | 否 | 中 | 可自动发现簇形状，适合记忆聚类 |
| **HDBSCAN** | 否 | 中-大 | DBSCAN 的层次改进版 |
| **Agglomerative** | 否 | 小-中 | 层次聚类，可看树状图 |
| **LLM 聚类** | 否 | 小 | LLM 直接分类，最灵活但最贵 |

对于记忆整合场景，**HDBSCAN** 通常是首选——不需要预设簇数量，能处理噪声点（不属于任何簇的记忆单独保留）。

## 四、短期到长期的晋升流水线

### 4.1 晋升流程

```
STM (Redis)
    │
    ▼
┌─────────────────────────────────────────────┐
│  晋升判定                                    │
│                                              │
│  维度              权重   阈值               │
│  ├─ 访问频率 ≥3次  0.25                       │
│  ├─ 重要性 ≥0.7    0.40                       │
│  ├─ 用户显式标记   0.25                       │
│  ├─ 跨会话出现    0.10                        │
│                                              │
│  综合评分 = Σ(维度得分 × 权重)                │
│  如果 Score > 0.6 → 晋升                     │
│  否则 → 继续留在 STM                         │
└──────────────────────┬──────────────────────┘
                       │ 晋升
                       ▼
┌─────────────────────────────────────────────┐
│  LTM 写入前处理                               │
│  1. 去重（检查 LTM 中是否已有）               │
│  2. 语义聚类（与已有 LTM 合并或分离）          │
│  3. 抽象化（LLM 提取核心事实）                 │
│  4. Embedding 计算                           │
└──────────────────────┬──────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────┐
│  LTM (Vector DB)                              │
│  写入 (content, embedding, metadata)          │
│  更新索引                                     │
└───────────────────────────────────────────────┘
```

### 4.2 晋升调度

```python
class PromotionPipeline:
    """
    STM → LTM 晋升流水线
    """
    def __init__(self, stm, ltm, llm, embedding_model):
        self.stm = stm
        self.ltm = ltm
        self.llm = llm
        self.embed = embedding_model

    def evaluate_for_promotion(self, memory: dict) -> float:
        """评估一条 STM 记忆是否值得晋升"""
        score = 0.0

        # 频率维度（是否被多次访问）
        access_count = memory.get("access_count", 0)
        if access_count >= 5:
            score += 0.25
        elif access_count >= 3:
            score += 0.15

        # 重要性维度
        importance = memory.get("importance", 0.0)
        score += 0.4 * importance

        # 用户显式标记
        if memory.get("user_flagged"):
            score += 0.25

        # 跨会话出现
        session_count = memory.get("session_count", 0)
        if session_count >= 2:
            score += 0.1

        return min(score, 1.0)

    def promote(self, memory_id: str):
        """执行单条记忆的晋升"""
        memory = self.stm.get(memory_id)

        # 去重检查
        existing = self.ltm.semantic_search(
            memory["content"], top_k=1
        )
        if existing and existing[0]["score"] > 0.92:
            # LTM 已有非常类似的内容 → 只更新元数据，不重复存储
            self.ltm.update_access(existing[0]["id"])
            return

        # 抽象化（对冗余信息做压缩）
        if len(memory["content"]) > 200:
            abstract = self.llm.summarize(memory["content"])
        else:
            abstract = memory["content"]

        # 计算 Embedding
        embedding = self.embed.encode(abstract)

        # 写入 LTM
        self.ltm.store(
            vector=embedding,
            payload={
                "content": abstract,
                "original_stm_id": memory_id,
                "promoted_at": time.time(),
                "importance": memory.get("importance", 0.5),
            }
        )

        # 从 STM 移除
        self.stm.delete(memory_id)

    def batch_promote(self, memory_ids: List[str]):
        """批量晋升"""
        for mem_id in memory_ids:
            score = self.evaluate_for_promotion(self.stm.get(mem_id))
            if score >= 0.6:
                self.promote(mem_id)
```

## 五、整合系统的运维

### 5.1 整合频率与调度策略

| 策略 | 触发条件 | 适用场景 |
|------|----------|----------|
| **定时整合** | 每小时 / 每天固定时间执行 | 常规场景 |
| **低负载整合** | CPU/GPU 利用率 < 30% 时执行 | 生产环境 |
| **阈值触发** | STM 中未整合记忆超过 N 条 | 高并发场景 |
| **手动触发** | 管理员显式调用 | 调试 / 维护 |

### 5.2 整合的性能影响

```
整合操作的资源开销（估算，基于 10000 条记忆）：

操作              耗时         Token 消耗        备注
─────────────────────────────────────────────────────
去重              2-5s        -                 向量相似度计算
语义聚类 (DBSCAN)  5-30s       -                 O(n²) 复杂度
LLM 抽象摘要       30-120s     ~2000/簇          每簇 1 次 LLM 调用
Embedding 计算    10-20s       -                 批量计算
LTM 写入          5-10s        -                 批量写入向量 DB
─────────────────────────────────────────────────────
总计:             52-187s

建议: 整合周期 > 15 分钟，避免频繁触发
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| **记忆整合（Consolidation）** | 将碎片化短期记忆转化为结构化长期知识的过程 |
| **Sleep Consolidation** | Agent 在低负载时段执行的后台记忆优化（类比人类睡眠） |
| **语义聚类** | 基于 Embedding 相似度将记忆自动分组的算法 |
| **晋升（Promotion）** | STM → LTM 的记忆转存，伴随去重和抽象 |
| **抽象化（Abstraction）** | 多条具体记忆 → 一条核心知识的 LLM 压缩 |
| **DBSCAN** | 无需预设簇数量的密度聚类算法 |
| **HDBSCAN** | DBSCAN 的层次改进版，适合记忆聚类场景 |
| **去重（Deduplication）** | 合并语义高度相似的记忆，消除冗余 |
