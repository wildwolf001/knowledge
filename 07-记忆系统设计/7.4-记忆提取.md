# 7.4 记忆提取——LLM 驱动 vs 关键词 vs 混合

> 记忆存储得再好，如果提取不出来，也是无效记忆。记忆提取（Memory Retrieval）是 Agent 记忆系统的关键瓶颈——它需要从海量存储中**快速、准确、相关**地找到当前对话所需的信息。本章对比三种提取策略：LLM 驱动、关键词匹配和混合方法。

---

## 一、记忆提取的挑战

### 1.1 提取的核心矛盾

```
                   准确率
                      ▲
                      │    LLM 驱动
                      │    (最准但最慢)
                      │
                      │        混合方法
                      │       (平衡点)
                      │
                      │   关键词匹配
                      │    (最快但最不准)
                      └──────────────────► 速度
```

记忆提取的三个核心挑战：

1. **语义鸿沟（Semantic Gap）**：用户的当前问题和过去存储的记忆可能用词完全不同。"上次安装遇到的问题"和"deployment 阶段的 dependency 冲突"指向同一件事。
2. **提取时机**：每次对话都检索全部记忆？只在特定触发词出现时检索？检索太频繁浪费 Token，太少则遗漏关键信息。
3. **去重与冲突解决**：多条记忆对同一事实的表述可能矛盾，需要判断哪条更可信。

### 1.2 提取性能指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **召回率（Recall）** | 检索到的相关记忆 / 所有相关记忆 | > 0.85 |
| **精确率（Precision）** | 检索到的相关记忆 / 所有检索到的 | > 0.70 |
| **延迟（Latency）** | 从请求到返回的时间 | < 200ms |
| **Token 消耗** | 检索结果注入上下文窗口的 Token 数 | < 窗口 30% |

## 二、LLM 驱动的提取

### 2.1 工作原理

LLM 驱动的提取（又称"生成式检索"）不依赖传统的关键词或向量匹配，而是让 LLM 直接"思考"需要什么记忆，然后生成检索指令。

```
传统检索:
  "数据库慢" → Embedding → 向量相似度 → 返回 Top-K 匹配块
                      (统计匹配，无推理)

LLM 驱动检索:
  "数据库慢" → LLM 推理 → "用户可能遇到了数据库性能问题
                          需要检查: 1) 慢查询日志 2) 索引使用情况
                          3) 之前咨询过的 DBA 建议"
  → 生成 3 条具体检索查询 → 并行执行 → 合并结果
                      (语义理解 + 查询规划)
```

### 2.2 实现方式

```python
class LLMDrivenRetrieval:
    """
    LLM 驱动的记忆提取
    - LLM 分析当前对话，生成检索计划
    - 根据计划从不同记忆层获取信息
    """
    def __init__(self, llm, episodic_memory, semantic_memory):
        self.llm = llm
        self.episodic = episodic_memory
        self.semantic = semantic_memory

    def retrieve(self, conversation_context: list) -> dict:
        """
        LLM 分析对话上下文，决定需要什么记忆
        """
        # Step 1: 让 LLM 生成检索计划
        retrieval_plan = self.llm.generate(
            self._build_retrieval_prompt(conversation_context)
        )
        # 期望输出格式:
        # {
        #   "queries": [            ← 对记忆中信息的自然语言描述
        #     "用户的项目截止日期",
        #     "用户的技术栈偏好",
        #     "上次关于预算的讨论"
        #   ],
        #   "memory_types": ["semantic", "semantic", "episodic"],
        #   "priority": "high"
        # }

        # Step 2: 执行检索
        results = {}
        for i, query in enumerate(retrieval_plan["queries"]):
            mem_type = retrieval_plan["memory_types"][i]
            if mem_type == "episodic":
                results[query] = self.episodic.recall_events(query)
            elif mem_type == "semantic":
                results[query] = self.semantic.query(query)

        # Step 3: LLM 综合评估，排除不相关的结果
        filtered = self.llm.filter_relevant(
            context=conversation_context,
            retrieved=results
        )

        return filtered
```

### 2.3 优缺点分析

| 优点 | 缺点 |
|------|------|
| 语义理解能力强，能处理同义替换和隐含意图 | 每次检索需要 1 次 LLM 调用，延迟高（1-3s） |
| 支持复杂的多步推理型检索 | 额外 Token 消耗 |
| 可以主动推理"需要什么"而不仅匹配"有什么" | LLM 自身的幻觉可能污染检索结果 |
| 自然支持跨记忆类型检索 | 成本高，不适合高频场景 |

## 三、关键词驱动的提取

### 3.1 工作原理

关键词提取是最传统但最稳定的方式，适合确定性匹配场景。

```python
class KeywordRetrieval:
    """
    关键词驱动的记忆提取
    使用 TF-IDF + BM25 变体
    """
    def __init__(self):
        self.inverted_index = {}  # 倒排索引
        self.document_store = {}
        self.bm25_k1 = 1.5
        self.bm25_b = 0.75

    def index_memory(self, memory_id: str, content: str):
        """建立倒排索引"""
        tokens = self._tokenize(content)
        doc_length = len(tokens)
        self.document_store[memory_id] = {
            "content": content,
            "length": doc_length,
        }
        for token in set(tokens):
            if token not in self.inverted_index:
                self.inverted_index[token] = []
            self.inverted_index[token].append(memory_id)

    def retrieve(self, query: str, top_k: int = 5) -> list:
        """BM25 检索"""
        query_tokens = self._tokenize(query)
        scores = {}

        # BM25 评分
        N = len(self.document_store)
        avg_doc_len = sum(
            d["length"] for d in self.document_store.values()
        ) / max(N, 1)

        for token in query_tokens:
            if token not in self.inverted_index:
                continue
            df = len(self.inverted_index[token])  # 文档频率
            idf = math.log((N - df + 0.5) / (df + 0.5) + 1)

            for doc_id in self.inverted_index[token]:
                doc = self.document_store[doc_id]
                tf = self._term_frequency(token, doc["content"])  # 词频
                # BM25 评分公式
                score = idf * (tf * (self.bm25_k1 + 1)) / (
                    tf + self.bm25_k1 *
                    (1 - self.bm25_b + self.bm25_b * doc["length"] / avg_doc_len)
                )
                scores[doc_id] = scores.get(doc_id, 0) + score

        # 排序返回
        ranked = sorted(scores.items(), key=lambda x: x[1], reverse=True)
        return [
            self.document_store[doc_id] for doc_id, _ in ranked[:top_k]
        ]
```

### 3.2 优缺点分析

| 优点 | 缺点 |
|------|------|
| 极快（<10ms），无需模型推理 | 无法处理同义替换（"买车"vs"购车"） |
| 零额外成本 | 无法理解隐含语义 |
| 完全确定性，可预测 | 对拼写错误敏感 |
| 适合精确匹配（用户 ID、日期、编号） | 不支持跨语言检索 |

## 四、混合提取（推荐方案）

### 4.1 架构设计

混合提取结合了关键词的速度和 LLM 的语义理解，采用**两阶段流水线**：

```
                               混合提取流水线
┌──────────────┐    ┌──────────────────┐    ┌──────────────┐
│  Phase 1     │    │   Phase 2        │    │  Phase 3     │
│  粗筛 (召回)  │───→│  精排 (重排序)   │───→│  注入 (整合)  │
│              │    │                  │    │              │
│  - BM25      │    │  - Cross-Encoder │    │  - Token 截断│
│  - 向量检索  │    │  - LLM 打分      │    │  - 去重      │
│  - 实体匹配  │    │  - 时效性加权    │    │  - 格式转换  │
│              │    │                  │    │  - 冲突解决  │
│  目标: 高召回│    │  目标: 高精确率  │    │  目标: 可用性│
│  Top-100     │    │  Top-5 → Top-10  │    │  最终输出    │
└──────────────┘    └──────────────────┘    └──────────────┘
```

### 4.2 实现

```python
class HybridRetrieval:
    """
    混合提取：关键词粗筛 + 语义精排 + LLM 整合
    """
    def __init__(self, llm, vector_db, embedding_model):
        self.llm = llm
        self.vector_db = vector_db
        self.embed = embedding_model
        self.keyword = KeywordRetrieval()

    def retrieve(self, query: str, top_k: int = 5) -> list:
        # Phase 1: 粗筛（多路召回）
        query_embedding = self.embed.encode(query)

        # 路 1: 向量检索
        vector_results = self.vector_db.search(
            vector=query_embedding, top_k=50
        )

        # 路 2: 关键词检索
        keyword_results = self.keyword.retrieve(query, top_k=50)

        # 路 3: 实体匹配（提取 query 中的实体并查找）
        entities = self._extract_entities(query)
        entity_results = self._entity_lookup(entities)

        # 合并候选集（去重）
        candidates = self._merge_and_dedup(
            vector_results, keyword_results, entity_results
        )  # 通常 50-100 条

        # Phase 2: 精排（Cross-Encoder 重排序）
        scored_candidates = []
        for candidate in candidates:
            relevance = self._cross_encoder_score(query, candidate["content"])
            recency = self._recency_score(candidate["timestamp"])
            importance = candidate.get("importance", 0.5)
            # 综合评分（详见 7.5 节的三维评分公式）
            combined_score = (
                0.5 * relevance +
                0.3 * recency +
                0.2 * importance
            )
            scored_candidates.append((candidate, combined_score))

        sorted_candidates = sorted(
            scored_candidates, key=lambda x: x[1], reverse=True
        )[:top_k]

        # Phase 3: 注入前 LLM 整合处理
        final = self.llm.integrate_memories(
            query=query,
            candidates=[c[0] for c in sorted_candidates]
        )

        return final
```

### 4.3 提取时机策略

不是每轮对话都需要全量检索。提取时机的选择直接影响系统成本和体验：

```python
class RetrievalScheduler:
    """
    记忆提取调度器：决定何时检索
    """
    def should_retrieve(self, context: dict) -> tuple:
        """
        返回 (是否需要检索, 检索策略)
        """
        # 条件 1: 新会话启动 → 必须检索
        if context.get("is_new_session"):
            return True, "full"

        # 条件 2: 用户提到特定触发词 → 增量检索
        trigger_words = [
            "记得", "上次", "之前", "以前",
            "你忘了？", "我说过", "remember"
        ]
        if any(w in context["user_message"] for w in trigger_words):
            return True, "targeted"

        # 条件 3: 实体引用 → 检索相关实体
        entities = self._extract_entities(context["user_message"])
        if entities:
            return True, "entity_only"

        # 条件 4: 对话轮次间隔 > N → 概率性刷新
        if context.get("turns_since_last_retrieval", 0) > 5:
            return True, "refresh"

        # 条件 5: 默认不检索（使用已在窗口中的记忆）
        return False, None
```

### 4.4 去重策略

多条存储的记忆可能描述同一事实，去重是提取阶段的关键环节：

```python
def deduplicate_memories(memories: list, similarity_threshold: float = 0.85) -> list:
    """
    记忆去重：基于语义相似度的聚类去重
    """
    unique_memories = []
    for memory in memories:
        is_duplicate = False
        for existing in unique_memories:
            # 计算语义相似度
            similarity = cosine_similarity(
                memory["embedding"],
                existing["embedding"]
            )
            if similarity > similarity_threshold:
                is_duplicate = True
                # 合并：保留置信度更高的
                if memory.get("confidence", 0) > existing.get("confidence", 0):
                    existing.update(memory)
                break

        if not is_duplicate:
            unique_memories.append(memory)

    return unique_memories
```

## 五、三种提取方式的对比

| 维度 | LLM 驱动 | 关键词 (BM25) | 混合方法 |
|------|----------|---------------|----------|
| **召回率（典型值）** | 0.82-0.95 | 0.50-0.70 | 0.85-0.95 |
| **精确率（典型值）** | 0.75-0.90 | 0.60-0.80 | 0.75-0.88 |
| **延迟（P99）** | 2-5s | <20ms | 100-500ms |
| **每千次检索成本** | $3-8 (LLM调用) | $0.001 | $0.50-2 (含小模型) |
| **语义理解** | 优 | 差 | 良 |
| **确定性** | 低（LLM 不稳定） | 高 | 中-高 |
| **实现复杂度** | 低 | 低 | 高 |
| **推荐场景** | 复杂推理型 QA | 精确匹配 | 通用场景首选 |

## 关键概念速查

| 术语 | 解释 |
|------|------|
| **召回率（Recall）** | 检索到的相关记忆占全部相关记忆的比例 |
| **精确率（Precision）** | 检索结果中相关记忆的比例 |
| **多路召回** | 同时使用多种检索方法获取候选集再合并 |
| **Cross-Encoder 重排序** | 使用深度交互模型对候选集进行精细化打分排序 |
| **BM25** | 基于词频和逆文档概率的经典排序函数 |
| **检索时机** | 决定何时触发记忆检索的调度策略 |
| **去重合并** | 消除语义重复的记忆，保留置信度最高的版本 |
