# 7.3 记忆类型——Episodic / Semantic / Procedural

> 认知科学将人类的长期记忆分为三类：**Episodic（情景记忆）**——记得"昨天午饭吃了什么"；**Semantic（语义记忆）**——知道"北京是中国的首都"；**Procedural（程序记忆）**——会"骑自行车"但说不清肌肉如何协调。Agent 记忆系统同样需要这三种不同类型的存储和检索策略。

---

## 一、记忆分类的理论基础

### 1.1 Tulving 的三分模型

加拿大心理学家 Endel Tulving 在 1972 年提出了情景记忆和语义记忆的区分，后续研究补充了程序记忆。三类记忆在人类大脑中由不同的神经系统支持：

```
                  长期记忆 (Long-Term Memory)
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   Episodic         Semantic        Procedural
  (情景记忆)       (语义记忆)       (程序记忆)
        │               │               │
  存储个人经历     存储事实知识     存储行动技能
  海马体主导      颞叶皮层主导     基底核/小脑主导
  "我记得..."     "我知道..."      "我会做..."
```

### 1.2 为什么 Agent 需要这三类记忆？

| 记忆类型 | 人类定义 | Agent 中的对应 | 例子 |
|---------|---------|---------------|------|
| **Episodic** | 特定时间、地点发生的事件 | 对话历史、用户交互记录 | "用户在 2026-05-20 询问过发票功能" |
| **Semantic** | 抽象的事实知识 | 用户画像、产品知识、领域概念 | "用户的公司使用 SAP 系统" |
| **Procedural** | 怎么做一件事的技能 | Agent 的 Tool-Use 能力、Workflow | "如何调用 CRM 系统的 API" |

## 二、Episodic Memory（情景记忆）

### 2.1 定义与特点

Episodic Memory 存储 Agent 与用户交互的**具体事件**。每条记录包含：

- **What**：发生了什么（事件内容）
- **When**：发生的时间戳
- **Where**：发生的上下文（会话 ID、状态）
- **Who**：涉及的角色（用户、Agent、第三方）
- **Affect**：情感/重要性标记

```python
class EpisodicMemory:
    """情景记忆：存储具体交互事件"""
    def __init__(self, db):
        self.db = db

    def record_event(self, event: dict):
        """记录一个交互事件"""
        episode = {
            "type": "episode",
            "content": event["content"],
            "timestamp": time.time(),
            "session_id": event.get("session_id", ""),
            "user_id": event.get("user_id", ""),
            "importance": self._assess_importance(event),
            "emotion": event.get("emotion", "neutral"),
            "entities": event.get("entities", []),
        }
        episode_id = self.db.insert(episode)
        return episode_id

    def recall_events(self, query: str, time_range: tuple = None) -> list:
        """按语义和/或时间范围检索情景"""
        filters = {}
        if time_range:
            filters["timestamp"] = {
                "$gte": time_range[0],
                "$lte": time_range[1]
            }
        return self.db.semantic_search(query, top_k=10, filters=filters)
```

### 2.2 存储策略

情景记忆的特点是**量大、包含噪声、有明确时间线**。存储策略需要平衡完整性和效率：

| 策略 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **逐条记录** | 每条交互独立存储 | 完整保留细节 | 存储量大，检索噪声多 |
| **事件摘要** | 将多轮对话压缩为摘要 | 节省空间，提取关键 | 可能丢失细节 |
| **时间窗口聚合** | 按时间段/主题聚合 | 结构化好 | 边界模糊 |
| **重要性过滤** | 只存储评分 > 阈值的 | 质量高 | 可能错过有用的边缘事件 |

**推荐策略**：组合使用——所有事件短期保留（STM），只将重要性评分>0.6 的晋升为长期情景记忆。

### 2.3 检索策略

情景检索的黄金法则是**时间 + 语义双重约束**：

```
User: "上个月关于预算调整的讨论，结论是什么？"

检索过程:
1. 语义筛选: "预算调整" → 获取所有含该语义的事件
2. 时间筛选: 上个月 (2026-05-01 ~ 2026-05-31)
3. 相关性排序: Cross-Encoder 重排序
4. 摘要生成: 将检索到的多条事件压缩为连贯回答
```

## 三、Semantic Memory（语义记忆）

### 3.1 定义与特点

Semantic Memory 存储 Agent"知道"的事实——用户画像、领域知识、概念关系。它是去语境化的（decontextualized），不绑定特定时间或事件。

```
情景: "2026-05-20 用户在对话中说他的公司用 SAP"
       ↓  经过语义抽取
语义: "用户(张三) 的公司使用 ERP 系统(SAP)"
       ↓  进一步推理 -> 补充知识
      "用户可能对 ERP 集成方案感兴趣"
      "用户的 IT 团队有 SAP 技术栈经验"
```

### 3.2 语义记忆的结构化存储

语义记忆适合用 **知识图谱（Knowledge Graph）或结构化记录** 存储，而不是纯文本：

```python
class SemanticMemory:
    """
    语义记忆：结构化事实知识
    支持 (Subject, Predicate, Object) 三元组存储
    """
    def __init__(self, graph_db=None):
        self.graph_db = graph_db  # Neo4j / ArangoDB
        self.facts = {}           # 本地缓存

    def store_fact(self, subject: str, predicate: str, object_: str,
                   confidence: float = 1.0, source: str = ""):
        """存储一个语义事实"""
        fact = {
            "subject": subject,
            "predicate": predicate,
            "object": object_,
            "confidence": confidence,
            "source": source,
            "created_at": time.time(),
            "updated_at": time.time(),
        }
        fact_id = self._hash_fact(subject, predicate, object_)
        self.facts[fact_id] = fact

        if self.graph_db:
            self.graph_db.create_relationship(
                subject, predicate, object_,
                properties={"confidence": confidence}
            )

    def query_fact(self, subject: str, predicate: str = None) -> list:
        """查询事实"""
        results = []
        for fact_id, fact in self.facts.items():
            if fact["subject"] == subject:
                if predicate is None or fact["predicate"] == predicate:
                    results.append(fact)
        return sorted(results, key=lambda x: x["confidence"], reverse=True)

    def infer_new_facts(self, llm) -> list:
        """
        基于已有事实推理新事实（知识推理）
        例: 知道 "用户_张三→works_at→AcmeCorp",
            知道 "AcmeCorp→uses→Salesforce"
            推断 "用户_张三可能会对 Salesforce API 集成感兴趣"
        """
        # 使用 LLM 执行推理
        existing_facts = list(self.facts.values())
        inferred = llm.knowledge_inference(existing_facts)
        return inferred
```

### 3.3 语义记忆 vs 向量检索

语义记忆与传统 RAG（向量检索）的区别：

| 维度 | 向量检索 (RAG) | 语义记忆 (结构化) |
|------|---------------|-------------------|
| **存储形式** | 文本块 + Embedding | 三元组 (S, P, O) |
| **检索方式** | 语义相似度 | 图遍历 / SPARQL |
| **推理能力** | 无（仅匹配） | 支持链式推理 |
| **更新代价** | 低（追加即可） | 高（需维护一致性） |
| **适用场景** | 非结构化知识 | 明确的实体关系 |
| **去重能力** | 弱（语义相似但文本不同） | 强（主键约束） |

> 实践中，语义记忆和向量检索是互补的。详细的 Embedding 技术见 [第 3 章：向量数据库](../03-数据基础/)，RAG 的实现见 [第 8 章：检索增强生成](../08-RAG/)。

## 四、Procedural Memory（程序记忆）

### 4.1 定义与特点

Procedural Memory 存储 Agent"知道怎么做"的知识——不是事实，而是**流程、技能和行为模式**。在 Agent 系统中，这对应着 Tool-Use 的熟练度、工作流执行模式、以及对特定任务的最佳实践。

```
┌───────────────────────────────────────────────────┐
│  Procedural Memory 在 Agent 中的体现              │
│                                                    │
│  显式程序记忆:                                      │
│  - Tool 的调用签名和参数规范                         │
│  - Workflow 的有向无环图 (DAG)                     │
│  - API 调用模板                                     │
│                                                    │
│  隐式程序记忆:                                      │
│  - 何时调用哪个 Tool 的策略                         │
│  - 错误恢复的常用模式                               │
│  - 多步推理的惯用路径                               │
└───────────────────────────────────────────────────┘
```

### 4.2 程序记忆的存储

```python
class ProceduralMemory:
    """
    程序记忆：存储工具调用技能和工作流
    """
    def __init__(self):
        self.tools = {}           # 显式：API 定义
        self.workflows = {}       # 显式：工作流模板
        self.skill_patterns = []  # 隐式：学习到的模式

    def learn_skill_pattern(self, execution_trace: list):
        """
        从成功的执行轨迹中学习技能模式
        输入: [{"step": 1, "tool": "search", "args": {...}}, ...]
        """
        # 提取模式：在什么条件下调用什么工具
        pattern = {
            "trigger": execution_trace[0]["condition"],
            "steps": [
                {"tool": step["tool"], "args_template": step["args"]}
                for step in execution_trace
            ],
            "success_rate": 1.0,
            "usage_count": 1,
        }
        # 模糊匹配已有模式
        for existing in self.skill_patterns:
            if self._pattern_similarity(pattern, existing) > 0.85:
                # 合并到已有模式
                existing["usage_count"] += 1
                existing["success_rate"] = (
                    existing["success_rate"] * (existing["usage_count"] - 1) + 1.0
                ) / existing["usage_count"]
                return

        self.skill_patterns.append(pattern)

    def suggest_tool(self, task_description: str) -> list:
        """根据任务描述推荐最佳工具和工作流"""
        matches = []
        for pattern in self.skill_patterns:
            if self._match_trigger(task_description, pattern["trigger"]):
                matches.append({
                    "pattern": pattern,
                    "confidence": pattern["success_rate"],
                })
        return sorted(matches, key=lambda x: x["confidence"], reverse=True)
```

### 4.3 程序记忆的学习与强化

程序记忆不是静态的——它通过**实践强化**不断优化：

```
新手 Agent: 每次都问"应该用什么工具？"
    ↓  (学习: 记住 "查询天气 → 调用 weather_api")
有经验 Agent: 自动匹配到最佳工具
    ↓  (强化: 每次成功调用增加 confidence)
专家 Agent: 不仅知道用什么工具，还知道
            "如果 weather_api 超时，自动 fallback 到 backup_api"
```

## 五、三类记忆的协同

### 5.1 统一的记忆管理接口

在实际系统中，三类记忆共享统一的接口：

```python
class UnifiedMemory:
    """
    统一记忆管理器：整合三类记忆
    """
    def __init__(self):
        self.episodic = EpisodicMemory(episodic_db)
        self.semantic = SemanticMemory(graph_db)
        self.procedural = ProceduralMemory()

    def remember(self, experience: dict, memory_type: str = None):
        """
        自动分类并存储记忆
        - Dialog turns → Episodic
        - Extracted facts → Semantic
        - Successful tool calls → Procedural
        """
        if memory_type == "episodic" or (memory_type is None and "event" in experience):
            self.episodic.record_event(experience)
        if memory_type == "semantic" or (memory_type is None and "fact" in experience):
            self.semantic.store_fact(**experience["fact"])
        if memory_type == "procedural" or (memory_type is None and "trace" in experience):
            self.procedural.learn_skill_pattern(experience["trace"])
```

### 5.2 三类记忆的交互模式

```
用户问题: "上次我遇到数据库慢的问题，你是怎么帮我解决的？"

                           ┌──────────────────┐
   语义检索 "用户 数据库慢" │  Semantic Memory │
       (实体匹配)           │  用户=张三       │
                           │  张三有MySQL DB  │
                           └────────┬─────────┘
                                    │
                                    ▼
                           ┌──────────────────┐
   情景检索 "数据库慢 解决"│  Episodic Memory  │
       (事件回顾)           │  2026-04-15: ...  │
                           │  2026-05-03: ...  │
                           └────────┬─────────┘
                                    │
                                    ▼
                           ┌──────────────────┐
   程序检索 "数据库优化"    │ Procedural Memory│
       (技能提取)           │  Step 1: 检查慢查询│
                           │  Step 2: 分析索引  │
                           └──────────────────┘
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| **Episodic Memory** | 情景记忆，存储具体交互事件（What/When/Where/Who） |
| **Semantic Memory** | 语义记忆，存储事实知识（Subject-Predicate-Object 三元组） |
| **Procedural Memory** | 程序记忆，存储工具使用技能和工作流模式 |
| **去语境化** | 从具体事件中剥离时间/地点等上下文，提炼为通用知识 |
| **知识推理** | 基于已知语义事实推断新事实 |
| **技能模式** | 从成功执行轨迹中提取的重复性 Tool-Use 模式 |
| **Tulving 三分模型** | Endel Tulving 提出的情景/语义/程序记忆分类 |
