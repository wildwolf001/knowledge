# 20.3 LLM-as-Judge

> LLM-as-Judge（以大模型为裁判）是一种利用更强的语言模型来评估弱模型输出质量的技术范式。它被广泛应用于开放式生成任务的自动评估中，但也面临评分偏差、校准不一致等挑战。**用模型评估模型，本质上是"用一个不确定系统去度量另一个不确定系统"。**

---

## 一、为什么需要 LLM-as-Judge？

### 1.1 传统评估方法的局限

在 Agent 评估中，许多任务的输出是**开放式的**——没有唯一的正确答案。例如：

```
任务：写一封说服客户续费的邮件
评估难题：什么样的邮件算"好"？标准是什么？
```

| 评估方法 | 适用场景 | 局限性 |
|---------|---------|--------|
| **精确匹配（EM）** | 选择题、分类任务 | 无法评估开放性任务 |
| **N-gram 重叠（ROUGE/BLEU）** | 摘要、翻译 | 忽略语义质量，惩罚同义表达 |
| **Embedding 相似度** | 语义匹配 | 对细粒度质量差异不敏感 |
| **人工评估** | 任何场景 | 成本高、速度慢、一致性差 |
| **LLM-as-Judge** | 开放式生成 | 存在偏差，需要校准 |

### 1.2 LLM-as-Judge 的核心优势

- **速度快**：评估速度是人工的 100-1000 倍
- **成本低**：单次评估成本约 $0.001-0.01（人工约 $0.1-1.0）
- **可扩展**：从 100 个样本扩展到 100 万样本，边际成本几乎为零
- **一致性**：同一模型在相同条件下给出稳定评分（相对于人类评估者的"心情波动"）
- **多维度**：可以针对准确性、流畅性、有用性、安全性等多个维度分别评分

## 二、LLM-as-Judge 的架构设计

### 2.1 基本架构

```
          ┌──────────────┐
          │  评估任务定义  │
          │  (评分标准)    │
          └──────┬───────┘
                 │
    ┌────────────┴────────────┐
    │     评估 Prompt         │
    │  "根据以下标准，从1-5分  │
    │   评估这个回答..."      │
    └────────────┬────────────┘
                 │
    ┌────────────┴────────────┐
    │     Judge LLM           │
    │  (Claude / GPT-4 / ...) │
    └────────────┬────────────┘
                 │
    ┌────────────┴────────────┐
    │   评估输出              │
    │  {"score": 4,           │
    │   "reasoning": "..."}   │
    └─────────────────────────┘
```

### 2.2 完整的 LLM-as-Judge 实现

```python
import json
import re
from typing import List, Dict, Optional
from dataclasses import dataclass, field


@dataclass
class EvaluationCriterion:
    """评估维度定义"""
    name: str                        # 维度名称，如 "accuracy"
    description: str                 # 详细描述
    weight: float = 1.0              # 权重
    min_score: int = 1               # 最低分
    max_score: int = 5               # 最高分


@dataclass
class EvaluationResult:
    """评估结果"""
    overall_score: float             # 综合评分
    dimension_scores: Dict[str, float]  # 各维度评分
    reasoning: str                   # 评分理由
    passed: bool                     # 是否通过阈值


class LLMAsJudge:
    """
    LLM-as-Judge 评估器
    
    使用强语言模型对 Agent 输出进行多维度评估
    """
    
    def __init__(self, judge_model, system_prompt: Optional[str] = None):
        """
        Args:
            judge_model: 用作裁判的 LLM 实例（需要支持 .generate() 方法）
            system_prompt: 可选的系统提示词
        """
        self.judge_model = judge_model
        self.system_prompt = system_prompt or self._default_system_prompt()
    
    def _default_system_prompt(self) -> str:
        return """你是 AI 输出质量评估专家。你的任务是客观、公正地评估 AI 助手的回答质量。
请严格遵循给定的评分标准进行评估，给出分数和详细理由。
避免以下偏差：
1. 位置偏差：不要因为回答在"前面"或"后面"就给出更高分数
2. 长度偏差：不要因为回答更长就认为它更好
3. 自我偏差：不要偏爱与自己（训练数据）风格相似的回答"""
    
    def evaluate(
        self,
        question: str,
        answer: str,
        criteria: List[EvaluationCriterion],
        context: Optional[str] = None,
        reference_answer: Optional[str] = None,
        output_format: str = "json"
    ) -> EvaluationResult:
        """
        评估单个回答
        
        Args:
            question: 用户问题
            answer: Agent 的回答
            criteria: 评估维度列表
            context: 可选的上下文信息（检索文档等）
            reference_answer: 可选的参考答案
            output_format: 输出格式 ("json" 或 "text")
        """
        prompt = self._build_evaluation_prompt(
            question=question,
            answer=answer,
            criteria=criteria,
            context=context,
            reference_answer=reference_answer,
            output_format=output_format
        )
        
        raw_output = self.judge_model.generate(prompt)
        result = self._parse_output(raw_output, criteria, output_format)
        
        return result
    
    def _build_evaluation_prompt(
        self,
        question: str,
        answer: str,
        criteria: List[EvaluationCriterion],
        context: Optional[str] = None,
        reference_answer: Optional[str] = None,
        output_format: str = "json"
    ) -> str:
        """构建评估 prompt"""
        
        # 评分标准描述
        criteria_text = "\n".join([
            f"{i+1}. {c.name}（权重 {c.weight}，评分范围 {c.min_score}-{c.max_score}）：{c.description}"
            for i, c in enumerate(criteria)
        ])
        
        # 总评分规则
        total_score_rule = (
            f"综合评分 = Σ(维度评分 × 维度权重) / Σ(权重)，"
            f"最终结果四舍五入到一位小数。"
        )
        
        prompt = f"""请以 AI 评估专家的身份，对以下 AI 回答进行多维度评估。

## 用户问题
{question}

## AI 回答
{answer}
"""
        
        if context:
            prompt += f"""
## 上下文信息（参考文档）
{context}
"""
        
        if reference_answer:
            prompt += f"""
## 参考答案
{reference_answer}
"""
        
        prompt += f"""
## 评估维度与标准
{criteria_text}

## 评分规则
{total_score_rule}
"""
        
        if output_format == "json":
            prompt += """
## 输出格式
请以合法的 JSON 格式输出评估结果，不要包含其他内容：
{
    "dimension_scores": {
        "accuracy": 4,
        "helpfulness": 5,
        ...
    },
    "reasoning": "针对各个维度的详细评估理由...",
    "overall_score": 4.5
}
"""
        else:
            prompt += """
## 输出格式
请按以下结构输出评估结果：

【各维度评分】
- accuracy（准确性）：X/5
- helpfulness（有用性）：X/5
...

【综合评分】：X.X/5

【评估理由】
（详细说明评分依据）
"""
        
        return prompt
    
    def _parse_output(
        self, 
        raw_output: str, 
        criteria: List[EvaluationCriterion],
        output_format: str
    ) -> EvaluationResult:
        """解析 LLM 的输出为结构化评估结果"""
        
        if output_format == "json":
            return self._parse_json_output(raw_output, criteria)
        else:
            return self._parse_text_output(raw_output, criteria)
    
    def _parse_json_output(
        self, 
        raw_output: str, 
        criteria: List[EvaluationCriterion]
    ) -> EvaluationResult:
        """解析 JSON 格式的评估输出"""
        
        # 尝试从输出中提取 JSON
        json_match = re.search(r'\{.*\}', raw_output, re.DOTALL)
        if json_match:
            try:
                data = json.loads(json_match.group())
            except json.JSONDecodeError:
                # JSON 解析失败，使用 fallback
                return self._fallback_parse(raw_output, criteria)
        else:
            return self._fallback_parse(raw_output, criteria)
        
        dimension_scores = data.get("dimension_scores", {})
        reasoning = data.get("reasoning", "")
        overall_score = data.get("overall_score", 0.0)
        
        # 验证维度评分完整性
        for criterion in criteria:
            if criterion.name not in dimension_scores:
                dimension_scores[criterion.name] = 0.0
        
        # 计算加权综合评分
        if overall_score == 0.0:
            total_weight = sum(c.weight for c in criteria)
            if total_weight > 0:
                overall_score = sum(
                    dimension_scores.get(c.name, 0) * c.weight 
                    for c in criteria
                ) / total_weight
        
        # 归一化到 0-1 范围
        max_possible = max(c.max_score for c in criteria)
        normalized_score = overall_score / max_possible if max_possible > 0 else 0
        
        return EvaluationResult(
            overall_score=round(normalized_score, 2),
            dimension_scores=dimension_scores,
            reasoning=reasoning,
            passed=normalized_score >= 0.6  # 默认阈值 0.6
        )
    
    def _fallback_parse(
        self, 
        raw_output: str, 
        criteria: List[EvaluationCriterion]
    ) -> EvaluationResult:
        """当 JSON 解析失败时的后备解析方法"""
        dimension_scores = {}
        
        for criterion in criteria:
            # 尝试匹配模式 "criterion_name：X/5" 或 "criterion_name: X"
            patterns = [
                rf"{criterion.name}\s*[：:]\s*(\d+(?:\.\d+)?)\s*/\s*{criterion.max_score}",
                rf"{criterion.name}\s*[：:]\s*(\d+(?:\.\d+)?)",
                rf"{criterion.name}.*?(\d+)\s*分"
            ]
            for pattern in patterns:
                match = re.search(pattern, raw_output, re.IGNORECASE)
                if match:
                    score = float(match.group(1))
                    score = max(criterion.min_score, min(criterion.max_score, score))
                    dimension_scores[criterion.name] = score
                    break
            else:
                dimension_scores[criterion.name] = 0.0
        
        # 计算综合评分
        total_weight = sum(c.weight for c in criteria)
        if total_weight > 0:
            overall = sum(
                dimension_scores.get(c.name, 0) * c.weight 
                for c in criteria
            ) / total_weight
        else:
            overall = 0.0
        
        max_possible = max(c.max_score for c in criteria)
        normalized = overall / max_possible if max_possible > 0 else 0
        
        return EvaluationResult(
            overall_score=round(normalized, 2),
            dimension_scores=dimension_scores,
            reasoning=raw_output[:500],  # 截取前 500 字作为理由
            passed=normalized >= 0.6
        )
    
    def batch_evaluate(
        self,
        question_answer_pairs: List[Dict],
        criteria: List[EvaluationCriterion],
        parallel: bool = True,
        max_workers: int = 5
    ) -> List[EvaluationResult]:
        """
        批量评估
        
        Args:
            question_answer_pairs: [{"question": "...", "answer": "...", ...}]
            criteria: 评估维度
            parallel: 是否并行评估
            max_workers: 并行 Worker 数
        """
        results = []
        
        if parallel:
            from concurrent.futures import ThreadPoolExecutor
            with ThreadPoolExecutor(max_workers=max_workers) as executor:
                futures = []
                for item in question_answer_pairs:
                    future = executor.submit(
                        self.evaluate,
                        question=item["question"],
                        answer=item["answer"],
                        criteria=criteria,
                        context=item.get("context"),
                        reference_answer=item.get("reference_answer")
                    )
                    futures.append(future)
                
                for future in futures:
                    results.append(future.result())
        else:
            for item in question_answer_pairs:
                result = self.evaluate(
                    question=item["question"],
                    answer=item["answer"],
                    criteria=criteria,
                    context=item.get("context"),
                    reference_answer=item.get("reference_answer")
                )
                results.append(result)
        
        return results
```

### 2.3 评估 Prompt 设计的核心技巧

**技巧一：明确的评分标准锚定（Anchoring）**

不明确的评分标准导致评分偏差：
```
❌ 差的评分标准：
"请评估这个回答的质量，从1到5分。"

✅ 好的评分标准：
"请从以下维度评估（每个维度1-5分）：
- 准确性（Accuracy）：回答中的每句陈述是否有可靠依据？5分=所有陈述都有据可查
- 有用性（Helpfulness）：回答是否直接解决了用户问题？5分=完全解决且额外提供了有价值的辅助信息
- 完整性（Completeness）：回答是否覆盖了问题的所有方面？5分=无一遗漏"
```

**技巧二：Few-shot 示例校准**

在 prompt 中提供校准示例：
```
示例1（高质量）：
问题：Python 中如何读取 CSV 文件？
回答：使用 csv 模块：`import csv; with open('file.csv') as f: reader = csv.reader(f); for row in reader: print(row)`。对于大型文件建议使用 pandas。
评估：准确性=5，有用性=5，完整性=4
理由：回答精确，提供了直接可用的代码，并给出了大型文件的优化建议。

示例2（低质量）：
问题：Python 中如何读取 CSV 文件？
回答：Python 可以处理文件。
评估：准确性=2，有用性=1，完整性=1
理由：过于笼统，没有提供任何具体方法或代码。
```

**技巧三：Chain-of-Thought（思维链）推理**

要求评估模型先推理再打分，而非直接输出分数：

```
❌ 差的格式：{"score": 4}

✅ 好的格式：请先逐步分析该回答的优缺点，
   然后给出各维度评分，最后计算综合评分。
   评分应基于事实分析而非直觉。
```

## 三、LLM-as-Judge 的偏差问题

### 3.1 偏差类型

| 偏差类型 | 表现 | 严重程度 | 缓解方法 |
|---------|------|---------|---------|
| **位置偏差（Position Bias）** | 在比较评估中，偏好排在前面的回答 | 高 | 交换顺序取平均 |
| **长度偏差（Length Bias）** | 偏好更长的回答（即使内容冗余） | 高 | 在评估标准中明确惩罚冗余 |
| **自我增强偏差（Self-Enhancement Bias）** | Judge 模型更青睐与自己风格相似的输出 | 中 | 使用与评估模型不同家族的 Judge |
| **极端值偏差（Extremity Bias）** | 倾向于给出中间分数（2-4分），避免极端值 | 中 | 强制使用全部评分范围 |
| **锚定偏差（Anchoring Bias）** | 首条评估结果锚定后续评分标准 | 低 | 每次独立评估，不参考历史 |
| **格式偏差（Format Bias）** | 结构化/Markdown格式的回答获得更高评分 | 中 | 标准化输出格式后再评估 |

### 3.2 位置偏差的检测与缓解

**检测方法——对称评估**：

```python
def detect_position_bias(judge, question, answer_a, answer_b):
    """
    检测 Judge 模型的位置偏差
    
    分别以 (A先B后) 和 (B先A后) 两种顺序进行评估，
    如果结果不一致，说明存在位置偏差。
    """
    # 顺序 1：A 在前，B 在后
    result_1 = judge.compare(question, answer_a, answer_b)
    
    # 顺序 2：B 在前，A 在后
    result_2 = judge.compare(question, answer_b, answer_a)
    
    position_bias_detected = False
    
    if result_1.preferred == "A" and result_2.preferred == "A":
        # 无论顺序如何，A 都胜出 → 无位置偏差
        winner = "A"
        confidence = min(result_1.confidence, result_2.confidence) + 0.2
    elif result_1.preferred == "B" and result_2.preferred == "B":
        # 无论顺序如何，B 都胜出 → 无位置偏差
        winner = "B"
        confidence = min(result_1.confidence, result_2.confidence) + 0.2
    else:
        # 结果依赖于顺序 → 位置偏差
        position_bias_detected = True
        # 使用分数平均而非偏好判断
        score_a = (result_1.score_a + result_2.score_b) / 2
        score_b = (result_1.score_b + result_2.score_a) / 2
        winner = "A" if score_a > score_b else "B"
        confidence = abs(score_a - score_b) / (score_a + score_b)
    
    return {
        "winner": winner,
        "confidence": confidence,
        "position_bias_detected": position_bias_detected,
        "order1_result": result_1.preferred,
        "order2_result": result_2.preferred
    }
```

**缓解方案——双向平均评分**：

```python
def position_bias_mitigated_evaluation(judge, question, answer, criteria):
    """
    缓解位置偏差的评估方法
    
    通过对评估标准进行随机排序来消除顺序影响
    """
    import random
    
    # 方法一：随机化评估维度顺序
    shuffled_criteria = criteria.copy()
    random.shuffle(shuffled_criteria)
    result_1 = judge.evaluate(question, answer, shuffled_criteria)
    
    # 方法二：再次随机化评估
    random.shuffle(shuffled_criteria)
    result_2 = judge.evaluate(question, answer, shuffled_criteria)
    
    # 取平均
    avg_score = (result_1.overall_score + result_2.overall_score) / 2
    
    # 一致性检查
    consistency = 1 - abs(result_1.overall_score - result_2.overall_score)
    
    return {
        "score": avg_score,
        "consistency": consistency,
        "run1_score": result_1.overall_score,
        "run2_score": result_2.overall_score,
        "note": "取两次随机化评估的平均值以缓解位置偏差" if consistency < 0.9 else "评估一致性好"
    }
```

### 3.3 自我增强偏差的检测

自我增强偏差（Self-Enhancement Bias）是指 Judge 模型倾向于给与自己同系列或同训练分布的模型打高分：

```python
def detect_self_enhancement_bias(judge_model, answers_by_model):
    """
    检测自我增强偏差
    
    让 Judge 模型评估多个不同模型的输出，
    如果 Judge 对自己家族的模型的评分显著更高，则存在自我增强偏差。
    
    Args:
        judge_model: {"name": "claude-3.5", "family": "anthropic"}
        answers_by_model: {
            "claude-3.5": [...],
            "gpt-4o": [...],
            "llama-3-70b": [...]
        }
    
    Returns:
        bias_report: 偏差分析报告
    """
    import numpy as np
    
    results = {}
    
    for model_name, answers in answers_by_model.items():
        scores = []
        for ans in answers:
            score = judge_model.evaluate(ans["question"], ans["answer"], ans["criteria"])
            scores.append(score.overall_score)
        
        results[model_name] = {
            "avg_score": np.mean(scores),
            "std": np.std(scores),
            "sample_size": len(scores)
        }
    
    # 计算自我增强偏差指数
    same_family_score = results.get(judge_model["family"], {}).get("avg_score", 0)
    other_scores = [
        v["avg_score"] for k, v in results.items() 
        if k != judge_model["family"]
    ]
    avg_other_score = np.mean(other_scores) if other_scores else 0
    
    self_enhancement_index = same_family_score - avg_other_score
    
    return {
        "results": results,
        "self_enhancement_index": self_enhancement_index,
        "bias_detected": self_enhancement_index > 0.3,  # 差异超过 0.3 认为存在偏差
        "recommendation": "考虑使用不同模型家族的 Judge" if self_enhancement_index > 0.3 else "无显著偏差"
    }
```

### 3.4 缓解偏差的最佳实践

1. **使用不同模型家族的 Judge**：评估 Anthropic 模型时，使用 OpenAI 或 Google 的模型作为 Judge
2. **多 Judge 投票**：使用多个 Judge 模型，取评分的中位数或平均值
3. **匿名化评估**：去除回答中的模型标识信息（但这对大型模型效果有限，因为风格差异仍然存在）
4. **校准数据集**：准备一组已知质量的校准样本，定期评估 Judge 的评分一致性
5. **评分理由要求**：要求 Judge 先给出具体理由再给分数，减少直觉性偏差

## 四、评分一致性校准（Calibration）

### 4.1 评估者间一致性（Inter-Rater Reliability）

当使用多个 Judge 模型或同一 Judge 在不同条件下评估时，需要衡量评分一致性：

**Cohen's Kappa（两位评估者）**：

```
κ = (P_o - P_e) / (1 - P_e)

其中：
- P_o = 观察一致率（两位评估者给出相同评分的比例）
- P_e = 随机一致概率（两位评估者偶然给出相同评分的概率）
```

```python
def cohens_kappa(scores_a, scores_b, num_categories=5):
    """
    计算 Cohen's Kappa 系数评估评分者间一致性
    
    Args:
        scores_a: 评估者 A 的评分列表
        scores_b: 评估者 B 的评分列表
        num_categories: 评分类别数
    
    Returns:
        kappa: Cohen's Kappa 值 (-1 到 1)
    """
    import numpy as np
    
    # 构建混淆矩阵
    n = len(scores_a)
    confusion = np.zeros((num_categories, num_categories))
    for a, b in zip(scores_a, scores_b):
        # 将分数映射到类别索引（假设分数为 1-5 分）
        i = min(int(a) - 1, num_categories - 1)
        j = min(int(b) - 1, num_categories - 1)
        confusion[i][j] += 1
    
    # 计算 P_o（观察一致率）
    po = np.trace(confusion) / n
    
    # 计算 P_e（随机一致概率）
    row_sums = confusion.sum(axis=1)
    col_sums = confusion.sum(axis=0)
    pe = sum(row_sums[i] * col_sums[i] for i in range(num_categories)) / (n * n)
    
    if pe == 1:
        return 1.0
    
    kappa = (po - pe) / (1 - pe)
    return kappa

# 一致性解释
# κ > 0.8: 几乎完全一致
# 0.6 < κ < 0.8: 高度一致
# 0.4 < κ < 0.6: 中度一致
# κ < 0.4: 一致性差
```

**Krippendorff's Alpha（多位评估者）**：

适用于多位评估者和有序评分的数据：

```python
def krippendorff_alpha(scores_matrix):
    """
    计算 Krippendorff's Alpha 系数
    
    Args:
        scores_matrix: 评估者 × 样本 的评分矩阵，
                       缺失值为 NaN
    
    Returns:
        alpha: Krippendorff's Alpha 值
    """
    import numpy as np
    
    # scores_matrix shape: (n_raters, n_samples)
    n_raters, n_samples = scores_matrix.shape
    
    # 获取所有有效评分
    valid_mask = ~np.isnan(scores_matrix)
    
    # 计算观察到的分歧
    observed_disagreement = 0
    n_pairs = 0
    
    for s in range(n_samples):
        valid_raters = np.where(valid_mask[:, s])[0]
        for i in range(len(valid_raters)):
            for j in range(i + 1, len(valid_raters)):
                r1, r2 = valid_raters[i], valid_raters[j]
                diff = scores_matrix[r1, s] - scores_matrix[r2, s]
                observed_disagreement += diff * diff
                n_pairs += 1
    
    if n_pairs == 0:
        return float('nan')
    
    observed_disagreement /= n_pairs
    
    # 计算期望的分歧（基于随机配对）
    all_valid_scores = scores_matrix[valid_mask]
    expected_disagreement = 0
    n_comparisons = 0
    
    for i in range(len(all_valid_scores)):
        for j in range(i + 1, len(all_valid_scores)):
            diff = all_valid_scores[i] - all_valid_scores[j]
            expected_disagreement += diff * diff
            n_comparisons += 1
    
    if n_comparisons == 0:
        return float('nan')
    
    expected_disagreement /= n_comparisons
    
    if expected_disagreement == 0:
        return 1.0
    
    alpha = 1 - (observed_disagreement / expected_disagreement)
    return alpha
```

### 4.2 Judge 校准方法

当发现 Judge 的评分存在系统性偏差时，需要进行校准。

**方法一：线性校准（Linear Calibration）**

假设 Judge 的评分与被评估质量之间存在线性偏差：

```python
def linear_calibration(judge_scores, human_scores):
    """
    线性校准：学习 Judge 评分到"真实"评分的映射
    
    使用线性回归：human = α × judge + β
    
    Args:
        judge_scores: Judge 给出的评分列表
        human_scores: 人类给出的评分列表（作为 ground truth）
    
    Returns:
        calibrator: 校准函数
        metrics: 校准前后的误差指标
    """
    import numpy as np
    from sklearn.linear_model import LinearRegression
    
    X = np.array(judge_scores).reshape(-1, 1)
    y = np.array(human_scores)
    
    model = LinearRegression()
    model.fit(X, y)
    
    alpha = model.coef_[0]
    beta = model.intercept_
    
    # 校准前的 MAE
    mae_before = np.mean(np.abs(X.flatten() - y))
    
    # 校准后的 MAE
    calibrated = model.predict(X)
    mae_after = np.mean(np.abs(calibrated - y))
    
    def calibrator(score):
        return model.predict([[score]])[0]
    
    return {
        "calibrator": calibrator,
        "alpha": alpha,
        "beta": beta,
        "mae_before": mae_before,
        "mae_after": mae_after,
        "improvement": (mae_before - mae_after) / mae_before * 100
    }
```

**方法二：Platt Scaling（逻辑回归校准）**

用于二分类评估（好/坏）的校准：

```python
def platt_scaling(judge_scores, binary_labels):
    """
    Platt Scaling：将 Judge 评分映射到概率
    
    适用于"回答是否可用"这样的二分类评估
    
    Args:
        judge_scores: Judge 评分（连续值或离散值）
        binary_labels: 人类标注的二分类标签（0/1）
    
    Returns:
        calibrated_probability: 校准后的概率值
    """
    from sklearn.linear_model import LogisticRegression
    
    X = np.array(judge_scores).reshape(-1, 1)
    y = np.array(binary_labels)
    
    calibrator = LogisticRegression()
    calibrator.fit(X, y)
    
    return calibrator
```

### 4.3 校准效果评估

```python
def evaluate_calibration(probabilities, binary_labels, n_bins=10):
    """
    评估校准效果
    
    使用 ECE（Expected Calibration Error）指标
    """
    import numpy as np
    
    bin_boundaries = np.linspace(0, 1, n_bins + 1)
    
    ece = 0.0
    for i in range(n_bins):
        # 找到落在该区间的样本
        in_bin = (probabilities >= bin_boundaries[i]) & \
                 (probabilities < bin_boundaries[i + 1])
        
        bin_size = np.sum(in_bin)
        if bin_size == 0:
            continue
        
        # bin 内的平均预测概率
        avg_pred = np.mean(probabilities[in_bin])
        
        # bin 内的实际正例比例
        actual_pos = np.mean(binary_labels[in_bin])
        
        # 累积 ECE
        ece += np.abs(avg_pred - actual_pos) * (bin_size / len(probabilities))
    
    return ece

# ECE < 0.05: 校准良好
# 0.05 < ECE < 0.1: 中度校准偏差
# ECE > 0.1: 校准偏差大，需要重新校准
```

```python
def evaluate_multi_turn_conversation(judge, conversation, criteria):
```

## 六、LLM-as-Judge 的工程化建议

1. **成本与质量权衡**：使用 Claude 3.5 Sonnet / GPT-4o 作为主 Judge（性价比最优），需要高精度时使用 Claude 3.5 Opus / GPT-4-Turbo

2. **分层评估架构**：
   - 第一层：规则检查（格式、关键词、长度）—— 零成本
   - 第二层：轻量 Judge（Claude 3 Haiku / GPT-4o-mini）—— 低成本
   - 第三层：专业 Judge（Claude 3.5 Sonnet / GPT-4o）—— 中等成本
   - 第四层：专家 Judge（人类评估）—— 高成本，仅用于校准和抽样验证

3. **评估缓存**：相同的 (question, answer) 对在相同评估标准下结果应可缓存复用

4. **定期偏差审计**：每周对 Judge 进行一次偏差检测，使用固定的校准集

5. **回退机制**：当 Judge 评分方差过大（同一任务多次评估结果不一致）时，自动升级到高级 Judge 或人工评估
