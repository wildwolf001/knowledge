# 20.5 Agent A/B 测试与实验设计

> 当你要回答"新版本的 Agent 真的更好吗？"时，**A/B 测试是唯一的可靠答案**。Agent 系统的评估涉及多步交互、工具调用、用户反馈，其复杂性远超传统 Web A/B 测试。**没有对照组的"改进"只是自我安慰。**

---

## 一、为什么 Agent 需要 A/B 测试？

### 1.1 传统评估的盲区

在 20.1 节的离线评估中，我们用基准数据集测试了 Agent 的质量。但离线评估的局限性：

| 问题 | 离线评估 | A/B 测试 |
|------|---------|---------|
| **数据分布** | 固定的测试集 | 真实在线流量 |
| **用户行为** | 无真实用户反馈 | 有真实用户行为 |
| **上下文多样性** | 有限的预设场景 | 无限的真实场景 |
| **长尾效应** | 难以覆盖 | 自然暴露 |
| **交互深度** | 单次或有限多轮 | 完整真实交互 |

**一个经典案例**：
```
离线评估显示：V2 版本的任务完成率比 V1 高 8%（72% → 80%）
团队信心满满地全量上线 V2。

结果：
- 转人工率上升了 15%（20% → 35%）
- 用户满意度从 4.2 降到了 3.6
- 平均处理时长增加了 40%

根因分析发现：
V2 在某些场景下表现得"更好"（更高的完成率），
但它在其他场景上的"过度自信"（详见 14.5 节）
导致了更多需要人工介入的复杂情况。
```

**教训**：离线评估的指标提升不必然转化为在线业务指标的改善。A/B 测试是连接离线评估与业务效果的桥梁。

### 1.2 Agent A/B 测试的特殊挑战

| 挑战 | 传统 Web A/B | Agent A/B |
|------|-------------|-----------|
| **干预单元** | 页面展示 | 完整对话（可能跨多轮） |
| **延迟反馈** | 即时（点击/转化） | 延迟（用户可能在多轮后才给出评价） |
| **状态残留** | 无状态（每次独立） | 有状态（Agent 的操作改变系统状态） |
| **评估指标** | 简单（CTR、CVR） | 复合（成功率、满意度、转人工率等） |
| **用户感知** | 低（按钮颜色/文案） | 高（回答质量影响体验） |

## 二、受控实验设计（Controlled Experiment Design）

### 2.1 实验设计的基本原则

**RCT（Randomized Controlled Trial，随机对照试验）**是 A/B 测试的黄金标准：

```
1. 随机分配（Randomization）：用户/会话随机分配到对照组和实验组
2. 对照原则（Control）：对照组使用当前生产版本
3. 双盲（Double Blind）：用户和评估者都不知道分组情况
4. 重复（Replication）：足够的样本量确保统计效力
```

**Agent 实验的分配层级**：

```python
class ExperimentDesigner:
    """
    Agent A/B 实验设计器
    
    支持会话级和用户级随机分配
    """
    
    def __init__(self, experiment_name: str):
        self.name = experiment_name
        self.variants = {}  # {variant_name: config}
        self.assignment_unit = "session"  # "session" 或 "user"
    
    def add_variant(self, name: str, config: dict, traffic_percentage: float):
        """
        添加实验变体
        
        Args:
            name: 变体名称（如 "control", "v2"）
            config: Agent 配置（prompt、model、tools 等）
            traffic_percentage: 流量百分比
        """
        self.variants[name] = {
            "config": config,
            "traffic_pct": traffic_percentage
        }
    
    def assign(self, user_id: str = None, session_id: str = None) -> str:
        """
        分配用户/会话到实验组
        
        使用确定性哈希确保同一用户的分配结果稳定
        """
        import hashlib
        
        identifier = user_id if self.assignment_unit == "user" else session_id
        
        if not identifier:
            identifier = f"{self.name}_{self._random_id()}"
        
        # 使用 MD5 哈希实现确定性分配
        hash_key = f"{self.name}:{identifier}"
        hash_value = hashlib.md5(hash_key.encode()).hexdigest()
        # 将哈希值映射到 0-99
        bucket = int(hash_value[:8], 16) % 100
        
        # 根据流量百分比分配
        cumulative = 0
        for name, variant in self.variants.items():
            cumulative += variant["traffic_pct"] * 100
            if bucket < cumulative:
                return name
        
        return list(self.variants.keys())[-1]
    
    def _random_id(self) -> str:
        import uuid
        return str(uuid.uuid4())[:8]
```

### 2.2 分流策略

**会话级分流（Session-level）**：每次新对话随机分配，同一用户的不同对话可能分到不同组。

```
优点：简单快捷，样本收集快
缺点：同一用户可能经历不同版本，造成体验不一致
适用于：短期实验、非用户感知的 Agent 功能
```

**用户级分流（User-level）**：同一用户始终分到同一组。

```
优点：体验一致，用户不会困惑
缺点：样本收集慢，需要等新用户积累
适用于：用户体验敏感的实验
```

**时间段分流（Time-sliced）**：按时间段切换版本。

```
优点：实现最简单，完全避免组间污染
缺点：受时间效应影响（白天/夜晚用户行为不同）
不推荐：除非无法实现真实随机分流的特殊场景
```

### 2.3 混淆变量控制（Confounding Variable Control）

Agent 实验中常见的混淆变量：

| 混淆变量 | 影响 | 控制方法 |
|---------|------|---------|
| **用户特征** | 不同用户群体对 Agent 的接受度不同 | 用户级随机化 + 分层分析 |
| **时间效应** | 同一用户在不同时间的需求不同 | 同时运行实验组和对照组 |
| **任务难度** | 不同对话的任务复杂程度不同 | 实验前后做任务难度匹配 |
| **Novelty 效应** | 用户对新版本的"新鲜感"带来短期偏差 | 延长实验周期（至少 1-2 周） |
| **位置偏差** | Agent 回答中不同位置的信息 | 交叉实验设计（见 20.3 节） |

**Novelty 效应的检测方法**：

```python
def detect_novelty_effect(daily_metrics: pd.DataFrame, experiment_start: str):
    """
    检测 Novelty 效应
    
    思路：如果实验组指标在实验初期显著提升但随后衰减，
    则可能是 Novelty 效应而非真实改进。
    
    使用"第一天 vs 后续周"的指标对比
    """
    experiment_data = daily_metrics[daily_metrics["date"] >= experiment_start]
    
    # 将实验期分为初期（第1-3天）和稳定期（第4天以后）
    early_period = experiment_data.iloc[:3]
    stable_period = experiment_data.iloc[3:]
    
    if len(early_period) == 0 or len(stable_period) == 0:
        return {"novelty_detected": None, "reason": "数据不足"}
    
    control_early = early_period[early_period["variant"] == "control"]["metric"]
    treatment_early = early_period[early_period["variant"] == "treatment"]["metric"]
    control_stable = stable_period[stable_period["variant"] == "control"]["metric"]
    treatment_stable = stable_period[stable_period["variant"] == "treatment"]["metric"]
    
    early_effect = treatment_early.mean() - control_early.mean()
    stable_effect = treatment_stable.mean() - control_stable.mean()
    
    # 如果早期效果明显但稳定期效果显著衰减
    effect_decay = abs(early_effect) - abs(stable_effect)
    novelty_ratio = effect_decay / abs(early_effect) if abs(early_effect) > 0 else 0
    
    return {
        "novelty_detected": novelty_ratio > 0.3,  # 衰减超过 30% 认为存在 Novelty 效应
        "early_effect": early_effect,
        "stable_effect": stable_effect,
        "effect_decay": effect_decay,
        "novelty_ratio": novelty_ratio,
        "recommendation": "延长实验周期，等待 Novelty 效应消退后再做结论" if novelty_ratio > 0.3 else "无显著 Novelty 效应"
    }
```

## 三、统计显著性检验（Statistical Significance Testing）

### 3.1 假设检验基础

```
原假设 H₀：新旧版本的效果没有差异（μ_旧 = μ_新）
备择假设 H₁：新旧版本的效果有显著差异（μ_旧 ≠ μ_新）

显著性水平 α = 0.05（第一类错误：假阳性）
统计功效 Power = 0.80（避免第二类错误：假阴性）
```

### 3.2 t 检验（Student's t-test）

对于连续型指标（如满意度评分、处理时长），使用独立样本 t 检验：

```python
import numpy as np
from scipy import stats

def independent_t_test(control_group: np.ndarray, treatment_group: np.ndarray) -> dict:
    """
    独立样本 t 检验
    
    适用于比较两组不相关的样本（如对照组和实验组）
    
    Args:
        control_group: 对照组的指标值数组
        treatment_group: 实验组的指标值数组
    
    Returns:
        test_result: 检验结果
    """
    n1 = len(control_group)
    n2 = len(treatment_group)
    
    mean1 = np.mean(control_group)
    mean2 = np.mean(treatment_group)
    
    var1 = np.var(control_group, ddof=1)
    var2 = np.var(treatment_group, ddof=1)
    
    # 合并标准误（Welch's t-test，不假设方差相等）
    se = np.sqrt(var1/n1 + var2/n2)
    
    # t 统计量
    t_stat = (mean1 - mean2) / se
    
    # Welch-Satterthwaite 自由度
    df = (var1/n1 + var2/n2)**2 / (
        (var1/n1)**2/(n1-1) + (var2/n2)**2/(n2-1)
    )
    
    # p 值（双尾检验）
    p_value = 2 * stats.t.sf(abs(t_stat), df)
    
    # 效应量（Cohen's d）
    pooled_std = np.sqrt(((n1-1)*var1 + (n2-1)*var2) / (n1+n2-2))
    cohens_d = abs(mean1 - mean2) / pooled_std
    
    # 置信区间（95%）
    t_critical = stats.t.ppf(0.975, df)
    ci_lower = (mean1 - mean2) - t_critical * se
    ci_upper = (mean1 - mean2) + t_critical * se
    
    return {
        "test_type": "Independent t-test (Welch's)",
        "control_mean": round(mean1, 4),
        "treatment_mean": round(mean2, 4),
        "difference": round(mean2 - mean1, 4),
        "t_statistic": round(t_stat, 4),
        "degrees_of_freedom": round(df, 2),
        "p_value": round(p_value, 6),
        "significant": p_value < 0.05,
        "effect_size": round(cohens_d, 4),
        "effect_size_interpretation": _interpret_cohens_d(cohens_d),
        "ci_95": [round(ci_lower, 4), round(ci_upper, 4)],
        "relative_improvement": round((mean2 - mean1) / mean1 * 100, 2) if mean1 != 0 else None,
        "sample_sizes": {"control": n1, "treatment": n2}
    }


def _interpret_cohens_d(d: float) -> str:
    """解释 Cohen's d 效应量"""
    if d < 0.2:
        return "微小效应（negligible）"
    elif d < 0.5:
        return "小效应（small）"
    elif d < 0.8:
        return "中等效应（medium）"
    else:
        return "大效应（large）"


# 配对 t 检验（适用于同一组实验前后的对比）
def paired_t_test(before: np.ndarray, after: np.ndarray) -> dict:
    """
    配对 t 检验
    
    适用于同一批用户在实验前后的指标对比
    """
    differences = after - before
    n = len(differences)
    
    mean_diff = np.mean(differences)
    std_diff = np.std(differences, ddof=1)
    se = std_diff / np.sqrt(n)
    
    t_stat = mean_diff / se
    df = n - 1
    p_value = 2 * stats.t.sf(abs(t_stat), df)
    
    cohens_d = mean_diff / std_diff
    
    t_critical = stats.t.ppf(0.975, df)
    ci_lower = mean_diff - t_critical * se
    ci_upper = mean_diff + t_critical * se
    
    return {
        "test_type": "Paired t-test",
        "mean_difference": round(mean_diff, 4),
        "t_statistic": round(t_stat, 4),
        "p_value": round(p_value, 6),
        "significant": p_value < 0.05,
        "effect_size": round(cohens_d, 4),
        "ci_95": [round(ci_lower, 4), round(ci_upper, 4)],
        "sample_size": n
    }
```

### 3.3 比例检验（z 检验）

对于比率型指标（如任务完成率、转人工率），使用比例 z 检验：

```python
def proportion_z_test(control_success: int, control_total: int, 
                       treatment_success: int, treatment_total: int) -> dict:
    """
    比例 z 检验
    
    适用于比较两个比例（如成功率、转人工率）
    
    Args:
        control_success: 对照组成功次数
        control_total: 对照组总次数
        treatment_success: 实验组成功次数
        treatment_total: 实验组总次数
    
    Returns:
        test_result: 检验结果
    """
    p1 = control_success / control_total
    p2 = treatment_success / treatment_total
    
    # 合并比例（在原假设下）
    p_pool = (control_success + treatment_success) / (control_total + treatment_total)
    
    # 标准误
    se = np.sqrt(p_pool * (1 - p_pool) * (1/control_total + 1/treatment_total))
    
    # z 统计量
    z_stat = (p2 - p1) / se
    
    # p 值（双尾）
    p_value = 2 * (1 - stats.norm.cdf(abs(z_stat)))
    
    # 风险比（Risk Ratio）
    risk_ratio = p2 / p1 if p1 > 0 else float('inf')
    
    return {
        "test_type": "Two-proportion z-test",
        "control_rate": round(p1, 4),
        "treatment_rate": round(p2, 4),
        "absolute_difference": round(p2 - p1, 4),
        "relative_improvement": round((p2 - p1) / p1 * 100, 2) if p1 > 0 else None,
        "risk_ratio": round(risk_ratio, 4),
        "z_statistic": round(z_stat, 4),
        "p_value": round(p_value, 6),
        "significant": p_value < 0.05,
        "sample_sizes": {"control": control_total, "treatment": treatment_total}
    }
```

### 3.4 多重比较校正

当同时评估多个指标时（如同时看成功率、满意度、转人工率），需要进行多重比较校正以避免"打了很多枪总会打中一个"：

```python
def bonferroni_correction(p_values: list, alpha: float = 0.05) -> list:
    """
    Bonferroni 校正
    
    最简单的多重比较校正方法：将显著性水平除以比较次数
    """
    m = len(p_values)
    corrected_alpha = alpha / m
    
    return {
        "corrected_alpha": corrected_alpha,
        "original_p_values": p_values,
        "significant_after_correction": [p < corrected_alpha for p in p_values],
        "note": f"对 {m} 个假设进行了 Bonferroni 校正，校正后 α = {corrected_alpha:.6f}"
    }


def benjamini_hochberg_correction(p_values: list, alpha: float = 0.05, 
                                    output_format: str = "table") -> dict:
    """
    Benjamini-Hochberg 校正（FDR 控制）
    
    比 Bonferroni 更宽松，控制错误发现率（False Discovery Rate）
    适用于探索性分析中观察多个指标
    """
    m = len(p_values)
    sorted_indices = np.argsort(p_values)
    sorted_p = np.array(p_values)[sorted_indices]
    
    # 计算 BH 临界值
    thresholds = np.array([(i + 1) / m * alpha for i in range(m)])
    
    # 找到最大的满足 p_i <= threshold 的 i
    significant_mask = sorted_p <= thresholds
    
    if any(significant_mask):
        max_significant = np.max(np.where(significant_mask))
        significant_indices = sorted_indices[:max_significant + 1]
    else:
        significant_indices = []
    
    return {
        "correction_method": "Benjamini-Hochberg (FDR)",
        "corrected_thresholds": thresholds.tolist(),
        "significant_indices": significant_indices.tolist(),
        "original_p_values": p_values,
        "note": f"在 {m} 个假设中发现了 {len(significant_indices)} 个显著性结果"
    }
```

## 四、样本量计算（Sample Size Calculation）

### 4.1 为什么需要样本量计算？

样本量太小 ⇒ 即使有效果也无法检测出（低统计功效）
样本量太大 ⇒ 浪费流量和成本（微小无意义的差异也可能"统计显著"）

**样本量估算的输入参数**：
- α = 0.05（显著性水平；犯第一类错误的概率）
- β = 0.20（统计功效 = 1-β = 0.80；检测到差异的概率）
- δ = 最小可检测效应量（Minimum Detectable Effect, MDE）
- σ = 指标的标准差

### 4.2 连续型指标样本量计算

```python
def sample_size_continuous(mde: float, std_dev: float, alpha: float = 0.05, 
                            power: float = 0.80, alternative: str = "two-sided") -> dict:
    """
    连续型指标的样本量计算（每组的样本量）
    
    适用场景：满意度评分、处理时长等连续指标
    
    Args:
        mde: 最小可检测效应量（绝对差值）
        std_dev: 指标的标准差
        alpha: 显著性水平（默认 0.05）
        power: 统计功效（默认 0.80）
        alternative: 检验方向
    
    Returns:
        每组所需的样本量和计算参数
    """
    # Z 值查找
    if alternative == "two-sided":
        z_alpha = stats.norm.ppf(1 - alpha / 2)
    else:
        z_alpha = stats.norm.ppf(1 - alpha)
    
    z_beta = stats.norm.ppf(power)
    
    # 标准化效应量（Cohen's d）
    effect_size = mde / std_dev
    
    # 样本量公式（每组的样本量）
    # n = 2 × (z_α/2 + z_β)² / δ²
    n_per_group = int(np.ceil(2 * (z_alpha + z_beta)**2 / (effect_size**2)))
    
    return {
        "required_sample_per_group": n_per_group,
        "total_required": n_per_group * 2,
        "parameters": {
            "mde": mde,
            "std_dev": std_dev,
            "effect_size": round(effect_size, 4),
            "alpha": alpha,
            "power": power,
            "alternative": alternative,
            "z_alpha": round(z_alpha, 4),
            "z_beta": round(z_beta, 4)
        },
        "practical_considerations": {
            "expected_duration_hours": f"约 {n_per_group * 2 / 1000:.1f} 小时" if n_per_group > 0 else "N/A",
            "note": "假设每小时 1000 个会话" if n_per_group > 0 else ""
        }
    }
```

### 4.3 比例型指标样本量计算

```python
def sample_size_proportion(baseline_rate: float, mde_relative: float, 
                            alpha: float = 0.05, power: float = 0.80) -> dict:
    """
    比例型指标的样本量计算
    
    适用场景：完成率、转人工率等比例指标
    
    Args:
        baseline_rate: 对照组的基准比例（如 0.70 = 70%）
        mde_relative: 相对最小可检测效应（如 0.10 = 10% 的相对提升）
        alpha: 显著性水平
        power: 统计功效
    
    Returns:
        样本量计算结果
    """
    # 绝对效应量
    mde_absolute = baseline_rate * mde_relative
    
    # 实验组预期比例
    treatment_rate = baseline_rate + mde_absolute
    
    # 平均比例
    p_bar = (baseline_rate + treatment_rate) / 2
    
    # Z 值
    z_alpha = stats.norm.ppf(1 - alpha / 2)
    z_beta = stats.norm.ppf(power)
    
    # 样本量公式
    numerator = (z_alpha * np.sqrt(2 * p_bar * (1 - p_bar)) + 
                 z_beta * np.sqrt(baseline_rate * (1 - baseline_rate) + 
                                  treatment_rate * (1 - treatment_rate)))**2
    denominator = mde_absolute**2
    
    n_per_group = int(np.ceil(numerator / denominator))
    
    return {
        "required_sample_per_group": n_per_group,
        "total_required": n_per_group * 2,
        "parameters": {
            "baseline_rate": baseline_rate,
            "expected_treatment_rate": round(treatment_rate, 4),
            "absolute_mde": round(mde_absolute, 4),
            "relative_mde": mde_relative,
            "alpha": alpha,
            "power": power
        },
        "example_scenarios": [
            {"traffic_per_day": 5000, "days_needed": round(n_per_group * 2 / 5000, 1)},
            {"traffic_per_day": 10000, "days_needed": round(n_per_group * 2 / 10000, 1)},
            {"traffic_per_day": 50000, "days_needed": round(n_per_group * 2 / 50000, 1)}
        ]
    }
```

### 4.4 样本量速查表

对于常见的 Agent 指标，预设的样本量速查：

## 五、Agent A/B 测试的完整流程

### 5.1 实验设计模板

```python
class AgentABTest:
    """
    Agent A/B 测试完整流程
    
    包含：实验设计 → 分流 → 数据采集 → 统计分析 → 结论判定
    """
    
    def __init__(self, config: dict):
        self.name = config["name"]
        self.control_config = config["control"]
        self.treatment_config = config["treatment"]
        self.metrics = config["metrics"]  # 主要和次要指标
        self.design = ExperimentDesigner(self.name)
        
        # 设置分流
        self.design.add_variant("control", self.control_config, 0.5)
        self.design.add_variant("treatment", self.treatment_config, 0.5)
    
    def analyze_results(self, experiment_data: pd.DataFrame) -> dict:
        """
        分析 A/B 测试结果
        
        Args:
            experiment_data: 包含所有实验数据的 DataFrame
                必填列: variant, metric_name, metric_value
        
        Returns:
            analysis_report: 完整的分析报告
        """
        report = {
            "experiment_name": self.name,
            "timestamp": self._timestamp(),
            "summary": {},
            "detail": {}
        }
        
        for metric in self.metrics:
            metric_name = metric["name"]
            metric_type = metric.get("type", "continuous")  # "continuous" or "proportion"
            
            # 分离对照组和实验组数据
            control_data = experiment_data[
                (experiment_data["variant"] == "control") & 
                (experiment_data["metric_name"] == metric_name)
            ]["metric_value"]
            
            treatment_data = experiment_data[
                (experiment_data["variant"] == "treatment") & 
                (experiment_data["metric_name"] == metric_name)
            ]["metric_value"]
            
            if len(control_data) == 0 or len(treatment_data) == 0:
                report["detail"][metric_name] = {"error": "数据不足"}
                continue
            
            # 执行统计检验
            if metric_type == "continuous":
                test_result = independent_t_test(
                    control_data.values, treatment_data.values
                )
            elif metric_type == "proportion":
                control_success = int(control_data.sum())
                control_total = len(control_data)
                treatment_success = int(treatment_data.sum())
                treatment_total = len(treatment_data)
                
                test_result = proportion_z_test(
                    control_success, control_total,
                    treatment_success, treatment_total
                )
            
            report["detail"][metric_name] = test_result
            
            # 记录摘要
            is_primary = metric.get("primary", False)
            if is_primary:
                report["summary"]["primary_metric"] = metric_name
                report["summary"]["significant"] = test_result.get("significant", False)
                report["summary"]["p_value"] = test_result.get("p_value")
                report["summary"]["improvement"] = test_result.get("relative_improvement")
        
        # 总体判定
        report["verdict"] = self._make_verdict(report)
        
        return report
    
    def _make_verdict(self, report: dict) -> dict:
        """生成实验结论"""
        summary = report.get("summary", {})
        
        if not summary.get("significant"):
            return {
                "decision": "不确定",
                "recommendation": "继续收集数据或停止实验",
                "details": "主要指标未达到统计显著性，无法得出可靠结论"
            }
        
        improvement = summary.get("improvement", 0)
        if improvement > 0:
            return {
                "decision": "实验组胜出",
                "recommendation": "建议全量发布新版本",
                "confidence": f"p = {summary.get('p_value', 'N/A')}",
                "effect_size": f"{improvement:.2f}% 改善"
            }
        else:
            return {
                "decision": "对照组胜出",
                "recommendation": "保留现有版本，分析实验组的问题",
                "details": "新版本未带来改善，甚至更差"
            }
    
    def _timestamp(self):
        from datetime import datetime
        return datetime.now().isoformat()
```

### 5.2 完整实验流程

```
阶段 1：实验设计（1-2 天）
├── 确定实验假设（H₀ 和 H₁）
├── 选择主要指标（Primary Metric）和次要指标（Secondary Metrics）
├── 计算所需样本量
├── 确定实验周期（至少覆盖一个完整业务周期）
└── 设计分流方案

阶段 2：实验实施（实验周期）
├── 部署实验版本（对照组 + 实验组）
├── 启动分流
├── 实时监控（防止异常）
└── 记录所有实验数据

阶段 3：数据分析（1 天）
├── 数据清洗（剔除机器人流量、无效会话）
├── 描述性统计
├── 统计显著性检验
├── 效应量评估
├── 多重比较校正
└── 敏感性分析

阶段 4：结果解读与决策
├── 统计显著 ⇒ 业务显著？ 
│   ├── 是 ⇒ 全量发布
│   └── 否 ⇒ 评估是否值得上线（微小改进可能不值得）
├── 统计不显著 ⇒ 是否有趋势？
│   ├── 有趋势 ⇒ 延长实验周期或增加样本量
│   └── 无趋势 ⇒ 放弃当前方案，尝试新方向
└── 副作用分析 ⇒ 检查次要指标是否恶化
```

### 5.3 实验注意事项

**PEESE 规则（Practicality, Ethics, Economics, Statistical power, Effect size）**：

```
P - Practicality（实用性）：实验设计是否可实施？
    - 分流机制是否稳定？
    - 数据采集是否完整？
    
E - Ethics（伦理）：实验是否对用户造成伤害？
    - 实验组是否可能给出危险的建议？
    - 是否已做好安全兜底？
    
E - Economics（经济性）：实验成本是否合理？
    - 计算资源、API 调用成本是否可控？
    
S - Statistical power（统计效力）：样本量是否充足？
    - 是否已做功效分析？
    - 能否在合理时间内收集到足够的样本？
    
E - Effect size（效应量）：改善是否具有实际意义？
    - 即使统计显著，3% 的改善是否值得上线？
    - 是否考虑了工程成本？
```

## 六、渐进式发布策略（Progressive Rollout）

### 6.1 阶梯式发布

在 A/B 测试验证了新版 Agent 的优越性后，采用渐进式发布来控制风险：

```python
class ProgressiveRollout:
    """
    渐进式发布管理器
    
    逐步增加新版本的流量比例，每个阶段验证指标后进入下一阶段
    """
    
    def __init__(self, new_version_config: dict, 
                 metrics_monitor, alert_thresholds: dict = None):
        self.config = new_version_config
        self.monitor = metrics_monitor
        self.thresholds = alert_thresholds or {
            "task_success_rate": {"min": 0.70},
            "handoff_rate": {"max": 0.35},
            "ttft_p95": {"max": 5000},  # ms
            "error_rate": {"max": 0.05}
        }
        self.phase = 0
    
    def rollout_phases(self):
        """定义发布阶段"""
        return [
            {"name": "内部测试", "traffic": 0.01, "duration": "1h", "scope": "内部员工"},
            {"name": "小流量", "traffic": 0.05, "duration": "4h", "scope": "随机 5%"},
            {"name": "中流量", "traffic": 0.20, "duration": "24h", "scope": "随机 20%"},
            {"name": "大流量", "traffic": 0.50, "duration": "48h", "scope": "随机 50%"},
            {"name": "全量", "traffic": 1.00, "duration": "—", "scope": "全部用户"}
        ]
    
    def check_phase(self, phase_metrics: dict) -> dict:
        """
        检查当前阶段是否健康，决定是否进入下一阶段
        
        Returns:
            {"proceed": bool, "issues": [...], "recommendation": str}
        """
        issues = []
        
        for metric, threshold in self.thresholds.items():
            actual = phase_metrics.get(metric)
            if actual is None:
                continue
            
            for direction, limit in threshold.items():
                if direction == "min" and actual < limit:
                    issues.append(f"{metric} = {actual}, 低于最低要求 {limit}")
                elif direction == "max" and actual > limit:
                    issues.append(f"{metric} = {actual}, 超过最高容忍 {limit}")
        
        if issues:
            return {
                "proceed": False,
                "issues": issues,
                "recommendation": "暂停发布，修复问题后再继续"
            }
        
        return {
            "proceed": True,
            "issues": [],
            "recommendation": "指标健康，可以进入下一阶段"
        }
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| **RCT（随机对照试验）** | 随机分配用户到对照组和实验组，消除选择偏差 |
| **原假设 H₀** | 实验组和对照组没有差异的假设 |
| **备择假设 H₁** | 实验组和对照组存在差异的假设 |
| **第一类错误（α）** | 误拒绝 H₀（假阳性），通常设为 0.05 |
| **第二类错误（β）** | 误接受 H₀（假阴性），统计功效 = 1-β |
| **p 值** | 在原假设为真的前提下，观察到当前结果的概率 |
| **统计显著性** | p < α 时称为"统计显著" |
| **效应量（Cohen's d）** | 标准化后的组间差异，不受样本量影响 |
| **最小可检测效应（MDE）** | 在给定样本量和功效下可检测到的最小差异 |
| **Novelty 效应** | 新版本因"新鲜感"导致短期指标虚高 |
| **混淆变量** | 同时影响分组和结果的第三方变量 |
| **多重比较校正** | 同时对多个假设检验时调整显著性水平 |
| **Bonferroni 校正** | 最严格的多重比较校正（α/m） |
| **Benjamini-Hochberg 校正** | 控制错误发现率（FDR）的多重比较校正 |
| **渐进式发布** | 逐步增加新版本流量比例的安全发布策略 |
