# 12.3 Orchestrator-Worker 模式

> Orchestrator-Worker 是最经典、最成熟的多 Agent 协作模式：一个中心协调者（Orchestrator）负责任务分解、分派和结果整合，多个专业 Worker Agent 各自负责一个子任务。本节提供完整的架构设计和代码骨架。

---

## 一、模式概述

### 1.1 核心思想

Orchestrator-Worker 模式借鉴了**主从架构（Master-Slave）** 和**领导者-追随者（Leader-Followers）** 的设计思想。一个 Orchestrator Agent 充当"主管"，将复杂任务拆解为多个子任务，分派给不同的 Worker Agent 并行执行，最后汇总各 Worker 的结果形成最终输出。

```
                    ┌─────────────────────────────┐
                    │         Orchestrator         │
                    │  (任务分解 + 分派 + 聚合)     │
                    └──────┬──────┬──────┬───────┘
                           │      │      │
              ┌────────────┘      │      └────────────┐
              ▼                   ▼                   ▼
     ┌────────────────┐ ┌────────────────┐ ┌────────────────┐
     │  Worker A      │ │  Worker B      │ │  Worker C      │
     │ (搜索专家)      │ │ (分析专家)      │ │ (生成专家)      │
     │ 工具: Web API  │ │ 工具: 统计分析  │ │ 工具: LLM 写作  │
     └────────────────┘ └────────────────┘ └────────────────┘
```

### 1.2 模式定位

对比其他多 Agent 模式：

| 模式 | 协调方式 | 职责分工 | 典型用途 |
|------|---------|---------|---------|
| **Orchestrator-Worker** | 集中式协调 | 任务级分工 | 搜索-分析-生成流水线 |
| **Architect-Coder**（12.4） | 接力式协调 | 阶段级分工 | 代码生成：设计→实现 |
| **Peer-to-Peer**（12.2） | 分布式协调 | 对等协作 | Agent 间自由讨论 |
| **层级模式**（12.2） | 树状协调 | 管理级分工 | 大规模 Agent 集群 |

## 二、架构设计

### 2.1 系统组件

```
┌─────────────────────────────────────────────────────────┐
│                    Orchestrator                          │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │任务分解器 │  │ 分派引擎  │  │结果聚合器 │  │错误处理 │ │
│  │(Task     │→│(Dispatch  │→│(Result   │  │(Error   │ │
│  │ Decomposer)│  │ Engine)  │  │ Aggregator│  │Handler)  │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
│                        │                                │
│                 ┌──────┴──────┐                         │
│                 │ Worker 注册表 │                         │
│                 │ (Registry)  │                         │
│                 └─────────────┘                         │
└─────────────────────────────────────────────────────────┘
           │                │                │
     ┌─────┴─────┐   ┌──────┴──────┐   ┌─────┴─────┐
     │ Worker A  │   │  Worker B   │   │  Worker C  │
     │ (搜索)     │   │  (分析)     │   │  (生成)     │
     └───────────┘   └─────────────┘   └───────────┘
```

### 2.2 核心职责

**Orchestrator**：
1. **任务分解**：根据用户请求，分析需要哪些专业能力
2. **Worker 选择**：根据分解出的子任务类型，选择最合适的 Worker
3. **任务分派**：向 Worker 发送结构化的子任务指令
4. **结果聚合**：收集并整合各 Worker 的输出
5. **质量控制**：检查结果完整性，异常处理
6. **错误恢复**：Worker 失败时重试、替换或降级

**Worker**：
1. **接收任务**：从 Orchestrator 接收标准化的任务描述
2. **专业执行**：使用自身的工具和知识执行子任务
3. **返回结果**：以结构化格式返回执行结果
4. **状态报告**：报告进度、异常或需要额外信息

### 3.1 Worker 注册表

```python
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Any, Callable, Coroutine
import asyncio
import json
from enum import Enum
from datetime import datetime


class WorkerStatus(Enum):
    IDLE = "idle"
    BUSY = "busy"
    ERROR = "error"
    OFFLINE = "offline"


@dataclass
class WorkerCapability:
    """Worker 的能力描述"""
    name: str                      # 能力名称，如 "web_search"
    description: str               # 能力描述
    input_schema: Dict              # 输入参数的 JSON Schema
    output_schema: Dict             # 输出结果的 JSON Schema
    cost_per_call: float = 1.0      # 单次调用的资源消耗（用于调度决策）


@dataclass
class WorkerRegistration:
    """Worker 的注册信息"""
    worker_id: str
    capabilities: List[WorkerCapability]
    status: WorkerStatus = WorkerStatus.IDLE
    current_task: Optional[str] = None
    last_heartbeat: datetime = field(default_factory=datetime.now)
    metadata: Dict = field(default_factory=dict)


class WorkerRegistry:
    """管理所有 Worker 的注册和发现"""
    
    def __init__(self):
        self._workers: Dict[str, WorkerRegistration] = {}
        self._capability_index: Dict[str, List[str]] = {}  # cap -> [worker_ids]
    
    def register(self, worker: WorkerRegistration):
        """注册一个新 Worker"""
        self._workers[worker.worker_id] = worker
        for cap in worker.capabilities:
            cap_name = cap.name
            if cap_name not in self._capability_index:
                self._capability_index[cap_name] = []
            self._capability_index[cap_name].append(worker.worker_id)
    
    def unregister(self, worker_id: str):
        """注销一个 Worker"""
        worker = self._workers.pop(worker_id, None)
        if worker:
            for cap in worker.capabilities:
                cap_name = cap.name
                if cap_name in self._capability_index:
                    self._capability_index[cap_name] = [
                        wid for wid in self._capability_index[cap_name]
                        if wid != worker_id
                    ]
    
    def find_workers(self, required_capability: str, 
                     preferred_workers: Optional[List[str]] = None) -> List[str]:
        """根据能力查找可用的 Worker"""
        candidates = self._capability_index.get(required_capability, [])
        
        # 按优先级排序：首选 > IDLE > BUSY > ERROR > OFFLINE
        def sort_key(worker_id: str):
            w = self._workers.get(worker_id)
            if not w:
                return 5
            priority = {"idle": 0, "busy": 1, "error": 2, "offline": 3}
            # 如果在 preferred_workers 中，优先级提升
            if preferred_workers and worker_id in preferred_workers:
                return -1
            return priority.get(w.status.value, 4)
        
        return sorted(candidates, key=sort_key)
```

### 3.2 任务定义

```python
@dataclass
class Task:
    """一个可分派的子任务"""
    task_id: str
    parent_task_id: Optional[str]        # 父任务 ID（用于任务树）
    capability_required: str              # 需要的 Worker 能力
    input_data: Dict                       # 输入数据
    priority: int = 0                      # 优先级（0=最高）
    timeout_seconds: float = 30.0          # 超时时间
    max_retries: int = 2                   # 最大重试次数
    dependencies: List[str] = field(default_factory=list)  # 依赖的任务 ID
    
    def to_message(self) -> Dict:
        """转换为传递给 Worker 的消息"""
        return {
            "type": "task_assignment",
            "task_id": self.task_id,
            "capability": self.capability_required,
            "input": self.input_data,
            "timeout": self.timeout_seconds,
        }


@dataclass
class TaskResult:
    """任务执行结果"""
    task_id: str
    worker_id: str
    status: str  # "success" | "failure" | "partial" | "timeout"
    output_data: Optional[Dict] = None
    error_message: Optional[str] = None
    execution_time_ms: float = 0.0
    token_usage: Dict = field(default_factory=dict)
    
    def is_success(self) -> bool:
        return self.status == "success"
```

### 3.3 任务分解器

```python
class TaskDecomposer:
    """将用户请求分解为可分派的子任务"""
    
    def __init__(self, orchestrator_llm: Any):  # Any = LLM client
        self.llm = orchestrator_llm
    
    async def decompose(self, user_request: str, 
                        available_capabilities: List[str]) -> List[Task]:
        """
        分析用户请求，输出子任务列表。
        由 Orchestrator 的 LLM 完成分析。
        """
        capabilities_str = "\n".join(f"- {cap}" for cap in available_capabilities)
        
        decomposition_prompt = f"""
        将以下用户请求分解为可以并行或串行执行的子任务。
        可用的 Worker 能力：
        {capabilities_str}
        
        用户请求：{user_request}
        
        请输出 JSON 格式的任务分解结果：
        {{
            "tasks": [
                {{
                    "task_id": "task_001",
                    "capability_required": "web_search",
                    "description": "搜索关于...的信息",
                    "input_data": {{ "query": "..." }},
                    "dependencies": [],  // 依赖的任务 ID，空表示无依赖
                    "priority": 0
                }}
            ],
            "reasoning": "为什么这样分解"
        }}
        
        注意：
        1. 无依赖的任务可以并行执行
        2. 每个任务只能指定一种能力
        3. 使用有意义的 task_id
        4. 任务数量不要超过 10 个
        """
        
        response = await self.llm.complete(decomposition_prompt)
        return self._parse_tasks(response)
    
    def _parse_tasks(self, response: str) -> List[Task]:
        """解析 LLM 返回的 JSON 为 Task 对象"""
        try:
            data = json.loads(response)
            tasks = []
            for t in data["tasks"]:
                task = Task(
                    task_id=t["task_id"],
                    parent_task_id=None,
                    capability_required=t["capability_required"],
                    input_data=t["input_data"],
                    priority=t.get("priority", 0),
                    dependencies=t.get("dependencies", []),
                )
                tasks.append(task)
            return tasks
        except (json.JSONDecodeError, KeyError) as e:
            # 回退：将整个请求作为一个任务
            return [Task(
                task_id="task_fallback",
                parent_task_id=None,
                capability_required="general",
                input_data={"request": response},
            )]
```

### 3.4 分派引擎

```python
class DispatchEngine:
    """负责任务的分派、执行跟踪和结果收集"""
    
    def __init__(self, registry: WorkerRegistry, 
                 worker_proxies: Dict[str, Any]):
        self.registry = registry
        self.worker_proxies = worker_proxies  # worker_id -> WorkerProxy
        self._pending_tasks: Dict[str, asyncio.Future] = {}
    
    async def dispatch_task(self, task: Task, 
                            preferred_workers: Optional[List[str]] = None) -> TaskResult:
        """
        将单个任务分派给合适的 Worker，并等待结果。
        返回 TaskResult。
        """
        # 1. 选择合适的 Worker
        candidates = self.registry.find_workers(
            task.capability_required, 
            preferred_workers
        )
        
        if not candidates:
            return TaskResult(
                task_id=task.task_id,
                worker_id="",
                status="failure",
                error_message=f"No worker available for capability: {task.capability_required}"
            )
        
        # 2. 尝试分派（带重试）
        last_error = None
        for attempt in range(task.max_retries + 1):
            worker_id = candidates[attempt % len(candidates)]
            proxy = self.worker_proxies.get(worker_id)
            
            if not proxy:
                last_error = f"Worker {worker_id} proxy not found"
                continue
            
            try:
                start_time = datetime.now()
                
                result = await asyncio.wait_for(
                    proxy.execute_task(task.to_message()),
                    timeout=task.timeout_seconds
                )
                
                execution_time = (datetime.now() - start_time).total_seconds() * 1000
                
                return TaskResult(
                    task_id=task.task_id,
                    worker_id=worker_id,
                    status="success",
                    output_data=result.get("data"),
                    execution_time_ms=execution_time,
                    token_usage=result.get("token_usage", {})
                )
                
            except asyncio.TimeoutError:
                last_error = f"Timeout after {task.timeout_seconds}s"
                continue
            except Exception as e:
                last_error = str(e)
                continue
        
        return TaskResult(
            task_id=task.task_id,
            worker_id=candidates[0] if candidates else "",
            status="failure",
            error_message=f"All retries exhausted: {last_error}"
        )
    
    async def dispatch_batch(self, tasks: List[Task]) -> Dict[str, TaskResult]:
        """
        批量分派任务，自动处理依赖关系。
        返回 task_id -> TaskResult 的字典。
        """
        results: Dict[str, TaskResult] = {}
        
        # 按依赖关系分层
        remaining = set(t.task_id for t in tasks)
        task_map = {t.task_id: t for t in tasks}
        
        while remaining:
            # 找到所有依赖已满足的任务
            ready = []
            for task_id in remaining:
                task = task_map[task_id]
                deps_met = all(
                    dep in results and results[dep].is_success()
                    for dep in task.dependencies
                )
                if deps_met:
                    ready.append(task)
            
            if not ready:
                # 死锁检测：剩余的 task 互相依赖但无法满足
                for task_id in remaining:
                    results[task_id] = TaskResult(
                        task_id=task_id,
                        worker_id="",
                        status="failure",
                        error_message=f"Deadlock: dependencies cannot be satisfied. "
                                      f"Remaining tasks: {remaining}"
                    )
                break
            
            # 并行执行所有 ready 的任务
            batch_tasks = [self.dispatch_task(task) for task in ready]
            batch_results = await asyncio.gather(*batch_tasks)
            
            for result in batch_results:
                results[result.task_id] = result
                remaining.discard(result.task_id)
        
        return results
```

### 3.5 结果聚合器

```python
class ResultAggregator:
    """收集各 Worker 的结果，生成最终输出"""
    
    def __init__(self, orchestrator_llm: Any):
        self.llm = orchestrator_llm
    
    async def aggregate(self, user_request: str, 
                        tasks: List[Task], 
                        results: Dict[str, TaskResult]) -> str:
        """
        将所有子任务的结果整合为最终输出。
        由 Orchestrator 的 LLM 完成综合分析和生成。
        """
        # 构建结果摘要
        summary_parts = []
        for task in tasks:
            result = results.get(task.task_id)
            if result and result.is_success():
                summary_parts.append(
                    f"## {task.task_id}: {task.capability_required}\n"
                    f"Worker: {result.worker_id}\n"
                    f"输出:\n{json.dumps(result.output_data, ensure_ascii=False, indent=2)}"
                )
            else:
                summary_parts.append(
                    f"## {task.task_id}: {task.capability_required}\n"
                    f"状态: 失败\n"
                    f"错误: {result.error_message if result else 'No result'}"
                )
        
        all_results = "\n\n".join(summary_parts)
        
        aggregation_prompt = f"""
        你是一个结果聚合器。请根据原始用户请求和各子任务的结果，生成完整、连贯的最终回答。
        
        原始用户请求：{user_request}
        
        各子任务的结果：
        {all_results}
        
        要求：
        1. 回答必须直接回应原始请求
        2. 整合各子任务的信息，消除矛盾
        3. 如果某些子任务失败，在回答中说明信息的不完整性
        4. 保持专业、准确的语言风格
        5. 在适当位置标注信息来源（引用哪个子任务的输出）
        """
        
        return await self.llm.complete(aggregation_prompt)
```

### 3.6 Orchestrator 主循环

```python
class Orchestrator:
    """Orchestrator 主控制器——协调整个多 Agent 工作流"""
    
    def __init__(self, 
                 llm: Any,
                 registry: WorkerRegistry,
                 dispatch_engine: DispatchEngine):
        self.decomposer = TaskDecomposer(llm)
        self.aggregator = ResultAggregator(llm)
        self.registry = registry
        self.dispatch_engine = dispatch_engine
    
    async def run(self, user_request: str) -> OrchestratorResult:
        """
        主入口：执行完整的 Orchestrator-Worker 流程。
        
        流程：
        1. 获取可用的 Worker 能力列表
        2. 任务分解
        3. 分派并执行
        4. 结果聚合
        """
        start_time = datetime.now()
        
        # Step 1: 获取可用能力
        available_caps = self._get_available_capabilities()
        if not available_caps:
            return OrchestratorResult(
                success=False,
                error="No workers registered",
            )
        
        # Step 2: 任务分解
        tasks = await self.decomposer.decompose(user_request, available_caps)
        if not tasks:
            return OrchestratorResult(
                success=False,
                error="Task decomposition failed",
            )
        
        # Step 3: 分派并执行（自动处理依赖和并行）
        results = await self.dispatch_engine.dispatch_batch(tasks)
        
        # Step 4: 结果聚合
        final_output = await self.aggregator.aggregate(
            user_request, tasks, results
        )
        
        total_time = (datetime.now() - start_time).total_seconds() * 1000
        
        return OrchestratorResult(
            success=True,
            output=final_output,
            tasks=tasks,
            results=results,
            total_time_ms=total_time,
        )


@dataclass
class OrchestratorResult:
    """Orchestrator 的执行结果"""
    success: bool
    output: Optional[str] = None
    tasks: Optional[List[Task]] = None
    results: Optional[Dict[str, TaskResult]] = None
    total_time_ms: float = 0.0
    error: Optional[str] = None
```

## 四、工程实践要点

### 4.1 错误处理与重试策略

```
Worker 失败
    │
    ├── 重试（最多 N 次）
    │      ├── 不同 Worker（如果可用）
    │      └── 相同 Worker（如果失败是暂时的）
    │
    ├── 降级
    │      ├── 使用更简单的处理方式
    │      └── 跳过非关键子任务
    │
    └── 报告
           ├── 在最终输出中标注"部分信息缺失"
           └── 触发告警
```

### 4.2 超时管理

| 超时级别 | 默认值 | 说明 |
|---------|-------|------|
| Worker 单次执行 | 30s | 单个子任务的最大执行时间 |
| 任务生命周期 | 5min | 从创建到返回结果的整个周期 |
| Orchestrator 总执行 | 15min | 完整流程的总时间预算 |

### 4.3 Worker 状态管理

Worker 需要定期向 Orchestrator 发送心跳（Heartbeat），Orchestrator 检测到 Worker 超时未心跳时，将其标记为 OFFLINE 并从分派候选列表中移除。

```python
class HealthChecker:
    """检查 Worker 健康状态"""
    
    def __init__(self, registry: WorkerRegistry, 
                 heartbeat_timeout: float = 30.0):
        self.registry = registry
        self.heartbeat_timeout = heartbeat_timeout
    
    async def check_all(self):
        """检查所有 Worker 的健康状态"""
        now = datetime.now()
        for worker_id, reg in self.registry._workers.items():
            elapsed = (now - reg.last_heartbeat).total_seconds()
            if elapsed > self.heartbeat_timeout:
                reg.status = WorkerStatus.OFFLINE
```

## 五、变体与扩展

### 5.1 动态 Worker（动态创建Worker）

当遇到目前没有 Worker 能处理的任务时，Orchestrator 可以**动态创建一个新的 Worker Agent**，为其配置所需的工具和 Prompt，完成后可以保留或销毁。

### 5.2 嵌套 Orchestrator

```
[主 Orchestrator]
    │
    ├── [子 Orchestrator A] ── [Worker A1] [Worker A2]
    │
    └── [子 Orchestrator B] ── [Worker B1] [Worker B2]
```

子 Orchestrator 本身也使用 Orchestrator-Worker 模式，但处理的是更细粒度的子问题。这实际上形成了 12.2 节所述的**层级通信模式**。

### 5.3 流式结果

对于长时间运行的任务，Orchestrator 可以在部分 Worker 完成后就开始输出中间结果，而不是等待所有 Worker 完成：

```python
# 流式聚合：边执行边输出
orchestrator = Orchestrator(llm, registry, engine)
async for partial_result in orchestrator.run_streaming(user_request):
    print(partial_result)  # 逐块输出
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Orchestrator | 中心协调者，负责分解、分派和聚合 |
| Worker | 执行具体子任务的专业 Agent |
| 任务分解（Task Decomposition） | 将复杂请求拆解为可独立执行的子任务 |
| 依赖图（Dependency Graph） | 子任务间的先后依赖关系 |
| 结果聚合（Result Aggregation） | 将多个 Worker 的输出整合为统一回答 |
| 心跳检测（Heartbeat） | Worker 定期向 Orchestrator 发送存活信号 |
| 嵌套 Orchestrator | 多层级 Orchestrator 架构，见 12.2 层级通信 |
