# 12.6 分歧解决 —— 规则优先→多数投票→Manager 仲裁→人工升级

> 多 Agent 系统中，Agent 间的分歧是常态而非异常。分歧解决（Conflict Resolution）机制是确保系统输出一致性和可靠性的关键。本节提出四层递进的争议解决框架：规则优先、多数投票、Manager 仲裁、人工升级。

---

## 一、分歧的本质

### 1.1 为什么 Agent 会产生分歧

多 Agent 系统中，分歧的来源多种多样：

```
分歧来源分类：

① 信息不对称
   Agent A 有信息 X，Agent B 没有。
   → 对同一问题的结论不同。
   例如：Agent A 搜索到最新版本号是 2.0，Agent B 参考的是旧文档版本号 1.0。

② 推理路径不同
   即使有相同的信息，不同 Agent 的推理路径也可能不同。
   → 得出不同的结论。
   例如：Agent A 从性能角度优先选择 NoSQL，Agent B 从一致性角度优先选择 SQL。

③ 模型差异
   不同 Agent 可能使用不同的 LLM（GPT-4 vs Claude 3），
   或相同的 LLM 但不同的采样参数（temperature 0.1 vs 0.8）。
   → 对同一输入的输出自然不同。

④ 提示词差异
   不同 Agent 的系统提示词不同，导致偏好不同。
   → "谨慎型"Agent 倾向于保守回答，"创新型"Agent 倾向于探索性回答。

⑤ 工具结果不一致
   不同 Agent 调用不同的工具，或同一工具返回不同时间点的数据。
   → 数据层面存在事实不一致。
```

### 1.2 分歧的分级

不是所有分歧都需要解决。根据影响范围，分歧可以分为：

| 级别 | 特征 | 示例 | 处理策略 |
|------|------|------|---------|
| **L1：细微分歧** | 输出风格差异，核心信息一致 | "温度约为25°C" vs "温度是25.3°C" | **忽略**或自动合并 |
| **L2：事实分歧** | 关键事实不一致 | "API返回200" vs "API返回403" | **裁决** |
| **L3：决策分歧** | 行动路线不同 | "应该用PostgreSQL" vs "应该用MongoDB" | **仲裁** |
| **L4：互斥输出** | 两个 Agent 的结论完全矛盾 | "这是个Bug" vs "这不是Bug" | **升级到人工** |

## 二、四层递进框架总览

四层递进解决框架的核心思想：**先用成本最低的方法，逐步升级到成本更高的方法**。

```
                        ┌─────────────────────┐
                        │    用户请求/输入      │
                        └──────────┬──────────┘
                                   │
                                   ▼
              ╔══════════════════════════════════════╗
              ║   Layer 1: 规则优先（Rule Priority）  ║
              ║   确定性规则匹配 → 快速裁决           ║
              ║   成本: ~0ms, 无 LLM 调用             ║
              ╚════════════════┬═════════════════════╝
                              │
                    能裁决？──┼──否──→
                              │       │
                              ▼       ▼
              ╔══════════════════╗     │
              ║ 直接输出结果      ║     │
              ╚══════════════════╝     │
                                       ▼
              ╔══════════════════════════════════════╗
              ║   Layer 2: 多数投票（Majority Vote） ║
              ║   收集所有 Agent 的投票 → 多数胜出    ║
              ║   成本: 1× LLM 调用（汇总分析）       ║
              ╚════════════════┬═════════════════════╝
                              │
                    有多数？──┼──否──→
                              │       │
                              ▼       ▼
              ╔══════════════════╗     │
              ║ 采用多数结果      ║     │
              ╚══════════════════╝     │
                                       ▼
              ╔══════════════════════════════════════╗
              ║  Layer 3: Manager 仲裁（Arbitration）║
              ║   专门的 Manager Agent 分析并裁决     ║
              ║   成本: 1× LLM 调用（强模型分析）      ║
              ╚════════════════┬═════════════════════╝
                              │
                    Manager ──┼──否──→
                    能裁决？    │       │
                              ▼       ▼
              ╔══════════════════╗     │
              ║ 采用仲裁结果      ║     │
              ╚══════════════════╝     │
                                       ▼
              ╔══════════════════════════════════════╗
              ║  Layer 4: 人工升级（Human Escalation）║
              ║   将分歧信息打包 → 提交给人类审核     ║
              ║   成本: 最高，但安全可靠              ║
              ╚══════════════════════════════════════╝
```

## 三、Layer 1：规则优先（Rule Priority）

### 3.1 原理

规则优先是**成本最低**的解决方式——通过预定义的确定性规则（无 LLM 调用）来快速裁决分歧。

规则的形式是：`IF (条件) THEN (结论)`，条件基于可观测的元数据而非内容语义。

### 3.2 实现

```python
from dataclasses import dataclass, field
from typing import List, Dict, Any, Optional, Callable
from enum import Enum, auto


class Verdict(Enum):
    """分歧裁决结果"""
    ACCEPT_A = auto()      # 接受 Agent A 的结果
    ACCEPT_B = auto()      # 接受 Agent B 的结果
    UNRESOLVED = auto()    # 无法裁决，升级到下一层
    MERGED = auto()        # 合并双方结果


@dataclass
class ConflictRecord:
    """一个分歧记录"""
    conflict_id: str
    agents_involved: List[str]
    question: str                  # 有分歧的问题
    answer_a: Dict                  # Agent A 的答案
    answer_b: Dict                  # Agent B 的答案
    metadata: Dict = field(default_factory=dict)
    # metadata 可包含：confidences, execution_time, 
    #                token_usage, model_name 等


class RuleBasedResolver:
    """
    第一层：规则优先裁决器。
    使用确定性规则无 LLM 调用快速裁决。
    """
    
    def __init__(self):
        self.rules: List[tuple[str, Callable[[ConflictRecord], Optional[Verdict]]]] = []
        self._register_default_rules()
    
    def _register_default_rules(self):
        """注册默认裁决规则"""
        
        # 规则 1：置信度优先
        # 如果一方置信度远高于另一方，采用高置信度的结果
        def confidence_rule(record: ConflictRecord) -> Optional[Verdict]:
            conf_a = record.metadata.get("confidence_a", 0.5)
            conf_b = record.metadata.get("confidence_b", 0.5)
            threshold = 0.2  # 置信度差超过 0.2 则采纳高置信度方
            
            if conf_a - conf_b > threshold:
                return Verdict.ACCEPT_A
            elif conf_b - conf_a > threshold:
                return Verdict.ACCEPT_B
            return None  # 无法用此规则裁决
        
        # 规则 2：来源权威性优先
        # 如果 Agent A 的结果来自官方文档，Agent B 来自论坛，采信 A
        def authority_rule(record: ConflictRecord) -> Optional[Verdict]:
            authority_levels = {
                "official_doc": 5,
                "academic_paper": 4,
                "well_known_media": 3,
                "user_forum": 1,
                "llm_knowledge": 2,
            }
            source_a = record.metadata.get("source_a", "llm_knowledge")
            source_b = record.metadata.get("source_b", "llm_knowledge")
            
            level_a = authority_levels.get(source_a, 0)
            level_b = authority_levels.get(source_b, 0)
            
            if level_a > level_b + 1:  # 相差至少一级
                return Verdict.ACCEPT_A
            elif level_b > level_a + 1:
                return Verdict.ACCEPT_B
            return None
        
        # 规则 3：时效性优先
        # 如果一方使用了更新的数据源，采用更新的一方
        def recency_rule(record: ConflictRecord) -> Optional[Verdict]:
            time_a = record.metadata.get("timestamp_a")
            time_b = record.metadata.get("timestamp_b")
            
            if time_a and time_b:
                if time_a > time_b:
                    return Verdict.ACCEPT_A
                elif time_b > time_a:
                    return Verdict.ACCEPT_B
            return None
        
        # 规则 4：模型能力优先
        # 如果 Agent 使用了更强/更新的模型，采用该结果
        def model_capability_rule(record: ConflictRecord) -> Optional[Verdict]:
            model_rank = {
                "gpt-4": 10, "gpt-4-turbo": 9, "gpt-4o": 9,
                "claude-3-opus": 10, "claude-3-sonnet": 8, "claude-3-haiku": 6,
                "gpt-3.5-turbo": 5, "llama-3-70b": 7, "llama-3-8b": 4,
            }
            model_a = record.metadata.get("model_a", "")
            model_b = record.metadata.get("model_b", "")
            
            rank_a = model_rank.get(model_a, 0)
            rank_b = model_rank.get(model_b, 0)
            
            if rank_a > rank_b + 2:
                return Verdict.ACCEPT_A
            elif rank_b > rank_a + 2:
                return Verdict.ACCEPT_B
            return None
        
        # 规则 5：安全优先（否决权）
        # 如果任一 Agent 标记为"存在安全风险"，采纳安全评估更严格的结果
        def safety_rule(record: ConflictRecord) -> Optional[Verdict]:
            safety_a = record.metadata.get("safety_flag_a", False)
            safety_b = record.metadata.get("safety_flag_b", False)
            
            if safety_a and not safety_b:
                return Verdict.ACCEPT_B  # 拒绝有安全问题的结果
            elif safety_b and not safety_a:
                return Verdict.ACCEPT_A
            return None
        
        self.rules = [
            ("safety", safety_rule),           # 安全规则优先级最高
            ("confidence", confidence_rule),    # 置信度规则
            ("authority", authority_rule),      # 权威性规则
            ("recency", recency_rule),          # 时效性规则
            ("model", model_capability_rule),   # 模型能力规则
        ]
    
    def add_rule(self, name: str, rule_fn: Callable, priority: int = 0):
        """添加自定义规则"""
        self.rules.insert(priority, (name, rule_fn))
    
    def resolve(self, record: ConflictRecord) -> Verdict:
        """
        应用所有规则尝试裁决。
        按优先级顺序检查，第一个匹配的规则决定结果。
        """
        for rule_name, rule_fn in self.rules:
            try:
                result = rule_fn(record)
                if result is not None and result != Verdict.UNRESOLVED:
                    return result
            except Exception as e:
                # 规则执行失败，跳过
                continue
        
        return Verdict.UNRESOLVED
```

### 3.3 规则优先的适用边界

```
可以处理的场景：
✓ 置信度差异明显（0.95 vs 0.60）
✓ 来源权威性差异大（官方文档 vs 个人博客）
✓ 时效性差异明确（2024年数据 vs 2020年数据）
✓ 安全标记触发

不可处理的场景：
✗ 双方置信度接近且都很高（0.94 vs 0.93）
✗ 双方都来自同等权威的来源
✗ 分歧本质上是对同一事实的不同解读（需要语义理解）
   → 这些场景升级到 Layer 2
```

## 四、Layer 2：多数投票（Majority Vote）

### 4.1 原理

当规则无法裁决时，让更多 Agent 参与"投票"——通常是让所有相关的 Agent（或一个独立投票团）各自给出答案，选择出现次数最多的结果。

```
         ┌──→ [Agent A] ──→ "方案 X"
         │
         ├──→ [Agent B] ──→ "方案 X"
[输入] ──┼──→ [Agent C] ──→ "方案 Y"
         │
         ├──→ [Agent D] ──→ "方案 X"  ← 多数胜出
         │
         └──→ [Agent E] ──→ "方案 Y"
```

### 4.2 实现

```python
@dataclass
class VoteResult:
    """投票结果"""
    winner: Any                           # 获胜的答案
    vote_counts: Dict[str, int]           # 每个答案的票数
    total_votes: int                      # 总投票数
    majority_threshold: float             # 多数阈值（如 0.5）
    reached_consensus: bool               # 是否达成共识


class MajorityVoteResolver:
    """
    第二层：多数投票裁决器。
    收集所有 Agent 的投票，按结果聚类，多数胜出。
    """
    
    def __init__(self, 
                 llm: Any,
                 threshold: float = 0.5,
                 max_voters: int = 7):
        """
        Args:
            llm: 用于聚类的 LLM
            threshold: 多数阈值（超过此比例即采纳）
            max_voters: 最大投票 Agent 数量
        """
        self.llm = llm
        self.threshold = threshold
        self.max_voters = max_voters
    
    async def resolve(self, 
                      conflict: ConflictRecord,
                      additional_voters: Optional[List['AgentProxy']] = None) -> VoteResult:
        """
        执行多数投票。
        
        1. 收集两个分歧方的答案
        2. 让更多 Agent 投票（可选）
        3. 聚类相似答案
        4. 统计票数
        """
        # Step 1: 收集所有投票
        votes = [
            ("agent_a", conflict.answer_a),
            ("agent_b", conflict.answer_b),
        ]
        
        # Step 2: 让更多 Agent 投票
        if additional_voters:
            for voter in additional_voters[:self.max_voters - 2]:
                vote = await self._ask_agent_to_vote(voter, conflict)
                votes.append((voter.agent_id, vote))
        
        # Step 3: 聚类相似答案
        clusters = await self._cluster_votes(votes)
        
        # Step 4: 统计票数
        vote_counts = {}
        for cluster_repr, member_ids in clusters.items():
            vote_counts[cluster_repr] = len(member_ids)
        
        total = len(votes)
        max_count = max(vote_counts.values())
        winner = max(vote_counts, key=vote_counts.get)
        reached = (max_count / total) > self.threshold
        
        return VoteResult(
            winner=winner,
            vote_counts=vote_counts,
            total_votes=total,
            majority_threshold=self.threshold,
            reached_consensus=reached,
        )
    
    async def _ask_agent_to_vote(self, agent, conflict: ConflictRecord) -> Any:
        """让一个 Agent 对分歧问题投票"""
        prompt = f"""
        请对以下问题给出你的答案：
        
        问题：{conflict.question}
        
        Agent A 的答案：{json.dumps(conflict.answer_a, ensure_ascii=False)}
        Agent B 的答案：{json.dumps(conflict.answer_b, ensure_ascii=False)}
        
        请直接输出你的答案（不要解释）。
        """
        return await agent.answer(prompt)
    
    async def _cluster_votes(self, votes: List[tuple]) -> Dict[str, List[str]]:
        """
        将相似的答案聚类。
        使用 LLM 判断答案的语义相似性。
        例如："用 PostgreSQL" 和 "采用 PostgreSQL 数据库" 是同一类。
        """
        if len(votes) <= 3:
            # 少量投票直接按内容精确匹配
            return self._exact_cluster(votes)
        
        # 多量投票使用 LLM 聚类
        votes_text = "\n".join(
            f"{agent_id}: {json.dumps(answer, ensure_ascii=False)}"
            for agent_id, answer in votes
        )
        
        cluster_prompt = f"""
        请将以下投票结果按语义相似性聚类。
        每个 cluster 是一个意思的不同表述。
        
        投票：
        {votes_text}
        
        输出 JSON 格式：
        {{
            "clusters": [
                {{
                    "representative": "该聚类代表的答案",
                    "members": ["agent_id_1", "agent_id_2"]
                }}
            ]
        }}
        """
        
        response = await self.llm.complete(cluster_prompt)
        data = json.loads(response)
        
        clusters = {}
        for cluster in data["clusters"]:
            clusters[cluster["representative"]] = cluster["members"]
        return clusters
    
    def _exact_cluster(self, votes: List[tuple]) -> Dict[str, List[str]]:
        """按精确匹配聚类"""
        clusters = {}
        for agent_id, answer in votes:
            key = str(answer)  # 简单处理，实际需要语义相似度
            if key not in clusters:
                clusters[key] = []
            clusters[key].append(agent_id)
        return clusters
```

### 4.3 多数投票的局限

```
多数投票可能错的场景：

✗ "多数并不正确"
   情景：5 个 Agent 用同样的错误数据得出结论 X
        2 个 Agent 用正确数据得出结论 Y
   结果：X 获胜（多数），但实际上是 Y 正确
   对策：结合 Layer 1 的权威性规则（如果 Y 方来源更权威）

✗ "持不同意见的都是更好的模型"
   情景：3 个 GPT-3.5 投票 A；1 个 GPT-4 投票 B
   结果：A 获胜（3:1），但 GPT-4 的 B 更可能正确
   对策：引入投票权重的概念——不同模型的投票权重不同

✗ "没有多数"
   7 个 Agent 分裂为 4 种不同意见（2:2:2:1）
   对策：升级到 Layer 3
```

## 五、Layer 3：Manager 仲裁（Arbitration）

### 5.1 原理

当多数投票也无法达成共识时，需要一个**独立的 Manager Agent** 来分析各方意见并做出裁决。Manager 通常使用最强的 LLM，并有权要求 Agent 提供更多信息。

```
                    [Manager Agent]
                  (使用最强 LLM 模型)
                 /        |        \
                /         |         \
               ▼          ▼          ▼
          [Agent A]   [Agent B]   [Agent C]
          (论证X)     (论证Y)     (论证Z)
               \         |         /
                \        |        /
                 └─── 提交证据 ───┘
                        │
                        ▼
                  ┌──────────┐
                  │最终裁决    │
                  └──────────┘
```

### 5.2 实现

```python
@dataclass
class ArbitrationResult:
    """仲裁结果"""
    winner_id: Optional[str]      # 胜出的 Agent ID（或 None 表示无法裁决）
    final_answer: Any             # 最终采用的答案
    reasoning: str                # 仲裁理由
    confidence: float             # Manager 对裁决的信心（0-1）
    suggest_escalation: bool      # 是否建议升级到人工


class ManagerArbitrator:
    """
    第三层：Manager 仲裁器。
    使用独立的 Manager Agent 分析各方分歧并做出裁决。
    """
    
    def __init__(self, manager_llm: Any):
        """
        Args:
            manager_llm: 用于仲裁的 LLM（应使用最强的模型）
        """
        self.llm = manager_llm
    
    async def arbitrate(self, 
                        conflict: ConflictRecord,
                        agent_arguments: Optional[Dict[str, str]] = None) -> ArbitrationResult:
        """
        执行仲裁。
        
        Manager 会：
        1. 分析各方的答案和理由
        2. 检查各方的论据质量
        3. 必要时要求补充信息
        4. 给出最终裁决
        """
        arguments_text = ""
        if agent_arguments:
            arguments_text = "\n\n各方论据：\n"
            for agent_id, argument in agent_arguments.items():
                arguments_text += f"\n=== {agent_id} ===\n{argument}\n"
        
        arbitration_prompt = f"""
        你是一个中立的 Manager 仲裁者。你需要分析两个 Agent 之间的分歧，
        并做出最终裁决。
        
        ## 分歧问题
        {conflict.question}
        
        ## Agent A 的答案
        {json.dumps(conflict.answer_a, ensure_ascii=False, indent=2)}
        
        ## Agent B 的答案
        {json.dumps(conflict.answer_b, ensure_ascii=False, indent=2)}
        
        ## 附加元数据
        - Agent A 模型: {conflict.metadata.get('model_a', 'unknown')}
        - Agent B 模型: {conflict.metadata.get('model_b', 'unknown')}
        - Agent A 置信度: {conflict.metadata.get('confidence_a', 'N/A')}
        - Agent B 置信度: {conflict.metadata.get('confidence_b', 'N/A')}
        - Agent A 来源: {conflict.metadata.get('source_a', 'N/A')}
        - Agent B 来源: {conflict.metadata.get('source_b', 'N/A')}
        
        {arguments_text}
        
        ## 仲裁流程
        1. 分析：识别分歧的核心是什么？是事实分歧还是立场分歧？
        2. 评估：哪一方的答案有更可靠的支撑？
        3. 裁决：选择一方的答案，或给出折中方案
        4. 标注：如果你对裁决没有把握，标注 suggest_escalation=true
        
        ## 输出 JSON 格式
        {{
            "winner_id": "agent_a 或 agent_b 或 null",
            "final_answer": "最终采纳的答案",
            "reasoning": "仲裁的详细理由",
            "confidence": 0.95,
            "suggest_escalation": false,
            "missing_information": "如果需要更多信息才能裁决，描述缺少什么"
        }}
        """
        
        response = await self.llm.complete(arbitration_prompt)
        data = json.loads(response)
        
        return ArbitrationResult(
            winner_id=data.get("winner_id"),
            final_answer=data.get("final_answer"),
            reasoning=data.get("reasoning", ""),
            confidence=data.get("confidence", 0.0),
            suggest_escalation=data.get("suggest_escalation", False),
        )
    
    async def arbitrate_with_hearing(self, 
                                     conflict: ConflictRecord,
                                     agents: Dict[str, Any]) -> ArbitrationResult:
        """
        带"听证"的仲裁。
        
        Manager 可以要求 Agent 提供更多论据，
        然后才做出裁决。
        """
        # Step 1: 收集各方的详细论证
        arguments = {}
        for agent_id, agent in agents.items():
            prompt = f"""
            请详细论证你的观点。针对问题：
            "{conflict.question}"
            
            你的答案是：{json.dumps(conflict.answer_a if agent_id == 'agent_a' else conflict.answer_b, ensure_ascii=False)}
            
            请提供：
            1. 支持你答案的证据来源
            2. 你的推理过程
            3. 为什么你比对方更正确
            4. 如果可能，指出对方答案中可能的错误
            """
            argument = await agent.answer(prompt)
            arguments[agent_id] = argument
        
        # Step 2: 基于完整证据仲裁
        return await self.arbitrate(conflict, arguments)
```

### 5.3 Manager 仲裁的成功率

| 分歧类型 | Manager 裁决成功率 | 说明 |
|---------|------------------|------|
| 事实性分歧（有客观正确答案） | ~95% | Manager 可以交叉验证双方数据 |
| 策略性分歧（无标准答案） | ~70% | Manager 给出"更合理"而非"正确"的裁决 |
| 高度主观分歧（审美/风格） | ~50% | 建议升级到人工 |
| 涉及安全/合规 | ~60% | 安全场景建议人工审核 |

## 六、Layer 4：人工升级（Human Escalation）

### 6.1 原理

当前三层都无法解决时，系统将分歧信息**打包**提交给人类审核者。这是成本最高但最可靠的方式。

### 6.2 实现

```python
@dataclass
class EscalationPackage:
    """提交给人类审核者的分歧信息包"""
    escalation_id: str
    conflict: ConflictRecord
    rule_result: Optional[Verdict] = None
    vote_result: Optional[VoteResult] = None
    arbitration_result: Optional[ArbitrationResult] = None
    context: Dict = field(default_factory=dict)
    created_at: str = field(default_factory=lambda: datetime.now().isoformat())
    status: str = "pending"  # pending / resolved / rejected
    
    def to_human_readable(self) -> str:
        """生成人类可读的分歧报告"""
        lines = [
            f"# 分歧升级报告 #{self.escalation_id}",
            f"",
            f"## 问题描述",
            f"{self.conflict.question}",
            f"",
            f"## 涉及 Agent",
            f"Agent A ({self.conflict.agents_involved[0]}) vs "
            f"Agent B ({self.conflict.agents_involved[1]})",
            f"",
            f"## 分歧详情",
            f"**Agent A 的答案：**",
            f"{json.dumps(self.conflict.answer_a, ensure_ascii=False, indent=2)}",
            f"",
            f"**Agent B 的答案：**",
            f"{json.dumps(self.conflict.answer_b, ensure_ascii=False, indent=2)}",
            f"",
        ]
        
        if self.rule_result:
            lines.append(f"## Layer 1 规则尝试：{self.rule_result.name}")
        
        if self.vote_result:
            lines.extend([
                f"## Layer 2 投票结果",
                f"总票数：{self.vote_result.total_votes}",
                f"票数分布：{self.vote_result.vote_counts}",
                f"多数阈值：{self.vote_result.majority_threshold}",
                f"达成共识：{self.vote_result.reached_consensus}",
                f"",
            ])
        
        if self.arbitration_result:
            lines.extend([
                f"## Layer 3 Manager 仲裁",
                f"胜出方：{self.arbitration_result.winner_id or '无法裁决'}",
                f"自信度：{self.arbitration_result.confidence}",
                f"理由：{self.arbitration_result.reasoning}",
                f"建议升级：{self.arbitration_result.suggest_escalation}",
                f"",
            ])
        
        lines.append(
            "## 请人类审核者决定\n"
            "- [ ] 采用 Agent A 的答案\n"
            "- [ ] 采用 Agent B 的答案\n"
            "- [ ] 自定义答案：__________\n"
            "- [ ] 标记为无效问题，返回默认响应\n"
        )
        
        return "\n".join(lines)


class HumanEscalationHandler:
    """
    第四层：人工升级处理器。
    将分歧提交给人类审核者，并处理结果回传。
    """
    
    def __init__(self, 
                 escalation_queue: asyncio.Queue,
                 storage: Any):
        self.escalation_queue = escalation_queue
        self.storage = storage
    
    async def escalate(self, 
                       conflict: ConflictRecord,
                       rule_result: Optional[Verdict] = None,
                       vote_result: Optional[VoteResult] = None,
                       arbitration_result: Optional[ArbitrationResult] = None) -> EscalationPackage:
        """
        打包分歧信息并提交到人工审核队列。
        """
        package = EscalationPackage(
            escalation_id=f"esc_{datetime.now().strftime('%Y%m%d_%H%M%S')}_{uuid.uuid4().hex[:6]}",
            conflict=conflict,
            rule_result=rule_result,
            vote_result=vote_result,
            arbitration_result=arbitration_result,
        )
        
        # 持久化存储
        await self.storage.save(f"escalation:{package.escalation_id}", package)
        
        # 提交到人工审核队列
        await self.escalation_queue.put(package)
        
        return package
    
    async def get_resolution(self, escalation_id: str, 
                              timeout: float = 3600) -> Optional[Dict]:
        """
        获取人工审核结果（阻塞等待）。
        超时后返回 None。
        """
        start = time.time()
        while time.time() - start < timeout:
            package = await self.storage.load(f"escalation:{escalation_id}")
            if package and package.status == "resolved":
                return package.context.get("human_decision")
            await asyncio.sleep(5)  # 每 5 秒轮询一次
        return None
```

## 七、四层递进的触发条件总结

### 7.1 决策流程图

```
开始
│
├─→ 是否存在分歧？
│   否 → 输出结果
│   是
│    ↓
├─→ Layer 1: 规则优先
│   ├─ 规则匹配成功？ → 输出规则裁决结果
│   └─ 规则无法裁决
│        ↓
├─→ Layer 2: 多数投票
│   ├─ 有多数共识？ → 输出投票结果
│   └─ 无多数共识
│        ↓
├─→ Layer 3: Manager 仲裁
│   ├─ 仲裁成功且置信度高？ → 输出仲裁结果
│   └─ 仲裁失败或置信度低
│        ↓
└─→ Layer 4: 人工升级
    ├─ 人工在超时内响应？ → 输出人工决定
    └─ 超时未响应？ → 输出降级结果+告警
```

### 7.2 各层的成本与延迟

| 层级 | 方法 | 延迟 | Token 消耗 | 可靠性 | 触发频率（典型） |
|------|------|------|-----------|--------|----------------|
| L1 | 规则优先 | 0-2ms | 0 | 高（有限场景） | ~60% 分歧在此解决 |
| L2 | 多数投票 | 2-10s | 中（N次投票） | 中高 | ~25% 分歧在此解决 |
| L3 | Manager 仲裁 | 1-5s | 中高（1次仲裁） | 中高 | ~10% 分歧在此解决 |
| L4 | 人工升级 | 分钟-小时 | 低（仅打包） | 最高 | ~5% 分歧升级到人工 |

**经验数据**（来自多 Agent 生产系统）：约 60% 的分歧在 L1 通过规则解决，25% 在 L2 通过投票解决，10% 在 L3 通过仲裁解决，5% 需要升级到人工。

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 分歧解决（Conflict Resolution） | 多 Agent 输出不一致时确定最终结果的机制 |
| 规则优先（Rule Priority） | 基于确定性规则的零成本快速裁决 |
| 多数投票（Majority Vote） | 收集多个 Agent 的输出，选择多数意见 |
| Manager 仲裁（Arbitration） | 独立的强 LLM 分析各方论据并做出裁决 |
| 人工升级（Human Escalation） | 将无法自动裁决的分歧提交给人类审核 |
| 听证（Hearing） | Manager 要求 Agent 提供更多论据的过程 |
| 安全否决权 | 安全规则在 Layer 1 中具有最高优先级 |
| 投票权重 | 不同模型/来源的投票具有不同权重 |
