# 12.5 Agent 间上下文传递

> 多 Agent 系统的核心挑战之一是**上下文（Context）如何在 Agent 之间传递**。不完整的上下文传递会导致信息丢失、重复工作和决策偏差。本节分析三种上下文传递方案：共享记忆、消息传递和结构化摘要交接。

---

## 一、问题的本质

### 1.1 什么是 Agent 上下文

在多 Agent 系统中，每个 Agent 的运行需要**上下文**——即理解当前状态、做出决策所需的所有信息。上下文的组成：

```
Agent 上下文 = 系统上下文 + 任务上下文 + 历史上下文

系统上下文（System Context）：
  - Agent 身份和角色定义
  - 可用工具清单
  - 全局规则和约束

任务上下文（Task Context）：
  - 当前任务的详细描述
  - 输入参数和数据
  - 任务间依赖关系

历史上下文（History Context）：
  - 之前步骤的执行结果
  - 已经做出的决策
  - 已经发现的错误和异常
```

### 1.2 上下文传递的三大挑战

```
挑战 1：上下文窗口限制
  LLM 有固定的上下文窗口（如 128K tokens）。
  随着 Agent 数量增加，所有上下文的总和可能超过窗口限制。

挑战 2：信息稀释
  不相关的上下文会"稀释"Agent 的注意力。
  给搜索 Agent 传入与搜索无关的分析结果，会降低搜索质量。

挑战 3：过时信息
  Agent A 在 T1 时刻产生的信息，Agent B 在 T2 时刻使用时可能已过时。
  例如：Agent A 搜索了最新数据，但 Agent B 拿到的是 Agent A 的旧缓存。
```

## 二、方案一：共享记忆（Shared Memory）

### 2.1 架构

共享记忆使用一个**中央存储**来保存所有 Agent 产生的和需要的信息。所有 Agent 读写同一个存储：

```
                     ┌─────────────────────┐
                     │    Shared Memory     │
                     │  (Redis / KV Store)  │
                     └──────┬──────┬───────┘
                            │      │
              ┌─────────────┘      └─────────────┐
              ▼                                    ▼
     ┌─────────────────┐                ┌─────────────────┐
     │    Agent A      │                │    Agent B       │
     │ 写: search结果   │                │ 读: search结果   │
     │ 读: 任务参数     │                │ 写: 分析结果     │
     └─────────────────┘                └─────────────────┘
```

### 2.2 实现示例

```python
from dataclasses import dataclass, field
from typing import Dict, Any, Optional, List
from datetime import datetime
import json
import asyncio


@dataclass
class MemoryEntry:
    """共享记忆中的一条记录"""
    key: str
    value: Any
    writer: str              # 写入的 Agent ID
    timestamp: datetime = field(default_factory=datetime.now)
    ttl: Optional[int] = None  # 过期时间（秒），None 表示永不过期
    tags: List[str] = field(default_factory=list)  # 标签，便于检索
    
    def is_expired(self) -> bool:
        if self.ttl is None:
            return False
        elapsed = (datetime.now() - self.timestamp).total_seconds()
        return elapsed > self.ttl


class SharedMemory:
    """
    共享记忆实现。
    使用 Redis 或内存字典作为后端存储。
    """
    
    def __init__(self, backend: str = "memory"):
        self._store: Dict[str, MemoryEntry] = {}
        self._index: Dict[str, List[str]] = {}  # tag -> [keys]
    
    # ──── 写入 ────
    
    async def write(self, key: str, value: Any, 
                    writer: str, 
                    ttl: Optional[int] = None,
                    tags: Optional[List[str]] = None) -> None:
        """写入一条记录到共享记忆"""
        entry = MemoryEntry(
            key=key,
            value=value,
            writer=writer,
            ttl=ttl,
            tags=tags or []
        )
        self._store[key] = entry
        
        # 更新索引
        for tag in entry.tags:
            if tag not in self._index:
                self._index[tag] = []
            self._index[tag].append(key)
    
    async def update(self, key: str, value: Any, 
                     writer: str) -> bool:
        """更新已有记录"""
        if key not in self._store:
            return False
        self._store[key].value = value
        self._store[key].writer = writer
        self._store[key].timestamp = datetime.now()
        return True
    
    # ──── 读取 ────
    
    async def read(self, key: str) -> Optional[Any]:
        """读取一条记录"""
        entry = self._store.get(key)
        if entry is None:
            return None
        if entry.is_expired():
            del self._store[key]
            return None
        return entry.value
    
    async def read_by_tag(self, tag: str) -> Dict[str, Any]:
        """根据标签读取所有匹配的记录"""
        keys = self._index.get(tag, [])
        result = {}
        for key in keys:
            value = await self.read(key)
            if value is not None:
                result[key] = value
        return result
    
    async def read_recent(self, limit: int = 10) -> List[MemoryEntry]:
        """读取最近的 N 条记录"""
        sorted_entries = sorted(
            self._store.values(),
            key=lambda e: e.timestamp,
            reverse=True
        )
        return [e for e in sorted_entries if not e.is_expired()][:limit]
    
    # ──── 删除 ────
    
    async def delete(self, key: str) -> bool:
        """删除一条记录"""
        entry = self._store.pop(key, None)
        if entry:
            for tag in entry.tags:
                if tag in self._index:
                    self._index[tag] = [k for k in self._index[tag] if k != key]
            return True
        return False
    
    async def clear_writer(self, writer: str):
        """清除某个 Agent 写入的所有记录"""
        keys_to_delete = [
            key for key, entry in self._store.items()
            if entry.writer == writer
        ]
        for key in keys_to_delete:
            await self.delete(key)
    
    # ──── 查询 ────
    
    async def exists(self, key: str) -> bool:
        """检查 key 是否存在且未过期"""
        entry = self._store.get(key)
        if entry is None:
            return False
        if entry.is_expired():
            del self._store[key]
            return False
        return True


# ===== 使用示例 =====

async def shared_memory_demo():
    memory = SharedMemory()
    
    # Agent A (搜索 Agent) 写入搜索结果
    await memory.write(
        key="search:climate_change_2024",
        value={
            "results": [
                {"title": "IPCC 2024 Report", "url": "..."},
                {"title": "Global Temp Rise 1.5C", "url": "..."}
            ]
        },
        writer="agent_search",
        ttl=3600,  # 1 小时后过期
        tags=["search", "climate"]
    )
    
    # Agent B (分析 Agent) 读取搜索结果
    search_results = await memory.read("search:climate_change_2024")
    
    # Agent B 写入分析结果
    await memory.write(
        key="analysis:climate_summary",
        value="Temperature rise is accelerating...",
        writer="agent_analyze",
        tags=["analysis", "climate"]
    )
    
    # Agent C (报告生成 Agent) 读取所有 climate 相关的信息
    climate_data = await memory.read_by_tag("climate")
    print(climate_data)
```

### 2.3 优缺点

| 方面 | 评价 |
|------|------|
| **优点** | 实现简单；Agent 可以读到任意其他 Agent 的输出；支持 TTL 自动清理过期信息 |
| **缺点** | 不存在隐私/隔离，所有 Agent 可见所有数据；并发写冲突需要锁机制；需要命名规范避免 key 冲突 |
| **适用场景** | Agent 数量少（<10）、信息共享简单的系统 |

## 三、方案二：消息传递（Message Passing）

### 3.1 架构

每个 Agent 通过**消息队列**发送和接收消息。Agent 之间不共享存储，上下文以消息的形式在 Agent 间流动：

```
  [Agent A] ─── msg_1 ──→ [消息队列] ─── msg_1 ──→ [Agent B]
                │                                        │
                │              ┌──────────┐               │
                └── msg_2 ───→│ 消息队列  │←── msg_3 ────┘
                              └──────────┘
```

### 3.2 实现示例

```python
import asyncio
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Any
from enum import Enum
from datetime import datetime
import uuid


class MessagePriority(Enum):
    LOW = 0
    NORMAL = 1
    HIGH = 2
    CRITICAL = 3


@dataclass
class AgentMessage:
    """Agent 间传递的消息"""
    message_id: str = field(default_factory=lambda: f"msg_{uuid.uuid4().hex[:8]}")
    sender: str = ""
    receiver: str = ""          # "" 表示广播
    context_type: str = ""      # "task", "result", "status", "query"
    payload: Dict = field(default_factory=dict)
    priority: MessagePriority = MessagePriority.NORMAL
    timestamp: str = field(default_factory=lambda: datetime.now().isoformat())
    correlation_id: Optional[str] = None  # 关联消息链
    requires_response: bool = False


class Mailbox:
    """每个 Agent 的消息邮箱"""
    
    def __init__(self, agent_id: str):
        self.agent_id = agent_id
        self._queue: asyncio.Queue = asyncio.Queue()
        self._processed: List[str] = []
    
    async def put(self, message: AgentMessage):
        """放入一条消息"""
        await self._queue.put(message)
    
    async def get(self) -> AgentMessage:
        """获取下一条消息（阻塞）"""
        return await self._queue.get()
    
    def size(self) -> int:
        return self._queue.qsize()


class MessageBus:
    """
    消息总线——负责 Agent 间的消息路由。
    每个 Agent 注册后获得一个 Mailbox，消息总线按 receiver 字段路由。
    """
    
    def __init__(self):
        self._mailboxes: Dict[str, Mailbox] = {}
    
    def register_agent(self, agent_id: str) -> Mailbox:
        """注册 Agent 并返回其邮箱"""
        if agent_id not in self._mailboxes:
            self._mailboxes[agent_id] = Mailbox(agent_id)
        return self._mailboxes[agent_id]
    
    def unregister_agent(self, agent_id: str):
        """注销 Agent"""
        self._mailboxes.pop(agent_id, None)
    
    async def send(self, message: AgentMessage):
        """发送消息给指定 Agent"""
        mailbox = self._mailboxes.get(message.receiver)
        if mailbox:
            await mailbox.put(message)
        else:
            raise ValueError(f"Agent {message.receiver} not found")
    
    async def broadcast(self, message: AgentMessage, 
                        target_agents: Optional[List[str]] = None):
        """
        广播消息给所有或指定的 Agent。
        注意：广播会将消息的 receiver 设为空，各 Agent 自行判断是否处理。
        """
        agents = target_agents or list(self._mailboxes.keys())
        for agent_id in agents:
            msg = AgentMessage(
                sender=message.sender,
                receiver=agent_id,
                context_type=message.context_type,
                payload=message.payload,
                priority=message.priority,
                correlation_id=message.correlation_id,
            )
            await self.send(msg)
    
    async def request(self, message: AgentMessage, 
                      timeout: float = 30.0) -> Optional[AgentMessage]:
        """
        请求-响应模式：发送消息并等待响应。
        响应消息的 correlation_id 会与原消息的 message_id 相同。
        """
        # 创建一个临时邮箱来接收响应
        response_mailbox = Mailbox("_response")
        original_id = message.message_id
        
        # 发送消息
        await self.send(message)
        
        # 等待响应（超时）
        try:
            response = await asyncio.wait_for(
                response_mailbox.get(),
                timeout=timeout
            )
            return response
        except asyncio.TimeoutError:
            return None
```

### 3.3 上下文传递模式

消息传递中的上下文可以以多种方式编码：

**模式 1：完整上下文携带**

每条消息携带 Agent 需要的所有上下文。简单但低效：

```python
message = AgentMessage(
    sender="orchestrator",
    receiver="agent_search",
    context_type="task",
    payload={
        "task": "search climate data",
        "context": {
            "user_request": "Tell me about climate change",
            "previous_results": {...},  # 可能很大
            "global_config": {...}
        }
    }
)
```

**模式 2：增量上下文（Diff）**

只传递自上次通信后变化的部分：

```python
message = AgentMessage(
    sender="agent_search",
    receiver="agent_analyze",
    context_type="result",
    payload={
        "diff": True,
        "new_results": [...],  # 只传增量
        "removed_results": [...],  # 需要移除的旧结果
        "context_ref": "session_001"  # 引用同一个会话的基础上下文
    }
)
```

**模式 3：引用传递（Reference）**

消息中只携带**引用**（指针），Agent 通过引用从共享存储获取实际数据。这实际上是**共享记忆 + 消息传递**的混合模式：

```python
message = AgentMessage(
    sender="agent_search",
    receiver="agent_analyze",
    context_type="result_ref",
    payload={
        "ref_keys": ["search:climate_change_2024"],
        "summary": "找到 10 条相关结果",
        # 实际数据不在消息中，Agent B 通过 ref_keys 去共享记忆读取
    }
)
```

### 3.4 优缺点

| 方面 | 评价 |
|------|------|
| **优点** | 松耦合，Agent 间无共享状态；消息可追踪、可审计；天然支持异步；自然支持增量传递 |
| **缺点** | 消息量大会导致队列积压；需要定义消息 Schema 和协议；调试时追踪消息流较复杂 |
| **适用场景** | 异步工作流、事件驱动架构、跨进程 Agent |

## 四、方案三：结构化摘要交接（Structured Summary Handoff）

### 4.1 架构

当前 Agent 在完成任务后，生成一个**结构化摘要**（Structured Summary），只包含下一个 Agent 需要知道的关键信息。这是"接力式"上下文传递的典型方案：

```
[Agent A]                     [Agent B]
    │                            ▲
    │  生成结构化摘要              │
    │  {                          │
    │    "findings": [...],       │  读取摘要
    │    "unresolved": [...],     │  + 
    │    "artifacts": [...],      │  添加自身贡献
    │    "next_steps": [...]      │
    │  }                          │
    └─────────────────────────────┘
        增量：添加 B 的贡献
        压缩：移除 A 的中间推理
```

### 4.2 实现示例

```python
from dataclasses import dataclass, field
from typing import List, Dict, Any, Optional
from datetime import datetime


@dataclass
class StructuredSummary:
    """
    结构化摘要——Agent 间传递上下文的标准格式。
    这是"接力式"上下文传递的核心数据结构。
    """
    # ──── 基本信息 ────
    session_id: str
    step_number: int                     # 当前在第几步
    agent_id: str                        # 生成此摘要的 Agent
    agent_role: str                      # Agent 的角色名
    
    # ──── 关键发现（只保留对后续步骤有价值的信息）───
    findings: List[Dict] = field(default_factory=list)
    # 每个 finding: {"type": "fact|decision|insight", 
    #                 "content": "...", 
    #                 "confidence": 0.95,
    #                 "source": "..."}
    
    # ──── 未解决的问题（后续 Agent 需要关注的）───
    unresolved: List[str] = field(default_factory=list)
    
    # ──── 演化的产物（代码、文档、配置文件等）───
    artifacts: List[Dict] = field(default_factory=list)
    # 每个 artifact: {"path": "src/main.py", "type": "code", 
    #                 "summary": "实现了用户注册API"}
    
    # ──── 建议的后续步骤 ────
    next_steps: List[str] = field(default_factory=list)
    
    # ──── 从上一个摘要继承的内容 ────
    inherited_context: Dict[str, Any] = field(default_factory=dict)
    # 例如: {"user_request": "...", "constraints": [...], "tech_stack": {...}}
    
    # ──── 元信息 ────
    context_token_count: int = 0         # 摘要的 token 数
    compression_ratio: float = 0.0       # 相比完整上下文的压缩率
    created_at: str = field(default_factory=lambda: datetime.now().isoformat())


class StructuredHandoff:
    """
    结构化摘要交接处理器。
    负责生成、压缩、继承摘要。
    """
    
    def __init__(self, llm: Any):
        self.llm = llm
    
    async def create_summary(self, 
                             agent_id: str,
                             agent_role: str,
                             session_id: str,
                             step_number: int,
                             full_context: Dict[str, Any],
                             previous_summary: Optional[StructuredSummary] = None,
                             max_tokens: int = 2000) -> StructuredSummary:
        """
        从 Agent 的完整上下文生成结构化摘要。
        
        使用 LLM 对 Agent 的完整执行过程进行"蒸馏"，
        只保留对后继 Agent 有价值的信息。
        """
        previous_context = ""
        if previous_summary:
            previous_context = f"""
            上一步的上下文继承：
            - 用户需求：{previous_summary.inherited_context.get('user_request')}
            - 已有发现：{len(previous_summary.findings)} 条
            - 未解决问题：{len(previous_summary.unresolved)} 个
            """
        
        summary_prompt = f"""
        你是一个上下文摘要生成器。请根据 Agent 的完整执行过程，
        生成一个结构化摘要，只包含对后续 Agent 有价值的信息。
        
        Agent 角色：{agent_role}
        当前步骤：{step_number}
        
        {previous_context}
        
        Agent 的完整上下文：
        {json.dumps(full_context, ensure_ascii=False, indent=2)[:5000]}
        
        请输出 JSON 格式的摘要：
        {{
            "findings": [
                {{"type": "fact|decision|insight", 
                  "content": "具体发现",
                  "confidence": 0.0-1.0,
                  "source": "来源"}}
            ],
            "unresolved": ["尚未解决的具体问题"],
            "artifacts": [
                {{"path": "产物路径", "type": "类型", "summary": "描述"}}
            ],
            "next_steps": ["建议下一步做什么"],
            "inherited_context": {{"key": "应传递给后续 Agent 的关键信息"}}
        }}
        
        原则：
        1. 每条信息都应当对后续 Agent 有实际价值
        2. 移除中间推理过程和试错路径
        3. 只保留 < {max_tokens} tokens 的关键信息
        4. 对不确定性信息标注置信度
        """
        
        response = await self.llm.complete(summary_prompt)
        data = json.loads(response)
        
        # 计算压缩率
        full_tokens = len(json.dumps(full_context))
        summary_tokens = len(json.dumps(data))
        
        return StructuredSummary(
            session_id=session_id,
            step_number=step_number,
            agent_id=agent_id,
            agent_role=agent_role,
            findings=data.get("findings", []),
            unresolved=data.get("unresolved", []),
            artifacts=data.get("artifacts", []),
            next_steps=data.get("next_steps", []),
            inherited_context=data.get("inherited_context", {}),
            context_token_count=summary_tokens,
            compression_ratio=1.0 - (summary_tokens / max(full_tokens, 1)),
        )
    
    async def merge_summaries(self, 
                               summaries: List[StructuredSummary],
                               max_tokens: int = 3000) -> StructuredSummary:
        """
        合并多个 Agent 的结构化摘要（用于 Orchestrator 聚合）。
        
        当多个并行 Worker 分别产生摘要后，Orchestrator
        需要将它们合成为一个统一的上下文。
        """
        merge_prompt = f"""
        请合并以下多个 Agent 的结构化摘要为一个统一的摘要。
        合并原则：
        1. 去重：相同内容的 finding 只保留一条（保留置信度最高的）
        2. 排序：按重要性排列 findings
        3. 冲突处理：对具有分歧的发现进行标注
        4. 压缩：总长度不超过 {max_tokens} tokens
        
        各 Agent 的摘要：
        {chr(10).join(f"=== Agent {s.agent_id} ({s.agent_role}) ===\n{json.dumps(s.__dict__, ensure_ascii=False, indent=2)}" for s in summaries)}
        
        请输出合并后的 JSON 摘要（格式同单 Agent 摘要）。
        """
        
        response = await self.llm.complete(merge_prompt)
        data = json.loads(response)
        
        return StructuredSummary(
            session_id=summaries[0].session_id,
            step_number=summaries[0].step_number,
            agent_id="_merged",
            agent_role="merged",
            findings=data.get("findings", []),
            unresolved=data.get("unresolved", []),
            artifacts=data.get("artifacts", []),
            next_steps=data.get("next_steps", []),
            inherited_context=data.get("inherited_context", {}),
        )
```

### 4.3 压缩效果

结构化摘要的压缩效果取决于 Agent 执行过程的"思考密度"：

| 上下文类型 | 原始大小（tokens） | 摘要后大小 | 压缩率 |
|-----------|------------------|-----------|--------|
| 搜索 Agent 执行过程 | 8,000 | 800 | ~90% |
| 分析 Agent 的推理链 | 15,000 | 1,500 | ~90% |
| Coder Agent 的生成日志 | 25,000 | 2,000 | ~92% |
| 多 Agent 合并摘要 | 10,000 × 3 | 3,000 | ~90% |

### 4.4 优缺点

| 方面 | 评价 |
|------|------|
| **优点** | 极高的压缩率，有效解决上下文窗口限制；只传递"有价值的信息"，减少噪声；自然支持接力式流程 |
| **缺点** | 依赖 LLM 生成摘要，引入额外 token 开销；摘要可能丢失重要细节；摘要质量依赖 LLM 的总结能力 |
| **适用场景** | 长流程、多步骤、需要频繁交接上下文的系统 |

## 五、三种方案对比

### 5.1 对比表

| 维度 | 共享记忆 | 消息传递 | 结构化摘要 |
|------|---------|---------|-----------|
| **架构复杂度** | 低 | 中 | 中高 |
| **上下文窗口压力** | 高（所有Agent可能读到全部内容） | 中（选择性传递） | 低（高度压缩） |
| **实时性** | 实时读写 | 异步队列，有延迟 | 接力式，步骤间延迟 |
| **信息丢失风险** | 低 | 中（消息可能丢失） | 中高（摘要依赖 LLM） |
| **审计追踪** | 困难 | 容易（消息日志） | 容易（摘要快照） |
| **Agent 隔离性** | 差（全部可见） | 好（按需接收） | 好（接收摘要） |
| **实现难度** | 简单 | 中等 | 较高 |
| **扩展性（N>20）** | 差 | 好 | 好 |

### 5.2 混合方案：实践中通常组合使用

```
┌──────────────────────────────────────────────────┐
│              混合上下文传递架构                      │
│                                                    │
│  [Orchestrator]  ←──→  结构化摘要         ←──→    │
│       │                    (前后步骤交接)            │
│       │                                            │
│  ┌────┴────┐    ┌────┴────┐    ┌────┴────┐       │
│  │Worker A │    │Worker B │    │Worker C │       │
│  └────┬────┘    └────┬────┘    └────┬────┘       │
│       │              │              │             │
│       └──────消息传递 ──────┘                      │
│              (实时状态同步)                         │
│                                                    │
│  ┌──────────────────────────────────────────┐      │
│  │        共享记忆 (Redis)                    │      │
│  │        - 全局配置                         │      │
│  │        - 共享检索结果                     │      │
│  │        - 会话状态                         │      │
│  └──────────────────────────────────────────┘      │
└──────────────────────────────────────────────────┘
```

**推荐的分层策略**：
1. **全局共享记忆**：存放不常变化、多个 Agent 都需要的基础信息（配置、全局状态）
2. **消息传递**：用于实时状态同步、事件通知、请求-响应
3. **结构化摘要**：用于任务的阶段性交接，特别是长流程和跨角色传递

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 共享记忆（Shared Memory） | 中央存储，所有 Agent 读写同一个存储空间 |
| 消息传递（Message Passing） | Agent 通过消息队列异步交换信息 |
| 结构化摘要（Structured Summary） | 压缩关键信息的结构化数据，用于 Agent 间交接 |
| 增量上下文（Diff Context） | 只传递自上次交互后变化的部分上下文 |
| 引用传递（Reference Passing） | 消息中携带指针而非实际数据，接收方按需读取 |
| 上下文蒸馏 | 用 LLM 从完整执行过程中提取关键信息的过程 |
| 摘要压缩率 | 摘要大小 / 原始上下文大小，通常 10-20% |
