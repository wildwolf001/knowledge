# 17.3 沙箱执行

> **沙箱**（Sandbox）是一种安全隔离机制，将一个程序限制在一个受限的执行环境中，使其无法影响宿主系统或其他程序。对于 Agent 系统，沙箱是实现 Shell 和 Network 权限等级的执行基础——即使 Agent 被注入攻击完全控制，沙箱也能将破坏范围限制在容器内部。

---

## 一、为什么 Agent 需要沙箱？

### 1.1 沙箱解决了什么？

Agent 的工具执行能力带来了一个根本性的安全矛盾：

```
Agent 需要执行代码来完成用户任务
   ├── 运行 Python 脚本分析数据
   ├── 安装 npm 包测试功能
   ├── 执行 Shell 命令操作文件系统
   └── 访问外部 API 获取信息
         │
         ▼
  这些操作如果被恶意利用，后果可能是灾难性的
         │
         ▼
  沙箱提供了一种"既要能力又要安全"的折中方案
```

### 1.2 沙箱的核心目标

1. **隔离性（Isolation）**：沙箱内的操作不能影响宿主系统
2. **限制性（Restriction）**：沙箱内可用的资源（CPU、内存、网络、磁盘）是受控的
3. **可清理性（Ephemeral）**：沙箱在任务完成后可被完全销毁，不留残余
4. **可审计性（Auditability）**：沙箱内的所有操作都有日志记录

## 二、三种沙箱技术对比

### 2.1 技术选型全景

```
隔离性强度
    ↑
  高 │              虚拟机
     │              (VM-Based Sandbox)
     │                 ▲
  中 │    Docker 容器     │
     │  (Container Sandbox) │
     │         ▲           │
  低 │    Host 进程隔离      │
     │  (Process Sandbox) │
     │         │           │
     └─────────┴───────────┴─────────→ 资源效率
       高                  低
```

| 维度 | Host 进程隔离 | Docker 容器（推荐） | 虚拟机 |
|------|-------------|-------------------|--------|
| **隔离层级** | 操作系统进程级 | 操作系统级（共享内核） | 硬件级（独立内核） |
| **启动时间** | 即时 | < 1 秒 | 10-60 秒 |
| **资源开销** | 极低 | 低（~MB 级） | 高（~GB 级） |
| **内核共享** | 是（宿主机内核） | 是（宿主机内核） | 否（独立内核） |
| **逃逸风险** | 高 | 中（有内核逃逸风险） | 低 |
| **管理复杂度** | 低 | 中 | 高 |
| **典型场景** | 快照式临时任务 | 代码执行、包安装 | 高风险任务、多租户 |
| **推荐度** | 不推荐独立使用 | 强烈推荐（默认方案） | 增强安全场景 |

### 2.2 Host 进程隔离（最基本的沙箱）

在操作系统中使用进程级别的隔离机制。这是最轻量但也是最弱的沙箱方案：

```python
import subprocess
import os
import resource
import signal

class ProcessSandbox:
    """
    Host 进程沙箱：使用操作系统原语进行基本隔离
    注意：这只是"基本隔离"，不是真正的安全沙箱
    """
    
    def __init__(self, work_dir: str = "/tmp/sandbox"):
        self.work_dir = work_dir
        os.makedirs(work_dir, exist_ok=True)
    
    def execute(self, code: str, language: str = "python", 
                timeout: int = 30, max_memory_mb: int = 256) -> dict:
        """
        在子进程中执行代码，带基本资源限制
        """
        script_path = self._write_script(code, language)
        
        try:
            start_time = __import__('time').time()
            
            proc = subprocess.Popen(
                self._get_command(language, script_path),
                cwd=self.work_dir,
                stdout=subprocess.PIPE,
                stderr=subprocess.PIPE,
                # 进程组隔离——杀死子进程时不会误杀父进程
                preexec_fn=os.setsid if hasattr(os, 'setsid') else None
            )
            
            try:
                stdout, stderr = proc.communicate(timeout=timeout)
                elapsed = __import__('time').time() - start_time
                
                return {
                    'success': proc.returncode == 0,
                    'stdout': stdout.decode('utf-8', errors='replace'),
                    'stderr': stderr.decode('utf-8', errors='replace'),
                    'exit_code': proc.returncode,
                    'elapsed': elapsed
                }
                
            except subprocess.TimeoutExpired:
                # 超时 → 杀死整个进程组
                if hasattr(os, 'killpg'):
                    try:
                        os.killpg(os.getpgid(proc.pid), signal.SIGKILL)
                    except:
                        pass
                proc.kill()
                return {
                    'success': False,
                    'error': f'Execution timeout ({timeout}s)',
                    'stdout': '', 'stderr': '',
                    'exit_code': -1
                }
                
        finally:
            # 清理临时脚本
            if os.path.exists(script_path):
                os.remove(script_path)
    
    def _write_script(self, code: str, language: str) -> str:
        ext = {'python': '.py', 'javascript': '.js', 'shell': '.sh'}
        path = os.path.join(self.work_dir, f"script_{__import__('uuid').uuid4().hex[:8]}{ext.get(language, '.txt')}")
        with open(path, 'w', encoding='utf-8') as f:
            f.write(code)
        os.chmod(path, 0o644)  # 不可执行——需要解释器执行
        return path
    
    def _get_command(self, language: str, script_path: str) -> list[str]:
        return {
            'python': ['python3', '-u', script_path],  # -u: 无缓冲输出
            'javascript': ['node', script_path],
            'shell': ['bash', script_path],
        }.get(language, ['python3', '-u', script_path])
```

**Host 进程沙箱的局限性**：子进程与宿主机共享文件系统、网络、进程表。一个简单的 `os.system("rm -rf /")` 就能造成破坏。因此 Host 进程隔离**不应单独作为安全沙箱使用**，仅适用于不涉及安全的快速原型开发。

### 2.3 Docker 容器沙箱（推荐方案）

Docker 容器利用 Linux 内核的命名空间（Namespace）和控制组（Cgroup）实现隔离：

│                                                         │

│  │                           │                        │
│  │  ┌────────────────────┐   │                        │

│  │  │  - 注入代码         │   │                        │
│  │  │  - 收集结果         │   │                        │

**完整 Dockerfile 示例——生产级 Agent 沙箱容器**：

```dockerfile
# ============================================================
# Stage 1: 构建阶段
# ============================================================
FROM python:3.11-slim AS builder

# 只安装必要的包，最小化攻击面
RUN apt-get update && apt-get install -y --no-install-recommends \
    gcc \
    && rm -rf /var/lib/apt/lists/*

# 安装 Python 包到单独的目录（用于复制到最终镜像）
RUN pip install --user --no-cache-dir \
    numpy==1.26.0 \
    pandas==2.1.0 \
    requests==2.31.0 \
    pyyaml==6.0.1

# ============================================================
# Stage 2: 运行阶段（最小镜像）
# ============================================================
FROM python:3.11-slim

# 安全配置
LABEL security.agent.sandbox="true"
LABEL security.agent.version="1.0"

# 1. 创建无特权用户
#    为什么？容器内的进程默认以 root 运行，
#    如果容器被逃逸，root 身份会造成更大破坏
RUN groupadd -r sandbox && \
    useradd -r -g sandbox -d /workspace -s /sbin/nologin sandbox && \
    mkdir -p /workspace && \
    chown -R sandbox:sandbox /workspace

# 2. 设置严格的文件权限
COPY --from=builder /root/.local /usr/local
RUN chmod -R 755 /usr/local/lib/python3.11/site-packages

# 3. 安装最小运行时依赖（不安装任何网络工具）
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates \
    && rm -rf /var/lib/apt/lists/* \
    && rm -f /usr/bin/curl /usr/bin/wget /usr/bin/nc /usr/bin/telnet \
    && apt-get remove -y --purge apt-get

# 4. 配置只读根文件系统（除 /workspace 和 /tmp）
#    在 docker run 时通过 --read-only 实现
#    这里先创建可写目录
RUN mkdir -p /tmp && chmod 1777 /tmp

# 5. 设置工作目录
WORKDIR /workspace

# 6. 沙箱执行入口
#    使用 tini 作为 init 进程（防止僵尸进程）
RUN pip install --no-cache-dir tini
ENTRYPOINT ["/usr/local/bin/tini", "--"]

# 默认用户
USER sandbox

# 默认命令
CMD ["python3"]
```

### 2.4 CAP_SYS_ADMIN 与 Linux Capabilities 详解

**Linux Capabilities（能力）**是 Linux 内核将传统的 root 超级用户权限拆分为多个独立的单元。每个能力控制一个具体的特权操作。

对于 Agent 沙箱，最关键的安全规则是：

> **永远不要赋予容器 CAP_SYS_ADMIN 能力**

```
CAP_SYS_ADMIN 是"能力的瑞士军刀"——它实际上包含了超过 30 种不同的特权操作，
包括但不限于：
  - mount/umount 文件系统
  - 创建命名空间（namespace）
  - 访问内核密钥环
  - 设置系统时间
  - 触发内核崩溃（用于调试）
  
如果攻击者在一个有 CAP_SYS_ADMIN 的容器中，
存在多条被验证的逃逸路径。

Docker 的默认能力集（在 --cap-drop=ALL 之前）包含约 14 个能力，
其中有些对 Agent 沙箱也是危险的：
```

**Agent 沙箱的 Capabilities 配置**：

```python
# sandbox_caps.py — 能力配置管理器

# 对 Agent 执行安全的 Linux Capabilities
# 只保留执行代码所需的最小能力集

DEFAULT_SAFE_CAPS = [
    # 没有任何能力是最安全的
    # 但如果需要某些基本操作，逐项添加
]

# 如果 Agent 需要编译代码，可能需要这些：
CODE_COMPILE_CAPS = [
    'CAP_NET_RAW',     # 原始 socket（用于某些编译器测试）
]

# 明确禁止的能力（即使不小心在配置中开启了，也要移除）
FORBIDDEN_CAPS = [
    'CAP_SYS_ADMIN',     # 系统管理——逃逸通行证
    'CAP_SYS_MODULE',    # 加载内核模块
    'CAP_SYS_RAWIO',     # 原始 I/O 访问
    'CAP_SYS_PTRACE',    # 进程跟踪（可读其他进程内存）
    'CAP_SYS_BOOT',      # 重启系统
    'CAP_NET_ADMIN',     # 网络管理
    'CAP_DAC_OVERRIDE',  # 绕过文件权限检查
    'CAP_DAC_READ_SEARCH', # 绕过文件读权限
    'CAP_SETUID',        # 设置用户 ID
    'CAP_SETGID',        # 设置组 ID
    'CAP_FSETID',        # 设置文件 Set-ID
    'CAP_LINUX_IMMUTABLE', # 设置文件不可变属性
    'CAP_MKNOD',          # 创建设备节点
    'CAP_SYS_TIME',       # 修改系统时钟
]

def build_container_config(needs_compile: bool = False) -> dict:
    """构建安全的容器配置"""
    caps = list(DEFAULT_SAFE_CAPS)
    if needs_compile:
        caps.extend(CODE_COMPILE_CAPS)
    
    return {
        'cap_drop': ['ALL'],           # 丢弃所有
        'cap_add': caps,                # 只添加绝对需要的
        'security_opt': ['no-new-privileges:true'],
        'read_only': True,
    }
```

**seccomp 配置文件示例**（限制系统调用）：

```json
{
    "defaultAction": "SCMP_ACT_ERRNO",
    "architectures": ["SCMP_ARCH_X86_64"],
    "syscalls": [
        {
            "names": [
                "read", "write", "open", "close",
                "fstat", "lseek", "mmap", "mprotect",
                "brk", "sched_yield", "exit_group",
                "clock_gettime", "nanosleep"
            ],
            "action": "SCMP_ACT_ALLOW"
        }
    ]
}
```

这个 seccomp 配置只允许最基本的系统调用——连 `fork` 和 `clone` 都不允许，意味着 Agent 不能创建子进程。这极大限制了攻击者的能力，但也限制了 Agent 的正常功能。实际部署时需要根据 Agent 使用的语言和库逐项放行。

## 三、网络隔离策略

### 3.1 网络隔离等级

```
网络隔离等级（从严格到宽松）：

Level 0: 完全无网络
  → network_mode: none
  → Agent 不能进行任何网络通信
  → 适用于纯代码分析、文本处理

Level 1: 仅白名单域名
  → 使用代理/DNS 劫持，只允许特定域名
  → 适用于需要访问特定 API 的 Agent

Level 2: 仅 HTTP(S) 出站
  → 屏蔽非 HTTP 协议（无 DNS、无 TCP 直连）
  → 适用于需要网络搜索的 Agent

Level 3: 受限网络
  → 允许 HTTP(S) + DNS，但屏蔽内部 IP 段
  → 适用于需要广泛网络访问的 Agent

Level 4: 无限制
  → 完全的网络访问（仅在信任环境使用）
  → 适用于高度受控的内部 Agent
```

### 3.2 使用 iptables 实现容器内网络限制

```bash
#!/bin/bash
# restrict_network.sh — 容器内网络限制脚本

# 在容器启动时运行

# 1. 默认丢弃所有出站连接
iptables -P OUTPUT DROP

# 2. 允许回环接口
iptables -A OUTPUT -o lo -j ACCEPT

# 3. 只允许到特定 API 的出站 HTTPS
iptables -A OUTPUT -p tcp --dport 443 -d api.openai.com -j ACCEPT
iptables -A OUTPUT -p tcp --dport 443 -d api.github.com -j ACCEPT

# 4. 允许 DNS 解析（仅到可信 DNS）
iptables -A OUTPUT -p udp --dport 53 -d 8.8.8.8 -j ACCEPT

# 5. 拒绝到内部 IP 段的连接
iptables -A OUTPUT -d 10.0.0.0/8 -j DROP
iptables -A OUTPUT -d 172.16.0.0/12 -j DROP
iptables -A OUTPUT -d 192.168.0.0/16 -j DROP

# 6. 拒绝 ICMP（防止 ping 隧道）
iptables -A OUTPUT -p icmp -j DROP
```

## 四、沙箱管理器的实现

### 4.1 Agent Sandbox Manager

```python
import docker
import time
import uuid
import os
import json

class AgentSandboxManager:
    """
    Agent 沙箱管理器：创建、执行和销毁代码沙箱
    """
    
    def __init__(self, 
                 image_name: str = "agent-sandbox:latest",
                 docker_socket: str = "unix://var/run/docker.sock"):
        self.client = docker.DockerClient(base_url=docker_socket)
        self.image_name = image_name
        self.active_containers: dict[str, docker.models.containers.Container] = {}
        
        # 确保镜像存在
        self._ensure_image()
    
    def _ensure_image(self):
        """确认沙箱镜像已构建"""
        try:
            self.client.images.get(self.image_name)
        except docker.errors.ImageNotFound:
            print(f"Image {self.image_name} not found. Building...")
            # 自动构建
            self.client.images.build(
                path=os.path.dirname(__file__),
                dockerfile="Dockerfile.sandbox",
                tag=self.image_name
            )
    
    def create_sandbox(self, 
                       session_id: str = None,
                       network_level: int = 0,
                       memory_limit: str = "256m",
                       cpu_limit: float = 0.5,
                       timeout: int = 60,
                       environment: dict = None) -> tuple[str, str]:
        """
        创建一个新的沙箱容器
        
        参数：
          session_id: 会话 ID（用于跟踪）
          network_level: 网络隔离等级（0-4）
          memory_limit: 内存限制
          cpu_limit: CPU 限制（核数）
          timeout: 容器最大运行时间（秒）
          environment: 环境变量
        
        返回：
          (container_id, container_name)
        """
        container_id = session_id or f"sandbox-{uuid.uuid4().hex[:12]}"
        
        # 构建网络配置
        network_config = self._build_network_config(network_level)
        
        # 环境变量（注入必要的元信息）
        env = environment or {}
        env.update({
            'SANDBOX_ID': container_id,
            'SANDBOX_TIMEOUT': str(timeout),
            'DEBIAN_FRONTEND': 'noninteractive',
        })
        
        # 构建挂载配置
        # 工作目录使用 tmpfs（内存文件系统）
        # 不挂载任何宿主机目录
        
        # 创建容器
        container = self.client.containers.create(
            image=self.image_name,
            command=["python3", "-c", "import sys; print('Sandbox ready'); sys.stdout.flush(); exec(sys.stdin.read())"],
            name=container_id,
            
            # === 安全配置 ===
            # 能力
            cap_drop=[cap for cap in self._all_caps()],  # 丢弃所有能力
            cap_add=[],                                   # 不添加任何能力
            security_opt=["no-new-privileges:true"],
            
            # seccomp 配置（从文件加载）
            # seccomp_profile=self._get_seccomp_profile(network_level),
            
            # 资源
            mem_limit=memory_limit,
            nano_cpus=int(cpu_limit * 1e9),
            pids_limit=50,
            
            # 文件系统
            read_only=True,
            tmpfs={
                '/workspace': 'size=100M,noexec,nosuid,nodeuid',
                '/tmp': 'size=50M,noexec,nosuid',
            },
            
            # 不分配 TTY，使用 stdin/stdout 通信
            stdin_open=True,
            
            # 网络
            **network_config,
            
            # 自动移除（退出时删除）
            auto_remove=True,
            
            # 环境变量
            environment=env,
            
            # 日志
            log_config={
                'type': 'json-file',
                'config': {'max-size': '10m', 'max-file': '3'}
            },
            
            # 工作目录
            working_dir='/workspace',
        )
        
        self.active_containers[container_id] = container
        container.start()
        
        return container_id, container.name
    
    def execute_code(self, 
                     container_id: str, 
                     code: str, 
                     language: str = "python",
                     timeout: int = 30) -> dict:
        """
        在沙箱中执行代码
        """
        container = self.active_containers.get(container_id)
        if not container:
            return {'success': False, 'error': f'Container {container_id} not found'}
        
        # 注入代码到 stdin
        try:
            # 根据语言包装代码
            wrapped_code = self._wrap_code(code, language)
            
            # 发送到容器 stdin 并等待结果
            result = container.exec_run(
                cmd=["python3", "-c", wrapped_code],
                demux=True,  # 分离 stdout/stderr
                timeout=timeout
            )
            
            stdout, stderr = result.output
            
            return {
                'success': result.exit_code == 0,
                'stdout': (stdout or b'').decode('utf-8', errors='replace'),
                'stderr': (stderr or b'').decode('utf-8', errors='replace'),
                'exit_code': result.exit_code
            }
            
        except Exception as e:
            return {
                'success': False,
                'error': str(e)[:500]
            }
    
    def destroy_sandbox(self, container_id: str):
        """
        销毁沙箱容器
        """
        container = self.active_containers.get(container_id)
        if container:
            try:
                container.stop(timeout=5)
                container.remove(force=True)
            except:
                pass
            del self.active_containers[container_id]
    
    def _build_network_config(self, level: int) -> dict:
        """根据网络等级构建网络配置"""
        if level == 0:
            return {'network_mode': 'none'}
        elif level == 1:
            # 使用自定义网络
            return {
                'network': 'sandbox-restricted-net',
                'extra_hosts': {
                    'api.openai.com': 'host-gateway',
                    'api.github.com': 'host-gateway',
                }
            }
        else:
            return {'network_mode': 'bridge'}
    
    def _wrap_code(self, code: str, language: str) -> str:
        """包装代码以便在沙箱中执行"""
        # 添加安全限制
        prefix = """
import sys, os

# 安全限制
os.chdir('/workspace')  # 只能在工作目录活动

# 禁止的危险操作
_BLOCKED_MODULES = ['ctypes', 'socket', 'pty', 'subprocess']
for mod in _BLOCKED_MODULES:
    sys.modules[mod] = None  # 阻止导入

# 超时机制
import signal
def _timeout_handler(signum, frame):
    print("EXECUTION_TIMEOUT", flush=True)
    sys.exit(1)
signal.signal(signal.SIGALRM, _timeout_handler)
signal.alarm(25)  # 25 秒超时

# 限制文件操作范围
_original_open = open
def _safe_open(file, mode='r', *args, **kwargs):
    if 'w' in mode or 'a' in mode:
        # 只允许在 /workspace 和 /tmp 写入
        import os.path
        abspath = os.path.abspath(file)
        if not abspath.startswith('/workspace') and not abspath.startswith('/tmp'):
            raise PermissionError(f"Write to {abspath} not allowed")
    return _original_open(file, mode, *args, **kwargs)
__builtins__['open'] = _safe_open

# === 用户代码 ===
"""
        return prefix + code

```

## 五、沙箱逃逸与防御

### 5.1 已知逃逸路径

即使使用 Docker 沙箱，也存在逃逸风险。Agent 系统需要了解这些路径：

| 逃逸方式 | 原理 | 防御 |
|---------|------|------|
| **内核漏洞逃逸** | 利用 Linux 内核漏洞（如 CVE-2022-0492）突破容器边界 | 保持内核更新、使用 seccomp、AppArmor |
| **Capability 滥用** | 如果容器有 CAP_SYS_ADMIN，可通过 mount + chroot 逃逸 | 移除所有 Capability |
| **Docker Socket 挂载** | 容器内挂载了 /var/run/docker.sock 可控制宿主机 Docker | 绝不挂载 Docker Socket |
| **共享挂载点** | 宿主机目录以读写方式挂载到容器内 | 使用 tmpfs 而非 host 目录 |
| **进程间通信** | 通过共享的 PID 命名空间操作宿主机进程 | 使用独立的 PID 命名空间 |
| **配置不当的 Seccomp** | seccomp 配置放行了 mount/open_by_handle_at 等 syscall | 严格的 seccomp 配置 |

### 5.2 安全的默认配置

```yaml
# config/sandbox-security.yml
# Agent 沙箱安全默认配置

sandbox:
  # 默认安全级别（生产环境）
  default:
    capabilities:
      drop: [ALL]           # 丢弃所有
      add: []                # 不添加
    security_opt:
      - no-new-privileges:true
      - apparmor=sandbox-default
    seccomp: sandbox-strict
    read_only_rootfs: true
    tmpfs:
      /workspace: "size=100M"
      /tmp: "size=50M"
    network: "none"
  
  # 高风险任务的安全级别（代码编译、安装包等）
  high_risk:
    extends: default
    network: "isolated-net"
    capabilities:
      drop: [ALL]
      add: []                # 仍然不添加
    pids_limit: 100          # 允许更多进程
  
  # 完全受控的内部任务
  trusted:
    extends: default
    network: "internal-only"
    tmpfs:
      /workspace: "size=500M"
    memory: "1g"
```

### 5.3 沙箱清理策略

任务完成后沙箱的销毁不是简单"删容器"——需要确保没有残留：

```python
def destroy_with_cleanup(container_id: str):
    """
    安全销毁沙箱并清理残留
    """
    # 1. 先尝试优雅关闭
    try:
        container.stop(timeout=5)
    except:
        pass
    
    # 2. 强制 kill 所有进程
    try:
        container.kill()
    except:
        pass
    
    # 3. 删除容器
    try:
        container.remove(force=True, v=True)  # v=True 删除关联卷
    except:
        pass
    
    # 4. 清理任何残余的网络端点
    try:
        container.disconnect_all_networks()
    except:
        pass
    
    # 5. 记录销毁日志
    audit_log("sandbox_destroyed", {
        'container_id': container_id,
        'timestamp': time.time()
    })
```

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 沙箱（Sandbox） | 限制程序执行范围的隔离环境 |
| Linux Capabilities | 将 root 权限拆分为独立单元的内核机制 |
| CAP_SYS_ADMIN | 最危险的 Linux 能力，包含约 30 种特权操作 |
| Namespace（命名空间） | Linux 内核隔离资源的机制（PID、网络、挂载等） |
| Cgroup（控制组） | Linux 内核限制资源使用（CPU、内存、磁盘 I/O）的机制 |
| Seccomp | Linux 内核的安全计算模式，限制可用的系统调用 |
| AppArmor | 基于路径的强制性访问控制（MAC）系统 |
| tmpfs | 位于内存中的临时文件系统，容器重启后丢失 |
| 容器逃逸 | 突破容器隔离限制，获得宿主机访问权限的攻击 |
| tini | 容器内的 init 进程，防止僵尸进程 |
| read_only_rootfs | 容器的根文件系统只读，防止恶意写入系统文件 |
