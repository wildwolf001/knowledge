# 17.2 工具权限分级

> **工具权限分级**（Tool Permission Grading）是指根据 Agent 工具的执行能力和影响范围，将其划分为不同的权限等级，每个等级对应明确的信任边界。其核心理念是：**没有任何 Agent 应该拥有所有权限，权限的最小化原则同样适用于 AI 系统**。

---

## 一、为什么需要权限分级？

### 1.1 Agent 权限的独特性

传统的权限管理面向人类用户或服务账户，权限是"用户身份"的属性。而 Agent 的权限管理面临三个独特挑战：

1. **动态执行路径**：人类用户的操作路径是可预测的（一个开发者通常只需要 IDE + 终端 + 浏览器权限），但 Agent 的思考路径千变万化，无法静态预判需要哪些权限
2. **上下文敏感**：同一个工具在不同上下文中风险等级不同（"读取一个日志文件" vs "读取 /etc/shadow"），而传统权限模型无法感知上下文
3. **级联调用**：Agent 调用工具 A，工具 A 可能内部调用工具 B，形成调用链。权限需要跨越整条链

### 1.2 不分级的风险

```
无权限分级的 Agent（单一扁平权限）：
  
  Agent 权限 = 全部
      ├── 读取用户文档（合理）
      ├── 发送邮件（正常需求）
      ├── 执行 Shell 命令（可能需要）
      └── 修改系统配置（也可能被调用）
  
  一次成功的 Prompt Injection → 所有能力被劫持
            
  有权限分级的 Agent（分层权限）：
  
  Agent 当前权限 = Read-only
      ├── 读取用户文档（✅）
      ├── 发送邮件（❌ 权限不足）
      ├── 执行 Shell 命令（❌ 权限不足）
      └── 修改系统配置（❌ 权限不足）
  
  一次成功的 Prompt Injection → 只能读取，无法写入
```

### 1.3 权限分级 vs 传统 RBAC

Agent 的权限模型不能直接照搬传统的基于角色的访问控制（RBAC，Role-Based Access Control），因为 Agent 的"角色"不是固定的：

| 维度 | 传统 RBAC | Agent 权限分级 |
|------|----------|---------------|
| 权限主体 | 人类用户（身份固定） | Agent 会话（运行时动态） |
| 权限变更 | 管理员手动分配 | 系统根据上下文自动升降级 |
| 粒度 | 粗粒度（角色级） | 细粒度（操作+参数级） |
| 持续时间 | 长期有效 | 会话级/操作级 |
| 上下文感知 | 无 | 强（权限与上下文绑定） |

## 二、五级权限模型

### 2.1 权限等级划分

```
权限等级光谱：

  Read        Write        Shell        Network       Agent
   ───────────┬───────────┬────────────┬──────────────┬─────→
  影响范围增大 ──────────────────────────────────────────→
  风险等级增大 ──────────────────────────────────────────→
  所需信任度增大 ──────────────────────────────────────────→
```

**每个等级的定义和信任边界**：

### Level 1: Read（只读）

| 项目 | 内容 |
|------|------|
| **能力** | 读取文件、搜索本地知识库、查询数据库（SELECT only）、读取配置 |
| **信任边界** | 不能修改任何持久化状态，不能执行任何副作用操作 |
| **典型工具** | `read_file`, `search_web`, `query_database(SELECT)`, `get_weather` |
| **适用场景** | 知识问答 Agent、信息检索 Agent、审核预览流程 |
| **逃逸后果** | 信息泄露——但可控，因为无法修改任何数据 |

**信任边界示意图**：
```
Read Level 的 Agent

  可以访问：                      不可以访问：
  /home/user/documents/          /etc/shadow
  公开知识库                     加密密钥文件
  只读数据库副本                  写数据库连接
  日志文件（脱敏后）               真实用户数据表
```

### Level 2: Write（写入）

| 项目 | 内容 |
|------|------|
| **能力** | 创建/修改文件、更新数据库记录、发送通知、修改文档 |
| **信任边界** | 能修改数据，但不能执行系统级操作或网络连接受限 |
| **典型工具** | `write_file`, `update_database`, `send_email`, `create_doc` |
| **适用场景** | 内容生成 Agent、数据分析 Agent、文档处理 Agent |
| **逃逸后果** | 数据篡改——中等严重，需额外审计和备份 |

**关键约束**：
- 所有写操作必须有审计日志
- 不可逆操作（DELETE/DROP）需要二次确认或直接禁止
- 写操作的"目标范围"应受限（如只能写 `/workspace/` 而不能写 `/etc/`）

### Level 3: Shell（命令执行）

| 项目 | 内容 |
|------|------|
| **能力** | 执行系统命令、运行脚本、安装软件包、管理进程 |
| **信任边界** | 能影响宿主机的运行状态，但不能修改网络配置或访问外部服务 |
| **典型工具** | `execute_shell`, `run_script`, `install_package`, `manage_service` |
| **适用场景** | DevOps Agent、开发辅助 Agent、自动化运维 Agent |
| **逃逸后果** | 远程代码执行（RCE）——严重，必须在沙箱中执行 |

**Shell 权限的额外约束**：
```
Shell 权限不是"允许所有命令"，而是"允许经过沙箱的命令列表"：

✅ 允许的命令（白名单）：
  - ls, cat, head, tail, grep, find（只读命令）
  - python, node, go（受限沙箱内的脚本执行）
  - git（受限仓库内操作）
  - docker（只允许预定义的容器操作）

❌ 禁止的命令（黑名单）：
  - rm -rf /, dd, mkfs（破坏性操作）
  - sudo, su, chown（权限提升操作）
  - nc, ncat, telnet（网络隧道）
  - wget, curl（不受控的文件下载）
  
⚠️ 需要二次确认的命令：
  - systemctl restart（重启服务）
  - docker rm, docker rmi（删除容器/镜像）
  - git push --force（强制推送）
```

### Level 4: Network（网络）

| 项目 | 内容 |
|------|------|
| **能力** | 发起 HTTP 请求、连接数据库、建立 WebSocket、访问内部服务 |
| **信任边界** | 能访问外部和内部网络资源，但不能直接执行 Shell 命令 |
| **典型工具** | `http_request`, `connect_database`, `websocket_connect`, `api_call` |
| **适用场景** | API Agent、集成 Agent、自动化工作流 Agent |
| **逃逸后果** | 横向移动——能访问内部网络的其他服务，风险极高 |

**网络权限的域白名单**：
```python
class NetworkPermissionGuard:
    """
    网络权限守卫：基于域白名单和协议白名单控制网络访问
    """
    
    # 域白名单配置
    ALLOWED_DOMAINS = {
        'api.github.com': {'read', 'write'},     # 读写
        'api.openai.com': {'read'},               # 只读
        'internal-api.company.com': {'read', 'write'},
        '*.internal.company.com': {'read'},       # 通配符
    }
    
    BLOCKED_IPS = [
        '10.0.0.0/8',     # 内网段（除非明确允许）
        '172.16.0.0/12',  # 内网段
        '192.168.0.0/16', # 内网段
        '169.254.0.0/16', # 链路本地
    ]
    
    def __init__(self, agent_id: str, session_id: str):
        self.agent_id = agent_id
        self.session_id = session_id
        self.network_calls: list[dict] = []
    
    def check_network_call(self, url: str, method: str, headers: dict = None) -> dict:
        """
        检查网络调用是否允许
        """
        from urllib.parse import urlparse
        import ipaddress
        
        parsed = urlparse(url)
        hostname = parsed.hostname or ''
        
        # 1. 检查是否匹配允许域
        allowed = self._match_domain(hostname, method)
        if not allowed:
            return {
                'decision': 'DENY',
                'reason': f'Domain {hostname} not in allowed list'
            }
        
        # 2. 检查是否在禁止 IP 段
        try:
            import socket
            ip = socket.gethostbyname(hostname)
            ip_obj = ipaddress.ip_address(ip)
            for blocked in self.BLOCKED_IPS:
                if ip_obj in ipaddress.ip_network(blocked):
                    return {
                        'decision': 'DENY',
                        'reason': f'IP {ip} falls in blocked range {blocked}'
                    }
        except:
            pass  # DNS 解析失败，继续执行
        
        # 3. 检查 headers 中是否有敏感信息
        if headers:
            sensitive_headers = ['authorization', 'cookie', 'x-api-key', 'token']
            for sh in sensitive_headers:
                if sh in {k.lower() for k in headers.keys()}:
                    return {
                        'decision': 'FLAG',
                        'reason': f'Network call contains sensitive header: {sh}',
                        'require_confirm': True
                    }
        
        self.network_calls.append({
            'url': url, 'method': method, 'timestamp': __import__('time').time()
        })
        
        return {'decision': 'ALLOW', 'reason': 'ok'}
    
    def _match_domain(self, hostname: str, method: str) -> bool:
        """匹配域白名单"""
        for pattern, allowed_methods in self.ALLOWED_DOMAINS.items():
            if pattern.startswith('*.'):
                # 通配符匹配
                suffix = pattern[1:]
                if hostname.endswith(suffix) or hostname == pattern[2:]:
                    if method.lower() in allowed_methods or 'read' in allowed_methods:
                        return True
            else:
                if hostname == pattern or hostname.endswith('.' + pattern):
                    if method.lower() in allowed_methods or 'read' in allowed_methods:
                        return True
        return False
```

### Level 5: Agent（元权限）

| 项目 | 内容 |
|------|------|
| **能力** | 创建子 Agent、修改自身权限、安装新工具、修改执行策略 |
| **信任边界** | 能修改 Agent 系统本身，直接影响系统元能力 |
| **典型工具** | `create_sub_agent`, `modify_permission`, `install_tool`, `update_policy` |
| **适用场景** | Agent 编排系统、自动化部署、超级管理员模式 |
| **逃逸后果** | 完全沦陷——攻击者获得 Agent 系统的全部控制权 |

**Agent 级权限的特殊约束**：
```
Agent 权限应被视为"系统的 root"：

1. 使用 Agent 权限进行的任何操作必须同时记录到独立的、
   不可篡改的审计日志（写入单独的日志服务器，不是本地文件）

2. Agent 权限创建的子 Agent 的权限不得超过父 Agent 的权限

3. Agent 权限的升级操作（Level 4 → Level 5）需要：
   - 至少两人批准
   - 实时通知安全管理员
   - 写审计快照（操作前的权限状态 vs 操作后的权限状态）

4. Agent 权限应默认禁用，仅在明确授权的任务中临时启用
```

## 三、权限的动态升降级

### 3.1 静态 vs 动态权限

Agent 的权限模型需要支持运行时动态调整，而不是在部署时一次性分配完毕：

```
静态权限模型（不推荐）：
  部署时分配 → 整个会话期固定 → Agent 要么权限不足（频繁失败）
                                 要么权限过大（风险高）

动态权限模型（推荐）：
  初始分配最小权限 → 按需申请升级 → 任务完成后降级
                     ↓
             上下文驱动的权限提升
```

### 3.2 上下文驱动的权限提升

```python
class DynamicPermissionManager:
    """
    动态权限管理器：基于最小权限原则，按需提升/降级 Agent 权限
    """
    
    # 权限等级映射
    LEVELS = {
        'read': 1,
        'write': 2,
        'shell': 3,
        'network': 4,
        'agent': 5
    }
    
    def __init__(self, default_level: str = 'read'):
        self.current_level = default_level
        self.request_history: list[dict] = []
        self.granted_permissions: dict[str, dict] = {}
    
    def request_elevation(self, 
                          agent_reasoning: str, 
                          requested_tool: str,
                          requested_level: str,
                          context: dict) -> dict:
        """
        处理 Agent 的权限提升请求
        """
        # 1. 评估请求的合理性
        assessment = self._assess_request(
            agent_reasoning, requested_tool, requested_level, context
        )
        
        # 2. 记录请求
        self.request_history.append({
            'tool': requested_tool,
            'requested_level': requested_level,
            'reasoning': agent_reasoning,
            'assessment': assessment,
            'timestamp': __import__('time').time()
        })
        
        # 3. 决定
        if assessment['score'] < 0.3:
            return {'granted': False, 'reason': assessment['reason']}
        
        elif assessment['score'] < 0.7:
            # 中等置信度 → 临时提升，限定范围
            self._grant_temporary_permission(
                requested_tool, requested_level, ttl_seconds=60
            )
            return {
                'granted': True,
                'temporary': True,
                'ttl': 60,
                'reason': 'temporary_elevation_for_specific_task'
            }
        
        else:
            # 高置信度 → 正常提升
            self.current_level = requested_level
            return {
                'granted': True,
                'temporary': False,
                'reason': 'elevation_granted'
            }
    
    def _assess_request(self, 
                        reasoning: str, 
                        tool: str, 
                        level: str, 
                        context: dict) -> dict:
        """
        评估权限请求的合理性分数（0.0-1.0）
        """
        score = 0.5  # 基准分
        
        # 正向信号：理由充分
        positive_signals = [
            'need to write', 'create file', 'update record',
            'save result', 'export data',
            '因为', '所以', '为了', '需要',
        ]
        for signal in positive_signals:
            if signal in reasoning.lower():
                score += 0.1
        
        # 负向信号：理由不充分或要求过高
        negative_signals = [
            'just', 'trust me', 'ignore security',
            'temporarily disable', 'bypass',
            '随便', '信任我', '不管安全',
        ]
        for signal in negative_signals:
            if signal in reasoning.lower():
                score -= 0.2
        
        # 等级合理性：如果 request 的等级超过实际需要，降低分数
        level_delta = self.LEVELS[level] - self.LEVELS.get(
            context.get('required_level', 'read'), 1
        )
        if level_delta > 1:
            score -= 0.2 * level_delta
        
        # 历史记录：如果最近有被拒绝的权限请求，降分
        recent_denials = [
            r for r in self.request_history[-5:]
            if not r.get('granted')
        ]
        score -= len(recent_denials) * 0.05
        
        return {
            'score': max(0.0, min(1.0, score)),
            'reason': f'Assessment score: {max(0.0, min(1.0, score)):.2f}'
        }
    
    def _grant_temporary_permission(self, tool: str, level: str, ttl_seconds: int):
        """
        授予临时权限
        """
        import time
        self.granted_permissions[tool] = {
            'level': level,
            'expires_at': time.time() + ttl_seconds
        }
        # 不改变 current_level——临时权限只针对特定工具
    
    def check_tool_permission(self, tool: str, required_level: str) -> dict:
        """
        检查当前是否有权使用某个工具
        """
        # 检查临时权限
        if tool in self.granted_permissions:
            perm = self.granted_permissions[tool]
            if __import__('time').time() < perm['expires_at']:
                return {'allowed': True, 'source': 'temporary_grant'}
            else:
                del self.granted_permissions[tool]  # 过期清理
        
        # 检查当前等级
        if self.LEVELS[self.current_level] >= self.LEVELS[required_level]:
            return {'allowed': True, 'source': 'current_level'}
        
        return {'allowed': False, 'source': 'insufficient_permissions'}
```

### 3.3 权限衰减

Agent 的权限应该随时间自动衰减，而不是保持在初始授予的等级：

```
权限衰减策略：

  初始权限（Read）
      │
      ├── Agent 请求提升 → 临时提升到 Write（60秒）
      │                              │
      │                    60秒无写操作 → 自动降级回 Read
      │                              │
      │                    40秒时执行写操作 → 续期 60秒
      │
      ├── 长时间无操作（300秒）→ Read → Locked（需要用户确认解锁）
      │
      └── 高风险检测 → 立即降级，无论当前在什么等级
```

## 四、权限的审计与可追溯性

### 4.1 每次工具调用的审计记录

```python
class PermissionAuditLogger:
    """
    权限审计日志：记录每一次权限使用和权限变更
    """
    
    def __init__(self, log_endpoint: str = None):
        self.logs: list[dict] = []
        self.log_endpoint = log_endpoint  # 外部日志服务
    
    def log_permission_check(self, 
                             agent_id: str,
                             session_id: str,
                             tool: str,
                             params: dict,
                             current_level: str,
                             required_level: str,
                             decision: str,
                             reason: str):
        """记录权限检查事件"""
        import time, json
        
        log_entry = {
            'event_type': 'permission_check',
            'timestamp': time.time(),
            'agent_id': agent_id,
            'session_id': session_id,
            'tool': tool,
            'params_snapshot': self._sanitize_params(params),
            'current_level': current_level,
            'required_level': required_level,
            'decision': decision,
            'reason': reason,
            'trace_id': self._generate_trace_id()
        }
        
        self.logs.append(log_entry)
        
        # 同步到外部日志服务（如果有）
        if self.log_endpoint and decision in ('DENY', 'FLAG'):
            self._sync_to_external(log_entry)
        
        # 拒绝和标记事件需要额外通知
        if decision in ('DENY', 'FLAG'):
            self._alert_security_team(log_entry)
    
    def _sanitize_params(self, params: dict) -> dict:
        """在审计日志中脱敏敏感参数"""
        sensitive_keys = ['password', 'api_key', 'token', 'secret', 'credential']
        sanitized = {}
        for k, v in params.items():
            if any(sk in k.lower() for sk in sensitive_keys):
                sanitized[k] = '[REDACTED]'
            else:
                sanitized[k] = str(v)[:200]  # 截断长参数
        return sanitized
    
    def _generate_trace_id(self) -> str:
        import uuid
        return str(uuid.uuid4())[:8]
    
    def _alert_security_team(self, entry: dict):
        """权限拒绝/标记事件 → 实时安全告警"""
        import logging
        logger = logging.getLogger('security.permission')
        logger.warning(
            f"Permission {entry['decision']}: "
            f"agent={entry['agent_id']} tool={entry['tool']} "
            f"reason={entry['reason']}"
        )
```

当权限问题导致安全事件时，需要能够回溯整个调用链：

```
审计追溯示例：

时间戳                   事件                               决策
2026-06-01 10:00:01  Agent 启动，初始权限 = Read          ALLOW
2026-06-01 10:00:05  工具调用: read_file(/docs/resume.pdf)  ALLOW (Read)

2026-06-01 10:01:02  工具调用: execute_shell(rm -rf /)      DENY (权限不足)
                    → 注入攻击检测！触发安全模式
```

## 五、多 Agent 系统中的权限传播

### 5.1 权限不升级原则

在多 Agent 协作场景中，子 Agent 的权限不能超过父 Agent：

```
主 Agent (权限: Write)
  │
  ├── 创建子 Agent A (权限: Read)      ← 合法，降级
  ├── 创建子 Agent B (权限: Write)     ← 合法，同级
  └── 创建子 Agent C (权限: Shell)     ← 非法！超过父级权限
       └→ 父 Agent 权限 Write < Shell，拒绝创建
```

### 5.2 跨 Agent 令牌传递

Agent A 调用工具获得了一个访问令牌（Token），不能自动允许 Agent B 使用该令牌：

```
场景：
  Agent A (Read) → 调用 API → 获得 session_token
  Agent A → 创建 Agent B (Read) → Agent B 尝试使用 session_token

防御：
  TokenGuard 检测到 session_token 是在 A 的上下文中获得的，
  B 试图使用时 → DENY + 记录"跨 Agent 令牌滥用"告警
```

## 六、最佳实践清单

### 6.1 部署检查清单

- [ ] 每个 Agent 有默认的最低权限（推荐：Read）
- [ ] 所有权限提升请求都记录审计日志
- [ ] 临时权限有过期时间（TTL）
- [ ] 权限衰减机制已启用
- [ ] 子 Agent 权限不超过父 Agent
- [ ] 高风险操作需要二次确认
- [ ] 权限事件与安全告警系统集成
- [ ] 权限配置可在运行时更新（不需重启）
- [ ] 网络权限配置了域白名单
- [ ] Shell 权限配置了命令白名单

### 6.2 常见误区和反面模式

| 误区 | 为什么危险 | 正确做法 |
|------|-----------|---------|
| "Agent 要解决所有问题，所以给满权限" | 一次注入攻击全系统沦陷 | 最小权限启动，按需提升 |
| "写操作我都加上二次确认就好" | 用户会产生"确认疲劳"，自动点击确认 | 基于风险等级动态决定是否需要确认 |
| "网络权限用了白名单所以安全" | SSRF 攻击可以绕过 DNS 解析拿到内部 IP | 白名单 + IP 段黑名单双重检查 |
| "Shell 命令我都转义了" | 转义挡不住 `rm -rf /` 这种合法但危险命令 | 命令白名单 + 参数校验 |

## 关键概念速查

| 术语 | 解释 |
|------|------|
| 工具权限分级 | 按能力和影响范围划分的 Agent 权限等级体系 |
| 信任边界 | 每个权限等级能够和不能做的事情的清晰界限 |
| 最小权限原则 | Agent 只获得完成任务所需的最小权限 |
| 权限动态升降级 | 运行时根据上下文调整 Agent 权限等级 |
| 权限衰减 | Agent 权限随时间自动降级的安全机制 |
| 二级确认 | 高风险操作需要用户或管理员二次批准 |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| 权限传播 | 多 Agent 系统中父 Agent 向子 Agent 的权限传递 |
| TTL | 临时权限的有效期（Time To Live） |
