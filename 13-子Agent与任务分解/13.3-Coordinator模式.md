# 13.3 Coordinator 模式 —— 任务分发、结果聚合、超时处理、部分失败恢复

> Coordinator（协调器）是 Multi-Agent 系统的中央调度节点，负责将分解后的子任务分发给子 Agent，收集并聚合结果，处理超时和部分失败场景。它是"分而治之"策略的执行引擎，也是系统容错能力的关键组件。

---

## 一、Coordinator 的核心职责

Coordinator 处于 Multi-Agent 架构的中间层，位于主任务和子 Agent 之间：

```
                         ┌───────────────────────┐
                         │    主任务入口          │
                         │   (Parent Task)        │
                         └───────────┬───────────┘
                                     │
                                     ▼
                         ┌───────────────────────┐
                         │     Coordinator        │
                         │   (协调器/调度器)       │
                         └──┬──────┬──────┬─────┘
                            │      │      │
              ┌─────────────┼──────┼──────┼─────────────┐
              │             │      │      │             │
              ▼             ▼      ▼      ▼             ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
        │SubAgent A│ │SubAgent B│ │SubAgent C│ │SubAgent D│
        └──────────┘ └──────────┘ └──────────┘ └──────────┘
              │             │      │      │             │
              └─────────────┼──────┼──────┼─────────────┘
                            │      │      │
                            ▼      ▼      ▼
                         ┌───────────────────────┐
                         │     结果聚合器         │
                         │   (Result Aggregator)  │
                         └───────────┬───────────┘
                                     │
                                     ▼
                         ┌───────────────────────┐
                         │     最终输出           │
                         │   (Final Response)     │
                         └───────────────────────┘
```

### 1.1 Coordinator 的五个核心职责

1. **任务解析与分解**：将主任务解析为子任务列表，确定依赖关系（依赖 13.1 节的粒度判定策略）
2. **子 Agent 生命周期管理**：创建、初始化、销毁子 Agent 的上下文和工具集（依赖 13.2 节的隔离策略）
3. **调度与分发**：按依赖关系将子任务分配给合适的子 Agent，管理执行顺序
4. **结果收集与聚合**：收集子 Agent 的执行结果，进行格式对齐和冲突消解
5. **容错处理**：处理超时、失败、部分失败场景，执行重试或降级策略

---

## 二、Coordinator 完整代码骨架

以下代码实现了完整的 Coordinator 模式，包含超时处理、部分失败恢复和结果聚合：

```python
"""
coordinator.py — Coordinator 模式完整实现

依赖:
- asyncio: 异步任务管理
- dataclasses: 结果数据结构
- typing: 类型注解
"""

import asyncio
import time
import logging
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Callable, Dict, List, Optional, Tuple, Union

logger = logging.getLogger(__name__)

# ============================================================
# 1. 数据类型定义
# ============================================================

class SubTaskStatus(Enum):
    """子任务状态"""
    PENDING = "pending"          # 等待执行
    RUNNING = "running"          # 执行中
    SUCCESS = "success"          # 执行成功
    FAILED = "failed"            # 执行失败
    TIMEOUT = "timeout"          # 执行超时
    SKIPPED = "skipped"          # 因依赖失败而跳过
    RETRYING = "retrying"        # 重试中


@dataclass
class SubTask:
    """子任务定义"""
    id: str                                # 唯一标识
    name: str                              # 任务名称
    agent_id: Optional[str] = None         # 分配的 Agent ID
    dependencies: List[str] = field(default_factory=list)  # 依赖的子任务 ID
    params: Dict[str, Any] = field(default_factory=dict)   # 输入参数
    timeout_seconds: float = 30.0          # 超时时间
    max_retries: int = 2                   # 最大重试次数
    retry_delay: float = 1.0              # 重试间隔（秒）
    status: SubTaskStatus = SubTaskStatus.PENDING
    result: Any = None                     # 执行结果
    error: Optional[str] = None            # 错误信息
    started_at: Optional[float] = None     # 开始时间
    finished_at: Optional[float] = None    # 结束时间
    retry_count: int = 0                   # 已重试次数


@dataclass
class TaskResult:
    """整体任务结果"""
    success: bool                          # 是否整体成功
    main_result: Any                       # 聚合后的主结果
    sub_results: Dict[str, Any]            # 各子任务的原始结果
    failed_tasks: List[str]                # 失败的任务 ID 列表
    timed_out_tasks: List[str]             # 超时的任务 ID 列表
    total_time: float                      # 总耗时（秒）
    partial: bool = False                  # 是否部分成功


# ============================================================
# 2. Coordinator 核心实现
# ============================================================

class SubAgentExecutor:
    """
    子 Agent 执行器抽象类。
    实际使用时需要继承此类，实现 execute 方法。
    """
    
    async def execute(self, task: SubTask) -> Any:
        """
        执行子任务。子类必须实现此方法。
        
        参数：
            task: 待执行的子任务
        
        返回：
            子任务的执行结果
        
        抛出：
            Exception: 执行过程中发生的任何异常
        """
        raise NotImplementedError


class Coordinator:
    """
    Coordinator 协调器
    
    负责任务分发、结果收集、超时处理和部分失败恢复。
    支持三种执行模式：
    - sequential: 串行执行（按依赖拓扑排序）
    - parallel: 并行执行（无依赖的子任务同时执行）
    - hybrid: 混合执行（按依赖层次组织，同层并行，层间串行）
    """
    
    def __init__(
        self,
        executor: SubAgentExecutor,
        mode: str = "hybrid",
        global_timeout: float = 120.0,
        partial_ok: bool = True,
    ):
        """
        初始化 Coordinator
        
        参数：
            executor: 子 Agent 执行器
            mode: 执行模式（sequential / parallel / hybrid）
            global_timeout: 全局超时时间（秒）
            partial_ok: 是否允许部分成功
        """
        self.executor = executor
        self.mode = mode
        self.global_timeout = global_timeout
        self.partial_ok = partial_ok
    
    # ----------------------------------------------------------
    # 2.1 任务分发
    # ----------------------------------------------------------
    
    async def dispatch(
        self,
        subtasks: List[SubTask],
        context: Optional[Dict[str, Any]] = None,
    ) -> TaskResult:
        """
        分发并执行一组子任务
        
        参数：
            subtasks: 子任务列表
            context: 可选上下文数据
        
        返回：
            TaskResult: 聚合后的任务结果
        """
        start_time = time.time()
        
        # 构建任务映射
        task_map: Dict[str, SubTask] = {task.id: task for task in subtasks}
        
        # 验证依赖关系
        self._validate_dependencies(task_map)
        
        # 按执行模式调度
        try:
            if self.mode == "sequential":
                await self._execute_sequential(subtasks, task_map, context)
            elif self.mode == "parallel":
                await self._execute_parallel(subtasks, task_map, context)
            elif self.mode == "hybrid":
                await self._execute_hybrid(subtasks, task_map, context)
            else:
                raise ValueError(f"不支持的模式: {self.mode}")
        except asyncio.CancelledError:
            logger.warning("任务被取消")
            return self._build_partial_result(
                task_map, start_time, cancelled=True
            )
        
        return self._build_result(task_map, start_time)
    
    def _validate_dependencies(
        self, task_map: Dict[str, SubTask]
    ) -> None:
        """验证依赖关系的合法性"""
        for task_id, task in task_map.items():
            for dep_id in task.dependencies:
                if dep_id not in task_map:
                    raise ValueError(
                        f"任务 {task_id} 依赖不存在的任务 {dep_id}"
                    )
                # 检测循环依赖
                if self._has_cycle(task_map, dep_id, task_id, set()):
                    raise ValueError(
                        f"检测到循环依赖: {task_id} ↔ {dep_id}"
                    )
    
    def _has_cycle(
        self,
        task_map: Dict[str, SubTask],
        current: str,
        target: str,
        visited: set,
    ) -> bool:
        """检测循环依赖（DFS）"""
        if current == target:
            return True
        if current in visited:
            return False
        visited.add(current)
        task = task_map.get(current)
        if task:
            for dep in task.dependencies:
                if self._has_cycle(task_map, dep, target, visited):
                    return True
        return False
    
    # ----------------------------------------------------------
    # 2.2 串行执行
    # ----------------------------------------------------------
    
    async def _execute_sequential(
        self,
        subtasks: List[SubTask],
        task_map: Dict[str, SubTask],
        context: Optional[Dict[str, Any]],
    ):
        """按拓扑排序串行执行"""
        sorted_tasks = self._topological_sort(subtasks, task_map)
        
        for task in sorted_tasks:
            # 检查依赖是否全部成功
            if not self._check_dependencies_success(task, task_map):
                task.status = SubTaskStatus.SKIPPED
                continue
            
            await self._execute_single_with_retry(task, context)
    
    # ----------------------------------------------------------
    # 2.3 并行执行
    # ----------------------------------------------------------
    
    async def _execute_parallel(
        self,
        subtasks: List[SubTask],
        task_map: Dict[str, SubTask],
        context: Optional[Dict[str, Any]],
    ):
        """所有无依赖的任务并行执行"""
        sorted_tasks = self._topological_sort(subtasks, task_map)
        
        # 按层级分组，同层并行
        levels = self._group_by_level(sorted_tasks, task_map)
        
        for level in levels:
            # 过滤掉依赖失败的任务
            executable = []
            for task in level:
                if self._check_dependencies_success(task, task_map):
                    executable.append(task)
                else:
                    task.status = SubTaskStatus.SKIPPED
            
            if not executable:
                continue
            
            # 并行执行当前层的所有任务
            tasks = [
                self._execute_single_with_retry(task, context)
                for task in executable
            ]
            await asyncio.gather(*tasks, return_exceptions=True)
    
    # ----------------------------------------------------------
    # 2.4 混合执行（默认模式）
    # ----------------------------------------------------------
    
    async def _execute_hybrid(
        self,
        subtasks: List[SubTask],
        task_map: Dict[str, SubTask],
        context: Optional[Dict[str, Any]],
    ):
        """
        混合执行：
        - 按依赖关系分层，层间串行
        - 层内并行执行
        """
        sorted_tasks = self._topological_sort(subtasks, task_map)
        levels = self._group_by_level(sorted_tasks, task_map)
        
        for level_idx, level in enumerate(levels):
            logger.info(
                f"执行第 {level_idx + 1}/{len(levels)} 层，"
                f"{len(level)} 个子任务"
            )
            
            executable = []
            for task in level:
                if self._check_dependencies_success(task, task_map):
                    executable.append(task)
                else:
                    task.status = SubTaskStatus.SKIPPED
            
            if not executable:
                continue
            
            # 层内并行
            with self._global_timeout_guard():
                tasks = [
                    self._execute_single_with_retry(task, context)
                    for task in executable
                ]
                await asyncio.gather(*tasks, return_exceptions=True)
    
    def _global_timeout_guard(self):
        """全局超时保护上下文管理器"""
        # 简化实现：实际可用 asyncio.wait_for 包裹外层
        return asyncio.timeout(self.global_timeout)
    
    # ----------------------------------------------------------
    # 2.5 单任务执行（含超时 + 重试）
    # ----------------------------------------------------------
    
    async def _execute_single_with_retry(
        self,
        task: SubTask,
        context: Optional[Dict[str, Any]],
    ):
        """执行单个子任务，含超时和重试机制"""
        while task.retry_count <= task.max_retries:
            task.status = SubTaskStatus.RUNNING
            task.started_at = time.time()
            
            try:
                # 使用 asyncio.wait_for 实现超时
                result = await asyncio.wait_for(
                    self.executor.execute(task),
                    timeout=task.timeout_seconds
                )
                
                task.result = result
                task.status = SubTaskStatus.SUCCESS
                task.finished_at = time.time()
                
                logger.info(
                    f"子任务 {task.id} ({task.name}) 执行成功，"
                    f"耗时 {task.finished_at - task.started_at:.2f}s"
                )
                return
                
            except asyncio.TimeoutError:
                task.retry_count += 1
                elapsed = time.time() - task.started_at
                
                if task.retry_count > task.max_retries:
                    task.status = SubTaskStatus.TIMEOUT
                    task.error = (
                        f"超时（{task.timeout_seconds}s），"
                        f"已重试 {task.max_retries} 次"
                    )
                    logger.warning(
                        f"子任务 {task.id} 超时，已达最大重试次数"
                    )
                else:
                    task.status = SubTaskStatus.RETRYING
                    logger.info(
                        f"子任务 {task.id} 超时，"
                        f"第 {task.retry_count} 次重试..."
                    )
                    await asyncio.sleep(task.retry_delay)
                
            except Exception as e:
                task.retry_count += 1
                
                if task.retry_count > task.max_retries:
                    task.status = SubTaskStatus.FAILED
                    task.error = f"执行异常: {str(e)}"
                    task.finished_at = time.time()
                    logger.error(
                        f"子任务 {task.id} 失败: {str(e)}"
                    )
                else:
                    task.status = SubTaskStatus.RETRYING
                    logger.info(
                        f"子任务 {task.id} 失败 ({str(e)})，"
                        f"第 {task.retry_count} 次重试..."
                    )
                    await asyncio.sleep(task.retry_delay)
    
    # ----------------------------------------------------------
    # 2.6 结果聚合
    # ----------------------------------------------------------
    
    def _build_result(
        self,
        task_map: Dict[str, SubTask],
        start_time: float,
    ) -> TaskResult:
        """构建最终结果"""
        total_time = time.time() - start_time
        
        successful = {}
        failed = []
        timed_out = []
        
        for task_id, task in task_map.items():
            if task.status == SubTaskStatus.SUCCESS:
                successful[task_id] = task.result
            elif task.status in (SubTaskStatus.FAILED, SubTaskStatus.SKIPPED):
                failed.append(task_id)
            elif task.status == SubTaskStatus.TIMEOUT:
                timed_out.append(task_id)
        
        overall_success = len(failed) == 0 and len(timed_out) == 0
        
        if not overall_success:
            if self.partial_ok:
                logger.warning(
                    f"部分成功: {len(successful)} 成功, "
                    f"{len(failed)} 失败, {len(timed_out)} 超时"
                )
            else:
                logger.error(
                    f"整体失败: {len(successful)} 成功, "
                    f"{len(failed)} 失败, {len(timed_out)} 超时"
                )
        
        return TaskResult(
            success=overall_success,
            main_result=self._aggregate_results(successful, task_map),
            sub_results=successful,
            failed_tasks=failed,
            timed_out_tasks=timed_out,
            total_time=total_time,
            partial=not overall_success if self.partial_ok else False,
        )
    
    def _build_partial_result(
        self,
        task_map: Dict[str, SubTask],
        start_time: float,
        cancelled: bool = False,
    ) -> TaskResult:
        """构建中断后的部分结果"""
        total_time = time.time() - start_time
        successful = {
            tid: t.result
            for tid, t in task_map.items()
            if t.status == SubTaskStatus.SUCCESS
        }
        
        return TaskResult(
            success=False,
            main_result=None,
            sub_results=successful,
            failed_tasks=[
                tid for tid, t in task_map.items()
                if t.status in (SubTaskStatus.FAILED, SubTaskStatus.SKIPPED)
            ],
            timed_out_tasks=[
                tid for tid, t in task_map.items()
                if t.status == SubTaskStatus.TIMEOUT
            ],
            total_time=total_time,
            partial=True,
        )
    
    def _aggregate_results(
        self,
        successful: Dict[str, Any],
        task_map: Dict[str, SubTask],
    ) -> Any:
        """
        聚合成功子任务的结果。
        子类可重写此方法实现自定义聚合逻辑。
        """
        # 默认行为：按任务 ID 排序后合并为字典
        return {
            task_map[tid].name: result
            for tid, result in successful.items()
        }
    
    # ----------------------------------------------------------
    # 2.7 工具方法
    # ----------------------------------------------------------
    
    def _check_dependencies_success(
        self,
        task: SubTask,
        task_map: Dict[str, SubTask],
    ) -> bool:
        """检查任务的所有依赖是否已成功完成"""
        for dep_id in task.dependencies:
            dep_task = task_map.get(dep_id)
            if dep_task and dep_task.status != SubTaskStatus.SUCCESS:
                return False
        return True
    
    def _topological_sort(
        self,
        subtasks: List[SubTask],
        task_map: Dict[str, SubTask],
    ) -> List[SubTask]:
        """拓扑排序（Kahn 算法）"""
        in_degree = {task.id: len(task.dependencies) for task in subtasks}
        queue = [
            task for task in subtasks
            if in_degree[task.id] == 0
        ]
        sorted_tasks = []
        
        while queue:
            task = queue.pop(0)
            sorted_tasks.append(task)
            
            # 寻找以此任务为依赖的其他任务
            for other in subtasks:
                if task.id in other.dependencies:
                    in_degree[other.id] -= 1
                    if in_degree[other.id] == 0:
                        queue.append(other)
        
        if len(sorted_tasks) != len(subtasks):
            raise ValueError("存在循环依赖，无法拓扑排序")
        
        return sorted_tasks
    
    def _group_by_level(
        self,
        sorted_tasks: List[SubTask],
        task_map: Dict[str, SubTask],
    ) -> List[List[SubTask]]:
        """按依赖层级分组"""
        level_map: Dict[int, List[SubTask]] = {}
        
        for task in sorted_tasks:
            if not task.dependencies:
                level_map.setdefault(0, []).append(task)
            else:
                max_dep_level = max(
                    level_map.get(dep_id, [-1])[0]  # 简化处理
                    if False else 0
                    for dep_id in task.dependencies
                )
                # 实际应计算依赖的最大层级
                level = self._compute_level(task, task_map, {})
                level_map.setdefault(level, []).append(task)
        
        return [
            level_map[i]
            for i in range(len(level_map))
        ]
    
    def _compute_level(
        self,
        task: SubTask,
        task_map: Dict[str, SubTask],
        memo: Dict[str, int],
    ) -> int:
        """计算任务的层级（依赖链最长路径）"""
        if task.id in memo:
            return memo[task.id]
        
        if not task.dependencies:
            memo[task.id] = 0
            return 0
        
        max_dep_level = max(
            self._compute_level(task_map[dep_id], task_map, memo)
            for dep_id in task.dependencies
        )
        memo[task.id] = max_dep_level + 1
        return memo[task.id]
```

## 三、超时处理策略

### 3.1 超时策略矩阵

Coordinator 支持四种超时处理策略，可以在 SubTask 级别配置：

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| **abort** | 超时后立即终止该子任务 | 强一致性要求的任务 |
| **skip** | 超时后跳过，继续执行其他任务 | 非关键路径上的可选任务 |
| **retry** | 超时后重试 N 次（指数退避） | 偶发延迟的任务（API 调用） |
| **fallback** | 超时后使用预设默认值/缓存结果 | 推荐结果、缓存数据查询 |

```python
# 超时策略配置示例
subtask = SubTask(
    id="query_revenue",
    name="查询营收数据",
    timeout_seconds=10.0,
    max_retries=2,
    retry_delay=2.0,
    # 自定义超时后的降级行为
)
```

### 3.2 超时传播（Timeout Propagation）

当依赖链上的某个子任务超时时，Coordinator 需要决定如何处理下游依赖：

```
场景：Task C 依赖 Task B，Task B 超时

策略 A：立即跳过所有下游（激进）
Task B (TIMEOUT) → Task C (SKIPPED) → Task D (SKIPPED)
优点：快速失败，不浪费资源
缺点：丢失可能的部分结果

策略 B：允许下游继续（保守）
Task B (TIMEOUT) → Task C (RUNNING with warning) 
优点：下游可能不需要 B 的结果，或能处理缺失
缺点：下游可能基于不完整数据产生错误结论

策略 C：带结果的超时（推荐）
Task B (TIMEOUT with partial_result) → Task C (RUNNING with partial)
优点：充分利用已完成的部分工作
缺点：实现复杂，需要下游理解"部分结果"语义
```

推荐策略 C 的实现方式：

```python
async def _execute_with_partial_timeout(
    self, task: SubTask, context: dict
) -> Any:
    """
    执行任务并在超时时返回已完成的中间结果
    """
    try:
        return await asyncio.wait_for(
            self.executor.execute(task),
            timeout=task.timeout_seconds
        )
    except asyncio.TimeoutError:
        # 获取已完成的部分结果
        partial = task.progress.get_partial_result()
        logger.info(f"任务 {task.id} 超时，返回部分结果")
        return {
            "_partial": True,
            "_completed_before_timeout": partial
        }
```

## 四、部分失败恢复策略

### 4.1 三级恢复策略

```
                       ┌───────────────────────┐
                       │    检测到子任务失败     │
                       └───────────┬───────────┘
                                   │
```

### 4.2 降级函数注册机制

```python
class DegradationRegistry:
    """
    降级策略注册表：为关键子任务注册备选方案
    """
    
    def __init__(self):
        self._fallbacks: Dict[str, Callable] = {}
        self._default_values: Dict[str, Any] = {}
        self._cache: Dict[str, Any] = {}
    
    def register_fallback(
        self,
        task_name: str,
        fallback_fn: Callable[[], Any]
    ):
        """注册降级函数"""
        self._fallbacks[task_name] = fallback_fn
    
    def register_default(
        self,
        task_name: str,
        default_value: Any
    ):
        """注册默认值"""
        self._default_values[task_name] = default_value
    
    def degrade(self, task_name: str) -> Any:
        """执行降级策略"""
        # 优先使用降级函数
        if task_name in self._fallbacks:
            try:
                return self._fallbacks[task_name]()
            except Exception as e:
                logger.warning(
                    f"降级函数执行失败: {e}"
                )
        
        # 其次使用默认值
        if task_name in self._default_values:
            return self._default_values[task_name]
        
        # 最后使用缓存
        if task_name in self._cache:
            return self._cache[task_name]
        
        return None


# 使用示例
degradation = DegradationRegistry()

# 为 "查询营收" 任务注册降级
degradation.register_fallback(
    "query_revenue",
    lambda: query_from_cache("revenue_2026Q1")  # 从缓存获取
)
degradation.register_default(
    "query_revenue",
    {"revenue": None, "note": "数据不可用"}     # 默认空值
)
```

### 4.3 补偿事务（Compensating Transaction）

对于已经有副作用的失败子任务，需要执行补偿操作：

```python
class CompensationManager:
    """
    补偿事务管理器
    
    在子任务失败时，执行补偿操作来撤销已产生的副作用。
    类似于 Saga 模式中的补偿事务。
    """
    
    def __init__(self):
        self._compensations: Dict[str, List[Callable]] = {}
    
    def register_compensation(
        self,
        task_id: str,
        compensate_fn: Callable[[], Any]
    ):
        """为任务注册补偿操作"""
        if task_id not in self._compensations:
            self._compensations[task_id] = []
        self._compensations[task_id].append(compensate_fn)
    
    async def compensate(self, task_id: str, task_name: str):
        """执行补偿操作"""
        compensations = self._compensations.get(task_id, [])
        
        if not compensations:
            logger.warning(
                f"任务 {task_id}({task_name}) 无注册的补偿操作"
            )
            return
        
        logger.info(f"执行任务 {task_id} 的补偿操作...")
        
        for comp_fn in reversed(compensations):  # 逆序执行
            try:
                await comp_fn()
            except Exception as e:
                logger.error(f"补偿操作失败: {e}")
                # 补偿失败需要人工介入
                self._report_compensation_failure(task_id, e)
```

## 五、Coordinator 的工程实践

### 5.1 可观测性

Coordinator 是 Multi-Agent 系统的"神经系统"，必须有完善的监控：

```python
class ObservableCoordinator(Coordinator):
    """带可观测性的 Coordinator"""
    
    async def _execute_single_with_retry(self, task, context):
        # 上报开始指标
        metrics.start_task(task.id, task.name)
        
        try:
            result = await super()._execute_single_with_retry(task, context)
            # 上报成功指标
            metrics.end_task(task.id, status="success")
            return result
        except Exception as e:
            # 上报失败指标
            metrics.end_task(task.id, status="failed", error=str(e))
            raise
```

**关键指标**：
| 指标 | 说明 | 告警阈值 |
|------|------|---------|
| task_success_rate | 子任务成功率 | < 90% |
| avg_task_latency | 子任务平均耗时 | > 5s |
| timeout_rate | 超时率 | > 5% |
| retry_rate | 重试率 | > 10% |
| coordination_overhead | 协调耗时占比 | > 30% |

### 5.2 反模式：Coordinator 变成瓶颈

```
❌ 反模式：所有子 Agent 都通过 Coordinator 串行通信
SubAgent A → Coordinator → SubAgent B → Coordinator → SubAgent C

✅ 正确模式：Coordinator 只负责任务分发和结果聚合
SubAgent A → SubAgent B（直接通信）
Coordinator 仅在开始（分发）和结束（聚合）时介入
```

避免 Coordinator 成为瓶颈的关键原则：
1. **尽量减少 Coordinator 在数据路径中的参与**：只在任务分派和结果聚合时介入
2. **使用异步非阻塞模型**：asyncio 是 Python 生态的最佳选择
3. **状态外部化**：Coordinator 不应持有大量运行时状态，状态应存储在 Redis/数据库
4. **Coordinator 支持水平扩展**：无状态设计，通过消息队列分发任务

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Coordinator（协调器） | Multi-Agent 系统的中央调度节点 |
| 拓扑排序 | 根据依赖关系确定子任务执行顺序的算法 |
| 超时传播 | 依赖链上的超时如何影响下游子任务 |
| 降级策略（Degradation） | 子任务失败时使用缓存、默认值或备用 API |
| 补偿事务（Compensating Transaction） | 撤销已失败子任务的副作用（Saga 模式） |
| 部分成功（Partial Success） | 部分子任务成功时仍返回有意义的结果 |
| 指数退避（Exponential Backoff） | 重试间隔逐次加倍，避免重试风暴 |
