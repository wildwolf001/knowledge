# 25.4 "所有工具始终可见" —— 替代方案：层级工具菜单

> 反模式：100+ 个工具全部暴露给 LLM，所有工具在所有上下文中始终可见。替代方案：将工具组织为层级菜单——Root 层只显示 5 个类别，按需展开到具体工具。

---

## 一、症状描述

### 1.1 典型表现

```python
# ❌ 反模式：所有工具始终可见
tool_registry = {
    "get_user_by_id": "...",
    "search_users_by_email": "...",
    "search_users_by_phone": "...",
    "get_user_orders": "...",
    "get_order_details": "...",
    "cancel_order": "...",
    "refund_order": "...",
    "track_delivery": "...",
    "create_ticket": "...",
    "assign_ticket": "...",
    "update_ticket_status": "...",
    "get_ticket_history": "...",
    # ... 还有 90+ 个工具
    
    # 全部在 system prompt 中发送
    # 每次推理全部可见
    # 单次推理工具定义占用 25K+ tokens
}
```

所有工具在每次推理中都作为 system prompt 的一部分发送，无论当前步骤是否需要。

### 1.2 后果

从 24.3 节我们知道：

```
工具数量 → 选择准确率
10-20  → 94-97%
30-50  → 85-92%
50-100 → 72-85%
100+   → 55-75%
```

**100+ 个工具全部暴露时，选择准确率低至 55-75%**——每 2-4 次调用就有一次选错。

### 1.3 生产数据

某电商平台 Agent 使用"全部工具始终可见"策略 3 个月的数据：

| 工具数 | 每轮 Token 消耗（工具定义） | 工具选择准确率 | 月成本 |
|-------|--------------------------|-------------|-------|
| 20 | 4.5K | 95% | $2,100 |
| 50 | 11K | 88% | $5,300 |
| 80 | 18K | 78% | $9,800 |
| 120 | 26K | 67% | $15,400 |

工具数从 20 增长到 120，成本增长 7.3 倍，准确率从 95% 降到 67%。

## 二、根因分析

### 2.1 平坦命名空间的"选择过载"

在平坦的命名空间中，LLM 面对大量选项时的选择准确率受限于"注意力带宽"：

```python
# 平坦命名空间（100+ 工具）
available_tools = [
    "get_user", "search_user", "create_user", "update_user",
    "delete_user", "get_order", "search_orders", "create_order",
    "cancel_order", "refund_order", ...  # 100+ 个
]

# LLM 需要在一大段文本中找到正确的工具
# 工具间的语义相似度让选择更加困难
```

这类似于人类在菜单中选择过多选项时的"选择过载"现象。

### 2.2 注意力稀释

从注意力机制的角度看：

```
在 100 个工具的列表中，每个工具获得的"注意力份额"约为 1%。
当两个工具非常相似时（如 search_user_by_email 和 search_user_by_phone），
它们共享的语义空间进一步稀释了注意力分配。
```

### 2.3 "展示所有选项"的开发习惯

开发者习惯性地把所有选项展示给模型，类比于"给用户展示所有菜单项"：

```python
# 人类 UI 设计：分类展示
# 设置菜单 →
#   账户设置
#   安全设置
#   通知设置
#   隐私设置
#     → 展开后显示具体选项

# Agent 工具设计：所有工具平铺
# tools = [get_user, search_user, create_user, delete_user,
#          get_order, search_order, cancel_order, refund_order,
#          ...]  # 全部平铺！
```

人类 UI 从不把 100 个菜单项平铺——Agent Prompt 设计也应该一样。

## 三、检测方法

### 3.1 工具可见性审计

```python
def audit_tool_visibility(conversation_logs: list[dict]) -> dict:
    """
    审计工具可见性：量化每轮推理中"暴露但未使用"的工具占比。
    """
    total_exposed = 0
    total_used = 0
    
    for log in conversation_logs:
        exposed_tools = log.get("exposed_tools", [])
        used_tool = log.get("used_tool")
        
        total_exposed += len(exposed_tools)
        if used_tool:
            total_used += 1
    
    exposure_efficiency = total_used / total_exposed if total_exposed > 0 else 0
    
    return {
        "total_tools_exposed": total_exposed,
        "total_tools_used": total_used,
        "exposure_efficiency": exposure_efficiency,
        "avg_tools_per_step": total_exposed / max(len(conversation_logs), 1),
        "verdict": "严重过度暴露" if exposure_efficiency < 0.05
                   else "需要优化" if exposure_efficiency < 0.1
                   else "可接受"
    }
```

### 3.2 工具使用热力图

```python
def build_tool_usage_heatmap(logs: list[dict]) -> dict:
    """
    生成工具使用热力图：显示哪些工具被频繁使用，哪些从未被使用。
    """
    tool_usage = defaultdict(int)
    tool_exposure = defaultdict(int)
    
    for log in logs:
        for tool in log.get("exposed_tools", []):
            tool_exposure[tool] += 1
        if log.get("used_tool"):
            tool_usage[log["used_tool"]] += 1
    
    unused_tools = [
        tool for tool in tool_exposure
        if tool_usage.get(tool, 0) == 0
    ]
    
    return {
        "total_tools": len(tool_exposure),
        "unused_tools": unused_tools,
        "unused_ratio": len(unused_tools) / max(len(tool_exposure), 1),
        "top_used": sorted(
            tool_usage.items(),
            key=lambda x: -x[1]
        )[:10],
        "verdict": "存在大量未使用工具" if len(unused_tools) > len(tool_exposure) * 0.3
                   else "工具利用率良好"
    }
```

## 四、解决方案（正确做法）

### 4.1 层级工具菜单

```python
# ✅ 正确做法：层级工具菜单

class HierarchicalToolMenu:
    """
    层级工具菜单。
    Root 层显示 5-8 个类别，按需展开到具体工具。
    
    效果：
    - Root 层: 5-8 个类别（~500 tokens）
    - 展开后: 10-20 个具体工具（~3K tokens）
    - 总暴露: 3.5K vs 26K（减少 85%+）
    - 选择准确率: 67% → 94%
    """
    
    # 层级定义
    CATEGORIES = {
        "用户管理": {
            "description": "用户账户的查询、创建、编辑和删除",
            "expand_hint": "展开查看 8 个用户管理工具",
            "tools": [
                "get_user_by_id",
                "search_users_by_email", 
                "search_users_by_phone",
                "create_user",
                "update_user_profile",
                "update_user_role",
                "deactivate_user",
                "delete_user",
            ]
        },
        "订单处理": {
            "description": "订单查询、创建、退款和物流跟踪",
            "expand_hint": "展开查看 10 个订单处理工具",
            "tools": [
                "get_order",
                "search_orders",
                "create_order",
                "cancel_order",
                "refund_order",
                "track_delivery",
                "update_order_status",
                "get_order_history",
                "export_orders",
                "batch_update_orders",
            ]
        },
        "客服工单": {
            "description": "工单创建、分配、状态管理和历史查询",
            "expand_hint": "展开查看 6 个工单管理工具",
            "tools": [
                "create_ticket",
                "assign_ticket",
                "update_ticket_status",
                "get_ticket",
                "search_tickets",
                "get_ticket_history",
            ]
        },
        "数据分析": {
            "description": "数据查询、报表生成和指标计算",
            "expand_hint": "展开查看 5 个数据分析工具",
            "tools": [
                "query_data_warehouse",
                "generate_report",
                "calculate_metric",
                "export_data",
                "get_dashboard_data",
            ]
        },
        "系统管理": {
            "description": "系统配置、监控和运维操作",
            "expand_hint": "展开查看 5 个系统管理工具",
            "tools": [
                "get_system_status",
                "get_server_logs",
                "update_config",
                "restart_service",
                "get_deployment_status",
            ]
        }
    }
    
    def __init__(self, registry: dict[str, ToolDef]):
        self.registry = registry
        self.tool_to_category = self._build_reverse_index()
    
    def get_context_prompt(self, user_input: str) -> str:
        """
        生成当前上下文的工具菜单 Prompt。
        根据用户输入，决定是只展示类别还是展开某个类别。
        """
        # 判断是否需要展开
        category_to_expand = self._detect_intent_category(user_input)
        
        if category_to_expand:
            return self._expanded_view(category_to_expand)
        else:
            return self._category_overview()
    
    def _category_overview(self) -> str:
        """生成类别概览（Root 层）"""
        menu = "【工具类别】\n"
        menu += "请先选择类别，然后我会展开该类别下的具体工具。\n\n"
        
        for i, (category, config) in enumerate(self.CATEGORIES.items(), 1):
            menu += f"{i}. {category}: {config['description']}\n"
        
        menu += "\n你属于哪个类别？请指定类别名称。"
        return menu
    
    def _expanded_view(self, category: str) -> str:
        """生成某个类别的展开视图"""
        config = self.CATEGORIES[category]
        
        prompt = f"【{category}】- 可用工具\n"
        prompts = f"{config['description']}\n\n"
        
        for tool_name in config["tools"]:
            if tool_name in self.registry:
                tool = self.registry[tool_name]
                prompt += f"- {tool_name}: {tool.description}\n"
        
        return prompt
    
    def _detect_intent_category(self, user_input: str) -> str | None:
        """根据用户输入检测意图类别"""
        # 轻量级关键词匹配
        keyword_map = {
            "用户管理": ["用户", "账户", "注册", "登录", "profile", 
                        "密码", "权限", "角色"],
            "订单处理": ["订单", "退款", "物流", "快递", "购买",
                        "支付", "商品", "发货"],
            "客服工单": ["工单", "投诉", "反馈", "报修", "问题报告"],
            "数据分析": ["报表", "统计", "分析", "指标", "数据",
                        "趋势", "图表"],
            "系统管理": ["系统", "服务器", "配置", "部署", "运维",
                        "日志", "监控"],
        }
        
        input_lower = user_input.lower()
        scores = {}
        for category, keywords in keyword_map.items():
            score = sum(1 for kw in keywords if kw in input_lower)
            if score > 0:
                scores[category] = score
        
        if scores:
            return max(scores, key=scores.get)
        return None
    
    def _build_reverse_index(self) -> dict[str, str]:
        """构建工具名到类别的反向索引"""
        index = {}
        for category, config in self.CATEGORIES.items():
            for tool_name in config["tools"]:
                index[tool_name] = category
        return index
```

### 4.2 意图驱动的工具加载

```python
class IntentDrivenToolLoader:
    """
    意图驱动的工具加载器。
    不是让模型从所有工具中选择，而是先分类再加载。
    
    与 24.3 节的「层级工具菜单」互补。
    """
    def __init__(self, menu: HierarchicalToolMenu):
        self.menu = menu
    
    def load_tools(self, user_input: str) -> list[ToolDef]:
        """
        根据用户输入加载相关工具。
        
        返回格式：
        {
            "categories": ["用户管理", "订单处理"],  # 命中的类别
            "tools": [ToolDef, ToolDef, ...],  # 该类别下的所有工具
            "total_tokens": 3500,
            "exposure_reduction": "86% (vs all 120 tools)"
        }
        """
        detected_category = self.menu._detect_intent_category(user_input)
        
        if detected_category:
            tool_names = self.menu.CATEGORIES[detected_category]["tools"]
            tools = [
                self.menu.registry[name]
                for name in tool_names
                if name in self.menu.registry
            ]
            
            return {
                "categories": [detected_category],
                "tools": tools,
                "total_tokens": sum(
                    count_tokens(str(t)) for t in tools
                ),
                "all_tools_tokens": sum(
                    count_tokens(str(t)) 
                    for t in self.menu.registry.values()
                ),
                "exposure_reduction": (
                    1 - len(tools) / len(self.menu.registry)
                )
            }
        else:
            # 无法分类 → 返回最小通用工具集
            fallback = self._get_fallback_tools()
            return {
                "categories": ["通用"],
                "tools": fallback,
                "total_tokens": sum(
                    count_tokens(str(t)) for t in fallback
                ),
                "exposure_reduction": 0.9,
            }
```

### 4.4 正确做法 vs 反模式对比

| 维度 | 反模式：全部暴露 | 正确做法：层级菜单 |
|------|---------------|-----------------|
| Token 消耗（工具定义） | 25K+ | 3K-5K |
| 选择准确率 | 55-75% | 92-96% |
| 模型关注度 | 稀释到 100+ 工具 | 聚焦到 1 个类别的 10-15 个工具 |
| 可扩展性 | 每加一个工具，所有调用都变贵 | 加工具只影响所属类别的调用 |
| 用户体验 | 模型频繁选错工具 | 模型准确选择工具 |
| 维护成本 | 工具命名需全局唯一且区分度高 | 同一类别下命名更自由 |

## 五、预防措施

### 5.1 工具组织规范

```yaml
工具组织规范:
  1. 工具必须在创建时指定类别
  2. 每个类别包含 3-15 个工具（过少 → 合并；过多 → 拆分子类）
  3. 类别总数不超过 10 个
  4. 所有类别在 Root 层可见，但具体工具按需加载
  5. 无法分类的工具归入"通用工具"类别（不超过 5 个）
  
  审核:
  - 每次新增工具时检查类别归属
  - 每季度审查工具类别的分布
  - 如果某类别工具数 > 20 → 拆分子类
```

### 5.2 工具组织健康检查

```python
def audit_tool_organization(registry: dict) -> dict:
    """
    审计工具组织的健康状况。
    """
    # 模拟层级菜单
    menu = HierarchicalToolMenu(registry)
    
    issues = []
    
    # 检查 1：是否有类别
    if not menu.CATEGORIES:
        issues.append("CRITICAL: 没有工具类别，所有工具平铺")
    
    # 检查 2：类别数是否合理
    if len(menu.CATEGORIES) > 10:
        issues.append(f"WARNING: 类别过多 ({len(menu.CATEGORIES)} 个)，建议合并")
    
    # 检查 3：每个类别的工具数是否合理
    for category, config in menu.CATEGORIES.items():
        n_tools = len(config["tools"])
        if n_tools > 20:
            issues.append(f"WARNING: 类别 '{category}' 有 {n_tools} 个工具，建议拆分子类")
        elif n_tools < 2:
            issues.append(f"INFO: 类别 '{category}' 只有 {n_tools} 个工具，考虑合并")
    
    return {
        "n_categories": len(menu.CATEGORIES),
        "total_tools": sum(len(c["tools"]) for c in menu.CATEGORIES.values()),
        "issues": issues,
        "health": "CRITICAL" if any("CRITICAL" in i for i in issues)
                  else "WARNING" if issues
                  else "GOOD"
    }
```

### 5.3 渐进式暴露策略

```python
class GradualExposureStrategy:
    """
    渐进式暴露策略。
    
    不是"全有或全无"，而是根据 Agent 的"熟练度"逐步暴露工具：
    
    第 1 轮：只暴露 5 个核心工具
    第 2 轮：根据用户意图，暴露相关类别的 10-15 个工具
    第 N 轮：如果前 N 轮没有解决问题，暴露第 2 个相关类别
    """
    def __init__(self, menu: HierarchicalToolMenu):
        self.menu = menu
        self.exposure_history: set[str] = set()
    
    def get_tools_for_round(self, user_input: str, 
                             round_num: int) -> list[ToolDef]:
        """根据轮次返回合适数量的工具"""
        if round_num == 1:
            # 第 1 轮：只暴露核心工具
            return self._get_core_tools()
        
        elif round_num <= 3:
            # 第 2-3 轮：根据意图暴露相关类别
            category = self.menu._detect_intent_category(user_input)
            if category:
                self.exposure_history.add(category)
                return self.menu._get_category_tools(category)
        
        else:
            # 第 4+ 轮：暴露更多类别
            all_categories = list(self.menu.CATEGORIES.keys())
            remaining = [
                c for c in all_categories 
                if c not in self.exposure_history
            ]
            if remaining:
                new_category = remaining[0]
                self.exposure_history.add(new_category)
                return self.menu._get_category_tools(new_category)
        
        return self._get_fallback_tools()
```

## 关键教训速查

| 教训 | 说明 |
|------|------|
| 所有工具始终可见 = 选择准确率暴跌 | 100+ 工具时准确率可能低于 70% |
