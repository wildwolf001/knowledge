# 25.5 "不区分压缩和摘要" —— 可逆压缩 vs 不可逆摘要

> 反模式：开发者将"压缩"和"摘要"混为一谈，在需要精确恢复的场景使用了不可逆摘要导致了信息永久丢失，或者在只需要粗略概括的场景浪费算力做了可逆压缩。

---

## 一、症状描述

### 1.1 混淆的后果

**场景 A：用摘要代替压缩（信息永久丢失）**

某金融 Agent 需要对历史对话做"压缩"以节省 Token。开发者使用了 LLM 摘要：

```python
# ❌ 错误的做法：用摘要（不可逆）代替压缩（可逆）
def compress_conversation(history: list[dict]) -> str:
    summary_prompt = f"请摘要以下对话：\n{history}"
    summary = llm.generate(summary_prompt)
    return summary
    # 问题：原始信息丢失！包含精确数字、日期、ID 的对话
    # 被压缩为大意——无法恢复精确事实
```

后果：

```
原始对话中包含：
"订单 ORD-2025-001 已退款 $299.00，退款单号 RF-2025-00421"

摘要后：
"用户的一个订单已经退款了"

3 天后，用户问"我的退款单号是多少？"
Agent 无法回答——信息已经在摘要中永久丢失了。
```

**场景 B：用压缩代替摘要（算力浪费）**

另一个极端——开发者对所有上下文都使用可逆压缩：

```python
# ❌ 不必要的可逆压缩
def process_context(context: str) -> bytes:
    return zlib.compress(context.encode())  
    # 对于不需要精确恢复的场景（如历史对话大意）
    # 浪费了 LLM 摘要的"理解"能力
```

**可逆压缩只能节省存储空间，不能节省 LLM 的 Token 消耗**——因为当数据被读取时，需要先解压缩回到原始文本，再送入 LLM。而摘要则直接节省了 Token。

### 1.2 根本性的区别

```python
# 压缩（Compression）：可逆的，信息可完全恢复
原始数据 → 压缩 → 压缩数据 → 解压 → 原始数据（完全一致）
                     ↑
              信息零损失

# 摘要（Summarization）：不可逆的，信息永久丢失
原始数据 → 摘要 → 摘要文本 → ❌ 无法恢复原始数据
                     ↑
              信息不可逆丢失

# 区别的本质：
# 压缩：改变数据的"表示方式"，不改变"内容"
# 摘要：改变数据的"内容"，只保留"要点"
```

### 1.3 对 Agent 的影响

| 场景 | 需要可逆压缩 | 需要不可逆摘要 |
|------|------------|--------------|
| 工具执行结果 | 需要保留精确参数和返回值 | 不需要摘要（消费后清除） |
| 对话历史 | 最近 N 轮保留完整，之前的历史可摘要 | > N 轮前可做摘要 |
| 用户提供的精确信息（订单号、日期） | 必须保留原始值 | 绝不能摘要！ |
| 检索文档 | 关键段落保留原文 | 非关键部分可摘要 |
| API 响应 | 需要保留精确的结构化数据 | 不需要摘要 |

## 二、根因分析

### 2.1 概念混淆

开发者常用的认知：

```
开发者认知：
"压缩 = 让内容变小 = 摘要"

正确认知：
"压缩" = 无损/可逆，"摘要" = 有损/不可逆
"压缩" + "摘要" = 让上下文变小的两大类方法
```

这是整个行业普遍存在的概念混淆。很多框架文档中"context compression"这个词同时指代了无损压缩和有损摘要。

### 2.2 对"不可逆性"的风险认知不足

摘要的风险在于**不可逆性**——一旦摘要生成，原始信息就永久丢失了：

```
摘要的风险梯度：

低风险摘要：
- 闲聊内容（"今天天气不错"）
- 一般性讨论（"我觉得这个方案可行"）
- 已确认的操作结果（"订单已创建"）

中度风险摘要：
- 部分精确信息的对话（包含一些数字但非关键）
- 工具调用的中间结果

高风险摘要（绝不应该摘要）：
- 用户提供的订单号、身份证号、地址
- 交易金额和交易状态
- API 返回的结构化数据
- 系统配置参数
- 任何用于后续决策的事实依据
```

### 2.3 工程实践中的"一刀切"思维

团队为了实现简单，对所有上下文类型使用同样的处理策略：

```python
# ❌ 一刀切策略
def manage_context(context):
    if len(context) > LIMIT:
        return summarize(context)  # 全部摘要！
    return context

# ✅ 差异化策略
def manage_context(context):
    for section in context.sections:
        if section.type == "precise_data":
            section.compress()  # 可逆压缩
        elif section.type == "conversation_history":
            section.summarize()  # 不可逆摘要
        elif section.type == "tool_result":
            section.clear()  # 直接清除（已消费）
```

## 三、检测方法

### 3.1 信息完整性检测

```python
def test_information_preservation(original: str, 
                                   processed: str) -> dict:
    """
    检测处理后文本中的关键信息是否完整保留。
    """
    # 提取原始文本中的关键信息
    key_patterns = {
        "order_id": r"ORD-\d{3,}",
        "refund_id": r"RF-\d{3,}",
        "amount": r"\$\d+\.\d{2}",
        "date": r"\d{4}-\d{2}-\d{2}",
        "email": r"\S+@\S+\.\S+",
        "phone": r"1[3-9]\d{9}",
    }
    
    preservation = {}
    for key, pattern in key_patterns.items():
        original_matches = set(re.findall(pattern, original))
        processed_matches = set(re.findall(pattern, processed))
        
        if original_matches:
            preserved = len(original_matches & processed_matches)
            preservation[key] = {
                "original_count": len(original_matches),
                "preserved_count": preserved,
                "preserved": preserved / len(original_matches)
            }
    
    overall = sum(
        v["preserved"] for v in preservation.values()
    ) / max(len(preservation), 1)
    
    return {
        "overall_preservation": overall,
        "details": preservation,
        "verdict": "信息丢失" if overall < 0.95
                   else "信息完整"
    }
```

### 3.2 压缩比 vs 信息损失的权衡分析

```python
def analyze_compression_tradeoff(original: str, 
                                  compressed: str) -> dict:
    """
    分析压缩效果和信息损失的权衡。
    """
    original_tokens = count_tokens(original)
    compressed_tokens = count_tokens(compressed)
    compression_ratio = compressed_tokens / original_tokens if original_tokens > 0 else 1
    
    # 语义相似度（信息保留程度）
    semantic_similarity = cosine_similarity(
        embed(original), 
        embed(compressed)
    )
    
    # 精确信息保留
    info_preservation = test_information_preservation(
        original, compressed
    )
    
    return {
        "compression_ratio": compression_ratio,
        "tokens_saved": original_tokens - compressed_tokens,
        "semantic_similarity": semantic_similarity,
        "info_preservation": info_preservation["overall_preservation"],
        "is_summarization": info_preservation["overall_preservation"] < 0.95,
        "efficiency_score": (1 - compression_ratio) * semantic_similarity
    }
```

## 四、解决方案（正确做法）

### 4.1 分层压缩策略

```python
# ✅ 正确做法：根据内容类型选择压缩或摘要

class IntelligentContextManager:
    """
    智能上下文管理器。
    根据内容类型和后续使用需求，选择压缩或摘要。
    """
    
    # 内容类型配置
    CONTENT_TYPES = {
        "precise_data": {
            # 精确数据（订单号、金额、配置参数等）
            # → 必须可逆压缩或保留原始
            "strategy": "compress_or_keep",
            "max_age_steps": None,  # 永不自动过期
        },
        "tool_result_consumed": {
            # 已消费的工具结果
            # → 直接清除（零成本）
            "strategy": "remove",
            "max_age_steps": 0,
        },
        "conversation_history_recent": {
            # 最近的对话历史
            # → 保留原始（最近 N 轮）
            "strategy": "keep_original",
            "max_age_steps": 5,  # 保留最近 5 轮
        },
        "conversation_history_old": {
            # 较早的对话历史
            # → LLM 摘要
            "strategy": "summarize",
            "max_age_steps": None,
        },
        "retrieved_docs_key": {
            # 检索文档的关键段落
            # → 可逆压缩（保留精确引用）
            "strategy": "compress",
            "max_age_steps": 10,
        },
        "retrieved_docs_nonkey": {
            # 检索文档的非关键段落
            # → 摘要或移除
            "strategy": "summarize_or_remove",
            "max_age_steps": 5,
        },
        "intermediate_reasoning": {
            # Agent 的中间推理
            # → 清除（已体现在最终决策中）
            "strategy": "remove",
            "max_age_steps": 2,
        },
    }
    
    def process(self, context: Context) -> Context:
        """处理上下文：对每部分应用正确的策略"""
        processed = Context()
        
        for section in context.sections:
            config = self.CONTENT_TYPES.get(section.type, {})
            strategy = config.get("strategy", "keep_original")
            max_age = config.get("max_age_steps")
            
            if max_age is not None and section.age > max_age:
                continue  # 过期，移除
            
            if strategy == "remove":
                continue  # 直接移除
            
            elif strategy == "keep_original":
                processed.add(section)
            
            elif strategy == "compress":
                compressed = self._compress_section(section)
                processed.add(compressed)
            
            elif strategy == "compress_or_keep":
                if section.length > 500:  # 长文本才压缩
                    compressed = self._compress_section(section)
                    processed.add(compressed)
                else:
                    processed.add(section)
            
            elif strategy == "summarize":
                summary = self._summarize_section(section)
                processed.add(summary)
            
            elif strategy == "summarize_or_remove":
                if section.importance > 0.5:
                    summary = self._summarize_section(section)
                    processed.add(summary)
                # 不重要的直接移除
        
        return processed
    
    def _compress_section(self, section: ContextSection) -> ContextSection:
        """
        可逆压缩：压缩后仍可恢复原始内容。
        这里使用"结构化压缩"：
        - 将 JSON 格式化为紧凑形式
        - 移除冗余的空格和注释
        - 使用缩写替代长名称
        """
        content = section.content
        
        if section.content_type == "json":
            # JSON 压缩：移除空格，紧凑格式化
            try:
                parsed = json.loads(content)
                compressed = json.dumps(parsed, separators=(',', ':'))
                section.metadata["compression_ratio"] = len(compressed) / len(content)
                section.content = compressed
            except:
                pass  # 非标准 JSON，保持原样
        
        elif section.content_type == "text":
            # 文本压缩：去空格、统一换行、缩写（可恢复的）
            compressed = ' '.join(content.split())  # 合并连续空白
            section.content = compressed
            section.metadata["compression_ratio"] = len(compressed) / len(content)
        
        return section
    
    def _summarize_section(self, section: ContextSection) -> ContextSection:
        """
        不可逆摘要：用 LLM 将内容压缩为摘要。
        被摘要的内容无法恢复原始信息。
        """
        # 标记来源，以便溯源
        source_id = section.id
        
        summary_prompt = f"""
请对以下内容进行摘要，保留所有关键事实（数字、日期、名称、金额等）。

内容：
{section.content[:3000]}  # 限制输入长度

摘要要求：
- 压缩到原文的 20% 以下
- 保留所有精确数字、日期、名称
- 不添加不在原文中的信息
- 保持客观，不做价值判断
"""
        summary = llm.generate(summary_prompt)
        
        return ContextSection(
            type=f"{section.type}_summary",
            content=summary,
            metadata={
                "source_id": source_id,
                "original_length": len(section.content),
                "summary_length": len(summary),
                "compression_ratio": len(summary) / max(len(section.content), 1),
                "is_summary": True,  # 标记为摘要
                "irreversible": True,  # 标记为不可逆
            }
        )
```

### 4.2 安全摘要：保留精确信息

当必须使用摘要时，确保精确信息被保留：

```python
class SafeSummarizer:
    """
    安全摘要器：在摘要中保留所有精确信息。
    """
    PRECISE_PATTERNS = [
        r'ORD-\d+',        # 订单号
        r'RF-\d+',         # 退款单号
        r'\$\d+\.?\d*',   # 金额
        r'\d{4}-\d{2}-\d{2}', # 日期
        r'[A-Z]{2,10}-\d+',   # 编号类
        r'\b\d{11}\b',        # 手机号
        r'\S+@\S+\.\S+',      # 邮箱
    ]
    
    def summarize_with_preservation(self, text: str) -> str:
        """
        生成摘要，但保留所有精确信息。
        方式：在摘要末尾附加"精确信息附录"。
        """
        # 提取所有精确信息
        precise_info = []
        for pattern in self.PRECISE_PATTERNS:
            matches = re.findall(pattern, text)
            precise_info.extend(matches)
        
        # 生成摘要
        summary = self._llm_summarize(text)
        
        # 在摘要末尾附加精确信息
        if precise_info:
            summary += "\n\n【精确信息】\n"
            for info in sorted(set(precise_info)):
                summary += f"- {info}\n"
        
        return summary
    
    def extract_precise_info(self, text: str) -> list[str]:
        """从文本中提取所有精确信息"""
        info = []
        for pattern in self.PRECISE_PATTERNS:
            info.extend(re.findall(pattern, text))
        return sorted(set(info))
```

### 4.3 正确做法 vs 反模式对比

```python
# ❌ 反模式：不区分压缩和摘要
def process_context(context):
    # 对所有内容使用同样的方法
    if len(context) > LIMIT:
        return summarize_all(context)  # 摘要了一切！
    return context
# 问题：包含精确信息的内容（如工具返回的结构化数据）
# 被不可逆地摘要了——信息永久丢失


# ✅ 正确做法：区分压缩和摘要
class SmartContextProcessor:
    """
    根据内容类型和后续需求选择处理方式。
    """
    def process(self, sections: list[Section]) -> list[Section]:
        result = []
        
        for section in sections:
            if section.type in ("tool_result", "api_response"):
                # 工具结果和 API 响应：
                # 如果已经消费 → 清除
                # 如果未消费 → 保留原始
                if section.consumed:
                    continue  # 已消费，清除
                else:
                    result.append(section)  # 保留原始
        
            elif section.type == "precise_user_info":
                # 用户提供的精确信息：
                # 始终保留原始
                result.append(section)
        
            elif section.type == "conversation_history":
                # 对话历史：
                # 最近 N 轮保留原始
                # 之前的摘要
                if section.is_recent:
                    result.append(section)
                else:
                    summary = safe_summarize(section)
                    result.append(summary)
        
            elif section.type == "retrieved_doc":
                # 检索文档：
                # 关键段保留原文
                # 非关键段摘要
                if section.is_key_segment:
                    result.append(section)
                else:
                    result.append(summarize(section))
        
        return result
```

## 五、预防措施

### 5.1 内容类型标注规范

```yaml
内容类型标注规范:
  precise: 必须保留原始内容
    - 订单号、退款单号、交易ID
    - 金额、数量
    - 日期、时间
    - 用户姓名、地址、电话、邮箱
    - 任何后续可能被查询的精确信息
    
  compressible: 可使用可逆压缩
    - 大 JSON 对象
    - 长文本段落（非关键部分）
    - 格式化的日志
    
  summarizable: 可使用不可逆摘要
    - 较早的对话历史（> N 轮前）
    - 闲聊、非关键讨论
    - 已确认的操作记录（大致流程）
    
  removable: 直接清除
    - 已消费的工具结果
    - 中间推理过程
    - 过期的系统消息
```

### 5.2 自动信息保留检测

```python
def assert_critical_info_preserved(original: str, 
                                     processed: str) -> None:
    """
    断言关键信息在处理后被保留。
    用于测试和 CI pipeline。
    """
    extractor = SafeSummarizer()
    original_info = set(extractor.extract_precise_info(original))
    processed_info = set(extractor.extract_precise_info(processed))
    
    missing = original_info - processed_info
    if missing:
        raise AssertionError(
            f"关键信息在处理后丢失: {missing}"
        )
```

### 5.3 选择决策树

```
需要精简内容？
│
├─ 内容是精确数据（订单号、金额、配置）？
│   └─ 是 → 保留原始或可逆压缩
│
├─ 内容是工具结果？
│   ├─ 已经消费 → 直接清除
│   └─ 未消费 → 保留原始
│
├─ 内容是对话历史？
│   ├─ 最近 5 轮 → 保留原始
│   └─ 更早 → LLM 摘要（保留精确信息）
│
├─ 内容是检索文档？
│   ├─ 关键段落 → 保留原文
│   ├─ 非关键 → 摘要或移除
│   └─ 已引用 → 保留直到引用完成
│
└─ 内容是中间推理？
    └─ 直接清除（已反映在最终决策中）
```

## 关键教训速查

| 教训 | 说明 |
|------|------|
| 压缩≠摘要 | 压缩是可逆的，摘要是不可逆的 |
| 用摘要代替压缩 = 信息永久丢失 | 精确数据（订单号、金额）绝不能被摘要 |
| 用压缩代替摘要 = 浪费算力 | 历史对话大意不需要精确恢复 |
| 内容类型决定处理策略 | 精确数据保留，已消费结果清除，历史摘要 |
| 安全摘要保留精确信息 | 在摘要末尾附加"精确信息附录" |
| CI 中应有信息保留断言 | 自动化检测关键信息是否在处理后丢失 |
| 为每段内容标注类型 | 明确每段内容属于哪一类，选择对应策略 |
