# 25.2 "没有上下文预算" —— 不追踪 Token 消耗就无法优化

> 反模式：系统中没有 Token 消耗的追踪机制，开发者不知道每轮推理消耗了多少 token，不知道哪些组件消耗最多，不知道成本花在哪里。不追踪 → 无法优化 → 无法规模化。

---

## 一、症状描述

### 1.1 典型表现

```
场景：月结时收到云厂商账单

CTO: "这个月的 AI 推理账单怎么是 $47,000？"
团队: "啊？我们预期是 $15,000..."

团队开始排查：
- 没有 Token 消耗的细粒度日志
- 不知道哪些对话/功能消耗最多
- 不知道每步的成本分布
- 无法回答"成本花在哪里"

花了一周时间加日志，最终才发现：
- 工具定义每次重复发送（占 35% 成本）
- 某个对话卡在死循环中（占 12% 成本）
- RAG 检索结果太大且未压缩（占 25% 成本）
```

**如果没有 Token 追踪，你连钱花在哪里都不知道。**

### 1.2 典型代码（反模式）

```python
# ❌ 反模式：没有预算，没有追踪
class BudgetlessAgent:
    """
    反模式 Agent：没有任何 Token 追踪或预算管理。
    """
    def __init__(self, model: str = "gpt-4"):
        self.model = model
        self.tools = self._load_all_tools()
    
    def run(self, user_input: str) -> str:
        messages = self._build_messages(user_input)
        
        # 直接调用 API——没有追踪消耗
        response = openai_client.chat.completions.create(
            model=self.model,
            messages=messages,
        )
        
        # 只使用了 response——没有记录消耗了多少
        return response.choices[0].message.content
        # Token 消耗记录：无
        # 成本记录：无
        # 预算检查：无
        # 分层分解：无
```

**缺失的功能**：
1. 没有记录 prompt_tokens 和 completion_tokens
2. 没有按组件分解 Token 消耗
3. 没有在超预算时告警
4. 没有成本优化所需的数据

### 1.3 生产数据

没有 Token 预算的系统在规模化后的典型表现：

| 规模 | 请求量/天 | 月成本（无预算） | 月成本（有预算+优化） | 差距 |
|------|---------|---------------|-------------------|------|
| 小型 | 1,000 | $1,200 | $450 | 2.7x |
| 中型 | 10,000 | $11,500 | $4,200 | 2.7x |
| 大型 | 100,000 | $108,000 | $38,000 | 2.8x |

**没有预算管理的系统，成本通常是有预算管理的 2.5-3 倍**。

## 二、根因分析

### 2.1 Token 消耗的"不可见性"

Token 不像 CPU 或内存那样有系统级的监控工具：

```
CPU 使用率 → top/htop（内置）
内存使用 → free/vmstat（内置）
磁盘 IO → iostat（内置）
Token 消耗 → ❌ 没有内置工具，需在应用层手动埋点
```

### 2.2 "反正云厂商会记账"的思维

云厂商的账单是粗粒度的：

```yaml
云厂商账单示例:
  条目: "GPT-4 API 调用"
  总金额: $47,382.50
  明细: ❌ 无

# 无法回答的问题：
# - 哪个功能模块消耗最多？
# - 哪些消耗是浪费（可优化）的？
```

### 2.3 "优化成本 = 降低质量"的误解

实际数据表明：**大部分浪费来自工程结构不合理**：

```
典型的 Token 浪费分布：
- 35%: 重复发送相同的工具 Schema（架构问题）
- 25%: 未压缩的检索结果（架构问题）
- 15%: 死循环和无效重复（架构问题）
- 10%: 过长的输出（Prompt 工程问题）
- 15%: 合理消耗（无法优化）

85% 的 Token 浪费可以通过工程优化消除，而不影响质量。
```

### 3.2 全链路 Token 分解

```python
class TokenBreakdownTracker:
    """全链路 Token 消耗分解追踪器"""
    def __init__(self):
        self.breakdowns: list[dict] = []
    
    def record(self, step_name: str, breakdown: dict):
        self.breakdowns.append({
            "step": step_name,
            "timestamp": datetime.now().isoformat(),
            **breakdown,
            "total": sum(breakdown.values())
        })
    
    def summary(self) -> dict:
        if not self.breakdowns:
            return {}
        totals = defaultdict(int)
        for b in self.breakdowns:
            for key, val in b.items():
                if key not in ("step", "timestamp"):
                    totals[key] += val
        total = totals.pop("total", 0)
        return {
            "total_tokens": total,
            "total_cost": calculate_cost_from_tokens(total),
            "component_breakdown": dict(totals),
            "component_percentages": {
                k: f"{v/total*100:.1f}%" for k, v in totals.items()
            },
        }
```

## 四、解决方案（正确做法）

### 4.1 Token 预算系统

```python
# ✅ 正确做法：带 Token 预算追踪的 Agent
class BudgetAwareAgent:
    def __init__(self, budget_config: dict = None):
        self.budget_config = budget_config or self._default_budget()
        self.token_tracker = TokenBreakdownTracker()
        self.step_count = 0
    
    def _default_budget(self) -> dict:
        return {
            "max_per_step": 15000,
            "max_per_dialog": 100000,
            "max_cost_per_dialog": 2.0,
            "component_limits": {
                "system_prompt": 1000,
                "tool_definitions": 5000,
                "chat_history": 5000,
                "tool_results": 3000,
                "retrieval_results": 2000,
                "output": 2000,
            }
        }
    
    def run(self, user_input: str) -> str:
        self.step_count += 1
        
        # 1. 检查对话总预算
        if self.token_tracker.summary().get("total_tokens", 0) > \
           self.budget_config["max_per_dialog"]:
            return self._degraded_response("预算超限")
        
        # 2. 构建上下文并分解 Token
        messages = self._build_messages(user_input)
        breakdown = self._analyze_token_breakdown(messages)
        
        # 3. 检查单步预算
        if breakdown["total"] > self.budget_config["max_per_step"]:
            messages = self._compress_context(messages)
            breakdown = self._analyze_token_breakdown(messages)
        
        # 4. 执行 LLM 调用（带成本追踪）
        response = self._tracked_llm_call(messages)
        
        # 5. 记录
        self.token_tracker.record(f"step_{self.step_count}", breakdown)
        return response
    
    def _analyze_token_breakdown(self, messages: list[dict]) -> dict:
        breakdown = {}
        for msg in messages:
            role = msg["role"]
            content = msg.get("content", "")
            tokens = count_tokens(content)
            if "可用工具" in content:
                breakdown["tool_definitions"] = breakdown.get("tool_definitions", 0) + tokens
            elif "[历史摘要]" in content or "对话摘要" in content:
                breakdown["chat_history"] = breakdown.get("chat_history", 0) + tokens
            elif role == "system":
                breakdown["system_prompt"] = breakdown.get("system_prompt", 0) + tokens
            elif role == "tool":
                breakdown["tool_results"] = breakdown.get("tool_results", 0) + tokens
            elif role == "user":
                breakdown["user_input"] = breakdown.get("user_input", 0) + tokens
        breakdown["total"] = sum(breakdown.values())
        return breakdown
    
    def _tracked_llm_call(self, messages: list[dict]) -> dict:
        prompt_tokens = count_tokens(messages)
        response = openai_client.chat.completions.create(
            model=self.budget_config.get("model", "gpt-4"),
            messages=messages,
        )
        completion_tokens = response.usage.completion_tokens
        logging.info(json.dumps({
            "event": "llm_call",
            "step": self.step_count,
            "prompt_tokens": prompt_tokens,
            "completion_tokens": completion_tokens,
            "total_tokens": prompt_tokens + completion_tokens,
            "cost": calculate_cost(prompt_tokens, completion_tokens),
        }))
        return response
```

### 4.2 成本告警系统

```python
class CostAlertSystem:
    def __init__(self):
        self.daily_cost = 0
        self.alert_thresholds = {
            "daily_cost": {"warning": 50, "critical": 100},
            "per_dialog_cost": {"warning": 1.0, "critical": 5.0},
            "token_waste_ratio": {"warning": 0.3, "critical": 0.5},
        }
    
    def check_and_alert(self, usage: dict) -> list[str]:
        alerts = []
        if usage.get("daily_cost", 0) > self.alert_thresholds["daily_cost"]["critical"]:
            alerts.append(f"CRITICAL: 日成本 ${usage['daily_cost']:.2f} 超过临界阈值")
        if usage.get("per_dialog_cost", 0) > self.alert_thresholds["per_dialog_cost"]["critical"]:
            alerts.append(f"CRITICAL: 单对话成本超过临界阈值")
        return alerts
```

### 4.3 正确做法 vs 反模式对比

| 维度 | 反模式：无预算 | 正确做法：有预算 |
|------|--------------|----------------|
| Token 记录 | 无 | 每次调用详细记录 |
| 组件分解 | 无 | 按 system/tools/history/results 分解 |
| 预算检查 | 无 | 每次调用前检查 |
| 超预算处理 | 无（继续累积） | 自动压缩/降级 |
| 成本可视化 | 月账单后才看到 | 实时 Dashboard |
| 优化依据 | 无数据，凭感觉 | 有数据，针对性优化 |

## 关键教训速查

| 教训 | 说明 |
|------|------|
| 没有追踪就无法优化 | Token 消耗是隐形的，必须主动记录 |
| 85% 的 Token 浪费可通过工程优化消除 | 不影响质量的前提下大幅降低成本 |
| 成本管理的单位是"元/请求"而非"元/月" | 月账单是滞后的，每请求成本是实时的 |
| 组件级分解是优化前提 | 不知道哪部分消耗最多就无法针对性优化 |
| 将预算检查集成到 API 调用中 | 在调用前检查预算，而不是事后收到账单才警醒 |
| Token 预算应写入架构文档 | 如同性能 SLA 一样，Token 预算也是架构要求 |
