# 6.2 Static/Dynamic 分离

> 每轮对话将所有 Prompt 内容原封不动发送给模型是最简单的做法，但也是 token 浪费效率最低的做法。Static/Dynamic 分离的核心思想是：**把不需要每轮变化的内容缓存起来，只让真正需要每轮变化的内容参与传输**。

---

## 一、Static vs Dynamic 的定义

在 System Prompt 的上下文中，Static 和 Dynamic 不是绝对概念，而是依据**时间维度**上的变化频率划分的：

| 维度 | Static（静态） | Semi-Static（半静态） | Dynamic（动态） |
|------|---------------|----------------------|----------------|
| **变化频率** | 数天/数周一次 | 每次会话、每切换项目 | 每轮对话 |
| **示例** | Base Layer、Tools 元信息 | Rules Layer、Skills | Context Layer、用户输入 |
| **缓存策略** | 长期缓存 | 会话级缓存 | 不缓存，每轮重建 |
| **典型 token 占比** | 30-40% | 20-30% | 30-50% |

**关键原则**：Static 部分负责"框架"——身份、持续有效的规则、固定的工具描述；Dynamic 部分负责"实例"——当前环境状态、会话上下文、本轮任务信息。

---

## 二、什么该缓存？—— Static 内容的识别

### 2.1 适合长期缓存的内容

以下内容在 Agent 的整个生命周期中几乎不变，适合缓存到本地或远程 KV 存储：

**① Base Layer（身份定义）**
- Agent 身份声明："你是 AI 助手 XXX，由 YYY 开发"
- 不可违反的安全规则列表
- 默认输出格式模板
- 这类内容的变化频率以天/周计，缓存有效期可以设为 24 小时以上

**② 工具注册信息（Tools 元信息）**
- 工具名称、参数定义、返回值格式（功能描述本身）
- 注意：工具的**可用性**（当前环境是否支持）属于动态信息
- 缓存有效期：工具集变化时才需要刷新

**③ 规则框架（Rules Layer 的骨架）**
- 通用的任务执行 SOP（标准操作流程）
- 不依赖特定环境的决策规则
- 通用的错误处理策略

**④ 技能定义（Skills Layer 的静态部分）**
- 技能的适用范围说明
- 技能包含的子流程描述
- 技能使用注意事项

### 2.2 缓存存储方案

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| **内存字典** | 零序列化开销，速度最快 | Agent 重启后丢失 | 单进程 Agent |
| **Redis/Memcached** | 跨进程共享，支持 TTL | 增加网络依赖 | 分布式 Agent 集群 |
| **本地文件缓存** | 持久化，Agent 重启后可用 | 读写性能不如内存 | 本地 Agent（如 Claude Code） |
| **数据库（SQLite/PostgreSQL）** | 支持 ACID，可版本管理 | 查询开销相对大 | 需要审计和回滚的场景 |

### 2.3 缓存键设计

缓存键（Cache Key）应精确反映内容的标识，避免缓存击穿和雪崩：

```
# 缓存键设计示例
cache_key = f"system_prompt:{layer}:{version}:{language}"

# 实际取值
system_prompt:base_layer:v2.1:zh-CN
system_prompt:tools:v1.4:zh-CN
system_prompt:rules:code_review:v3.0:zh-CN
```

当工具集或模型版本变化时，通过变更 `version` 字段来"主动失效"缓存。

## 三、什么该每轮重建？—— Dynamic 内容的识别

### 3.1 必须每轮重建的内容

以下内容与当前状态强相关，缓存会给出错误或过时的信息：

**① Context Layer**
- 工作目录、分支名称、最近修改的文件
- 用户当前的偏好设置（如果支持实时切换）
- 本轮会话的中间状态（已完成步骤、待执行任务）
- 这些信息如果不更新，Agent 会基于过时状态做决策，导致"幻觉"——不是事实幻觉，而是**状态幻觉**

**② 工具可用性信息**
- 当前环境可用的工具列表（某些工具可能因权限/配置不可用）
- 工具的实时状态（API Key 是否有效、服务是否在线）
- 这些信息缓存在跨会话时可能失效（用户更新了环境变量）

**③ 用户输入 + 对话历史**
- 本轮用户提问和之前的对话轮次
- 用户输入天然每轮不同，不存在缓存的意义

### 3.2 状态幻觉（State Hallucination）

状态幻觉是指 Agent 基于过时或错误的上下文状态做出的合理但错误的决策。它与事实幻觉不同：

| 类型 | 事实幻觉 | 状态幻觉 |
|------|----------|----------|
| **根因** | 模型参数知识错误或缺失 | 上下文状态信息过期 |
| **表现** | "李白是唐朝第二位皇帝" | "当前目录仍为 /old/path"（实际已切换） |
| **修复** | RAG、引用溯源 | 每轮刷新 Context Layer |
| **与缓存的关系** | 弱相关 | 强相关——过期缓存是主要诱因 |

**示例**：

```
# 错误的状态缓存（过时信息）
System Prompt中包含: "当前工作目录: /project/v1"
# 实际上用户已经用 cd 切换到了 /project/v2

Agent (基于过时状态): 我已经检查了 /project/v1 中的文件...
User (困惑): 但我们现在在 /project/v2 啊？
```

这就是为什么 Context Layer 必须每轮重建——它直接影响 Agent 的行为正确性。

## 四、Semi-Static 内容的处理策略

介于 Static 和 Dynamic 之间的内容是工程中最需要精心设计的部分。

### 4.1 会话级缓存

Rules Layer 和 Skills Layer 在**同一会话内**通常不变，但**不同会话**（打开不同项目）可能需要不同规则集。

**实现方案**：使用会话 ID 作为缓存命名空间的一部分

```python
import hashlib
import json
from typing import Optional

class SessionCache:
    def __init__(self, storage_backend):
        self.storage = storage_backend

    def build_cache_key(self, session_id: str, layer: str, context_hash: str) -> str:
        """构建会话级缓存键"""
        raw = f"{session_id}:{layer}:{context_hash}"
        return f"prompt_cache:{hashlib.sha256(raw.encode()).hexdigest()[:16]}"

    def get_or_build(
        self,
        session_id: str,
        layer: str,
        context_snapshot: dict,
        builder_fn
    ) -> str:
        """获取缓存或重建"""
        context_hash = hashlib.md5(
            json.dumps(context_snapshot, sort_keys=True).encode()
        ).hexdigest()[:8]
        cache_key = self.build_cache_key(session_id, layer, context_hash)
        cached = self.storage.get(cache_key)
        if cached is not None:
            return cached
        result = builder_fn(context_snapshot)
        self.storage.set(cache_key, result, ttl=3600)  # 1小时TTL
        return result
```

### 4.2 按需注入

对于一个包含 20 个技能的 Agent，每次注入全部技能描述既不现实也不必要。按需注入策略：

```
┌─────────────────────────────────────────┐
│           技能选择器                     │
│                                         │
│  用户输入 ─→ 意图分类 ─→ 匹配技能 ─→ 注入  │
│                  │            │           │
│             关键词匹配    技能-场景映射表   │
│             语义相似度                    │
│             历史模式                      │
└─────────────────────────────────────────┘
```

**技能选择算法**（简化版）：

```python
def select_skills(user_input: str, session_history: list, all_skills: dict) -> list:
    """根据用户输入和会话历史选择需要注入的技能"""
    activated = set()
    # 1. 关键词匹配
    for skill_name, skill_def in all_skills.items():
        for keyword in skill_def["trigger_keywords"]:
            if keyword in user_input.lower():
                activated.add(skill_name)
                break
    # 2. 会话历史连续性：如果上一轮激活了某个技能，本轮默认保留
    if session_history and session_history[-1].get("active_skills"):
        for skill in session_history[-1]["active_skills"]:
            activated.add(skill)
    # 3. 限制技能数量，防止 token 溢出
    return list(activated)[:5]  # 最多同时激活 5 个技能
```

## 五、缓存破裂检测

缓存破裂（Cache Staleness）是指缓存内容与实际状态不一致但未及时更新，导致 Agent 基于过期内容决策的现象。

### 5.1 缓存破裂的信号

以下事件**必须触发**缓存失效：

| 事件 | 影响的缓存层 | 检测方式 |
|------|-------------|----------|
| 用户切换目录 | Context Layer | 监听 `cd` 或 shell 的 CWD 变更事件 |
| 项目配置变更 | Rules Layer | 检测 `.claude/settings.json` 文件修改时间 |
| 工具集变化 | Tools Layer | 启动时重扫描可执行文件列表 |
| 环境变量变化 | Context Layer | 对比环境变量快照的哈希值 |
| 用户更新偏好 | Rules/Skills Layer | 检测配置文件修改 |
| Agent 版本更新 | 全部层 | 版本号变更 |

### 5.2 缓存破裂检测的实现

```python
import hashlib
import os
import time
from pathlib import Path

class CacheStalenessDetector:
    """缓存破裂检测器"""

    def __init__(self, cache_dir: str = ".cache/prompt_snapshots"):
        self.cache_dir = Path(cache_dir)
        self.cache_dir.mkdir(parents=True, exist_ok=True)

    def snapshot_key(self, key: str) -> Path:
        return self.cache_dir / f"{key}_snapshot.json"

    def check_staleness(self, layer: str, current_value: str) -> bool:
        """
        检查指定层是否缓存破裂。
        返回 True 表示缓存已破裂（需要重建），False 表示缓存仍有效。
        """
        snapshot_file = self.snapshot_key(layer)
        current_hash = hashlib.sha256(current_value.encode()).hexdigest()

        if not snapshot_file.exists():
            return True  # 没有快照，必然破裂

        try:
            with open(snapshot_file) as f:
                snapshot = json.loads(f.read())
            stored_hash = snapshot.get("content_hash")
            timestamp = snapshot.get("timestamp", 0)
            return stored_hash != current_hash
        except (json.JSONDecodeError, KeyError, OSError):
            return True  # 读取失败，保守起见视为破裂

    def update_snapshot(self, layer: str, current_value: str):
        """更新缓存快照"""
        snapshot_file = self.snapshot_key(layer)
        current_hash = hashlib.sha256(current_value.encode()).hexdigest()
        snapshot = {
            "content_hash": current_hash,
            "timestamp": time.time(),
            "layer": layer
        }
        with open(snapshot_file, "w") as f:
            f.write(json.dumps(snapshot, indent=2))

    def invalidate_all(self):
        """强制全部缓存失效（Agent 启动/重启时调用）"""
        for f in self.cache_dir.glob("*_snapshot.json"):
            f.unlink()


class PromptCacheManager:
    """提示词缓存管理器 —— 整合缓存读写与破裂检测"""

    def __init__(self, detector: CacheStalenessDetector, storage):
        self.detector = detector
        self.storage = storage

    def get_prompt(self, layer: str, content_builder_fn) -> str:
        """
        获取提示词内容。
        如果缓存有效，直接返回缓存；如果缓存破裂，重新构建。
        """
        is_stale = self.detector.check_staleness(layer, content_builder_fn.get_snapshot_value())
        if not is_stale:
            cached = self.storage.get(f"prompt:{layer}")
            if cached is not None:
                return cached
        # 缓存破裂或不存在，重建
        content = content_builder_fn()
        self.storage.set(f"prompt:{layer}", content)
        self.detector.update_snapshot(layer, content_builder_fn.get_snapshot_value())
        return content
```

### 5.3 主动破裂 vs 被动检测

| 策略 | 方式 | 延迟 | 可靠性 | 实现复杂度 |
|------|------|------|--------|-----------|
| **主动破裂** | 事件驱动的失效（检测到变化立即清除缓存） | 无 | 高 | 中等 |
| **被动检测** | 使用时对比哈希值判断是否破裂 | 有（每次读取时校验） | 中 | 低 |
| **TTL 过期** | 设定固定有效期，到期自动失效 | 有（最坏为 TTL 时长） | 低 | 最低 |

**生产建议**：主动破裂 + 被动检测**组合使用**。主动破裂处理已知事件（切换目录、配置文件变更），被动检测作为兜底（防止漏检）。

## 六、分层级的具体缓存策略矩阵

| 层级 | 缓存级别 | 缓存 Key 维度 | 破裂信号 | 重建时机 |
|------|---------|---------------|----------|----------|
| **Base Layer** | 长期（24h+） | model_version + locale | Agent 版本更新 | 启动时或版本变更 |
| **Rules Layer** | 会话级 | session_id + rules_version | settings.json 变更 | 会话启动或配置变更 |
| **Context Layer** | 不缓存 | — | — | 每轮 |
| **Tools Layer** | 长期（24h+） | tools_version + env_hash | 环境变量/工具集变更 | 启动时或工具集变更 |
| **Skills Layer** | 会话级 + 按需 | session_id + skill_name | 项目类型切换 | 会话启动或项目切换 |

## 关键概念速查

| 术语 | 解释 |
|------|------|
| Static Content | 变化频率极低（天/周级），适合长期缓存的部分 |
| Dynamic Content | 每轮对话都可能变化，必须每轮重建的部分 |
| Semi-Static Content | 会话内稳定、跨会话可能变化，采用会话级缓存 |
| 缓存破裂（Cache Staleness） | 缓存内容与实际状态不一致 |
| 状态幻觉 | 基于过时上下文状态做出正确但不符合当前实际的决策 |
| 主动破裂 | 事件驱动立即清除过期缓存 |
| 被动检测 | 使用时通过哈希对比检测缓存是否失效 |
| 按需注入 | 根据当前场景有选择地注入提示词内容，而非全量注入 |
