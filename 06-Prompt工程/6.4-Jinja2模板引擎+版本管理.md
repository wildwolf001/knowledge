# 6.4 Jinja2 模板引擎 + 版本管理

> 当 System Prompt 从数百字膨胀到数千字、从单一文件演变为五层结构时，手动拼接已不可行。Jinja2 模板引擎提供了变量替换、条件判断、循环渲染等能力，使提示词可编程化；结合版本管理，则让提示词迭代可回滚、可对比、可审计。

---

## 一、为什么需要模板引擎？

### 1.1 手写拼接的痛点

在未引入模板引擎时，System Prompt 的构建通常是这样做的：

```python
# 手动拼接 —— 不可维护
def build_system_prompt(os_type, shell, tools, skills, cwd, user_name):
    prompt = f"你是一个 AI 助手。运行在 {os_type} 的 {shell} 环境中。\n\n"
    prompt += "【可用工具】\n"
    for t in tools:
        prompt += f"- {t['name']}: {t['description']}\n"
    prompt += "\n【当前状态】\n"
    prompt += f"目录: {cwd}\n"
    if os_type == "windows":
        prompt += "注意: 文件路径使用反斜杠\n"
    # ... 随着层级增加，这段代码不断膨胀
    return prompt
```

**问题**：
1. 逻辑与表述耦合：Python 代码中混入了提示词的具体措辞
2. 修改提示词需要修改代码：非技术人员无法参与
3. 不可审计：没有版本号，无法追溯某次变化
4. 不可测试：无法单独测试某层内容的改动效果

### 1.2 Jinja2 的解决方案

Jinja2 是一个 Python 模板引擎，它将提示词内容与渲染逻辑分离。模板是纯文本（.j2 文件），渲染逻辑由 Python 代码驱动。

```
提示词模板（.j2 文件）          渲染数据（Python dict）
    ┌──────────────┐              ┌──────────────┐
    │ 你是一个 AI 助手。     │              │ "os_type": "win32"  │
    │ 运行在 {{ os_type }}  │     +       │ "shell": "powershell"│
    │ 环境中。              │              │ "tools": [...]       │
    └──────────────┘              └──────────────┘
                                         │
                                         ▼
                               ┌──────────────────┐
                               │ 你是一个 AI 助手。   │
                               │ 运行在 win32 的     │
                               │ powershell 环境中。  │
                               └──────────────────┘
```

## 二、完整的 Jinja2 System Prompt 模板

### 2.1 五层模板设计

按照 6.1 节的五层架构，每一层对应一个独立的 Jinja2 模板文件：

```
prompts/
├── base_layer.j2           # 身份 + 铁律
├── rules_layer.j2          # 行为规则
├── context_layer.j2        # 会话上下文
├── tools_layer.j2          # 工具描述
├── skills/
│   ├── code_review.j2      # 代码审查技能
│   ├── git_workflow.j2     # Git 工作流技能
│   └── project_mgmt.j2     # 项目管理技能
├── includes/
│   ├── safety_rules.j2     # 安全规则片段（被 base_layer.j2 引用）
│   └── output_format.j2    # 输出格式定义（被多个层引用）
└── macros/
    └── tool_descriptor.j2  # 工具描述宏（被 tools_layer.j2 引用）
```

### 2.2 Base Layer 模板（base_layer.j2）

```jinja2
{# === Base Layer: 身份与元规则 === #}
{% import 'macros/tool_descriptor.j2' as td %}

你是一个 AI 助手，由 Anthropic 开发。
当前运行平台: {{ os_type }}
Shell 类型: {{ shell_type }}

【不可违反规则】
{% for rule in base_rules %}
- {{ rule }}
{% endfor %}

【输出规范】
- 语言偏好: {{ language | default("zh-CN") }}
- 回复格式: {% if output_format == "markdown" %}Markdown{% else %}纯文本{% endif %}
```

**关键语法**：`{{ }}` 是变量输出，`{% %}` 是控制结构（循环、条件），`{# #}` 是注释（不会被渲染到最终输出中）。

### 2.3 Rules Layer 模板（rules_layer.j2）

```jinja2
{# === Rules Layer: 行为规则 === #}
{% if rules_mode == "strict" %}

【严格模式规则】
{% elif rules_mode == "normal" %}

【标准规则】
{% endif %}

{% for category, rules in rules_map.items() %}
## {{ category }}
{% for rule in rules %}
{{ loop.index }}. {{ rule }}
{% endfor %}
{% endfor %}

{% if stderr_handling %}
【错误处理】
- 工具调用失败: 重试最多 {{ max_retries }} 次
- 超时处理: 超过 {{ timeout_s }} 秒则报告超时
{% endif %}
```

**关键设计**：`rules_mode` 变量控制注入哪种规则集——严格模式适用于生产环境，普通模式适用于开发调试。

### 2.4 Context Layer 模板（context_layer.j2）

```jinja2
{# === Context Layer: 会话上下文 === #}
{% if auto_detected_context %}
【自动识别】
- 工作目录: {{ cwd }}
- 项目类型: {{ project_type }}
- 主要语言: {{ primary_language }}
- Git 分支: {{ git_branch | default("N/A") }}
- 未提交变更: {% if has_uncommitted_changes %}是{% else %}否{% endif %}
{% endif %}

{% if user_preferences %}
【用户偏好】
{% for key, value in user_preferences.items() %}
- {{ key }}: {{ value }}
{% endfor %}
{% endif %}

{% if session_state %}
【会话状态】
- 已完成的步骤: {{ session_state.completed_steps | join(" → ") }}
- 当前阶段: {{ session_state.current_phase }}
- 待办: {{ session_state.pending_tasks | join(", ") }}
{% endif %}
```

**关键设计**：`auto_detected_context` 控制是否注入自动检测的信息；`user_preferences` 是可选的用户偏好。

### 2.5 Tools Layer 模板（tools_layer.j2）

```jinja2
{# === Tools Layer: 工具描述 === #}
{% macro tool_block(tool) %}
### {{ tool.name }}
{% if tool.deprecated %}
⚠️ 已弃用，请使用 {{ tool.replacement }} 替代
{% endif %}
- 功能: {{ tool.description }}
- 参数:
{% for param in tool.params %}
  - {{ param.name }} ({{ "必填" if param.required else "选填" }}{% if param.type %}, {{ param.type }}{% endif %}): {{ param.desc }}
{% endfor %}
{% if tool.notes %}- 注意事项: {{ tool.notes }}{% endif %}
{% endmacro %}

【可用工具】
{% for tool in tools %}
{{ tool_block(tool) }}
{% endfor %}

{% if tools | length > 10 %}
提示: 当前有 {{ tools | length }} 个可用工具，请根据任务需要选择合适的工具。
{% endif %}
```

**关键设计**：使用 Jinja2 的 `macro` 功能封装 tool 渲染逻辑，可在多处复用。`deprecated` 标记让 Agent 知道哪些工具已被弃用。

### 2.6 Skills Layer 模板（skills_layer.j2）

```jinja2
{# === Skills Layer: 技能模块 === #}
{% if active_skills %}
【已激活技能】
{% for skill in active_skills %}
## 技能: {{ skill.name }}
适用场景: {{ skill.scenario }}
{% if skill.sub_skills %}
包含子技能:
{% for sub in skill.sub_skills %}
  - {{ sub }}
{% endfor %}
{% endif %}
{% endfor %}
{% endif %}
```

### 2.7 主模板（main_system_prompt.j2）

主模板通过 `{% include %}` 将各层组合在一起：

```jinja2
{# === 完整 System Prompt — 由各层模板组合而成 === #}
{% include 'base_layer.j2' %}

{% include 'rules_layer.j2' %}

{% if include_tools %}
{% include 'tools_layer.j2' %}
{% endif %}

{% if active_skills %}
{% include 'skills_layer.j2' %}
{% endif %}

{# Context Layer 最后注入，确保模型对当前状态保持最新认知 #}
{% include 'context_layer.j2' %}

{# 会话级别的覆盖指令 #}
{% if session_overrides %}
【本轮特殊指令】
{{ session_overrides }}
{% endif %}
```

## 三、Python 渲染引擎

### 3.1 完整渲染实现

```python
import json
from pathlib import Path
from typing import Optional
from jinja2 import Environment, FileSystemLoader, select_autoescape


class PromptRenderer:
    """System Prompt 渲染引擎"""

    def __init__(self, template_dir: str = "prompts"):
        self.env = Environment(
            loader=FileSystemLoader(template_dir),
            autoescape=select_autoescape(default=False),
            trim_blocks=True,       # 移除块语句后面的第一个换行
            lstrip_blocks=True,     # 移除块语句前面的空白
        )
        self.version = "1.0.0"

    def set_version(self, version: str):
        """设置当前模板版本"""
        self.version = version

    def get_template_info(self) -> dict:
        """获取所有模板文件的信息，用于审计"""
        loader = self.env.loader
        templates = {}
        for template_name in ["base_layer.j2", "rules_layer.j2",
                              "context_layer.j2", "tools_layer.j2",
                              "main_system_prompt.j2"]:
            try:
                source, _, _ = loader.get_source(self.env, template_name)
                templates[template_name] = {
                    "size_bytes": len(source.encode("utf-8")),
                    "exists": True,
                }
            except Exception:
                templates[template_name] = {"exists": False}
        return templates

    def render_base_layer(self, os_type: str, shell_type: str,
                          base_rules: list, **kwargs) -> str:
        """渲染 Base Layer"""
        template = self.env.get_template("base_layer.j2")
        return template.render(
            os_type=os_type,
            shell_type=shell_type,
            base_rules=base_rules,
            **kwargs
        )

    def render_rules_layer(self, rules_mode: str, rules_map: dict,
                           stderr_handling: bool = True,
                           max_retries: int = 2, timeout_s: int = 30) -> str:
        """渲染 Rules Layer"""
        template = self.env.get_template("rules_layer.j2")
        return template.render(
            rules_mode=rules_mode,
            rules_map=rules_map,
            stderr_handling=stderr_handling,
            max_retries=max_retries,
            timeout_s=timeout_s
        )

    def render_context_layer(self, cwd: str, project_type: str,
                             primary_language: str, **kwargs) -> str:
        """渲染 Context Layer"""
        template = self.env.get_template("context_layer.j2")
        return template.render(
            cwd=cwd,
            project_type=project_type,
            primary_language=primary_language,
            **kwargs
        )

    def render_tools_layer(self, tools: list) -> str:
        """渲染 Tools Layer"""
        template = self.env.get_template("tools_layer.j2")
        return template.render(tools=tools)

    def render_skills_layer(self, active_skills: list) -> str:
        """渲染 Skills Layer"""
        template = self.env.get_template("skills_layer.j2")
        return template.render(active_skills=active_skills)

    def render_full_prompt(
        self,
        os_type: str,
        shell_type: str,
        base_rules: list,
        rules_mode: str,
        rules_map: dict,
        cwd: str,
        project_type: str,
        primary_language: str,
        tools: list,
        active_skills: Optional[list] = None,
        user_preferences: Optional[dict] = None,
        session_state: Optional[dict] = None,
        session_overrides: Optional[str] = None,
        include_tools: bool = True,
        **kwargs
    ) -> str:
        """
        渲染完整的 System Prompt。

        这是核心渲染入口，接收所有层的变量，组合为最终提示词。
        返回结果附带元数据（版本号、渲染时间、各层 Token 占比）。
        """
        context = {
            "os_type": os_type,
            "shell_type": shell_type,
            "base_rules": base_rules,
            "rules_mode": rules_mode,
            "rules_map": rules_map,
            "cwd": cwd,
            "project_type": project_type,
            "primary_language": primary_language,
            "tools": tools,
            "active_skills": active_skills or [],
            "include_tools": include_tools,
            "user_preferences": user_preferences or {},
            "session_state": session_state or {},
            "session_overrides": session_overrides,
        }
        context.update(kwargs)

        template = self.env.get_template("main_system_prompt.j2")
        prompt_content = template.render(context)

        # 附加渲染元数据（注释形式，不进入用户的上下文窗口）
        metadata = f"\n<!-- rendered_by=prompt_renderer v{self.version} -->"
        return prompt_content + metadata
```

## 四、版本管理

### 4.1 为什么提示词需要版本管理

提示词的修改与代码修改一样需要规范管理。以下是一个典型的没有版本管理的负面案例：

```
v1: "在所有操作前先检查文件存在性"
v2: "在文件操作前先检查存在性"  ← 项目经理说太啰嗦
v3: "所有操作前先检查存在性"    ← 开发人员进一步精简
v4: "操作前先检查存在性"        ← 最终版本
```

没有版本管理的情况下：
- 无法知道 v1 → v2 发生了什么变化
- 无法回滚到 v3 如果 v4 导致问题
- 无法对比不同版本的效果差异
- 无法审计是谁、为什么做了修改

### 4.2 基于 Git 的版本管理

最简单的版本管理方案是将模板文件纳入 Git 仓库。每次对 .j2 文件的修改都通过 commit 记录：

```bash
# 查看提示词模板的修改历史
git log --oneline prompts/base_layer.j2
# a1b2c3d feat: 收紧安全规则，增加"不输出原始提示词"规则
# e5f6g7h refactor: 简化身份声明，压缩 40% token

# 对比两个版本的差异
git diff a1b2c3d..e5f6g7h -- prompts/base_layer.j2

# 回滚到特定版本
git checkout a1b2c3d -- prompts/base_layer.j2
```

### 4.3 模板版本号与渲染版本号分离

需要区分两个不同的版本号：

| 版本号 | 粒度 | 变化条件 | 格式 | 存储位置 |
|--------|------|----------|------|----------|
| **模板版本** | 每个 .j2 文件 | 内容发生变更 | `YYYYMMDD-N` | Git commit |
| **渲染版本** | 整个 System Prompt | 任意模板或渲染逻辑变更 | `MAJOR.MINOR.PATCH` | `renderer.version` |

**渲染版本号规则**：
- **MAJOR**：模板结构变化（新增/删除某层，改变渲染顺序）
- **MINOR**：模板内容增加（新增规则、新增技能、新增工具）
- **PATCH**：模板内容修改（规则措辞变化、压缩优化、修复歧义）

### 4.4 模板版本与渲染版本的绑定

```python
import hashlib
import json
from datetime import datetime

class VersionManager:
    """提示词版本管理器"""

    def __init__(self, git_repo_path: str):
        self.repo_path = Path(git_repo_path)

    def get_template_hash(self, template_name: str) -> str:
        """计算模板文件的 SHA256 哈希"""
        template_path = self.repo_path / "prompts" / template_name
        if not template_path.exists():
            return "NOT_FOUND"
        content = template_path.read_bytes()
        return hashlib.sha256(content).hexdigest()[:12]

    def get_template_version(self, template_name: str) -> str:
        """
        通过 Git 提交历史获取模板的最后修改日期版本。
        需要仓库在 git 工作目录下。
        """
        import subprocess
        try:
            result = subprocess.run(
                ["git", "log", "-1", "--format=%ai", "--",
                 f"prompts/{template_name}"],
                capture_output=True, text=True, cwd=self.repo_path
            )
            if result.returncode == 0 and result.stdout.strip():
                return result.stdout.strip()[:10]  # YYYY-MM-DD
        except Exception:
            pass
        return "unknown"

    def generate_render_manifest(self, renderer: PromptRenderer,
                                 render_context: dict) -> dict:
        """生成渲染清单，包含所有模板的版本信息和上下文快照"""
        manifest = {
            "render_version": renderer.version,
            "render_timestamp": datetime.utcnow().isoformat(),
            "templates": {},
            "context_snapshot": {
                "os_type": render_context.get("os_type"),
                "rules_mode": render_context.get("rules_mode"),
                "num_tools": len(render_context.get("tools", [])),
                "num_skills": len(render_context.get("active_skills", [])),
            }
        }
        for name in ["base_layer.j2", "rules_layer.j2", "context_layer.j2",
                      "tools_layer.j2", "skills_layer.j2", "main_system_prompt.j2"]:
            manifest["templates"][name] = {
                "hash": self.get_template_hash(name),
                "version": self.get_template_version(name),
            }
        return manifest

    def compare_manifests(self, m1: dict, m2: dict) -> list:
        """比较两个渲染清单，列出差异"""
        diffs = []
        if m1["render_version"] != m2["render_version"]:
            diffs.append({
                "type": "render_version",
                "old": m1["render_version"],
                "new": m2["render_version"],
            })
        for tmpl_name in m1.get("templates", {}):
            old_hash = m1["templates"][tmpl_name]["hash"]
            new_hash = m2.get("templates", {}).get(tmpl_name, {}).get("hash", "")
            if old_hash != new_hash:
                diffs.append({
                    "type": "template_change",
                    "template": tmpl_name,
                    "old_hash": old_hash,
                    "new_hash": new_hash,
                })
        return diffs
```

### 4.5 审计日志

每次 System Prompt 渲染生成，都应记录审计日志：

```python
import logging

class PromptAuditLogger:
    """提示词审计日志记录器"""

    def __init__(self, log_path: str = "logs/prompt_audit.log"):
        self.logger = logging.getLogger("prompt_audit")
        handler = logging.FileHandler(log_path)
        handler.setFormatter(logging.Formatter(
            "%(asctime)s | %(levelname)s | %(message)s"
        ))
        self.logger.addHandler(handler)
        self.logger.setLevel(logging.INFO)

    def log_render(self, version: str, manifest: dict, token_count: int):
        """记录一次渲染"""
        self.logger.info(
            f"RENDER | version={version} | tokens={token_count} | "
            f"templates={json.dumps(manifest['templates'])} | "
            f"context={json.dumps(manifest['context_snapshot'])}"
        )

    def log_rollback(self, from_version: str, to_version: str, reason: str):
        """记录一次版本回滚"""
        self.logger.warning(
            f"ROLLBACK | {from_version} → {to_version} | reason={reason}"
        )

    def log_test_result(self, version: str, test_name: str, passed: bool,
                        metrics: dict = None):
        """记录提示词版本的测试结果"""
        status = "PASS" if passed else "FAIL"
        self.logger.info(
            f"TEST | {status} | version={version} | test={test_name} | "
            f"metrics={json.dumps(metrics or {})}"
        )
```

## 五、A/B 测试与版本对比

### 5.1 System Prompt 的 A/B 测试框架

```python
import random

class PromptABTest:
    """提示词 A/B 测试框架"""

    def __init__(self, renderer: PromptRenderer, version_mgr: VersionManager):
        self.renderer = renderer
        self.version_mgr = version_mgr
        self.audit = PromptAuditLogger()

    def get_assigned_version(self, session_id: str, variants: list) -> str:
        """基于 session_id 将用户分配到某个变体"""
        idx = hash(session_id) % len(variants)
        return variants[idx]

    def run_comparison(self, variant_a: dict, variant_b: dict,
                       sessions: list) -> dict:
        """
        对比两个提示词版本的效果。
        返回 A/B 测试的关键指标对比。
        """
        results = {"A": {"sessions": 0, "avg_tokens": 0, "success_rate": 0},
                   "B": {"sessions": 0, "avg_tokens": 0, "success_rate": 0}}
        for i, session in enumerate(sessions):
            variant = "A" if i % 2 == 0 else "B"
            params = variant_a if variant == "A" else variant_b
            full_prompt = self.renderer.render_full_prompt(**params)
            # 模拟评估过程
            results[variant]["sessions"] += 1
            results[variant]["avg_tokens"] += len(full_prompt.split())
        # 计算平均值
        for v in ["A", "B"]:
            if results[v]["sessions"] > 0:
                results[v]["avg_tokens"] /= results[v]["sessions"]
        return results
```

### 5.2 版本回滚策略

| 回滚级别 | 粒度 | 操作 | 恢复速度 | 风险 |
|----------|------|------|----------|------|
| **文件级** | 单个 .j2 文件 | `git checkout OLD_HASH -- file.j2` | 秒级 | 单个文件回滚可能与其他文件不兼容 |
| **渲染级** | `renderer.version` | 切换到旧版本号 | 秒级 | 旧版本可能缺失新功能 |
| **全量级** | 整个 prompt 仓库 | `git revert COMMIT_HASH` | 分钟级 | 完全恢复到旧状态 |

**推荐策略**：优先使用**渲染级回滚**——保留最新的模板文件，但将 `renderer.version` 切回旧版本号。这样可以快速恢复，同时保留问题排查的线索。

## 六、模板性能优化

### 6.1 缓存编译结果

Jinja2 支持缓存编译后的模板，避免重复解析：

```python
from jinja2 import Environment, FileSystemLoader
from jinja2 import BytecodeCache

class PromptBytecodeCache(BytecodeCache):
    """将编译后的模板字节码缓存到磁盘"""
    def __init__(self, cache_dir: str = ".jinja_cache"):
        self.cache_dir = Path(cache_dir)
        self.cache_dir.mkdir(parents=True, exist_ok=True)

    def load_bytecode(self, bucket):
        path = self.cache_dir / f"{bucket.key}.bc"
        if path.exists():
            with open(path, "rb") as f:
                bucket.bytecode = f.read()

    def dump_bytecode(self, bucket):
        path = self.cache_dir / f"{bucket.key}.bc"
        with open(path, "wb") as f:
            f.write(bucket.bytecode)

# 使用字节码缓存
env = Environment(
    loader=FileSystemLoader("prompts"),
    bytecode_cache=PromptBytecodeCache(),
)
```

### 6.2 渲染时间与 Token 的权衡

| 优化策略 | 渲染时间减少 | Token 数影响 | 适用场景 |
|----------|-------------|-------------|----------|
| 字节码缓存 | 30-50% | 不变 | 频繁渲染同一模板 |
| 减少 include 层级 | 10-20% | 不变 | include 嵌套过深 |
| 移除未使用的宏 | 5-10% | 不变 | 模板文件积累过多宏 |
| 条件渲染合并 | 5-15% | 可能增加 | 多个相似的条件分支 |
