# 24.10 多模型协同路由平衡难

> 现象：为了平衡成本和效果，系统使用多个模型（大模型+小模型）协同工作。但任务-模型匹配策略不当导致"该用小模型的用了大模型"（成本翻倍）或"该用大模型的用了小模型"（质量下降）。错误的决策基准和滞后的监控使平衡更加困难。

---

## 一、症状描述

### 1.1 两种失败模式

**失败模式 A：大材小用（成本翻倍）**

某 Agent 系统使用了"全部路由到大模型"的简单策略：

```yaml
# ❌ 简单粗暴的路由策略
route:
  default: "claude-sonnet-4-20250514"  # 所有请求都走大模型
```

成本分析：

```
月请求量: 500 万
月成本: $18,500

分析显示：
- 65% 的请求可以用小模型（claude-haiku）处理，质量无差异
- 优化后可节省 60% 成本 → 月成本降至 $7,400
- 年化节省: $133,200
```

**失败模式 B：小马拉大车（质量下降）**

另一个极端——为了省钱，所有请求强制使用小模型：

```yaml
# ❌ 另一个极端的路由策略
route:
  default: "claude-haiku-4-20250514"  # 所有请求强制用小模型
```

质量分析：

```
工具选择准确率: 92% → 78%（下降 14%）
复杂推理成功率: 88% → 62%（下降 26%）
用户投诉率: 2.1% → 5.8%（上升 176%）
客户流失率（推理相关）: 月均 0.5% → 月均 1.8%
```

### 1.2 动态路由的"抖动"问题

即使实现了动态路由，还面临"抖动"问题——同一个用户在同一个对话中，被反复路由到不同模型：

```
用户输入 1 → 路由判断 → 小模型（正确识别为简单查询）
用户输入 2 → 路由判断 → 大模型（识别为复杂查询，但实际不复杂）
用户输入 3 → 路由判断 → 小模型（又变回来了）
```

模型切换导致：
1. 回答风格不一致（小模型简短、大模型详细）
2. 上下文缓存无法复用（不同模型有不同的缓存）
3. 用户体验割裂感

### 1.3 生产数据

根据 2025 年对 50 个生产 Agent 系统的调研：

| 路由策略 | 月成本（百万请求） | 任务成功率 | 用户体验评分 |
|---------|-----------------|-----------|------------|
| 全部大模型 | $18,500 | 96.5% | 4.2/5 |
| 全部小模型 | $3,200 | 82.3% | 3.1/5 |
| 基于规则路由 | $7,800 | 91.2% | 3.8/5 |
| ML 动态路由 | $8,200 | 93.5% | 4.0/5 |

**结论**：好的路由策略可以在成本降低 55% 的同时保持 93%+ 的质量。但"好的路由策略"是动态的、需要持续优化的，而非一次性决策。

## 二、根因分析

### 2.1 路由决策的信息不足

大多数路由系统只基于"请求长度"或"关键词"做路由：

```python
# ❌ 信息不足的路由决策
def route_request(user_input: str) -> str:
    if len(user_input) > 200:
        return "large_model"  # 仅基于输入长度
    elif "分析" in user_input or "为什么" in user_input:
        return "large_model"  # 仅基于关键词
    else:
        return "small_model"
```

这种简单规则无法捕捉任务的真实复杂度：

```python
# 短但复杂的查询
"DROP TABLE users; 这条 SQL 会有什么影响？"
# 很短，但需要大模型的安全推理能力

# 长但简单的查询
"你好，我想问问如果我的订单已经发货了，但是我一直没有收到，我该怎么办呢？我查了一下物流信息显示已经签收了，但是我没有收到货。"
# 很长，但只是简单的物流咨询，小模型完全可以处理
```

### 2.2 冷启动问题

新模型发布时，路由策略需要重新调整：

```
旧模型: claude-sonnet-3
新模型: claude-sonnet-4

问题：
1. 新模型能力更强，但成本也可能不同
2. 原本需要大模型的任务，新模型的小版本即可胜任
3. 路由策略需要"学习"新模型的能力边界
4. 学习期间（1-2 周）可能做出较差的路由决策
```

### 2.3 任务复杂度的"渐进性"

任务复杂度不是二元的（简单/复杂），而是渐进的：

```
直观的认知：
简单任务 ←──────────────→ 复杂任务

实际分布：
                      
                      /\
                     /  \
                    /    \
                   / 中等  \
                  /  任务   \
                 /  (60%)    \
                /              \
          简单任务(25%)    复杂任务(15%)
```

大多数任务是"中等复杂度"的——既可以用小模型处理（但质量一般），也可以用大模型（但浪费成本）。

**中等复杂度任务的路由决策是最难的**，因为两个选择都有合理的理由。

### 2.4 缺乏反馈闭环

大多数路由系统是开环的——路由决策做出后，没有反馈信号来验证决策是否正确：

```
❌ 开环路由：
用户输入 → 路由决策 → 模型执行 → 结束（没有反馈）

✅ 闭环路由：
用户输入 → 路由决策 → 模型执行 → 质量评估 → 反馈更新路由策略
```

没有闭环反馈，路由策略无法自我优化。坏的路由决策会被重复执行。

## 三、检测方法

### 3.1 路由混淆矩阵

```python
def build_routing_confusion_matrix(logs: list[dict]) -> dict:
    """
    构建路由混淆矩阵。
    
    分析：
    - 哪些请求被路由到了"错误"的模型？
    - 被路由到大模型但小模型也能处理的请求比例（成本浪费）
    - 被路由到小模型但实际需要大模型的请求比例（质量损失）
    """
    matrix = {
        "correct_routes": 0,
        "overkill": {  # 大材小用
            "count": 0,
            "wasted_cost": 0,
            "examples": []
        },
        "underpowered": {  # 小马拉大车
            "count": 0,
            "quality_loss": 0,
            "examples": []
        }
    }
    
    for log in logs:
        actual_model = log["model_used"]
        required_level = log["required_level"]  # 人工标注或事后评估
        
        if actual_model == required_level:
            matrix["correct_routes"] += 1
        elif actual_model == "large" and required_level == "small":
            matrix["overkill"]["count"] += 1
            matrix["overkill"]["wasted_cost"] += (
                log["large_model_cost"] - log["small_model_cost"]
            )
        elif actual_model == "small" and required_level == "large":
            matrix["underpowered"]["count"] += 1
            matrix["underpowered"]["quality_loss"] += (
                log["expected_quality"] - log["actual_quality"]
            )
    
    return matrix
```

### 3.2 路由效率指标

```yaml
指标: routing_cost_efficiency (gauge)
  定义: 实际成本 / 最优成本（如果所有路由决策都正确）
  说明: > 1.5 → 存在严重的大材小用
  
指标: routing_quality_efficiency (gauge)
  定义: 实际质量 / 最优质量（如果所有路由决策都正确）  
  说明: < 0.9 → 存在严重的小马拉大车

指标: routing_consistency (gauge)
  定义: 同一对话中模型切换频率
  说明: > 3 次/对话 → 路由抖动，需要对话级路由而非请求级
```

## 四、解决方案

### 4.1 分层路由策略

```python
class HierarchicalRouter:
    """
    分层路由策略。
    
    第一层：意图分类（确定任务类型）
    第二层：复杂度评估（确定任务难度）
    第三层：成本-质量权衡（做出路由决策）
    """
    def __init__(self):
        self.intent_classifier = self._load_intent_classifier()
        self.complexity_estimator = self._load_complexity_estimator()
        
        # 路由策略配置
        self.cost_quality_tradeoff = {
            "simple_factoid": {"model": "haiku", "cost_weight": 0.8},
            "complex_reasoning": {"model": "sonnet", "quality_weight": 0.8},
            "tool_calling": {"model": "sonnet", "quality_weight": 0.7},
            "creative_generation": {"model": "sonnet", "cost_weight": 0.5},
            "sentiment_analysis": {"model": "haiku", "cost_weight": 0.9},
            "summarization": {"model": "haiku", "cost_weight": 0.7},
        }
    
    def route(self, user_input: str, context: dict = None) -> RouteDecision:
        """做出路由决策"""
        # 第 1 层：意图分类
        intent = self._classify_intent(user_input)
        
        # 第 2 层：复杂度评估
        complexity = self._estimate_complexity(user_input, intent)
        
        # 第 3 层：路由决策
        if complexity > 0.7:
            # 高复杂度 → 必须大模型
            model = self._select_best_model(intent)
            confidence = 0.9
        elif complexity < 0.3:
            # 低复杂度 → 小模型即可
            model = self.cost_quality_tradeoff[intent]["model"]
            confidence = 0.8
        else:
            # 中等复杂度 → 动态权衡
            model, confidence = self._tradeoff(intent, complexity)
        
        return RouteDecision(
            model=model,
            confidence=confidence,
            intent=intent,
            complexity=complexity
        )
    
    def _estimate_complexity(self, user_input: str, intent: str) -> float:
        """评估任务复杂度（0.0 - 1.0）"""
        signals = []
        
        # 信号 1：长度
        signals.append(min(len(user_input) / 500, 1.0) * 0.15)
        
        # 信号 2：推理关键词
        reasoning_keywords = ["为什么", "如何", "如果", "分析", "比较",
                             "推理", "原因", "影响", "假设", "证明"]
        reasoning_density = sum(1 for kw in reasoning_keywords if kw in user_input)
        signals.append(min(reasoning_density / 3, 1.0) * 0.35)
        
        # 信号 3：多步指令
        multi_step = user_input.count("，") + user_input.count("。") > 3
        signals.append(0.3 if multi_step else 0.0)
        
        # 信号 4：工具调用需求
        tool_keywords = ["查询", "修改", "删除", "创建", "更新"]
        has_tool = any(kw in user_input for kw in tool_keywords)
        signals.append(0.2 if has_tool else 0.0)
        
        return min(sum(signals), 1.0)
    
    def _select_best_model(self, intent: str) -> str:
        """为高复杂度任务选择最佳模型"""
        if intent in ["complex_reasoning", "tool_calling"]:
            return "claude-sonnet-4-20250514"
        return "claude-haiku-4-20250514"
```

### 4.2 对话级路由（而非请求级）

解决"路由抖动"问题——在同一对话中路由到同一个模型：

```python
class ConversationLevelRouter:
    """
    对话级路由：整个对话使用同一个模型。
    避免请求级路由导致的模型切换抖动。
    """
    def __init__(self):
        self.conversation_assignments: dict[str, str] = {}
    
    def route_conversation(self, conversation_id: str, 
                            first_input: str) -> str:
        """
        对话开始时做出路由决策，后续请求沿用同一模型。
        """
        if conversation_id in self.conversation_assignments:
            return self.conversation_assignments[conversation_id]
        
        # 基于首轮输入做路由
        # 首轮输入通常最能反映任务的复杂度
        router = HierarchicalRouter()
        decision = router.route(first_input)
        
        assigned_model = decision.model
        self.conversation_assignments[conversation_id] = assigned_model
        
        return assigned_model
    
    def clear_conversation(self, conversation_id: str):
        """对话结束后清除路由记录"""
        self.conversation_assignments.pop(conversation_id, None)
```

### 4.3 成本-质量预算管理

```python
class CostQualityBudget:
    """
    成本-质量预算管理器。
    在月度预算约束下优化模型路由决策。
    """
    def __init__(self, monthly_budget: float):
        self.monthly_budget = monthly_budget
        self.monthly_cost = 0
        self.quality_score = 0
        self.request_count = 0
    
    def can_afford(self, model: str, estimated_quality_gain: float) -> bool:
        """
        判断在当前预算约束下是否"买得起"某模型。
        
        预算紧张时 → 只在高质量增益时使用大模型
        预算充裕时 → 可适当放宽
        """
        model_cost = self._get_model_cost(model)
        
        if self.monthly_cost + model_cost > self.monthly_budget:
            # 预算已满 → 必须用小模型
            return False
        
        remaining_budget = self.monthly_budget - self.monthly_cost
        remaining_requests_estimate = max(10000 - self.request_count, 1)
        
        avg_cost_per_request = remaining_budget / remaining_requests_estimate
        
        # 如果这个请求的成本远高于平均预算，需要有足够的质量增益
        quality_threshold = model_cost / avg_cost_per_request
        
        return estimated_quality_gain >= quality_threshold
    
    def record_usage(self, model: str, quality: float):
        """记录一次路由使用"""
        self.monthly_cost += self._get_model_cost(model)
        self.quality_score = (
            (self.quality_score * self.request_count + quality) 
            / (self.request_count + 1)
        )
        self.request_count += 1
```

### 4.4 路由策略自动优化

```python
class AutoRouterOptimizer:
    """
    路由策略自动优化器。
    基于历史路由决策和事后审计，持续优化路由规则。
    """
    def __init__(self):
        self.rules: list[RoutingRule] = []
        self.feedback_history: list[Feedback] = []
    
    def optimize(self):
        """定期优化路由规则"""
        if len(self.feedback_history) < 1000:
            return  # 数据不足
        
        # 1. 分析路由错误模式
        wrong_decisions = [
            f for f in self.feedback_history 
            if not f.correct
        ]
        
        for wrong in wrong_decisions:
            # 2. 学习正确的路由模式
            new_rule = self._learn_rule_from_feedback(wrong)
            if new_rule:
                self.rules.append(new_rule)
        
        # 3. 淘汰低效规则
        self._prune_ineffective_rules()
        
        # 4. 评估优化效果
        current_accuracy = self._evaluate_routing_accuracy()
        logging.info(f"Routing accuracy after optimization: {current_accuracy:.2%}")
    
    def _learn_rule_from_feedback(self, feedback: Feedback) -> RoutingRule:
        """从路由错误中学习新规则"""
        if feedback.actual_model == "large" and feedback.correct_model == "small":
            # 过度路由 → 学习"这类请求小模型就够了"
            return RoutingRule(
                pattern=self._extract_pattern(feedback.input),
                recommended_model="small",
                confidence=0.6,
                source="feedback_overkill"
            )
        elif feedback.actual_model == "small" and feedback.correct_model == "large":
            # 路由不足 → 学习"这类请求需要大模型"
            return RoutingRule(
                pattern=self._extract_pattern(feedback.input),
                recommended_model="large",
                confidence=0.7,
                source="feedback_underpowered"
            )
```

### 4.5 兜底策略：渐进式升级

当路由不确定时，使用"先小模型，不满意升级"的策略：

```python
class ProgressiveRouter:
    """
    渐进式路由：先用小模型，检测到质量不达标时升级到大模型。
    这样可以避免"小马拉大车"的问题，同时最大程度节省成本。
    """
    def __init__(self):
        self.small_model = "claude-haiku-4-20250514"
        self.large_model = "claude-sonnet-4-20250514"
    
    def route_with_escalation(self, user_input: str) -> str:
        """先尝试小模型，必要时升级"""
        # 第一步：用小模型
        haiku_response = self._call_model(self.small_model, user_input)
        
        # 第二步：自评估质量
        quality_score = self._self_evaluate_quality(
            user_input, haiku_response
        )
        
        if quality_score > 0.8:
            # 小模型质量已够
            return haiku_response
        
        # 第三步：升级到大模型
        logging.info(f"Escalating to large model (quality={quality_score:.2f})")
        sonnet_response = self._call_model(self.large_model, user_input)
        
        return sonnet_response
    
    def _self_evaluate_quality(self, user_input: str, 
                                 response: str) -> float:
        """自评估小模型输出的质量"""
        eval_prompt = f"""
任务: {user_input}
回答: {response}

请评估该回答的质量（0-1.0），考虑：
- 准确度：是否完全正确？
- 完整性：是否涵盖了所有的要点？
- 清晰度：是否清晰易懂？

只输出一个 0-1.0 的数字。
"""
        score_text = self._call_model(self.small_model, eval_prompt)
        try:
            return float(score_text.strip())
        except:
            return 0.5  # 无法评估时保守升级
```

class ABRouter:
    """
    A/B 测试路由策略。
    按百分比分配流量到不同的路由策略，比较效果。
    """
    def __init__(self, strategy_a: Router, strategy_b: Router, 
                 b_percentage: float = 0.1):
        self.strategy_a = strategy_a
        self.strategy_b = strategy_b
        self.b_percentage = b_percentage
        
        self.metrics_a = {"cost": 0, "quality": 0, "count": 0}
        self.metrics_b = {"cost": 0, "quality": 0, "count": 0}
    
    def route(self, user_input: str) -> tuple[str, str]:
        """随机分配到 A 或 B 策略"""
        if random.random() < self.b_percentage:
            metrics = self.metrics_b
            strategy = self.strategy_b
            variant = "B"
        else:
            metrics = self.metrics_a
            strategy = self.strategy_a
            variant = "A"
        
        result = strategy.route(user_input)
        # ... 记录指标 ...
        
        return result, variant

## 关键教训速查

| 教训 | 说明 |
|------|------|
| "全部用大模型"和"全部用小模型"都是错的 | 前者成本翻倍，后者质量下降 |
| 路由信息不足是根因 | 简单规则无法捕捉任务真实复杂度 |
| 中等复杂度任务（60%）最难路由 | 小模型和大模型都有合理理由 |
| 对话级路由优于请求级路由 | 避免同一对话中的模型切换抖动 |
| 闭环反馈是路由优化的基础 | 没有反馈，路由策略无法自我优化 |
| 渐进式升级是安全的兜底策略 | 先小模型，自评估不过关时升级到大的 |
| 定期评估 + A/B 测试持续优化 | 路由策略不是一次性的，需要持续调整 |
