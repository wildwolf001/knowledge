# 24.9 缺少"我已尝试过什么"跟踪 —— Agent 原地打转

> 现象：Agent 反复调用同样的工具、尝试同样的方案，期望不同的结果——但没有记录"我已经尝试过什么"。每次"又试一次"看起来都像是一个新的合理决策，但整体上 Agent 在原地打转。

---

## 一、症状描述

### 1.1 经典场景

某 DevOps Agent 在处理"部署失败"的故障排查时：

```
步骤 1  → 检查服务状态 → 返回 "服务运行中"
步骤 2  → 检查服务状态 → 返回 "服务运行中"  ← 又查了一次
步骤 3  → 检查服务状态 → 返回 "服务运行中"  ← 再查一次
步骤 4  → 检查日志 → 返回 "无异常日志"
步骤 5  → 检查服务状态 → 返回 "服务运行中"  ← 又回来了
步骤 6  → 检查日志 → 返回 "无异常日志"  ← 又查日志
...（持续 20+ 步，循环在 "查状态 → 查日志" 之间切换）
```

每一步看起来都是合理的——"让我确认一下当前状态"。但整体来看，Agent 完全没有进展，只是在反复确认同样的信息。

### 1.2 三个层次的"原地打转"

**层次 1：同一工具反复调用**

```python
# 日志中的模式
actions = [
    ("get_server_status", {"server": "prod-01"}),
    ("get_server_status", {"server": "prod-01"}),  # 重复
    ("get_server_status", {"server": "prod-01"}),  # 重复
    ("get_server_status", {"server": "prod-02"}),  # 稍微换个参数
    ("get_server_status", {"server": "prod-01"}),  # 又回来
]
```

**层次 2：同一策略反复尝试**

```
尝试方案 A → 失败 → 尝试方案 B → 失败 → 回到方案 A → 失败 → 又回到方案 B
```

Agent 没有记录"方案 A 已经试过且没有效果"，所以当它再次"想到"方案 A 时，认为这是一个新的好主意。

**层次 3：没有维度提升**

Agent 在同一个"维度"（如"检查状态"）上反复操作，但没有能力意识到"在这个维度上我已经穷尽了所有可能性，需要换一个维度思考"。

### 1.3 生产数据

根据 2024 年对 100 个生产 Agent 的日志分析：

| Agent 类型 | 平均无效重复率 | 平均"原地打转"步数 | 额外 Token 消耗 |
|-----------|-------------|-----------------|---------------|
| 客服 Agent | 12-18% | 4-8 步 | 15K-30K/对话 |
| DevOps Agent | 18-25% | 6-12 步 | 25K-50K/对话 |
| 数据分析 Agent | 8-15% | 3-6 步 | 10K-25K/对话 |
| 代码生成 Agent | 5-10% | 2-4 步 | 8K-15K/对话 |

**DevOps Agent 的无效重复率高达 18-25%**——每 4-5 步就有 1 步是无效重复。

## 二、根因分析

### 2.1 核心问题：Agent 缺乏"尝试元记忆"

Agent 的每一步决策基于当前上下文，但上下文中的"历史记录"是隐式的——模型需要从大量文本中自行推断"哪些方案已经尝试过"。

问题是：**这种推断本身不可靠**。当上下文长度增长、注意力分散时，模型可能"忘记"自己已经尝试过某个方案。

```
标准的 Agent 循环：

while True:
    context = system_prompt + chat_history + tool_results  # 隐式历史
    action = llm.select_action(context)    # 需要自己从历史中推断"做过什么"
    execute(action)
    
这里缺失了：一个显式的、结构化的"已尝试"记录
```

### 2.2 "再试一次"的合理性陷阱

从单个步骤看，"再试一次"往往有合理的理由：

```python
# Agent 的内部推理（thought）
step_5_thought = """
我检查了服务状态，正常。让我再检查一次，
因为可能是缓存延迟导致状态未实时更新。
"""
# 看起来合理 ✅

step_7_thought = """
服务状态仍然正常，但错误还在。让我再检查一次日志，
也许刚才的日志没刷新完全。
"""
# 也合理 ✅

# 但从整体看，Agent 陷入了 "查状态 → 查日志" 的无限循环
```

每个单步决策都合理，但整体是循环。这是**局部最优但不是全局最优**的典型表现。

### 2.3 失败模式缺乏学习

经典 Agent 循环中，失败的尝试不会改变后续的决策策略：

```python
# 当前状态：没有"从失败中学习"
attempts = []

def select_action(context):
    # 每次都基于相同的策略做选择
    return llm.select(context)

# 理想状态：有"从失败中学习"
def select_action(context, attempts):
    # 排除已尝试过的方案
    exclude = [a for a in attempts if a.result == "FAILED"]
    return llm.select(context, exclude=exclude)
```

缺少"失败排除"机制（Failure Exclusion），导致 Agent 可以反复尝试已证明无效的方案。

## 三、检测方法

### 3.1 重复调用检测

```python
def detect_repeated_calls(step_history: list[dict], 
                           window: int = 5) -> list[dict]:
    """
    检测给定窗口内的重复工具调用。
    """
    repeats = []
    
    for i in range(len(step_history) - window + 1):
        segment = step_history[i:i+window]
        tool_names = [s["tool_name"] for s in segment]
        
        # 检测完全重复
        if len(set(tool_names)) == 1 and len(tool_names) >= 3:
            repeats.append({
                "type": "SAME_TOOL",
                "tool": tool_names[0],
                "start_step": i,
                "length": window,
                "description": f"连续 {window} 步调用同一工具 {tool_names[0]}"
            })
            continue
        
        # 检测交替重复 (A-B-A-B)
        if len(set(tool_names)) == 2:
            is_alternating = all(
                tool_names[j] == tool_names[j % 2] 
                for j in range(window)
            )
            if is_alternating:
                repeats.append({
                    "type": "ALTERNATING",
                    "tools": list(set(tool_names)),
                    "start_step": i,
                    "length": window,
                    "description": f"{tool_names[0]} ↔ {tool_names[1]} 交替"
                })
    
    return repeats
```

### 3.2 方案多样性指数

量化 Agent 尝试的策略多样性：

```python
def strategy_diversity_score(actions: list[dict]) -> float:
    """
    计算 Agent 策略的多样性指数。
    
    0.0 = 完全重复（所有动作都一样）
    1.0 = 完全多样（没有重复动作）
    
    低于 0.3 = Agent 大概率在打转
    """
    if not actions:
        return 1.0
    
    unique_tools = set(a["tool_name"] for a in actions)
    
    # 工具多样性
    tool_diversity = len(unique_tools) / max(len(actions), 1)
    
    # 参数多样性（对同一工具的参数变化）
    param_diversity = 0
    for tool in unique_tools:
        tool_actions = [a for a in actions if a["tool_name"] == tool]
        param_sets = set(
            tuple(sorted(a.get("parameters", {}).items()))
            for a in tool_actions
        )
        param_diversity += len(param_sets) / max(len(tool_actions), 1)
    param_diversity /= max(len(unique_tools), 1)
    
    return 0.5 * tool_diversity + 0.5 * param_diversity
```

### 3.3 监控指标

```yaml
指标: agent_attempt_reuse_ratio (gauge)
  定义: 与已尝试过的方案完全相同的调用 / 总调用
  告警: > 20% → warning
        > 40% → critical

指标: agent_strategy_diversity (gauge)
  定义: 策略多样性指数
  告警: < 0.3 → critical（Agent 可能进入循环）

指标: agent_dimension_exhaustion (gauge)
  定义: Agent 是否在一个维度上反复操作而没有切换
  告警: 连续 10 步在同一分类下 → warning
```

## 四、解决方案

### 4.1 Attempt Tracker（已尝试跟踪器）

解决方案 24.1 中已经介绍了基本方案。这里给出增强版本：

```python
class EnhancedAttemptTracker:
    """
    增强版已尝试跟踪器。
    除了记录"尝试过什么"，还记录"为什么失败"和"还有什么可试"。
    """
    def __init__(self, tool_registry: dict):
        self.attempts: list[Attempt] = []
        self.tool_registry = tool_registry
    
    def record(self, tool_name: str, params: dict, 
               result: Any, thought: str):
        """记录一次尝试"""
        self.attempts.append(Attempt(
            tool_name=tool_name,
            params=params,
            result=result,
            thought=thought,
            success=self._is_success(result),
            timestamp=time.time()
        ))
    
    def get_exclusion_list(self) -> list[str]:
        """
        获取已尝试过且失败的方案列表。
        这些方案应该被排除在后续选择之外。
        """
        failed = [
            a for a in self.attempts 
            if not a.success 
            and self._is_recent(a)  # 只考虑最近的失败
        ]
        
        return [
            f"{a.tool_name}({self._param_summary(a.params)})" 
            for a in failed
        ]
    
    def get_suggested_approaches(self) -> list[str]:
        """
        建议尚未尝试过的方向。
        基于已尝试的方案，反向推断"还有什么没试过"。
        """
        tried_tools = set(a.tool_name for a in self.attempts)
        all_tools = set(self.tool_registry.keys())
        untried_tools = all_tools - tried_tools
        
        # 进一步：在同类别中找替代工具
        suggestions = []
        for tool in untried_tools:
            if self._is_related_to_current_problem(tool):
                suggestions.append(tool)
        
        return suggestions
    
    def to_context_prompt(self) -> str:
        """生成注入 Agent 上下文的提示"""
        if not self.attempts:
            return ""
        
        lines = ["【已尝试记录】"]
        for i, att in enumerate(self.attempts[-8:], 1):  # 最近 8 条
            status = "✓" if att.success else "✗" 
            lines.append(f"  {i}. [{status}] {att.tool_name} "
                        f"→ {'成功' if att.success else '失败: ' + str(att.result)[:50]}")
        
        excluded = self.get_exclusion_list()
        if excluded:
            lines.append(f"\n【已失败且不应重复的方案】")
            for e in excluded:
                lines.append(f"  - {e}")
        
        suggestions = self.get_suggested_approaches()
        if suggestions:
            lines.append(f"\n【尚未尝试的相关工具】")
            for s in suggestions[:5]:
                lines.append(f"  - {s}")
        
        lines.append("\n⚠️ 如果以上所有方案都已尝试，请返回当前最佳结果或请求人工介入。")
        
        return "\n".join(lines)
```

### 4.2 维度切换检测器

当 Agent 在一个维度上停留太久时，"推"它换一个维度：

```python
class DimensionSwitcher:
    """
    维度切换器。
    当 Agent 在同一个维度（如"检查"）上反复操作时，
    建议切换到另一个维度（如"修复"）。
    """
    DIMENSIONS = {
        "diagnose": {
            "keywords": ["检查", "查看", "查询", "状态", "日志", "check", "status"],
            "suggested_switch": "fix"
        },
        "fix": {
            "keywords": ["修复", "重启", "更新", "重置", "restart", "update"],
            "suggested_switch": "verify"
        },
        "verify": {
            "keywords": ["确认", "验证", "verify", "confirm"],
            "suggested_switch": "diagnose"
        }
    }
    
    def detect_stuck(self, recent_steps: list[dict]) -> bool:
        """检测 Agent 是否在一个维度上卡住"""
        if len(recent_steps) < 5:
            return False
        
        current_dimension = self._classify_dimension(recent_steps[-1])
        dimension_steps = sum(
            1 for step in recent_steps[-5:]
            if self._classify_dimension(step) == current_dimension
        )
        
        return dimension_steps >= 4  # 5 步中有 4 步在同一维度
    
    def get_switch_suggestion(self, recent_steps: list[dict]) -> str:
        """生成维度切换建议"""
        current_dim = self._classify_dimension(recent_steps[-1])
        
        if current_dim in self.DIMENSIONS:
            suggested = self.DIMENSIONS[current_dim]["suggested_switch"]
            return (
                f"⚠️ 你已在「{current_dim}」维度上进行了多次尝试。"
                f"建议切换到「{suggested}」维度尝试不同的方法。"
            )
        
        return ""
    
    def _classify_dimension(self, step: dict) -> str:
        """将步骤分类到维度"""
        thought = step.get("thought", "").lower()
        tool_name = step.get("tool_name", "").lower()
        text = thought + " " + tool_name
        
        best_dim = "unknown"
        best_score = 0
        
        for dim, config in self.DIMENSIONS.items():
            score = sum(1 for kw in config["keywords"] if kw in text)
            if score > best_score:
                best_score = score
                best_dim = dim
        
        return best_dim
```

### 4.3 思维链中的"排除法"注入

在 Agent 的推理提示中增加结构化排除：

```python
def build_action_selection_prompt(
    attempts: list[Attempt],
    available_tools: list[ToolDef]
) -> str:
    """
    构建包含"排除法"的行动选择提示。
    """
    prompt = "请选择下一步操作。注意以下规则：\n\n"
    
    # 规则 1：已失败的不重复
    failed = [a for a in attempts if not a.success]
    if failed:
        prompt += "【已失败的方案（不要重复）】\n"
        for a in failed[-5:]:
            prompt += f"- {a.tool_name}: {a.thought[:50]}...\n"
        prompt += "\n"
    
    # 规则 2：已成功的不需要再做
    succeeded = [a for a in attempts if a.success]
    if succeeded:
        prompt += "【已成功的方案（已完成，不需要再做）】\n"
        for a in succeeded[-3:]:
            prompt += f"- {a.tool_name}: 已完成\n"
        prompt += "\n"
    
    # 规则 3：建议的新方案
    prompt += "【可用的新方案】\n"
    tried_tools = set(a.tool_name for a in attempts)
    new_tools = [t for t in available_tools if t.name not in tried_tools]
    for t in new_tools[:10]:
        prompt += f"- {t.name}: {t.description}\n"
    
    if not new_tools:
        prompt += "所有可用方案已尝试完毕。请返回当前最佳结果。\n"
    
    return prompt
```

### 4.4 终止条件

TERMINATION_CONDITIONS = """

1. 所有可用工具都已尝试过 → 返回当前最佳结果

终止不是失败——在无法解决问题时优雅地返回当前进度，
比强行编造一个结果要好得多。
"""

## 五、预防措施

### 5.1 显式"尝试预算"

为 Agent 设定每次对话的"尝试预算"：

```python
class AttemptBudget:
    """
    尝试预算：限制 Agent 在每个方案上的尝试次数。
    """
    def __init__(self):
        self.budgets = {
            "per_tool": 3,     # 同一工具最多尝试 3 次
            "per_strategy": 2, # 同一策略（同类工具）最多 2 次
            "total": 15,       # 总尝试次数上限
        }
        self.tool_attempts: dict[str, int] = {}
        self.strategy_attempts: dict[str, int] = {}
        self.total_attempts = 0
    
    def can_attempt(self, tool_name: str, strategy: str) -> bool:
        """检查是否还有尝试预算"""
        if self.total_attempts >= self.budgets["total"]:
            return False
        if self.tool_attempts.get(tool_name, 0) >= self.budgets["per_tool"]:
            return False
        if self.strategy_attempts.get(strategy, 0) >= self.budgets["per_strategy"]:
            return False
        return True
    
    def consume(self, tool_name: str, strategy: str):
        """消耗一次尝试预算"""
        self.tool_attempts[tool_name] = self.tool_attempts.get(tool_name, 0) + 1
        self.strategy_attempts[strategy] = self.strategy_attempts.get(strategy, 0) + 1
        self.total_attempts += 1
```

### 5.2 架构设计：失败模式库

构建运行时"失败模式库"，让 Agent 从中学习：

```python
class FailurePatternLibrary:
    """
    失败模式库：记录常见的失败模式及其解决方案。
    当 Agent 检测到匹配的失败模式时，可以直接参考历史解决方案。
    """
    patterns: list[dict] = []
    
    def learn_from_attempts(self, attempts: list[Attempt]):
        """从失败尝试中学习模式"""
        if len(attempts) < 3:
            return
        
        # 检测常见模式
        if self._is_repeated_tool_failure(attempts):
            pattern = {
                "type": "TOOL_NOT_HELPING",
                "signature": "同一工具收到相同结果 3+ 次",
                "solution": "换用不同工具或转换维度",
            }
            self.patterns.append(pattern)
    
    def query_similar_patterns(self, current_state: dict) -> list[dict]:
        """查询匹配当前状态的已知失败模式"""
        matching = []
        for pattern in self.patterns:
            if self._pattern_matches(pattern, current_state):
                matching.append(pattern)
        return matching
```

## 关键教训速查

| 教训 | 说明 |
|------|------|
| Agent 天然缺乏"尝试记忆" | 标准 Agent 循环不追踪"什么已经试过" |
| 再试一次往往看起来合理 | 单步决策合理，整体可能是循环 |
| 18-25% 的 DevOps Agent 调用是无效重复 | 客服和 DevOps Agent 尤为严重 |
| Attempt Tracker 是核心方案 | 显式记录已尝试的方案和结果 |
| 维度切换检测防止打转 | 在同一个维度停留太久时推一把 |
| 尝试预算限制资源消耗 | 每工具/每策略/总体的尝试次数上限 |
| 失败模式库积累经验 | 从历史失败中学习模式 |
