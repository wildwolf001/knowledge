# 24.3 工具选择错误 —— 100+ 工具全部暴露、名称相似的函数互相干扰

> 现象：Agent 在 100+ 个工具中选择错误工具，名称相似的函数之间存在严重的互相干扰。不是模型能力问题，而是工具注册和暴露策略的设计缺陷。

---

## 一、症状描述

### 1.1 典型场景

某数据分析 Agent 注册了 120+ 个工具。上线后，团队发现 Agent 经常调用错误的工具：

```
用户: "查询上个月的用户留存率"

❌ Agent 调用: get_daily_active_users(date_range="last_month")
   → 返回 DAU 数据
   → 错误：用户要的是留存率，不是活跃用户数

✅ 应该调用: calculate_user_retention(start_date="2025-04-01", end_date="2025-04-30")
```

类似错误在 A/B 测试中频繁出现：

| 用户问题 | Agent 选择的工具 | 正确的工具 | 频率 |
|---------|-----------------|-----------|------|
| "查询上个月留存" | `get_daily_active_users` | `calculate_user_retention` | 23% |
| "创建新用户 Campaign" | `create_email_campaign` | `create_user_segment_campaign` | 18% |
| "导出销售报表" | `export_sales_summary` | `export_sales_detail_report` | 15% |
| "更新产品库存" | `update_product_stock` | `batch_update_inventory` | 12% |

### 1.2 工具选择错误的分类

生产环境中工具选择错误可分为四类：

**类型 1：相似名称干扰** 
两个工具名称过于相似（`send_email` vs `send_email_reminder`），模型混淆其功能边界。

**类型 2：功能重叠混淆**
多个工具实现类似功能（`search_user_by_email`、`search_user_by_phone`、`search_user_by_id`），模型选了功能正确但输入不匹配的工具。

**类型 3：粒度不匹配**
用户请求是"汇总级别的"，但 Agent 选择了"明细级别的"工具，或者反过来。例如用户问"总销售额"，Agent 却调用了 `get_daily_sales_breakdown`。

**类型 4：上下文误导**
工具名称在特定上下文中看起来合理。比如用户提到"退款"，Agent 可能选择 `process_refund` 而不是正确的 `create_refund_request`（前者是直接退款，后者是创建退款申请单——两个完全不同的业务流程）。

### 1.3 生产数据

根据 2024 年 Berkeley 对 50 个生产 Agent 的研究（"Tool Selection Accuracy in LLM Agents"）：

| 工具集规模 | 工具选择准确率 | Top-3 准确率 |
|-----------|--------------|-------------|
| 10-20 个工具 | 94-97% | 99% |
| 30-50 个工具 | 85-92% | 95-98% |
| 50-100 个工具 | 72-85% | 85-93% |
| 100+ 个工具 | 55-75% | 70-85% |

工具数量超过 50 个后，准确率开始显著下降。超过 100 个后，准确率可能低于 70%——这意味着**每 3 次工具调用就有 1 次选错**。

## 二、根因分析

### 2.1 注意力稀释

当大量工具定义被塞入上下文时，模型对每个工具的关注度被稀释。工具描述在模型注意力机制下的"有效长度"非常有限。

从信息检索的角度理解：在 100+ 个工具中，模型需要从每个工具的 description 字段中提取足够的信息来做选择。但 attention 机制对长序列中"中等重要"的内容关注度呈幂律分布 —— 头部几个最可能的工具占据了大部分注意力，尾部工具几乎被忽略。

### 2.2 名称相似度陷阱

模型在区分相似名称时依赖于嵌入空间的语义距离。当两个工具的功能接近时，它们的嵌入向量也接近：

```
工具 A: "通过邮箱搜索客户"  →  embedding_A
工具 B: "通过手机号搜索客户" →  embedding_B

cosine_similarity(embedding_A, embedding_B) ≈ 0.89  （高度相似！）
```

模型无法有效区分这两个工具，因为它们在语义空间中的位置几乎相同。这是一个**嵌入空间的坍缩问题**。

### 2.3 描述中的冗余信息

工具描述的冗余信息降低了信噪比：

```json
// ❌ 冗余描述
{
  "name": "search_customer_by_email",
  "description": "通过邮箱地址搜索客户信息。输入完整的邮箱地址，返回匹配的客户记录。如果找到多条记录，返回所有匹配项。如果没找到，返回空列表。",
  "parameters": {
    "email": {
      "description": "要搜索的客户邮箱地址，必须是完整的邮箱格式"
    }
  }
}

// ✅ 高效描述 
{
  "name": "search_customer_by_email",
  "description": "按邮箱搜索客户",
  "parameters": {
    "email": {
      "description": "客户邮箱"
    }
  }
}
```

冗长描述中的"填充词"（如果、当、完整的、必须）占据了 attention 的资源，稀释了关键区分信息。

### 2.4 缺乏工具消除选择（Disambiguation）

最根本的原因：系统**没有在架构层面帮助模型做选择**。100+ 个工具平铺在模型面前，把所有选择负担都交给了模型的分类能力。

## 三、检测方法

### 3.1 工具选择混淆矩阵

构建工具选择的混淆矩阵，识别最容易混淆的工具对：

```python
def build_confusion_matrix(tool_selection_logs: list[dict]) -> pd.DataFrame:
    """
    从工具选择日志构建混淆矩阵。
    
    输出示例：
                实际工具
            ┌─────────────────────────────────────────┐
  选择的工具  │           search_by_email  search_by_phone  ...
            ├─────────────────────────────────────────┤
search_by_email  │     234             45
search_by_phone  │      38            198
            ...
    
    高亮：search_by_email ↔ search_by_phone (45+38=83次混淆)
    """
    tools = list(set(
        [log["selected"] for log in tool_selection_logs] +
        [log["expected"] for log in tool_selection_logs]
    ))
    matrix = pd.DataFrame(0, index=tools, columns=tools)
    
    for log in tool_selection_logs:
        matrix.loc[log["selected"], log["expected"]] += 1
    
    return matrix
```

**重点关注**：混淆次数超过总调用次数 5% 的工具对，需要解决。

### 3.2 工具选择熵

计算每次工具选择的"不确定性"：

```python
def tool_selection_entropy(logits: dict[str, float]) -> float:
    """
    计算工具选择的熵值。
    
    高熵（> 2.0）：模型在前几个工具之间犹豫不决，选择不稳定
    低熵（< 0.5）：模型非常确定
    
    持续高熵的工具场景需要人工干预。
    """
    probs = softmax(list(logits.values()))
    entropy = -sum(p * math.log(p) for p in probs if p > 0)
    return entropy
```

### 3.3 自动回归测试

构建工具选择的基准测试集：

```python
TOOL_SELECTION_TESTS = [
    {
        "user_input": "上个月的用户留存率是多少？",
        "expected_tool": "calculate_user_retention",
        "context": {"conversation_type": "analytics"}
    },
    {
        "user_input": "帮我查一下邮箱是 test@example.com 的用户",
        "expected_tool": "search_customer_by_email",
        "context": {}
    },
    ...
]

def test_tool_selection():
    """自动回归测试工具选择准确率"""
    correct = 0
    for test in TOOL_SELECTION_TESTS:
        selected = agent.select_tool(test["user_input"])
        if selected == test["expected_tool"]:
            correct += 1
        else:
            logging.warning(
                f"Tool selection failed: input='{test['user_input']}', "
                f"expected={test['expected_tool']}, got={selected}"
            )
    
    accuracy = correct / len(TOOL_SELECTION_TESTS)
    assert accuracy > 0.9, f"Tool selection accuracy too low: {accuracy:.2%}"
```

将此测试加入 CI/CD pipeline，每次工具注册变更时自动触发。

## 四、解决方案

### 4.1 层级工具菜单（效果最好）

将 100+ 个工具按功能分类，让模型先选类别再选工具。这是 25.4 节「层级工具菜单」的核心思路。

```python
class HierarchicalToolSelector:
    """
    两级工具选择：先选类别 → 再选工具。
    将模型的选择范围从 100+ 缩小到 5-15 个。
    """
    def __init__(self):
        self.category_tree = {
            "用户管理": {
                "description": "用户账号的查询、创建、更新",
                "tools": ["get_user", "search_users", "create_user", 
                         "update_user", "delete_user"]
            },
            "数据分析": {
                "description": "数据查询、报表生成、指标计算",
                "tools": ["calculate_user_retention", "get_daily_active_users",
                         "export_sales_report", "query_data_warehouse"]
            },
            "营销工具": {
                "description": "Campaign 管理、邮件发送、用户分群",
                "tools": ["create_email_campaign", "send_newsletter",
                         "create_user_segment", "schedule_push_notification"]
            },
            ...
        }
    
    def select_tool(self, user_input: str) -> tuple[str, str]:
        """
        两步选择：
        1. 模型从 5-8 个类别中选择
        2. 模型从类别内的 10-15 个工具中选择
        
        选择范围从 100+ → 10-15，准确率从 ~70% → ~95%
        """
        # Step 1: 选类别
        category = self._select_category(user_input)
        # Step 2: 从类别中选工具
        tools = self.category_tree[category]["tools"]
        tool = self._select_tool_from_category(user_input, tools)
        return category, tool
```

**效果数据**：

| 策略 | 工具选择准确率 | Token 消耗（工具描述） |
|------|--------------|---------------------|
| 全部暴露（100+工具） | 72% | 25,000 |
| 层级菜单（8类别×12工具） | 94% | 8,000 |
| 意图驱动（仅加载相关类别） | 96% | 4,000 |

### 4.2 工具名去歧义化

对相似工具进行名称优化，使其在语义空间中更可区分：

```python
class ToolNameDisambiguator:
    """
    工具名称去歧义化。
    核心原则：名称中体现核心差异点。
    """
    def disambiguate(self, tools: list[ToolDef]) -> list[ToolDef]:
        """对有混淆风险的工具重命名"""
        similar_pairs = self._find_similar_tools(tools)
        
        for t1, t2 in similar_pairs:
            # 找到两个工具的核心差异
            diff = self._extract_difference(t1, t2)
            # 将差异嵌入名称
            t1.name = f"{t1.name}__{diff.t1_unique}"
            t2.name = f"{t2.name}__{diff.t2_unique}"
        
        return tools
    
    def _find_similar_tools(self, tools: list[ToolDef]) -> list[tuple]:
        """通过 embedding 余弦相似度找到易混淆的工具对"""
        similarities = []
        for i, t1 in enumerate(tools):
            for t2 in tools[i+1:]:
                sim = cosine_similarity(t1.embedding, t2.embedding)
                if sim > 0.85:  # 阈值可调
                    similarities.append((t1, t2, sim))
        return similarities
```

**命名优化示例**：

| 原始名称 | 混淆率 | 优化后名称 | 混淆率变化 |
|---------|-------|-----------|----------|
| `send_email` / `send_email_reminder` | 22% | `send_email__oneoff` / `send_email__reminder` | 8% |
| `export_sales_summary` / `export_sales_detail` | 15% | `export_sales__summary` / `export_sales__detail` | 5% |
| `search_user_by_email` / `search_user_by_phone` | 18% | `search_user__by_email` / `search_user__by_phone` | 6% |

### 4.3 工具描述的"差异优先"原则

重写工具描述，**第一句就说明该工具与其他工具的区别**：

```python
# ❌ 通用描述
"通过邮箱地址搜索客户信息。输入完整的邮箱地址，返回匹配的客户记录。"

# ✅ 差异优先描述
"【区别于 search_user_by_phone】仅通过邮箱搜索客户。返回精确匹配的客户记录。"
```

工具描述的写作原则：
1. **第一句话**必须是"这个工具和 XXX 的区别是..."
2. **参数描述**只写参数的约束（如"精确匹配"或"模糊匹配"）
3. **删除**所有常识性的说明（如"邮箱必须是完整格式"）

### 4.4 工具选择置信度阈值

设置工具选择的置信度下限，低于阈值时要求 Agent 重新选择：

```python
def confident_tool_selection(user_input: str, tools: list[ToolDef],
                             confidence_threshold: float = 0.7) -> str:
    """
    带置信度检查的工具选择。
    
    < 0.5: 重新选择（模型没有把握）
    0.5-0.7: 要求模型输出"为什么选择这个工具"
    > 0.7: 直接执行
    """
    tool_name, confidence = agent.select_tool_with_confidence(user_input)
    
    if confidence < confidence_threshold:
        # 降低温度重新选择
        tool_name_2, confidence_2 = agent.select_tool_with_confidence(
            user_input, temperature=0.1
        )
        if tool_name != tool_name_2:
            # 两次选择不一致 → 转人工或启用救生筏
            return fallback_to_simpler_toolset(user_input)
    
    return tool_name
```

## 五、预防措施

### 5.1 工具注册审核流程

每次新增工具时，自动检查：

```yaml
工具注册检查清单：
1. ❓ 新工具的名称是否与已有工具相似（cosine > 0.85）？
   → 是：要求修改名称或合并为参数化工具
2. ❓ 新工具的功能是否与已有工具重叠？
   → 是：考虑是否需要新工具，还是扩展现有工具
3. ❓ 工具数量是否已 > 50？
   → 是：必须采用层级菜单策略
4. ❓ 描述中是否包含"差异优先"说明？
   → 否：重写描述
```

### 5.2 定期混淆检测

每周自动运行工具选择混淆检测：

```python
def weekly_confusion_audit():
    """
    每周混淆检测报告生成。
    """
    logs = load_recent_tool_selection_logs(days=7)
    matrix = build_confusion_matrix(logs)
    
    report = []
    for tool1 in matrix.index:
        for tool2 in matrix.columns:
            confusion_count = matrix.loc[tool1, tool2]
            total = matrix.loc[tool1, :].sum()
            if total > 0 and confusion_count / total > 0.05:
                report.append({
                    "tool_a": tool1,
                    "tool_b": tool2,
                    "confusion_rate": confusion_count / total,
                    "action": "REQUIRED"
                })
    
    return report
```

### 5.3 渐进式工具数量管理

设定工具数量上限，超过时进行合并：

| 阶段 | 工具数量上限 | 策略 |
|------|------------|------|
| MVP | 20 | 全部暴露 |
| 成长期 | 50 | 基本的分类 |
| 成熟期 | 80 | 层级菜单 |
| 规模化 | 100+ | 层级菜单 + 意图驱动懒加载 |

当工具数量超过上限时，**不是简单增加上限，而是对已有工具进行合并重构**。

## 关键教训速查

| 教训 | 说明 |
|------|------|
| 工具数 > 50 后准确率显著下降 | 100+ 个工具时准确率可能低于 70% |
| 层级菜单是最有效的方案 | 将选择范围从 100+ 缩小到 10-15，准确率提升到 95%+ |
| 工具名去歧义化效果显著 | 在名称中嵌入核心差异点 |
| 描述遵循"差异优先"原则 | 第一句话就说清与同类工具的区别 |
| 设置工具注册审核流程 | 防止无节制地新增相似工具 |
| 定期运行混淆矩阵检测 | 及早发现相似工具对的混淆问题 |
