# 9.7 工具调用失败三层处理

> 工具调用不可能永远成功。网络抖动、API 限流、参数错误、服务不可用——失败是常态而非异常。关键不是如何避免所有失败，而是**当失败发生时，系统如何优雅地应对**。这就是工具调用失败三层处理的核心：可重试（指数退避）/ 参数修正（LLM 重新生成）/ 不可恢复降级。

---

## 一、失败分类体系

### 1.1 工具调用的失败类型

工具调用的失败可以分为三大类，每类有不同的处理策略：

```
工具调用失败分类
│
├── ① 瞬时性失败（Transient）—— 可重试
│   ├── 网络超时（Timeout）
│   ├── API 限流（Rate Limit）
│   ├── 服务暂时不可用（503 Service Unavailable）
│   └── 连接重置（Connection Reset）
│
├── ② 参数性失败（Parametric）—— 可修正
│   ├── 必填参数缺失
│   ├── 参数类型错误
│   ├── 参数值超出范围
│   └── 参数组合不合法
│
└── ③ 永久性失败（Permanent）—— 不可恢复
    ├── 工具不存在（Tool Not Found）
    ├── 用户无权限（Permission Denied）
    ├── 资源不存在（Resource Not Found, 404）
    └── 业务逻辑冲突（Business Rule Violation）
```

### 1.2 失败分类的判定

```python
from enum import Enum
from typing import Optional


class FailureCategory(Enum):
    TRANSIENT = "transient"       # 瞬时性——可重试
    PARAMETRIC = "parametric"     # 参数性——可修正
    PERMANENT = "permanent"       # 永久性——不可恢复


class FailureClassifier:
    """失败分类器"""

    # 瞬时性错误码
    TRANSIENT_CODES = {
        408,  # Request Timeout
        429,  # Too Many Requests
        502,  # Bad Gateway
        503,  # Service Unavailable
        504,  # Gateway Timeout
    }

    # 参数性错误码
    PARAMETRIC_CODES = {
        400,  # Bad Request
        422,  # Unprocessable Entity
    }

    @classmethod
    def classify(
        cls,
        error: Exception,
        status_code: Optional[int] = None,
        error_message: str = ""
    ) -> FailureCategory:
        """自动分类失败类型"""

        # 网络超时 → 瞬时性
        if isinstance(error, TimeoutError):
            return FailureCategory.TRANSIENT

        # 连接错误 → 瞬时性
        if isinstance(error, ConnectionError):
            return FailureCategory.TRANSIENT

        # 基于 HTTP 状态码
        if status_code:
            if status_code in cls.TRANSIENT_CODES:
                return FailureCategory.TRANSIENT
            if status_code in cls.PARAMETRIC_CODES:
                return FailureCategory.PARAMETRIC
            if status_code == 404:
                return FailureCategory.PERMANENT
            if status_code == 403:
                return FailureCategory.PERMANENT

        # 基于错误信息关键词
        error_lower = error_message.lower()
        transient_keywords = [
            "timeout", "rate limit", "too many", "busy",
            "unavailable", "try again", "temporarily"
        ]
        parametric_keywords = [
            "invalid", "missing", "required", "wrong type",
            "out of range", "not found", "bad request"
        ]

        for kw in transient_keywords:
            if kw in error_lower:
                return FailureCategory.TRANSIENT

        for kw in parametric_keywords:
            if kw in error_lower:
                return FailureCategory.PARAMETRIC

        # 默认为永久性（安全策略：无法确定时按最严重处理）
        return FailureCategory.PERMANENT
```

## 二、第一层：可重试（指数退避）

### 2.1 指数退避算法

**指数退避**（Exponential Backoff）是应对瞬时性失败的标准策略。每次重试的等待时间指数增长，避免对下游系统造成"重试风暴"（Retry Storm）。

```
重试延迟增长模式:
  第1次重试: 等待 1s
  第2次重试: 等待 2s
  第3次重试: 等待 4s
  第4次重试: 等待 8s
  第5次重试: 等待 16s

  最大重试次数: 5 次（累计等待约 31 秒）
```

### 2.2 带抖动的指数退避

为了避免多个客户端同时重试导致"惊群效应"（Thundering Herd），在等待时间中加入随机**抖动**（Jitter）：

```python
import random
import asyncio
from typing import Optional


class ExponentialBackoff:
    """带抖动的指数退避重试器"""

    def __init__(
        self,
        base_delay: float = 1.0,    # 基础延迟（秒）
        max_delay: float = 60.0,    # 最大延迟（秒）
        max_retries: int = 5,       # 最大重试次数
        jitter_factor: float = 0.1  # 抖动因子
    ):
        self.base_delay = base_delay
        self.max_delay = max_delay
        self.max_retries = max_retries
        self.jitter_factor = jitter_factor
        self._attempt = 0

    def get_delay(self) -> float:
        """计算当前重试的等待时间"""
        delay = min(
            self.base_delay * (2 ** self._attempt),
            self.max_delay
        )
        # 加入随机抖动
        jitter = random.uniform(
            -delay * self.jitter_factor,
            delay * self.jitter_factor
        )
        return max(0, delay + jitter)

    async def execute(
        self,
        func,
        *args,
        should_retry: Optional[callable] = None,
        **kwargs
    ):
        """
        执行带重试的函数调用。

        should_retry: 可选的回调函数，用于判断是否应该重试。
                     接收异常对象，返回 bool（默认：全部瞬时性失败都重试）
        """
        last_error = None

        while self._attempt <= self.max_retries:
            try:
                result = await func(*args, **kwargs)
                self._attempt = 0  # 重置
                return result
            except Exception as e:
                last_error = e
                self._attempt += 1

                if self._attempt > self.max_retries:
                    break

                # 检查是否应该重试
                if should_retry and not should_retry(e):
                    break

                delay = self.get_delay()
                print(
                    f"重试 {self._attempt}/{self.max_retries}: "
                    f"等待 {delay:.2f}s，错误: {e}"
                )

                await asyncio.sleep(delay)

        raise RetryExhaustedError(
            f"重试 {self._attempt} 次后仍然失败",
            last_error
        )


class RetryExhaustedError(Exception):
    """重试耗尽错误"""
    def __init__(self, message: str, original_error: Exception):
        super().__init__(message)
        self.original_error = original_error
```

### 2.3 各类型错误的推荐重试参数

| 错误类型 | base_delay | max_delay | max_retries | 说明 |
|---------|-----------|-----------|-------------|------|
| 网络超时 | 1s | 30s | 3 次 | 快速失败，避免长时间等待 |
| HTTP 429 (限流) | 2s | 60s | 5 次 | 需要更长退避等待限流解除 |
| HTTP 503 (不可用) | 1s | 30s | 5 次 | 服务可能正在恢复 |
| DNS 解析失败 | 0.5s | 10s | 2 次 | 快速重试，往往立即恢复 |
| 连接重置 | 1s | 30s | 3 次 | 中等退避 |

## 三、第二层：参数修正（LLM 重新生成）

### 3.1 参数错误的处理流程

当工具调用因为参数错误失败时，让 LLM 自己修正参数是最有效的方法——因为模型最了解它"意图调用什么"，只是推理过程中参数构造出现了偏差。

```
参数修正流程：

工具调用失败（参数错误）
     │
     ▼
① 解析错误信息 → 提取具体问题
     │  "missing required field: user_id"
     │  "type mismatch: expected number, got string"
     ▼
② 构造修正 Prompt → 将错误信息反馈给模型
     │  工具: get_user_info
     │  错误: missing required field: user_id
     │  请修正参数后重新调用
     ▼
③ 模型重新生成 → 输出修正后的参数
     │  {"user_id": "123", "include_details": false}
     ▼
④ 重新执行 → 再次调用工具
     │
     ├─ 成功 → 继续流程
     └─ 失败 → 进入第三层或降级
```

### 3.2 参数修正的具体实现

```python
class ParametricFixHandler:
    """
    参数修正处理器。
    当工具调用因参数错误失败时，将错误信息反馈给 LLM 让其修正参数。
    """

    def __init__(self, llm_client, max_fix_attempts: int = 2):
        self._llm = llm_client
        self._max_fix_attempts = max_fix_attempts

    async def fix_and_retry(
        self,
        tool_call: dict,
        error: Exception,
        conversation_history: list
    ) -> dict:
        """
        修正参数并重试。

        流程：
        1. 构造"错误修正"请求
        2. 发送给 LLM，只请求修正参数
        3. 使用修正后的参数重新执行
        """
        for attempt in range(1, self._max_fix_attempts + 1):
            # 构造修正请求
            fix_prompt = self._build_fix_prompt(
                tool_call, error
            )

            # 请求 LLM 修正参数
            fix_response = await self._llm.chat(
                messages=[
                    {
                        "role": "system",
                        "content": (
                            "你是一个工具调用参数修正器。"
                            "用户的上一次工具调用因为参数错误失败。"
                            "请根据错误信息修正参数，只输出修正后的参数 JSON。"
                            "不要添加其他内容。"
                        )
                    },
                    {
                        "role": "user",
                        "content": fix_prompt
                    }
                ],
                response_format={"type": "json_object"},
                temperature=0.1  # 低温度，保证确定性
            )

            # 解析修正后的参数
            try:
                fixed_params = json.loads(
                    fix_response["content"]
                )
            except json.JSONDecodeError:
                continue  # 无法解析 JSON，再试一次

            # 用修正后的参数重新调用
            try:
                result = await self._execute_tool(
                    tool_call["name"],
                    fixed_params
                )
                return {
                    "status": "fixed",
                    "result": result,
                    "fix_attempts": attempt,
                    "original_error": str(error)
                }
            except Exception as retry_error:
                # 修正后仍然失败
                if attempt >= self._max_fix_attempts:
                    raise FixAttemptsExhaustedError(
                        f"经过 {self._max_fix_attempts} 次修正仍然失败",
                        retry_error
                    )
                # 更新错误信息，继续下一轮修正
                error = retry_error

        raise FixAttemptsExhaustedError("参数修正失败")

    def _build_fix_prompt(
        self, tool_call: dict, error: Exception
    ) -> str:
        """构造参数修正提示"""
        return json.dumps({
            "tool_name": tool_call["name"],
            "tool_description": tool_call.get("description", ""),
            "original_parameters": tool_call.get("arguments", {}),
            "error_message": str(error),
            "task": "请根据错误信息修正参数。确保所有必填字段都已提供且类型正确。"
        }, ensure_ascii=False)


class FixAttemptsExhaustedError(Exception):
    """参数修正次数耗尽"""
    pass
```

### 3.3 参数修正的成功率与策略

根据生产环境的数据统计：

| 参数错误类型 | 一次修正成功率 | 二次修正成功率 | 建议策略 |
|------------|--------------|--------------|---------|
| 必填参数缺失 | 85-92% | 95-98% | 最多 2 次修正 |
| 参数类型错误 | 80-88% | 90-95% | 最多 2 次修正 |
| 枚举值非法 | 75-85% | 88-93% | 最多 2 次修正 |
| 参数组合不合法 | 60-70% | 75-85% | 最多 1 次修正 + 降级 |
| 业务规则冲突 | 40-50% | 55-65% | 立即降级 |

**关键发现**：参数组合的非法性对 LLM 来说最难自行修正——因为业务规则往往是隐式的，模型需要理解业务逻辑才能做出正确修正。

### 3.4 修正 Prompt 的设计要点

设计参数修正的 Prompt 时，需要包含以下要素：

```
一个好的修正 Prompt 应该包含:
1. 原始工具调用（名称 + 完整参数）
2. 具体的错误信息（错误码 + 错误消息）
3. 工具的完整 Schema（帮助模型理解参数约束）
4. 修正的目标说明（"只修正参数，不要改变意图"）

一个差的修正 Prompt 只包含:
"上次调用失败了，你再试一次"
```

## 四、第三层：不可恢复降级

### 4.1 降级策略体系

当工具调用经过重试和参数修正后仍然失败，或者遇到永久性失败（如无权限、资源不存在），系统必须优雅地降级（Graceful Degradation）。

```
降级策略（从优到劣）:

                     ┌─────────────────────┐
                     │  ① 功能降级           │ ← 最佳降级
                     │  使用替代工具执行      │
                     │  例：缓存 → 旧数据    │
                     └──────────┬──────────┘
                                │
                     ┌──────────▼──────────┐
                     │  ② 语义降级           │
                     │  用自然语言告知用户    │
                     │  工具不可用，请求替代方案 │
                     └──────────┬──────────┘
                                │
                     ┌──────────▼──────────┐
                     │  ③ 转人工             │ ← 最差降级
                     │  转接给人工客服处理    │
                     └─────────────────────┘
```

### 4.2 降级策略的实现

```python
from enum import Enum
from typing import Optional, Any


class DegradationStrategy(Enum):
    FALLBACK_TOOL = "fallback_tool"       # 使用替代工具
    CACHED_RESULT = "cached_result"       # 返回缓存的历史结果
    SEMANTIC_DECLINE = "semantic_decline" # 用自然语言委婉告知
    HUMAN_ESCALATION = "human_escalation" # 转人工
    RETRY_LATER = "retry_later"           # 建议稍后重试


class DegradationHandler:
    """降级处理器"""

    def __init__(self):
        # 为每个工具注册降级方案
        self._fallback_map: dict[str, list[dict]] = {}
        # key: 工具名称, value: [(条件, 降级策略)]
        self._cache: dict[str, Any] = {}

    def register_fallback(
        self,
        tool_name: str,
        fallback_tool_name: str,
        param_mapping: dict
    ):
        """注册降级方案：用工具 B 替代工具 A"""
        if tool_name not in self._fallback_map:
            self._fallback_map[tool_name] = []

        self._fallback_map[tool_name].append({
            "type": "tool_fallback",
            "fallback_to": fallback_tool_name,
            "param_mapping": param_mapping
        })

    def register_cached_fallback(
        self, tool_name: str, ttl_hours: int = 24
    ):
        """注册降级方案：返回缓存的旧数据"""
        if tool_name not in self._fallback_map:
            self._fallback_map[tool_name] = []

        self._fallback_map[tool_name].append({
            "type": "cached_result",
            "ttl_hours": ttl_hours
        })

    async def degrade(
        self,
        tool_call: dict,
        error: Exception,
        context: dict
    ) -> dict:
        """
        执行降级操作。
        返回包含降级信息和结果（如果可用）的字典。
        """
        tool_name = tool_call["name"]
        fallbacks = self._fallback_map.get(tool_name, [])

        for fallback in fallbacks:
            if fallback["type"] == "tool_fallback":
                # 尝试使用替代工具
                try:
                    fallback_tool = fallback["fallback_to"]
                    mapped_params = self._map_parameters(
                        tool_call["arguments"],
                        fallback["param_mapping"]
                    )

                    result = await self._execute_tool(
                        fallback_tool, mapped_params
                    )

                    return {
                        "status": "degraded",
                        "strategy": "fallback_tool",
                        "original_tool": tool_name,
                        "used_tool": fallback_tool,
                        "result": result,
                        "message": (
                            f"工具 {tool_name} 暂时不可用，"
                            f"已使用 {fallback_tool} 替代"
                        )
                    }
                except Exception:
                    continue  # 降级方案也失败，尝试下一个

            elif fallback["type"] == "cached_result":
                cached = self._get_cached(tool_name, tool_call["arguments"])
                if cached:
                    return {
                        "status": "degraded",
                        "strategy": "cached_result",
                        "result": cached["data"],
                        "cached_at": cached["timestamp"],
                        "message": (
                            f"工具 {tool_name} 暂时不可用，"
                            f"返回 {cached['age_hours']:.1f} 小时前的缓存数据"
                        )
                    }

        # 所有降级方案都失败 → 语义降级
        return {
            "status": "unavailable",
            "strategy": "semantic_decline",
            "message": self._build_decline_message(tool_name, error)
        }

    def _map_parameters(
        self, original_params: dict, mapping: dict
    ) -> dict:
        """根据映射关系转换参数"""
        mapped = {}
        for target_key, source_key in mapping.items():
            if source_key in original_params:
                mapped[target_key] = original_params[source_key]
        return mapped

    def _get_cached(self, tool_name: str, params: dict) -> Optional[dict]:
        """获取缓存结果"""
        cache_key = f"{tool_name}:{json.dumps(params, sort_keys=True)}"
        entry = self._cache.get(cache_key)
        if not entry:
            return None

        age = time.time() - entry["timestamp"]
        if age > entry.get("ttl", 86400):  # 默认 24h
            del self._cache[cache_key]
            return None

        return {
            "data": entry["data"],
            "timestamp": entry["timestamp"],
            "age_hours": age / 3600
        }

    def _build_decline_message(self, tool_name: str, error: Exception) -> str:
        """构造语义降级的用户消息"""
        return (
            f"很抱歉，{tool_name} 功能暂时不可用。"
            f"技术原因: {str(error)}。"
            f"请稍后再试，或联系技术支持。"
        )
```

### 4.3 三层处理的完整流程

将三层失败处理整合后的整体流程：

```

└────────────────────┬────────────────────────────┘
                     │
                     ▼

│  LLM 重新生成参数        │        │

            │                      │

│  第三层：降级                             │
│  ├─ 功能降级（替代工具）                  │
│  ├─ 缓存降级（返回旧数据）                │

└─────────────────────────────────────────┘
```

### 4.4 完整的编排器实现

```python
class RobustToolOrchestrator:
    """
    健壮的工具编排器——整合三层失败处理。
    """

    def __init__(
        self,
        tool_registry,
        llm_client,
        max_retries: int = 5,
        max_fix_attempts: int = 2
    ):
        self._registry = tool_registry
        self._retrier = ExponentialBackoff(max_retries=max_retries)
        self._fix_handler = ParametricFixHandler(
            llm_client, max_fix_attempts=max_fix_attempts
        )
        self._degradation = DegradationHandler()

    async def execute(
        self,
        tool_call: dict,
        conversation_history: list
    ) -> dict:
        """
        执行工具调用，自动应用三层失败处理。
        """
        try:
            # 首次执行（带指数退避重试）
            result = await self._retrier.execute(
                self._execute_with_registry,
                tool_call
            )
            return {
                "status": "success",
                "result": result,
                "strategy": "direct"
            }

        except RetryExhaustedError as e:
            # 重试耗尽，检查是否为参数错误
            error = e.original_error
            category = FailureClassifier.classify(error)

            if category == FailureCategory.PARAMETRIC:
                # 第二层：参数修正
                try:
                    result = await self._fix_handler.fix_and_retry(
                        tool_call, error, conversation_history
                    )
                    return result
                except FixAttemptsExhaustedError:
                    # 参数修正也失败 → 降级
                    pass

            # 第三层：降级
            return await self._degradation.degrade(
                tool_call, error, {}
            )

        except Exception as e:
            # 其他意外错误
            category = FailureClassifier.classify(e)
            if category == FailureCategory.PERMANENT:
                return await self._degradation.degrade(
                    tool_call, e, {}
                )
            raise  # 无法处理的错误，向上抛出

    async def _execute_with_registry(self, tool_call: dict):
        """从注册中心获取工具并执行"""
        tool_name = tool_call["name"]
        tool_meta = self._registry.get(tool_name)
        if not tool_meta:
            raise ToolNotFoundError(f"工具不存在: {tool_name}")
        return await tool_meta.handler(**tool_call["arguments"])


class ToolNotFoundError(Exception):
    pass
```

## 五、失败监控与告警

### 5.1 关键监控指标

| 指标 | 定义 | 告警阈值 |
|------|------|---------|
| **工具成功率** | 成功调用 / 总调用 | < 95% 告警 |
| **重试率** | 需要重试的调用 / 总调用 | > 10% 告警 |
| **参数修正率** | 需要参数修正的调用 / 总调用 | > 5% 关注 |
| **降级率** | 需要降级的调用 / 总调用 | > 1% 告警 |
| **平均重试次数** | 每次失败的平均重试次数 | > 3 次关注 |
| **P999 延迟** | 最慢 0.1% 调用的延迟 | > 30s 告警 |

## 关键概念速查表

| 概念 | 定义 | 重要性 |
|------|------|--------|
| **瞬时性失败** | 临时的、可自动恢复的失败（网络超时、限流） | P0 |
| **参数性失败** | 参数错误导致的失败（缺失、类型错误、越界） | P0 |
| **永久性失败** | 不可恢复的失败（无权限、资源不存在） | P0 |
| **指数退避** | 重试等待时间指数增长的策略 | P0（第一层核心） |
| **抖动（Jitter）** | 在退避延迟中引入随机性避免惊群效应 | P1 |
| **参数修正** | 将错误信息反馈给 LLM 让模型自行修正参数 | P0（第二层核心） |
| **降级** | 当所有恢复手段都失败时的优雅失败方案 | P0（第三层核心） |
| **功能降级** | 使用替代工具执行相同功能 | P1 |
| **语义降级** | 用自然语言告知用户工具不可用 | P1 |
