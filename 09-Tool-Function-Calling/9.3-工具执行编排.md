# 9.3 工具执行编排

> 当 Agent 一次需要调用多个工具时，执行顺序和并发策略直接影响系统的正确性、性能和资源消耗。工具执行编排（Tool Execution Orchestration）负责分析工具之间的依赖关系，决定哪些工具可以并行执行，哪些必须串行，从而在保证正确性的前提下最大化执行效率。

---

## 一、编排的核心问题

### 1.1 为什么需要编排？

考虑一个电商 Agent 的典型场景——用户说"帮我查一下上个月的订单总额，如果超过 5000 元就给我发一封总结邮件"：

```
步骤:
1. query_orders({"date_range": "2025-05-01~2025-05-31"})  → 订单列表
2. calculate_total(orders_data)                             → 总额
3. if total > 5000: send_email(...)                          → 发邮件
```

这里步骤 2 依赖步骤 1 的结果，步骤 3 依赖步骤 2。但如果用户同时问"帮我查一下北京和上海的天气"，两个天气查询之间没有依赖关系，可以**并行执行**。

编排引擎的核心任务就是：**识别依赖关系，最大化并行度，保证执行正确性**。

```
无依赖工具 → 并行执行
    get_weather(北京) ──┐
                       ├── 同时执行
    get_weather(上海) ──┘

有依赖工具 → 串行执行
    query_orders → calculate_total → send_email
    (串行链条，每一步依赖上一步结果)
```

### 1.2 编排错误的后果

| 错误类型 | 后果 | 示例 |
|---------|------|------|
| **并行执行写冲突** | 数据不一致 | 两个工具同时修改同一订单状态 |
| **串行执行顺序错误** | 下游使用错误数据 | 库存扣减在支付确认之前执行 |
| **死锁** | Agent 永久等待 | 工具 A 等待 B，工具 B 等待 A |
| **超时顺序不当** | 关键路径阻塞 | 只读查询占据了写操作的排队时间 |

## 二、并发安全判定（isConcurrencySafe）

### 2.1 什么是并发安全？

**并发安全**（Concurrency Safety）标志 `isConcurrencySafe` 是工具元数据中的一个关键属性，它标记该工具是否可以与其他工具同时执行。

```python
@dataclass
class ToolMetadata:
    name: str
    # ...
    concurrency_safe: bool  # True: 可并行, False: 必须串行
    safety: ToolSafety      # READ / WRITE / DESTRUCTIVE
```

### 2.2 判定规则

并发安全的判定依据是**工具是否具有副作用**以及**副作用的范围**：

```
isConcurrencySafe = True 的条件（同时满足）：
  1. 工具是只读的（Safety = READ）
  2. 不修改任何共享状态
  3. 不依赖其他工具的中间结果
  4. 多次调用产生相同结果（幂等性）

isConcurrencySafe = False 的条件（任一满足）：
  1. 工具是写操作（Safety = WRITE 或 DESTRUCTIVE）
  2. 工具修改了全局/共享状态
  3. 工具的执行结果依赖于外部时序
  4. 工具调用了有副作用的第三方 API
```

### 2.3 并发安全的实际判定指南

在注册工具时，可以通过以下 checklist 判定并发安全性：

| 场景 | 示例工具 | isConcurrencySafe | 原因 |
|------|---------|-------------------|------|
| 查询天气 | `get_weather` | True | 只读、幂等、无副作用 |
| 数据库查询 | `query_users` | True | 只读查询 |
| 发送邮件 | `send_email` | False | 有副作用（发送行为本身） |
| 创建订单 | `create_order` | False | 修改数据库状态 |
| 文件读取 | `read_file` | True | 只读 |
| 文件删除 | `delete_file` | False | 破坏性操作 |
| 日志写入 | `append_log` | False | 写操作，依赖写入顺序 |
| 缓存读取 | `cache_get` | True | 只读 |
| 余额扣减 | `deduct_balance` | False | 写操作，必须串行保证原子性 |

## 三、读工具并行 vs 写工具串行

### 3.1 读写分离策略

在生产系统中，最常用的策略是**读工具并行、写工具串行**：

```
┌────────────┐  ┌────────────┐  ┌────────────┐
│ get_weather │  │ get_stock  │  │ get_price  │  ← 读工具：全部并行
│  (北京)    │  │  (商品A)   │  │  (商品A)   │
└──────┬─────┘  └──────┬─────┘  └──────┬─────┘
       │               │               │
       └───────────────┼───────────────┘
                       │  全部同时启动
                       ▼
                  ┌────────────┐
                  │ create_order│  ← 写工具：必须串行
                  │  (创建订单) │
                  └────────────┘
                       │
                       ▼
                  ┌────────────┐
                  │  send_email │  ← 写工具：在 create_order 之后
                  │  (通知邮件) │
                  └────────────┘
```

### 3.2 读写分离的实现

```python
import asyncio
from typing import Any


class ToolExecutor:
    """工具执行器，实现读写分离策略"""

    def __init__(self):
        self._write_lock = asyncio.Lock()

    async def execute_batch(self, tool_calls: list[dict]) -> list[Any]:
        """批量执行工具调用（含读写分离）"""
        read_tools = []
        write_tools = []

        # 1. 按读写分类
        for call in tool_calls:
            if call.get("concurrency_safe", True):
                read_tools.append(call)
            else:
                write_tools.append(call)

        results = {}

        # 2. 读工具并行执行
        if read_tools:
            read_results = await asyncio.gather(
                *[self._execute_one(t) for t in read_tools],
                return_exceptions=True
            )
            for tool, result in zip(read_tools, read_results):
                results[tool["id"]] = result

        # 3. 写工具串行执行（加锁保证顺序）
        for tool in write_tools:
            async with self._write_lock:
                result = await self._execute_one(tool)
                results[tool["id"]] = result

        return results

    async def _execute_one(self, tool_call: dict) -> Any:
        """执行单个工具"""
        # 实际执行逻辑（调用 handler）
        ...
```

### 3.3 写工具串行的实现细节

写工具串行不仅仅是"一件一件做"，还包括：

**① 顺序保证**：如果模型输出的工具调用列表中写工具之间有顺序依赖，必须严格按顺序执行。

**② 原子性边界**：相关的一组写操作应该在同一个事务中执行，或者有补偿机制（回滚）。

**③ 超时隔离**：写工具的超时应独立设置，一个写工具的超时不应当影响其他写工具的执行。

```python
class WriteQueue:
    """写工具队列——串行化写操作"""

    def __init__(self):
        self._queue: asyncio.Queue = asyncio.Queue()
        self._current_task: Optional[asyncio.Task] = None

    async def enqueue(self, tool_call: dict) -> Any:
        """将写工具加入执行队列"""
        future = asyncio.get_event_loop().create_future()
        await self._queue.put((tool_call, future))
        self._schedule_processing()
        return await future

    async def _process_queue(self):
        """串行处理队列"""
        while not self._queue.empty():
            tool_call, future = await self._queue.get()
            try:
                result = await self._execute_with_timeout(
                    tool_call,
                    timeout=tool_call.get("timeout_ms", 30000) / 1000
                )
                future.set_result(result)
            except Exception as e:
                future.set_exception(e)

    async def _execute_with_timeout(
        self, tool_call: dict, timeout: float
    ) -> Any:
        """带超时的工具执行"""
        try:
            return await asyncio.wait_for(
                self._execute_one(tool_call),
                timeout=timeout
            )
        except asyncio.TimeoutError:
            raise TimeoutError(
                f"写工具 '{tool_call['name']}' 执行超时 ({timeout}s)"
            )
```

## 四、依赖 DAG 分析

### 4.1 什么是 DAG 分析？

**DAG**（Directed Acyclic Graph，有向无环图）是工具执行编排的核心数据结构。每个工具调用是图中的一个节点，数据依赖关系是有向边。DAG 分析的目的是找到**拓扑排序**，从而决定工具的执行顺序。

```
依赖 DAG 示例:

              ┌──────────┐
              │ get_user  │  ← 根节点（无依赖）
              │  信息     │
              └────┬─────┘
                   │ user_id
                   ▼
              ┌──────────┐
         ┌───│get_orders│  ← 依赖 get_user
         │   │ 订单列表 │
         │   └────┬─────┘
         │        │ order_ids
         │        ▼
         │   ┌──────────┐
         │   │calc_total│  ← 依赖 get_orders
         │   │ 计算总额 │
         │   └────┬─────┘
         │        │ total > 5000
         │        ▼
         │   ┌──────────┐
         └──▶│send_email│  ← 依赖 calc_total
             │ 发送邮件 │
             └──────────┘
```

### 4.2 DAG 分析算法

以下是一个完整的 DAG 分析算法实现，用于工具执行编排：

```python
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any
from collections import deque


@dataclass
class ToolNode:
    """DAG 中的工具节点"""
    id: str
    name: str
    parameters: dict
    concurrency_safe: bool
    depends_on: list[str] = field(default_factory=list)
    # depends_on: 此节点依赖的节点 ID 列表

    # 运行时数据
    result: Any = None
    status: str = "pending"  # pending | running | completed | failed


class ToolDAG:
    """工具执行依赖图"""

    def __init__(self):
        self.nodes: dict[str, ToolNode] = {}
        self._adjacency: dict[str, list[str]] = {}
        # _adjacency: 邻接表，key 指向其依赖的所有节点

    def add_node(self, node: ToolNode):
        """添加节点"""
        self.nodes[node.id] = node
        self._adjacency[node.id] = []

    def add_dependency(self, from_id: str, to_id: str):
        """添加依赖边：from_id → to_id（from 依赖 to）"""
        if from_id not in self.nodes or to_id not in self.nodes:
            raise ValueError("节点不存在")
        self._adjacency[from_id].append(to_id)

    def _has_cycle(self) -> bool:
        """检测环——使用三色标记法"""
        WHITE, GRAY, BLACK = 0, 1, 2
        color = {nid: WHITE for nid in self.nodes}

        def dfs(nid: str) -> bool:
            color[nid] = GRAY
            for dep in self._adjacency.get(nid, []):
                if color[dep] == GRAY:
                    return True  # 发现后向边 = 环
                if color[dep] == WHITE and dfs(dep):
                    return True
            color[nid] = BLACK
            return False

        for nid in self.nodes:
            if color[nid] == WHITE:
                if dfs(nid):
                    return True
        return False

    def topological_sort(self) -> list[list[str]]:
        """
        拓扑排序——返回按依赖层级分组的节点 ID 列表。
        同一层的节点可以并行执行。
        """
        # 计算入度（每个节点被依赖的次数）
        # 注意：我们的邻接表是"from → depends on to"
        # 所以入度 = 有多少节点依赖"我"
        in_degree: dict[str, int] = {nid: 0 for nid in self.nodes}

        # 反向邻接表
        reverse_adj: dict[str, list[str]] = {nid: [] for nid in self.nodes}
        for from_id, deps in self._adjacency.items():
            for dep_id in deps:
                reverse_adj[dep_id].append(from_id)

        # 入度 = 依赖项数量
        for nid in self.nodes:
            in_degree[nid] = len(self._adjacency[nid])

        # Kahn 算法
        queue = deque()
        for nid, degree in in_degree.items():
            if degree == 0:
                queue.append(nid)

        levels: list[list[str]] = []

        while queue:
            level_size = len(queue)
            current_level = []

            for _ in range(level_size):
                nid = queue.popleft()
                current_level.append(nid)

                # 减少依赖此节点的所有节点的入度
                for dependent in reverse_adj.get(nid, []):
                    in_degree[dependent] -= 1
                    if in_degree[dependent] == 0:
                        queue.append(dependent)

            levels.append(current_level)

        # 检查是否所有节点都处理了
        processed = sum(len(level) for level in levels)
        if processed != len(self.nodes):
            raise ValueError(
                f"DAG 中存在环！已处理 {processed}/{len(self.nodes)} 个节点"
            )

        return levels

    def get_execution_plan(self) -> ExecutionPlan:
        """
        生成执行计划：
        - 同层级可并行
        - 不同层级串行
        - 不可并行的节点提升到独立层级
        """
        if self._has_cycle():
            raise ValueError("依赖图中存在环，无法生成执行计划")

        raw_levels = self.topological_sort()
        refined_levels = []

        for level in raw_levels:
            safe_nodes = []
            unsafe_nodes = []

            for nid in level:
                node = self.nodes[nid]
                if node.concurrency_safe:
                    safe_nodes.append(nid)
                else:
                    unsafe_nodes.append(nid)

            # 并发安全节点可在同一层级并行
            if safe_nodes:
                refined_levels.append(safe_nodes)
            # 非安全节点各自独立层级（串行化）
            for nid in unsafe_nodes:
                refined_levels.append([nid])

        return ExecutionPlan(levels=refined_levels)


@dataclass
class ExecutionPlan:
    """执行计划"""
    levels: list[list[str]]

    def total_stages(self) -> int:
        """执行阶段数"""
        return len(self.levels)

    def estimate_latency(
        self,
        tool_latencies: dict[str, float],
        parallel_overhead: float = 0.05
    ) -> float:
        """
        估算总延迟。
        tool_latencies: 每个工具的平均延迟（秒）
        parallel_overhead: 并行执行的调度开销比例
        """
        total = 0.0
        for level in self.levels:
            if len(level) == 1:
                # 串行执行：单工具延迟
                total += tool_latencies.get(level[0], 1.0)
            else:
                # 并行执行：最慢的工具延迟 + 调度开销
                max_latency = max(
                    tool_latencies.get(nid, 1.0) for nid in level
                )
                total += max_latency * (1 + parallel_overhead)
        return total


# ========= 使用示例 =========

def build_example_dag() -> ToolDAG:
    """构建示例 DAG"""
    dag = ToolDAG()

    # 创建节点
    dag.add_node(ToolNode(
        id="t1", name="get_user_info",
        parameters={"user_id": "123"},
        concurrency_safe=True
    ))
    dag.add_node(ToolNode(
        id="t2", name="get_orders",
        parameters={},
        concurrency_safe=True,
        depends_on=["t1"]
    ))
    dag.add_node(ToolNode(
        id="t3", name="calc_total",
        parameters={},
        concurrency_safe=True,
        depends_on=["t2"]
    ))
    dag.add_node(ToolNode(
        id="t4", name="send_email",
        parameters={"template": "summary"},
        concurrency_safe=False,  # 写操作
        depends_on=["t3"]
    ))

    # 添加依赖关系
    dag.add_dependency("t2", "t1")  # t2 依赖 t1
    dag.add_dependency("t3", "t2")  # t3 依赖 t2
    dag.add_dependency("t4", "t3")  # t4 依赖 t3

    return dag


def analyze_dag():
    """DAG 分析演示"""
    dag = build_example_dag()
    plan = dag.get_execution_plan()

    print("执行计划（按层级）:")
    for i, level in enumerate(plan.levels):
        tool_names = [dag.nodes[nid].name for nid in level]
        mode = "并行" if len(level) > 1 else "串行"
        print(f"  第 {i+1} 层 [{mode}]: {tool_names}")

    latencies = {
        "t1": 0.3, "t2": 0.5, "t3": 0.2, "t4": 1.0
    }
    print(f"\n估算延迟: {plan.estimate_latency(latencies):.2f}s")
    print(f"总阶段数: {plan.total_stages()}")


# 输出:
# 执行计划（按层级）:
#   第 1 层 [串行]: ['get_user_info']
#   第 2 层 [串行]: ['get_orders']
#   第 3 层 [串行]: ['calc_total']
#   第 4 层 [串行]: ['send_email']
# 估算延迟: 2.00s
# 总阶段数: 4
```

### 4.3 DAG 的运行时构建

在真实的 Agent 场景中，DAG 不是在工具注册时预定义的，而是在运行时根据模型输出的 tool_calls 动态构建：

```python
def build_runtime_dag(tool_calls: list[dict]) -> ToolDAG:
    """
    从模型输出的 tool_calls 构建运行时 DAG。

    策略：
    1. 所有同批次输出的 tool_calls 默认为"可并行"
    2. 检查参数中是否有 ${previous_tool_id.output} 格式的引用
    3. 有引用的工具会被标记为依赖被引用的工具
    """
    dag = ToolDAG()
    id_pattern = re.compile(r'\$\{(t_\w+)\.(\w+)\}')

    for call in tool_calls:
        call_id = call.get("id", f"t_{call['name']}")
        args_str = json.dumps(call.get("arguments", {}))

        # 检测参数中是否引用了其他工具的输出
        dependencies = []
        for match in id_pattern.finditer(args_str):
            dep_id = match.group(1)
            if dep_id != call_id:
                dependencies.append(dep_id)

        node = ToolNode(
            id=call_id,
            name=call["name"],
            parameters=call.get("arguments", {}),
            concurrency_safe=call.get("concurrency_safe", True),
            depends_on=dependencies
        )
        dag.add_node(node)

        for dep_id in dependencies:
            dag.add_dependency(call_id, dep_id)

    return dag
```

## 五、执行编排的实践模式

### 5.1 默认编排策略

对于大多数 Agent 系统，推荐以下默认策略：

```
1. 模型输出 M 个工具调用
2. 分析依赖关系构建 DAG
3. 执行拓扑排序得到分层执行计划
4. 同一层中：读工具全部并行，写工具逐个串行
5. 跨层之间：严格串行（上层全部完成后才能进入下一层）
6. 某层中有工具失败：根据失败策略决定是否继续

执行流程:
  模型输出 → DAG构建 → 拓扑排序 → 分层执行 → 结果聚合
                              │
                     ┌────────┴────────┐
                     ▼                 ▼
               ┌────────────┐  ┌────────────┐
               │ 第1层：并行  │  │ 第2层：串行  │
               │ get_weather │  │ create_order│
               │ get_stock   │  │             │
               └────────────┘  └────────────┘
```

### 5.2 异步编排（Async Orchestration）

在大规模场景中，使用异步事件驱动的方式执行编排：

```python
class AsyncOrchestrator:
    """异步编排引擎"""

    def __init__(self, executor: ToolExecutor):
        self._executor = executor
        self._dag: Optional[ToolDAG] = None

    async def execute(self, tool_calls: list[dict]) -> dict[str, Any]:
        """执行完整的编排流程"""
        # 1. 构建 DAG
        self._dag = build_runtime_dag(tool_calls)

        # 2. 获取执行计划
        plan = self._dag.get_execution_plan()
        all_results = {}

        # 3. 按层级执行
        for level in plan.levels:
            level_tools = [self._dag.nodes[nid] for nid in level]

            if len(level_tools) == 1:
                # 串行执行
                result = await self._executor._execute_one(
                    level_tools[0]
                )
                all_results[level[0]] = result
            else:
                # 并行执行
                tasks = [
                    self._executor._execute_one(node)
                    for node in level_tools
                ]
                results = await asyncio.gather(
                    *tasks, return_exceptions=True
                )
                for nid, result in zip(level, results):
                    all_results[nid] = result

            # 4. 将结果注入到下一层工具的参数中
            self._inject_results(next_level, all_results)

        return all_results
```
