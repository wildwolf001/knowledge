# 9.5 海量工具管理

> 当 Agent 系统中的工具数量从十几个增长到几十个甚至数百个时，"把所有工具描述一股脑塞给模型"的策略将不再可行。这不仅消耗大量 Token（见 9.6 节），还会严重降低模型的选择准确率。海量工具管理通过层级工具菜单、按需展开和分组策略来解决这一挑战。

---

## 一、海量工具的挑战

### 1.1 工具数量与选型准确率的关系

**实验数据**显示，随着提供给模型的工具数量增长，模型选择正确工具的概率呈现下降趋势：

```
工具选型准确率 vs 工具数量

准确率 (%)
 100 │●
  95 │  ●
  90 │    ●
  85 │      ●
  80 │        ●
  75 │          ●
  70 │            ●
  65 │              ●
  60 │                ●
     └────────────────────────────────
       5  10  20  30  40  50  60  70
                工具数量
```

**关键发现**：
- **5-10 个工具**：选型准确率 > 95%，模型可以轻松区分
- **10-20 个工具**：准确率约 88-93%，开始出现轻微的混淆
- **20-40 个工具**：准确率约 78-88%，混淆明显增加
- **40-60 个工具**：准确率约 70-80%，需要额外策略辅助
- **60+ 个工具**：准确率可能低于 70%，必须使用层级菜单或分组策略

### 1.2 Token 消耗问题

每个工具的工具描述（name + description + parameters schema）会占用上下文窗口。以中等复杂度的工具为例：

```
一个工具的平均 Token 消耗:
  - name: 1-3 tokens
  - description: 15-50 tokens
  - parameters schema: 30-150 tokens
  - 总计: 50-200 tokens/个

60 个工具的理论 Token 消耗:
  60 × 100 (平均) = 6,000 tokens

114 个工具的 Token 消耗（实际案例）:
  114 个工具 × 平均 ~400 tokens（含复杂 schema）= 45,600 tokens
  → 详见 9.6 节分析
```

## 二、层级工具菜单架构

### 2.1 分层设计思想

层级工具菜单（Hierarchical Tool Menu）借鉴了文件系统的目录结构。顶层只展示最宽泛的工具类别，当模型选择某一类别后，再展开该类别下的子工具。

```
层级工具菜单结构：

Root（根节点 — 5 大类）
  │
  ├── 📊 数据查询类 (Data Query)
  │     ├── get_weather
  │     ├── get_stock_price
  │     ├── query_database
  │     ├── search_documents
  │     └── ... (最多 15 个子工具)
  │
  ├── 📝 内容管理类 (Content Management)
  │     ├── create_document
  │     ├── update_document
  │     ├── delete_document
  │     └── ...
  │
  ├── 🔧 系统管理类 (System Admin)
  │     ├── list_users
  │     ├── create_user
  │     ├── update_permissions
  │     └── ...
  │
  ├── 📬 通信类 (Communication)
  │     ├── send_email
  │     ├── send_sms
  │     ├── send_push_notification
  │     └── ...
  │
  └── 🛠 工具类 (Utilities)
        ├── calculate
        ├── format_data
        ├── generate_report
        └── ...
```

### 2.2 层级菜单的实现

```python
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Optional, Callable
import json


@dataclass
class ToolMenuItem:
    """工具菜单项"""
    name: str
    description: str
    type: str = "tool"  # "tool" | "category"

    # 如果是工具
    parameters: Optional[dict] = None
    handler: Optional[Callable] = None
    concurrency_safe: bool = True

    # 如果是分类
    children: list[ToolMenuItem] = field(default_factory=list)
    is_expanded: bool = False  # 是否已展开


class HierarchicalToolMenu:
    """
    层级工具菜单管理器

    架构：
    Root (5 categories)
    ├── Category A (expanded = False)
    │   ├── Tool A1
    │   ├── Tool A2
    │   └── ...
    ├── Category B (expanded = False)
    │   ├── Tool B1
    │   └── ...
    └── ...

    初始状态：只向模型展示 Root 5 个分类。
    模型选择某个分类后，展开该分类的子工具。
    """

    MAX_TOOLS_PER_LEVEL = 15  # 每层最大工具数
    MAX_CATEGORIES = 7  # 根部分类数限制

    def __init__(self):
        self.root: list[ToolMenuItem] = []
        self._tool_map: dict[str, ToolMenuItem] = {}  # name → item

    def register_tool(
        self,
        name: str,
        description: str,
        parameters: dict,
        category: str,
        handler: Optional[Callable] = None,
        concurrency_safe: bool = True
    ):
        """注册工具到指定分类"""
        tool = ToolMenuItem(
            name=name,
            description=description,
            type="tool",
            parameters=parameters,
            handler=handler,
            concurrency_safe=concurrency_safe
        )
        self._tool_map[name] = tool

        # 找到或创建分类
        category_item = self._find_or_create_category(category)

        # 检查该分类下的工具数量限制
        if len(category_item.children) >= self.MAX_TOOLS_PER_LEVEL:
            raise ValueError(
                f"分类 '{category}' 已达到最大工具数限制 "
                f"({self.MAX_TOOLS_PER_LEVEL})"
            )

        category_item.children.append(tool)

    def _find_or_create_category(self, name: str) -> ToolMenuItem:
        """查找或创建分类"""
        for item in self.root:
            if item.name == name:
                return item

        if len(self.root) >= self.MAX_CATEGORIES:
            raise ValueError(
                f"根部分类数已达上限 ({self.MAX_CATEGORIES})"
            )

        category = ToolMenuItem(
            name=name,
            description=self._get_category_description(name),
            type="category"
        )
        self.root.append(category)
        return category

    def _get_category_description(self, name: str) -> str:
        """获取分类的描述"""
        descriptions = {
            "data_query": "查询和检索数据的工具，包括数据库查询、API 调用、文件读取等只读操作",
            "content_management": "创建、编辑和管理内容的工具，包括文档处理、数据录入等",
            "system_admin": "系统管理和配置工具，包括用户管理、权限设置等",
            "communication": "发送通知和消息的工具，包括邮件、短信、推送等",
            "utilities": "通用工具类，包括计算、格式化、报告生成等",
        }
        return descriptions.get(name, f"{name} 类工具")

    def get_menu_for_llm(self) -> list[dict]:
        """
        生成当前可用工具的 Function Call Schema。
        只包含展开的分类下的工具。
        """
        tools = []

        for item in self.root:
            if item.type == "category":
                if item.is_expanded:
                    # 展开状态：包含该分类的所有子工具
                    for child in item.children:
                        tools.append(self._tool_to_schema(child))
                else:
                    # 折叠状态：只暴露分类本身作为一个"导航工具"
                    tools.append(self._category_to_schema(item))
            else:
                tools.append(self._tool_to_schema(item))

        return tools

    def _category_to_schema(self, category: ToolMenuItem) -> dict:
        """分类项 → Function Call Schema（作为导航工具）"""
        child_names = [c.name for c in category.children]
        return {
            "type": "function",
            "function": {
                "name": f"navigate_to_{category.name}",
                "description": (
                    f"展开 [{category.name}] 分类查看可用工具。"
                    f"该分类包含以下工具：{', '.join(child_names[:5])}"
                    f"{'等' if len(child_names) > 5 else ''}"
                ),
                "parameters": {
                    "type": "object",
                    "properties": {},
                    "required": []
                }
            }
        }

    def _tool_to_schema(self, tool: ToolMenuItem) -> dict:
        """工具项 → Function Call Schema"""
        return {
            "type": "function",
            "function": {
                "name": tool.name,
                "description": tool.description,
                "parameters": tool.parameters or {
                    "type": "object",
                    "properties": {}
                }
            }
        }

    def handle_navigation(self, tool_name: str) -> str:
        """处理导航请求，展开分类"""
        for item in self.root:
            if tool_name == f"navigate_to_{item.name}":
                item.is_expanded = True
                return (
                    f"已展开 [{item.name}] 分类，包含 "
                    f"{len(item.children)} 个工具。"
                )
        return f"未知分类: {tool_name}"

    def find_tool(self, name: str) -> Optional[ToolMenuItem]:
        """按名称查找工具"""
        return self._tool_map.get(name)

    def search_tools(self, query: str) -> list[ToolMenuItem]:
        """搜索工具（按名称和描述模糊匹配）"""
        query = query.lower()
        results = []
        for tool in self._tool_map.values():
            if query in tool.name.lower() or query in tool.description.lower():
                results.append(tool)
        return results
```

### 2.3 交互流程

层级工具菜单的典型交互流程如下：

```
用户: "帮我查一下北京明天会不会下雨"

第一轮（只有 Root 5 个分类）:
  System: 可用工具：
    [navigate_to_data_query] - 展开数据查询类...
    [navigate_to_content_management] - 展开内容管理类...
    [navigate_to_system_admin] - 展开系统管理类...
    [navigate_to_communication] - 展开通信类...
    [navigate_to_utilities] - 展开工具类...

  模型 → navigate_to_data_query()

第二轮（展开 data_query，看到其子工具）:
  System: 数据查询类已展开，可用工具：
    [get_weather] - 查询天气预报...
    [get_stock_price] - 查询股票价格...
    [query_database] - 执行 SQL 查询...
    [search_documents] - 搜索文档...
    ...

  模型 → get_weather({"city": "北京", "date": "2025-06-02"})

  系统返回天气信息，模型组织回答。
```

### 2.4 动态按需展开

为了进一步优化，可以实现**多层展开**——分类之下还可以有子分类：

```python
class MultiLevelToolMenu(HierarchicalToolMenu):
    """多层工具菜单——支持嵌套分类"""

    def __init__(self):
        super().__init__()
        self._breadcrumb: list[str] = []  # 当前路径

    def navigate_to(self, path: str):
        """导航到指定路径（如 "data_query/weather/forecast"）"""
        self._breadcrumb = path.split("/")

    def get_current_level(self) -> list[ToolMenuItem]:
        """获取当前层级的所有项"""
        current = self.root
        for segment in self._breadcrumb:
            for item in current:
                if item.name == segment:
                    current = item.children
                    break
            else:
                raise ValueError(f"路径 '{'/'.join(self._breadcrumb)}' 不存在")
        return current

    def get_active_categories(self) -> list[str]:
        """获取当前激活的路径"""
        return self._breadcrumb
```

## 三、工具分组策略

### 3.1 分组维度

除了层级结构，工具还可以从多个维度进行分组，以便在不同场景下灵活选择：

```python
@dataclass
class ToolGroup:
    """工具分组"""
    name: str
    description: str
    tools: list[str]  # 工具名称列表

    # 分组类型
    group_type: str  # "domain" | "permission" | "safety" | "custom"


class ToolGroupManager:
    """工具分组管理器"""

    def __init__(self, menu: HierarchicalToolMenu):
        self._menu = menu
        self._groups: dict[str, ToolGroup] = {}

    def create_group(self, group: ToolGroup):
        """创建工具分组"""
        self._groups[group.name] = group

    def get_group_tools(
        self, group_name: str
    ) -> list[dict]:
        """获取分组中所有工具的 Schema"""
        group = self._groups.get(group_name)
        if not group:
            return []

        tools = []
        for tool_name in group.tools:
            tool = self._menu.find_tool(tool_name)
            if tool:
                tools.append(
                    self._menu._tool_to_schema(tool)
                )
        return tools

    def get_groups_for_context(
        self, context: dict
    ) -> list[str]:
        """根据上下文选择合适的分组"""
        active_groups = []

        # 基于用户角色
        user_role = context.get("user_role", "anonymous")
        if user_role == "admin":
            active_groups.append("admin_tools")

        # 基于对话主题
        topic = context.get("topic", "")
        if topic == "weather":
            active_groups.append("weather_tools")
        elif topic == "database":
            active_groups.append("database_tools")

        # 基于工具使用频率
        # ...

        return active_groups
```

## 四、选型准确率优化

### 4.1 提高选型准确率的策略

对于 60+ 工具的 Agent 系统，组合使用以下策略可以显著提高选型准确率：

**策略一：层级菜单 + 按需展开**

将工具分为 5-7 个顶层分类，每类不超过 15 个子工具。模型在任何时刻看到的工具不超过 20 个。

```
效果：将单次可见工具数从 60+ 降低到 15-20 个
准确率提升：约 15-25%
```

**策略二：上下文感知预筛选**

根据对话上下文，在调用模型之前预先过滤掉不相关的工具：

```python
class ContextAwareToolSelector:
    """上下文感知工具选择器"""

    def __init__(self, menu: HierarchicalToolMenu):
        self._menu = menu
        # 关键词 → 相关工具列表
        self._keyword_index: dict[str, list[str]] = {}

    def build_keyword_index(self):
        """从工具描述中建立关键词索引"""
        for tool_name in self._menu._tool_map:
            tool = self._menu._tool_map[tool_name]
            keywords = self._extract_keywords(
                tool.description + " " + tool.name
            )
            for kw in keywords:
                self._keyword_index.setdefault(kw, []).append(tool_name)

    def _extract_keywords(self, text: str) -> list[str]:
        """提取关键词"""
        # 简单实现：分词 + 去停用词
        stop_words = {"the", "a", "an", "for", "to", "of", "in", "on"}
        words = text.lower().split()
        return [w for w in words if w not in stop_words and len(w) > 2]

    def select_relevant_tools(
        self, user_input: str, max_tools: int = 20
    ) -> list[str]:
        """根据用户输入选择最相关的工具"""
        input_keywords = self._extract_keywords(user_input)
        scores: dict[str, float] = {}

        for kw in input_keywords:
            # 精确匹配
            for tool_name in self._keyword_index.get(kw, []):
                scores[tool_name] = scores.get(tool_name, 0) + 2.0
            # 模糊匹配（子串匹配）
            for tool_name, keywords in self._keyword_index.items():
                if kw in tool_name or tool_name in kw:
                    for t in keywords:
                        scores[t] = scores.get(t, 0) + 1.0

        # 按分数排序取 top N
        ranked = sorted(
            scores.items(), key=lambda x: x[1], reverse=True
        )
        return [t[0] for t in ranked[:max_tools]]
```

**策略三：工具描述优化**

精简但准确的工具描述（详见 9.1 节）比冗长的描述效果更好。特别是在海量工具场景下，描述的一致性比描述的详尽性更重要。

**策略四：工具别名和同义词**

观察到用户常以不同称呼描述同一工具时，可以在工具描述中加入别名：

### 4.2 准确率的测量方法论

```python
def evaluate_selection_accuracy(
    menu: HierarchicalToolMenu,
    test_cases: list[tuple[str, str]]
) -> dict:
    """
    评价工具选型准确率。

    test_cases: [(用户输入, 期望工具名称), ...]
    """
    correct = 0
    total = len(test_cases)
    confusion: dict[str, list[str]] = {}  # 期望 ↔ 实际选择

    for user_input, expected_tool in test_cases:
        # 模拟模型选择过程
        selected = simulate_model_selection(menu, user_input)

        if selected == expected_tool:
            correct += 1
        else:
            confusion.setdefault(expected_tool, []).append(selected)

    accuracy = correct / total * 100

    return {
        "accuracy": accuracy,
        "correct": correct,
        "total": total,
        "confusion_matrix": confusion
    }
```

### 4.3 60+ 工具时的推荐配置

当工具数量超过 60 个时，推荐以下组合配置：

| 配置项 | 推荐值 | 说明 |
|-------|--------|------|
| 根部分类数 | 5-7 个 | 不超过 Miller's Law（7±2） |
| 每类子工具数 | ≤ 15 个 | 保证单次可见工具数可控 |
| 上下文预筛选 | 启用 | 基于关键词匹配预过滤 |
| 工具描述长度 | 15-30 字 | 海量场景下描述宜精简 |
| 默认展开分类 | 1 个 | 根据对话历史预判 |
| 展开机制 | 异步按需 | 模型导航后展开 |
| 缓存策略 | TTL 60s | 避免重复展开操作 |

## 关键概念速查表

| 概念 | 定义 | 重要性 |
|------|------|--------|
| **层级工具菜单** | 将工具按分类组织成树状结构，按需展开 | P0（海量管理核心） |
| **按需展开** | 只在模型选择某分类后才展示其子工具 | P0（Token 优化） |
| **上下文感知预筛选** | 根据用户输入预过滤无关工具 | P1（准确率提升） |
| **工具分组** | 从多维度对工具进行逻辑分组 | P1 |
| **关键词索引** | 从工具描述建立关键词到工具的映射 | P1 |
| **选型准确率** | 模型正确选择工具的概率 | P0（核心度量） |
| **导航工具** | 代表一个分类的虚拟工具（用于展开操作） | P1 |
